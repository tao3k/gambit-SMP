The proposed home of the incremental compiler service is Gerbil running on Gambit.
Gambit provides explicit compiler-stage/context contracts and the modern C runtime.
gxi/gxc are clients of one query service. This is a redesign of compiler and build
interfaces, not a larger subprocess pool. It neither requires Zig nor obtains
same-VM multicore execution from task scheduling alone.

[[file:models/sysml/iter-compiler-service.sysml][SysML]] owns five source-chain groups and four edges, five stage seams, five context custody groups, five retirement
conditions, four explicit refinement routes, four net-benefit cases and seven open admission gates. Native SysML
projects values through [[file:../../modeling/tools/iter-compiler-service-study.py][Python]] to the [[file:iter-compiler-service-matrix.org][matrix]], [[file:diagrams/iter-compiler-service.svg][D2]], and QNT parameters;
[[file:../../modeling/ascent/iter-compiler-service.rules.scm][ASCENT DSL]] routes IS-H/I/S/E and checks missing/stale/wrong-scope evidence.
[[file:../../../models/build/iter_compiler_service.qnt][QNT]] explores a two-consumer context protocol; [[file:../../../models/build/IterCompilerService.lean][Lean]] supplies conditional boundary
lemmas. [[file:../../../evidence/research/iter-compiler-service/checks.json][Receipts]] bind subjects and logs. No runtime/compiler implementation,
native test, generator execution or performance benchmark is authorized or run.

This establishes actual users, not a claim that all their dependencies have been
classified. iter/iterators additionally imports std/error and creates interface
methods; the prelude, implicit compiler helpers, native support and recursive
initializers are part of the remaining closure. A static import list cannot sign
the executable-support credential. [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/expander/module.ss::853][Positive-phase import handling]] collects module
dependencies and invokes eval-module; [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/expander/module.ss::102][module evaluation]] also forces preludes.

The current implementation evaluates those dependencies via hash-for-each. This
is not evidence of a prescribed deterministic initializer order. The replacement
must record actual dependencies and define an observational refinement of allowed
orders. It cannot silently sort effectful initializers or parallelize them. Unknown
or noncommuting effects stay owner-serialized and nonreusable; an explicit stricter
initialization policy is a language change requiring separate approval/proof.

[[file:../../../../gerbil-gambit-bootstrap-audit/src/std/list/list-builder.ss::29][list-builder]] documents shared mutable list state under continuation re-entry.
That is evidence against treating every reachable helper closure as frozen. It is
not proof that this particular in-range expansion executes that procedural helper
or captures its mutable instance. Likewise source use of let/cc in string/misc is
runtime semantics to preserve, not evidence that its expansion suspends a compiler
query by invoking a continuation.

** Readiness and safe parallelism

The two consumers may expand concurrently only after (a) their exact binding
projections resolve, (b) executable transformer/helper support is ready, (c) owned
fresh lexical/session instances exist, and (d) initializer/effect dependencies are
settled. Their unrelated phase-zero runtime native objects need not precede that
expansion. A runtime helper actually required by macro execution DOES precede it.
The graph is phase-resolved: the same module can have distinct executable and
ordinary runtime readiness, and may need multiple phase instantiations.

This changes the dependency authority from whole-module completion to requested
result projections. It does not authorize arbitrary per-form caching. The initial
query grain remains module × phase × stage × semantic profile.

* RESEARCH Gambit stage interface and independent contexts :contract:
:PROPERTIES:
:CUSTOM_ID: iter-gambit-stage-contract
:CURRENT_API_STATUS: internal-functions-not-admitted-service-interfaces
:END:

[[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/compiler/driver.ss::647][Gerbil runtime emission]] constructs Scheme code, loaders and nested module outputs.
[[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/compiler/driver.ss::707][Meta emission]] creates SSI and positive-phase Scheme sections. [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/compiler/driver.ss::787][compile-scm-file]]
writes declarations and code, then invokes or defers [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/compiler/driver.ss::881][gsc-compile-file]]. Thus the real
handoff is GeneratedSchemeResult, not Gerbil IR mislabeled as Gambit GVM.

#+begin_src text :eval never
GeneratedSchemeResult = {
 module, phi, sectionKind(runtime|loader|phase), code,
 declarations(block, standard/extended bindings, phase inlining policy, ...),
 semanticIdentity, originMap, dependencyTrace, diagnosticProjection, effectClass
}
GambitRequest = { ownedContext, inputResult, requestedStage,
                 semanticProfile, layoutProfile, inputEpoch, attemptCapability }
StageOutcome = Success(sealedResult, actualDemands, diagnostics)
             | Suspended(ownedState, pendingDemands)
             | Failed(diagnostics, drainResponsibility)
             | Cancelled(drainResponsibility) | Unknown(retainedCustody)
#+end_src

These are proposed data contracts, not implemented API names. Gerbil retains
hygiene/phase/module policy. Gambit owns parsing/normalization of generated Scheme,
semantic target selection, GVM lowering and modern C emission. The declarations,
source origin, C interface and supplied/demanded module metadata must cross the
boundary without loss. A direct in-memory call cannot simply omit reader/source
location semantics from the previous Scheme serialization roundtrip.

| Cut | Current Gambit source | Proposed returned contract | Invalidation boundary |
|---+---+---+---|
| Parse/normalize | [[file:../../../vendor/gambit/gsc/_front.scm::194][compile-frontend-aux]], normalize-program at 250 | Normalized result + environment/C interface + origins + module demands | Reader, semantic compiler options and input/phase effects |
| GVM lower | [[file:../../../vendor/gambit/gsc/_front.scm::397][compile-parsed-program and module descriptor]] | GVM plus ModuleSpec/FrameSpec/PointId duties | Optimizer facts, semantic target constraints and compiler identity |

Generated source bytes, parsed trees and GVM are distinct representations with
separate fidelity obligations. The existing .gvm dump is diagnostic output, not a
stable serialization ABI. Cross-stage results either deeply seal all reachable
mutable data, transfer an exclusive rooted context, or remain private within the
same live context. No promise of persistent normalized/GVM caching is made before
that graph/identity closure is proven.

** Concrete mutable state to remove from process-global authority

[[file:../../../vendor/gambit/gsc/_front.scm::317][compile-frontend]] installs compilation options and runs begin/end for environment,
parse tree, GVM and selected target. The corresponding concrete state is:

- [[file:../../../vendor/gambit/gsc/_env.scm::348][env.begin!/end!]]: variable counter and return/closure/temp variables.
- [[file:../../../vendor/gambit/gsc/_ptree1.scm::2980][ptree.begin!/end!]]: node/temp counters and diagnostic port. end! clears the
  counters but does not clear *ptree-port* in the inspected body; end! alone is
  therefore not a proof of root retirement or port ownership transfer.
- [[file:../../../vendor/gambit/gsc/_gvm.scm::3022][virtual.begin!/end!]]: operand interning table/allocation cursor. The frontend
  additionally mutates *bb* and emission state, e.g. [[file:../../../vendor/gambit/gsc/_front.scm::953][basic-block globals]].
- [[file:../../../vendor/gambit/gsc/_back.scm::388][target-select!]]: target and target-derived dispatch/primitive/frame data.
  [[file:../../../vendor/gambit/gsc/_back.scm::475][target-unselect!]] resets selected helper objects and invokes target cleanup;
  the target-specific writable closure still requires a complete census.

The minimal acceptable architecture is not a mutex around this whole list. A
Gambit CompileContext must own the mutable closure and explicit target-emission
state. Immutable target descriptions can be shared only after a writer proof;
semantic-target options cannot be mistaken for CC-only flags. Gerbil needs its
own owned expander/optimizer/loader context as well. Process isolation can preserve
current global ownership for early parallel execution, at measurable startup,
copying and memory costs; it does not certify an in-process API.

** Context state and one-shot outcome

#+begin_src text :eval never
Created -> Active -> Suspended -> Active -> Sealing -> Draining -> Closed
                  \-> Failed/Cancelled/Unknown -> Draining -> Closed-or-Quarantined
#+end_src

Suspension relinquishes CPU capacity, retaining context, roots, borrow/callback
ownership and the pending dependency list. It must also count retained memory so
that suspended sessions cannot deadlock the memory budget needed by their producers.
Context generation + attempt/epoch + owner identity gate every resume. Service
completion is one-shot even if an internal continuation is multi-shot. A callback
or saved continuation must not reenter a closed/reassigned context; explicitly
supported re-entry needs fresh owned state and its own semantic proof.

A success detaches/seals the returned graph and closes context-owned callbacks and
borrows before context reuse. Failed/unknown execution cannot publish success or
free its context on a timeout assumption. Unknown work stays retained/quarantined
until its execution endpoint settles. Borrow closure, root coverage, actual exit
handlers and failure of cleanup are still source-refinement obligations. The QNT
protocol abstracts them; it does not prove native root maps or exceptions correct.

Dune's dependency collector explicitly relies on a cooperative single-threaded
scheduler; its collector pool is not thread/domain safe. Therefore its Fiber
concurrency does not prove OCaml domain or Gambit processor parallelism. We learn
its dependency representation, cutoff and completion discipline; we must provide
our own thread-safe/process-owned coordination. Memo's in-memory values also do
not establish portable on-disk caching of Scheme syntax/closure heaps.

The theoretical reference remains [[https://simon.peytonjones.org/assets/pdfs/build-systems-original.pdf][Build Systems a la Carte]]: rebuilding and
scheduling are distinct design choices. The pinned Dune node source also points
to the [[https://doi.org/10.1017/S0956796820000088][Theory and Practice]] treatment. This study derives a Scheme application,
not a proof supplied by either paper. No superiority over Dune is demonstrated.

* RESEARCH Retirement and net-benefit obligations :retirement:benefit:
:PROPERTIES:
:CUSTOM_ID: iter-retirement-benefit
:END:

The generated [[file:iter-compiler-service-matrix.org][matrix]] lists five paths and exact conditions. In order: classify all
actual consumers and phase supports; define GeneratedSchemeResult fidelity; move
compiler mutable state into owned contexts; qualify sealed stage results; migrate
readiness/publication/scheduling consumers; only then remove old authority. gsc as
standalone tool, the native C compiler, and Scheme semantics remain required.

There is no benefit from merely relocating old loops. A cold cache must still do
necessary expansion/lowering/native work; a warm trace only avoids work proven
unchanged. The existing std/make already skips unrelated modules in many leaf
edits, so that is baseline, not a new saving. Shared immutable programs may avoid
repeated preparation; fresh lexical/module instances and ordered effects remain.

Let R be avoided work, H added validation + sealing/instantiation + transfer work,
D removed critical-path delay, K added critical-path delay, and M retained memory.
Work benefit requires R > H; a strict span reduction requires D > K. Both equations
need comparable real-stage accounting; they are not speed predictions. Total time
also depends on available parallel slack, memory/CPU budgets and contention. On
12 cores, two independent consumer expansions expose at most two-way concurrency
at this particular cut; they cannot justify an end-to-end twelvefold claim.

For a precisely qualified pipeline cut, let p be the shared executable-phase
prefix, U a runtime/native branch needed by the final target but not by either
expansion, and B the maximum remaining consumer-branch span. A whole-module gate
adds the dependency U -> both consumers, yielding old DAG span p + U + B.
Removing that edge yields new DAG span p + max(U, B), saving min(U, B) in graph
span before added coordination. This is a symbolic architecture comparison,
not a measured number or an assertion that this real chain has a nonzero U.
If U is required to execute a macro, the edge remains and this saving is zero.
The production map must establish U and all other edges; finite CPU/memory slots
can prevent actual elapsed time from reaching the smaller span. New work H and
new span K remain separate charges, and the scheduling work bound still applies.

| Case | Falsifiable target | Added work / failure of benefit |
|---+---+---|
| No-change | Zero recomputation of admitted unchanged demanded stages | Trace/absence/tool validation and materialization remain; hidden input refutes reuse |
| Changed iter transformer | Invalidate both real users of changed executable support | Same export names do not save expansion; trace comparison may cost more than tiny expansion |
| Equal consumed result after change | Stop only downstream propagation beyond genuinely equal projections | New dependency trace still replaces old one; relevant origin/effect change defeats equality |
| Two consumers | Remove unrelated phase-zero/native wait from expansion span | Real macro runtime helpers, serial effects, IPC and retained contexts may dominate |
| CC/profile-only change | Reuse semantic stages under a proven nonsemantic projection | Semantic target flags, layout dependencies or declarations invalidate broader stages |

Darwin cold generated-C preprocessing remains a separate backend/runtime refactoring
problem; this graph can avoid unnecessary invocations but does not make a necessary
GCC macro expansion intrinsically cheaper. No matched platform timing exists in
this study. The reported Linux/macOS gap cannot be assigned to this design alone.

SysML additionally defines typed CompileContext/StageResult records and publication/
release requirements. These constrain the proposed design; parsing/validation does
not establish their satisfaction by native code. Four refinement routes name actual
QNT operations and Lean declarations; the adapter checks those names and ASCENT
projects the associations. Their evidenceGap fields prevent the associations from
being misreported as completed refinement proofs.

The new QNT has 18 named scenarios, including six explicit invalid controls.
Its state integer stages denote generated Scheme, normalized, GVM and C results;
these are protocol labels, not computed Scheme semantics. Context generations
reject stale resume tokens. Unknown attempts retain roots until an explicit endpoint acknowledgement; that
acknowledgement and settle action are assumptions requiring native source refinement.
The epoch edit abstracts invalidation, retaining old
execution custody for draining. The ordered-trace example is a hypothetical guard
that changes before an irrelevant later probe; it is not an observed extra import
in iter. It exposes why eager probing is not universally sound, without claiming
that all validation reads are effects or that parallel sections must serialize.

The parent eight-node model checks reuse, dynamic discovery and scheduling. This
new model adds context/stage custody; neither silently replaces the production
compiler or proves liveness. ASCENT routes obligations and rejects missing/stale
receipts; it does not manufacture proofs from file links. All seven source/platform
gates stay false until their actual evidence is provided, including in the control
where every formal obligation is synthetically marked checked.

Bootstrap retains an explicit existing-compiler seed -> service artifact -> recorded
self-rebuild graph, distinct producer identities and optional persistent store.
Neither a pre-existing daemon nor a populated cache is a correctness requirement.
The next research priority is the target-specific writer closure and stage result
sealing/fidelity, rather than another isolated notifier lifetime subproblem.
