** Linux and Darwin source comparison for descriptor closure

Current os_setup.c:225 implements the same priority for POSIX callers:
HAVE_CLOSEFROM, then HAVE_SYS_close_range, then USE_fcntl with F_CLOSEM, then a
loop to sysconf(_SC_OPEN_MAX) or its resource-limit fallback. os.h:352 controls
the configure-dependent first branches; os_io.c:9237 calls this routine before
execvp. A Linux installation may take a bulk branch; neither its OS name nor a
configure symbol proves that the kernel operation succeeds. The legacy call
site does not check the returned closefrom status, so the replacement contract
must explicitly own closure failure, fallback or refusal. No newly reachable
Linux failure is claimed from this source review.

D879 recorded openMax1048575 and absent bulk-close capabilities on its Darwin
host, with a near-million-close fallback. Its retained120-module launch control
28.853->10.465s supports the combined eligible launch mechanism. It does not
separate fork from fd sweep, provide a current-host capability receipt or give
MCP/POO package seconds. A current configured build must preserve the installed
eligible fast behavior instead of reintroducing the old loop during C23 migration.
Already-installed bypass is baseline/non-regression work, not a new2.76x gain.
This source review does not attest which current installed requests actually

** Parent-planned launch is the architectural replacement

One existing NativeAction owner holds executable/argv, environment, cwd, fd
mapping/closure, signal state, PTY mode and result custody. A qualified Darwin
realization uses parent-prepared actions instead of limit-proportional child
work. Linux may retain a cheaper direct/bulk realization under the same contract.
The contract retires the old launch authority only for fully migrated callers;
it does not replay a patch or add a second wrapper around it.

The historical spawn patch is useful semantic evidence: PTY uses fallback;
with an explicit child environment, a bare executable name is not freely
substitutable with posix_spawnp because PATH lookup context can differ. The fd
moves must preserve standard-descriptor aliases and partial failure ownership.
Signal mask/defaults, child affinity, cwd failures, exec errors and status must
remain equivalent. Current code masks interrupts around creation so child exit
can be associated with its process device before SIGCHLD handling resumes.
The existing error-pipe handshake and device/process registration therefore
belong to the launch protocol, not removable bookkeeping. The native adapter
must classify synchronous spawn failure versus accepted child exit and retain
unknown outcomes under the existing request/custody model.

** What differs at the compiler and script boundaries

Current configure.ac:2696 selects the checked bundle option for Darwin dynamic
modules and checked shared/rdynamic options for other GNU POSIX targets; BUILD_OBJ/BUILD_DYN at3335/3337
construct distinct commands. Native format, symbol resolution, relocation and
bundle alias semantics remain required. ELF shared modules are not substitutes
for Mach-O bundles. The installed script has the same metadata extractor shape;
its configured flags are a separate SDK profile, not a current C23 artifact.

Current _gsclib.scm:367 supplies the target C file as metadata to gambuild.
The installed Darwin driver also explicitly supplies runtime C as
BUILD_DYN_META_INFO_FILE_PARAM for the object-to-bundle step. gambuild-C.unix.in:157
get_meta_info performs grep followed by sed, and extract_cc_ld_options at239
invokes it five times for one nonempty file: pkg-config-path, pkg-config,
cc-options, ld-options-prelude and ld-options. This is why the eligible obj+dyn
branch has two extraction rounds versus one in the ordinary action.

These are file-scan/decoding pipelines, not five measured disk reads or known
spawn costs: caches and shell behavior matter. Empty/multiple metadata files,
feature expressions and pkg-config add different conditions. No milliseconds
are inferred from scanning the11.43MB MCP C or180KB POO C. Whole executable
comparisons must also account for later else/static work; the local4-versus2
skeleton is not a whole-package Darwin/Linux process ratio.

| Existing authority | Proposed owner / product | Can retire | Must remain / added cost |
|---+---+---+---|

| FD-limit child setup | Qualified platform launch realization | Eligible limit-proportional close work | Complete fd/signal/PTY/PATH/cwd and process-result semantics; explicit fallback |
| Whole-module completion as only demand | Existing phase query graph and required bundle demand | An unrequested bundle only after actual consumers prove it unnecessary | Compile-time macro/support loads, live initializers and public artifact contract |

Do not share a final object argv unchanged with bundle linking. Parse common
metadata once when justified, then form separate projections with distinct
flags, inputs, aliases and outputs. Legacy feature names and evaluation semantics
must be preserved; a new target triple must not silently reinterpret a metadata
condition. Raw script warnings, unsupported-expression handling and diagnostics
remain equivalence obligations. pkg-config or other opaque queries cannot be
cached without their real environment/tool/input/effect closure.

Generator-owned structured metadata is an output of the existing semantic/native
contract, not a new package wrapper. Fresh script/CLI dispatch retires on migrated obj/dyn service paths only
when exact products and original error/output behavior are covered. Public GSC
-obj, gambuild and generic open-process clients remain supported where they are
still real consumers; no whole command/file deletion follows from these cuts. Source and generated C can still be required: no GSC semantic stage
is deleted merely because a native-only CLI wrapper can be bypassed.

A standalone static executable does not prove that build-time bundles are
unneeded. Imports, executable macro support and module initializers may require
them. The ordinary POO library also owes its public dynamic products. Bundle
omission therefore requires an actual demand proof under the existing phase
contract; no bundle count is credited from artifact names alone.
