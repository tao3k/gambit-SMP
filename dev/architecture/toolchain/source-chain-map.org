| Case | Change | Current path | Proposed work | Scoped mathematical count | Boundary | Open obligation |
|---+---+---+---+---+---+---|
| noChange | All semantic inputs, producer/target, headers, ordered metadata and outputs unchanged | Make may revisit phony phases/stamp; Git stamp branch preserves unchanged bytes; non-Git branch rewrites stamp.h | Validate complete cuts; zero eligible generation/compile/link work | Abstract 10-node model: 0 executions if all saved signatures match | Fresh validation/planning and live context instantiation still cost work; changed bootstrap identity is not this case | BF-BUILD-CUT |
| leaf | Implementation-only change to _t-c-3.scm under fixed bootstrap compiler; exported link metadata assumed unchanged | Its .scm.c recipe, library metadata targets and dependent object/library/executable recipes become eligible by timestamps | Regenerate leaf, compile changed leaf C, rebuild affected library and executable; stop unchanged metadata descendants | Abstract 10-node model: nodes 0,2,6,9 = 4 executions under its declared oracle | Current targ-link-info reads generated C; metadata-only reuse needs an explicit producer/projection. Archive/executable relink generally remains necessary | BF-BUILD-CUT |
| macro | Semantic change to include-adt in fixnum.scm | MODULES_C explicitly depends on fixnum.scm: 33 library modules plus executable module, 34 generation targets | Invalidate real semantic consumers; retain broad set until producer dependency closure proves a narrower set | Two-unit model: up to all 10 nodes; real 34-unit impact is not certified by that projection | A shared macro can genuinely invalidate almost everything. No claimed N-to-1 generation speedup; unchanged downstream bytes may still cut off work | BF-BUILD-CUT |

** Phase split and retirement
#+BEGIN: sysml-view :kind source-chain-phases :source architecture/toolchain/models/sysml/architecture.sysml
#+NAME: source-chain-phases
| Phase | Current role | Proposed cut | Admission | Keep | Retirement |
|---+---+---+---+---+---|
| phase1 | Generate library and executable module C | Reuse existing per-module generation tasks; replace blanket phase release only where true dependencies allow | Frozen producer and common inputs; independent compilation contexts; preserve module and bootstrap identities | Keep macro/elaboration dependencies and all source readers | Retire whole-phase generation envelope only after all actual units use explicit rules |
| phase2 | Generate library and executable semantic linkfiles | Separate library link-plan and executable link-plan tasks from unrelated object compilation | All ordered input metadata ready; executable plan waits for its actual library metadata | Keep actual input readiness; do not reorder modules | Retire the global phase barrier, not its true producer edges |
| phase3 | Shared mode compiles library objects; static mode builds library | Stream each ready object; archive/shared-library task waits for its exact object list | One compiler/jobserver budget; per-object header/ABI inputs closed | Keep archive dependencies and configured shared/static differences | Retire delayed object release and duplicate scheduling only after the old callers migrate |
| phase4 | core library/executable construction | Release final archive/link tasks when their actual inputs are committed | Exact semantic/native closure and preserved failure propagation | Keep link and output-set completion, no partial publish | Retire final blanket orchestration only after native/action parity, not from graph shape alone |
| bootstrap | from-scratch cleans/bootstrap/core and can change producer | Model each compiler-producing stage with its own identity | Source and producing compiler lineage, boot/gsc-boot setup and runtime header closure | Required self-hosting stage edges remain | No retirement of a necessary second producer stage merely because source bytes repeat |
#+END:
