** What is actually repeated, and what is already shared

The two MCP Scheme paths are byte-equal (1857054 bytes) and the two C paths are
byte-equal (11425281 bytes). That proves two names/copies, not two GSC executions.
The installed Darwin producer already implements one -c, a C copy and shared
object reuse for its eligible static branch. The same C supplied to GSC -obj is
recognized as target input by _gsclib.scm's input-is-target-file? branch, avoiding
another Scheme-to-C conversion. These are deducted from new benefit.

POO has two equal35305-byte Scheme files and one179814-byte static C file; the
selected dynamic C path is absent. Neither duplicate C generation nor its
absence over all past requests follows. Currentness checks and compile-file
modes must be traced, not inferred from filename counts. An equal output hash
also cannot prove equivalent native options or safely merge different modes.

* GROUNDED Current C producer and consumer responsibilities

Current _t-c-1.scm:1189 defines module symbol/global/subobject/label/OFD counts
before including gambit.h. targ-dump-sub at1641 dispatches strings, vectors and
other object classes; targ-dump-string at1718 invokes targ-vector-like-object,
whose body at1695 emits character chunks. This is the producer of ___STR8 calls.
module_generation.h.in:994 selects the target string representation and expands
word-packing expressions. The selected branch and actual preprocessed expansion
were not executed in this study. Do not claim that every unused width/endian
branch is expanded or assign a timer from lexical macro counts.

The root header is1818 bytes and directly includes37 component headers totaling
526499 source bytes. This is a root-local textual inventory before conditional
selection, nested/system includes and include guards; it is not526499 expanded
bytes per object, nor an observed preprocessing duration. Splitting a header
into37 files alone removes no semantic reconstruction responsibility.

The generated module descriptor at module_generation.h.in:1373 references binding,
label, OFD, constant and subobject tables plus setup/init functions. The consumer
setup.c:1742 setup_module_fixup checks version and structure sizes before changing
SETUP_FIXUP_DONE at1812; fixrefs at1632 updates encoded references in place.
Therefore an immutable descriptor/template does not make existing binding tables,
objects or fixup state immutable. Stable interface migration must separate these
roles rather than map every current static array into a read-only shared image.

* RESEARCH Proposed replacement: one semantic product, separate projections

| Product | Owner and key | Work that can disappear | Work that remains |
|---+---+---+---|
| GeneratedSourceResult | Generic phase graph with an admitted source producer | Re-execution of identical input-to-Scheme construction after complete key validation | Changed catalogs, ordered input reads and required generator outputs |
| ModuleCodePlan | Scheme/GVM semantic owner; code, support and literal-use projection | Eligible code re-generation/re-compilation after data-only edits | Constant-folding or inlined-payload changes; actual function bodies and hot GVM operations |
| LiteralImageSpec | Target-qualified literal graph/layout emitter | Repeated per-character macro packing and representation choice inside each C translation | Full payload encoding, tags, padding, alignment, graph identity and actual data materialization |
| BindingPlan / ModuleSpec | Scheme identity/init owner plus compiled runtime helper | Repeated common setup/table-construction implementation | Ordered globals/symbols/keywords, fixups, required module effects and writable bindings |
| FrameSpec | Existing frame semantic owner and all actual consumers | Duplicate layout/descriptor emission only after parity | GC root coverage, return labels/OFD, tail calls, continuation and descriptor lifetime |
| NativeProduct | Qualified NativeAction/output store | Equal-key generation/object actions not already removed by baseline | Every native miss, ABI/compiler/profile change, bundle alias and link work |

The initial representation candidate is target-qualified C data plus a stable C23
interface and compiled common helper implementation. It is not a change to one
STR8 macro. The Scheme emitter must produce the canonical word/data encoding
and relocations; the consumers must accept the descriptor contract. Separate
code/data translation units require migration of today's local static arrays and
symbol visibility. A data-only edit can retain code only when complete semantic
use/constant-folding and stable-reference projections prove the code independent.
It is not established merely because the edit is inside a string literal.

The encoding can be immutable; the Scheme objects it describes need not be.
POO's absent gensym and required module/class initialization preserve instance
identity. Do not cache a live RBTree, object graph, binding table or expander
instance as though it were a construction program. Preserve the actual existing
module-instance scope rather than silently making every load fresh or global.

The target profile includes word and character widths, endian, tag/header scheme,
alignment, module identity and frame ABI. The native key additionally includes
actual configured headers, compiler/options and linkage/relocation/TLS context.
A data encoding change invalidates its data/relocation consumers; an ABI change
invalidates every dependent generated and native product. Reuse ends at a missing
or unqualified effect/identity input. C23 is the modernization baseline; these
architectural gains are not automatically produced by choosing its standard flag.

Direct packed data may have more textual bytes than character macros while
requiring fewer compiler expression operations. It still needs parsing and data
emission. Hence neither69.13% fewer compiler time nor removing the whole11.43MB
is claimed. The POO lexical string spans cover only0.69% of its C; a string-only
proposal has little representational coverage there, although byte share is not
a bound on compiler-time share. Shared metadata/helper work must be investigated
across ordinary modules to address the broad late tail.

The retained D858 result already rejected the header-only route: its one adjacent
MCP package pair77.650/77.013s is not a stable0.82% improvement, despite the real
atomic gain. This remains counterevidence, not an invitation to repeat the patch.

A stronger same-cohort limit follows from D855: the selected embedded compile
job occupies37.841 worker-s of636.536 parseable compile-file worker-s. Even
optimistically deleting that ENTIRE job while every other duration and the
12-worker capacity stay fixed leaves598.695/12 =49.89125s, above the37.3355s
half-time target. At least150.669 MORE worker-s would still have to disappear or
shorten, before mandatory other work and new overhead. This is an impossibility
bound for a single-job-only solution under stated assumptions, not a proof that
any expression-packing rewrite removes that whole job. POO's historical producer
interval1.631s belongs to another source/profile and is not assigned to current
native rationaldict compilation.

Twofold contribution is therefore constrained, not numerically forecast: native
work must shrink across many relevant modules, and preparation/phase dependency
cuts must also meet the wall-span budget. Equal-key object omission already
includes its internal parsing; do not add a second header/literal saving for the
same omitted action. Current complete MCP and POO comparisons are still required
independently; a win in one package cannot mask regression in the other.

* RESEARCH Exclusive obligations and next gate

SysML module0/module1/moduleContract is the design source. Existing QNT owns
phase invalidation, readiness and publication interleavings. Existing Lean owns
key/layout correctness and the shared net-benefit laws. New literal encoding,
reference/fixup and cross-consumer layout fidelity are explicit open refinements,
not new duplicate scheduling theorems. ASCENT checks typed projection transport
and deliberate missing/wrong-scope observations; static source/byte census does
not become a native success fact.

Before implementation, close the literal-use/code projection and mutable binding
consumer lists for these exact classes; identify which work is absent from the
already optimized Darwin producer. Native experiments require a specific
candidate that removes those duties, unchanged package/profile/cache scope and
original budgets. No compiler, preprocessing, module or package benchmark was
run to create this census. No runtime patch, Python runner or parallel framework
was added. Missing raw cache bodies cannot authorize fresh native reuse.

The prior [[file:c23-development-refactor-design.org::*Explain the Darwin/Linux differential inside that same model][platform differential architecture]] and
[[file:darwin-cost-factor-design.org][nine-factor evidence graph]] already own this question. The current module
study must not substitute a new shared-code narrative for them. Module CodePlan,
LiteralImageSpec and BindingPlan are shared mechanisms. Linux benefiting is not
a disqualification, but neither a shared mechanism nor a Darwin-only occupancy
bound demonstrates a reduction of the Darwin/Linux gap.

Keep three separate terms for each matched additive work cohort:
W_D-W_L=(n_D-n_L)*c_L+n_D*(c_D-c_L)+(H_D-H_L).
Existing DevelopmentBenefit.platformGap owns this algebra. Actual durations,
action identities, clock/overlap and native correspondence remain evidence duties.
Do not duplicate the formula as a new Lean or QNT proof. Parallel elapsed time
requires the real dependency/resource span rather than a CPU-work sum.

An equal proportional improvement on both platforms can leave their ratio
unchanged. Darwin self-acceleration D0/D1 and residual ratio D1/L1 remain the
separate objectives already recorded in the prior design; no target is silently
substituted. The shared module rows therefore retain zero admitted differential
credit until a matched platform edge supplies it. This is an admission state,
not a claim that their actual future differential benefit must be zero.

The current task's next priority is the Darwin native-action/platform cost chain
under its existing evidence gates, not more isolated literal/header experiments.
The shared contract research remains supporting architecture and is not deleted
or counted again as a new explanation of the platform gap.
