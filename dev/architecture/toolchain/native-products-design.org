** Metadata is not one undifferentiated cost

Shell substitution transports parameters into configured commands. C metadata
parsing extracts conditional options and pkg-config information. Gerbil optimizer
.ssxi import is a third, different activity. The successful0015 change left
metadata parsing intact. The rejected metadata-empty probe changed a different
mechanism. The optimizer metadata record additionally observed152 distinct paths
and builtin metadata once in a real12-consumer build, disproving a12x installation
multiplier there. Do not share initialized optimizer state or multiply a
single-consumer timer by12 as the basis for BuildMetadata.

* RESEARCH BuildMetadata: one producer and two explicit key levels

The Scheme target emitter is the semantic producer. Its GeneratedCResult seals
both generated C and the ordered metadata projection. It can keep the legacy
C comment representation for external clients while internal consumers use the
same typed value. A hand-maintained sidecar or a second parser-derived registry
is not another source of truth. Existing arbitrary-C/legacy CLI inputs without
this producer contract retain their legacy path or refuse typed reuse.

#+NAME: metadata-product-shape
#+BEGIN_EXAMPLE
BuildMetadata {
  producerIdentity, generatedResultIdentity, originalMetadataIdentity,
  ordered pkgConfigPath, pkgConfig, ccOptions, ldPrelude, ldOptions,
  legacyFeatureExpressions, diagnosticAndFailureContract
}
ParsedMetadataKey = exact metadata projection + emitter/format + feature language
ResolvedMetadataKey = ParsedMetadataKey + effective feature map + role + overlays
                    + env/cwd + pkg-config/tool/read/effect closure
#+END_EXAMPLE

Parsed metadata can be reused across C payload changes only when the generating
producer proves that projection unchanged. Resolved values cannot be reused
across a changed feature map, option precedence or query context. Object, bundle
and executable have separate argv projections, input/output roles and aliases.
One parsed product never means one final argv shared unchanged by all roles.

Preserve Scheme-string decoding, empty arguments, newlines, backslashes, ordering,
conditional language, warning/failure behavior and actual pkg-config effects.
Do not silently substitute a new target-triple interpretation for legacy feature
names. Opaque or stateful queries cannot become cache hits without a complete
contract. A structured product removes repeated whole-C grep/sed/decoding on
migrated paths; it does not omit metadata, its interpretation or native work.

* RESEARCH NativePipelinePlan: replace authority, do not add a coordinator

#+NAME: native-pipeline-shape
#+BEGIN_EXAMPLE
NativePipelinePlan {
  generatedResult, parsedMetadata, resolvedRoleProfiles,
  effectiveConfig, capacityPlan, immutableInputSnapshot,
  actions: ObjectCompile | BundleLink | ExecutableLink,
  dependencies, exactInputsOutputs, resultPublicationBoundary
}
ActionKey = role profile + exact executable/tool contents and prefix
          + argv/env/cwd/original source spelling + input/header/query snapshot
#+END_EXAMPLE

A single recipe/configuration authority produces both the retained legacy
script view and the typed EffectiveConfig view; independently maintained flag
tables or a second toolchain manifest are not introduced. The existing phase
planner owns demand; the existing native capability owns execution. Native-only C roles can consume an ObjectCompile plan directly instead
of starting GSC solely to reconstruct a compiler request. Required object, bundle
and final-link products remain distinct; reuse already present in the baseline
is retained. Public GSC/gambuild clients and unsupported recipes remain genuine
legacy consumers until separately migrated.

Simple one-versus-two GSC producer fusion is also already tested: D1416 reached
identical C/native text with only about4.16% producer-wave difference, without
package admission. NativePipelinePlan cannot relabel that experiment as a new
major opportunity. A distinct design must eliminate additional complete duties
with a demonstrated budget beyond that route.

Do not prepare the old configured driver and then run a new coordinator with
independent tool discovery and redundant validation. That is the measured
0.88->1.59s regression, not a modernization win. Shared validation is legal only
where one existing owner replaces an equivalent obligation with equal strength.
Before/after object, source, header and selected-tool checks remain unless an
equally strong snapshot/lifetime argument actually subsumes them.

The real environment must execute. The native-object environment experiment
showed a failing declared GCC environment rejected by ordinary GSC while an
unpaired coordinator compiled under its ambient environment and committed.
Preprocessor identity did not detect it. Full envp, compiler prefixes, cc1,
assembler, SDK selection and cwd therefore belong to execution identity. The
later corrected controls are useful requirements, not current C23 deployment.
Relative includes and source spelling also remain real inputs; canonical identity
alone does not replace the source/cwd observed by the compiler and diagnostics.

No new independent pool, outer manifest, wrapper CLI or mutable global environment
is introduced by the product design. An unsupported request chooses one original
fallback rather than paying both old preparation and new execution layers.
All validation, query, private-context, IPC/storage and interaction costs are
charged. Fewer authorities and processes are not proof of positive net return.

* RESEARCH Invalidation and publication

| Change / event | Required invalidation | What may remain |
|---+---+---|
| C payload changes, metadata projection proved equal | Native object and actual downstream link products | Parsed metadata; semantic results not observing the edit |
| cc option / compiler / actual env / cwd / header change | Affected object role, selected tools and dependent bundle/executable | Unobserving generation and unrelated role products |
| ld-only option | Affected bundle/link projection | Object only if no compile-side dependency changed |
| pkg-config or feature/lookup change | Resolved metadata and actual consuming roles | Pure parsed metadata if source/language unchanged |
| target/module/frame ABI change | All generation/native/descriptor consumers that depend on it | Only independently qualified products outside that ABI |
| producer/output/input mutation during request | Refuse publication or retain known original failure policy | Private data is not a committed consumer result |
| failed/cancelled/unknown process | No complete consumer manifest; responsibility remains owned | Immutable private successful products only under their own validity contract |
| late/duplicate response | Check exact action/generation; cannot complete a later invocation | Prior terminal result record until its observers retire |

The publication boundary preserves the actual request contract: one failed batch
member cannot publish a successful complete group. A content-store artifact is
not a public consumer manifest. Existing QNT request/publication schedules and
Lean key/configuration laws remain the owners; source-to-native refinement is
explicitly open. No duplicate scheduling model or new arithmetic theorem is
created from these records.

** RESEARCH Darwin installer reconciliation and reader lifetime
:PROPERTIES:
:CUSTOM_ID: darwin-installed-image-reconciliation
:END:

The examined Gerbil [[file:../../../../gerbil-gambit-bootstrap-audit/install.sh::10][prefix installer]] copies =build/*= into the destination. The
[[file:../../../../patches/gerbil-v19-make-completion.md::7][Bazel completion patch]] has a different responsibility. It seals completed
numbered bundles at the producer. These sources identify a real
build-to-install cut. The prefix installer is a reference caller. A package
publisher must establish its own copy and load chain before claiming the
same result.

The existing publisher reconciles its last committed image map with the
desired, completed products. Each entry records the logical module and
numbered bundle, final image digest, ABI, signing policy, load closure and
resolved installed path. Validate the destination against the previous
receipt before retaining an entry. Reuse the existing path and file for a
match. Invalidate the affected load closure when install names, dependencies,
target or signing requirements change. An absent or changed destination
requires ordinary publication.

Build a replacement map privately, copying and signing changed images before
exposing them. Publish the complete map atomically through the existing
owner. A reader must resolve a single map for a load closure, and unchanged
entries in a new map must still resolve to the same installed image. A moving
prefix alias alone does not pin a reader. If the existing loader can mix
generations on successive lookups, complete the reader contract before
enabling concurrent install. Retain the old complete map and images until
reader reachability is discharged. Unknown reader lifetime delays retirement.

| Failure or request | Owner and outcome |
|---+---|
| No change and destination still matches | Publisher reuses the map and original files. Zero native copies, replacements and re-signs. |
| Missing, stale or foreign destination | Publisher validates or stages the affected closure. Completion of the producer alone cannot admit it. |
| Failed staging, signing or commit | The last committed map remains usable. The staging owner retains cleanup responsibility. |
| Partial lookup during publication | Reader keeps its selected map for the closure. Unchanged images retain the same resolved path. |
| Process exit or unknown reader | Publisher retires only when the image is unreachable from every admitted reader and published map. |

The first REV can own unchanged-file reconciliation end to end in one
existing publisher. Atomic multi-image migration requires a verified reader
contract. Keep these as distinct retirement gates. Compiler phase reuse and
C23 emission reduction keep their existing owners and evidence.

*** RESEARCH Bind interface resolution and native loading to one installed view
:PROPERTIES:
:CUSTOM_ID: darwin-managed-load-view
:END:

The [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/expander/module.ss::414][expander library resolver]] searches each current load path for
=.ssi=, then source fallbacks. [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/compiler/driver.ss::707][compile-meta-code]] can emit a runtime
=load-module= call into that interface. The [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/runtime/loader.ss::107][runtime resolver]] independently
walks contiguous numbered bundles from =.o1= and chooses the last existing
number. As a result, installing a new =.ssi= before its bundle can pair the
new interface with the old native image. Publishing the bundle first can
expose the inverse. Removing an earlier number can hide later bundles from
the legacy lookup.

For managed installed modules, one view resolves both sides of the edge.
Each entry binds an interface, the runtime module identifier emitted by that
interface, and the exact selected image. Include required phase support and
transitive native dependencies in the same publication validation. Acquire
the view before the first managed interface or runtime resolution, and
carry it through generated runtime loads and nested initializers. Existing
runtime state is keyed by module path in [[file:../../../../gerbil-gambit-bootstrap-audit/src/gerbil/runtime/loader.ss::32][load-module]]. A per-request
view switch inside one initialized process would require new module-instance
semantics. The initial managed design keeps the selected installed view for
the process or compiler session. Arbitrary load-path mutations and explicit
=reload-module!= remain separate admission cases.

The unchanged-image REV can preserve the legacy lookup when it leaves
both existing interface and image untouched. Changed cohorts need the shared
view contract before concurrent publication is admitted. Keep contiguous
numbered discovery, source fallback precedence, cached failure, builtin
handling and reload behavior as explicit compatibility cases. A managed
view can supersede numbered discovery only for its own admitted entries.
Readers with untracked lookup or lifetime keep the old retirement rule.

Real historical gains are already part of the evidence base, not a new budget.
The0015 ABBA difference is about17.58s on that old matched MCP build. D851's
mode-specific benefit belongs to its own cohort and has no two-package admission.
These gains cannot be added, multiplied, or counted again against a later faster
anchor. The old source-only4/2 launch skeleton supplies no extra seconds.

The new design has no measured incremental contribution yet. Twofold Darwin
self-acceleration still requires net critical-path removal >=D0/2 for the actual
qualified comparison. A new native-product architecture must remove duties
remaining AFTER spawn/object-reuse/0015, while charging validation and mandatory
compiler/linker work. Neither the zero-fork census nor the failed coordinator
supports assuming a positive contribution. Linux non-regression, platform-gap
reduction and residual ratio remain separately scoped; no matched Linux timing
was manufactured from the portable semantic controls.

For early feedback, later startup records select reached build.ss child execution,
not seconds of root spawn. NativePipelinePlan applies after those stages are
ready and cannot claim an earlier first-compile line from a mechanism that runs
after it. Full first-feedback/whole-build/test goals therefore cannot be closed
by repackaging post-compile transport work alone.
