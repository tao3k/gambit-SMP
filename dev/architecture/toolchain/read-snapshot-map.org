| I-TRACE | Ordered trace plus dependency/effect completion and failure records | Retire duplicate dynamic dependency recording only after one trace owner covers every path | Old trace can validate an adaptive branch without rerunning a closed producer; cannot infer closure from no new edges |
| I-SEAL | Staging owner, output/schema inventory, process/IO drain | Retire scattered success/exit translation only after complete caller replacement | Avoid repeated wrapper decisions; no promise of zero validation work |
| I-ADMIT | One revocation/commit owner, manifest CAS and reader lifetime policy | Retire multiple currentness issuers only after no bypass remains | Prevents stale publication; atomic manifest is a design, not an implemented Darwin guarantee |
