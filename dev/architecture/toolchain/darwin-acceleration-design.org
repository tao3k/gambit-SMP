** GROUNDED Stable view before allocating enumeration callbacks
:PROPERTIES:
:CUSTOM_ID: darwin-stable-iteration
:AUTHORITY: GambitDarwinAcceleration::stableHashIteration
:END:

The source/native handoff exposed an actual compiler correctness requirement:
a table's abstract entries may be unchanged while GC reorders its physical
buckets. A cursor cannot retain a bucket index across an allocating callback.
The private strong entry view makes callback traversal independent of rehash;
the same vector remains traced if a callback captures and resumes a continuation.

Allocation of the destination happens before copying, so the table is reloaded
after any allocation-triggered GC. Raw copy uses distinct WEAK/VECTOR body tags,
has no callbacks or safepoints, and runs under the iterator's existing interrupt
declaration. It does not make concurrent mutation of a shared table safe. Current
non-generational runtime scanning traces the ordinary vector; a future generation
barrier requires its own admission. The cost is O(capacity) copy/roots even for an
early-return search. This is a bounded per-iteration view, not whole-session
context eviction or persistent expanded-product reuse.

The [[file:darwin-acceleration-matrix.org::#STABLE-HASH-ITERATION][actual mechanism and matrix]] retains the old negative, rejected candidates,
corrected component controls and missing original bad-C boundary. Source/native
products still require successful complete compiler and both original packages.
Failed C is preserved at its original producer, then archived by the shared
executor after process quiescence; a successful isolated regeneration never
substitutes for that failed observation.

** Which current compiler mechanism the semantic model refines

Current _t-c-2.scm26-83 collects procedure code, value-label order and read/write
resource vectors. targ-wr-res503 also calls targ-rd-res499. targ-begin-cod in
_t-c-1.scm2129 derives declaration/read/write sets and host label lists.
stack_operations.h.in BEGIN_HLBL/BEGIN_COD/END_COD loads/stores the selected
resources; gvm_registers.h.in67-80 gives explicit local-register versus direct
context aliases. targ-res-op453 includes HEAP, FP, GVM registers and separate
unboxed declarations, so a three-slot register model is not their full layout.

The proposed semantic relation is source logical Machine = observe(target Host).
The target Host retains a stable base and selected locals; observe overlays
kept locals on that base. The relation includes logical resource values,
pc/nargs/fp/frameId/denv identity, effect trace and an uncaptured world state.
It is not an equality of cache keys. The scope is a single unchanged host-region
boundary whose exact reads/writes are admitted. It does NOT prove arbitrary
host repartition, direct tail-edge lowering or GCC execution equivalence.

** Concrete semantics and proof content

| Operation | Source step | Target resource step | Condition / result |

** Root refactor cut: ExplicitNativeCodePlan

The existing Scheme GVM/emitter owns one sealed compilation plan, not a Python
runner, source postprocessor or extra wrapper around the old generator:

- Canonical GVM blocks and typed transfer edges include the original instruction
  semantics, nargs and checked/unchecked entry, frame/root/poll points, source
  diagnostics and opaque C/FFI boundaries.
- HostId and label ordinal mapping, exact resource read/write sets and effective
  optimization/host policy are explicit compilation inputs. ModuleSpec/FrameSpec
  and code layout come from the same authority; native code cannot carry an old
  frame map under a new plan identity.
- Proven GVM normalization removes domain-redundant CFG/check/representation work
  before GCC has to rediscover it. Existing dead/jump/common cleanup remains; the
  next-label>300 common-code guard in _gvm.scm1105 is a real sparse-budget example,
  not proof that the actual package frequently hits it or gains large time.
- Host topology is an explicit policy, with current topology as the zero-gain
  control. Different policies require exact group resource unions, compatible
  label order and a cost contract for every cross-host transfer. There is no
  automatic SCC-only, per-procedure or fixed256-label partition selection.
- C emission consumes the closed plan and replaces the corresponding implicit
  macro decisions. Merely printing the same expanded C, adding plan validation
  to old preparation, or renaming BEGIN_COD supplies no demonstrated gain.

This reaches the representation processed by the larger native phase and can
apply to ordinary modules, not only large literals. The hypothesis is reduced
native optimization/CFG work without lowering program optimization. It is still
a hypothesis: required work that remains includes actual Scheme computation,
GC-visible roots/frames, polls, multi-shot continuation, native labels, FFI and
required module initialization. Added Scheme planning, resource analysis, code
layout, snapshot validation, transitions, code size and ABI rebuilds are charged.

** Cold2x composition and stopping rule

For the selected ordinary timer snapshot, preprocessing-only and parsing-only
mechanisms are inadequate even before new costs. A credible cold2x composition
must shorten unavoidable ordinary native optimization input over a broad actual
critical span, cooperate with earlier phase readiness, and retire eligible native
reconstruction/link work beyond existing fixes. A cold all-miss cannot borrow an
incremental cache HIT as its saving. No current two-package cost join establishes
that coverage or the required local reduction. A claimed full-plan gain remains
unresolved until those actual weights and semantic/resource costs are supplied.

If the only proved changes are smaller constants, header organization, plan-key
bookkeeping or a host split that increases execution work, this design fails as
the twofold vehicle. The target is retained; the current mechanism receives no
unearned forecast. This is an architecture selection gate, not a request to run
another unchanged trial or keep refining micro-macros indefinitely.

** Numeric threshold for a credible >=2x architecture

For ONE actual disjoint critical-path accounting, let T=U+C be baseline time,
where C is time covered by the redesign. Let Tnew=U+Cprime+A, with uncovered
work U unchanged and all new costs A>=0. Then:

#+begin_example
>=2x  <=>  C >= U + 2*Cprime + 2*A
If Cprime=C/k, f=C/T and a=A/T:
f*(1-1/k) >= 1/2 + a
#+end_example

This is a conditional consequence of the existing DevelopmentBenefit balance
laws, not an additional timing model or a source-equivalence proof. Under the
optimistic A=0 assumption, the following necessary coverage is exact:

| Local improvement k of the covered region | Minimum covered fraction of the same request critical span | Consequence |
|---+---+---|
|2x |100% |Any positive uncovered/additional work prevents whole-request2x |
|3x |75% |Needs most of the request to be covered, not setup-only counts |
|4x |2/3 (66.67%) |Still requires broad real-time coverage |
| Infinite / zero remaining covered time |50% |Even ideal elimination cannot halve a minority region |

For A>0, the required fraction increases by a/(1-1/k). Cache misses, snapshot
validation, factory/runtime compilation/loading, fixup interpretation and ABI
rebuilds are costs; ongoing runtime-call overhead is also a correctness/product
tradeoff and cannot be hidden outside the acceptance workload.

The D855 historical capacity obligation is still188.510 worker-s before other
work/new costs. The D857 isolated embedded C-to-object~12.04->3.93s result is
one target/module atomic observation; D858 rejects its header-only whole-package
transfer. Neither local factor can be assigned to ordinary modules or multiplied
by543 jobs. Later source-loader/driver/object reuse reduces the current baseline;
those historical improvements do not supply fresh contribution to this plan.
