* Benefit accounting and counterexamples
:PROPERTIES:
:CUSTOM_ID: DARWIN-AUDIT-NET-LAW
:END:

Use =Tnew = B - E - O + A= for one fixed workload and resource/schedule projection.
=E= is omitted exclusive critical-path work, =O= newly verified overlap beyond
that baseline, and =A= all validation, dispatch, context setup, storage, retention
and schedule-interaction cost. Twofold requires =E + O - A >= B/2=.
The signed balance is a refinement obligation; it is not established by choosing
values for the equation. Keep CPU work, wall span and memory as separate units.

| Mechanism | Real structural leverage | Present credit against optimized control | Counterexample / required cost |
|-----------+--------------------------+------------------------------------------+--------------------------------|
| Existing GCC macro tracking suppression | Avoids expensive diagnostic expansion bookkeeping | Zero new credit | Already in control; allocation reduction is not elapsed gain |
| Existing spawn/fd and literal command construction | Removes qualified launch preparation and shell subprocess work | Zero new credit for retained baseline gains | Unsupported launch semantics retain fallback; eligible action count and time remain needed |
| Runtime/static C and object reuse | Can omit duplicate generation and compilation in an executable graph | Zero for merely restoring0007 | Valid identity, read/write ordering, invalidation and verification costs remain |
| Sealed stage products and consumed-projection reuse | Can omit repeated exact semantic/native actions on valid hits | Unmeasured | A first cold miss cannot reuse nonexistent products; persistence validation and changed effects cost time |
| Frontend process retirement | Separates expansion lifetime from GCC memory demand | Feasibility evidence, not acceleration seconds | More interpreter startups and lost pipeline overlap can regress Darwin span |
| Resource-order admission | Bounds overlap of unqualified large generated units | Feasibility/correctness only | Serial order may increase critical span; 12 configured workers are not12 useful CPU cores |
| Selective phi host fallback | Large connection~1 C can compile under observed capacity conditions | Calibration only | One large procedure remains unbounded; censored old failure has no speedup denominator |
| Native runtime-command product | Could remove unnecessary expander/provider loading | Hypothesis | Executable is currently absent; exact provider path and omitted import closure must be proven |
| ModuleImageSpec / stable generated-C ABI | Could remove repeated private-layout/interface construction | Future architecture only | Not the current14-file source implementation; semantic and consumer migration remain open |

The26.907860s historical preparation complement has no exclusive macro/dyld
owner. It cannot be allocated to a proposed mechanism as "recoverable time".
One-second fcntl stack samples cannot be multiplied by thirty-second command
timeouts. A shared optimization benefits Darwin more only under a proved
relative reduction; it is not automatically a Darwin-specific gap reduction.

* Five-component architectural interpretation
The generated component inventory below is the existing longer-term blueprint.
The two PRs implement selected phase, executor and command cuts, not all five
components. A full new GVM/FrameSpec/ModuleSpec ABI is not a prerequisite for the
current Darwin line; GC/SMP remains outside it. Retirement means removing an old
producer/authority after all real consumers migrate, not layering a second cache
or a second executor above it.
