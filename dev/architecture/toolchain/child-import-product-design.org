* OPEN One selected path: SealedInterfaceProduct
:PROPERTIES:
:STATUS: Architecture hypothesis; existing generic-expansion boundary, no major removable budget proved
:END:

One compiler-produced product has two projections, not two independent caches:

1. DependencyProjection records canonical module identity, nested module root,
   phase-labelled imports/reexports, output roles and complete observed inputs.
   Planning may read it without constructing a live ModuleContext only where
   planner-observable effects are absent or independently preserved. Unknown
   reader/macro/eval/I/O effects refuse reuse. The current eager initializer
   order cannot silently change under the name of incremental compilation.
2. InterfaceConstructionProgram replaces repeated generic SSI preparation and
   dispatch with ordered operations against a fresh private context. It retains
   import-record allocation, binding callbacks, marks, properties, positive-phase
   execution, atomic delayed evaluation and context-correct compiler-facing code.
   First-stage effects precede deferred exports. Native phase code is imported
   as before; it is not serialized or regenerated for this product.

The existing emitter derives both from successful expanded code and a closed
input/effect trace. Keys bind source, reader/prelude/provider/declaration state,
phase, search order including negative lookup, compiler/runtime ABI and observed
external inputs. Validation and publication must refer to the same snapshot.
Any unknown completion retains private custody and publishes no success. Failed
production has no reusable result. Duplicate responses cannot initialize again;
a real later execution has a new request generation. Retained products need
GC-updated roots and module/descriptor leases, not raw context pointers.

The native C23 portion initializes immutable payload before release publication;
an acquire reader must obtain a storage pin with a proved non-reclamation
protocol. A raw acquire load is not such a pin. Root registration precedes any
collecting allocation; closing admission cannot reclaim while instances,
continuations or unknown work still hold roots/descriptors. C23 atomics cannot
prove Scheme purity or eliminate required phase execution.

This differs from the denied72.213895s whole-context memo: it does not cache
resolver answers or share initialized records. It also differs from raw AST
restoration, quoting an unexpanded SSI, declaration-only deletion and phase
serialization. The existing interface-transfer report already leaves this full
fresh-instance program open for analysis; this document narrows its consumers,
not claims discovery or implementation admission.

A fully cold all-miss package pays product construction and sealing. Reusing a
prebuilt SDK product is a declared cache state, not proof of cold all-miss gain.

when it has not changed the consumed macro/interface/ABI/effect projection. A
shared macro change invalidates its actual expansion consumers. Failure/unknown
results do not close completion barriers as successful output.

* OPEN Net-return and Darwin excess matrix

Let D,L be qualified same-scenario baseline wall times, with retained fixes.
Let gD,gL be actual net critical-path savings after validation, new instantiation,
publication, storage/lifetime and any producer compilation/loading costs.
Then Dnew=D-gD; self-speedup>=2 requires gD>=D/2.
The Darwin/Linux ratio shrinks exactly when gD/D>gL/L (positive remaining times).
This distinguishes absolute gap reduction from ratio improvement.

| Scenario / mechanism | Work truly removable if qualified | Added or retained work | Credit now / missing evidence |
|---+---+---+---|
| No-change or graph-only request | Live interface read/expand/resolve required only to discover unchanged graph | Product validation, actual build.ss effects and result checks |0 demonstrated seconds; actual planning import share/effect-neutrality OPEN |
| Leaf incremental request | Unaffected phase/C/native products, not merely moved before timer | Changed module phases, invalidated consumers, joins |No12x multiplier; complete two-package stage footprint OPEN |
| Fresh process with matching interface program | Repeated generic interface preparation and dispatch | Fresh context/imports/bindings/phase effects, factory load and validation |Reached mixed4.670305s probe, not a removable budget; dispatch cost OPEN |
| Fully cold all-miss | No prior-product reuse guaranteed | Original required work plus sealing/compiler costs |May regress; cannot claim2x from reuse alone |
| Darwin excess | Eliminated eligible calls remove their actual Darwin cost; higher per-unit excess disappears only if bound to those same calls | Matched Linux cost, schedules and platform residuals |Existing reports do not isolate that differential; no numeric residual ratio |
| Combined native pipeline | Retire reconstruction/transport after BuildMetadata/native contract closes | Actual object/bundle/link work and producer costs |No re-credit for0015,187 loaders or D851; whole-package2x remains OPEN |

The import probe cannot be added to or subtracted from a different historical
complete-build cohort. Even its full interval is not a proven removable budget.
Current guaranteed positive timing credit is zero; that is an evidence limit,
not proof the architecture has no value. A twofold package claim needs a
same-scenario critical-path composition beyond prefix work.
