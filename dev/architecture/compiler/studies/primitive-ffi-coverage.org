*** 1. Coverage Universe and Decisions
:PROPERTIES:
:ID: 5c9bf583-52cc-595b-8760-5bbc7050c878
:CUSTOM_ID: 1-coverage-universe-and-decisions
:END:

The pinned ~vendor/gambit~ commit is
~7c490c3ab5b5a4238b26f4a59d8cd9fd4b085882~. Paths/line numbers below are
relative to that directory. The inspected ~_prims.scm~ literal database has
1,588 records and 1,587 distinct names, with an identical duplicated ~##values~.
The C target adds ~##c-code~ (~_t-c-1.scm:294-300~), giving 1,588 distinct
names across these two inspected registration sources. The catalogue preserves
each record, source line and all six metadata fields.

This is a complete census of those registration sources, not of all Gambit
procedures or forms. Libraries, generated ~c-lambda~ procedures, macros and
other targets extend the universe. Unknown names must be represented as
ordinary calls with unknown effects until resolved, or reject the requested
profile if no correct callable lowering exists. Never treat absence from the
database as absence of effects or erase an unknown call.

Use four independent coverage dimensions per exported call site:

| Dimension | Required record | Decision when missing | Source basis |
|-
| Identity | Resolved binding, target primitive identity, declaration and guard policy | Ordinary dynamic call; no primitive rewrite | ~_ptree1.scm:556-573,629-648~; ~_ptree2.scm:190-240~ |
| Semantics | Arity, values, numeric/type behavior, memory/control effects and identity | Conservative opaque operation; no semantic optimization | ~_prims.scm:17-22~; ~_gvm.scm:149-220~; counterexamples in section 2 |
| Lowering | Exact runtime-call entry or reviewed intrinsic/FFI path for this artifact role | Reject semantic profile before artifact construction | ~_back.scm:288-301~; ~_t-c-1.scm:302-312~; native contract |
| Transformation | Pass-specific proof conditions, valid summaries and assumptions | Preserve operation and reject that transformation | ~_ptree2.scm:1465-1505~; pass matrix |

*CAT* means metadata catalogued. *Rule specified* means the semantic design
below supplies a rule. Neither means a lowering or pass is admitted. There is
no implemented MLIR support in this research collection. A preserved runtime
call still needs correct Gambit call/frame/root lowering; it is not an arbitrary
platform C call.

The database has 1,287 ~side-effects?=#f~ rows, including allocation and mutable
reads. The C ~targ-apply-cons~ path explicitly reserves/checks heap space while
using ~side-effects?=#f~ (~_t-c-2.scm:2606-2639~). This is direct evidence that
copying that Boolean into MLIR ~NoMemoryEffect~/~Pure~ would be an invalid
translation. ~strict-pat~, ~lift-pat~, ~type~ and ~dead-end?~ are likewise distinct
legacy facts, not a complete effect/termination contract.

The specializer/expander/simplifier infrastructure remains valuable, but its
closures mutate parse trees/procedure objects. ~_prims.scm:6342-6357~ even marks
several folder predicates with TODOs about C-backend dependencies. Reuse semantic
rules and target descriptions after making dependencies explicit; do not claim
the existing Scheme closures are already portable MLIR rewrites.

**** 3.1 Two Export Surfaces Are Required
:PROPERTIES:
:ID: bc289f73-1ef6-5f21-a028-ede0478a0b16
:CUSTOM_ID: 31-two-export-surfaces-are-required
:END:

The pre-normalization hook is correct for the resolved Scheme tree, but it is
*not sufficient to reconstruct typed FFI*. ~parse-program~ calls
~c-interface-end~ before returning (~_ptree1.scm:894-907~). That function returns
only declarations/procedures/initializers/objects and clears types/converters
(~_ptree2.scm:2093-2112~). ~make-c-proc~ retains Scheme name, C name, arity and
generated body, not the original typed signature (~2171-2182~).

Select a structured FFI side record *during parsing*, at ~add-c-type~,
~build-c-lambda~, ~build-c-define~ and initializer/declaration collection. Resolve
and capture types while that registry exists. Associate generated names with
logical procedure IDs, exact C text dependencies and the semantic module.
Return that immutable record alongside the tree export; do not reverse-engineer
generated C or retain pointers into the cleared registry.

This adds information preservation to Gambit's parser/FFI producer. Existing
wrappers can remain the chosen C island for compatible runtime profiles. The new
service-to-island call path still needs qualification. If neither wrapper
integration nor direct lowering is specified, reject the semantic compilation
request and report the unsupported form; the independently selected existing C
profile remains available. No silent partial compilation or runtime fallback is
authorized by the coverage classification.

**** 3.2 Foreign Effect Contract
:PROPERTIES:
:ID: d71ca4a9-adc0-5295-b730-db34e23f5594
:CUSTOM_ID: 32-foreign-effect-contract
:END:

Each foreign entry needs a signature and an independently sourced effect record:
memory access/aliases, Scheme allocation/GC, callbacks, exceptions/nonlocal exits,
blocking/yielding, pointer retention and required release actions. A named C
function is not automatically a leaf. Missing facts receive the conservative
summary in the effect contract.

The baseline header's fixed ~GC_SAVE1/RESTORE1~ slots (~8059-8076~) are not a
nestable root-stack API. Its SFUN macros create/kill markers and propagate errors
(~10043-10060~); CFUN cleanup uses the configured try/end protocol
(~10375-10378~). Preserve those mechanisms in reused wrappers. A new Zig ~defer~
or C lexical scope is not an equivalent nonlocal-exit protocol. Runtime overlays
may add further requirements; matching only these baseline macros is insufficient
to admit a candidate runtime generation.
