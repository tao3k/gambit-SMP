* RESEARCH Distinct cuts and ownership
:PROPERTIES:
:CUSTOM_ID: membership-cuts
:STATUS: target-contract-open
:END:

Let M(e,g) be the required root-carrier membership for collection e and membership
generation g, W(e,p,r,t) the worker team, and A the accepted work/transfer domain.
M, W and execution contexts need not have equal cardinalities. A frozen member
set does not yet mean published final root values. A zero queue size does not
mean A is empty. These are definitions of the target interpretation, not claims
that the current processor_count has already been separated.

#+NAME: membership-cut-matrix
| Cut | Closes | Still permitted / required | Necessary law |
|---+---+---+---|
| Freeze membership | External membership insertion for this cut, serialized with pending admissions | Existing members publish final roots and acknowledge; no wait for root scan to finish before membership freeze | MemberFreezeLaw |
| Seal roots | Final values/writer census for every frozen required carrier | Scanner acquires descriptors; accepted moving updates later require reload before reentry | RootSealLaw + existing participant acknowledgement |
| Announce phase revocation | New acquisitions and new external producer rights under one gate | Already admitted producers retain scoped drain rights, including accounted child derivation and pending publication | RevocationAnnouncementLaw |
| Withdraw one worker | New acquisitions by that worker incarnation | Finish its work or transfer complete restore state and debt to an accepting live custodian; other workers may continue | WorkerWithdrawalLaw |
| Effective phase revocation | Old scope's remaining grants, publishers, readers and unresolved transfers, after existing phase drain | Publish a separately identified successor; never mutate old scope into a new generation | RevocationEffectiveLaw; PhaseAdvanceLaw |
| Retire resize backing | Execution entry, root membership, worker use and target-specific late issuers | Release only the actual permitted target after native termination/last-use evidence and single consumption | ResizeRetirementLaw + existing removal/permission/consumption laws |

A membership insertion racing freeze either commits into M before the cut and
must acknowledge, or is refused/deferred without managed access. A genuinely
future context can defer only if it holds no root needed by this collection and
cannot enter before the next admission. A newly discovered *currently relevant*
root after seal is a census failure, not ordinary future work. Before moving or
observable copy effects, restart is conditional on retaining roots, revoking and
draining every affected old grant. After relocation starts, no general restart
or next-epoch repair is established. Reclaim/resume permission remains denied;
retaining memory cannot retroactively protect an unregistered stale raw pointer.

Single-worker withdrawal does not require global phase drain. Its release
receipt must bind VM, worker incarnation, complete cursor/copy/Tail/acquired-chunk
state and accepted destination. Effective phase revocation does require complete
phase drain. In CollectorWorkContext, teamGrantLive denotes a custody/drain lease;
it is not the new-acquisition gate. A revoke bit cannot invalidate pointers
already loaded by a scanner.

#+NAME: membership-late-work-matrix
| History | Acceptance / custody rule | Failure to avoid |
|---+---+---|
| External request wins before close | Accept and count before publication becomes visible; close must include it | Check-open / close / enqueue with no outstanding debt |
| External request loses to close | Refuse this scope; pending disposition retains valid prior custody and debt | Silently drop required work or a raw pointer |
| Admitted parent derives after external seal | Reserve child before parent release; commit acceptance with a drain lease while phase remains live | Revoking drain rights first, then waiting for the stranded parent |
| Publisher accepted before close, bytes arrive later | Keep publication user/debt until an observed acceptance or known failure; full scope must match | Phase finishes between queue commit and receipt |
| Dequeue races worker withdrawal | Queue removal atomically transfers debt to scanner or an accepted successor | Empty queue interpreted as completed scan |
| Transfer outcome unknown | Source/transfer custodian and prior lease remain live; retain debt and reconcile identity | Blind retry duplicates work or both ends free the payload |
| Old phase packet after effective revoke | Reject before dereferencing old backing; independently retain any valid prior custody | Matching collection epoch used to accept stale phase/team/producer generation |
| Root relevant to current cut appears late | Fail the completeness premise; do not issue completion/reuse permission | Re-label current raw alias as future-epoch work |

The scope key is (VM, VM generation, collection, root cut, phase, round, producer
generation, team identity, team generation). Every accepted record must match
coherent authority for that key; stable immutable handle resolution must precede
payload dereference. Finite native identifiers need non-wrap/ABA and handle-table
lifetime arguments. A thread-local cached copy of an old coordinator scope is
not coherent authority.

** Conditional no-reopen argument
Assume a complete member and producer census; serialized admission/close; a
complete disjoint ledger for private, queued, scanning, reserved-child and
transfer work; live leases for all publishers/readers; and child acceptance
before parent settlement. At effective revocation, all origins of later work
are excluded: external admission is closed; no admitted producer retains a
right; no private/queued/acquired/reserved/transfer obligation remains; and no
publisher can expose a previously unobserved acceptance. Thus a new valid task
in the identical scope contradicts one of those premises. Rejected stale records
cannot restore the scope or authorize backing access.

This is a conditional safety argument. [[https://www.cs.utexas.edu/~EWD/transcriptions/EWD06xx/EWD684.html][Dijkstra–Scholten's termination analysis]]
accounts computation messages and return signals and assumes bounded diffusion.
The lesson for Gambit is to count accepted derived responsibility until it is
settled, not to copy a distributed algorithm literally. Applying that reasoning
to shared-memory publication, forwarding winners, weak processing and foreign
effects requires the additional source refinements above. No such refinement
is proved here.

Progress separately needs finite production, eventual scheduling/delivery,
well-founded internal progress and no wait cycle. Close may stop new acquisitions
but must leave a drain executor or accepted transfer route. A parked participant
must publish roots before awaiting GC; a withdrawing worker must not await a
receipt from an owner blocked on that worker's untransferred task. Unknown
outcomes can block permission indefinitely; a timeout does not prove absence.

* OPEN Modern C memory-order obligations
:PROPERTIES:
:CUSTOM_ID: membership-memory-order
:OWNER: modern-C runtime and platform adapter
:OBLIGATION: native-access-and-lifetime-refinement
:END:

The design relies on release/acquire observation of the same synchronization
object or an equivalent proven lock protocol. Conflicting non-atomic accesses
without happens-before are not repaired merely by surrounding them with fences.
These constraints follow from [[https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf][N1570 §§5.1.2.4, 7.17.4]]; concrete mechanisms below
are proposed obligations, not an evaluated atomic implementation.

#+NAME: membership-memory-order-matrix
| Boundary | Required order / linearization | Source correspondence / unresolved part |
|---+---+---|
| Enroll vs freeze | One serialized commit decision; publish member descriptor before acquired census observation | setup.c processor-count collective is a baseline, not a complete dynamic registry |
| Final roots vs scan | Root writes and acknowledgement release precede scanner acquire; exclude every admitted writer; retain descriptor | mem.c strong root entry plus existing ROOT-HANDOFF; final-value/root-location closure remains open |
| New task vs revoke | Gate decision and accepted credit are one protocol; failed post-effect result retains transfer custody | A relaxed Boolean checked before an unrelated queue push is insufficient |
| Chunk payload vs visibility | Initialized scan inputs and accepted debt precede release publication; acquiring consumer observes them before scan | Preserve end_heap_chunk old-link / first barrier / tail / second barrier obligations until every reader path is mapped |
| Queue removal vs scan completion | Removal transfers debt; last-use and acquired scan completion precede settlement | scan_complete_heap_chunk occurs after unlock; not covered by empty-queue observation alone |
| Phase zero vs wake | Check a coherent zero-debt/closed-producer predicate with admission serialization; wait in the protocol's predicate loop | Existing worker count and condition signal are not certificates for newly introduced asynchronous producers |
| Effective revoke vs reuse | Acquire final drain evidence, prevent new stale-handle resolution, wait all prior readers, then release backing | An atomic revoked flag alone provides no grace period |
| Result vs reentry | Publish committed relocation and terminal capacity result; context acquires, reloads and invalidates aliases | Coherent capacity failure may still require Scheme error delivery; do not require allocation success to resume that path |

Current __sync selection uses compiler predefines and word size. [[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][GCC documents]]
__sync_synchronize as a full barrier and most legacy __sync operations as full
barriers, with exceptions. That does not by itself certify the complete
volatile/ticket-lock fast path, platform emulation or all queue reads. The actual
Darwin/GCC macro branch, supported compiler extension semantics, lock behavior,
identifier width and all participating accesses remain qualification inputs.
Choosing modern C atomics requires redesigning the access protocol, not merely
renaming these macros. No current native data race is asserted by this study.

Dependencies in SysML are conjunctive proof obligations. They do not instantiate
satisfaction or generate a behavior. Work/identity/credit numbers are mathematical
integers; native finite widths and concurrent snapshots require separate proofs.

[[file:../../../../models/library/gc/CollectionContract.qnt][CollectionContract.qnt]] already guards terminal actions with not(done). It
has one object, two roots, stopped mutators and atomic visibility; its old direct
finish→rescan trace is excluded. [[file:../../../../models/gambit/gc_work_closure.qnt][gc_work_closure.qnt]] is a supporting two-worker,
two-object/two-phase slice, not the full dynamic membership/revocation protocol.
[[file:../../../../models/gambit/lean/WorkAccounting.lean][WorkAccounting.lean]] proves zero-count exclusion only under producer-lifetime
coverage; its missing-lifetime counterexample prevents using count=0 alone.
[[file:../../../../models/gambit/lean/SavedStackRetirementWindow.lean][SavedStackRetirementWindow.lean]] retains stable-window/ordered-reuse premises.
Neither proves C weak-memory refinement or whole-protocol progress.

Every real source transition needs a matching model step or justified stutter,
including failed acquisition, partial publication and late callback. A separate
well-founded rank must rule out infinite stuttering. Behavior design must retain
positive draining histories as well as the negative sketches below; making all
steps disabled would satisfy safety vacuously. Existing report classes are
retained: CONTROL-ORIGIN's selected QNT is not covered by its Lean report; the
selected GC binding has no admitted scoped validation report.

#+NAME: membership-benefit-matrix
| Change | Work that can disappear | Added necessary work | Positive-net-benefit condition / refutation |
|---+---+---+---|
| Separate M and W | Participation/worker-policy coupling and unnecessary worker retention during resize | Membership snapshot, incarnations and a complete root census | Saved coordination/retention exceeds snapshot/admission costs; no benefit if every policy needs the same fixed team |
| Explicit per-worker withdrawal | Requiring a whole phase stop merely to move a worker's responsibilities | Complete restore/handoff, acknowledgement, retained unknown outcomes | Transfer is cheaper and progresses; refuted by per-task handoff overhead or no useful policy change |
| Phase closure shared with publication | Duplicated guessed-empty decisions and repeated defensive rescans caused by unclear custody | Gate/credit publication, coherent zero cut and publisher/read leases | Removes demonstrated redundant work; refuted if centralized contention exceeds avoided work or old path already provides it |
| Target-specific resize retirement | Retaining unrelated resources until an unnecessarily global shutdown | Per-target last-use census and permits | Relevant retention is actually bounded/reduced; extra metadata without earlier safe release provides no demonstrated gain |
| Preserve existing parallel copy/steal | No new benefit claimed for functionality already present | Adapt existing queues and worker accounting to new roles | Benefit is only incremental decoupling, never credit for inventing parallel GC |
| Mandatory roots / copied live payload | Exactly 0 required root visits and 0 necessary payload words removed by role separation alone | Descriptor resolution/lease checks may add work | Any scan/copy reduction needs a separate generational/barrier/coverage proof |
| Zig implementation alternative | No Scheme root, scope, lifetime, weak-memory or cancellation obligation automatically disappears | Additional language/toolchain/ABI boundary unless a named C support path retires | Zig-specific net benefit is unestablished; shared modern-C modernization is insufficient justification |

For matched semantics define A = avoided coordination + avoided redundant scans
+ reduced policy-induced idle time, H = added registry/gate/lease/handoff/drain
CPU cost. A time benefit requires A > H without shifting the debt into unbounded
latency or retention. Model space as O(|M| + |W| + |in-flight transfers|), plus
existing work queues; this is a logical representation bound, not a requirement
for one allocation or atomic increment per root/edge. Peak-memory improvement
requires released retained bytes > new metadata + still-retained uncertain work.
Pause, throughput and peak memory are separate dimensions, not one summed score.
No numeric speedup, percentage or number of barriers eliminated is established.
Batch/worker aggregation is a candidate only if it preserves the complete ledger.

#+NAME: membership-retirement-matrix
| Migration gate | Old responsibility eligible for replacement | Prerequisite / reason still retained now |
|---+---+---|
| Complete M snapshot and acknowledgement | processor_count as implicit root-participant census | Real root/writer/FFI membership and reload proofs; source uses remain live |
| Worker task custody + transfer | PSTATE identity as unique private cursor/chunk/Tail custodian | Complete copy/scan restore and exactly accepted handoff; preserve existing copy algorithm |
| Phase admission + common drain | Bare worker-count/queue emptiness used as a future generalized completion authority | Complete producer census and C publication refinement; do not remove current working count merely on a structural model |
| Target-specific removal/last use | Combined cleanup/count-change/join as the only lifetime boundary | Partial setup/create/join failures and native users explicitly accounted; preserve current error behavior until replaced |

Eight new laws are OPEN; zero runtime paths are retired. Next research must close
actual member/writer inventory, per-worker publisher/reader census and a concrete
C acquisition/close protocol before claiming a target QNT refinement. Runtime
implementation, native tests and performance verification are outside this task.
