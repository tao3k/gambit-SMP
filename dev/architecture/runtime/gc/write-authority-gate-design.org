* Fixed layout and atomic state machine
** Bit budget and representable range
#+NAME: native-scope-word
| Bits | Meaning | Invariant |
|------+---------+-----------|
| 0 | closed | CAS closes future registered role acquisition |
| 1..8 | live roles | Each granted role remains until its actual last use |
| 9..16 | spent roles | Monotone for a generation; released role cannot be reused |
| 17..24 | actor | Exclusive pre-registered activation id 1..255 |
| 25..WORD_WIDTH-2 | generation | Checked increment; exhaustion refuses |
| WORD_WIDTH-1 | sign | Zero; C shifts/conversions remain representable |

A record has no pointers or Scheme roots. The compiler asserts one WORD of
storage. Default 64 slots require 256 bytes for 32-bit WORD or 512 bytes for
64-bit WORD, before any possible surrounding-VM ABI padding effects. Current
Darwin arm64 object compilation checks the 64-bit layout; no 32-bit native
qualification is claimed. The generation maxima are 63 and 274877906943.
These are real finite limits, not a hidden wrapping counter.

Roles 0..3 cover control writers and 4..7 data writers. The owner initially holds
roles 0 and 4; three delegates remain per class. Each role has one producer per
generation. Permits track write lifetime; they do not serialize overlapping
plain-field writes. A declared write set must be disjoint, exclusive or protected
by its own atomic/lock protocol. Last-use, role assignment and immutable helper
intent are caller proof obligations, not facts manufactured by this primitive.

** Linearization and unknown results
:PROPERTIES:
:CUSTOM_ID: native-scope-linearization
:END:
1. Prepare the candidate tag from the previous exact tag and exclusive actor
   identity. Retain that intent in stable storage before invoking handoff.
2. Handoff CAS succeeds only on the exact previous tag, closed gate and empty
   live set. One CAS advances generation and installs both owner class permits.
   There is no open unaccounted owner before a lost response.
3. Acquire reads the whole word and CASes the same word with live/spent role bits.
   Close in between invalidates the CAS. A stale reader retries all guards; a
   separate open check followed by an increment is not used.
4. Close CAS sets the closed bit and preserves existing permits. It stops future
   acquisition, not already running writes, callbacks or an OS thread.
5. Release clears exactly one live bit for the current tag and retains its spent
   bit. Repeating release is a no-op; the role cannot be reused in that generation.
   A stale-generation release cannot clear the successor's corresponding bit.
6. A successor again needs the previous helper's own drained closed header.
   Original owner closure is insufficient. Unknown writer outcome leaves its
   bit live. No dead flag, timeout, ignored/failed join or arbitrary reset clears it.

Snapshot/class-quiescent results are instantaneous observations of registered
permits. They are not reservations, physical-stop receipts, result ACKs, root
freeze receipts or permission to destroy the VM. A =STALE= result says nothing
about historical delivery. A =REPLAY= tag observation authorizes no second native
initialization. Separate result/scan/reader custody still governs reclamation.

The first implementation reuses Gambit's backend full-barrier RMW/CAS operations
and handles the explicitly sequential backend without PSTATE scratch fields.
This removes service dependence on a processor just for atomics; it does not
redesign the shared synchronization backend. The emulated mutex backend has no
arbitrary lock-owner-death recovery. Full-barrier reads generate cache-line
traffic; hardware retry count and starvation are unbounded by these models.
A later C11 acquire/release backend needs independent C/ISA refinement first.

* Why refactoring can address the remaining four contracts
:PROPERTIES:
:CUSTOM_ID: native-scope-modernization-value
:END:
The objective is to replace implicit ownership and global phase coupling in real
consumers. Passing one gate primitive cannot establish the following outcomes.
The SysML milestone targets keep the separate causal chains explicit:

- Lifecycle: transactional member construction/rollback, canonical actor and
  source custody, real last-use/termination evidence and delayed cleanup must
  replace PSTATE-lifetime assumptions. Existing retained cleanup is already a
  repair; new credit requires eliminating duplicate distributed state and
  qualifying the still-open natural recovery/old-handler paths.
- GC/FFI: precise FrameSpec roots, a complete RootRegistry, safe constructor and
  marker publication, and native park/reload participation must connect all
  writers to GC. Then generational collection can skip proven unchanged mature
  graphs. This patch supplies no root cell, barrier or minor-GC saving.
- Gerbil: the retained structure type-field fault has unresolved causes. Find
  its actual producer/ownership violation before attributing it to GC/SMP or
  selecting a fix. A guard that hides bad objects or a new native scope is not
  a source-causal crash repair. Complete downstream builds/tests remain required.
- Performance: the numerical C compilation cap and whole release latency/build
  gates require compiler/build/runtime work decomposition. Generated native
  contracts, correct smaller units, dependency snapshots and AOT reuse must
  eliminate actual expansion/compilation; CAS safety does not shorten GCC parse
  work or certify a whole-consumer speedup.

Net benefit requires replacing the old responsibilities, not indefinitely
maintaining the new scope service beside all old VM/PSTATE counters. The matrix
states each retirement condition and the remaining original acceptance inventory.
The milestone remains 8/12. Neither a model pass, object build nor this source
commit increments it. A fundamental solution is a source-refined replacement
and complete observable acceptance, not a promise that refactoring guarantees
all four outcomes regardless of unknown crash causes.
