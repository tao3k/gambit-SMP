* C memory order
| Edge | Required order | Rejected shortcut |
|---+---+---|
| OWNER-PIN | Run Tcl interpreter APIs only on their owner thread; use short bridge lock for pin/close versus GC metadata. | GC worker never calls Tcl delete API. No bridge lock held across Tcl/Scheme callbacks or native waits. |
| DELETE-CUT | Preserve Tcl delete traces before deleteProc; close bridge admission at hook entry, publish close before returning. | Changing the public deletion cut to before traces requires separate semantic change, not claimed compatibility. |
| TOMBSTONE | Pin storage and logical open/generation validation precede data_rc read; retirement acquires actual reader/owner-drain evidence. | Command refCount, Tcl_Preserve(interp) and zero payload pins are three different lifetimes. None alone proves token storage safe. |
| PARK-HB | Stop raw accesses and complete mapped spills precede release PARKED; collector acquire precedes scan/update. | A root registration or borrower counter decrement without complete view/stop proof does not admit independent scan. |
| RESUME-HB | Collector relocation and context/binding preparation precede release resume seal; owner acquire reloads mapped roots before same-call use. | No re-evaluation of Scheme inputs, duplicate native invocation or reuse of old raw fp/hp/SCMOBJ copies. |
| RUN-CLEANUP | Outer catcher restored before canonical cleanup; claim, marker clear, count drop, root retirement and status delivery have explicit progress. | The existing no-allocation kill body is source material for effect qualification, not proof of concurrent atomicity or idempotent decrement. |
| FAILURE | Known cleanup failure retains duty; unknown write/count outcome requires stop/result settlement before reclamation or replay. | C longjmp state and object lifetime must refine actual C ordering; no timeout clears uncertainty. |

* Benefits and added overhead
| Capability | Removed work | Bound | Added cost | Positive condition or falsifier |
|---+---+---+---+---|
| Tcl payload lifetime | Avoid retaining payload merely because Command structure remains referenced | Closed+zero accepted pins can release payload separately from token | Entry pin/close transitions and deferred last-pin release | Owner profile, result custody and no raw reader must close first. No measured speedup. |
| Tcl token lifetime | Avoid UAF in late or captured entry | Tombstone metadata remains until dispatch/owner quiescence | Potential long-lived token metadata and registry lookup | Unbounded token/producer history means no bounded total memory theorem. |
| Self-delete | Remove self-wait cycle in deleting callback | Delete hook waits for 0 callback pins: no waiting is permitted there | Deferred release and outer callback retirement bookkeeping | No callback, cleanup or Tcl event pump under bridge lock. |
| Parent location reuse | Reuse mapped source locations instead of copying every root | 0 duplicate value evaluations/native calls on qualified retry | Freeze/reload, map validation and activation pin | Cannot reuse an unmapped raw C local or unknown borrower. |
| Run root payload | Explicit thunk/marker custody for selected zero-arg run | Illustrative two SCMOBJ slots: 16B at64; nested2:32B | Registry/map/control/native frame and marker allocation excluded | Existing program root or owned-still marker may alias/elide extra slots; not mandatory net allocation. |
| Run error path | Retire normal-only inline marker ownership assumption | One cleanup claimant, marker clear and owned count drop each at most once | VM-canonical progress record and exit-funnel control work | Original error codes, catcher and continuation behavior must remain; native acceptance still required. |
| Still ownership reuse | Reuse positive-refcount marker/vector/converter retention | No forced copying of every stable still payload | Typed ownership transfer and scan/write qualification | Stable address does not imply all root fields or arbitrary owner writes are safe. |
| Peak accounting | Count separate token/root/native backing once | Peak=max_t(unique backing + separate roots/maps + token/native escrow) | Overlap on lost ACK, tombstones and unknown cleanup can increase peak | No net peak reduction or bounded GC latency proved. |
| Retirement scope | Replace real ___run ownership logic before broad FFI migration | Two actual caller families; no external ___run signature change planned | Internal root scanner, marker ownership and producer migration obligations | SFUN/Tcl/raw ___call remain separate next routes; zero retired runtime paths now. |
| Modern C leverage | Share one activation/root/exit contract across runtime and Scheme generators | One language-level runtime contract reused by multiple consumers | Typed metadata and generated effect/location plans | Not another advisory wrapper over unchanged unsafe producer assumptions. |
