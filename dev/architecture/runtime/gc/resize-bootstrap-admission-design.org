The first modern-c cut starts in the generated CFUN /before a movable value is
copied into the resize C API/. Reuse the existing mapped Scheme frame as the
origin; introduce a VM-owned resize transaction with a rooted thunk, exact child
identities, staged membership and failure custody. A root wrapper around run
alone cannot cover the earlier value/sop copies or membership-before-create.

[[file:models/sysml/resize-bootstrap-admission.sysml][SysML]] owns typed root-view rows, five membership roles, creation/rollback
transitions, source obligations, dependencies, research-gate requirements and
cost arithmetic. The collector/barrier membership obligation is owned by
=gc-work=; root-view/admission/failure coordination is owned by =host-roots=,
with typed cross-component prerequisites. [[file:resize-bootstrap-admission-matrix.org][Org matrices]] and [[file:diagrams/resize-bootstrap-admission.d2][D2]] derive from native SysML evaluation.
[[file:thread-thunk-activation-design.org][The predecessor activation study]] is retained unchanged; imported reload,
activation and all-context GC-root duties remain open. The [[file:../../../../evidence/research/resize-bootstrap-admission/checks.json][receipt]] binds the
actual source/model snapshot. No runtime implementation or native test is
performed. Existing vendor changes on modern-c are preserved.

=##cvmr= passes =##startup-processor!= in the two conditional scheduler source
branches. [[file:../../../../vendor/gambit/lib/_kernel.scm::2353][current-vm-resize]] is a c-lambda from =(scheme-object int)= to
=scheme-object=. The ordinary named-procedure route is not evidence that a
movable closure currently fails; raw embedding calls and future movable thunks
need explicit, separately admitted origins.

[[file:../../../../vendor/gambit/gsc/_parms.scm::569][The type table]] identifies scheme-object; both it and int have no cleanup

argument a macro alias to =CFUN_ARG(i)= instead of declaring a separate C value
local. Integer conversion remains a separate operation; its known error occurs
before the resize body and before a new transaction should acquire resources.

[[file:../../../../vendor/gambit/gsc/_t-c-2.scm::122][targ-scan-c-procedure]] spills arguments and the saved return address, forms
a complete call frame, and emits a return label with fs=arity+1, link=fs-1 and
[[file:../../../../vendor/gambit/gsc/_t-c-3.scm::486][all-live map (2^fs)-1]]. For arity two these are fs=3, link=2, mask=7.
This is confirmed by the tracked [[file:../../../../vendor/gambit/lib/_kernel.c::30819][kernel return descriptor]]:

#+end_example

The tracked [[file:../../../../vendor/gambit/lib/_kernel.c::6258][CFUN body]] aliases arg1 to the first mapped stack argument and calls the

These facts close the selected /tracked-source shape/ observation. They do not

that its configuration matches an installed binary, or that FRAME_SPACE has the

performed. The literal physical advance 8 is not a portable frame-size theorem.

** Where location identity is lost

[[file:../../../../vendor/gambit/include/gambit.h.in::10402][CFUN_ARG]] reads through the current PSTATE frame pointer and FRAME_SPACE.
Passing its value into [[file:../../../../vendor/gambit/lib/setup.c::1155][current_vm_resize]] creates a separate raw C parameter.
The function then copies that value into sop.arg[0]. The sync loop and barrier
tree copy the operation into local sop values and sync_op0/1/2 fields before
[[file:../../../../vendor/gambit/lib/setup.c::1025][execute_sync_op]] copies it into vm_resize_pstate's thunk parameter.
The WORD/volatile representation of [[file:../../../../vendor/gambit/include/gambit.h.in::11599][sync_op_struct]] is not a GC root map.

A collector may update the original precise stack slot without updating these
copies. Prefer carrying a stable transaction identity through all sync messages
and loading its registered root at each consuming boundary. The alternative is
to register/update every actual live pointer-bearing copy, including tree and
local copies; this is a larger support surface. Value equality is not location
identity. A pointer to the current CFUN slot is also insufficient because the
Scheme stack may move: a RootOrigin needs logical frame/slot identity, a pinned
view and address reacquisition after restoration.

OP_VM_RESIZE has higher priority than OP_GARBAGE_COLLECT in the current priority
ordering. Do not claim every simultaneous GC precedes resize. The decisive
source window remains the direct capacity GC /inside/ vm_resize_pstate, plus
possible later GC serviced by the worker startup loop.

* Complete root view and custody
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-root-view
:END:

The [[file:resize-bootstrap-admission-matrix.org][typed root-view inventory]] distinguishes storage from values and native
resources. The selected call requires the two Scheme argument slots, saved RA,
current return label, logical frame identity, materialized context, register /
saved / type-cache roots, and the actual processor/thread/denv/continuation root
graph. [[file:../../../../vendor/gambit/lib/mem.c::3898][mark_continuation]] decodes the frame description and scans it;
[[file:../../../../vendor/gambit/lib/mem.c::6854][the strong phase]] also marks register, saved, cache and processor roots.
Thread/denv references use their real graph paths, not an invented independent
copy of the whole dynamic environment.

A full-view receipt must identify all /live locations/, their owner, mapping,
scan/update responsibility, epoch, and raw-borrow exclusion. Native int arg2 is
not an SCMOBJ root; its Scheme source slot is. Temporary C values such as copied
thunk parameters or sop payloads do not become roots by type name. Each temporary
must be dead before relocation, reloaded afterwards, proven immediate/stable, or
explicitly mapped. This includes generated result/error temporaries whenever
live, arbitrary c-code aliases, callbacks, register-held values and embeddings.
The selected signature does not imply a general all-FFI proof.

Acquire the origin only after argument conversion succeeds and the complete
frame exists, before on_all_processors or any possible GC. Metadata allocation
must be non-GC under that valid view or already reserved; failure leaves the
caller responsible. Pending registration does not authorize the parent to destroy its frame on an
exception or continuation escape. Exit must either settle registration and
transfer the full view/root duty into VM custody, or cancel without losing the
existing mapped source. A canonical activation guard owns this handoff outside
modified setjmp locals; the imported TA-SCOPE source duty is not discharged here.
A safe root cell is initialized with a valid value before
registry publication. Parent NativeActivation lifetime pins the view across
park/resume; raw writes must be closed before independent scanning. Imported
source and all-context scanner obligations remain unresolved.

* Registration against a closing GC round
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-gc-gate
:END:

#+NAME: resize-bootstrap-admission-close-cases
| Linearized winner | Storage accepted into current round | Custodian while GC runs | Next action |
|-------------------+-------------------------------------+-------------------------+-------------|
| Registration | Safe descriptor root and snapshot pin | VM registry plus overlapping caller view | Scan/update descriptor; consume only after context-ready reload |
| Close | No new live descriptor root in the closed snapshot | Already mapped, frozen caller view with native lifetime pin | Pending metadata holds identity and safe empty slots; GC updates caller; reload after reopen before acceptance |
| Origin invalid | None | Original caller/embedding remains responsible | Reject managed admission; do not wait with an unrooted value |
| Registration result unknown | Canonical transaction may be accepted or pending | VM/caller overlap remains until exact state lookup | Query same identity; never create a second descriptor or drop source on timeout |

Registration and close must share one lock/atomic linearization domain and an
explicit snapshot/read-pin protocol. Release/acquire pointer publication alone
cannot place a late root into an already closed scan set. The close loser must
not fill an unscanned native slot with a raw movable value, then wait for GC.
It retains the frozen caller location; pending metadata may retain logical
origin identity and initialized empty slots only.

No lock spans the collector rendezvous, callback, OS creation/join or cleanup.
The waiting owner stops raw access, hands over a complete frozen view, and
participates only through admitted VM wait work. Reopen requires scanned root
updates, drained current snapshot readers and prepared owner/context state.
Re-resolve the logical source location and reload its current value before
accepting the descriptor in the next admissible epoch. Root admission does not
require the collector to wait for an uncreated child or an unfrozen owner.

The QNT model covers known register-before-close and close-before-register
histories. It does not yet model loss of the registration result independently
of OS-create result loss. Idempotent canonical registration lookup and source
ACK settlement therefore remain an explicit refinement gap, not a completed
history proof. Source handoff/activation receipt semantics are inherited open
obligations; no late native adoption is justified by the finite model.

* Five membership roles and the real handoff
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-membership
:END:

The five native-evaluated roles are requested capacity, prepared PSTATE,
barrier routing, OS-child binding and committed collector membership. Gambit
already separates requested capacity as mem.target_processor_count_: the GC
uses it to reserve a minimum number of msections before growth. Reuse this
mechanism rather than claim it as a new refactor benefit.

Current processor_count, however, controls the barrier tree and global-root
partition, and changes inside OP_SET_PROCESSOR_COUNT before the OS-create loop.
This conflates staged transport and committed execution/collection membership.
The target is a generation protocol, not five unrelated counters:

1. Keep the old committed rendezvous/collector generation operational while preparing new capacity and safe PSTATE descriptors.
2. Publish stable bootstrap routes and reserve per-child attempt/root leases. These routes are not obligations for uncreated children to join the old barrier.
3. Invoke OS creation once per child generation. Child binding may precede creator result publication; new children wait in an admitted bootstrap state and do not run Scheme yet.
4. Gather exact success, owner binding, current root/context and generation readiness for every requested child. Unknown or failed results cannot masquerade as ready.
5. With GC admission coordinated, collectively switch barrier routing and collector partition/root participants to the same generation. Only then release Scheme entry and perform the post-sync root reload/activation handoff.

Changing processor_count or bypassing one barrier is insufficient. Every
consumer of barrier topology, GC global partition, per-context scanning,
requested capacity and startup synchronization must migrate together.
Preparation failure is not collector membership. The model's abstract
publishRouting step intentionally has no native implementation yet; a concrete
generation switch and its old-generation reader drain remain source obligations.

** Different failure families

#+NAME: resize-bootstrap-admission-failure-matrix
| Event | What is known | Custody and permitted recovery |
|-------+---------------+--------------------------------|
| Argument conversion failure | No resize transaction or OS attempt should exist | Return existing conversion error; caller mapped frame remains authoritative |
| PSTATE setup failure | Some earlier indices completed; failed index may be partial | Per-index phase ledger; complete phase-specific cleanup under VM custody; no blanket cleanup of an uninitialized mem list |
| Known POSIX create failure | That attempt created no child; output thread ID invalid | Retain until descriptor/scan readers drain, release that reservation; successful siblings remain live |
| Child entered before create result | Native execution exists independently of creator bookkeeping | Descriptor/root/physical PSTATE cannot be rolled back from missing creator ACK |
| Create result lost | Child may exist or enter later | Retain VM escrow and exact attempt identity; no retry or PSTATE reuse until real result/stop settlement |
| Failed/unknown join | Termination not established by this observation | Retain physical descriptor/PSTATE/native backing; do not convert to StopReceipt |
| Known partial failure after another success | Exact requested growth cannot commit | Close Scheme-entry admission, abort/drain created children outside GC critical section; do not return silent partial success |

The setup failure source contains a concrete identity mismatch:
[[file:../../../../vendor/gambit/lib/setup.c::946][the rollback loop]] decrements i but repeatedly calls cleanup_pstate(ps) without
recomputing ps for the earlier index. The source proves this pointer/index
relationship. Whether it triggers a particular leak/double-cleanup/crash is
/not/ established by a native test. A replacement ledger must distinguish the
failed partial index from each successfully prepared index and issue at most
one physical cleanup per accepted phase/child.

[[file:../../../../vendor/gambit/lib/setup.c::4572][Setup OS/memory wrappers]] have their own partial cleanup, while setup_pstate
also initializes interrupts. [[file:../../../../vendor/gambit/lib/mem.c::4928][cleanup_mem_pstate]] frees still objects and RC
storage. These are not interchangeable failure endpoints, and RC/foreign cleanup
can introduce further resource/root obligations. A cleanup receipt must state
which effects occurred and who owns derived duties; no control lock may span
those callbacks. The model assumes external phase-cleanup receipts rather than
claiming the existing wrappers already supply them.

OS-create failure currently invokes fatal_error and shrink join errors are
ignored. The new recoverable abort/drain behavior is an explicit architectural
change requiring semantic acceptance, not proven equivalence to a fatal path.
The POSIX wrapper also discards pthread_create's returned error and uses errno;
preserve the real error in the future adapter. Win32/unimplemented variants
require independent admission before claiming portable rollback.

** Escrow without a GC/owner cycle

A VM-owned transaction retains the root, per-child native backing, exact
initialization progress and pending outcomes. Logical abort closes future Scheme
entry before cleanup. A late-starting child checks its stable transaction's
abort/generation state before touching Scheme roots or entering a collector
rendezvous. Such an unknown child is not a committed collector participant.
This requires complete entry/write-authority coverage; an uncontrolled raw entry
or native writer still blocks admission, not merely reclamation.

Stop/drain/cleanup work runs outside the collector close lock and outside a
barrier that expects the same child. Other committed GC participants can proceed
using the VM-retained roots. An error can be delivered before physical cleanup
only after an explicit VM escrow acceptance and Scheme-entry revocation proof;
this earlier status handoff is not modeled as completed here. Unknown native
writers must not be declared stopped from creator death, absence of ACK, timeout
or run return. Existing run-and-throw continues servicing synchronous operations
after run returns, so its return is not OS termination.

Physical reuse requires known no-child or exact stop for that attempt, no
committed membership, drained descriptor/scanner readers, and settled partial
initialization/derived cleanup duties. Root-value retirement, logical transaction
completion, native descriptor reclamation, capacity demand refund and allocator
release are distinct endpoints.

* Capacity and benefit accounting
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-benefit
:END:

[[file:../../../../vendor/gambit/lib/mem.h::66][The current constants]] are 131072 words per msection and a minimum of two
msections per processor. The existing requested-count contribution is therefore
262144 words per requested processor: 2097152 bytes (2 MiB) if a word is eight
bytes. Two requested processors contribute a four-section lower bound, 4 MiB at
that word width. SysML evaluates these arithmetic cases and Lean checks them.
They are not added RSS, per-worker exclusive allocation, or a total GC-space
upper bound. Occupied objects, stack sections, recent history, maximum heap,
existing free capacity, section metadata and OS stacks also affect allocation.

Releasing a failed child's demand may lower a later target minimum only when
no live/unknown child or resource loan still needs that capacity. It is not an
immediate free: cleanup_mem_pstate does not release msections. Physical contraction
uses [[file:../../../../vendor/gambit/lib/mem.c::903][adjust_msections]], including free_mem_aligned_heap in its contraction loop,
after [[file:../../../../vendor/gambit/lib/mem.c::6335][GC sizing]] computes a permitted target. The old physical generation and
readers must also be retired. Refunding after an already observed peak does not
reduce that round's max_t. A lower peak requires avoiding/defering an allocation
before the maximum or proving safe physical reuse at that earlier point.

Use disjoint backing classes:

\[
P=\max_t(B_{values}+H_{tx}+N L+V_{pin}+R_{scan}
 +PSTATE_{unique}+Stack_{unique}+U_{extra}).
\]

B_values counts each Scheme allocation once; metadata and native backing are
excluded from it. PSTATE and native stack sets count unknown children already
retained there; U_extra adds only escrow not counted elsewhere. Free PSTATE
slots in a fixed VM array are not assumed to become OS-freed memory.

If K safe independently registered value carriers were otherwise needed, one
shared cell saves (K-1)*w /value-slot bytes/ and their duplicate cell visits.
K is a live-location inventory parameter, not a measured constant: local/tree
sop carriers depend on participants and compiler lowering. Message copies and
per-child control work remain. Existing unregistered WORD copies are not a safe
zero-cost baseline. The actual high-value reuse is the existing precise CFUN
frame and shared runtime contract, with no new Scheme evaluation or copied
thunk object required just for admission. Total support and runtime benefit
remain conditional; Zig-specific support elimination is not established.

The first cut is this connected vertical slice. It cannot retire only the C
field while leaving raw sop copies, and cannot add descriptors while keeping
uncreated children as mandatory participants of a broken generation. Not every
FFI generator needs immediate migration; this builtin produces a source-aware
contract that later generated entries can share. Exported raw C entry semantics,
header/GSTATE binary layout and configured module consumers require separate
migration inventory. No new wrapper may silently claim those users admitted.

* Formal models, refinement duties and evidence gates
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-formal
:END:

[[file:../../../../models/gambit/resize_bootstrap_admission.qnt][The two-child QNT model]] covers close/register order, full caller-view
retention, one relocation, descriptor-root update, independent child binding and
create result, successful generation commit, one-success/one-failure or unknown
rollback, partial initialization receipts, late success and no-child settlement.
A commit seal records the atomic open-gate admission event: already ready
children cannot bypass a concurrent close. Future GC may still close a properly
committed generation; the seal is not a requirement that GC stay open forever.

The model's coarse required-view IDs denote five abstract location/graph
categories, not the five literal stack cells or a replacement precise bitmap.
Root contents, snapshot scan/reader drain, per-child writes, physical generation
switch, arbitrary callback depth and actual allocator effects are premises or
open source refinements. It proves no arbitrary-N fairness/liveness result and
no recovery from uncontrolled native writer death. Random runs are finite
sampling, not exhaustive verification.

[[file:../../../../models/gambit/lean/ResizeBootstrapAdmission.lean][Lean]] checks conditional view/coverage, stale-origin rejection, member and
unknown-reclaim guards, sibling stability, ledger conservation and byte/word
arithmetic. Full QNT Step induction, source-to-model stuttering and safety
reflection must still establish every concrete transition's rely conditions.
SysML also owns concrete Boolean admission-cut predicates and a root-coverage
requirement. Seven native-evaluated illustrative cuts separate root acceptance,
coverage, membership commit and physical reclaim. These assume complete inputs
and do not prove requirement instantiation or the correspondence of actual C
events. Native-evaluated SysML transition rows reference actual QNT actions and Lean
law names; mechanical existence checking is not semantic refinement.

[[file:../../../modeling/ascent/resize-bootstrap-admission.rules.scm][The actual ASCENT DSL]] joins current source bundle, native output and DSL
digests; exact method/check/artifact/scope receipts feed dependency closure.
SysML also defines root-admission, member-commit and first-cut research gates
through typed ModelNeed references. These are evidence-planning predicates, not
runtime gates or execution permission. Current local model receipts cannot open
a gate whose source/ordering prerequisites are missing. The all-scoped control
is synthetic policy input only. The [[file:../../../modeling/ascent/resize-bootstrap-admission.request.scm][maintained request]] and five actual Evidence
queries retain current, omitted-history, wrong-scope, stale-digest and synthetic
full-evidence cases. Initial SysML identifier/evaluation and QNT annotation
diagnostics are retained as authoring failures, not native failures.

* Learning from primary evidence
:PROPERTIES:
:CUSTOM_ID: resize-bootstrap-admission-references
:END:

[[https://ocaml.org/manual/5.2/intfc.html][OCaml's C-interface manual]] requires registered locations to be valid and
coordinates access with GC; relocation updates registered /locations/. Gambit's
existing mapped frame can serve that purpose without duplicating its runtime
architecture. [[https://armael.deuxfleurs.page/publis/melocoton.pdf][Melocoton (OOPSLA 2023)]] formalizes roots and value/representation
reconciliation. This study applies that distinction to CFUN alias versus C/sop
copies; the paper does not prove Gambit's barrier or bootstrap protocol.

[[https://pubs.opengroup.org/onlinepubs/000095399/functions/pthread_create.html][POSIX pthread_create]] distinguishes real failure/no-child from success;
[[https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html][POSIX memory synchronization]] does not establish later moving-root ordering or
successful synchronization from an error return. The C implementation must
refine these conditions on each supported adapter. Platform evidence here is
specification research and source reading, not an installed Darwin/native test.
