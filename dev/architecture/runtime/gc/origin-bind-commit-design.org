* Decision and scope
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-decision
:AUTHORITY: models/sysml/origin-bind-commit.sysml
:STATUS: CONDITIONAL-HISTORIES-FIRST-SOURCE-C-ORDER-AND-STOP-PRODUCTION-OPEN
:COMPONENT: host-roots
:SHARED_COMPONENT: gc-work
:END:

First origin admission must borrow a /complete registered source/ through a
preinstalled safe root port before allocating a marker or publishing a native
operation. It cannot allocate an unprotected Scheme helper to create the very
root protection it needs. The bind transaction is a sequence of ownership,
private-field, progress, locator, root-admission and final-commit cuts, not one
indivisible C block.

Observed owner exit is distinct from /control writes closed/ and /data writes
closed/. Until both future writers and in-flight accesses are excluded, retain
VM journal, source and any candidate-slot ownership. A helper may reconstruct
only exact-token, private idempotent metadata; it must never replay an old
Scheme payload over a root already updated by GC.

[[file:models/sysml/origin-bind-commit.sysml][SysML]] owns component needs, typed source routes, progress transitions,
writer/GC guards, dependencies, gates, costs and topology. Native evaluation
derives [[file:origin-bind-commit-matrix.org][the matrix]] and [[file:diagrams/origin-bind-commit.d2][D2]]. Actual [[file:../../../modeling/ascent/origin-bind-commit.rules.scm][ASCENT rules]] and [[file:../../../modeling/ascent/origin-bind-commit.request.scm][request]] enforce
artifact/method/check/scope joins. [[file:../../../../evidence/research/origin-bind-commit/checks.json][The receipt]] binds live source identities and
unchanged [[file:activation-vm-routing-design.org][predecessor]] evidence. No runtime implementation, native test, ABI or
performance qualification is performed. The atomic cut in the predecessor is
now decomposed at abstract field-operation granularity, not claimed as an ISA
or complete C-memory model.

* Actual generator, marker and exit evidence
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-source
:END:

** The selected CFUN already has a precise caller to borrow

[[file:../../../../vendor/gambit/lib/_kernel.scm::2353][Resize source]] and [[file:../../../../vendor/gambit/gsc/_ptree2.scm::2850][argument generation]] produce a Scheme object alias to CFUN_ARG.
[[file:../../../../vendor/gambit/lib/_kernel.c::6258][Tracked CFUN]] uses a no-cleanup body; [[file:../../../../vendor/gambit/lib/_kernel.c::26338][its caller]] materializes arguments and
resources, with [[file:../../../../vendor/gambit/lib/_kernel.c::30819][fs=3/link=2/map=7]] at its return point. [[file:../../../../vendor/gambit/include/gambit.h.in::10325][BEGIN_CFUN_CTX]] writes
back the context. This is the real starting point for a generated full root
view, not a new root map inferred from a raw C argument. Tracked output is not
proof of freshness or installed ABI equivalence.

[[file:../../../../vendor/gambit/gsc/_ptree2.scm::2902][Cleanup selection]] and [[file:../../../../vendor/gambit/gsc/_ptree2.scm::3238][body emission]] currently follow conversion requirements.
[[file:../../../../vendor/gambit/include/gambit.h.in::10375][AT_END placement]] is not an all-exit ownership guard. The new generated entry
plan must declare source materialization, first admission, every write stage,
publication, current-value reload and exit disposition independently.

[[file:../../../../vendor/gambit/lib/setup.c::1155][current_vm_resize]] copies a raw thunk into sop. Its [[file:../../../../vendor/gambit/lib/setup.c::1050][sync loop]] can perform an
effect and copy a result before throwing. A missing C return is not a failed
claim. [[file:../../../../vendor/gambit/lib/mem.c::4529][GC restores PSTATE fp]], so [[file:../../../../vendor/gambit/include/gambit.h.in::10402][CFUN_ARG]] or a logical RootRef must be
re-resolved after GC; a cached argument value cannot be blindly re-stored.

** Marker allocation has a real unprotected-source warning

[[file:../../../../vendor/gambit/lib/c_intf.c::6511][make_sfun_stack_marker]] calls make_vector before using proc_or_false and
explicitly comments that proc_or_false may have been GC'd. It then writes the
procedure and processor identity into the marker. [[file:../../../../vendor/gambit/include/gambit.h.in::10040][SFUN macros]] call that marker
allocator before later generated argument transfer. [[file:../../../../vendor/gambit/lib/setup.c::3394][run]] has the same ordering.
The first admitted source must therefore precede marker allocation/conversion.
A raw parameter or still refcount does not automatically prove its GC view.
[[file:../../../../vendor/gambit/lib/c_intf.c::6550][Marker invalidation]] and refcount decrement remain distinct final duties.

[[file:../../../../vendor/gambit/lib/setup.c::763][Worker run]] and [[file:../../../../vendor/gambit/lib/setup.c::6395][main run]] need different first-source producers. The startup
worker receives data_scmobj after [[file:../../../../vendor/gambit/lib/setup.c::905][resize may have collected]], and before thread
creation. Replace that raw retained thunk with a rooted startup descriptor or
RootRef; accept its root port before processor/member/thread visibility. Main
startup can use an exclusive startup publication cut before managed exposure,
but the module-thunk producer and its source lifetime still need audit. Merely
finding program_descr in GSTATE is not a proof of root registration.

** Real stop observations are weaker than the required receipt

[[file:../../../../vendor/gambit/lib/setup.c::3276][call/run catchers]] can rethrow past normal cleanup. [[file:../../../../vendor/gambit/include/gambit.h.in::9979][setjmp macros]] require
stable progress outside modified nonvolatile locals. [[file:../../../../vendor/gambit/lib/setup.c::930][A shrinking worker]] cleans
PSTATE before thread_exit. [[file:../../../../vendor/gambit/lib/os_thread.c::546][thread_join]] reports failure, but [[file:../../../../vendor/gambit/lib/setup.c::966][its resize caller]]
ignores that result. None of these code paths currently produces the proposed
complete control/data-writer census and stop receipt.

[[file:../../../../vendor/gambit/lib/mem.c::6845][The selected root scan]] calls mark_rc under processor-zero dispatch, then scans
globals, continuation and registers. Nonzero-processor RC/source coverage must
be redesigned explicitly; a new port cannot silently inherit a complete RC
closure that the current selected path does not establish.

* First origin without recursive registration
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-first
:END:

Preallocate VM-owned RootViewPorts and their journals before context/processor
or host-entry exposure. The GC adapter knows the fixed array while all payload
cells are safe false. Empty/control-only ports can be inspected without a new
Scheme allocation. An active view is admitted only with complete source and
scan-membership evidence; never publish a partly assembled frame descriptor.
The fixed port itself supplies origin identity/generation, so entry does not
call an unbounded identity service to discover its own key.

#+NAME: origin-bind-commit-first-sources
| Entry producer | First-source plan | Closed-GC behavior | Refusal condition |
|----------------+-------------------+--------------------+-------------------|
| Selected generated CFUN | Materialize complete FrameSpec/PointId/register/slot view from current caller; freeze raw borrowers | Existing included view protects source while new bind waits; metadata only may progress | Partial frame, stale raw argument, unknown writer or missing source scan membership |
| Main VM startup | Preinstall empty port; exclusive startup root publication from an audited live module-thunk producer before marker/managed exposure | No payload publication outside admitted startup/root cut | Source object provenance or startup exclusion not established |
| New worker | Parent's current rooted startup descriptor/RootRef, reloaded after resize GC; publish before member/thread handoff | Parent/VM retains source until child's root admission and membership acceptance | Raw data_scmobj is the only holder, partial creation or unknown transfer |
| Nested SFUN/callback | Parent NativeActivation source borrow plus current logical frame/RC root receipt | Frozen parent/VM source remains scanner-owned; nested origin cannot revive dead marker | Untracked ClientData/RC source, wrong owner or dead native extent |
| Fresh external host | Pre-admitted host/context port and already registered native root location | Attach only through GC-participation/source-admission cut | Bare SCMOBJ with no valid registered owner; a marker cannot repair missing prior protection |

No Scheme payload is needed to allocate the native empty port. For a fresh host,
requiring a registered source is an explicit API precondition, not proof that
arbitrary Scheme objects can safely enter from arbitrary C memory. Startup and
parent-context producers need their own source/refinement receipts. If a new
participant is excluded by the current closed scan set, it cannot execute
Scheme or publish a new payload until the correct admission epoch.

RootView freeze is not a copy of all values into unscanned C storage. It is an
exact source-domain/map/PointId/epoch contract with stopped raw root writers and
collector-updatable locations. RootViewPort publication, root registration and
physical PSTATE cleanup have separate lifetimes. The current design has not
closed all of those source obligations.

* Decomposed write set and publication order
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-writes
:END:

#+NAME: origin-bind-commit-stages
| Cut | Required writes/evidence | Canonical custodian | Meaning if normal return is lost |
|-----+--------------------------+---------------------+----------------------------------|
| PortReady | Safe false payload and scanner-known port lifetime | VM root domain; caller still holds source | No activation or payload publication implied |
| SourceFrozen | Complete source/map/epoch, no raw source mutation, source scan owner | Existing source/parent plus VM view receipt | Keep exact registered source, not a raw cached value |
| Intent | Immutable origin serial, candidate, expected owner header, source lease and write-set plan | Fixed VM journal | Request may still claim slot later; absence of result is not no-effect |
| Claimed | Atomic header names exact journal/slot lease | Exact claimant owns initialization debt | Read canonical header after actual control stop; cached progress may lag |
| PrivateFields | Finite metadata fields and safe false root shell; write before progress bit | Unique initializer | Store may exist without logged completion |
| Locator | Exact slot/lease and immutable intent binding published | Journal plus owned slot | Locator is not whole commit or payload permission |
| RootAccepted | Canonical root cut owns a current scan-visible cell | Root domain, with old source overlap | Query canonical root receipt; GC may already have moved the value |
| Committed | Final release tag after metadata, locator and root validation | Canonical VM binding | Query/replay same commit, never reserve/evaluate again |
| Settled | Actual source/result/reader/child/writer duties closed | VM retirement/fence service | Recycle exact own support; never a competing slot |

The owner header contains only an exact checked control token/lease, not a
Scheme payload. Publish immutable Intent before the ownership operation can
execute. A single early observation of a free header cannot prove no future
claim: a delayed CAS may still win. After complete control closure/drain, exact
header comparison distinguishes ours, still-free and a competing owner.

A real C header encoding must fit and be atomically supported by the target.
Do not assume a multiword tuple assignment is atomic. Single-word packing,
checked bounded IDs and alignment are implementation obligations. A stronger
asynchronous-owner-death profile additionally needs qualified lock-free atomic
operations or a platform stop mechanism that excludes unfinished internal
locks. C atomics alone do not prove that fault-tolerance property. A portable
mutex/cooperative profile remains possible but cannot blindly unlock a mutex
whose owner died or promise the same recovery progress.

The ordinary C field stores, their progress updates and final phase word are
separate operations. Progress can lag a completed store. Once old data/control
writes are verifiably closed and an exclusive helper epoch is acquired, replay
of declared private idempotent metadata may repair the record. Do not rerun
malloc, foreign initialization, destructor calls, Scheme evaluation or a
published native effect. Concurrent identical plain stores are still excluded.

A helper's own interruption uses the same ownership/stop rules for a subsequent
helper; this study models one exclusive helper, not arbitrary helper churn.
Without proof that the prior helper has stopped, another helper cannot simply
write the same metadata concurrently.

* Stop receipts, unknown outcomes and owner exit
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-stop
:END:

#+NAME: origin-bind-commit-stop-producers
| Observation/producer | What may be established | What it does not establish |
|----------------------+-------------------------+----------------------------|
| Owner-exit notification / timeout | Need to retain/recover a VM-owned operation | No-future CAS, no in-flight store, stopped helper or released root |
| Close request / generation revocation | Future protocol entries can be denied | Already executing CAS/plain store has stopped |
| Generated cooperative exit guard | Covered data and control producer paths finish or transfer before throw/return | Arbitrary c-code, signal/native helper and escaped borrow are also covered |
| Catcher after END_TRY | Stable VM disposition can be processed before rethrow | Modified local progress is valid, or normal AT_END has run |
| Verified thread stop/join | Joined thread has stopped, under actual platform contract | Every descendant/helper/borrower has stopped, or an ignored error is success |
| Complete DataWriteClosed | No future/in-flight data producers in admitted census | Outstanding control CAS has completed |
| Complete ControlWriteClosed | No future/in-flight slot/header/commit producers in admitted census | Plain field/payload writer is stopped |
| Exclusive helper lease | One new reconstruction authority after old-writer closure | Safe reuse before source/GC/result readers drain |

Before physical exit, VM accepts journal, exact source lease and original
exception/result disposition. A helper is admitted only after BOTH writer
closures and in-flight drains; origin RootFrozen is a different receipt.
Unknown shutdown/control outcome retains the operation. For a claimant that
never acquired the slot, abort closes future ownership publication and releases
only its journal/source duty. A competing claimant's slot and fields remain
untouched. An owned but private slot can be cancelled after verified stop.
Committed/root-visible operations require canonical result and actual consumer/
child-stop treatment; they cannot be reclassified as unpublished.

A field operation may finish after owner-exit observation; the abstract model
keeps the in-flight flag until actual completion. Concrete production of stop
receipts from catcher, join, cancellation and every helper remains source work.
The current ignored join status is not a valid shortcut. POSIX thread exit may
run cancellation cleanup/TSD destructors before actual termination; a guard
before thread_exit is not by itself a complete producer stop. The selected
[[file:../../../../vendor/gambit/lib/os_thread.c::989][Gambit POSIX TLS key]] is created with a NULL destructor, which bounds that
own-key path only. Foreign-library keys, native helpers and escaped capabilities
remain part of the required producer census. Unknown raw writers
or missing stopped-owner evidence must refuse helper/recycle admission.

* GC close and root ownership
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-gc
:END:

Keep the candidate payload safe false while metadata is private. GC scans the
already complete frozen source view; it does not treat private journal words as
Scheme objects. Private control reconstruction can proceed while GC is closed
if it touches no scan-visible root layout/value. Pending root admission waits
for the correct close/membership cut and reloads the source at the current
epoch. Do not add a late source to an already sealed scan set.

Canonical RootAccepted means the root shell/layout is initialized and its word
belongs to the scanner protocol. If GC intervenes before final commit, the
collector updates that canonical cell. A later helper repairs metadata only;
it must not reset the root to false or copy an old SCMOBJ over the moved value.
Final commit validates current canonical ownership/epoch and publishes control
state; effects also obey the VM user gate. The preceding router close protocol
remains required even though the finite model focuses on bind/GC cuts.

Source ACK settles only the exact extra source lease. Physical source-view
release waits for its own scan/raw borrowers, even when the same object is
also rooted by the canonical descriptor. Natural Scheme frame maps are not
erased by this ACK. Original result acceptance is a separate gate.

An unknown metadata owner need not block collection WHEN the complete source
view is already frozen, registered, updatable and independent of that owner's
private writes. This is the useful conditional decoupling for future independent
collector workers. If source/root writes or scan membership are unknown, safe
collection/handoff may still be blocked. This study proves no general GC or
shutdown progress bound and never manufactures a stop receipt by waiting for
an owner callback inside GC/control locks.

* Models and source refinement boundary
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-models
:END:

[[file:../../../../models/gambit/origin_bind_commit.qnt][QNT]] models one fixed port/intent/candidate, a competing header owner, two
private control fields and progress bits, one actual owner/exclusive helper,
one moving GC and Boolean reader flags. Actions separate Intent, CAS start/
application/observation, data start/store/completion/log, locator, root acceptance,
commit, stop, helper writes, source/result ACK and reuse. Atomic header/root/
phase actions and registered source/stop/consumer receipts remain premises.
No full C/ISA, arbitrary reader/port population, repeated helper or liveness proof.

Histories cover first source refusal, origin admission during GC close, CAS
response loss, late CAS after exit observation, competing claims, store without
progress log, helper locator repair, moved root before commit, commit reply loss,
GC under unknown metadata owner, source-scan retention and separate result ACK.
Controls force missing source/port, false stop, incomplete commit, early effect,
stale root overwrite, source-scanner loss, result/pin premature free and touching
a competitor's slot. A separate unsafe run must violate the invariant.

[[file:../../../../models/gambit/lean/OriginBindCommit.lean][Lean]] checks selective first-admission/stop, idempotent private repair, moved
root preservation, complete commit and recycling conditions. These do not prove
full QNT induction, target atomics or existing Gambit behavior. ASCENT qualifies
only exact local history/conditional-law slices and keeps first-source,
writer-census, root adapter and C-order gates open. Earlier atomic binding
histories are retained rather than reinterpreted as instruction-level evidence.

:CUSTOM_ID: origin-bind-commit-cut

#+NAME: origin-bind-commit-source-cut
| Source responsibility | Required future redesign | Old duty retires only when |
|-----------------------+--------------------------+----------------------------|
| Scheme generator / FrameSpec / PointId | Explicit entry source, finite InitSpec/effect/write set, locator and all-exit guard plan | Selected CFUN/SFUN/c-code and restore paths have complete writer/root inventory |
| VM/setup/context / startup producers | Safe empty ports and root scanner adapter before payload/member/thread exposure | Main and worker sources have real GC/provenance receipts, not assumed GSTATE/local ownership |
| marker constructor / SFUN entry | RootRef/parent-borrow admission before marker allocation; reload current source | proc_or_false raw-local protection gap and every managed callback producer are covered |
| canonical resize / origin journal | Immutable intent before claim, exact-token header, field/progress/locator stages and final commit | No raw sop thunk or lost return causes duplicate claim/effect |
| collector / RC / source transfer | Canonical root admission/close, pending-source coverage, nonzero participant scanning | PSTATE-only cleanup and processor-zero-only RC assumption no longer own managed live roots |
| call/run / native stop adapters | Stable VM escrow and distinct control/data no-future/no-inflight receipts | Normal-only cleanup, ignored join and observed-exit flags are not sole ownership evidence |
| helper / retirement | Exclusive stopped-writer reconstruction and separate source/result/readers/fence closure | No helper replays payload/native effect or frees a competing/unknown slot |

This is an entry-and-runtime ownership redesign in modern generated C. It is
not a configuration switch or a new wrapper around unchanged raw writes.
Preserve C interoperability through explicit managed contracts and separately
inventoried legacy entry behavior; do not declare all old C macros globally
retired because one selected managed call migrates.

* Benefit, added work and peak accounting
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-benefit
:END:

The design removes the need for a hypothetical retry-sized identity/progress
history by using fixed ports and intent records. It can reconstruct private
support without repeating Scheme argument evaluation, allocation or native
effects, and permits GC to use a frozen source independently of an unknown
metadata owner. These are conditional architectural gains, not measured current
Gambit speedups or evidence that current C already implements such a registry.

Costs include safe ports, checked exact-token headers, progress writes and
release/acquire reads, writer-stop production, helper exclusion and root-view
retention. A simple always-visible port array adds O(C) tag/empty-cell checks per
collection for C installed ports, plus live source scanning. Skipping inactive
ports or deduplicating source/descriptor scans needs a separate correct bitmap/
close protocol; no scan-work reduction is assumed here.

Use the preceding full budget and add only fields not already included:

\[
\Delta C=O\,H_{rootPublicationExtra}+W\,H_{progressExtra}
         +H_{qualifiedHeadersExtra}+H_{ticketsExtra}.
\]

Root ports/journals embedded in base mailbox Ho or activation cell Hc are counted
once. A finite progress mask bounds bookkeeping by the declared InitSpec write
set; the model has two fields, a broader SysML parameter has sixteen bits, and
neither is an actual Gambit ABI measurement. Post-Intent control operations are
required to allocate zero new control records in this proposed profile; that
is a source implementation obligation, not observed malloc behavior.

\[
P=\max_t(C_{fixed}+B_{unique}(t)+V_{extra}(t)
         +Q_{external}(t)+Native_{unique}(t)).
\]

Unknown claim/writer/root/result outcomes may extend overlap and retain backing.
Count source/descriptor/result aliases of one Scheme object once, but retain
extra frame/slot/native backing as separate physical classes. Neither fixed
control capacity nor later cleanup proves whole-round peak reduction. A verified
net CPU/peak benefit, lock contention bound, arbitrary owner-death progress and
actual runtime retirement remain unproved; no person-day estimate or extra
Zig-specific advantage is used as a decision criterion.

* Primary evidence and preserved failures
:PROPERTIES:
:CUSTOM_ID: origin-bind-commit-primary
:END:

[[https://cs.brown.edu/~mph/HerlihyW90/p463-herlihy.pdf][Herlihy and Wing]] motivate explicit invocation/effect/response cuts. A recoverable
commit record is separate from response delivery; the paper is not a proof of
this C journal or of crash persistence.

The official [[https://pubs.opengroup.org/onlinepubs/9799919799.2024edition/functions/pthread_join.html][POSIX join specification]] ties successful join to target-thread
termination. The official [[https://pubs.opengroup.org/onlinepubs/009696899/functions/pthread_exit.html][exit specification]] describes cleanup/destructor execution
and explicitly does not release application-visible mutex/resource ownership.
Indexed official excerpts were available after direct-page requests returned
403. These contracts do not prove all Gambit/foreign helpers have stopped.

[[https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf][C draft N1570]] is the predecessor's primary source for memory order, lifetime,
atomic/plain-access and setjmp constraints. This round's fetch timed out and is
recorded accordingly; it is not new target/ABI evidence. Native SysML authoring
errors (reserved identifier and fixed-value/default override) and the initial
Evidence presentation-capacity failure are retained separately from model and
native-runtime outcomes. No model/runtime assertion was weakened to hide them.
