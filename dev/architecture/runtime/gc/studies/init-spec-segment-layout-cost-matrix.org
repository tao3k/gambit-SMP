The [[file:allocation-check-bound-cost-matrix.org][bound/backend report matrix]] further
separates actual selected word bounds, logical versus native address permission,
pre/post-check boxing, remaining slow-path work, sparse completion support and
the real Scheme-to-Zig product. Architecture recommendation and positive
language-specific net benefit remain separate judgments.

The report compares equal full capabilities. C-G/C-full is modern C with
Scheme-generated builders/descriptors, opaque services and mature helpers;
C-ZT adds useful Zig tooling while keeping that C runtime. Z-full implements
the same native service in Zig. Current processor-owned C is the B0 comparison
for total modernization, not the ceiling granted to C in the language choice.

*** Quantities That Can Be Stated Now
:PROPERTIES:
:ID: 65b28bba-1b3b-5996-97c2-460c2bd858a4
:CUSTOM_ID: quantities-that-can-be-stated-now
:END:

This selected inventory has 16 producer families; one explicitly represents
unqualified raw/external clients. That count does not prove 15 families are
admitted or cover the entire primitive/FFI graph. Each family contains actual
success/failure/configuration branches; completion and root semantics need
independent closure.

For each qualified writable grant i, the check condition is L_i+B_i<=b_i.
Retaining F_i reserve requires B_i<=F_i and L_i<=b_i-F_i. These are conditional
capacity inequalities, not measured memory or speed improvements. Compiler
4096 and runtime 8193+SUBTYPED_BODY are different source constants; this study
does not derive a global B from either or from the ignored macro argument m.

Let N_s be old allocated objects and N_r the objects actually reachable under
the complete declared-root/strong/weak/will semantics. A design
that scans all old segments as roots can force work/liveness toward N_s rather
than N_r. Root-driven tracing preserves the opportunity to avoid that excess;
it does not eliminate actual copying/tracing. Charge copied payload/header words,
traced fields and physical root cells separately: object count alone misses large
pointer-free payloads. Add actual weak/frame/list/task and synchronization work;
no whole-collector asymptotic or workload reduction is proved here. Do not use
a paper's benchmark ratio as ours.

With K qualified run descriptors, X sparse/partial/escaped exceptions and P
pending constructors/users, metadata can be organized around O(K+X+P) records
plus variable payloads. This is conditional on admitted compact run grammar
and last-user retirement. If actual pointer validation needs N object starts,
index space/build/lookups must be charged explicitly; O(K) cannot be claimed
for that stronger capability. Indefinitely unknown effects defeat a finite
retention bound in C and Zig alike.

New allocation bytes, copying work, live-after-GC bytes, policy charge, assigned
capacity and native section/metadata bytes are distinct reporting dimensions.
Moving interval rights between worker/context creates zero new Scheme objects;
it may still incur synchronization/layout/reporting work. No elapsed time,
labor-hour, RSS percentage or pause saving is asserted.

*** Net-Benefit Gate
:PROPERTIES:
:ID: 0f53a5f3-126b-540a-a559-d06148deeae5
:CUSTOM_ID: net-benefit-gate
:END:

| ID | Condition for a defensible positive bound | Refutation / unresolved term |
|-
| ISN01 | One semantic constructor/check source feeds backends; old late C-only semantics and duplicate PSTATE layout owners genuinely retire. | If wrappers retain the original authorities or raw-client gaps persist, the new layer adds maintenance without full decoupling. |
| ISN02 | Common modernization value exceeds migration plus runtime metadata/scan/check/public-counter/retention work over the same horizon. | Over-rooting, perobject global logging, excessive zero-fill, duplicated indices or stalled cleanup can negate total benefit. |
| ISN03 | Zig's bounded avoided residual support exceeds its incremental migration/tool/ABI/target/retained-island costs after the best modern C reuse. | If Scheme-generated C removes the same helpers, the private Zig saving is zero or too small. No numerical positive lower bound is presently established. |
| ISN04 | Full roots/check spans/target parser/statistics/FFI domain is admitted without regressions outside the selected slice. | A source endpoint or arithmetic inequality is not configured/native coverage; unresolved marker/no-fill/copy/external clients remain gates. |
| ISN05 | LLVM services bring a separately supported modernization capability through the shared contract, with an independently bounded Zig advantage. | Shared LLVM engineering benefits alone justify neither a Zig-specific language choice nor a runtime correctness claim. |

Total modernization and Zig increment are separate comparisons. The architecture
can remove hidden C-emission assumptions and support independent collectors and
compiler providers in either modern C or Zig. Zig has plausible local support
savings, but this source/theory work has not bounded them above its added costs.
All five full requirements and AG05/AG06/future-native AG07 remain unresolved.
