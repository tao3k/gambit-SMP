*** 1. Separate Identities Before Moving Fields
:PROPERTIES:
:ID: 5b725d0b-2f8f-51a8-a0a2-6b878a8ea892
:CUSTOM_ID: 1-separate-identities-before-moving-fields
:END:

[[file:../diagrams/collector-domain-separation.svg][Ownership domains]]
[[file:../diagrams/collector-domain-separation.d2][D2 source]].

Current code uses processor_count to assign initial sections, partition globals,
choose victim queues, initialize scan_workers_count, sum occupancy and operate
sync barriers [CW-S01--05]. Replacing that count with worker_count everywhere
would confuse several different populations.

| ID | Proposed domain / identity | Responsibility and permitted relation |
|-
| CWI01 | MutatorContext set U | Scheme execution, saved register/stack state, interrupt and return obligations. Context lifetime is not OS thread lifetime; stopped contexts still contribute roots. |
| CWI02 | RootDomain set K | Final physical root cells plus structured stack/continuation tasks, target carriers and actual pending arguments. K includes roots without a runnable mutator; one canonical writer per actual root cell/structured mutable domain [CW-S04/S06]. |
| CWI03 | HeapShard/Extent set S | Persistent still/RC/storage custody, section occupancy and reclamation effects. Copied objects remain VM heap objects after a worker stops; W retirement cannot free their backing extents [CW-S02/S07]. |
| CWI04 | CollectorWorker set W | Native collector threads/contexts admitted for one epoch and phase, each with tracing allocation cursor, work claim and queue access. W may differ from U in cardinality; no Scheme execution or unregistered managed locals on those workers. |
| CWI05 | OperationParticipant set P | Actors that acknowledge/reconfigure contexts, service rendezvous, startup, retire, resolve or deliver results. P is role-indexed per operation; acknowledging a safe point does not make an actor a copying worker [CW-S01/S08]. |
| CWI06 | Request set O and selected operation E | Durable request identity differs from origin ContextId, round, selected operation, child collection and participant role. Merged GC requests share E but retain separate obligations/results. One actor may participate without originating any request [CW-S01/S08]. |

An epoch binds VM/heap reuse identity, U/K/S snapshots, W roster and a role map
for P. M/K/W enrollment identities precede acknowledgements; final root locations
follow them. No ordinary context/carrier mutation is admitted across the sealed
moving epoch. A resize may alter U/P only at explicit nonmoving membership cuts;
W is frozen during an active collection. No identity is inferred from an array
index after membership changes.

| CWB08 | traverse_weak_refs_, nonexecutable_wills_, executable_wills_, reached_gc_hash_tables_ [CW-S04/S07]. | Phase token supplies traversal mode; logical will ownership stays with its admitted runtime owner, while discovered table work is epoch output with a canonical consumer. Continuation root discovery may rewrite frame links and copy captured frames, not merely enumerate immutable pointers. Preserve the existing capture exclusion and root-publication ordering. |
| CWB12 | VM section allocator, heap policy/statistics, custom_msection_alloc/adjust_heap hooks and scan synchronization [CW-S02/S07/S10]. | VM HeapServices, phase/termination authority and qualified hook/control islands. | CWB13 | SINGLE_THREADED_VMS gates forwarding CAS, MISC/ALLOC locks, queues and scan counters [CW-S03/S05/S09]. | CollectorConcurrencyProfile is independent of mutator count. U=1,W>1 requires multiwriter forwarding/frame/allocation/queue support. A fast path needs a sealed one-worker/no-other-writer proof; it cannot follow merely from one Scheme processor. |

The semantic side stays in Scheme/Gambit: root-kind/frame interpretation,
continuation/effect/return rules, will semantics and allocation/overflow behavior.
The shared native plane owns explicit contexts, leases, queues, allocation and
publication. Either modern C or Zig can implement that plane. LLVM providers
supply admitted maps/relocation metadata; they cannot implement runtime
participation, GC or the ownership decomposition by themselves [CW-P04].

A source-to-service call boundary must pass *both* root owner and tracing
worker. Helpers such as mark_continuation currently read ___ps->fp while
mark_array uses that same ___ps for allocation/queues. A fake PSTATE holding a
mixture of donor roots and worker cursors would preserve the ambiguity. Replace
helper dependencies explicitly or keep a qualified legacy context island until
its cohort can migrate. No copying/reinterpreting the old struct into Zig is a
substitute for transitive call, macro/TLS, custom hook and exceptional-exit review.

| ID | Source behavior | Mapping consequence |
|-
| CWR01 | OP_MAKE orders priorities; resize precedes GC; GC has COMBINING_ADD, resize has no combining [CW-S01]. | Preserve operation selection and checked capacity aggregation separately. Matching opcode does not mean every operation is mergeable. |
| CWR02 | barrier_sync_op reduces child/self proposals and propagates winner/op to the tree; ties without combining retain a tree-selected origin [CW-S01]. | Do not silently replace the tie rule with smallest ContextId or newest RequestId. | CWR06 | startup thread enters the sync loop before running its thunk; shrinking actors cleanup/exit and leader joins. | CWR07 | gc_pstate initializes local overflow=0, only processor 0 assigns resize_heap's result, then returns local overflow; dispatch copies that local result [CW-S10]. | The inspected vendor path does not establish a common published GC capacity result for all participants. CWR07 is a source-level result-delivery gap, not a reproduced failure or proof
that a particular deployed build fails. It matters to resize too: if capacity
branches differ across participants, their next collective actions need not
agree. Do not claim a common Boolean result merely because all actors returned
from a barrier. Exact configured/candidate behavior and intended semantic
correction remain qualification obligations.

**** Proposed Mapping Contract
:PROPERTIES:
:ID: c3cbf723-149a-504b-b064-8cf99141a6f1
:CUSTOM_ID: proposed-mapping-contract
:END:

| ID | Record / rule | Required invariant |
|-
| CQM01 | RequestRecord | RequestId/reuse identity, origin ContextId, operation kind/arguments, ABI profile, rooted argument carrier, result sink and custody/cancel state. RequestId survives scheduling rounds; a context can originate later requests with the same opcode without ABA. |
| CQM02 | SelectionRound + SelectedOperation | Freeze admitted pending proposals and role/topology snapshot for this round; bind selected operation, exact represented RequestIds, origin policy and combined argument. A retained legacy profile admits at most one active proposal per participant per round; additional requests stay queued. New arrivals cannot join a result after its capacity calculation. |
| CQM03 | GC combine | Represent each eligible admitted GC request exactly once. Validate admitted nonnegative demand and sum requested_words_still with representability/capacity checks before execution; allocate one CapacityOutcome record. Requests excluded by a higher-priority selection stay pending. Aggregate demand is not a count of W workers. |
| CQM04 | Resize select | Resize remains noncombined: select one request's thunk/count according to the bound policy. Other resize requests survive for subsequent rounds. Their thunks remain actual roots. Target U count and W count are separate parameters/capacity obligations. |
| CQM05 | ParticipantRoleMap | Bind required acknowledgers, root owners, storage tasks, tracing workers, membership actors and result consumers to E/phase. One participant may have several roles; none can attest for an absent owner. Work assignments cover K/S independently of origin set O. |
| CQM06 | Resize child epoch | Authorized child collect inherits the held parent boundary, old U/K/S snapshot and a frozen worker roster. It neither reacquires the same operation gate nor completes unrelated queued GC requests. Any future subsumption optimization needs a separate demand/result/refinement proof. |
| CQM07 | Membership and startup | Publish prepared native context/root storage before any Scheme startup use; bind Dormant/Starting/Participating/Running states and admitted startup GC. Retain old participants needed to serve it. Shrink migrates/drains actual root/storage/return users before physical retirement. Role changes do not mutate an active W roster. |
| CQM08 | Completion fan-out | Publish one authoritative CapacityOutcome from heap-policy authority; qualified participants acquire it before common branch decisions. Then map to each represented RequestId exactly once; Deferred/Rejected/Unknown cannot become old false-success. Preserve/explicitly requalify resize errors, participant-local diagnostics and managed reload. A normalization of CWR07 is a semantic repair requiring evidence, not proved ABI equivalence. |
| CQM09 | Round exit / cancellation | A lost request remains pending; a request whose context retires gets an explicit lifecycle disposition with live roots/result custody, not a forged successful return. Cancellation after selection cannot undo shared GC or free its arguments. A worker fault keeps epoch custody/VM hold; no retry of partial moving collection as a fresh request. |

Analytical examples, not executed tests:

* Two pending GC requests a,b with demands x,y select one GC operation with
  membership {a,b} and checked demand x+y. W=1 or W=8 does not change that sum.
* Pending resize r and GC g select resize first. If its child collection runs,
  g remains pending; a later GC selection consumes g. Counting the child as g's
  result would change the source loop's consumption rule.
* Two resize requests remain two operations, even with identical target count.
  Their thunk, timing, failure and origin obligations can differ.
* An idle NOOP participant scans assigned roots and helps the selected operation
  without receiving a fictitious originating request receipt.

This contract requires reconstruction of selection/result publication and
internal scopes, not a claim that the existing synchronous loop already supplies
RequestRecords or independent-worker roles.

*** 4. Independent Worker Root and Termination Protocol
:PROPERTIES:
:ID: 25fc3e00-caf3-5f7f-9b1c-7aeaf800648c
:CUSTOM_ID: 4-independent-worker-root-and-termination-protocol
:END:

[[file:../diagrams/collector-root-termination.svg][Root materialization and termination]]
[[file:../diagrams/collector-root-termination.d2][D2 source]].

Choose a *closed, stop-the-world moving epoch* with a frozen W roster and a
serialized phase-work authority T. Mutator/root writers are held, final root
descriptors are complete, and external work injection is sealed. This is a
concrete synchronization design to refine, not an implementation or a promise
of fast queue operations. It retains copying/still and later-phase semantics.

Root-stage copies remain charged to their seed-task/producer leases; ready
queue handles and heap pins survive the RootReady-to-TraceStart handoff. A root
producer cannot report completion with unpublished output, and a failed root
stage cannot be skipped to reach TraceStart.

Ready queue links must use reserved or intrinsic chunk metadata. A separately
bounded queue must not make root producers wait for consumers that cannot run
until RootReady. Capacity failure retains producer/work/heap custody and aborts
the admission or holds the failed epoch; it cannot discard copied output. Stack
root descriptors are scoped to their epoch: the next snapshot uses updated
owner state after continuation movement, not cached old stack addresses.

T is a short native metadata gate, separate from G/C/L. It serializes ready-chunk
queue membership, worker activation/deactivation, root-ready state and phase
closure. Payload copying/scanning, native allocation, OS waits and callbacks
occur outside T. Existing chunk payload/trace logic is reusable; existing
independent queue push/pop and idle decrement paths cannot remain uncontrolled
back doors. A faster multi-queue implementation would need its own equivalent
publication/claim/termination proof; this study does not assume it.

| ID | Phase / operation | Closed-loop obligation |
|-
| CWS01 | Enroll and final safe cut | Bind U/K/S/W/P, final owner acknowledgements, worker/facility/heap leases and capacity. Materialize actual root tasks after acknowledgements; seal outside producers. Unbound raw aliases, callback reentry or missing body admission block the epoch. |
| CWS02 | RootMaterialize | Assign every K domain/physical cell to a canonical writer. Each context continuation is a structured task with owner metadata and worker tracing state; preserve shared captured-frame exclusion. Still external roots initialize once per shard. Globals partition by actual root ranges, not legacy worker-as-processor index. |
| CWS03 | RootReady fence | Wait for all assigned root tasks, actual frame writes and seed producers to finish/publish. Root tracing can create copied chunks; cross-worker queued-chunk consumption waits for this fence so incomplete frame/root construction is not read. Existing local tail marking and forwarding/capture synchronization need qualified preservation. Fence cardinality is W acknowledgements plus completed K/S tasks, not U identical barrier calls. |
| CWS04 | TraceStart / active permit | Under T enter the strong trace phase and initialize the fixed worker states once. Every worker capable of scanning, copying, keeping an unscanned private chunk/still chain or publishing work owns an Active permit. Zero-root workers do not count as finished before RootReady. |
| CWS05 | Publish ready work | Active producer builds a bounded ready chunk outside T, then commits its queue handle under T with payload-before-visibility ordering and persistent wake predicate/notification debt. It retains Active through every unpublished/private unit; no host/background producer may publish without such a permit. No per-object ledger allocation is required. |
| CWS06 | Claim / local work | Under T, an idle worker becomes Active before removing queued work; an active worker retains its permit. Pop is exclusive. Scan outside T; derived chunks and private incomplete arenas stay covered by Active. Do not decrement queue count then reactivate after releasing T. |
| CWS07 | Quiesce and strong termination | A worker may relinquish Active under T only after all local seeds/scans/still chains/private partial chunks/forwarding or capture writes and ready publications settle. Recheck the authoritative queue predicate in the same T transition; ready work must be claimed or remain runnable rather than parked behind a false wait predicate. If RootReady, external producers sealed, no remaining seed tasks, queue empty and Active=0, T commits StrongClosed. No new worker activation/publication is legal in that phase afterward. |
| CWS08 | Weak/will and later tasks | StrongClosed is not EpochTerminal. Coordinator opens a distinct weak/will phase with its own seed producers, Active/queue accounting and traversal mode. Complete derived marking before continuation move, table cleanup, sweep/release effects and heap policy. Owner/effect constraints remain explicit; no arbitrary foreign destructor on a GC worker. |
| CWS09 | Resume, result and physical retirement | Publish heap outcome, canonical persistent extents, per-context ResumeBindings and complete relocated root writes; acquire those facts before each context reload/return. EpochTerminal additionally drains actual queues/scanners/cursors/waiters/signallers/resolvers. Worker scratch can retire after real borrows; copied heap extents and live root carriers remain VM-owned. |

**** Termination Invariant
:PROPERTIES:
:ID: 13bbe6c0-bdcb-5150-a2c9-2b7a06b886d6
:CUSTOM_ID: termination-invariant
:END:

For one sealed trace phase, let A be workers with Active permits and Q ready
chunks in the authoritative queue. Local incomplete copied objects, still chains,
claimed chunks and publication-in-progress are covered by their worker's A
permit. Root seeding is separately charged until RootReady. Queue claims,
activation, deactivation and phase closure are serialized by T.

The proposed closure predicate is:

    RootReady && external_producers_closed && seed_tasks_remaining == 0
    && A == 0 && Q == 0

Every unfinished trace obligation must be represented by a seed obligation, a
queued item or a live Active owner. This representation invariant, correct
forwarding/tracing and phase admission are *premises*, not consequences of an
integer check. Once T closes the phase, no legal producer remains to create new
work in it. A new weak phase is a new authorized producer domain, not a spurious
reactivation of the closed strong phase [CW-P01/P02].

Each root producer acknowledges through T only after its actual root/frame
writes and output publication. RootReady and TraceStart use that same qualified
synchronization authority; workers acquire it before consuming ready work.
Likewise every worker's final writes precede its deactivation transition, and
the coordinator/context resume acquires the resulting phase/resume publication.
This is an explicit visibility chain to qualify in C or Zig, not a claim that
volatile fields or an unrelated barrier already provide it [CW-P05].

Notification debt and physical borrowers are deliberately outside the logical
A/Q predicate: a thread may still need to observe closure, return from a wait or
finish signalling. They block facility destruction, and live notification debt
is required for progress. Waiting uses the durable predicate under T and the
qualified condvar/event protocol; spurious wakeups recheck phase/Q before any
activation. Do not nest T with legacy queue locks or hold it while waiting for a
resolver that needs T/G. The proposed single metadata queue trades a simpler
proof boundary for potential contention; no performance dominance is claimed.

A lost worker with a private chunk still owns an unfinished obligation. Its A
permit must not be decremented by a timeout. Transfer of that work needs verified
old-worker exclusion, complete task/arena disposition and preserved heap state;
otherwise hold/quarantine the epoch and VM. Safety retention is not a finite
shutdown or memory bound. Shared native cancellation does not reverse relocation.

*** 6. Migration and Open Gates
:PROPERTIES:
:ID: 416266bf-f2ff-54a6-811c-3641d0bc5443
:CUSTOM_ID: 6-migration-and-open-gates
:END:

1. Bind concurrency, semantic roots/frames, allocator/hooks, ABI and participant
   profiles; the 34-field inventory is only one selected correspondence slice.
2. Introduce durable request/selection/role/result semantics across public/private
   GC/resize and all startup/error/retirement clients, preserving source policy or
   explicitly qualifying semantic repairs such as common capacity outcome.
3. Split copy arenas, context resume areas, heap shards and epoch queues. Replace
   implicit VM/PSTATE access and occupancy/capacity reductions together.
4. Close root materialization/capture publication and implement one qualified
   termination authority for the complete work producer/claim domain. This is a
   required future migration step, not authorization to implement in this study.
5. Preserve weak/will/cleanup effects and publish resume/storage/result records;
   drain actual worker/facility users before retiring old routes by cohort.
6. Bound post-reuse C-full/C-ZT/Z-full support and costs at equal capability before
   selecting Zig or authorizing any separate native qualification.

Remaining gaps: transitive field/helper coverage, root/frame completeness,

allocator sharing/capacity, forwarding/capture native ordering, T/queue and

bounds. No worker profile or old runtime path is qualified/retired here.
