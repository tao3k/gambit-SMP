| SC-P01 | [[https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf][WG14 N1570]], §5.1.2.4. | Release/acquire synchronization can order initialized stores before consumer reads. Volatile/list-pointer stores and data-layout resemblance alone do not qualify C/Zig cross-language publication. One opaque service ABI or a proven native mapping is required. |
| SC-P02 | [[https://simonmar.github.io/bib/papers/parallel-gc.pdf][Marlow et al., Parallel Generational-Copying Garbage Collection with a Block-Structured Heap]], §§3.1--3.3, Figure 2. | Forwarding/copy claims, private tospace allocation blocks and incomplete scan work are distinct responsibilities. Motivates explicit worker tails and borrowers; neither GHC block layout nor its performance transfers to Gambit. |
| SC-P03 | [[https://ocaml.org/manual/5.3/intfc.html][OCaml manual, Interfacing C]], §§4.4, 5.1. | Safe high-level allocation initializes traced fields; low-level allocation requires legal initialization before another allocation. Local/parameter roots are explicit. This supports separate scan-safe and semantic initialization, not importing OCaml tags, generations, barriers or macros into Gambit. |
| SC-P04 | [[https://kcsrk.info/papers/retro-parallel_icfp_20.pdf][Retrofitting Parallelism onto OCaml]], §4.4. | Root coordination, stop-the-world entry and copying races are separate modernization duties. Runtime GC changes must preserve language/FFI behavior; switching the systems language does not discharge them. No OCaml collector or benchmark claim is adopted. |
| SC-P05 | [[https://www.llvm.org/docs/Statepoints.html#overview-core-concepts][LLVM statepoints]]. | Compiler relocation/root support needs a runtime protocol and correct use of relocated references. It does not manage still credits, constructor effects, heap intervals or shutdown. LLVM/MLIR compiler benefits are available to both modern C and Zig service implementations. |
| SC-P06 | [[https://ziglang.org/documentation/0.15.1/#Lifetime-and-Ownership][Zig lifetime/ownership]], [[https://ziglang.org/documentation/0.15.1/#errdefer][errdefer]]. | Explicit allocators and local error cleanup may reduce private builder support; pointer lifetime remains programmer responsibility. errdefer cannot legally refund a Consumed grant, free a published root, cancel a live native writer or replace GC rooting. |

Links include actual publication/manual identities for reproducible evidence;
these are not architectural generation names. Paraphrases support design
premises only. No timing, speedup, pause, RSS or maintenance-hour number is
imported from a paper into the net-benefit conclusion.
