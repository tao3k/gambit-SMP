* Decision and evidence boundary
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-decision
:MAINLINE: modern-generated-C
:STATUS: conditional-model-source-refinement-open
:END:

Modern generated C remains mandatory. Scheme owns FFI semantics, converter
selection and generated release declarations. Modern C owns explicit release
rights, immutable effect profiles, reservation ledgers, root-domain handles and
origin-specific dispatch. Moving these boundaries can amplify Gambit's C FFI
and multicore GC independently of a language migration. No incremental Zig
runtime-work saving is established by this study.

A release-function pointer is neither an effect description nor an ownership
receipt. Admit delayed GC release only for a registered producing protocol and
a concrete release right whose budget, dependency roots, code lifetime, thread
permission and legal delay have all been established. Unknown custom C is an
open-world boundary. An inventory of this repository cannot authorize every
loaded extension or every downstream direct write to an exported object layout.

[[file:models/sysml/release-producer-admission.sysml][GambitReleaseProducerAdmission]] is the maintained authority for component
obligations, dependencies, source routes, caller/cost rows and diagram topology.
Native sysml evaluates it together with the previously selected model sources.
[[file:../../../modeling/ascent/release-producer-admission.rules.scm][The actual ASCENT rules]] join native obligations to exact artifact, digest,
method, check and scope; [[file:../../../../models/gambit/release_producer_admission.qnt][QNT]] and [[file:../../../../models/gambit/lean/ReleaseProducerAdmission.lean][Lean]] qualify only conditional formal slices.
The [[file:release-producer-admission-matrix.org][generated matrix]], [[file:diagrams/release-producer-admission.d2][D2]] and [[file:../../../../evidence/research/release-producer-admission/checks.json][receipt]] expose remaining source and C-memory
obligations. The [[file:resume-seal-cleanup-design.org][preceding resume-seal study]] stays historical; its open
premises are imported as needs, never as successful native receipts.

No runtime implementation, native test, benchmark, production-path retirement,
commit or push is included. SysML validation does not prove every requirement
instance. Finite sampled QNT traces do not establish exhaustive coverage or
fairness. Lean does not yet simulate all QNT actions, native effects or actual C.

** Direct runtime constructors

[[file:../../../../vendor/gambit/lib/os_io.c::4550][os_io.c]] contains twelve direct foreign-wrapper registration expressions:
ten register device_cleanup_from_ptr, one registers release_rc_tls_context, and
one registers release_event inside the Win32 event-read branch. A thirteenth
runtime expression in [[file:../../../../vendor/gambit/lib/setup.c::1942][setup_module_collect_moddescrs]] wraps a permanent
module with a null release pointer. These are thirteen expressions, not thirteen
release-function implementations, active Darwin paths or runtime jobs.

The native-derived caller matrix lists all twelve names and source coordinates:
TLS construction; event queue read; raw fd open; predefined stream open; path
stream open; process stream open; TCP client open; TCP server open; accepted TCP
client conversion; UDP open; directory open; and event queue open.

Every constructor has two duties: establish ownership of the native result,
and hand that exact duty to a wrapper or retain it through conversion failure.
The same callback name does not make their rollback behavior equivalent.

Three concrete source cuts require correction or additional ownership evidence:

| Source cut | Observed source behavior | Admission consequence |
|------------+--------------------------+-----------------------|
| os_io.c:10952, TCP server read | Wraps client; on conversion failure calls device_cleanup on d, the server | Reject until rollback payload and server/client lifetime obligations are reconciled |
| os_io.c:10615, process open | On conversion success drops the Scheme hold; failure has no local dev cleanup; argv/env/dir temporaries are cleaned | Reject until native result custody and return/error mapping are explicit |
| os_io.c:7135, Win32 event read | PeekMessage(PM_REMOVE) consumes an event then directly returns the conversion result; no local conversion-failure release branch | Reject this profile until consumed message and RC result failure ownership are covered |

These are static observations. No failure was executed; no leak frequency,
platform impact or repair correctness is claimed. Existing behavior cannot be
silently called correct and reproduced as a new ownership contract.

** Generated and custom producer protocols

[[file:../../../../vendor/gambit/gsc/_ptree2.scm::2586][c-type-converter]] selects POINTER, NONNULLPOINTER, STRUCT, UNION and TYPE
conversions. Pointer defaults select RELEASE_POINTER, whose current body is a
no-op because the C world owns the pointee. Default value conversions emit three
release templates. The compiler deduplicates generated release code by
(kind . name) within a module; it does not deduplicate per-object release rights.

[[file:../../../../vendor/gambit/include/gambit.h.in::9838][The current allocation macros]] define RC allocation for foreign values;
the C deletion branch releases RC storage. The alternative C allocation branch
uses ALLOC_MEM/FREE_MEM. Effect profiles must bind actual preprocessing and
allocator selection; a generated TYPE release is not automatically free(),
thread-neutral, or independent of processor RC-chain lifetime. C++ branches are
source configuration context, not a proposed architecture.

[[file:../../../../vendor/gambit/gsc/_ptree2.scm::2380][check-c-type]] validates a custom release identifier's syntax. The identifier
is then emitted directly. It supplies no effect, root, lock or affinity proof.
Named custom converter definitions, c-declare text, public conversion APIs,
loaded modules and direct representation writes remain admission-controlled
escape paths. A closed managed domain must register them or refuse independent
worker/deferral qualification for the affected domain. Merely rejecting the
currently observed pointer leaves future unregistered producers possible.

[[file:../../../../vendor/gambit/examples/Xlib-simple/Xlib.scm::61][The Xlib example]] supplies four actual custom release registrations:
release_rc_XGCValues, XFreeFontInfo_XFontStruct, release_rc_XColor and
release_rc_XEvent. Three release RC; the font helper calls XFreeFontInfo.
Conditional debug printing and really_free macros affect actual behavior.
These examples exercise custom generation; they do not prove installed Xlib,
RC ownership or cross-thread safety. The pthread example's default pointer
release adds no custom owning release function. Scalar test converters do not
become owning foreign producers merely by using c-define-type.

** Installer and invocation endpoints

[[file:../../../../vendor/gambit/lib/c_intf.c::5156][POINTER_to_SCMOBJ]] is the inspected installer of release_fn and native ptr;
the nonnull converter forwards to it. It allocates the wrapper and can fail.
The native producer has already run when this converter receives x: reserving
only here is too late for producer failure/rollback capacity.

[[file:../../../../vendor/gambit/lib/c_intf.c::5283][STRUCT/UNION/TYPE conversion helpers]] call release_fn(x) directly on conversion
failure. [[file:../../../../vendor/gambit/lib/_kernel.scm::3884][Explicit foreign-release!]] calls release_foreign and observes its result.
The generated _kernel.c copy is not a second semantic producer. [[file:../../../../vendor/gambit/lib/mem.c::4390][Sweep and
free_still_objs]] invoke release_foreign before wrapper free; teardown then frees
RC chains. release_foreign clears callback/pointer fields before arbitrary C
invocation. Its at-most-once guard does not establish accepted task ownership.
release_function is a separate C-closure helper, not evidence of another
registered foreign-wrapper producer; non-null FUNCTION_to_SCMOBJ is unsupported
in the inspected body. Do not count every release-prefixed helper as a producer.

* Effect and thread-ownership contract
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-profile
:END:

SysML ReleaseProfile, ResourceBudget and ReleaseRight define distinct types.
ReleaseProfile is immutable for a code/library/configuration generation. It
records allowed origins, callback effects, VM/processor/OS-thread affinity,
allocation/free/lock effects, dependency shape, delay permission and a bounded
reservation recipe. ReleaseRight identifies one acquired release duty and owns
its concrete resource budget, root/trace receipts, result custody and reader/
child debt. A pointer address or callback address is not that identity.

| Family | Transitive effects to describe | Required owner/affinity evidence | Deferral disposition now |
|--------+-------------------------------+----------------------------------+--------------------------|
| Default pointer / null permanent wrapper | No native disposal via callback | Borrow/code/module users still have lifetimes | Zero release jobs; no invented asynchronous work |
| Generated C value release | RC decrement/free, possible RC-chain mutation | Exact RC owner, allocation domain, readers and teardown | Candidate only after RC and lifetime refinement |
| TLS context release | Strings, SSL_CTX_free, RC release, configured library callbacks | Library/config generation, RC domain and callback policy | Unknown callbacks or owner dependency rejects worker execution |
| Device cleanup | Group unlink, close read/write, select/poll waits, virtual release, storage free | Device subtype, group synchronization, native borrowers, explicit WaitContext, actual callback owner | Per-leaf profile required; one common callback is insufficient |
| Win32 event release | RC MSG release; producer also consumes a thread message | Message-source thread and RC domain are separate | Source failure gap and target evidence block admission |
| Xlib custom helpers | RC or XFreeFontInfo, optional debug I/O | Library/display policy, RC domain, code pins | Unqualified; no blanket cross-thread dispatch |
| Arbitrary custom release / converter | Any C/library/callback/lock effect until restricted | Explicit audited manifest and capability boundary | Reject deferral and domain qualification when unknown |

“No managed callback observed locally” is weaker than a transitive no-callback
profile. A worker-safe profile may not borrow PSTATE scratch or mutate a source
RC chain after teardown. Owner-affine work becomes accepted post-seal dispatch
with rooted activation; cleanup must never wait for the callback that needs
that seal. Raw managed nonlocal exits across a foreign frame, unknown lock order,
unbounded fanout, unknown native byte bounds and unknown resource disposition
are rejection conditions for the relevant bounded deferred profile.

C acquire/release publication must make the entire immutable profile and exact
instance visible before a consuming worker obtains authority. Configuration
changes revoke new admission for that generation; existing rights retain their
old profile/code/library pins until drain or a proved equivalent transfer. A
function-pointer equality check cannot authorize migration to a changed profile.

* Reservation before production and a closed collection cut
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-budget
:END:

** One duty, one persistent ticket

#+BEGIN_EXAMPLE
preflight(profile, origin, known input bounds)
  -> reserve physical/credit capacity and return slot
  -> register concrete dependency handles and pin code/native users
  -> invoke native producer
  -> conversion consumes same reserved right
  -> Wrapped OR synchronous rollback OR retained unknown outcome
  -> accepted GC service custody -> running -> terminal-retained -> retired
#+END_EXAMPLE

This is an architecture protocol, not implemented C. CFUN/SFUN result adapters
must preflight before invoking native resource-producing code. Direct runtime
constructors need the same cut before the allocation/open/consume operation,
not just immediately before wrapper conversion. Inputs requiring conversion
must have separate rooted preparation and error semantics. If output bounds
cannot be derived from inputs or a trusted provider contract, the bounded
profile refuses admission; it does not guess a native allocation size.

Reservation and root-slot preparation must be bounded no-GC operations over
already backed service storage; they cannot introduce an earlier unprotected
safepoint. Existing Scheme arguments remain protected by the caller's frame/root
contract throughout preparation. Preflight may reserve empty result-root slots,
but a provider that creates new managed dependencies must populate registered
handles before any callback, collection or native escape can expose them.
Registering only after that provider returns is insufficient if it could have
reentered Scheme. Unknown result dependency shape or a non-cooperating provider
therefore rejects this profile. This is a required source refinement, not an
existing property inferred from the C conversion signature.

The budget is a resource vector q_i: task slots, root cells, code/library pins,
wait storage, native-byte capacity, external handles and descendant capacity.
A bounded release body may reuse its ticket as a resumable continuation. If it
can create children, each transferred child needs pre-reserved capacity and
parent/child conservation. Unbounded fanout is outside this admitted profile.
The small formal model covers two fixed-size rights and cannot prove arbitrary
vector bounds, recursive child production or actual allocator backing.

#+NAME: release-credit-partition
#+BEGIN_EXAMPLE
M_live = Constructing + Wrapped + Queued + Running + TerminalRetained
for each resource dimension k:
  sum(live right q_i[k]) + separately charged descendant commitments <= pool[k]
#+END_EXAMPLE

These states are disjoint. Transfer never charges the same right twice. A
reservation recipe must distinguish shared physical backing from multiple
release rights: two RC acquisitions may share a pointer and still require two
decrements/tickets; exclusive native ownership cannot be duplicated. The actual
physical-byte ledger counts a shared allocation once and releases it only after
its last physical dependency. Conservative per-right quota bounds may overreserve
bytes, but cannot be reported as actual retained allocation bytes.

Budget capacity must correspond to pre-existing physical storage, including
allocator overhead and root/wait records. Logical integer credit alone cannot
promise allocation success. Admission failure before the first native effect
returns a preparation error with no newly produced resource. After an effect,
known source custody or accepted service custody persists; an observer timeout
or scalar error cannot manufacture a refund or a second cleanup invocation.

** Constructor debt: the discovered counterexample

The retained initial sampled model allowed seal with a reserved constructor,
then let that constructor create a native object with an untraced dependency.
The failure log is retained as before-constructor-cut-simulation.log (replay seed
0x719). This refutes “producer entry closed + credits counted implies roots
closed”. The corrected model requires no unresolved constructor debt before its
dependency closure seal. The dedicated counterexample remains a named history.

A source refinement must choose a non-cyclic cut: complete enrolled construction
before closure, abort a reservation proven to precede every native effect, or
park a suspended producer with an explicit next-generation permission and a
frozen complete root/native view. The current model proves the first two
abstract alternatives only; it does not model a parked next-generation permit.
An in-flight foreign producer with an unknown effect cannot be blindly aborted.
GC may not wait on an owner already waiting for GC return. If the required cut
cannot be established, refuse the profile/recovery rather than assert progress.

** Root dependencies close at three distinct cuts

1. Profile registration declares all dependency kinds and effect paths. This
   establishes a recipe, not a concrete root or a lifetime extension.
2. Before the first possible collection, native escape or reentrant callback,
   register actual relocation-safe handles and pin code/native storage. Avoid
   permanently rooting the finalizable wrapper itself; retain its declared
   dependencies with a precise release boundary.
3. Before cleanup settlement/WholeRoundResumeSeal, the current round has traced
   every retained managed dependency and closed admitted root writers. A late
   edge requires an already counted producer, reserved capacity and a pre-seal
   rescan; otherwise closure and deferral are refused.

FOREIGN payload is opaque in the current scanner. RC addref alone does not
survive cleanup_rc's unconditional teardown. Nonzero processor registration,
scan ownership, root-domain publication and actual relocation paths remain
imported source obligations. Enqueue and profile registration cannot replace
these proofs. Retained code, native borrowers, root-domain readers and task
children must drain before retiring dependency storage or recycling a ticket.

* Origin-preserving dispatch and failure custody
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-origins
:END:

| Origin | Semantic endpoint | Required custody and decision |
|--------+-------------------+-------------------------------|
| GC sweep | At-most-once invocation for an unreachable foreign wrapper | Qualified legal delay plus traced dependencies, pre-reserved task and accepted custody before destructive detach |
| Explicit foreign-release! | Synchronous visible effects/result or Scheme exception | Keep caller boundary; shared typed dispatcher is possible, blanket queue-and-return is not equivalent |
| Value conversion rollback | Native result created but Scheme conversion failed | Same reserved result right; invoke synchronous cleanup or retain source-known unknown outcome; preserve original conversion outcome contract |
| Native device/TLS constructor rollback | Partial initialization/open/consume followed by conversion failure | Per-constructor payload identity, stages, temporary resources and library effects; the three source cuts stay blocked |
| Teardown | free_still_objs followed by RC and OS-service withdrawal | Close producers, settle or transfer tasks, drain readers/children/code/roots, then withdraw services in dependency order |

Unknown callback outcome keeps the attempt identity, pins and budget. It never
permits replay or refund. Unknown handoff/root/constructor ownership blocks the
GC-critical closure permit. Separately proved native-only outcome uncertainty
may be isolated after an accepted handoff, as in the predecessor; this study
adds no blanket isolation proof. If device_release already freed storage despite
an error, a second free is invalid. Error value, native effect progress and
storage disposition require separate fields.

* Formal refinement chain and retained falsifiers
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-proof
:END:

The SysML need graph drives ASCENT method selection and dependency blocking.
RP-H binds the exact QNT file/digest/scope; RP-I binds the exact Lean file and
named declarations. RP-CENSUS, RP-EFFECTS, RP-BUDGET, RP-ROOTS, RP-ORIGINS and
RP-ORDER are independent obligations. Seven imported RS needs remain open.
No successful predecessor formal slice is relabeled as a source simulation.

QNT represents two rights in one admitted abstract effect class. It covers
reservation before native construction, independent rights with shared function
identity as a premise, slot/native-credit exhaustion, in-flight debt, root trace,
synchronous rollback, origin rejection, unknown results and reader-gated refund.
It retains explicit unsafe histories for allocation before reservation,
function-level dedup, early seal with constructor/root debt, unknown-result
refund/replay, reader-unsafe retirement and deferred explicit release.

Lean proves conservation across a separate credit Step/Trace relation, scalar
quota consequences, conditional effect/affinity/root/origin rejection,
constructor/root debt rejection and dependency-coverage composition. These are
necessary premises, not a verified implementation of profiles or all QNT
transitions. C-memory refinement must locate actual linearization points for
reserve, producer-gate close, accepted custody, root publication and retirement;
then prove acquire/release ordering and generation reuse safety.

Five actual ASCENT cases check current evidence, missing history, wrong scope,
stale digest and an explicitly synthetic all-scoped positive control. An
independent Scheme-fact reader compares need/dependency/artifact/route transport
against native SysML observations. Current exact formal slices do not close a
component while source/order obligations remain. The synthetic control verifies
routing logic only and has runtimeAdmitted=false.

* Mechanism learning, benefit and falsification
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-benefit
:END:

The [[https://ocaml.org/manual/5.3/intfc.html][OCaml custom-block contract, sections 9.1-9.3]] separates opaque native data,
restricted finalizer interactions and out-of-heap resource pressure. Its used/max
and custom-memory parameters guide collection pressure; they are not a hard
release-queue capacity guarantee. Gambit should learn the separation while
retaining explicit root, continuation and FFI semantics. This design adds hard
admission reservations rather than treating a GC pacing heuristic as a bound.

[[https://www.hboehm.info/popl03/slides.pdf][Boehm's POPL finalization/synchronization discussion]] motivates treating native
users, locks and shutdown dependencies explicitly. Its Java examples and cost
observations do not establish Gambit speedups. [[https://cs.brown.edu/people/mph/HerlihyW90/p463-herlihy.pdf][Herlihy and Wing's linearizability]]
provides the operation-history criterion used for reservation, handoff and
retirement cuts; naming those cuts is not a proof that C implements them.

For a matched serial critical-path comparison with unchanged core work,
conditional saving is sum eligible(F_i-H_i) minus new profile/root/ledger costs.
Only eligible legal-delay release bodies leave the round-critical path. This is
not a wall-time prediction under overlapping workers or a native benchmark.

Peak is max over time of simultaneous heap, physical pools, unique retained
native backing, root backing and quarantine. Reserved-but-unused storage counts
if physically allocated. Queue ACK is no free. Unknown effects can retain memory
indefinitely; admission caps bound new work but do not prove eventual drain.
No whole-round peak reduction has been established. The native-derived matrix
separates reusable support, transferred work, added persistent costs and each
positive-benefit condition. No person-day estimate or arbitrary percent is used.

* Migration and retirement conditions
:PROPERTIES:
:CUSTOM_ID: release-producer-admission-migration
:END:

1. Scheme emits a single typed ReleaseSpec from converter semantics; audit custom
   converter/c-declare/module registrations. Resolve the three constructor
   failure-ownership cuts before enabling their managed profiles.
2. Introduce modern C per-instance rights and pre-native-call preflight adapters.
   Establish real budget backing, exact payload ownership and generation-bound
   code/config profiles. Preserve explicit and rollback observation boundaries.
3. Establish concrete root-domain registration, current-round tracing and RC/
   code/native lifetime transfer; prove closure without owner/GC wait cycles.
4. Replace destructive clear-then-call only when accepted custody, at-most-once
   dispatch and typed effect/disposition are source-preserving. Share the same
   support across eligible producers rather than stack a second language layer.
5. Retire implicit PSTATE wait scratch and synchronous collector invocation only
   for fully qualified leaf/origin cohorts. Keep caller-synchronous adapters for
   explicit/rollback contracts. Withdraw old module/RC paths only after actual
   service/readers/children drain and independent native acceptance.

No old path is retired now. Remaining gates include installed-target inventory,
transitive library effects/affinity, external write capability closure, physical
budget bounds, parked producer progress, concrete root relocation and C memory
ordering. These are tracked obligations rather than optimistic implementation
claims.
