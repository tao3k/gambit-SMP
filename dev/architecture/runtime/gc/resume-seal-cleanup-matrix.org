* Benefit and peak-memory matrix
#+NAME: root-costs-native
| Capability | Removed work | Quantified bound | Added cost | Condition or falsifier |
|---+---+---+---+---|
| GC critical path | Move only qualified delayed release body off round-critical cleanup | Serial conditional work: old=Tcore+sum(Fi), new=Tcore+sum(Hi)+ledger/rescan costs | Reservation/handoff, root closure and new queue contention | Saving only if Fi exceeds Hi plus added costs and delay semantics permit; no measured time or universal positive benefit |
| Task support | Reuse shared descriptor/queue/attempt/result machinery across eligible leaves | One reserve, acceptance, claim and terminal-publication transition per ordinary task; notifications/queries separate | Stable metadata, source/service custody and bounded admission pools | These are design operations, not four machine atomics or four syscall costs |
| Root coverage | Preserve callback procedure/managed dependencies across delayed execution | Additional root scanning O(Rdeps); newly discovered roots require closed rescan before seal | Root-domain records, relocation-safe handles and retained dependency backing | Opaque foreign payload cannot silently become scanned; no new unseen managed edge after closure |
| Native result ambiguity | GC can resume despite isolated native outcome uncertainty | Zero additional invocation on outcome query; zero refund without known disposition | Native task/backing retained, possibly indefinitely | Only effect-isolated admitted cohort; handoff/root/gate/capacity uncertainty still refuses resume |
| Error and disposition | Avoid replay/free based on scalar error | At most one invocation per foreign release attempt; FailedFreed must not free again | Typed effect progress and allocation-disposition ledger | Current device_release can free on error; external close outcome and device-storage outcome differ |
| Owner callback cycle | Publish accepted callback task then let owner reacquire before executing it | Cleanup waits handoff/root closure, not owner callback completion | Post-seal dispatch and activation/root/binding protocol | Unknown affinity/hidden callback or delayed-effect semantics rejects profile; no guaranteed callback latency |
| Admission memory | Reserve delivery/root/native-dependency budget before released GC profile is admitted | For M admitted possible jobs: O(M) task slots plus exact retained native/root backing budget | Registration/reservation capacity can raise resident/peak memory | Pool failure before destructive transfer retains source; never block GC waiting for owner that waits for seal |
| Whole-round peak | Keep physical backing distinct from wrapper retirement and receipt ACK | Peak=max_t(existing backing+task/receipt/wait pools+retained roots/native payload+quarantine) | Deferred cleanup may postpone native/RC/library release beyond this GC | Do not add independent maxima or refund on enqueue; no whole-round peak reduction proved |
| Modern C architecture | Reuse Scheme semantic/FrameSpec output and C representation/conversion machinery | Zero additional Zig runtime-work reduction established | Both require effect/origin profiles, root transfer, stop/restore and ordering proofs | Modernization gain is role/ownership/phase separation, not a language-provided GC or automatic finalization proof |
