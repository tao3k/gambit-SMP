*** 1. Necessary Support Units After Reuse

implementation snippets, LOC estimates or mandatory generic-library components.
Use one common service. Ten wrapper registrations do not require ten copies.

Retaining C library/code/VM dependencies costs memory and support in both. |

The old ~device_cleanup~ loop and group-cleanup drain body cannot remain the
hidden authority for migrated callers: the former owns implicit-PSTATE waits
and unlinks before error; the latter frees its group after a cleanup error.
The replacement common stage/drain bodies are needed in both C-full and Z-full.
They may reuse leaf close/release operations under qualified assumptions, not
reinvoke the whole old helper and claim independent WaitContext ownership.

Potential shared construction savings belong to the union of WSU01/06/09's
remaining ordinary native construction work after reuse, not every asynchronous
unit. Language-local enum/slice checks are useful mechanisms, but no claim is
made that they prove ownership, cancellation or resource disposal.

*** 2. One Concrete Builder Comparison
:PROPERTIES:
:ID: 8eaebfae-8da0-5db9-876a-0ec1c81225f7
:CUSTOM_ID: 2-one-concrete-builder-comparison
:END:

For an admitted POSIX/select profile a WaitContext builder validates capacities,
acquires two native bitmaps plus an optional exception bitmap, acquires a wake
endpoint pair, configures flags, initializes identity/predicate state, and
publishes. Source already has the two/three-buffer failure funnel and candidate
endpoint rollback [DW-S03/S08]. This is a dependency graph, not a native test.

C-full can use null buffer pointers, invalid-fd sentinels, one partial-destroy
routine and one publication transfer. It need not maintain a flag for every
failure edge or a generic container library. Z-full can use equivalent fields
with lexical errdefer/defer before transfer; it still needs partial resource
state, a correct destroy operation and a transfer/disarm law. Once published,
both must use asynchronous wait/wake/reader drain rather than scope exit.

The three buffer cleanup bodies or two endpoint closes are not removed because
syntax is shorter. An actual exclusive saving must be in necessary builder
control/review work remaining after the C helper/funnel/generator alternatives.
New C generation has development/schema/qualification cost; new Zig comptime or
helper machinery has corresponding cost. Existing Scheme generation is actual
reuse, not a forecast of cost-free new generation. Neither alternative's local
construction saving is quantified yet.

| WRT01 implicit processor OS scratch in release waits | WCT01--WCT07 and explicit wait adapters serve every migrated cleanup caller; managed condvar path retains its own admitted law |
| WRT02 synchronous caller/wrapper lifetime as delivery custody | DLT01--DLT06 and every release origin establish accepted ownership, reservation and result resolution; raw ABI outside cohort remains priced |

No existing source authority/body is retired by these documents. A new Zig
wrapper that keeps the old implicit scratch, synchronous custody and group-free
logic satisfies none of these exits. Full reconstruction capability remains the
same for the C and Zig alternatives.

*** 4. Net Benefit, Bounds and Refutation
:PROPERTIES:
:ID: 7d0ec93c-28be-5b56-bc97-b08267c16a54
:CUSTOM_ID: 4-net-benefit-bounds-and-refutation
:END:

Use one effort unit and declared support horizon. Let K be the disjoint union
of necessary native support/change bodies **remaining after actual reuse and
costed alternatives**. Let cC(k), cZ(k) include construction, review, upgrades and
qualification for each unit; count shared pool/queue/builder support once.

#+BEGIN_SRC text :eval never
IncrementLower = sum_k [ lower(cC(k)) - upper(cZ(k)) ]
                 - upper(Z-only migration + tooling + ABI/residual cost)

Zig effort selection requires IncrementLower > 0,
plus independently positive total modernization and admitted semantics/runtime.
#+END_SRC

Common wait/context/lifetime/LLVM modernization gains are outside this language
increment. Build latency, GC pause, release latency, descriptors/images/bytes
retained over time and support effort remain separate dimensions unless an
explicit policy prices them. No empirical phase follows merely from fewer
syntax branches.

| ID | Positive condition and matched counterexample |
|-
| WNB01 private construction | Positive only if unavoidable post-reuse C construction/change support is demonstrably absent or cheaper in Zig by a bounded amount. Refuted for a proposed saving if existing C funnel plus shared destroy already covers it with no additional avoidable support. |
| WNB02 shared portfolio | Multiple demanded services can amortize a new necessary private helper's fixed setup once. Refuted by multiplying one shared service saving by ten callers, or inventing helper demand. If C already shares the helper, client count is not a crossover proof. |
| WNB03 actual authority replacement | Savings require WRT exits and deletion/retirement of corresponding support. Refuted by indefinite dual old/new state machines or unpriced C/ABI islands. |
| WNB04 finite native progress | Deferred work needs live owner/library/executor and bounded retained obligations. Refuted by a stopped owner, a peer that never progresses or an unbounded descendant stream; shorter GC path alone is insufficient. |
| WNB05 cancellation correctness | Observer cancellation must preserve native task custody and known partial effects. Refuted by dropping queued work, replay after uncertain close or freeing outcome while a resolver reads it. A semantic failure cannot be traded for saved effort. |
| WNB06 comparable maintenance | Both price new C generation and Zig comptime/tool/binding support; use existing helper/OS libraries first. Refuted by a free imaginary C generator or a deliberately duplicated C baseline. |
| WNB07 positive conservative bound | Justified lower avoided-support savings must exceed all upper added Z-only costs and residual runtime limits. With K empty and positive added Z cost the incremental effort result is negative. Unknown intervals leave the claim unresolved, not positive. |

The native wait/task/drain architecture has source-backed necessity. This slice
establishes no strictly positive Zig-only support-effort lower bound, no global
positive modernization bound and no native admission. The next theory evidence
must supply exact target/effect/user/wake refinement and post-reuse support-cost
bounds. Current conclusions are conditional; no implementation/native test or
architecture generation naming is introduced.
