Arguments over [[file:tcl-reuse-service-design.org][SD01–SD15]] and
[[file:tcl-reuse-service-evidence.org][pinned evidence]]. These are handwritten conditional
proofs and source-composed cases. No native tests, whole-program analyzer, model
or proof engine ran. The corpus operation is a bounded lexical text search.

SP01. *Correct private entry.* Assume matching source/ABI/header/stub archive,
successful actual stub initialization, validated public hook/private table/reset
entry and a live lease on the matching core image. Capture those entries in the
facade without concurrent rebinding. Dispatch through that capability calls the
selected library's reset, independent of a later unrelated global pointer.
A version-only macro call, non-NULL stale private global or matching public magic
cannot establish these premises. Failed binding publishes no capability. This
proves an access contract, not the unperformed link/load qualification. [SD01–SD03]

SP02. *Selected producer closure.* The source graph establishes registration,
request/mark, callback/child installation, consumers, reset and deletion for the
selected core paths. A native API caller needs a joined epoch lease; synchronous
interp cancel within an accepted scope is bounded by that scope's actual return.
Include internal child creation and all reached target/ancestor generations.
Only when every loaded/embedding producer is covered or explicitly excluded can
the selected source graph become a managed ProducerClosureReceipt. The 350-file
negative text results alone cannot supply that step. [SD04–SD07]

SP03. *Idle interval.* Assume every accepted native/NRE/event/async/control
entry registers before effects and retires only after actual return, all such
sources are closed, the real OS owner holds exclusive BarrierTicket and the
affected tree is stable. Zero outstanding scopes plus zero native nesting and
no active async invocation then permits a borrowed OwnerIdleReceipt. Any admitted
reentry revokes it. The parser's decrement/reset inside a surrounding activation
is a concrete refutation of deriving this receipt from numLevels/flags alone.
Unsupported foreign escapes remain outside the premise, not an automatic cleanup.
[SD06, SD08–SD10, SL02]

SP04. *Existing thread-wide pending settlement.* Under SP02–SP03, all old API
calls returned and each eligible handler is context-safe, finite and under the
same closure policy. Owner AsyncInvoke runs ready handlers and rescans outside
an active invocation; all derived tasks are charged before parent settlement.
Renew owner-idle after callbacks. No old mark can be installed later because
its producers are closed. A NULL invocation is valid only if every eligible
handler supports that context. The testasync source defeats assuming this for
all handlers. The claim is conditional; no loaded handler manifest was certified.
[SD07–SD11]

SP05. *Proposed targeted settlement.* Assume a Tcl-owned helper exists with the
SD12 contract, validates target token/owner/generation, preserves order and other
handlers, follows cancelLock -> asyncMutex, performs no arbitrary callbacks,
and atomically records each old pending disposition before clearing/resetting.
Under closed old senders and actual idle scope, no old target mark remains or
can be reinstalled before publication. This may settle rather than execute an
old cancellation only under the declared epoch-bound request policy. It is not
equivalent to silently discarding raw idle cancellation. No such helper was
implemented or inferred from private reset slot 237. [SD05, SD09–SD12]

SP06. *Reset-to-publication.* Require the same binding/ticket/tree throughout,
a current idle receipt, a pending receipt from SP04 or SP05, verified non-forced
clear-state postcondition and revoked old authority. Exclude callback-capable
work in the interval; prepare storage earlier. Publication under the lifecycle
lock synchronizes with next-job acquisition. Inductively, a new request either
uses the fresh epoch or rejects before pointer use; a queued old request cannot
become fresh by resolving current state later. If any premise changes, invalidate
and close again rather than publish an obsolete ResetReceipt. [SD08–SD14, SL01]

SP07. *Custody on failure.* At every point the old producer/receiver or facade
lease owns live outcome roots, native result/string support and image references.
Binding failure, unknown handlers, reset no-op, lost ownership or stale witnesses
leave admission sealed and retain that responsibility. Owner retirement is allowed
only after actual users/requests leave and required cleanup can run. Neither an
unbounded wait nor interpreter deletion fabricates recipient delivery. Scheme
continuation/native-marker validity is unaffected by a new epoch. [SD08–SD15, SO01]

SP08. *Value under equivalent behavior.* Compare providers with the same source,
loaded producer domain, request policy, handlers, outcomes and GC/control corridor.
Thread-wide service pays real scans and callbacks. A targeted helper may remove
unrelated handler invocation from its barrier but adds a maintained library
operation and must preserve unrelated pending work for later normal service.
Deleting required handler work or changing raw cancellation behavior is not saved
work. Zig shares these constraints with generated C, so syntax or no automatic
Zig GC cannot establish a positive incremental lower bound. [SD11–SD15, SO01]

| ID | Source-composed history | Required correction |
|-
| SC01 | InitStubs fails after an earlier private global was initialized | Non-NULL private pointer is not current binding success |
| SC02 | Client omits USE_TCL_STUBS; macro version check succeeds | No private-table initialization receipt follows |
| SC03 | Two cores report compatible public versions but differ in private layout/image | Pin private ABI and provider identity; public compatibility is insufficient |
| SC04 | A second binding overwrites stub globals while first provider remains active | Use stable captured entries or serialized/island binding |
| SC05 | Reset function pointer is retained after its core image unloads | Keep image lease through last return and receipt use |
| SC06 | Host CancelEval ingress is sealed, but an accepted Tcl script invokes interp cancel | Join actual source scopes and all affected targets before pending settlement |
| SC07 | Wrapper intercepts only public Tcl_CreateInterp; ChildCreate calls TclCreateInterp | Register internal creators or declare and enforce the restricted domain |
| SC08 | NULL thread-wide invocation reaches testasync's GetObjResult before its NULL branch | Qualify eligible handler context; no blind NULL-safe assumption |
| SC09 | Raw cancellation accepted while idle was intended for the next script; barrier discards it as old | Epoch-specific settlement must be explicit; do not claim raw-contract equivalence |
| SC10 | Barrier is invoked inside AsyncInvoke while asyncReady is zero | Actual outer control scope must return before idle issuance |
| SC11 | DoOneEvent(DONT_WAIT) returns 1 after invoking async before ordinary events | Nonblocking/queue status is not absence of callbacks or producer work |
| SC12 | Token substitution decrements to zero and resets cancellation before surrounding native return | Native scope frontier, not count/flag alone, establishes idleness |
| SC13 | A hook decrements active count while its Tcl callback/native frame is still live | Count retirement only after actual return |
| SC14 | Non-forced reset returns OK at nonzero nesting | Require preconditions and observed clear-state postcondition |
| SC15 | Reset succeeds; a result freeProc/diagnostic hook then marks an old cancel before publication | Forbid callback-capable work or invalidate/renew the receipt |
| SC16 | Child is reset, but an ancestor's in-flight API call installs flags afterwards | Close/join ancestor request authority and include its targets |
| SC17 | New settle helper holds asyncMutex while waiting on cancelLock against an API marker | Preserve cancelLock -> asyncMutex and no callback under the pair |
| SC18 | Pending token is deleted/recreated to clear it | Creation appends to handler order; identity/priority changes require separate semantics |
| SC19 | Helper clears thread asyncReady to clear one target, losing another ready handler | Preserve unrelated readiness and service obligations |
| SC20 | Pinned Tcl corpus is clean but a loaded Tk/native extension bypasses managed request admission | Lexical source closure does not qualify the loaded producer universe |

SC08 and SC15 are static hazards, not observed crashes or executions. SC09 is a
semantic refutation, not a proposed optimization. SC17–SC19 constrain a new helper;
they are not allegations that current Tcl implements that helper incorrectly.
