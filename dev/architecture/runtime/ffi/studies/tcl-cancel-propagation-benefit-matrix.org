PV01. Modernization here is a complete lifecycle contract: explicit native owner,
cancellation epoch, library return, independent result/root custody and terminal
retirement. Modern Scheme-generated C is the mainline; Zig is an optional provider.
Neither language removes Tcl's control machinery or proves Scheme equivalence.

| Necessary support / evidence | Modern generated C | Optional Zig | Actual removal candidate and residual obligation |
|-
| Epoch/lease/dispatch seal: CP09–CP10 | Scheme-generated typed records, lifecycle lock and checked transitions | Same plan, tagged states and explicit synchronization | Per-adapter ad hoc close bookkeeping can consolidate; raw-pointer/generation proof remains |
| Request batching: CP02 | One common monotone coordinator and NULL-message lane | Same coordinator; unions can express dispositions | Redundant library requests can fall from N to batches B; no required host acknowledgment is dropped |
| Native evaluation exits: CP03–CP06 | Reuse Tcl VM/direct/NRE and qualified C control island | Same library and retained C island where needed | No native cleanup, interpreter check or marker mechanism disappears |
| Result custody: CP09–CP11 | Shared snapshot/root/sink interface | Same payload ownership; error unions are representation aids | Per-call borrowed-result recipes can retire after caller migration; bytes/roots/receipts remain |
| Thread/event/child integration: CP07–CP08 | Explicit owner generation tree and scope ledger | Same thread affinity, event closure and child frontier | No event preemption, arbitrary handler time bound or free child reset from Zig |

PV03. Break-even over one identical admitted history H, expressed in runtime
work rather than invented coefficients:

#+BEGIN_SRC text :eval never
C_saved(H) = (N - B) * request_cost
           + removed_duplicate_setup_and_classification_work(H)
C_added(H) = epoch_and_lease_work(H) + mandatory_snapshot_and_root_work(H)
           + delivery_and_derived_task_accounting(H) + retirement_grace_work(H)
net_runtime_gain(H) = C_saved(H) - C_added(H)
#+END_SRC

Existing VM checks, trampoline, conversions, actual handlers and useful cleanup
appear on both sides and cancel; deleting semantics is not a saving. N=1 gives
no batching saving. A borrowed synchronous result needing no durable delivery
may gain no throughput from the richer profile; charge its added checks honestly.
For a cancellation-storm workload batching may matter, but a bounded-batch
progress policy must avoid indefinitely postponing dispatch while requests arrive.
No universal positive lower bound is established.

PV04. Space: with R retained request receipts, L live scopes, O unsettled outcomes,
I affected interpreter generations and Q derived tasks, distinct native metadata
is O(R+L+O+I+Q), plus owned result/options bytes and the union of rooted payload
objects. Batching reduces library calls, not the storage needed to acknowledge
all R accepted requests. A bounded receipt-retention policy may compact settled
records only after external receipt obligations end. A memory saving cannot be
claimed merely by dropping diagnostic provenance or a still-live continuation.

PV05. Maintenance is measured by independent maintained policies, representations,
ABI mappings and route matrices. One Scheme plan may consolidate epoch, outcome,
owner and drain policy across actual necessary components. Modern C can already
share that generator/support. Zig's incremental balance is:

#+BEGIN_SRC text :eval never
Zig increment = necessary C support actually retired
              + independently qualified provider/runtime capability gained
              - retained C island and duplicate provider representations
              - extra ABI/toolchain/control and library-upgrade obligations
#+END_SRC

No positive numerical value or retired support count follows from tagged unions,
ordinary defer or access to LLVM. LLVM/MLIR can consume the common native plan
without owning Tcl cancellation, Scheme dynamic-wind or GC roots.

PV06. Retirement order: classify the real Tcl_Eval/error/callback/event callers;
introduce the shared outcome/owner plan; migrate every custody/close caller and
its failure exit; qualify terminal scope/tree/lease closure; remove old adapter
policies only when no caller or native resource depends on them. Retire borrowed
string assumptions only after replacement ownership exists. Reuse and broad
continuation interoperability have separate gates and may not be silently
removed from an existing API. No retirement has happened here. [PE01–PE03, PD01]

PV07. Refutation: Zig does not win if C emits the same plan with the same shared
support and Zig retains that support plus a bridge. The whole modernization
fails if its fast path loses returning-handler behavior, native trace effects,
finally semantics promised by its profile, cancellation provenance or live
resources. It also fails as a bounded-shutdown claim when one native handler or
re-marking async service has no progress bound. Safety under retained custody
can still hold while progress/value remains unproved.

PV08. Decision: continue the common native-contract and generated-C modernization.
Admit terminal cancellation only under AP01–AP05/AP07–AP08 premises. Keep
reusable reset, full compiled Try coverage, general foreign continuation,
installed source identity and positive incremental Zig value unresolved. Learning
from OCaml means budgeting control/root/cleanup boundaries together, while
retaining Gambit's own semantics. It does not justify rewriting this mechanism
in Zig merely to obtain LLVM services. [PL01–PL02]
