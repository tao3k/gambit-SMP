These are handwritten, source-composed contracts and proofs for
[[file:tcl-entry-cancel-design.org][the proposed gate/guard]]. No implementation, native
scenario, compiler, model, solver or prover was run. Complete installed domains,
callback legality and every failure exit remain separate qualifications.
[[file:tcl-entry-cancel-evidence.org][Source/paper evidence]] binds the inspected paths.

GP01. *Ordering is an algorithm plus a context.* Assume OrderedEntry calls the
same dispatcher with a qualified context and all its side effects are retained.
Each selection is the first ready registered handler under A, code/result flow to
the next callback, and newly ready older handlers regain priority on the next
head scan. This retains the dispatch rule at that invocation. Moving the invocation
to entry changes its temporal/context history, so the argument does not establish
literal-source equivalence. CancellationFirstEntry changes its relative priority
and must use a different semantic policy. [GD01–GD03, GX01–GX03, GX11, GL01]

GP02. *Callout-free publication is conditional on custody.* Assume a native
lifetime lease protects the target during preparation, message storage/ownership
is reserved, and every relevant producer uses prepare/publish/retire. Conversion
and release happen without L/C/A; C/A publish revalidates the target and orders
acceptance. An entry callback during preparation therefore cannot deadlock on C
held by that operation, and is ordered before this publication if it enters first.
This removes the reviewed hazard, not every global lock cycle. A remaining legacy
C-held callback path or changed unproved failure decrement invalidates the claim.
[GD04–GD05, GD11, GX02, GX06, GX07, GX09, GX12, GL01–GL02]

GP03. *No stale body permit at the declared cut.* Assume final gate validation
and allow/reject publication use C with actual entry phase/coverage, and callbacks
run outside the locks. Raw publication before the decision must be accounted in
that cut; publication afterward is active cancellation. Thus an entry cannot use
an earlier service snapshot to authorize body execution across an already accepted
request. This proves the declared ordering point, not zero instructions after a
later active cancellation or finite completion of the service loop. [GD06–GD10,
GX01–GX05, GO01, GL01–GL02]

GP04. *Nested async service cannot be inferred from readiness.* Assume current
AsyncInvoke is active and asyncReady is zero. A re-mark sets a token's ready bit
without restoring global readiness while active; a nested Invoke can return
without servicing it. A correct OrderedEntry therefore cannot derive drain from
that return, mutate the outer active flag, or wait for its own parent handler.
Its domain must exclude or explicitly fail/defer the unsupported entry. A new
cancellation-first operation can have different behavior only under its declared
priority/claim/callback-free policy. [GD08–GD11, GX01, GX08, GX11]

GP05. *Early guard coverage and durable lifetime.* Assume registration precedes
all admitted failure/reentry sites and every path records either terminal completion
or a charged dependency. Early readiness ERROR then has a guard even though the
existing bytecode-return callback was never registered. Scheduled NRE and suspended
coroutine records hold durable custody; no exited stack guard is referenced. This
is a coverage/lifetime requirement, not proof all real paths have migrated or that
non-local foreign exits automatically run a C/Zig lexical cleanup. [GD07, GD13–GD14,
GX04, GX05, GX10, GE01, GL03]

GP06. *Clearing cannot erase newer raw work.* Assume true owner/native/logical
closure, same-policy guard identity, full target-frontier provenance and final
L,C,A validation. If every live contributor belongs to completed admitted coverage
and no future installer/new debt remains, normalized clearing changes only eligible
state. Otherwise all-or-defer retains shared flags and custody; no partial origin
subtraction is attempted. A later raw request invalidates the cut before cleanup
or runs after the protected transition. This is safety, not universal neutralization
or a proof that later raw debt is consumed. [GD14–GD17, GX01–GX05, GX09–GX10,
GO01, GL01–GL02]

GP07. *A final guard cannot repair invisible earlier resets.* Assume one old
inline reset can still clear untagged current state before the final guard runs.
Then a newer raw contribution may already be gone and the final snapshot cannot
recover its causal history. Therefore all admitted reset writers must route through
or independently satisfy scope/generation-aware clearing. This necessity follows
from actual TEOV/bytecode/private/substitution/descendant clear sites, not from
preferred programming-language syntax. [GD15–GD16, GX04–GX06, GX09–GX11, GO01]

GP08. *Receipt policy prevents false equivalence.* Assume receipt issuance binds
semantic policy, entry-kind contract, guard generation and neutrality basis, and
consumers enforce them. An early-error normalized clear cannot satisfy a consumer
requiring an actual natural-source reset. Entry rejection is not consumption until
actual cause/control/return evidence exists; settled cleanup is not outcome delivery.
A deleted/rewind/parse or other ERROR outcome cannot stand in for an attributed
cancellation under the declared precedence. This separation prevents a circular
proof that the future reset authorizes itself.
[GD12–GD18, GO01, GL01–GL02]

GP09. *Conditional positive normalized control.* Assume no unrelated ready or
claimed handler, immutable callback-free attributed payload, qualified target entry,
a guard armed before checks, no new request, actual native/logical closure and
NormalizedComplete policy. A cancellation-first gate can decide rejection before
body effects, materialize its owned outcome outside locks, and settle eligible old
U at the completed frontier. It then supports normalized consumption/neutrality
without relying on the absent bytecode-return cleanup. This is a source-composed
new-contract control; it does not prove literal raw equivalence, real installed
support, bounded time or the premises for arbitrary plugins. [GD06–GD17, GX01–GX10]

GP10. *Net benefit needs an equal-capability baseline.* Let N denote histories
that gain qualified entry preemption/completion or reuse under the required policy.
Count actually avoided equivalent reconstruction/duplicate policy work, or report a
required new capability separately. Charge message preparation/publish leases,
handler service or readiness repair, decision snapshots, guard/reset migration,
logical/native closure, failures and retained outcomes. Positive balance requires
that gain to exceed the additions across successful and refused histories. Keeping
the same protocol in Zig does not retire any necessary support by itself.
[GD19–GD20, GL01]

GP11. *Readiness repair preserves the active dispatcher protocol.* Assume target
mark removal and readiness handling occur under A. Inactive service permits a
locked remaining-ready scan and assignment; a concurrent later mark then sets
readiness normally. Active service instead keeps its original global-ready/active
protocol and continues its outer head scan, which sees remaining/newly marked
handlers. The exit/mark race is serialized by A. This proves no lost unrelated
ready mark for the proposed operation, not original cancellation-relative order.
A nested child return still cannot authorize guard settlement before affected
outer service scopes actually return. [GD09, GD11, GD14–GD15, GX01, GO01]

*** Inert Counterexamples and Positive Control

| Case | Source-composed schedule | Required outcome / missing premise |
|-
| GC01 | Target cancellation is serviced ahead of an older ready handler | New control priority; cannot claim original cross-handler order |
| GC02 | Same dispatcher is called earlier with a different code/result context | Relative selection rule may match; full source history does not automatically match |
| GC03 | Older handler re-marks during a later callback | Head rescan gives it renewed priority; no snapshot FIFO |
| GC04 | A handler changes code/result before cancellation check | Preserve ordered fold or declare sticky normalized rejection explicitly |
| GC05 | Raw message conversion callback reenters an entry hook while C is held | Possible recursive-lock hazard if legal in profile; qualify or move callouts from core commits |
| GC06 | C is made recursive around a half-updated pending record | Partial-state exposure and L/C order remain; recursion is not a proof |
| GC07 | Target retires while payload is prepared outside locks | Lifetime lease and publish revalidation fail safely; no stale pointer publication |
| GC08 | Preparation A starts first, preparation B publishes first | Selection order is publication under C, not start order |
| GC09 | Missing-target raw failure is assumed to decrement a message because success does | Pinned early failure differs; ownership result must be explicit |
| GC10 | Preparation callback naturally evaluates before this cancellation publishes | Entry precedes acceptance; do not assign future cancellation retroactively |
| GC11 | Raw publish precedes actual entry claim | First eligible target entry must account for that idle coverage |
| GC12 | Handler service finishes, raw publishes, stale body permit is issued | Final C-serialized decision cut must detect it |
| GC13 | Allow-body permit wins C; raw publishes before physical first instruction | Active cancellation; no promised instruction-free interval |
| GC14 | Gate holds C throughout script execution to prevent the race | Blocks cancellation/reentry and violates protocol; do not hold locks across body |
| GC15 | Outer AsyncInvoke active, asyncReady zero, nested entry invokes dispatcher | Nested return may service nothing; no drain/consumption receipt |
| GC16 | Nested entry waits for its own outer handler while holding a lock | Self-dependency; explicit unsupported/deferred domain instead |
| GC17 | Arbitrary legacy raw caller still converts/releases under C after wrapper migration | Callout-free normalized ingress closure is incomplete |
| GC18 | Rejected entry's cleanup callback clears flags or changes result to OK | Normalized per-attempt decision stays rejected; raw source fold is a different policy |
| GC19 | Error diagnostics allocate or release user objects inside final C/A/L commit | Forbidden callout/GC/reentry; materialize and retire outside locks |
| GC20 | Guard is registered only after TclInterpReady succeeds | Early ERROR has no completion support; pre-register it |
| GC21 | A stack guard is queued on NRE work after its C frame returns | Dangling ownership; durable guard transfer required |
| GC22 | Native scheduling TCL_OK or coroutine yield is treated as settled completion | Logical activation/dependency remains open |
| GC23 | Inner eval returns but outer Tcl_Eval still mirrors its result | Actual outer native-return frontier remains open |
| GC24 | Early ERROR leaves U and private reset is called as if it were natural cleanup | Normalized transition needs its own policy/basis, not a source-reset witness |
| GC25 | New raw C shares flags with old completed U | All-or-defer; do not subtract an origin or erase new state |
| GC26 | An unqualified TEOV inline reset clears a newer contribution before final guard | Every reset writer must migrate; final guard cannot restore lost history |
| GC27 | Pending/re-marked target callback can reinstall old state after guard clear | Future-installer debt blocks settlement |
| GC28 | One child clears successfully, another fails; whole tree is published clean | Full-frontier validation and sealed partial-failure custody; no partial clean publication |
| GC29 | Guard retry resets or releases the same payload twice | Issuer generation permits exactly-once terminal settlement |
| GC30 | Continuous re-marks prevent ordered gate stabilization | No finite progress result; do not turn a timeout into consumed cancellation |
| GC31 | Fully qualified no-other-handler normalized rejection/guard path closes all scopes | Conditional positive control; new-contract result, not native or literal-source pass |
| GC32 | Zig defer is credited with eliminating actual return, reset-writer or GC-root support | Necessary native obligations remain; no exclusive retirement proved |
| GC33 | Target clear during active Invoke sets asyncReady to force recursive service | Preserve the active protocol and outer rescan; no artificial nested dispatcher |
| GC34 | Inactive scan computes readiness, unlocks A, then stores stale zero after another mark | Compute and assign under A; preserve later marks |
| GC35 | Rejected child evaluation returns inside a still-active parent handler | Record deferred guard completion; wait for no parent while locked; owner-safe settlement follows real service return |
| GC36 | First lock use allocates inside a claimed allocation-free commit, or a no-thread build supplies empty mutex macros | Pre-initialize locks and qualify the actual threaded synchronization domain; no native support from source alone |
| GC37 | Deleted/rewind or direct parse ERROR is recorded as consumed cancellation, or entry preemption silently changes error precedence | Bind error precedence to policy and record real causes; reject-other-error retains unresolved raw debt |

Cases are handwritten discriminators. GC31 is a conditional positive control;
none is an executed test. Full/native/installed/normalized/value gates remain
unresolved in [[file:../../../../../docs/experimental/zig/tcl-entry-cancel-traceability.json][traceability]].
