*** 1. Same-Capability Comparison
:PROPERTIES:
:ID: d9d96a07-ae99-556f-98fb-a3fa1cc31cbb
:CUSTOM_ID: 1-same-capability-comparison
:END:

C-G = modern C with existing/generated/opaque support and strict selected compiler
checks. C-ZT = the *same C core*, plus the independently necessary common Zig
tool role. Z = private Zig consumers over the same Scheme plans/runtime protocol,
retaining the required C control shell. All controls have the same callback,
processor, wait and collector capability. Supporting a previously absent arm64
trampoline or BW2 is a separate feature cost, not evidence that Zig is cheaper.

S = common semantic/runtime reconstruction; L = conditional language mechanism;
A = added/substituted work; U = unbounded/unresolved. Z0 means no independent
Zig attribution, not measured zero time. No safety deficit can be averaged away.

| ID / dimension | Current source / modernization need | C-G | C-ZT | Zig increment and limit | Positive condition / counterexample |
|-
| OM01 RC scan owner | ps list vs P0-only mark_rc [OW02/03] | Explicit per-processor scan/mutation law | Same C core | S/Z0; types do not enumerate roots | Cohort closure necessary in all controls; P0-only valid use may need no scanner change |
| OM02 root bootstrap | Marker allocation may GC [OW05] | Existing mapped extent or designed scope + reload | Same | S/L; typed root identity can hide raw values | Gain only from removed private helper work; opaque C root API may already suffice |
| OM03 callback identity | Global c_closure_self [OW06] | Invocation context/capture; qualified provider | Same | S/L/A; typed target cases, same ABI/provider cost | Native C context reuse may make extra language marshalling net negative |
| OM04 owner/binding | No admitted generic switch [OW07] | Preserve same owner; explicit activation stack | Same | S/L; no automatic exclusive VM ownership | No-switch scope is cheaper than inventing a guard/mutex/member system |
| OM05 continuation/error | Marker/unwind/error-handler reentry [OW08] | Retain C control shell and explicit cleanup | Same | S/A; defer only outside nonlocal region | Retained shell can consume all apparent cleanup savings |

*** 2. What Is Actually Removed
:PROPERTIES:
:ID: 1d741763-9108-5cb9-be57-46115177def3
:CUSTOM_ID: 2-what-is-actually-removed
:END:

| ID | Selected old decision owner | Replacement and deletion boundary | Must remain |
|-
| OR01 root protection implicit in SFUN emission | Callback plan declares roots and first relocating effect; shared adapter consumes it | Retire duplicate per-site root/effect choices only after every selected generator path migrates | C frame/GC scanner, legacy SFUN macros and opaque user bodies |
| OR02 global target reselection on supported OC1 | Invocation-local carrier/context + admitted platform provider | Remove global reselection for migrated dynamic entries; retire generator/global only after all supported legacy clients leave | Public callback ABI, provider code-lifetime rules; static callbacks do not justify deleting unrelated dynamic code |
| OR03 scattered entry/binding policy | Same-owner validation and one activation protocol | Delete local guesses/rebind attempts for migrated owned callers | Configured TLS selector and startup thread_set_pstate; no automatic removal of bind macros/API |
| OR04 duplicated wait-effect assumptions | Shared BW1 effect/lock/service contract | Retire selected wrappers' independent assumptions, retain physical save/reload generation | select backend, abort pipe/event, collective barriers, scheduler wait queues and queue locks |
| OR05 private variant/cleanup support | Generated C helper or Zig product implementation | Count disjoint code/review support only when genuinely absent from selected alternative | C nonlocal shell, semantic issuer and all runtime algorithms |

Current retired implementation bodies = *none*. These are future deletion
conditions, not five removable files. A retained legacy path remains maintained
and cannot be booked as a saving. Replacing a decision owner with Scheme/common
runtime is shared architecture value; only OR05's established differential may
contribute Zig-language saving. OR02's platform work is shared feature work.

*** 3. Marginal Cost Certificate
:PROPERTIES:
:ID: 149b270e-2a66-5549-b2e7-3b6d36c4a891
:CUSTOM_ID: 3-marginal-cost-certificate
:END:

For a demanded set F of callback/wait/native-service consumers over horizon H:

#+BEGIN_SRC text :eval never
Delta_Z-C = S_private(F,H)
            - I_language(F,H) - I_bridge(F,H) - I_transition(F,H)
            - I_qualification(F,H) - I_exit(F,H)
Positive sufficient condition:
  lower_bound(S_private) > upper_bound(sum of all marginal I)
#+END_SRC

S_private is the *union* of necessary private native construction, variant,
propagation and ordinary-return support avoided after existing C/Scheme/library
reuse. A helper serving three components is one maintained body, not three
savings. Repeated real integration/change work can count separately with a
reviewed event denominator. Shared root/collector/VM/wait correctness cancels
between equal-capability controls; do not cancel different algorithms silently.
This increment does not price the separate overall modernization-vs-current
investment, which also pays shared C-layer reconstruction.

| Cost/event account | Modern C baseline credited | Zig residual / upper-bound obligation | Parent account |
|-
| Root/scan or collector invariant changes | Existing runtime owner, generated caller updates | Same owner + foreign type/import review; no saved scanner algorithm | KC01/02/07 |
| New converter/effect/result variant | Scheme generator + strict enum/check policy | Product consumers, C shell and effect/root correspondence all change | KC01/05/07 |
| New wait backend/device method | Existing C backend/locks/abort mechanism | Same platform qualification; any Zig bindings/custody adapter | KC03/07 |
| ABI/profile/nonlocal mode change | C shell/layout/profile checks | Additional C/Z interface verification and debug tooling | KC04/05/07 |
| Additional necessary native service | Credit existing NJS/shared helpers once | Only genuinely reused private support amortizes; per-client roots/control remain | KC06/08 |
| Zig/stdlib/import upgrade or removal | C-ZT common driver share only where actually identical | Language/stdlib/API migration and a viable extraction path | KC08 |

A theoretical positive domain is possible if many **necessary ordinary-return
native consumers** share real private support that C generation/reuse does not
already remove, while the C control shell is small/stable and marginal language,
bridge, qualification and exit costs have justified bounds. No counts of those
consumers, change rates, work intervals or lower/upper effort estimates are yet
established. Merely adding this managed seam does not prove amortization.

Countermodel: static same-owner callbacks use an unchanged C shell, BW1 uses
existing wrappers, private dispatch is generated in Scheme, and Zig adds only
an imported handle/status wrapper. S_private can be zero with positive bridge/
maintenance cost. Another: making OC1 portable dominates the project; that cost
is shared feature work and cannot manufacture a language gain. These are valid
same-contract alternatives to defeat an unconditional Zig-positive claim.
TG4/OR retirement closure and TG5 marginal bounds remain *open*.

Structural future measures, not observations: admitted effect edges divided by
all demanded transitive edges; managed RC carriers whose registration/scanner
owners match divided by all live managed carriers; all entry exit cases with
correct root/origin cleanup; every blocking/lock interval with a legal service
cut; actual retired decision owners; distinct residual helper bodies and reviewed
change events. For a selected per-processor scanner, work scales with actual
registered carriers visited, including FAL carriers unless redesigned; do not
infer free parallel scanning. Added roots scale with peak live extents and slots.
No denominator, saved milliseconds, GC speedup or maintenance percentage is
reported from source family counts.

*** 4. Migration Dependencies (Design Before Implementation)
:PROPERTIES:
:ID: 1797b4eb-3f45-590c-80b8-dd1158eb3501
:CUSTOM_ID: 4-migration-dependencies-design-before-implementation
:END:

| Stage | Concrete design product and prerequisite | Retirement / stop condition |
|-
| OS00 profile/cohort | Bind exact source/configuration/target and OC0/OC1/OC2, OW0/OW1/OW2 actual clients, explicit/implicit ps agreement | Reject unknown owner/target; no broad compatibility assertion |
| OS01 root/RC closure | OU02/03: owner scan domain, update/removal, bootstrap and nested slot lifetime; choose P0 restriction or per-processor scan refinement | No managed RC extension before closure; no new registry solely to enlarge saving |
| OS02 target/marker program | OS00/01; pre-effect capture/protection, marker success/failure, raw inputs and converters/errors; CS00-CS11 | OR01 and selected OR02 only after full corresponding producer/caller replacement |
| OS03 control/binding | OS02; same-owner no-switch plan, matching/outer unwind and all cleanup/return paths | OR03; retain native C shell until legal mixed-control proof; no lexical-defer shortcut |
| OS04 wait cut | OS00/01/03; virtual methods, native aliases, locks, abort races, disabled-interrupt return path and service reachability | OR04; keep BW1 and queue/barrier mechanics; unresolved paths not reclassified as leaf |
| OS05 matched cost/design | OS01-04 may inform paired designs without implementation; OR05 union, C reuse and bounded marginal accounts | Theory gate closes only with defensible positive bound or explicit decision for C; no native test fills effort/retirement gaps |
| OS06 future qualification | Only a later explicitly authorized implementation/qualification stage after chosen design | Independent exact-profile root/control/progress/native evidence; not performed or authorized by this research |

OS00-OS05 refine RM00-RM06; they do not demand optional RM07 BW2/foreign attach.
Future native validation must distinguish target movement/input protection,
nonzero-owner scanning, nested callback identity, wrong-processor/repeated/outer
return, marker/converter failures, wait abort/error/lock paths and unchanged
same-owner binding. These are future obligations, not tests written or run.

*** 5. Minimum-Component Cost Refinement
:PROPERTIES:
:ID: 8efe82d0-3098-563f-a847-e8da990e5bee
:CUSTOM_ID: 5-minimum-component-cost-refinement
:END:

[[file:rc-marker-maintenance-matrix.org][MR01-MR08, RN01-RN10 and RMS00-RMS06]] credit existing candidate repairs and a small generated/opaque C control. Saved0 is a short borrowed extent, not a new root-stack framework; broader MP3/MP4 costs are admitted only by necessary caller demand. The minimal wrapper-only Zig topology can have zero disjoint support saving with positive bridge cost. This narrows the local adoption claim while leaving portfolio economics open; no new runtime code has retired.
