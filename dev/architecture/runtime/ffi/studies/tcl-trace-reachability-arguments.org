RP01. Independent registration supplies the missing same-name premise.

Each public add allocates a new tcmdPtr and linked CommandTrace. The direct loop
selects each record and enters TraceExecutionProc if its flags are nonzero;
that callee tests the selected record's busy bit, not the command name or global
I. For stable ordinary f and two prefixes with the RD03 behavior, inner f skips
busy A and reaches idle B. The root-bounded nested evaluation then returns,
clears B's busy bit and eventually A's, allowing the later outer B entry. This
is a closed public-source path under stated no-error/finite-resource premises,
not a claim about undefined imported-command behavior or native test success.
[RD02, RD03, RX02–RX04]

RP02. Callback-count recurrence follows from the actual selection rule.

With k idle records and all ancestors' records busy, the command scan reaches
each of the k; selected record becomes busy and its sole recursive call has
k-1 idle records. After return it becomes idle before the next scan entry.
Therefore T(k)=k*(1+T(k-1)), T(0)=0. Induction gives RD04's closed expression,
and one f body per command invocation gives 1+T(r). Maximum simultaneously busy
callback records is r. This relies on fixed record identity, one recursive call,
OK results and adequate limits; no hardware measurement or model execution is
encoded by the hand-derived table. [RD03, RD04, RX02, RX03]

RP03. Installed U is invariant in the declared positive-depth core domain.

Assume RD08's writer/owner/depth/root/identity/exit premises and start with U=1.
Installers OR U; checks clear only C. Non-force reset at h>0 is a no-op, child
reset respects that same target depth, nested exception handling is not scheduled
at level one and caller exception callbacks remain below the nested root.
Bytecode return cannot take its level-zero clear branch. Nested snapshots save
and restore U=1 by induction; older ancestors cannot return while this frame is
active. None of these transitions supplies U=0. Thus this domain cannot realize
the 1->0->1 resurrection history. Any alleged witness must identify the premise
it leaves: force/private alias/hook, zero-depth entry, context switch or escape.
[RD06–RD08, RX03–RX08]

RP04. The depth-zero bracket path has an actual reset branch.

Given the explicit private-entry preconditions in RD09, direct Tcl_EvalEx has not
incremented numLevels before token substitution. The bracket branch increments
0->1; readiness returns ERROR while U remains set and clears C if present. The
branch decrements 1->0 and unconditionally calls non-force reset; its predicate
is now true, so U becomes zero. ERROR remains the substitution return code;
direct evaluator propagates it and the enclosing saved-word assignment restores
U=1. This closes the bodies/branches, not the external private calling contract.
Known TEOV callers do not supply the zero-depth precondition. [RD07, RD09, RX03–RX06, RX11]

RP05. Hook signatures do not authorize a reset history.

The result-reset code proves callbacks may be invoked before readiness. Manuals
specify storage/internal-representation duties and restrictions; a function
pointer signature alone neither supplies a valid target lease nor proves that a
callback may evaluate Scheme/Tcl or invoke a private force reset. No selected
reset call identifies a force=1 hook producer. Therefore that route remains a
conditional native construction, not an established supported program history.
Absence from this text pattern does not rule out aliases or loaded clients.
[RD10, RD11, RX01, RX05, RX07, RX11]

RP06. Early ERROR is not completed target neutrality.

Even when readiness rejects and C was consumed, U may persist. In RD09 a genuine
source reset clears it temporarily, yet the enclosing native trace remains a
future writer. A child completion receipt cannot prove the absence of that
writer, and must not justify reclaiming its frame/history or publishing reuse.
The same dependency rule prevents a new premature normalized clear from creating
a 1->0->1 history during mixed migration. No child waits for the ancestor it is
preventing from returning. [RD09, RD11, RD12, RX08, RO01, RL01, RL02]

RP07. Source and separated profiles preserve different cancellation histories.

Given complete writer migration, separated trace exit leaves CancelCell untouched;
ordinary record-level nesting and source points can still be preserved. But
private reset and name-level suppression policies have their own effects. Neither
excluding one resurrection domain nor eliminating trace replay proves all old
and new observers equivalent. Retain source-event receipts and source/normalized
cuts separately; zero bits or equal names cannot supply generation/lifetime
identity. [RD05, RD11–RD15, RO01, RL01]

RP08. No total speedup follows from removing the semantic hazard.

The cancellation-free RD04 family has no U resurrection to remove, and preserving
its source behavior retains T(r) callbacks. A canonical cell still needs checks,
source-reset accounting, native/image lifetime and completion dependencies.
Scope bookkeeping costs attach to actual invocations, including nested scans;
they cannot be assumed O(r) in total merely because maximum live records is r.
Changing suppression to reduce that work changes observable behavior. [RD04, RD14–RD16, RV01–RV04]

RP09. The Zig increment is separate from the shared modernization mechanism.

For equal policies and capabilities, both generated C and Zig need the same
thirteen support families, hook admission, private ABI closure and acyclic guard
protocol. Optional Zig syntax/error/defer facilities do not prove legal reentry,
native-frame exit or absent reset writers. A positive increment requires actual
necessary support eliminated or reusable capabilities exceeding additional
provider/toolchain/ABI qualification, without counting a ruled-out bug or common
state split twice. That inequality remains unproved. [RD15, RD16, RV01–RV08, RL02]

function-body composition. No case certifies an installed native caller, passing
fixture or benchmark.
