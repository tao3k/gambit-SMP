These handwritten arguments concern the [[file:tcl-next-evaluation-design.org][proposed identity/receipt contract]].
No compiler, implementation, native scenario, model, solver or prover was run.
Selected source and paper evidence is in [[file:tcl-next-evaluation-evidence.org][the evidence document]].
None of the coverage or callback-freedom premises below is an installed-runtime receipt.

NP01. *First attempt uniqueness is per target.* Assume every admitted semantic
entry passes the source hook before callback-capable preparation, forwarding roles
are explicit, and raw idle acceptance/entry are ordered by C. The first new semantic
entry ordinal for that target after the relevant idle cut binds its raw coverage
uniquely. Internal wrappers forward without incrementing it; a different interpreter
cannot win it. This proves the proposed abstraction's uniqueness, not that existing
Tcl exposes such a hook or that all call sites are covered. [ND01–ND05, NX01–NX04,
NX09, NL01]

NP02. *Reservation and natural callback behavior.* Assume the reference includes
the same natural event/native script callers and their admitted ordering. A queued
host reservation is not a semantic entry; a natural callback may win first. Once
the outer entry has claimed first, a permitted preparation callback creates a child
and cannot replace its parent. Excluding callbacks or inserting a consumer script
changes the reference history, so it cannot certify transparent reuse of the
original domain. Merely classifying intent does not change raw cancellation.
[ND01–ND05, ND10–ND11, NE01, NX01, NX07, NX09]

NP03. *Identity does not imply consumption.* Assume the first identity remains
bound even for empty/direct/early-error paths. A successful empty attempt without
an attributed check leaves its consumption predicate false. Renaming the next
nonempty invocation first would contradict the recorded entry order. An already
installed one-shot check returning ERROR can be observed while an early U check
leaves persistent state; the receipt types represent both facts independently.
[NX03–NX05, ND06–ND09, ND13–ND14]

NP04. *Destructive filtered checks cannot fabricate observation.* Assume check
records capture beforeC/beforeU, filter and returned code at the real owner site.
With C=1,U=0 and an UNWIND-only filter, the source clears C and returns OK. This
record fails returnedERROR and does not satisfy an idle consumption requirement.
A later managed-only ERROR has different causal coverage. Re-arming C to make
later checks succeed would be an additional semantic operation. [ND09, ND13,
NX05, NX10, NO01]

NP05. *Nested observation needs a causal route.* Assume complete evaluation parent/
child identities and actual exception/catch/foreign-boundary return records. A child
ERROR can support the parent's first-attempt consumption only if the same raw cause
is routed into the required parent preemption/error outcome at the admitted phase.
If swallowed, copied into a string, returned as TCL_OK or observed after parent
script effects, it cannot prove strict preemptive entry. This keeps raw source
steps visible without declaring all possible nested outcomes equivalent. Gambit C
return validity is an independent requirement. [ND10–ND13, NE01, NX05–NX07, NL03]

NP06. *Completion is more than a native function returning.* Assume attempt
identity travels with NRE callbacks and coroutine activation/suspension records.
Scheduling TCL_OK closes only that API scope, not the evaluation's terminal logical
boundary. Coroutine yield can restore a caller without running its exit/wind-down
callback. Any such old capability keeps child/NRE closure false until a qualified
terminal/grace transition. Source snippets identify the need, not an implemented
closure or termination proof. [ND02, ND12–ND14, NX08, NE01, NL03]

NP07. *Consumption and neutrality compose without a cycle.* Assume attributed
first-attempt preemption, actual control/native/logical completion and complete raw
coverage. This supports consumption even if U still blocks raw neutrality. Only a
separately valid source-defined neutralization/installer closure then supports
RawHistoryDischargeReceipt. Managed pending settlement and final reset/publication
follow both receipts. A future reset cannot be used as evidence required to authorize
itself. A new raw request invalidates provisional cuts before final commit or runs
after publication under C serialization. [ND13–ND16, NX02, NX05, NO01, NL01–NL02]

NP08. *Normalization is a different proof obligation.* A new uniform entry gate
changes where pending async cancellation is installed/checked; a completion guard
adds reset transitions; a non-destructive peek changes callers' check semantics.
They may implement a deliberately stronger future contract, but do not follow as
literal-source refinements from passive identity recording. Handler priority,
message/flags selection, nested effects, new raw requests and every failure path
must be specified and independently proved. A new language does not remove those
obligations. [ND15–ND18, NX01–NX10, NO01]

NP09. *Positive value is conditional.* Let R be histories newly admitted with all
identity, consumption, completion and neutral-state premises met. Qualified reuse
can avoid equivalent creation/init/reconstruction for R histories or supply a
necessary retained-state capability. Charge all entry/forward/check/NRE activation/
return records, raw serialization, custody and source upgrade policies across both
successful and rejected histories. Runtime gain requires actually avoided work to
exceed that addition; normalized capability requires an explicit changed contract.
Neither is a demonstrated exclusive Zig benefit. [ND17–ND18, NL01]

NP10. *Selected positive controls need no semantic repair.* Assume installed raw
coverage, complete first-target identity, normal entry flags, a reference contract admitting the relevant entry kind,
qualified preparation,
no pending/claimed/new mark, and complete child/NRE/native closure. For C=1,U=0 in
the non-list object route, readiness checks ERROR before body execution, clears C,
and actual return can leave neutral state. For installed U in ordinary level-one
EvalObjv with exception handling enabled, readiness ERROR can run through TEOV's
existing reset and then the remaining callbacks/native return. If no later
installation occurs, this also leaves neutral state. These are distinct concrete
source paths supporting the receipt conjunction; unqualified callback/entry scope
or a late mark refutes the premises. They prove no native timing or support.
[ND06, ND13–ND14, NX03–NX06, NO01]

*** Inert Distinguishing Cases

:END:

| Case | Source-composed history | Required outcome / missing premise |
|-
| NC01 | Host reserves job J; a natural event script enters the target first | Callback script wins actual first identity; J is later |
| NC02 | Service inserts a dummy script to clear raw cancellation before J | Changed history; cannot claim transparent reuse |
| NC03 | Tcl_Eval forwards through Tcl_EvalEx and TclEvalEx | One semantic attempt, multiple native scopes; no triple counting |
| NC04 | A multi-command direct script uses internal NRE dispatch for each command | Command steps share the script identity, not separate first attempts |
| NC05 | Native callback publicly invokes EvalObjv during an outer script | New child attempt despite using the same helper as an internal command step |
| NC06 | Same Tcl_Obj/cached bytecode evaluates twice | Different semantic entry ordinals; object identity is insufficient |
| NC07 | Another interpreter J evaluates on the target I's owner thread | J cannot consume I's requested-target idle debt |
| NC08 | Cancel callback invoked during J installs into stored target I | Installation is not an evaluation of I |
| NC09 | Parent cancellation propagates flags to a child; only child checks | Child observation does not automatically discharge parent next-script debt |
| NC10 | Empty direct attempt returns OK without an attributed cancellation route | Identity valid, consumption false; next nonempty attempt cannot replace first |
| NC11 | Route empty bytes through EvalObjv to force different readiness behavior | Semantic route change must be explicit, not hidden equivalence |
| NC12 | Non-list object readiness returns cancellation ERROR before bytecode cleanup registration | Observation may be valid; U still blocks neutrality/reuse |
| NC13 | Repeating that object call observes persistent U again | New attempt; not a second receipt for the original first identity |
| NC14 | Canceled(U-only) clears C and returns OK | Destructive filter, no cancellation observation/consumption |
| NC15 | Matching message or unrelated managed ERROR follows a filtered check | No raw causal coverage; reject receipt |
| NC16 | Inner Tcl evaluation observes raw ERROR; Scheme callback handles it and outer bridge returns OK | Child observation alone does not preempt parent |
| NC17 | A qualified child cancellation route causes parent rejection before script commands | May support parent consumption only with complete causal/phase proof |
| NC18 | Permitted preparation callback evaluates after outer semantic entry but before its readiness check | Child identity; it cannot steal the outer first binding |
| NC19 | Custom freeProc pointer exists; report assumes any recursive Tcl use is legal | Source callback boundary is known; legality/domain remains unqualified |
| NC20 | Inner Tcl_EvalEx returns; outer Tcl_Eval still mirrors string result | Outer native scope has not returned; premature closure invalid |
| NC21 | Tcl_NREvalObj returns scheduling TCL_OK while callbacks remain | Logical completion false; no consumed-and-returned receipt |
| NC22 | A local TclNRRunCallbacks reaches its saved root but other logical work remains | Local callback exhaustion is not whole-evaluation closure |
| NC23 | Coroutine yields and restores caller without exit callback | Activation suspended, logical evaluation/custody remains |
| NC24 | TEOV reset runs, then NRCommand installs a newer raw request | Earlier neutrality proof stale; revalidate actual terminal frontier |
| NC25 | Completion guard clears U after a new idle raw cancellation accepts | New request must survive; stale guard forbidden |
| NC26 | First-target entry and idle acceptance race without shared core ordering | Identity/debt association unresolved; no counter-based guess |
| NC27 | Target-only entry gate runs cancellation ahead of other ready handlers | Changed handler order/effects; normalized contract needs proof |
| NC28 | New Zig wrapper claims to remove entry-role, root and coroutine evidence support | Same necessary native obligations; no exclusive retirement established |
| NC29 | An admitted custom object callback reenters evaluation while raw CancelEval holds C | A new C-taking entry hook could deadlock; callback domain/order redesign must qualify |
| NC30 | Qualified installed C-only object entry, or U EvalObjv entry with normal natural reset, has no future installer | Conditional positive controls can satisfy all receipts for their admitted entry kind without added private reset; not a native pass |
| NC31 | A contract admits only scripts, but an external prepared-command check consumes raw state first | Preserve the entry kind and raw effects; do not claim the stronger next-script receipt |

Cases are written discriminators, not executed tests or native observations.
Whole installed entry coverage, fully general mixed histories and normalized
semantics remain unresolved in [[file:../../../../../docs/experimental/zig/tcl-next-evaluation-traceability.json][traceability]].
