** Why one translation unit remains
These fragments are ordered internal source modules, not independent libraries.
The old file changes macros such as =___VMSTATE_MEM=, defines private helpers
before their consumers, and contains conditional declarations and debugging
paths. Splitting linker objects at the same time would change visibility,
inlining, build recipes and possibly ABI. That requires a separate interface
design. This change preserves the original declaration, definition and macro
order. No function or preprocessor conditional is cut across included files.

The original 24-line include/copyright preamble remains in =mem.c=. Each fragment
has a generated =#line= prefix and an end-marker suffix surrounding the exact
original bytes. The marker makes preserved final blank lines admissible to
strict Git patch checking. =___MEM_SOURCE_FILE= uses GCC/Clang =__BASE_FILE__= to preserve the original
compiler input identity; other compilers use the canonical =mem.c= build name.
The fallback is not qualified for arbitrary absolute-path diagnostic identity.
Initial logical line coordinates are migration provenance; current physical
locations are given in the table. Future edits need fresh source-bound evidence.

** Build and distribution consumers
=MEMORY_SOURCES= explicitly lists every fragment in =lib/makefile.in=. The
existing =mem@obj@= rule consumes the list, =NORMAL_SOURCES= includes it for
source-control/distribution packaging, and the distribution rule creates the
=memory= subdirectory. No extra runtime object or public symbol is introduced.
The actual Make prerequisite expansion is checked with =-W= for every fragment;
the unchanged fixture stays up to date. This is a build-graph check, not a timing
benchmark or a complete source distribution build.

** Conditional equivalence argument
Let =P= be the unchanged preamble and =F[i]= the ordered original byte intervals.
Reconstruction requires =S = P ++ F[0] ++ ... ++ F[24]= exactly, including comments
and whitespace. Compilation equivalence additionally requires complete top-level
boundaries, closed preprocessor groups, unchanged quote-include resolution, and
preserved values of all include-sensitive builtins actually consumed. The
introduced reserved macro must not collide with existing source. The native
comparison qualifies eight selected preprocessor configurations and one release
object configuration; it is not a universal theorem about every C compiler.
No include-level-dependent behavior is claimed portable without qualification.

** Verification ownership
[[file:../../modeling/ascent/memory-organization.rules.scm][The actual ASCENT DSL]] checks exact ordered source parts, current source identity,
contract-bound observations, missing evidence and conflicting unknown outcomes.
It must reject deletion, reordering and stale source observations. No new QNT or
Lean model is needed for moving unchanged C text. Existing QNT owns scheduling
histories; existing Lean owns coherence/mapping algebra. Their original
obligations and the source refinement adapter remain open where previously open.

* Integration and retirement boundary
The source organization retires the monolithic implementation body as an editing
surface. It does not retire synchronous worker/carrier binding, physical refill,
collective barriers, old phase scheduling or unknown native-writer custody.
Those remain governed by [[file:root-worker-exit.org][the complete responsibility replacement contract]].

The first root-task kernel has separate GCC, pthread and ASan/UBSan evidence;
it is not a linked-runtime GC acceptance result. Full bootstrap and real
map/multiple-continuation/GC checks must use the exact new fragment inventory.
The current materializer admits only existing locked paths, so its source-delta
contract needs a general new-file admission path before those fragments can
enter the sealed bootstrap. Do not commit early or edit a producer cache to
bypass that restriction. The previous bootstrap receipt cannot qualify this
changed source. No heap increase, timeout extension, patch import or commit is
authorized as a substitute for the five unresolved submission gates.
