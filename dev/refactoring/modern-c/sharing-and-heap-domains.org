The native-evaluated [[file:models/sysml/shared-heap-smp.sysml][SysML composition]] owns three separate logical roles:
=sharing=, =allocationRegions= and =collectionDomains=. Existing execution,
roots, worker, control, scheduler and retirement roles consume their contracts.
These are architecture distinctions, not three new C modules, a new token table
or additional delivery/SMP counters. [[file:shared-heap-smp-design.org][ASCENT's existing five-gate matrix]] remains
the acceptance authority. Modern C/C23 is the implementation baseline.

Learning input: [[file:../../knowledge/systems/shared-heap-smp-literature.org][recent primary-source survey]]. A paper identifies a mechanism,
premise or counterexample; it does not prove Gambit's implementation. This
research changes no runtime, managed native source product, profile or budget.

* RESEARCH What makes the SMP design modern?

#+NAME: modern-smp-design-questions
| Design question | Required architectural answer | Evidence that would refute success |
|-----------------+-------------------------------+------------------------------------|
| Can Scheme share without conflating ownership? | Preserve identity/aliases/shared mutation while distinguishing execution, roots, physical storage and collection authority | Copying an environment changes later multi-shot observations |
| Can parallel work remain safe on the real target? | Actual C23 access/order contracts, complete roots and unique effect/copy/scan custody | A legal source access races relocation or consumes partially initialized state |
| What must rendezvous, and why? | Explicit collected regions, incoming edges, participants and source-close conditions | A supposedly independent cut misses a foreign-region pointer or waits on its own blocked owner |
| What progress can actually be promised? | Separate safety, completion and bounded-latency premises; account native/OS stalls | An unknown shared writer is treated as stopped, or a counter is repaired by timeout |
| Can lifecycle changes preserve useful work? | Retain unresolved dependencies, hand off accepted work and exclude last users before reuse/free | Worker exit loses a Tail, returned claim, root or provider dependency |
| Does locality repay its new costs? | Measure allocation, roots, barriers, promotion, work/span, synchronization and retention together | Reduced scan counters accompany worse matched total time or unacceptable peak memory |
| Can control and native code participate explicitly? | Per-shot root reload, Scheme-owned winding and native access/affinity/exit contracts | One-shot restrictions or hidden GC during an unqualified native operation manufacture the gain |
| Can the system evolve and be audited? | Generated contracts and exact source/profile/consumer evidence; retire replaced responsibilities | More wrappers or unbound historical binaries substitute for a complete replacement |

Modernity is not a mandatory collector name, lock-free label or larger thread
count. Parallelism, concurrent mutation, generations, movement, isolation and
bounded reclamation are separate choices. A coordinated moving minor collector
can be modern; an unqualified concurrent collector is not an architectural win.

* RESEARCH Separate the semantic and physical mappings

#+NAME: heap-role-separation
| Role | Owns | Does not imply |
|------+-------+----------------|
| Sharing contract | Admitted identity, aliases, mutations and observable control effects | One contiguous heap or globally shared allocation from birth |
| ExecutionContext | Registers, denv, frame/control state and permitted execution | Ownership of every reachable object or permanent OS-thread affinity |
| Allocation region | Placement, allocation/initialization bounds, physical intervals and accounting | Private reachability, request-local lifetime or independent GC |
| Collection domain | Regions being considered, epoch, roots/incoming edges, participant and native-access cut | Equality with VM, Actor, processor, root-source count or worker count |
| RootOrigin / RootTask | Canonical references and scan/update custody | Permission to move an object still accessed through an unqualified native pointer |
| CollectorWorker / WorkerArena | Accepted copy/scan tasks, destination space and private/Tail debts | A mutator nursery or the lifetime of its carrier |
| Native/resource owner | Actual access validity, affinity and final use | Logical death when a request, Scheme shot or join observation completes |

Describe the logical object graph separately from a placement map into physical
regions. Movement changes addresses/placement while preserving the admitted
graph observations through the existing root/forwarding contract. Root locations
and native pointers are not interchangeable with live referent objects.

A collection cut must account for every reference from uncollected storage to
objects it may move: direct roots, captured frames/denv, other regions, mature
objects and native structures. It needs complete source slots/cards, qualified
handles/access/promotion, pinning, or refusal. Merely knowing a target is alive
does not repair the incoming reference. One active evacuation owner per object
and epoch is still required when regions or workers change.

* RESEARCH Multi-shot continuation and FFI custody: one complete case

Use map with a callback that captures a continuation and closes over a mutable
cell. Retain two wrappers sharing its frame/denv graph, complete the original
request, invoke native code and perform later collection/restores.

1. Before allocation or native conversion, the active/captured roots and source
   protection exist. Placement in a local region does not make the cell private.
2. Capture publishes complete frame/denv references and their root lifetime.
   Another wrapper may alias them; request completion cannot discharge that debt.
3. If the callback/global/mailbox/native client exposes an object outside an
   independently collectible region, publication must retain the source and
   install the required target/incoming-edge protection before source ACK.
   Under a coordinated VM cut, cross-context edges remain within that cut.
4. A native borrow retains its source/record lifetime separately from active
   pointer access. It must park/reload, use a qualified handle/pin, or prevent
   the affected movement. Retention does not legalize a racing raw read.
5. Each continuation shot acquires current execution/domain/root permission,
   reloads moved references and performs required Scheme winding effects.
   Shared mutation remains shared; restoring control is not rolling back data.
6. Moving a logical computation to another carrier differs from relocating its
   objects or transferring it to another VM. Unsupported closure/native-resource
   transfer must be rejected before effects; no transparent arbitrary migration.
7. Exception, cancellation, callback deletion and unknown return preserve the
   unresolved root, region and resource custodian. Exact last users, not request
   return or a generation number alone, permit reclamation and reuse.

This case amplifies Gambit's control freedom by making supported execution and
resource dependencies explicit. It does not restrict continuations to one shot
or imply a captured native activation is safe on every target.

#+NAME: sharing-domain-benefit-cost
| Mechanism | Potential benefit | Added cost / counterexample | Measurement still required |
|-----------+-------------------+-----------------------------+----------------------------|
| Local allocation | Less allocator coordination, better locality | Refill slack and cross-context publication can dominate | Matched allocation throughput, cycles and peak reserved/occupied memory |

Time savings and space cost are separate dimensions. Correctness precedes net
benefit. A finite worker budget or one request's completion supplies neither a
constant pause nor a bounded-retention guarantee under arbitrary native/OS
failure or user-retained continuations.

Whole admission remains the same five gates: complete cut and incoming edges;
actual alias/root repair; supported control/native/domain semantics; full native
execution/PBT; matched cost/peak. The next complete implementation boundary is
the same-VM sharing/root/native handoff under the selected cut, including partial
publication and failure custody. Generational exclusion, independent regions
and actor isolation are separately admitted policies on that foundation, not
additional fixes silently bundled into its REV.

Root update and remembered-edge update have different jobs. A root source that
is scanned every minor need not be treated like an omitted mature heap interior;
a smaller cut must nevertheless find every native/root reference into it. Still
allocation and pinning likewise do not exempt pointer-bearing bodies from edge
coverage. The complete bulk/native caller inventory is still OPEN.

The paper evidence informs three different choices. In [[https://kcsrk.info/papers/retro-parallel_icfp_20.pdf][OCaml ICFP2020,
sections 1.3 and 4.4]], local young heaps can admit inter-heap references when
minor collection coordinates; this avoids making C reads new safe points. This
is a tradeoff to study, not Gambit admission. [[https://www.steveblackburn.org/pubs/papers/iso-pldi-2025.pdf][Iso PLDI2025, section 4]] reports
separate bulk/native barriers and an initialization/publication reordering bug;
these motivate our writer inventory and first-escape rule. [[https://www.steveblackburn.org/pubs/papers/julia-ismm-2025.pdf][Julia ISMM2025,
section 3.4]] distinguishes identifying referents from finding repairable root
locations; its transitive-pinning experience motivates checking descendants,
rather than assuming a top-level native pin solves movement. Their measured
results are not transferred into Gambit's benefit matrix.

** Publication, update and last-use protocol

Let C be the physical regions moved by one cut. Its incoming references comprise
all admitted direct roots plus slots in storage outside C whose referents are in
C. Privacy is a proven reachability/access property, not the allocation address.

1. Protect source and target canonical references before any allocation,
   conversion, callback or other collecting boundary. Reload them after that
   boundary before using physical addresses. Unpublished construction separately
   requires a valid scan shape and complete initialization before first escape.
2. Enroll the semantic writer under the selected source/domain epoch, validate
   its source slot and reserve any metadata capacity before mutation. The
   admitted span covers the physical store and incoming-edge metadata commit.
   It cannot allocate, secretly collect or reenter through an unqualified hook.
3. A coordinated-cut candidate closes writer admission and drains admitted
   spans before trusting the frozen edge view. Release publication of the
   completed view pairs with acquire consumption; this does not legalize racing
   plain C field accesses. A concurrently mutating alternative needs a separate
   rescan/epoch argument and actual atomic access discipline, not a fence alone.
4. Log-before-store alone is insufficient: a scanner can consume the old slot
   before its later mutation. Log-after-store alone is insufficient: phase close
   can intervene. The writer enrollment/drain must cover both. A failed CAS
   installs no new edge; a conservative dirty entry may survive but cannot serve
   as a successful-install ACK.
5. Metadata overflow must use pre-reserved space, conservative full coverage or
   a merged/coordinated cut, or refill before mutation at a complete-frame safe
   point. Preserve valid Scheme mutation; do not reject ordinary sharing to make
   a region appear private. Failure retains the original roots and write debt.
6. Scan using the frozen or otherwise qualified view; repair actual source
   locations through canonical identity. A raw slot address is not a durable card
   identity if its source can move. Promotion and bulk relocation must record
   residual outgoing edges needed by subsequent cuts.
7. Clear/retire metadata only after its covered writes, scan updates and old
   readers settle. Unknown store/commit/return keeps source, target, roots and
   unresolved writer responsibility in custody. Query the existing operation;
   blindly repeating a Scheme mutation or callback can duplicate effects.
8. A native loan preserves lifetime separately from access. Park raw access and
   reload canonical values after reentry, use a fully qualified nonmoving policy,
   or exclude the affected movement. Pinning an outer object does not validate
   raw pointers to its movable descendants. Unknown native access cannot be
   declared stopped from a timeout or failed join.

This is the required replacement for implicit direct-store assumptions. It is
not evidence that a C23 remembered set or independently collecting domain has
already been implemented. Existing QNT slices cover declared temporal premises;
existing Lean laws cover conditional slot/alias rewriting. Neither is extended
with a duplicate proof to turn a missing C adapter into a checked result.

Its primitive =map-1*= executes =proc=, recursively computes =tail=, then creates

** Quantitative work and peak-memory bounds

Use the same workload, source/profile, allocation volume and budget. Let S be
baseline scanned pointer slots in a declared comparison interval; let A be slots
safely omitted, and I the additional incoming/card scanning work not already in
S. Candidate scan work is S - A + I, with overlapping roots/cards deduplicated
in the accounting. Thus scan reduction alone is A - I; it is not a speedup.
Use the same units throughout a comparison, such as slots or bytes by shape.

#+NAME: incoming-edge-net-benefit-matrix
| Dimension | Benefit bound / condition | New charge / falsifier | Current evidence |
|-----------+---------------------------+------------------------+------------------|
| Pointer scan | A - I positive; A cannot exceed the eligible omitted portion of S | Full/unknown writer coverage forces the affected omitted portion back into S | Source mechanism only; counts unmeasured |
| Store path | Scan CPU saved must exceed total barrier CPU across actual stores, including unsuccessful CAS/overflow bookkeeping | High write traffic or dirty coverage approaching the whole mature graph can erase the gain | Barrier implementation and matched cost unmeasured |
| Coordination | Count removed participant rendezvous and unaffected root work | Cross-region/native dependencies can require the original coordinated cut | Independent-cut admission unproved |
| Promotion/copy | Charge survival/promotion once in the selected CPU interval; account residual edges | Extra promotion, duplicated scanning and reserve fragmentation may exceed omitted work | Source/capacity refinement open |
| Control / FFI | Keep multi-shot semantics while avoiding unnecessary graph rediscovery where admissible | Frame materialization, per-shot reload/winding, native retention and access checks remain | Whole generated/native case not executed here |
| Peak memory | DeltaPeak = max_t M_candidate(t) - max_t M_baseline(t) | Simultaneously live nursery slack, metadata, pinned/retained graphs and copy/restore reserves count; later refunds cannot lower an earlier peak | No measured peak or percentage claim |
| Wall latency | Savings depend on dependency span, worker budget and rendezvous/native-stop tail | Summing overlapping CPU/phase times or dividing copied bytes by W is invalid | No throughput, pause or speedup claim |

CPU net benefit requires saved scan/coordination/control CPU to exceed barrier,
incoming-scan, additional promotion, protocol and retention-pressure CPU, measured
without double counting. High continuation escape can defeat request-private
optimization while leaving generational optimization viable. An unqualified
writer can veto movement entirely; performance arithmetic cannot override it.

All five joint gates remain OPEN. This delivery supplies the integrated source
argument, missing adapter contract and falsifiers; it does not change 4/4, 1/12
or the separate repair-line counter. A complete implementation must replace all
admitted writer classes and old implicit scan assumptions under its selected
cut before retiring those responsibilities, then pass the whole history and
matched cost/peak gates. Unknown native extensions retain conservative coverage
or an explicit unsupported movement boundary rather than a fictitious closure.

** One physical-write and access lifecycle

Use the existing activation/root/domain owners rather than an independent
registry. The following record requirements specify facts, not a new public API:
source and destination canonical identities; typed offset/range; layout revision;
source/domain epoch; admitted writer identity; reserved metadata; optional rooted
chunk input; completed progress; outstanding native readers/writers and outcome.
Logical identity and offset survive source relocation through qualified lookup;
a physical pointer is valid only within its admitted span. Generation wrap and
record reuse remain subject to the existing checked arithmetic/last-user rules.

The candidate C implementation uses release publication of completed metadata
and acquire consumption under a closed/drained cut. Plain memmove accesses must
not race collector or native accesses; adding a fence cannot repair such a C
data race. The actual selected C23 atomic backend, storage alignment and writer
closure need source and native evidence. General concurrently mutating bulk
copy requires a separate qualified algorithm and stays outside this boundary.

An ordinary GC write permit does not grant application-level exclusion between
two conflicting vector mutations. Preserve existing serial semantics and use
the declared synchronization/atomic-operation contract for concurrent clients;
do not advertise whole-copy atomicity from a GC card or RC lock.

** Overflow, overlap and interruption have one custody rule

Before the first destructive store, metadata failure permits refill at a
complete-root safe point or selection of conservative scan/coordinated-cut
coverage. Neither branch may silently omit the write, reject valid Scheme
mutation or collect while a cached physical pointer is live. Failure after a
completed chunk preserves its edge coverage and retains all remaining debt.

Long bulk operations also need an explicit GC-latency policy. One unbounded
noncollecting memmove would retain a valid root view but may delay a cut for its
entire duration. A bounded-chunk candidate must preserve directional overlap,
store progress in canonical coordinates and only park between scan-valid chunks.
Choose the chunk budget from the declared latency/metadata constraints; no magic
constant, inserted yield or longer watchdog constitutes a bound.

Unknown completion of an overlapping chunk cannot be resolved by repeating the
original memmove: some of its input may already have been overwritten. Recovery
requires a rooted, complete input for the chunk before its first destructive
write, an unambiguous progress/ownership record, and proven closure of the old
writer/helper before reconstruction. Moving the source requires rewriting the
staging roots as well as source/destination handles. Raw destination words may
be partially written; reconstruct a valid chunk before granting its scan access.
A dirty card alone supplies neither scan validity nor permission to repair
concurrently with a late writer. Merely making the writes word-sized also does
not determine which writes completed.

Two policies must remain explicit: cooperative bounded spans retain the affected
region while a write outcome/stop is unknown; a recoverable-span policy adds the
rooted input and settlement machinery above. The latter is not implemented or
proved here. Arbitrary OS-thread death, cross-library longjmp or continuation
escape through an unqualified C span cannot acquire a recovery guarantee by
naming an exit guard. Unrelated GC progress is possible only with independently
closed access/dependency domains.

In the map case, the shared vector may be reachable from both retained
continuation wrappers and Tcl's RC payload. A callback deletion can release
Tcl's installed ownership while an in-flight pin still retains the record.
Normal callback return releases that pin; exceptions/nonlocal escapes require
an actual cleanup/custody path. Each continuation shot reloads the current graph
and performs its own winding effects. Settling a bulk-copy outcome does not
permit replay of a user callback or undo shared mutation.

original source values still needed by future chunks. Within the current chunk,
a rooted input image must be complete before any destructive write if recovery
is promised. This invariant handles aliasing and overlap; physical relocation
adds slot repair but must not change the logical intervals or their equality.

No new Lean overlap theorem or QNT chunk machine is asserted here. Existing Lean
slot/identity results are consumed for relocation only; existing QNT ownership
results are consumed for phase/unknown/last-user ordering only. The concrete
overlap and staging premises remain visible source-refinement obligations.

** Rooted staging must have a real writer and scanner

private RC span, sets =root_count=, initializes every cell to FAL and then calls
=___register_rc=. =mark_rc= scans both =h->data= and the =root_count= payload

** Installation, filling and the scan-valid cut

Registration of FAL cells establishes allocation/list ownership, not successful
transfer of the original input. The parent retains source/destination roots
through endpoint installation and complete chunk-input publication. The
=installedRoot= role may acknowledge that transfer only for the exact input
revision with sufficient rooted values; a lost response is queried by the same
operation identity rather than repeating registration or destructive copying.

Partial filling can permit GC between known completed batches: every registered
cell is a valid SCMOBJ, source/destination retain all remaining inputs, and the
initialized prefix/readiness state is consistent. The scanner traces the entire
fixed root_count, including FAL remainder. It need not wait for the mutator to
finish the logical bulk operation merely to scan this valid partial stage.
Unknown/torn writes are different: no scan permission is issued until actual
writer closure permits repair to a valid shape. Shrinking root_count to hide
an uncertain cell would violate the representation and lose custody.

The native bulk candidate uses GC-only parking at complete-root chunk boundaries
without new user callbacks/call/cc capture inside a move. Such a boundary is an
implementation prerequisite, not an existing API inferred from a POLL token.
Existing Scheme fill loops retain their actual POLL/control semantics. A future
adapter allowing user hooks/captures inside the native operation must give each
Scheme shot appropriate control-local progress; a shared completed operation
cursor cannot silently consume subsequent multi-shot execution. Ordinary pending
user cancellation/exception delivery cannot acquire new partial-copy semantics
merely because GC parking was added.

Known stop includes the last physical data store and all helpers that could
still issue one. Validation before a grant is insufficient if that grant can
outlive closure. Retired revisions reject newly arriving controlled accesses;
already issued raw accesses must actually drain. Helper takeover needs a fresh
exclusive authority bound to the same operation after old data closure, not
another thread passing the old owner's PSTATE to current setters.

Recovery preserves serial overlap order and saved input for the uncertain chunk.
It does not roll back already committed Scheme mutations or replay callbacks.
Where the original API has no interruptible partial-effect contract, normal user
exception/cancellation delivery stays at a compatible semantic boundary. An
uncontrolled native escape remains unresolved custody, not an invented success
or a newly promised arbitrary-death recovery feature.

** GC-only means an effect restriction, not skipping VM coordination

The current service loop ends with =___lifecycle_drain= and possible error
throwing. Its body arbitrates multiple VM operations. Therefore calling it at a
new bulk checkpoint is not automatically a no-user-code operation, and masking
=INTR_SYNC_OP= or ignoring a pending resize can prevent other participants from
completing the collective. A busy bulk activation must remain a real lifecycle
participant, with retirement eligibility checked by its actual purpose.

The complete candidate adapter separates these responsibilities inside the
existing entry paths, preserving ordinary callers:

1. Close physical staging/destination access, publish complete logical progress
   and root view, then participate in the necessary VM/control/memory protocol.
   No source lock or live derived body pointer crosses this boundary.
2. Execute only the memory/root/control work permitted by this phase. Resize
   must respect bulk activity and cannot retire a carrier with a required native
   return or unresolved operation; it cannot be silently skipped after collective
   arbitration. No new environment option or parallel service loop is required.
3. Publish accepted restoration and reacquire source authority before reloading
   source, destination and staged references. Whole-round error/refusal is a
   separate outcome, not a successful resume inferred from one scan DONE.
4. Retain owner-affine FOREIGN cleanup, Scheme hooks/notification and pending
   errors for a semantically permitted effect boundary. Their work, roots and
   in-flight/unknown outcomes remain accounted; deferral is not discard or
   evidence of effect completion. New bulk GC parking must not accidentally
   introduce a call/cc capture point or repeat dynamic-wind/native effects.
5. Deliver pending effects with original ownership and error semantics once raw
   spans are closed and the calling boundary permits them. If compatibility with
   the current operation's effect boundary cannot be established, this parking
   mode is not admitted. A later general effectful bulk checkpoint needs its own
   shot-local control refinement, not a shared mutable completed cursor.

A pending error code that is proven nonmoving can remain native metadata; a
pending Scheme payload needs a declared root slot or other already installed
root. Extra root slots are reserved before allocation and included in immutable
root_count. The baseline copy span has 2+b slots; with e additional error/effect
roots it has 2+b+e, with checked addition/multiplication. Do not place a movable
Scheme error object into unscanned native progress metadata.

This source split is an actual implementation requirement. The current service
loop, notification handler and destructor caller have not been qualified as
GC-only by the checked formal slices. Safety, effect equivalence and eventual
pending-effect delivery all need actual source and native acceptance.

** Four outcomes that the existing postlude must not conflate

In setup.c, run_and_throw_error_on_processor_0 receives the startup result,
