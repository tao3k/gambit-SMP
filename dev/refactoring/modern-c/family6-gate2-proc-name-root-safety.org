* Root Cause

In =vendor/gambit/gsc/_gvm.scm= (=proc-obj-name=), procedure names are stored
as tagged Scheme strings (=___sSTRING=), never symbols; every existing caller
in =gsc/_t-c-2.scm= (=string->canonical-symbol=, =string->symbol=) consumes a
string.

The Gate 2 observation instrumentation in =vendor/gambit/gsc/_t-c-2.scm= wrote:

#+begin_src scheme
(set! targ-proc-gate2-name (symbol->string (proc-obj-name proc)))
#+end_src

Because =gsc/_t-c-2.scm= is compiled under =(declare (not safe))=, the C backend
inlines =(symbol->string x)= to unchecked =___SYMBOLNAME(x)= (=___BODY0_AS(x, ___tSUBTYPED)[0]=).
When =x= is a Scheme string starting with ="##"= (such as ="##open-process-generic"=),
=body[0]= contains the two 32-bit UTF-32 characters =0x0000002300000023=. Storing
that untyped payload word into the GC-scanned global variable =c#targ-proc-gate2-name=
violates the collector's root-tag invariant: =0x23 & 3 = 3= (=___tPAIR=), so
=mark_global_variables -> census_array= untags =0x0000002300000023= and reads
=*(0x0000002300000020)=, raising =SIGBUS=.

Even without an intervening GC, storing the raw character word instead of the
procedure-name string also prevented =targ-note-group-site= from emitting valid
=___GATE2_OPEN= / =___GATE2_ENTER= procedure-name literals in Pass 2.
