replaces every admitted real address consumer. The selected flat-header source
changes nineteen handwritten paths. [[file:execution-storage-audit.org][The file-by-file audit]] states necessity,

No new profile, executor, SCM test module or parallel namespace is introduced.

The existing call-arity scalar =na= and allocator capacity guard =heap_limit=
retain their unique PSTATE storage. Root storage separation does not justify
rewriting instruction dispatch or register allocation. Those implementations
and the three CPU emitters remain byte-identical to the base. The root record
is not permission for live rebinding, independent retirement, W<R or a complete
transferable call/allocator context. =pstate_mem= and current GC policy remain.

SysML is the authority. Its native projection drives the existing ASCENT
commit policy; Org and [[file:execution-storage.d2][D2]] are views. QNT schedules and Lean laws are
not duplicated for this coordinate change. Future participant/worker protocols
retain their own finite-schedule and universal-coverage obligations.

The original numeric fields mixed two owners. The CPU backend's actual current
instruction callers need carrier guards, while the C bridge materializes GVM
roots. This distinction removes the need for a general nested-memory operand
or register-spill redesign. Startup binds each context before helper access;
resize initializes additional states before publishing processor_count. Existing
collective and owner lifetimes remain premises, not newly proved protocols.

* Admission before cached completion :modules:counterexample:

The existing module descriptor/version/structure-size fields remain. Their
checks now precede =SETUP_FIXUP_DONE= cache acceptance, module-count mutation
and fixup writes. No release version, ABI-dispatch shim or fallback layout is
added. Old compiled private-layout modules require recompilation.

The actual negative control holds an old module with a native =dlopen= handle.
Before the ordering change, the first layout rejection changed flags from1
to3. Thus rejection itself poisoned persistent fixup state. After the change,
flags remain1 after two rejections and the old body never executes. The first
rejection is the exact layout error; the second may be the existing once-only
load error. That official policy is preserved. Matching concurrent module
fixup remains outside this sequential admission unit.

A real baseline positive loaded the same old module and executed its body.
This excludes wrong filename/linker lookup from the successful rejection
claim. Earlier failed fixture calibrations are retained separately. These
existing size checks distinguish this actual old/new layout; they do not
establish a universal fingerprint for future same-size ABI changes.
