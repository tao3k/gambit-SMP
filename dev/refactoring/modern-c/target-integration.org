source tree previously qualified. Current target =f1c787a0= contains complex
=atanh= fixes and added original unit cases. The checked-in branch numeric C
still implements the earlier formula; the new case expects =1e-200= for the
real part at =1.+1e100i=, but all tested platforms produced zero. Keeping core

Normally merge the existing target without rebasing or force-pushing. Produce
distribution C from the resulting exact Scheme tree, including its shared
numeric constants. Retain every inherited unit expectation. A complete
independent bootstrap qualifies the producer; clean objects plus dummy seed,
original core and every original check prerequisite qualify its consumer. This
changes no workflow Build/Test command and introduces no numerical algorithm.

* Pending source custody :ownership:

Handwritten target updates are three-way merged separately into the existing
index and working view. For example, numeric formula changes must not discard
pending context field migrations elsewhere in =_num.scm=. Conflicts reject
the operation before applying any source plan. Qualified generated blobs enter
the selected index; pending feature-specific raw generated bytes remain intact.
The submitted alternate index contains the tested tree and neither pending
runtime content nor a successful-looking partial test run.

* Questions resolved and excluded :review:

Portable C, multi-shot continuation, frame/root contracts and public namespaces
are unchanged by this integration. The benefit is reliable qualification of
the actual source tree that GitHub builds. It does not establish worker/root
