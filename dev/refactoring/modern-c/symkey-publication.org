** Problem and complete responsibility

At7abe6770, the UTF8 factory probes the shared table and later constructs
and inserts without one transaction. Two callers can both miss, then each
publish a different permanent object for the same name/subtype. Even a
serialized pair of insertions after those two misses duplicates the count;
the counterexample needs no simultaneous bucket write or undefined data race.
Rehash also rewrites NEXT while native walkers can follow it independently.
Passing the mutable anchor address straight to physical marking does not
specify who owns it when a native publisher replaces that anchor.

The replacement gives one existing registry gate authority over an entire
native lookup/create/insert/rehash operation, including count and anchor
publication. Native walkers use that same authority. GC instead captures
its own two cells, marks outside the gate and conditionally commits moved
anchors. The retired responsibility is split mutation authority, not merely
one unchecked instruction. This does not claim a parallel, wait-free registry.

** Conditional correctness argument

#+NAME: symkey-premises
| Premise | Concrete source/refinement obligation | Falsifier |
|---------+--------------------------------------+-----------|
| P1: every admitted native bucket/count/NEXT reader/writer uses one gate | Public service wrappers, exclusive direct bootstrap insertion, two reverse walkers and actual TTY callback | New ungated consumer, raw alias mutation or callback reentry |
| P2: permanent publication lifetime | NULL-processor tables/names/nodes, no reclaim before exclusive global cleanup | Concurrent global cleanup or moving native publication |
| P3: no GC/continuation escape inside the fragment | Private helpers allocate only permanent storage, callback has NoReentry, no join or safepoint under gate | New Scheme allocation, callback/nonlocal escape or unknown dead owner |
| P4: moving test anchor is exclusive | Existing p1 relocation control temporarily replaces anchors and restores them before Scheme reentry | Concurrent moving publisher or raw access to half-restored anchors |
| P5: source strings stay stable | Native C string lifetime / Scheme caller roots and no concurrent character mutation | Borrow escapes or string modified while hashing/copying |

1. Under P1--P3, critical sections are ordered by the existing acquire/release
   mutex. An existing name returns its permanent object; a missing name is
   inserted before the next lookup enters. Thus at most one canonical object
   and one count increment are published per admitted name/subtype. A gate
   around insertion alone would not establish this property.
2. Native rehash rewrites bucket/NEXT/count and installs the replacement
   vector under the same authority. Readers cannot traverse an intermediate
   topology. Hashing, string comparison and rehash remain real critical work.
3. Construction failure before insertion leaves topology/count unchanged.
   Rehash failure after insertion is different: that node is already accepted
   and remains in the old valid table. Retrying allocation must not reinsert it.
   Integer checks use min(fixnum bound, C index bound), and growth arithmetic
   avoids an overflowing length-times-four predicate.
4. GC captures =before[2]= and =cells[2]= under the gate. Its physical mark
   owns only the local cells. A permanent anchor does not move and requires no
   writeback; a newer permanent table is never overwritten by the captured
   value. Under P4, a moved fixture anchor is committed only while the global
   anchor still equals =before=. The task is SCANNED only after this handoff.
   A stale unconditional writeback is an explicit native negative control.
5. No native operation waits for GC while holding the registry gate under P3.
   Marking releases that gate before any chunk/refill work. This excludes this
   particular registry/GC wait cycle; it does not establish robust recovery
   from arbitrary owner death, all FFI progress or scheduler fairness.

** Architectural questions and next dependencies

Why is this refactoring? The service receives mutation authority for its
whole lifecycle and GC receives an owned view plus commit protocol; split
check/create and borrowed mutable anchor addresses retire. It is falsified by
a second native identity/count increment, a walker seeing intermediate NEXT,
or stale mark overwriting a newer publication. Extra heap or longer waits
cannot repair those invariants and are not used.

Why is this useful for modern SMP? A shared registry can be serialized while
Scheme executions remain parallel. A defined source/reader boundary is a
necessary predecessor of independent collector workers; it is not sufficient
for W != R, whole-root coverage or Repair9 capacity. Coarse registry contention
is an explicit cost to measure rather than a claim of universal scalability.

How does it amplify Gambit? Canonical shared Scheme identities and existing
multi-shot frame/root behavior remain available across parallel contexts.
Collector work need not own a mutable global anchor address. No one-shot
restriction, isolated actor heap or alternate language backend is imposed.
This cut learns ownership separation, not an OCaml/Erlang mechanism transplanted
without matching Gambit's shared-object and continuation semantics.

Next: ROOT-VIEWS must specify Scheme reflection/iteration and alias ownership;
ROOT-WRITERS must close remaining value stores/native borrows; ROOT-CENSUS must
compose the frozen union and lifetimes. Then worker/arena and retirement stages
can use those premises. No whole-SMP numerator is earned by this local cut.
