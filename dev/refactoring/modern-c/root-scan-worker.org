** Responsibility replaced

Previously the collective supplied a processor to six scan APIs, and those
APIs selected processor.collector internally. Capturing it once inside a source
was necessary but did not expose the collective-to-scanner contract. The caller
could not name or falsify which worker owned that scan.

The actual strong-phase caller now passes its work directly to root_round_scan.
The dispatcher carries it through RC, VM, bank, stack, globals and symbol/keyword
scan entries. Private globals/symkey helpers and read-only copy census also take
that explicit value. Each scan entry compares it with the admitted carrier
binding before dereferencing worker or source payload. A mismatching argument
is refused; it is never silently replaced by carrier.collector.

The processor remains the existing current-executor/source-lifetime adapter for
publish, claim, finish and source predicates. Those APIs are not renamed or
duplicated. This is not live worker migration, an independent reclamation permit,
or retirement of every carrier relation. All RC/global/frame locks, canonical
source checks, epochs, single leases and scan order remain.

QNT retains temporal task/phase/copy histories; Lean retains range/capacity
laws. Native C refinement and PBT own concrete argument routing/refusal. These
are distinct obligations rather than duplicate state machines.

** Consumer failure boundary

SFUN root-bank feature. Six-source PBT, frozen-root union, collector and moving

That whole recipe is not called green. A same-source parent/candidate comparison
must classify the failure before submission; it is not silently omitted or fixed

expects two intercepted calls. The current generated activation delegates root
allocation through begin_sfun in the runtime. Source inspection explains why
that interception premise can be stale, but only native same-condition parent
