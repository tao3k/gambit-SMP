** Why the previous candidate is not this delivery

The previous explicit root-scan routing candidate remains DENIED. All its
unfavorable samples remain evidence; a later favorable result cannot erase them.
Every original request interval reported zero GC and equal Scheme allocation.
Its actual one-argument entry differs only at the resolved external TLS stub
address; the related store helper differs at external stub addresses. Thus the
changed GC scan branches have no observed collection in that workload. Static
instructions and this absence do not prove equal cache, processor or frequency
state. Original observations do not contain those dimensions; the exact hardware
cause remains unresolved, rather than invented after the fact.

The real request path still called lifecycle_marker_prepare and abort for each
SFUN entry. Those unconditionally allocated/freed one physical native record.
Replacing that complete storage ownership is useful on the actual workload;
it neither weakens a source guard nor claims the earlier GC routing was faster.

** Actual role replacement

| Phase | Published source | Replacement / owner |
|-------+------------------+---------------------|
| Acquire | lifecycle entry then unconditional record allocation | Same entry authentication; RC domain offers its one clean idle record or allocates on a miss |
| Live / revoked | VM activation list owns physical extent, bank and marker | Unchanged; an unknown/live/revoked physical extent never becomes reusable |
| Known final use | Unlink, return bank borrow, release roots, free record, leave | Unlink/return/release first; clear owner, marker, roots and next; offer idle storage or free excess; leave last |
| GC | Registered bank and marker roots, multi-shot frame descriptors | Unchanged; idle record has no Scheme edge and is not on the active list |
| Domain teardown | Closed lifecycle entry and RC cleanup gate | Check clean idle state; free slot before source detachment; byte RC owner can retain detached domain |

The slot is singular because one admitted cooperative source can use its next
record once. It is not a general pool, capacity knob, global identity table or
cross-owner work queue. Nested records remain distinct; a full slot releases
excess known-dead storage. A live cleanup attempt refuses without recycling the
active record. Terminal cleanup retains its original direct-free path and cannot
infer physical death from a timeout or unknown join.

** Source and C-memory-order premises

Only the admitted native owner changes both its activation list and its domain's
idle pointer. Existing lifecycle_enter checks current PSTATE, native thread owner,
VM registry/phase, entry counter and RC source binding before slot access. There
is no Scheme allocation, poll or callback between taking storage and linking the
fully initialized record. GC workers never read/write idle storage.

On release, the old final-use path unlinks and returns every root first. Clean
slot writes precede lifecycle_leave's existing CAS decrement. The GCC profile
uses the existing full-barrier sync CAS; cleanup acquires/owns entry closure and
the RC gate before destruction. No new lock or weaker memory order is introduced.
The last entry is not published zero before its last metadata write.

A void scope pointer expires at physical end, just as it did when the record was
freed immediately. Address reuse is not a new logical identity or a lease for a
late raw pointer. No Scheme continuation stores that private record pointer as
its resumable frame identity; existing markers, registered roots and frame
descriptors keep that responsibility. Arbitrary private-API misuse, asynchronous
owner death and unknown-effect recovery are not admitted by this cut.

For N flat, known-completed entries without other acquisitions, the first miss
allocates a record and subsequent entries reuse it. The source law is N record
allocations/frees versus one allocation and eventual domain-teardown free; it is
not a measured total malloc count. Rooted SFUN banks still allocate/free and
markers still consume Scheme space. This is not allocation-free FFI.

The portable additional requested native-byte bound is48*R (8 metadata plus40
idle per retained domain), excluding allocator rounding. Concurrent/nested active
records remain necessary. Do not call the retained slot free memory or infer a
whole-round physical-memory saving. The observed process peaks are separate.
Single-cohort timing is favorable, not a universal or statistically stable
percentage. Strict publication rejects adverse measured rows and unproved
positive benefit; structural gains cannot hide runtime regression.
