* Why the earlier bootstrap expired
** Aliased responsibility
=clone()= mapped the in-place policy to =reuse_workspace()= for every type.
A successful seed output consequently referred to the same physical directory
that =bootstrap()= passed to =bootclean= and =make from-scratch=. The native
Make target itself cleans once, builds the compiler, cleans again and builds
with that compiler. In the second pass it removed target GSI/GSC products.
The retained =source-state.json= / state inventory recorded hashes, not backup
bytes. It could detect loss but could not supply the missing executable.

** Duplicate necessary work
The old validation graph first ran a whole =seed-core=, then the existing
=from-scratch= target's two complete target builds. That is three target core
builds. A source-bound complete AOT host compiler was already present and its
Scheme generator graph matched, so the preliminary target seed was redundant.
The interrupted native run spent 157.470 seconds in seed-core; the whole600
limit left 361.521 seconds for from-scratch. It expired at600.449 seconds with
phase announcements =(2,2,2,1)=. Seven announcements do not establish eight
completed phases. Preserve that DENY, quiescence and absence of child authority.
This is a work/deadline composition explanation; no matched timing regression
or percentage speedup follows from those uncontrolled observations.

* Implemented ownership architecture
** Compiler is an input, not an already validated target runtime
=gambit.bootstrap-input= requires the host executable hash, original completed
producer/child/identity hashes, all current Scheme generator input hashes, and
the target configuration. Its =bootstrap-input-identity= explicitly says no
target runtime has been established. It cannot feed semantic runtime tests.
Only bootstrap review and the actual two-pass target build accept this type.
The original Make target runs both complete passes; no target pass is skipped.

** Completed outputs are independent generations
Seed and completed bootstrap publication use =preserve= / =freeze=. The source
and copied complete inventories must match; partial copies and source changes
cannot publish completion. Copies are APFS COW when available and full byte
copies otherwise. Hardlinks are excluded. A separately published preservation
record controls reuse; directory existence alone is insufficient.

A content-bound derivation records the build role and exact input inventory,
while preserving compiler, flags and environment. Its source remains inside
the registered =gambit-core= build product and actual task/workspace leases.
No source is allocated under an attempt directory. Private dirty generations
fail closed and require explicit recovery; they are not silently overwritten.
Published runtimes remain hash checked and every destructive consumer obtains
an independent working generation. This protects producer bytes, not indefinite
archival availability; normal cache retention still applies and missing bytes
refuse reuse.

** Precise reuse and reconstruction
A completed target needs actual exit0, full two-pass phase inventory, stable
Scheme inputs, exact source/profile/compiler identity and reaped/quiescent
processes. Only that producer can issue an explicit reusable runtime reference.
The next consumer must use those bytes and record original expenditure; it
cannot infer a producer from a partial workspace or rerun bootstrap merely
because a new attempt directory exists. Configuration/source/toolchain drift
requires a new producer and cannot load an old target binary.

* Conditional argument and counterexamples
1. Producer completion follows checked copy and independent storage. A later
   working-copy unlink/write cannot mutate producer bytes because no hardlink
   exists. Actual per-file identity and mode checks establish the copy boundary.
2. An incomplete copy lacks its completion record; even if its directory exists,
   reuse is rejected. Late source mutation is detected by before/after identity.
3. Compiler-only data carries no target GSI/library identity. The type graph
   rejects its use by map/GC semantic tests before native invocation.
4. Host receipt drift, wrong executable hash, changed Scheme generator graph,
   wrong target profile or changed producer bytes defeats exact reuse.
5. Two actual source passes and original limits remain mandatory. A local C
   kernel, old-source continuation pass, seven phase announcements or a new
   metadata envelope cannot substitute for them.

These are source/filesystem/typed-receipt refinement arguments. They assume
correct OS copy, file-identity and lease primitives; native snapshots and
adverse tests validate their scoped use. They are not a new Lean theorem.

* Five gates and remaining global questions
The stage gates require tests, architecture learning, current process location,
model delivery and answered scoped questions. A bounded stage commit does not
close global =osCommitReady= or runtime release authority: unknown-owner recovery,
other backends and diagnostic history remain explicitly open. The stage's
question is how to preserve and qualify the synchronous current-target contract,
not how to assume those future services are already implemented.

Current source implements typed compiler input, independent completed seed/
target snapshots and private destructive rebuild. Original target compilation,
GC roots, full continuation and native C consumers still execute. The staged
benefit is eliminating one whole redundant target build and protecting exact
reuse, rather than changing the target language or increasing memory/time caps.
