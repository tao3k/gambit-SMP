** Authority and geometry

Model an authority as =(owner, region, generation, extent, access)= and bind
its use to an activation, write-group identity and attempt. A region generation
changes when its backing is retired or reassigned. A GC/root-view revision
tracks relocation and reloading separately. Moving collection may require
reloading references while a source segment remains pinned. Shared reads
require live custody; exclusive writes require current write authority.

For an extent =[lo, hi)=, a footprint beginning at offset =start= with
=words= words fits when =lo <= start <= hi= and =words <= hi - start=.
Each actual store additionally needs an offset strictly below =words=.
The subtraction requires the preceding order check. The C correspondence
must establish object provenance, alignment, checked word-to-byte conversion
and representable arithmetic before forming a pointer. Logical frame depth,
initialized/root prefix and physical backing have separate meanings.

Evaluate physical authority before capacity. A live valid region with a
short footprint can use an existing backed recovery path. Invalid ownership,
expired backing, an outside cursor or arithmetic failure requires a preserved
diagnostic before an unbacked spill or collection. The failure path needs its
own backing contract.

** Research basis for engineering decomposition

The following adaptations target checklist items 4-12. The cited publications
establish methods in their own settings. Applicability to the current Gambit

*** Contracts and local memory reasoning

Meyer's /Applying Design by Contract/ (1992) assigns obligations through
preconditions, postconditions and invariants. Apply this vocabulary to each
of the five existing supplier/consumer boundaries. For a footprint check,
state the allocator-supplied authority, the exact admitted writes and the
invalidation conditions. Resource shortage and invalid authority need
separate outcomes with backed failure handling.
[[https://se.inf.ethz.ch/~meyer/publications/computer/contract.pdf][Meyer, Applying Design by Contract]]

Calcagno, Distefano, O'Hearn and Yang's /Compositional Shape Analysis/
(2008 technical report, followed by the 2009 bi-abduction publication)
analyzes procedures using local heap specifications. Bi-abduction infers
missing required state and the residual state outside the operation's
footprint. For items 4 and 6-8, describe what each allocation, spill, copy
or reload requires and changes. Validate that caller state supplies the
required footprint, while retained source custody survives the operation.
Grok may propose these summaries from observed code. A summary becomes
verification evidence only through a corresponding checked source model.
[[https://spiral.imperial.ac.uk/entities/publication/a3590359-6c02-406d-8bdd-b6f20cdb23a3][Calcagno et al., Compositional Shape Analysis]]

The immediate implementation unit is the effect boundary around a generated
group or runtime helper. Reuse current source functions and allocator records.
Separate capacity calculation, ownership validation and effectful mutation
where a reproduced failure shows that they are interleaved. Provide an exact
effect inventory before attempting a wider structural refactor.

*** Concurrent interference and authority transfer

Vafeiadis's /Modular fine-grained concurrency verification/ (2008) combines
rely/guarantee and separation reasoning in RGSep, including ownership transfer
and linearizability arguments. For items 7-9, state which changes other
handlers or the collector may make, which shared invariant survives those
changes and which existing synchronization operation linearizes the claim.
Bind this to actual section pin/release, capacity validation and publication.
QNT can explore these histories. Source refinement must additionally relate
the real locks/atomics and memory-order assumptions to the modeled events.
[[https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-726.html][Vafeiadis, Modular fine-grained concurrency verification]]

For the final-section race, record the locked capacity read, successful
reservation and publication, and unsuccessful-contender custody. For source
handoff, record successor authority and the last required source use before
release. Model counterexamples identify candidate failures in this mapping.

*** Validate each generated translation at the affected boundary

Necula's /Translation Validation for an Optimizing Compiler/ (2000) checks
the relation between intermediate programs across individual compilation
passes. Adapt the principle to items 4-6 and 12 by relating each affected GVM
operation inventory to the actual emitted C and macro effects. Check that
whole-group admission dominates the stores, that decoded return descriptors
match the intended old view, and that demand covers the complete footprint.
[[https://people.eecs.berkeley.edu/~necula/Papers/tv_pldi00.pdf][Necula, Translation Validation for an Optimizing Compiler]]

This proposed checker initially validates these selected properties. Full
semantic preservation requires source and target semantics and broader
coverage. Retain missing cases explicitly. The operation inventory emitted
by the producer needs an independent check against actual C/macro effects.
Make hashes establish artifact identity and lineage; the property checker
establishes its stated correspondence. Keep both in the existing receipts.

*** Reduce a stable native failure and refine only implicated state

Zeller and Hildebrandt's /Simplifying and Isolating Failure-Inducing Input/
(2002) minimizes a failing input or the difference between passing and failing
cases. For item 4, hold host identities and formal prelude fixed while reducing
the module using syntax/dependency-aware changes. If the prelude difference
is itself the hypothesis, retain private matched variants and return to the
original full prelude for the repair regression. Preserve the original inputs.
[[https://www.st.cs.uni-saarland.de/publications/files/zeller-tse-2002.pdf][Zeller and Hildebrandt, Simplifying and Isolating Failure-Inducing Input]]

The oracle must recognize the same first violated contract or native failure
signature. A syntax error, different crash or ambiguous timeout is unresolved
for that oracle. Retain PASS, matching FAIL and UNRESOLVED outcomes. Reduction
can require many tests and may expose timing sensitivity. Record the experiment
cost and choose another hypothesis when evidence supports it. A reduced case
is a diagnostic artifact; original module/bootstrap and campaign evidence
still close the corresponding checklist items.

Clarke et al.'s /Counterexample-guided Abstraction Refinement/ (2000) checks
whether an abstract counterexample has a concrete counterpart and refines
the abstraction when it is spurious. Apply this discipline when a QNT trace
and native observation disagree. Add the state that explains the mismatch,
such as region generation, root revision, nested-service scope or post-unwind
cursor. Preserve a concrete reproducer when the counterexample is realizable.
[[https://web.stanford.edu/class/cs357/cegar.pdf][Clarke et al., Counterexample-guided Abstraction Refinement]]

ASCENT should associate hypotheses with those traces, source bindings,
counterevidence and missing observations. A sound CEGAR implementation would
also require a sound abstraction/concretization relation. The current proposed
evidence loop retains this as an OPEN correspondence obligation. New evidence
can change the selected repair and experiment without a fixed retry sequence.

** 4. Give failed recovery an explicit settlement
