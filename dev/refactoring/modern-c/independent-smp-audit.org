** Physical partition and logical label identity

The compiled creator resolves through =##continuation-parent= and
=##subprocedure-parent=. For ordinary C labels the runtime locates the
preceding INTRO in the contiguous logical label table. Subprocedure IDs
are offsets from that INTRO, and return descriptors consume out-of-line
GC maps in the original label order. Preserve the INTRO, label indices,
return descriptors and OFD order. Module fixup separately obtains the
computed-goto table when the physical host changes. The portable switch
path must also check the destination host before applying a local offset.

A static midpoint cut on the actual candidate C crosses 1,445 explicit
GOTOs in =f64vector= and 545 in =concatenate=. Every counted target is
a C-only label. Turning these targets into Scheme label records would
change logical offsets. The planner must first identify control-flow
regions whose cut edges already have a materialized GVM state and an
addressable entry. Otherwise it must prove a separate physical entry
protocol or refuse the cut. These counts exclude fallthrough and
computed branches, so they are a lower bound for that trial cut.
[[file:../../../evidence/research/retained/modern-c/frozen-568e0276-smp/mvp-gsc-physical-host-cut.json][Source-bound cut counterexample]].

The existing physical compilation-unit model owns this refinement.
Whole DEV native model validation still reports an unresolved
