** Delivered ownership change and actual falsifier

The old higher-order fold retained a live bucket vector and followed intrusive
NEXT between user callbacks. Individual native transaction locking did not
protect that semantic lifetime. A callback could rehash the registry and change
the remaining traversal even on one processor.

The replacement captures N canonical identities under the existing native
registry gate into a Scheme-allocated/rooted vector. Native capture allocates
nothing and retains no pointer after return. On count mismatch it writes no
destination cell and returns the new size hint. Capture ends before any user
callback; the fold reads only its managed vector. GC, exception, dynamic-wind
and multi-shot resumption use ordinary Scheme frame/object ownership.

The actual compiled predecessor captured6297 members but visited2020 after
callback growth. The13-action history shrinks to one adversarial-fold action,
replays against that old body and passes against current code. That action
contains real callbacks/interning/rehash/GC; it is not one C instruction or a
globally minimal OS schedule. Gambit's own reader confirms identical old/control
parameter/body ASTs, apart from definition name and matching compiler declarations.
There is no old-loop fallback in production.
