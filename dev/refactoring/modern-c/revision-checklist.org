The native SysML comment contract applies to large refactors and small fixes.
The existing submission service projects its fields, freezes the reviewed
report before ASCENT admission, and appends it to the actual Git commit body.
Missing fields, a missing/stale report, an absent Org checklist anchor, or
changing the reviewed report after admission blocks publication. The commit
also records base, exact tree, source-manifest/profile/report hashes.
The checklist's own content hash is bound to that report; changing the
checklist after review also blocks publication. After each submission, the
user-facing report must name the actual REV, its responsibility cut, executed
tests/results, evidenced benefit, added cost and open/next obligations.

Every progress and final report must also answer these architectural questions:

1. Which concrete failure/ownership window does this REV remove, and which
   official consumers change? State whether this is qualified or still a candidate.
2. Which stable Checklist ID owns the replacement? Give closed and remaining
   obligations with an explicit unit and evidence boundary, rather than a test
   count or number of commits presented as SMP progress.
3. Where is this cut in the dependency chain, and what must close next?
4. Which old authority, storage or repeated work actually retires? Give the
   invariant and a counterexample that would falsify the claimed replacement.
5. What measured benefit, added synchronization/space and unresolved scope remain?

The delivery-plan SysML owns stage and responsibility coverage. Org and ASCENT
project those facts. A scoped root-source leaf does not close the ROOTS stage,
and no repair-line test8/test9 or 8--12 numerator transfers to this branch.
