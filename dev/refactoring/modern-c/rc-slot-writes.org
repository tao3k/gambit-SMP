** The responsibility being replaced

A stable RC root cell must keep its logical referent while borrowed. The old
owner/OPEN/refcount check admitted a different value even with two live loans.
The receiver could consequently resume a different thunk after a GC-capable
handoff. This is an allowed bad source history, not an assertion that a recorded
test8/Repair9 failure had this cause.

The single admitted setter now arbitrates writes against the existing per-header
borrow count under the existing domain mutex. A differing value is refused while
any loan remains. An identical value is accepted without a store. All public
=___set_data_rc= calls already delegate to this authority; no caller-side shadow
counter or second API is introduced. Native positive refcount does not override
a logical loan. Mutating the Scheme object's contents remains legal.

This is a small, complete write-authority replacement in the larger architecture,
not a whole-root or whole-SMP completion. It removes a conflicting permission
rather than adding a timing check around a known failing workload.

** Conditional correctness and counterexamples

Given a live valid RC header, admitted owner access, domain-lock mutual exclusion,
and the existing cooperative collector freeze/participation protocol:

1. Borrow increments cell/domain loan counts under that mutex before returning
   the native cell address. Native release cannot reclaim a header with a loan.
2. An admitted mutator write during the loan is either rejected or a no-store
   identity operation. Thus it cannot change the borrowed logical referent.
3. A frozen claimed scanner may still relocate the cell's address value. This
   preserves referent identity. The borrower reloads after allocating calls;
   freezing the cell's bytes or forbidding GC during loans would be incorrect.
4. Last loan return can reclaim a header only if native refs are also zero.
   An unknown outstanding loan retains custody; no timer invents a return.

The old setter's real function body is compiled under a test-only renamed symbol.
Create→borrow twice→replace produces a counterexample with live native refs.
The existing shrinker reduces a13-action history to one *compound request* and
replays it against old/current functions. That request still contains allocation,
two loans, attempted replacement and cleanup: one action is not one C instruction
or a globally minimal concurrent schedule. No production legacy fallback exists.

Other counterexamples remain open: naked =data_rc= snapshot carried through an
allocation; a foreign reader ignoring GC participation; dead owner retaining an
unreturned loan; a raw external store bypassing the API. This leaf cannot grant
independent-worker or arbitrary native-death recovery admission.
