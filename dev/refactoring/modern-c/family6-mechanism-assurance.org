** Refusal closure at public reentry
:PROPERTIES:
:CUSTOM_ID: refusal-composition
:END:

The existing QNT owner now includes caught-refusal -> new exact-fit entry,
plus a separating mutant with zero writes but missing backing. This is an
abstract missing guarantee, not an implementation of exception unwind.
Its normalization action assumes current backing and the exact map; the C
path must independently supply those premises. A model test passing cannot
create them.

Distinguish terminal construction refusal, invalid authority, and valid soft
shortage followed by GC and a fresh grant. Successful recovery may write its
authorized result. A terminal refused attempt must not perform its protected
construction writes. Neither condition implies rolling back valid GC root
movement or backed handler metadata. Their permitted effect frames must be
separate from the protected construction footprint.

Grok can compare fresh exact fit with refused-then-exact-fit using one image
and independently observed public boundaries. The resulting first contract
discrepancy chooses the next source cut. No fixed retry sequence is prescribed.

** Logical extent and source lifetime
:PROPERTIES:
:CUSTOM_ID: logical-extent
:END:

The Lean stop lemma proves a conditional geometry implication: if the logical
stop lies in a segment and the actual decoder advances no further than that
stop, every continuing position remains within that segment. It does not
prove the real decoder or pointer provenance correct.

The existing =smp_rest_record_lifetime= tests pin/close/retire orderings. A
logical model edge must map to a real source-consuming C edge. A prefix walk
whose supplied stop ends at the current break cannot substitute for it.
Locate the legitimate successor descriptor and its consumer, then observe old
pin, successor admission, final old metadata use and release. Do not fabricate
a successor pointer or change the original acceptance workload to obtain it.

* Feeley research and mechanism-level amplification

[[https://www.cs.tufts.edu/~nr/cs257/archive/marc-feeley/polling.pdf][Feeley's Polling Efficiently on Stock Hardware]] places checks using program
structure and an explicit latency/cost model. The engineering implication here
is to make the compiler's aggregate demand and runtime service obligations
match. Removing checks without preserving those premises does not follow from
the paper. Its instruction-cost bounds do not establish our wall-time budget.

[[https://3e8.org/pub/pdf-t1/feeley.pdf][Feeley's A Better API for First-Class Continuations]] separates capture,
graft, return and next operations. Our application is to model the semantic
continuation at exception return explicitly, rather than treating an exception
message or zero stores as proof of a restored execution context. This is an
engineering inference, not a claim that the paper proves this SMP runtime.

[[https://people.eecs.berkeley.edu/~necula/Papers/tv_pldi00.pdf][Necula's translation validation]] motivates checking each actual producer /
consumer correspondence. Hashes establish identity; a demand/effect relation
still needs a checked correspondence to that emitted and linked code.

Model-based LLM amplification is our application: one stable counterexample
separates hypotheses and identifies the supplier/consumer edge to inspect.
Reuse unaffected verified premises; invalidate source-dependent results after
changes. Avoid repeated large builds to rediscover a mechanism, and avoid a
second simulated algorithm whose proof can diverge from production C.

* Remaining implementation and native obligations

QNT histories do not prove C memory order; Lean premises do not extract a
complete lowered store inventory. The current C cut does not prove actual
exception unwind, decoder provenance, pin atomic ordering, or frame reuse.
Existing Frama-C/WP owners can express function assigns/loop invariants for a
selected actual source cut; concurrency ordering needs its own implementation
proof or litmus evidence when relevant. These are focused obligations, not a
requirement to invoke every tool for every repair.

The previous native recorder regressions establish transport, macro hooks and
receipt validation. They do not establish complete construction-write coverage
or actual same-GSI checklist 6-9. Full interval snapshots alone also cannot
detect every write-then-restore without independent store coverage. Preserve
that gap; do not silently relax the validator or call a sentinel a full frame.

Mechanism closure requires actual supplier/consumer correspondence, permitted
effects, failure composition and native observation on the identified image.
A new guard that merely moves failure downstream is not closure.
