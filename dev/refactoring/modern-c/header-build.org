** Why this replaces a responsibility

The old Autoconf entry and two Make variables each restated the forty ordered
paths already present in =include/gambit.h.in=. Equality checks detected drift
but left four maintained lists. The new Make target derives its ordered
render inputs, prerequisites and =RCFILES/DISTFILES= from that original manifest.
Configure registers a standard header command that calls the existing target.
No second manifest, executor, profile, environment variable or public namespace
is introduced. Standard =MAKE= and =AWK= retain their normal tool meanings.

=config.status --file= remains the substitution service. Make renders to a
target-local temporary, compares bytes and atomically publishes only changed
content. It issues =stamp-gambit= after success. That checked-input stamp is
distinct from the public header's content timestamp: an unchanged-content
input touch must not cause perpetual rerendering. Missing output still causes
reconstruction. Invalid/duplicate manifests, missing fragments and failed
substitution cannot advance completion or replace a valid output.

The non-Git =stamp= target also compares its empty output before publication.
Repeatedly rewriting that unrelated input previously rebuilt =_kernel.o= and
relinked consumers even on a no-change core build. Official target names,
phase structure, preprocessor semantics and installed header shape remain.

** Native acceptance and custody

Use the existing =modern-c-frame-contract= workspace and the existing Bazel
Darwin GCC/C23 profile. The public [[file:../../../evidence/research/retained/modern-c/header-build/native.json][native packet]] records exact inputs, tools,
commands, matched controls, exit/quiescence, file identities and measured work.
The runner is the existing =ExecutionContext= and workspace lease. No second
runtime source copy is needed. Temporary generation protection belongs to the
same task and is reclaimed only after exact recovery and child quiescence.

#+NAME: header-build-acceptance
| Case | Required observation | Excluded inference |
|------+----------------------+--------------------|
| No-change core, repeated | Count real generation, C, archive/link and file writes; retain identical header | No whole cold-build claim |

| One header module changes | Derived dependency rerenders header and rebuilds a real C consumer | No hidden manual list update |
| Unchanged-content touch | One successful input check; header identity retained; next check does not render | No timestamp-only completion |
| Duplicate manifest | Nonzero Make exit; valid public header unchanged | Failure is not a cache hit |
| Distribution | Same ordered forty modules in derived dependency and distribution views | No glob order assumption |
| Installation | Installed public header equals the configured public output | No private runtime header dependency |
| Scheme consumer | Four restores of one continuation with GC, natural exit and exact marker | No one-shot substitution |
| Failure recovery | Every protected source/product authenticated before reuse; unknown child custody blocks | No partial acceptance |

The first native campaign's operational checks finished but its rollback
metadata assertion failed. A later recovery attempt exposed POSIX rename's
same-inode no-op: an owned temporary alias may survive a rename between hard
links. Mutable artifacts require independent generations; rollback must handle
same-file aliases explicitly. The failures and their raw command identities
remain in [[file:../../../evidence/research/retained/modern-c/header-build/counterexamples.json][counterexample evidence]]. They grant no completion credit. The admitted
packet must come from one complete later campaign, including settled recovery.

** CI repair boundary

The reviewed failure packet separates pre-test tool download, test-fixture
interface drift and cross-job interpreter drift. Pinning producer/consumer
Python to the same patch preserves the sealed executable identity; it does
not replace a missing executable with an unverified fallback. The formal-tool
archive cache is keyed by the pinned SHA, rechecked on reuse and again before
publication; the existing JAR digest and 15-second cold-download limit remain.
A cold download can still fail within that unchanged limit. The stress
inventory control uses the existing task fixture and retains every assertion.
Actual remote conclusions remain separate from local contract checks.
