** Why this replaces a responsibility

The old Autoconf entry and two Make variables each restated the forty ordered
paths already present in =include/gambit.h.in=. Equality checks detected drift
but left four maintained lists. The new Make target derives its ordered
render inputs, prerequisites and =RCFILES/DISTFILES= from that original manifest.
Configure registers a standard header command that calls the existing target.
No second manifest, executor, profile, environment variable or public namespace
is introduced. Standard =MAKE= and =AWK= retain their normal tool meanings.

=config.status --file= remains the substitution service. Make renders to a
target-local temporary, compares bytes and atomically publishes only changed
content. It issues =stamp-gambit= after success. That checked-input stamp is
distinct from the public header's content timestamp: an unchanged-content
input touch must not cause perpetual rerendering. Missing output still causes
reconstruction. Invalid/duplicate manifests, missing fragments and failed
substitution cannot advance completion or replace a valid output.

The non-Git =stamp= target also compares its empty output before publication.
Repeatedly rewriting that unrelated input previously rebuilt =_kernel.o= and
relinked consumers even on a no-change core build. Official target names,
phase structure, preprocessor semantics and installed header shape remain.

** Native acceptance and custody

Use the existing =modern-c-frame-contract= workspace and the existing Bazel
Darwin GCC/C23 profile. The public [[file:../../../evidence/research/retained/modern-c/header-build/native.json][native packet]] records exact inputs, tools,
commands, matched controls, exit/quiescence, file identities and measured work.
The runner is the existing =ExecutionContext= and workspace lease. No second
runtime source copy is needed. Temporary generation protection belongs to the
same task and is reclaimed only after exact recovery and child quiescence.

The first published companion's local stress-inventory test used a working
lease-admission dependency absent from that commit. Remote CI correctly refused
the fixed suite-pool root. Its runtime Recipe consumers also exposed a separate
coupling: already-owned =fixtures/.../run/= observations were rejected because
the producer expected a directory literally called =runs=. Neither failure is
a scheduler or Scheme assertion failure. The earlier local success is not an
exact-head closure of these consumers; keep that limitation with its evidence.

[[file:models/sysml/suite-pool-custody.sysml][The custody model]] replaces label-based routing with the existing
=task_output= ownership decision and connects the producer to the exact
=fixture_root= lease admission. It grants no general build-directory access.
Workers still share one fixed pool and the existing exclusive, identity-checked
lease; a sibling task, a nested worker root or an unrelated directory stays
outside that admission. Historical fixture data already tracked in Git is read
from its repository location instead of a private cache path.

Validation uses the same fixed audit source view: every Python implementation
and test comes from one Git tree plus the declared source delta. Required
required immutable data inputs are selected from that Git tree; only declared
vendor source inputs are projected, with an isolated fixture Git reader sharing
immutable objects. The real submodule index is untouched. This view is a framework source fixture, not a cloned
native runtime, new executor or cache generation. Standard unittest and the
existing isolated task fixture exercise all related modules, both observation
layouts, actual exclusive leases and refusal controls. Imported dirty Python
dependencies cannot silently become the tested implementation again.

The existing =review_validation.run_suite= produces the full input-bound
receipt. The whole caller population includes Recipe deadlines, early completion,
observation payloads, source preservation and unknown-child refusal. Pure
execute stubs explicitly declare their synthetic completed lifecycle through
one shared test helper; they never qualify native process evidence. No real
quiescence check or deadline is removed.

The submission index is also an ownership boundary. The observed failed submit
had unchanged staged entries but different index bytes after a Git stat-cache
refresh. Git now supplies proposal identity: stages/blobs/modes, assume/skip
flags, intent-to-add behavior and resolve-undo records. Only stat representation
may change; every proposal change still refuses admission. Physical-byte change
is reported separately, never silently called byte preservation. Controls use
real Git refresh and flag/intent operations, without taking a global index lock
or blocking another thread's work.

The original vendor audit described four continuation restores. The actual
retained program makes one capture, resumes it three times and visits the
successor/GC point four times. This is an accounting correction, not another
native run or additional acceptance credit; the multi-shot control remains valid.
