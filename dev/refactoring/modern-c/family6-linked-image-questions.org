* 1. Can natural Scheme make caller_chain return false?

No valid example is established. Under the explicit premises that the current
logical stop is in the admitted half, every decoded frame is valid and advances
within that stop, this walk cannot reach the second-section pin. The linked
compare at =0x10002afe0= takes its equal branch at =0x10002afe4= to
=0x10002b1bc= and returns true. The pin increment is at =0x10002b030=,
on a later iteration that requires leaving the already-held physical half.
The half bounds and positive frame extents also put the number of valid frames
below the 100000-step guard; the Lean arithmetic states that conditional fact.

Returning false and crossing a segment are different questions. The function
can return false for bad inputs, failed source resolution, decoder rejection,
an invalid extent, or the guard. None of these is by itself a legitimate
cross-break Scheme producer. The direct false branch at =0x100064af4= does
reach the =___rest_extend_interval= call at =0x100064ca4=. It does not prove
that a valid natural Scheme program supplies that false result.

This is a conditional negative result, not a whole-language unreachability
proof. Mixed producer descriptors, another legitimate frame kind, or a
previously unmodeled incoming state would need a real producer and its first
failed decoder contract. Do not invent an invalid descriptor, overwrite a
break, or equate more recursion with a successor transition.

For checklist 7 the current bounded prefix is insufficient. For checklist 9,
the boolean also conflates source-validation refusal with destination refill
selection. Grok's mechanism design should distinguish valid-prefix completion,
legitimate successor consumption, invalid-source refusal and capacity shortage.
An allocation fallback must not turn a source-validation failure into proof
of custody. Functional changes belong to Grok and a newly bound image.

* 2. Can post-GC soft room be nine?

The linked arithmetic does not rule it out. Repeated observations of
=9 -> 4968= do not prove that every collection enlarges the published limit.
The reviewed =prepare_mem_pstate= cut publishes the minimum of a global heap
quota Q and physical hard-tail room after the 9220-word reserve:

#+begin_example
soft_room = min(Q, max(R - 9220, 0))
R = (hard_heap_limit - current_hp) / word_size
#+end_example

The =___heap_limit= cut tests physical tail against 9219 at
=0x100032ec4..0x100032ed0=; it does not require a ten-word rest reservation
above the reserve. In particular, R=9229 is above that refill threshold.
The optional refill in =prepare_mem_pstate= also does not replace this tail
merely because only nine soft words remain. With Q>=9, and an otherwise
eligible admitted current interval, the final publication can equal nine.
This condition also requires that the intervening service retain that interval:
a released-stack-section reuse or another selection can replace the tail.
If a global threshold requires another GC, its final publication must be
examined separately; a small pre-GC quota is not a retained post-GC witness.

QNT and Lean check the conditional numerical state R=9229, Q>=9. They do not
construct a collector copy census or a natural Scheme workload producing it.
The old fresh-section inequality has a different premise: an empty exclusive
half has 56316 soft words. A restored occupied tail need not be that half.

The mathematical producer question remains unresolved. It is not the active

* 3. Is the parent retained outside context+8?

Yes, as a numeric address in the handler's C stack. The actual first-GC cuts
are:

| Rest handler | Save parent to caller [sp+0xd0] | Call GC | Return PC | Overwrite slot with current context fp |
|-
| Ordinary | 0x100064b14 | 0x100064b5c | 0x100064b60 | 0x100064b78 |
| Keyword | 0x100065a38 | 0x100065a80 | 0x100065a84 | 0x100065a9c |

The complete caller byte intervals have no intervening overwrite of this slot
and no caller-SP change. This liveness claim is conditional on the normal
AArch64 call ABI and no mutation through an escaped caller-stack alias; the
adapter does not claim a whole-program alias proof. The counter-only
=___rest_note_before_collect= does not create an fp receipt, but that fact
does not imply that the enclosing handler discarded its local fp slot.

The linked GC wrapper at =0x100017320= saves 48 bytes on its own C stack and
restores them at =0x100017340=, before its return at =0x10001734c=.
At the latter normal pre-return window, SP is again the caller's SP. Bind the
actual return address to the relevant ordinary/keyword call before interpreting
=[sp+0xd0]=. Before that restoration, use the caller frame/SP relation rather
than applying the same offset to an arbitrary collector frame.

This supplies an existing observation window without recompiling the image.
A future read-only debugger capture must bind image SHA, actual load slide,
actor, call occurrence/GC round, caller SP and return PC. Capture old numeric
parent before overwrite, current repaired context fp, and independently live
activation/attempt/epoch while each is valid. Existing compiled slot/epoch
locations still require their own byte-bound field correspondence.
Do not dereference the old address after source retirement, call inferior
functions to obtain it, or treat a C stack spill as a GC root/source pin.
Do not transfer the first-GC slot interpretation automatically to a second GC.

Will callbacks and process-body entry are later observation phases. Their
absence of the old owner does not disprove this earlier window. Conversely,
the structural window alone does not establish moving collection, repaired
aliases, backing, unique delivery or checklist 8 acceptance.
