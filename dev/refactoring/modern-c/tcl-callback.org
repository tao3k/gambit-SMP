** Complete responsibility and actual source consumers

The original scheme_call_cmd reads a Scheme vector from ClientData before calling
its generated Scheme entry. SFUN conversion of strings and marker construction
can collect before the Scheme body consumes that value. Command deletion invokes
scheme_delete_cmd, which releases the still vector and Tcl's RC owner. Command
existence and in-flight callback ownership must therefore be represented separately.

The callback now adds an existing RC owner before reading any Scheme payload.
It passes the stable native RC identity into the changed private tcltk_call ABI.
The real c-define converts that pointer and the existing string list, builds its
marker and only then reads the GC-updated vector through the existing data_rc API.
The normal C return releases exactly that callback's RC owner. Tcl deletion releases
only the command's owner; outer and inner callbacks retain independent owners.
The Scheme name and Tcl result/string ownership remain; no parallel namespace,
root table, API, runtime field or execution framework is introduced.

The existing optional test-tcl-command compiles the real production header and a
source-equal copy of the production Scheme entry, through the actual GSC generator.
A narrow C entry adapter forces GC before entering that generated converter. The
callback body forces GC again, recursively invokes the command, or deletes it
from the inner/outer callback. The original construction suite still runs first.
The existing process replay/shrink driver is reused; no additional test SCM exists.
The old header callback is retained exactly except symbol renaming and a typed
probe entry. The probe reads the actual RC refcount; the same old function first passes with an
externally supplied callback owner, then fails without it. It observes absent
callback ownership before any destructive
GC/delete; it is not an assertion that an old generated ABI survived forced GC.

** Conditional ownership argument and memory order

Let C be1 while Tcl owns the registered command, A the number of active pinned
callbacks, and R the RC count contributed by these participants. R=C+A. Valid
owner-thread Tcl dispatch provides a live initial C before the first pin. Each
callback increments R before allocation or reentry, nested deletion decrements C,
and each normal callback return decrements A. R cannot reach zero while A>0.
The existing RC mutex supplies acquire/release around count/unlink operations;
no new atomics are needed for this synchronous owner-thread boundary. The RC cell
stays in its existing scan domain; moving collection updates its vector/procedure
edges. The raw native identity has no moving Scheme address embedded in it.

The command constructor is the only admitted writer of its RC payload: proc first,
then the owned still vector before Tcl publication. Callback code does not rebind
that cell. Arbitrary Tcl_GetCommandInfo mutation, cross-thread/VM invocation,
interpreter destruction or global cleanup is outside this source/lifetime premise.
The existing RC addref overflow path is contract failure; it grants no phantom pin.

Counterexamples: releasing Tcl's sole owner during an unpinned callback can retire
the record before outer return. Pinning only after reading the payload preserves
a stale address across earlier conversions. Passing a raw SCMOBJ while retaining
only the native record does not force generated C locals to reload after GC.
A count inferred only from command existence fails nested deletion. A normal-return
pin cannot prove arbitrary continuation/exception escape through Tcl cleans up.
That last case is explicitly open; it must not be presented as full CFFI closure.

** Platform evidence and exclusions

The fixed [[https://github.com/tcltk/tcl/blob/core-9-0-3/generic/tclBasic.c][Tcl source]] shows InvokeStringCommand dispatching proc/clientData
and Tcl_DeleteCommandFromToken invoking deleteProc during command deletion.
This explains why an application's active callback needs its own lifetime owner.
The actual provider's version/header/library hashes are recorded separately;
release-tag source is not claimed byte-equivalent to that binary.

Only valid interpreter-owner calls returning normally are admitted. Arbitrary
Scheme exceptions or multi-shot continuations escaping across Tcl, foreign thread
cancellation, physical allocation failure, interpreter/global teardown and the
dynamic C-closure trampoline are not qualified. Gambit's multi-shot continuation
semantics are unchanged; this cut does not restrict them to one-shot operation.
Existing QNT owns competing root/task histories and Lean distinct conditional laws;
neither is duplicated, rerun, or claimed to prove this concrete C-to-Scheme adapter.

** Accounted space and calibration boundary

The pointer converter allocates a foreign wrapper of3 payload words plus6 still
words:72 accounted bytes at the recorded8-byte word profile, excluding allocator
and alignment overhead. The generated END_SFUN_POINTER conversion releases its
SCMOBJ reference on normal return; physical reclamation waits for still sweep.
Thus unswept wrappers as well as active entries contribute to peak space. Deleting
a command during a callback additionally retains its existing7-word vector and
reachable Scheme graph until callback release; this is conditional retention, not
a fixed whole-round RSS estimate. No new native allocation/root table is added.

The first exploratory negative probe returned a fixed failure and is rejected as
independent evidence. Its receipt is retained as superseded; only the calibrated
count-observing probe, including its positive control, can satisfy publication.
A generated-code inspection initially expected an expanded C converter name;
actual GSC output uses BEGIN/END_SFUN macros. Source refinement now follows those
macros to the actual converter and normal-return release, with the full binding
compiled independently. No source/runtime failure was hidden by that inspection
correction, and no resource limit changed.

If C control never returns, this leaf supplies no independent recovery receipt for
the extra RC reference. It can retain the record/object graph and impede owner
domain teardown. That cost is explicit and remains an activation/exception-boundary
obligation; a passing normal-return history is not evidence that unknown outcomes
can release it. No result claims full callback or CFFI lifetime closure.
