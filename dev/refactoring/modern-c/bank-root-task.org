** Task, lifetime and conditional refinement :proof:boundary:

1. A fresh unexposed C record is initialized with the admitted nonzero RC round
   epoch minus1. Shared confined publication installs the BANK origin and one
   lease; its returned epoch must equal that actual GC epoch.
2. Shared claim checks kind/executor/key/state. Source-specific admission also
   checks active VM-slot identity. Only the same current participant scans it.
3. The actual scanner reads/updates the four disjoint root ranges, with the
   existing visitor bodies. Only normal return sets SCANNED; shared finish
   releases once, and known duplicate completion is idempotent.
4. DONE ends the scanner's native borrow, not the source context's lifetime,
   captured-frame ownership or the enclosing round. Existing storage/roster
   holds continue through descendant/weak/copy/cleanup work and restoration.

The task is never queued or exported from its C invocation. Init is only a
constructor for fresh storage, not recovery of unknown scanning. A stale raw
pointer needs lifetime protection before metadata can be read. Unknown worker
death, join isolation and source migration are separate obligations.

Counterexamples: flattening the entire context scans code/stack/heap pointers;
capturing bank values into an unupdated copy loses relocation; reusing another
context's bank violates source ownership; treating bank DONE as stack/round
completion loses pending descendants; deduplicating roots by shared object
identity drops a second cell holding the same multi-shot continuation. None
is an admitted interpretation of this cut.

replay and deletion shrinker to BANK. The same executable is reused for an
additional p2 bank payload run through the existing Make target. No new SCM,

For an immediate-only bank trace, the fresh p1 child first snapshots all C
arguments, then sets only the four bank ranges to FAL. Its fp/hp/pc are not

allocation, callback or return. VM/BANK observation phase means published
origin, not a synthetic stopped-writers certificate. Destruction of this child
is test isolation, not an unknown-owner recovery protocol.

Separate real p2 checks pin the producer to processor0 and1 in turn, store a
fresh pair/vector in documented processor unused-field15, request ordinary GC
and verify that the actual root cell is updated and contents survive. Only
fixture-owned storage is cleared by dynamic-wind. Other bank ranges are
covered by the unchanged visitors and existing bootstrap/frame/map/GSI consumers;
one payload control is not a universal arbitrary-cell proof.

Per family, an explicitly labeled stale-finish invocation mutation must shrink

SCANNED/lease1 retained. This is deletion1-minimal, not globally minimal or a
discovered production defect. Source/executor/key rejections are observable.
