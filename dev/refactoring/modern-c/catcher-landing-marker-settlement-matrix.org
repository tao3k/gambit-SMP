** Role

| key | identity | retirement | boundary |
|---+---+---+---|
| StablePreparation | Private progress ledger outside the abandoned C frames | Known rollback returns only private extra leases; original custody persists | Unknown preparation is not permission to free or repeat |
| CatcherLandingReceipt | OperationId, NativeThreadIncarnation, ContextId, TargetFrameId, marker identity and exit kind | Published after exact target restoration/checks, retained for replay | Intermediate catcher and current catcher pointer are not equivalent identities |
| MarkerReleaseTicket | Marker incarnation plus one native-owned reference and committed settlement | Effect and receipt occur inside one qualified NoAbandon/exclusive interval | Ordinary refcount decrement is not idempotent and current code has no durable ticket |
| MutableRootSlot | Stable SlotKey with GC-rewritten SCMOBJ, source/context transfer and borrow lease | Reader/admission grace after final semantic owner exits | C23 visibility does not substitute for root enumeration or slot rewriting |
| OpaqueReturnTokenCandidate | Preissued native return handle separated from Scheme procedure roots | Expired native return traps; storage/descriptor/replay leases retire independently | Requires native-entry ABI and reflection/serialization design; not a drop-in Scheme allocator substitution |
| MarkerOwnerUseClosure | MarkerOwnerId plus final-use generation; distinct from each invocation FrameId | Release only after invocation exit and all future owner uses are closed | Current bounded model admits outer ___run only; outer SFUN retry lifecycle needs additional states and native qualification |

** Gain

| key | avoided | added | condition |
|---+---+---+---|
| G1 | One target-classified landing record can replace inferred completion at arbitrary catch sites | Frame/thread/context/operation identity checks and stable receipt storage | Current END_TRY is not a signer; only exact target UNWIND route is modeled as accepted return |
| G2 | Reply replay performs zero additional native reference decrements after commit | Query lookup, operation retention and generation protection | Uncommitted physical effect remains inside an unproven native NoAbandon interval; no crash recovery claim |
| G3 | Two-entry model performs exactly two native marker-reference drops in a completed path | Exclusive writer/collector participation and two stable commit records | Does not reduce the baseline two drops; establishes conditional correctness, not speedup |
| G4 | Opaque return-token candidate could retire one logical marker-vector construction and one native count release per admitted entry | Stable token slot, RootBundle, generation lookup and FrameSpec/reflection/serialization migration | E marker-owning entries: net object constructors E-(R+S), native count releases E-D only if replacement qualifies; R views/S boxes/D new owned releases may erase savings; native paths retired zero |
| G5 | Slot identity survives relocation; stale native cached values need not be trusted | Mutable registry/context cells, scanner freeze and fresh borrow reload | Partial cell updates cannot be exposed to a running borrower or Scheme context |
| G6 | One root/code/receipt ledger could replace separate implicit ownership reconstruction | Metadata and native pin occupancy plus reader-grace work | Savings require deletion of old responsibilities, not a second ledger layered over them |
| G7 | C23 expresses both retained-marker and opaque-token candidates | Same GC, source, landing and code-lifetime obligations in Zig | No Zig-specific net return established; no per-resumption thread saving claimed |
