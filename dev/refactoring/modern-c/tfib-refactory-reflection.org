* Current mechanism composition work

The [[file:family6-linked-image-questions.org][three linked-image questions]] expose three design errors to avoid:
conflating source refusal with allocation-path selection, treating a fresh
section as every restored heap tail, and observing a parent frame only after
the handler has overwritten its saved address. Model transitions need actual
image edges and observation lifetimes. Checklist 6 refusal and 8 delivery use
different invocations on the same qualified image.

The [[file:family6-mechanism-assurance.org][Family 6 mechanism assurance experiment]] applies the existing models
to checklist 6-7. It adds public refusal/reentry and logical source-extent
contracts, validates actual C demand functions, and keeps source refinement
and same-image native witnesses separate. Feeley's polling and continuation
papers motivate explicit compiler/runtime and continuation interfaces; the
LLM amplification workflow is our engineering application.

* Questions the architecture must answer
:PROPERTIES:
:CUSTOM_ID: tfib-review
:END:

** Can we remove the failure mechanism rather than guard its symptom?

Yes, conditionally. Replace physical address or carrier identity as
authority. The execution context publishes the actual descriptor and
complete roots at a mapped point. A source lease carries VM incarnation,
generation, physical section/half and a logical extent. Capture, census,
copy and undo acquire that authority before their first read, including the
break link and its separately authorized successor. Freeze arbitrates
reflective writes. RootTask owns exact updates, and the worker owns copy
and Tail debt until publication. The host acquires the repaired view,
reloads its live state and acquires a continuous reservation covering the
last word before the first resumed store. An unknown forwarding or ACK
retains the same attempt and source until query or drain resolves it.

This makes a foreign or stale interval inadmissible even when its address
is numerically in bounds. A missing descriptor slot, a cursor inherited
across break, a grant consumed before reload, or one-short physical room
must fail independently. A later valid write or eventual process exit
cannot repair an invalid first access. Keep the existing raw-suffix,
generated rest/keyword-rest and allocation-size controls in the same
product. Distinguish absence of a fault from the oracle observing the
first read and complete write. This excludes a class of corruption once
all consumers are covered. It does not attribute either retained crash to
an exact first writer.

** What must change at the stack interval entry?
:PROPERTIES:
:CUSTOM_ID: stack-interval-mechanism-review
:END:

The stack counterexample exposes two decisions hidden in a Boolean
capacity result. The runtime must first establish that this activation may
use the current section and half. It can then decide whether that live
interval has enough space. Selecting the half from =fp= or falling back to
a lower-bound comparison lets the cursor supply the authority that is
supposed to constrain it. Tightening that comparison can fix one
counterexample while a retry or another writer still uses the old rule.
[[file:allocation-intervals.org::*Family 6 stack interval review][Stack interval proof and evidence route]]

Use the allocator's existing ownership state for this decision. An owned
interval with enough room admits the complete write group. An owned but
short interval can use the existing limit service if its entry already
has backed spill space and a scannable old frame. An invalid interval
must stop before spill or collection. On retry, resolve ownership and
check extent against the actual repaired view again. A successful
collection by itself supplies neither a grant nor enough room.

The check must dominate the first real store, including dirty unboxed
spills emitted before the demand call. Either prove those spills already
backed by the old view or move admission earlier. Resolve once per
uninterrupted write group under existing execution custody. If a poll,
collection or ownership transfer intervenes, acquire a fresh view. Retire
address-derived admission once the actual writers and limit entries have
been mapped. A complete source mapping can also show that a particular
invalid state is unreachable without adding another runtime check.
[[file:../../../vendor/gambit/gsc/_t-c-2.scm::612][Write group emission]]
[[file:../../../vendor/gambit/lib/_mem/allocation-limits.inc::403][Current stack capacity predicate]]

Compare the old and replacement paths on exact fit, one word short, an
inactive half and a stale interval after refill. Check the first spill,
root custody, service entry and first application write, not just the
eventual return. A failure after an invalid spill is detection too late.
A fatal refusal of a valid short interval is a regression. Require that
the valid short case can collect, reload and enter the application once.
The source mapping establishes coverage. These controls on the qualified
generated image test that mapping at the actual boundary. Both are
required to claim removal of the failure mechanism. The cause of the
historical TFIB censor and the whole-family result remain separate.

** Does safe restoration imply progress?

No. A wait has its own identity and roots. Service obtains a distinct
activation and commits result, exception or authorized abandonment before
the waiter may consume it. Wake grants a recheck; it need not imply
completion. A legal requeue retains the same wait. After an unknown
return or exit, the original ticket stays queryable until terminal outcome
and last-reader drain. User continuation replay must not repeat internal
request settlement. Retire a transient service frame only when no
register, resume closure, RC slot, published task or user continuation
still reaches it. Unknown custody can be safe while progress is blocked.

Compare child completions and ordered top-level joins with runnable
owners, wait dependency and request generations, phase and worker progress,
and actual poll/park/wake transitions. A closed wait cycle requires evidence
that every edge and its enabled producer were observed and that no outside
producer can break it. A missed wake requires a committed result, a still
eligible parked waiter and a missing required notification or runnable
handoff on the same identity. Work counters advancing
with no verified join progression only establish local activity. Report
partial observation as unresolved. Expected progress is conditional on
fair dispatch, finite admitted work, eventual exit or resolution of
external blockers, and capacity for work at the unchanged budget.

** Where does Feeley's design let us remove work?

Feeley's balanced polling separates the cost of checking from servicing an
interrupt and controls how far execution can run before noticing it. Apply
that idea by keeping an explicitly bounded poll corridor while making a
plain unary tail entry cheap. Hold unexposed operands in mapped root slots
and give each logically distinct lexical location a stable identity at
exposure. Before a poll handler, reflection, debugger/stepper, escaping
closure, or continuation makes the location observable, materialize its
ordinary environment using the pre-existing slow semantics. Preserve two
independently observable locations across GC and repeated restoration.
Fallback before the first observable effect when guards change; after a
committed effect resume at its successor. A Scheme instruction bound is
separate from elapsed interrupt latency, which also depends on scheduling,
native calls, and collector synchronization.
[[https://www.cs.tufts.edu/comp/150FP/archive/marc-feeley/polling.pdf][Feeley, Polling Efficiently on Stock Hardware]]
[[https://www.schemeworkshop.org/2000/][Feeley, Scheme/C continuation interoperability, proceedings entry]]
[[file:../../../vendor/gambit/lib/_eval.scm::4255][Ordinary unary entry and heap check]]
[[file:tfib-interpreter-candidate.org::*Asynchronous observation of unary RTE identity][Two real lexical locations and alias mutant]]

The allocation result makes this the primary /throughput hypothesis/ for
the interpreted hot path. A faster subtraction, fewer polls, or additional
collector workers alone do not remove eager unary environments. A bounded
probe must measure admissions, ordinary fallbacks, exposures, materialized
environments, and meaningful completed work. For a matched workload,
observed eliminated RTEs times 32 bytes gives the corresponding cumulative
physical payload avoided at the measured 64-bit layout. At 100% elimination
the source-count projection is about 1.894 TB per topology. It is a
conditional cumulative upper bound for those unary records only, neither
resident memory nor a speedup prediction. Compare saved allocation,
copying and scanning against guards, polling, exact-root maintenance,
deoptimization, synchronization and peak committed memory.

** What should we learn from the other systems?

- OCaml's experiment shows the value of designing compiler polling, native
  participation and collector synchronization together and comparing
  collector alternatives empirically. Gambit should separately measure
  last safe-point arrival, collector work and resume publication. Changing
  collection generations is an independent optimization hypothesis and is
  unnecessary for the TFIB authority argument.
  [[https://kcsrk.info/papers/retro-parallel_icfp_20.pdf][Retrofitting Parallelism onto OCaml]]
- The Scheme continuation literature gives a useful bound to seek: retain
  and copy only the stack segment actually required by capture or resume,
  with exact roots and valid aliases. Gambit must qualify this against its
  own multiple restoration, reflection, dynamic-wind and native
  boundaries. Internal one-shot settlement never changes Scheme's
  first-class continuation contract.
  [[https://doi.org/10.1145/93542.93554][Hieb, Dybvig and Bruggeman, Representing Control]]
  [[file:../../architecture/runtime/control/continuation-segments.org][Pinned Chez and Guile source correspondence]]
- OTP's process-signal queue has explicit enqueue and receiver fetch
  endpoints. Use that separation to audit publication and receiver
  ownership in Gambit. A fetch is not a terminal join result; Gambit also
  needs frozen roots for shared heap references and preserves Scheme
  continuation identity.
  [[file:../../../vendor/erlang-otp/erts/emulator/beam/erl_proc_sig_queue.c::826][OTP enqueue and receiver fetch implementation]]
- Work-stealing theory suggests measuring total work and the dependency
  critical path separately. Its fully strict task theorem does not give
  Gambit a bound for interpreter, interrupt, shared-heap GC and arbitrary
  control effects. TFIB's syntactic fork/join tree is a starting point for
  attribution, not a proof that every runtime edge is a fork/join edge.
  [[https://www.cs.cornell.edu/courses/cs612/2006sp/papers/blumofe94.pdf][Blumofe and Leiserson, Scheduling Multithreaded Computations by Work Stealing]]
