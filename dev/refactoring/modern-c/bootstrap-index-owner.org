* Source refinement and causal question :source:gc:

The base revision contains all the failing primitive declarations in
~gsc/_prims.scm~. ~make-prim-proc-table~ in ~gsc/_back.scm~ inserts canonical
string keys with Scheme ~make-table~; ~targ-get-prim-info~ in ~gsc/_t-c-1.scm~
retrieves them. The startup call in ~gsc/_t-c-2.scm~ happens before ~-v~ or ~-e~
can be processed. A missing-primitive error is therefore not proof that its
declaration or the compiler frontend is missing.

The ownership chain is:

1. ~lib/_system.scm~: ~checks-done~ chooses the semantic test/hash functions;
   ~table-access~ uses those functions to choose physical slots.
2. ~lib/_mem/object-scanning.inc~ repairs key/value references of GC tables.
3. ~lib/_mem/wills.inc~ defaults multithreaded VMs to eager native rehash,
   including when only one processor executes Scheme.
4. ~lib/_mem/weak-tables.inc~ marks movable keys as address-moved and invokes
   ~gc_hash_table_rehash_in_situ~. That routine uses the C address-hash algorithm;
   the old metadata does not identify a Scheme-owned index.
5. Subsequent Scheme lookup still uses the recorded semantic hash. Physical
   presence, key equality and equal current hashes do not imply that the key
   lies on that algorithm's probe chain.

The eager-policy selection and worst-case key-moved path are already present
in ~7c490c3a:lib/mem.c~, before the frame and source-organization commits. This
is a source-level localization, not a claim that the older commit was executed
under the current profile or that every older bootstrap necessarily failed.

* Candidate responsibility boundary :design:

[[file:models/sysml/hash-index-ownership.sysml][The existing SysML component]] owns the design. The explicit
[[file:../../../evidence/refactoring/modern-c/index-owner-submission-source.json][four production-source changes]] refines ~creation~, ~repair~ and ~scheme~:

- C and Scheme define the same persistent ~SCHEME_INDEX~ flag in the existing
  flags word; the value 128 is bit 7, after the seven existing flag bits.
- ~checks-done~ publishes that owner when ~test-fn~ selects Scheme access.
- GC repairs references and weak entries, then clears only address-movement
  debt for that owner. Existing ~NEED_REHASH~ from reconstruction survives.
- Native identity indexes retain the existing eager route in this candidate.
  There is no GSC-name exception, heap increase, lazy-mode switch, Scheme
  callback in GC or general replacement of native traversal ownership.

The working research tree already contains the broader index-ownership design.
This candidate isolates a four-path projection against committed source so its
effect is independently testable. It does not import the mixed working tree or
the patch-repair series into branch acceptance.
