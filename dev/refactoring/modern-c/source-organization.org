* Why these changes form one deliverable

The pure organization tree cannot compile its generated kernel because its
parent role migration omitted a real root producer/consumer family. Combining
only the six macro accessors completes that existing ownership decision; adding
back PSTATE.saved, a fallback bank or an alias would recreate the retired
responsibility. The new frame-consumer checks exercise all six macros against
a bank updated to represent relocation and require roots to clear after restore.
That unit is deterministic C refinement, not a concurrent collector proof.
Actual rebuilt map/continuation/GC execution remains a separate required test.

The checked-in configure is also a real consumer. Its two default/explicit
header maps are updated from the same41-fragment list while preserving the
shipped Autoconf2.69 shell logic. The existing Bazel profile separately uses its
configured generator. Testing the mapping does not claim fresh qualification of
all legacy configure probes or upgrade the generator in this commit.
