** Independent receipt and TFIB attribution

After the implementation owner publishes the receipt, audit the sequence
=source lease → first read → mapped roots → GC → acquired reload →
first write or refusal → terminal delivery=. Each event includes the
attempt, epoch, emitted label, and independently observed address/slot.
For the negative run, distinguish argument pops from later mapped cleanup.
For a lost reply preserve the same settlement identity.

The same GSI must then emit real completion observations from the join
consumer, with cumulative distinct child joins and ordered top-level
joins, runnable/parked dependency, terminal wake/delivery and GC phase
progress, plus ordinary unary RTE entries, allocations and wall/CPU
intervals. Counters or histograms must declare coverage and observer
overhead. Distinguish the following outcomes.

| Observation | Independent audit classification |
|-
| An unauthorized first load/store, changed one-short sentinel, stranded pin or duplicate delivery | Correctness failure at the first violated cut. |
| A committed result strands its eligible parked consumer, or a captured closed wait dependency has no enabled outside producer | Scheduling/settlement obstruction, scoped to the observed identity. |
| Distinct joins advance and the matched critical path is dominated by interpreter/GC work per completed join | Throughput evidence. Attribute interpreter allocation separately from collector and waits. |
| Unary events alone, a stationary sampled join count, all shards censored, or incomplete traces | Unresolved. These cannot establish either a wait cycle or an interpreter bottleneck. |

Read the [[file:../../../evidence/research/retained/modern-c/stress-gsi/dev-tfib-a-construction-audit.json][source-bound audit packet]]
for the current candidate snapshot and prior campaign. The retained campaign

* B. Give join one settlement owner
:PROPERTIES:
:CUSTOM_ID: tfib-construction-join
:END:

1. Trace =##thread-join-wait!= through =##thread-park!= and
   =##thread-join-register!= to the emitted park, restart and result read.
   A logical wait has one identity, exact roots and an owner independent
   of its service activation. Legal wake/recheck/requeue keeps the same
   wait. Give generated restart code a static entry only for proven
   nonescaping internal waits. Materialize the general continuation on
   exposure with its roots installed before the previous root is released.
2. Bind =##thread-intr-service!= and =##thread-end-locked!= to the actual
   request claim and result/exception publication. Preserve existing
   result, timeout, interruption and exception arbitration. Release-publish
   the winning outcome before terminal notification. The waiter acquires
   it and claims delivery once. Resuming a user continuation can execute
   user code again while internal settlement remains unique. An unknown
   outcome retains queryable custody; GC and exit can retire the service
   frame only after the last root, reader and authorized writer drain.
3. Return distinct trace events for wake, requeue, terminal commit,
   delivery, last use and release. Observe the actual scheduler edge and
   emitted frames. An unchanged counter or elapsed timeout alone cannot
   prove a wait cycle or a missed wake.

* C. Defer unary RTE materialization without weakening polls
:PROPERTIES:
:CUSTOM_ID: tfib-construction-rte
:END:

1. Start at =##cprc-prc-req1=. Map the ordinary unary call, lexical reads,
   entry-hook dispatch and generated poll/return descriptor. Keep the
   direct entry and revalidation criteria explicit. Store live unexposed
   operands in mapped roots while avoiding the eager =macro-make-rte=
   allocation. Retain the stepper, rebound dispatch, and unsupported
   shapes on the general path. Keep a bounded poll corridor.
2. Before an interrupt handler or another consumer can observe the frame,
   materialize its ordinary environment with the original lexical
   identities, source/stepper metadata and live roots. Materialization can
   collect. Preserve the previous root authority until the installed
   environment is acknowledged. Distinct retained locations must stay
   distinct across moving GC and two continuation invocations. Guard
   failure before an observable effect uses the ordinary entry; after an
   effect commits, resume at its successor without repeating the effect.
   [[file:../../../vendor/gambit/lib/_eval.scm::4223][Unary interpreter path]]

* Benefit and admission
:PROPERTIES:
:CUSTOM_ID: tfib-construction-benefit
:END:

| Chain | Structural threshold on the admitted path | Matched cost and stop condition |
|-
| A | Every first read and complete write is authorized. Refused attempts have zero unapproved accesses and no duplicate delivery. | Correctness can close independently of speed. Report added pins, grants, stalls and peak reserved bytes. Claim fewer scans or reservations only when the paired counts show the decrease. |
| B | One terminal settlement and one delivery per completed logical wait. Admitted static retries create no transient capture or resume closure. | Measure captures, closures, retained/scanned words and peak live wait roots per completed join, plus queue and ACK cost. If old work has moved into ticket bookkeeping, count the new work in full. |
| C | Zero eager RTE allocations on qualified unexposed entries. Every exposure receives the ordinary environment with distinct lexical locations. | Measure eliminated and materialized RTEs, allocated bytes per completed join, GC phase cost, p1/p2 wall and CPU, and peak memory. At the observed 64-bit layout, each actual eliminated RTE avoids 32 physical payload bytes before replacement costs. An allocation reduction alone earns no speed claim. |

Compare matched producer variants with identical instrumentation for
attribution and uninstrumented runs for elapsed cost. Declare the noise
and memory thresholds before comparison using the existing cost evidence.
If no matched comparison can bound variation, record performance as
unresolved. Assess saved work on completed useful units and wall improvement
outside the measured variation, including added fast-path checks and slow
paths. For RTEs, count materializations on the deferred path and compute
the avoided records from the measured baseline minus all candidate records
for the same useful work. For join, use capture/closure and retained-word
deltas per completed wait and report timed-out attempts separately so
the rate cannot hide censored work. Report peak separately. The
conditional RTE byte projection and historical p1 ceiling are bounds,
not speed measurements.
