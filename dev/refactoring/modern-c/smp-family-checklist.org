** Replace the shared authority

Keep Scheme object sharing and multi-shot continuations within a VM. Make the
execution context the owner of control state, the VM epoch the owner of the
frozen root cohort, and a collector worker the temporary owner of an explicitly
claimed scan task or copy interval. A carrier runs these responsibilities under
a lease. Its identity alone gives no permission to publish, write or reclaim.

1. Close root/reader admission for the epoch. Each pending publisher, frame
   reader, queued weak task and foreign borrower must settle or remain under a
   named owner. A local empty queue or a successful unrelated join cannot settle
   debt. Allow healthy VMs to proceed when unresolved debt is isolated by
   identity and does not intersect their root or physical-space dependencies.
2. Transfer scan tasks and continuous copy/resume grants independently of the
   carrier count. Preserve single copy authority, private work and Tail until
   publication and completion. Reject an insufficient continuous grant before
   forwarding. A late or uncertain result keeps custody until a matching query
   or reconciliation can settle it.
3. Publish a resume grant after restoring the continuation and establishing
   the relevant reader cut. Bind VM incarnation, context, epoch, section/parity,
   writable interval, cursor and poll bound. Before using cached heap state,
   the generated return host must acquire the publication through its actual
   synchronization edge and reload the corresponding cursor. Reserve the full
   first allocation and pre-check batch, including header, alignment and last
   payload field. Retire the old interval after its last authorized user.
4. Separate accepted request, runnable notification and terminal completion.
   The wait frame retains its exact root projection. A service activation
   keeps its own roots through execution, exceptional exit and explicit result
   delivery or abandonment. A user capture can keep service frames reachable.
   Elide per-request closure or capture only on a proven non-escaping path
   with an exact general fallback. Preserve independent multi-shot restoration.

This creates a falsifiable sufficiency argument for the targeted failures:
if every writer has exactly one live grant, reload acquires that grant, and
every old reader blocks conflicting reuse, neither a stale in-range cursor
nor an early section recycle can authorize the first write. If the grant is
too short or an unregistered FFI writer exists, the argument fails even if
the address lies in the semispace. Request progress separately requires a
runnable consumer and a valid wake or terminal-disposition mechanism. A
permanent wake fault can preserve safety while preventing completion.

** What transfers from the literature

- [[https://www.cs.tufts.edu/comp/150FP/archive/marc-feeley/polling.pdf][Feeley, Polling Efficiently on Stock Hardware]]. Preserve compiler placement
  of cheap polls. Use actual poll and return points as the boundary for
  publishing precise root state and reloading a changed allocation grant.
  Poll distance alone cannot bound time spent in blocking native code.
- [[https://arxiv.org/abs/2004.11663][Sivaramakrishnan et al., Retrofitting Parallelism onto OCaml]]. Treat roots,
  foreign entry, allocation and collection as one compatibility problem.
  For Gambit, preserve captured frame aliases and repeated restoration.
  A generational follow-up can skip mature graph scanning only after closing
  every relevant writer and retaining residual edges across epochs.
- [[https://www.usenix.org/conference/jvm-01/presentation/parallel-garbage-collection-shared-memory-multiprocessors][Flood et al., Parallel Garbage Collection for Shared Memory Multiprocessors]].
  Partition roots independently and balance tracing work across workers.
  Gambit's adaptation must account for private frontier, Tail and weak work
  before it closes a phase. Work stealing alone provides no retirement right.

*** Three proof obligations for the implementation owner

1. *Safety.* A frame read consumes a live, immutable source grant keyed by
   VM incarnation, owner, section/parity and logical extent. Admit before
   the first return-address load, then admit each descriptor, saved RETI,
   payload and successor before dereferencing it. Capture and ordinary
   undo fallback must use the same semantics as collector reads. Crossing
   a break requires a separately admitted successor. Keep captured
   continuations multi-shot and preserve exact root identities when
   physical coordinates move. A write independently consumes the current
   destination grant after an acquire/reload. Build the bound from emitted
   writes and checked native allocation entries. A pair before a closure,
   or an in-range address from the previous epoch, must be distinguishable.
2. *Termination and isolation.* Closing external admission must leave
   exactly one accountable custodian for each outstanding root scan,
   forwarded copy, private Tail, queued successor, callback or completion.
   Publish child responsibility before discharging the parent. Reclamation
   requires sealed admission, zero outstanding work and last-reader drain.
   An unknown outcome retains its original token and cannot be replayed
   blindly. Independent VM progress is conditional on no dependency through
   roots, physical intervals, locks or owner-affine cleanup. A quarantined
   launch can be safe while the affected VM lacks a progress guarantee.
3. *Liveness and cost.* Count successful work, not activity at the deadline.
   The request path needs a runnable consumer or a terminal disposition
   under the original watchdog. Compare matched workloads by completed
   requests, copied bytes, scanned slots, barrier wait, pause tails and
   physical peak. To claim net gain, eliminated capture/scan/idle work must
   outweigh publication, fencing, fallback and retained-space costs.
   Shared ownership correctness does not supply a bound on interpreter
   allocation, worker skew or scheduler delay.

*** Record identity and storage lifetime

Use an opaque =VM incarnation / slot / generation= token for a retry.
Resolve it within the existing VM lifecycle admission. Before loading
the activation record, check its generation and acquire a pin under
the slot owner's gate. The slot owner serializes closing admission with
pin acquisition. Closing wins if it precedes the pin. Pinning wins if
it precedes closing and delays destruction until release. Generation
advance rejects an old token even if the physical address recurs.
A lookup outside the owner may inspect control status only. The
execution context remains responsible for accesses to movable values.

The implementation may keep slot metadata in stable storage or
resolve it under a registry gate. In either case it must prove the VM
or registry lifetime before even accessing that metadata. Allocation
and reuse remain bounded by admitted simultaneous waits and unresolved
receipts. If no slot is available, keep the caller's complete root
view and route through a mapped slow or error path. A new slot or
generation cannot manufacture closure for an earlier attempt. A lost
result is queried using its original token. Keep the corresponding
terminal receipt until its consumers settle. A missing receipt is
unknown.

A pin protects native storage only. GC still obtains its root view
through the RC domain and may repair the tagged cells. For several
readers, use a checked count or admit one reader and return an explicit
retry to contenders. Never interpret a refused lookup as proof that a
record was retired. Keep lookup
locks and temporary movable-value copies out of the blocking, GC and
callback intervals. Owner exit closes lookup admission and settles
or transfers roots to VM custody. It does not wait in a cycle for
GC or for a callback that needs the closing owner.

same managed batch that just failed. The successful claim must transfer
roots before release and cross into the tail entry without a safepoint.
If interrupted outside that window, keep the outcome under the same
token for settlement. Replaying the call is unsafe after an unknown
claim or entry outcome.

*** How this advances 6–12

Families 6 and 7 share the authorization semantics. The interpreted
and compiled routes still need independent generated consumers and
their own original workloads. Families 8 and 9 supply registry and
lifecycle dependencies to both stress families. Their native controls
can run independently of a rest throughput fix. Family 10 extends the
same source and root rules to cross-break reads, nested FFI and
multi-shot restore. Family 11 verifies the installed ABI through the
pinned downstream consumer. Family 12 compares complete cohorts after
the correctness gates. The [[smp-refactory-falsifiers][projected
falsification matrix]] gives the workload and retirement rule for each.

For family 6, retain the first invalid read/write, lost root or
duplicate settlement as a correctness failure. If authority checks
hold at censor, retain completed requests and jobs, last phase,
allocation and wait counters. This distinguishes measured slow progress
from a run with missing progress evidence. Classify a proven wait
cycle separately. The historical 188.383-second interrupt2 shard
shows why a shorter TFIB sample alone cannot establish the original
p2-to-p1 deadline. The throughput question needs independent
attribution of interpreter allocation, capture, service and GC
waiting. Compare avoided allocations, copied/scanned words and
barrier wait against added pins, publications and retained bytes.
Record completed work, pause/wall tails and peak. The net cost of this
design is unmeasured.

*** Proof and acceptance ownership

The existing Quint file now separates three storage-lifetime histories
from five wait reentry histories and nine footprint controls. The
storage histories model pin before close, close before pin with reuse,
and the old first-read counterexample. They model one slot and one pin.
A production implementation must refine that abstraction to every
query/cleanup caller and concurrent borrower. The temporal histories
do not own configured frame offsets. The existing frame and slot proof
route owns the representation obligations. In particular, preserve
the independently decoded RETN stride, saved RETI slot, precise root
inventory and physical interval bounds. Keep the C memory-order and
actual generated entry correspondence as explicit source and native
obligations.

*** Older raw suffix provenance and cross-break contract

A half claim answers whether storage is still live. A parked interval
answers where one recorded stack segment ends. Multiple captured
continuations can name different segments in that same half. Neither the
latest parked end nor the receiving context's break identifies the end of
an earlier captured segment.

**** Origin and handoff rules

1. For the non-break paths of =CONTINUATION_CAPTURE= and =THREAD_SAVE=,
   snapshot the previous logical break before installing the new one.
   Publish the raw root with a grant for its original segment. In the
   already-at-break branch, inherit the grant referenced by NEXT. A single
   mutable endpoint in the section claim loses information when a later
   capture splits another segment.
2. Stack overflow has two producers. The short path points NEXT at the
   previous top. The split path points it at the surviving fp after copying
   the prefix. Both park with the previous break. The prefix carries a
   successor to the surviving segment and does not extend that segment.
   The existing stack-limit walk itself reads RA and RETI before parking.
   Its starting authority must come from the current active stack and its
   existing break, never from the grant it is about to publish.
3. A successor is either an interior frame with a strictly advancing
   coordinate in the same grant, a terminal break with a separately
   authorized successor or end marker, or a committed forwarded heap
   frame. Install new root custody before clearing an old publication,
   including THREAD_RESTORE's consume step. THREAD_PARK, continuation graft
   and repeated resume inherit source identity. The destination break is
   a transport slot, not the source boundary.
4. Resolve a raw edge to the VM incarnation, section and half incarnation,
   stable segment identity and exact interval before loading RA. Keep its
   reader permit through saved RETI, descriptor, payload and link use.
   Decode against remaining words. Read the structural NEXT only after
   admitting that slot and validating the terminal break. Resolve the next
   grant before loading its RA. Hold the original reference until the
   successor reference or a committed forwarding result has custody.
5. Use the same admission semantics in active/captured census, GC copy,
   undo fallback and reflection. Census may operate on an admitted
   immutable round view. The mutator helper currently resolves under
   =ALLOC_MEM_LOCK= and holds the section gate. Prove its lock order and
   last-reader behavior. =##continuation-next!= additionally mutates the
   successor RA and needs writer authority. A heap frame uses its own
   typed extent and forwarding/slot contract.
6. A missing grant leaves the producer or root owner responsible. Refuse
   before an unverified raw load or use a separately qualified
   materialization route. After partial copying keep prefix and Tail under
   their owner. A forwarded link can discharge source custody only once
   the target's exact image, initialized prefix and successor are known.

The proposed grant is a logical identity, not an implementation choice
about side tables or frame encoding. Retirement requires a complete
publisher/reader/writer inventory and a bounded storage/reclamation
argument. Old aliases must not resolve after half reuse, and failure to
obtain provenance cannot become a full-half success path.

**** One joint history from capture to retirement

Use a stable segment key comprising VM incarnation, half incarnation and
segment generation. Each root carries the key and an entry coordinate.
The immutable record supplies the original logical end and the terminal
edge identity. Narrowing the entry retains the end. Replacing an edge
advances its mutation revision, which is separate from the segment
generation and from a physical address.

holding a gate that the successor may need. Retain a pinned source or an
explicit transfer record across that acquisition. A delayed query must
validate the same generation again before using the cached result.

one unresolved receipt to each live copy attempt. Multiple aliases share
the record. An admission limit, allocation failure or unavailable receipt
slot preserves custody or uses a separately qualified fallback. Reclaim a
receipt only after query admission closes and outstanding readers drain,
or after installing an independently valid terminal result for them.
This is a proposed contract, not a selected C storage layout.

**** Configured publisher geometry control

A focused C fixture constructs one stack half and executes the configured
=___CONTINUATION_CAPTURE= and =___THREAD_SAVE= macros. Their definitions
match the current header template. Capture keeps the first raw coordinate
and leaves a continuation-object gap between that entry and the new break.
Thread save keeps a second raw coordinate and inserts a break without
that object gap. With a third prefix parked, the real =census_capture=
visits three frames through the generated NEXT links.

The independent logical-end control changes only the oldest frame's
return descriptor. The shared reader admits the enlarged frame when given

that same reader rejects it. The fixture supplies this endpoint explicitly.
A production record must be published by each detaching writer before its
raw coordinate escapes and must exclude the capture-object gap. One
latest parked endpoint or an untyped physical address cannot supply it.

**** Recorded raw span implementation

The running stack owner records the old frame start and logical break under
the section gate before capture or thread save publishes a new raw
coordinate. The same-section stack-limit split also records its span.
The existing parked prefix remains separate. Each half has two bits per
word for boundary marks, initialized on first publication. With the current
section size this reserves 32 KiB per section across both halves. The whole
claim becomes unreachable at retirement, so a newly published half never
inherits its old marks.

Census, captured copying and raw undo use the matching span before a frame
load. Copy and census keep the bound across ordinary frame successors and
reacquire it at a cross-break edge. A coordinate in the capture-object
gap refuses before the first RA. A frame crossing its segment's recorded
end refuses before traversal or destination writes. The fixture uses
the actual configured capture and thread-save macros. A linked diagnostic
recompiled the collector and the three cached modules that emit those
macros. It exercised p1/p2 multi-shot RTE identity and p2 GC/join and
first-RTE controls.

Reflective raw writes, complete current producer coverage, last-reader
joint controls and original workload cost remain separate obligations.

***** Query and ACK after a lost result

- *Identity and access.* Give the frozen source owner or its designated
  reconciler an attempt handle bound to VM incarnation, collection epoch,
  source segment generation, source frame coordinate and attempt sequence.
  A root or request consumer may query only under that handle and a live
  receipt pin. Only the copy owner or a helper with transferred exclusive
  settlement authority may change the result. The address and worker slot
  alone are insufficient.
- *Read protocol.* Under the receipt registry gate, validate identity,
  acquire the pin, and refuse admission after retirement closes. The
  publisher initializes the immutable result and release-stores COMMITTED
  after the target is initialized and successor, root and scan debt are
  covered. Query acquire-loads that same state word while pinned before
  reading the payload. A result from another generation, pending work or
  missing custody remains unresolved. A single shared mutex spanning both
  publication and query is a valid equivalent.
- *Outcome.* A matching terminal result grants ACK through one guarded
  transition, serialized under the receipt gate or by an acquire-release
  CAS of the matching state. Repeat query may recover the same result,
  and duplicate ACK cannot discharge custody again. A proved pre-forward
  rollback can admit a later attempt after refund. Visible forwarding or
  unknown commit forbids retry by allocation. The holder queries or
  reconciles the existing attempt and preserves roots and reservations
  until an authoritative outcome.
- *Retirement.* Close receipt admission before checking pins. Require the
  original segment's aliases to be transferred or gone, readers and
  writer permits drained, ACK settled, and pending copy/Tail/scan
  obligations either drained or proved independent of old storage. The
  roster barrier must cover the remaining old readers before physical
  clearing. A late query after generation reuse fails before payload
  access. A live query may keep only a terminal receipt if it no longer
  names old storage and its own lifetime is independently protected.

***** Falsification on an exact image

Use the existing cuts to stop after forwarding, after READY, after arena
commit with an unresolved successor, and after terminal publication with
the reply withheld. Check pending custody, no duplicate reservation,
matching query, exactly one ACK and a delayed reader blocking retirement.
Run both local-frontier and FIFO publication paths. Separately exercise a
stale generation at the same physical address and a worker slot reused
before the delayed query. These are proposed native controls. The current
Quint abstraction has one attempt and one successor and supplies no C
happens-before proof.

**** Required implementation sequence

1. *Source read.* At an ordinary successor stay within the same pinned
   logical segment. At a true break check the structural link slot, then
   independently acquire the successor grant. Keep the old reference until
   installation succeeds. END and forwarded heap frames take distinct
   routes. A visible forwarding word with unresolved scan debt retains
   original custody and uses the same-attempt query, never a second copy.
2. *Write preflight.* At both fallback entries in =_kernel.scm=, let =i=
   be remaining pairs and =np= the vector payload length. For the current
   layout the batch is =i * (PAIR_SIZE + PAIR_BODY) + np + VECTOR_BODY=.
   Derive the actual footprint from the configured writer, include any
   padding, and check arithmetic before forming a pointer. Bind the
   exclusive interval to context, epoch, section and reloaded cursor.
   For keyword-rest also account for the stack adjustment by =j= and
   staging =nb_key= values. Verify that stack space separately and
   preserve keyword resolution and parameter order.
3. *Commit or retain.* Prepare an independently scannable call state
   before destructive operations, with pre-admitted storage or an
   established complete frame. It must hold the operator, remaining
   arguments, partial rest list, and any resolved keyword values plus
   scalar progress. A failure cannot allocate the very vector whose
   capacity was refused. Keep the caller's complete view until the
   destination root registration is acknowledged. On known refusal
   there are no batch writes to undo. On unknown registration retain
   source custody and reconcile the same attempt.
4. *Resume once.* After GC, reload movable fields and revalidate the
   epoch-bound grant before any new store. On success the initialized
   parameter vector takes custody before temporary roots are released.
   The existing =##rest-param-check-heap= and

   exceptional exit may replay consumed arguments or release an

** Model evidence and Scheme implementation gate

The [[file:models/quint/smp_dev_composition.qnt][joint Quint model]]
and [[file:../../../evidence/research/retained/modern-c/stress-gsi/dev-smp-authority-quint.json][typecheck and history receipt]]
exercise delayed readers, hidden work, a foreign loaded grant, a lost scan
reply and wake before settlement. The reply recovery models an authoritative
query that confirms the existing claim completed. An inconclusive query
keeps the task uncertain. The model has one epoch and abstract task/grant
identities. It does not establish source correspondence, C memory ordering,
fairness or measured progress.

Before handing off Scheme implementation, require an exact map from each
wait/capture/wake/exit caller to its generated host, root view and observable
result. For each proposed change, record which existing history rejects the
old behavior, how the original assertion and timeout semantics are
preserved, and which native observation would reject the new behavior.
A state-machine pass alone does not establish the frame projection or
authorize changing an original workload. Keep the Scheme handoff pending
until that source correspondence and review are available.

** Implementation order and admission

1. Bind the original producer, workload manifests and profile. Freeze the
   generated frame/root representation and identify each real writer and
   borrower before switching authority.
2. Introduce the freeze-to-task and task-to-resume handoffs as one ownership
   cut. Use registry and lifecycle fault controls to establish that reuse and
   unknown completion cannot invalidate an active grant. Keep the existing
   whole-collection route available for cases whose coverage is incomplete.
3. Switch the real return host and request service together with the relevant
   caller and cleanup paths. Qualify same-activation publication, actual reload
   and complete first write. Preserve escaped user continuations, exception and
   dynamic-wind semantics. Retire carrier shortcuts only after their actual
   consumers are covered and no authorized access still uses them.
4. Run the original interpreted and compiled campaigns independently. Then
   qualify complete GC/FFI and downstream consumers on the same producer.
   Compare matched release cohorts only after the correctness receipts close.

A complete handoff needs source/producer identity, exact slot and alias
coverage, control and native boundary correspondence, complete original
native/PBT evidence, and matched cost/peak evidence. Existing QNT covers
competing histories. Lean covers separate frame/slot and interval laws.
Source hashes and ASCENT links establish where to check the implementation.
The original workload remains the acceptance authority. Fault injection and
replay are complementary controls and remain distinct from those runs.

The comparison counts work removed by fewer scans, transient captures and
cross-carrier waits, and work added by grants, fences, root publication,
reconciliation and retained bytes. Record physical peak and pause tails
separately. No net benefit or retirement is admitted from this projection.
