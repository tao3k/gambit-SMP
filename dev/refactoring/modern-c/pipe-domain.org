** Actual old counterexample and replacement

The exact b299e267 runtime returns different actual mutex identities for both
endpoints of vector, string and u8vector pipes. Those endpoints nevertheless
share FIFO chunks, reader/writer cursors, peer close flags and wait predicates.
The old comment claiming exclusive access to one endpoint does not establish
exclusive access to this shared state. Model negative control =splitLock= maps
to that actual two-lock witness, not an invented impossible owner value.

The pipe factory now creates one Scheme mutex before either endpoint and passes
it into the existing three port constructors. Both endpoint graphs receive it
before peer buffers/links are returned. Standalone constructors retain their
existing four-argument use with a nonallocating optional sentinel and a fresh
mutex at its original body position after FIFO construction; public names and buffering
semantics remain. No native permit registry, extra RC root or cached moving
Scheme address is introduced.

| Source owner | Actual consumers | Obligation |
|--------------+------------------+------------|
|Pipe factory|Three constructor families and both settings branches|One guard before peer publication |
|Shared state|rbuf-fill, wbuf-drain, force-output, close|One guard covers both endpoint aliases |
|Waiting|mutex-signal-and-condvar-wait!, retry and timeout hooks|Release before park; reacquire before predicate/cursor reread |
|Close|Peer condition signals and close options|Publish close and wake under common guard |
|Failure/GC|Unpublished Scheme locals; managed ports; existing frame/heap tracing|No native resource transfer or early root release |

The close path calls force-output before acquiring its own guard; it does not
recursively acquire the common mutex while holding it. Existing methods do not
acquire a second peer lock. Normal waits release the guard and reacquire before
retry; timeout hooks run while released. Six real throwing read/write timeout hooks can
subsequently reset the timeout and exchange data. Partial Scheme construction
is unpublished and collectible. Native allocation failure and asynchronous
owner death are not inferred from these exception controls.

The initial proposal allocated a default mutex while binding optional arguments,
unnecessarily changing ordinary port allocation order. Its passing properties,
costs and whole-population timeout remain evidence. The final design uses =#f=
as the nonallocating sentinel and allocates inside the established body instead.
This preserves the original construction/root-view sequence while admitting a
factory-supplied common mutex.
