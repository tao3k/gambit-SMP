#+NAME: bulk-runtime-interface-contract
The [[file:models/sysml/shared-heap-smp.sysml][native SysML composition]] owns call-boundary identities, guards, source
bindings and existing receipt-role dependencies. This packet specifies the
private C23 interfaces those boundaries require. Names/layout below are candidate
implementation notation, not existing exports, a public ABI, a second runtime,
a new configuration layer or generated code. Code blocks never tangle or run.
The [[file:sharing-and-heap-domains.org::#bulk-sync-root-delivery][source refinement]] owns the evidence and limitations.

Complete unit: restricted synchronous core/postlude, real bulk-purpose root
writes, target prepare/install/query/ACK, purpose-aware exit and next-round scan.
Preserve ordinary entry names, their effects and original Scheme fill/multi-shot
semantics. All five joint gates remain OPEN; this packet does not authorize a
runtime commit or native readiness.

* RESEARCH Data and authority ABI
:PROPERTIES:
:CUSTOM_ID: bulk-interface-data
:END:

One existing lifecycle-owned bulk operation retains one registered original span
and at most one unresolved target intent. A caller holds a real VM/operation
lifetime reference before dereferencing either; no query by arbitrary stale
pointer is admitted. Extend the existing purpose discriminator and its consumers;
never borrow a SFUN/STARTUP kind, and create no independent global ID table.

#+NAME: bulk-interface-records
| Conceptual record | Required fields / ownership | Prohibited contents or inference |
|-------------------+-----------------------------+----------------------------------|
| bulk_ref | Held VM incarnation and operation storage lease; exact operation incarnation; lifetime valid before dereference | Bare pointer+generation is not a safe lookup or proof old readers stopped |
| bulk_key | Operation incarnation, one target-attempt incarnation, canonical input revision | GC placement/round epoch is not semantic input revision; increment only with checked no-wrap/reuse rules |
| bulk_roots | Registered RC pointer and immutable count; source, destination, chunk input and any reserved error/effect slots | Native progress/opaque pointers are not SCMOBJ root slots; no shortening count to hide uncertainty |
| bulk_control | Real BULK purpose, current source identity, direction/ranges, known progress, input/effect/edge states, active physical spans and last users | A completed cursor is not physical write-stop, whole-round resume or authority for another continuation shot |
| target_intent | Key, actual target source, publication state, owned target-span reference if known, refused/unknown status, ACK state | No retry with a second possible target while the first outcome is unknown |
| sync_outcome | Exact request result/consumption, round/restore outcome, first error disposition and delivery owner, cleanup disposition | No unrooted moving error/result in native metadata; request NOOP does not mean effects delivered |
| cleanup_observation | Owner-affine effect identity, pending/inflight/uncertain/known result, provider/resource lifetime | Cleared FOREIGN fields and nested drain success do not prove callback completion |

The copy span has 2+b+e root slots: two endpoints, b input capacity and e reserved
root-bearing pending values. Check every addition and byte multiplication before
allocation; unused cells remain FAL. A moving pending value is accessed through
its canonical slot after GC. A proved immediate error code may use native storage,
but this classification must be established for its actual producer.

Candidate result vocabulary, shared by the private operations:

#+begin_src c
/* Interface notation only: not an implemented or exported ABI. */
enum bulk_result {
  COMMITTED,          /* exact declared postcondition is durable */
  REFUSED_NO_EFFECT,  /* this requested transition had no effect */
  IN_PROGRESS,        /* accepted; named custodian still owns it */
  UNKNOWN,            /* some declared effects may have happened */
  STALE               /* key/authority mismatch; grants no access */
};
#+end_src

REFUSED_NO_EFFECT concerns the named transition, not earlier completed chunks or
a prior target allocation. UNKNOWN preserves original and possible target custody.
STALE does not establish absence or permit recycling. The operation-specific
postcondition below defines COMMITTED; it never means all aspects are complete.

These are required private call contracts, not final header prototypes. ps means
the actual admitted executor for that operation; target_ps must be current target
owner. Stopped-source reads need separately authorized source-maintenance access;
passing an old owner's PSTATE cannot manufacture it. No listed operation waits
for GC/owner/callback while holding a source gate or operation metadata lock.

The implementation must update all current internal callers of changed signatures,
including generated SFUN support, setup sync callers and terminal activation
consumers; it must not maintain an unchecked old bulk path through an alias.
Current ordinary Scheme/native names and build entry points remain intact.

* RESEARCH Publication, locking and partial commit
:PROPERTIES:
:CUSTOM_ID: bulk-interface-publication
:END:

Use a metadata guard owned by the existing lifecycle operation, with lifetime
through its last query/helper; a dedicated operation mutex is an allowed concrete
choice and a charged cost. Reusing an existing guard requires the same lifetime
and ordering. No global registry, fixed magic admission capacity or new executor
is needed. The guard cannot be destroyed with the original PSTATE while its
record remains queryable.

Lock order: operation metadata guard before pinned source/target RC gates in one
documented total order. Allocation, GC, callbacks and waits occur outside this
locked section. Scanner takes its source gate and never acquires operation guard.
Any physical-span closure fact consumed by source freeze is published under that
source gate; do not make freeze depend on acquiring locks in the reverse order.
Root-array writes and metadata commit have one guarded publication span; consumers
outside those locks require a real release/acquire and independent lifetime.

1. Publish one target intent in the held operation before enqueuing/preparing.
   It retains original source and target-attempt lifetime. Reserve its control
   metadata before any destructive or fallible target step.
2. Initialize valid FAL cells, publish the owned target pointer and register under
   target source exclusion. Allocation-to-result-publication has a real native
   interruption boundary: if the allocator result is lost before it is recorded,
   the intent stays UNKNOWN. A Scheme-nonreentrant window is not a proof against
   arbitrary OS death. Recovery needs an actual allocator/known-stop witness;
   do not fabricate absence or allocate a replacement target.
3. Fill target slots using admitted typed writes; partial prefix remains valid,
   root_count fixed. Inputs are read from qualified canonical source slots, not
   stale pre-GC body addresses. Parent/source roots remain held.
4. Publish installed revision only after complete payload and operation ownership.
   Do not publish COMMITTED first and fill later. A lost return is resolved through
   the same intent; query pins exist before metadata dereference.
5. ACK applies only to that installed revision and its complete coverage guard.
   Old root clearing and reference release occur later under their own write/last-
   use admission. An ACK retry does not clear roots twice or repeat payload writes.
6. Retire/reuse intent and its identity only after source removal, query/helper
   users and all possible old grants settle. A known failed attempt may be replaced
   only after its cleanup/absence and last use are known. Unknown attempts remain
   the same attempt; checked incarnation arithmetic never wraps through live users.

Physical write permission is scoped to one actual span. Closing admission rejects
new late accesses; already granted raw accesses must really return/stop. An old
writer cannot be revoked merely by changing a generation. An interrupted overlap
write needs complete saved chunk input and exclusive repair authority after known
stop; until then retain source, destination, staging and scan restrictions.

* RESEARCH Restricted postlude and pending values
:PROPERTIES:
:CUSTOM_ID: bulk-interface-postlude
:END:

Extract the existing core; keep execute_sync_op_loop/service_sync_op/on_all_processors
ordinary effect delivery semantics. The bulk caller uses the core with a held
purpose-bound outcome sink and performs postlude only at its admitted semantic
boundary. Core participation still handles pending resize/control operations;
retirement eligibility remains constrained by real bulk/native-return obligations.
No environment variable or runtime configuration profile selects this policy.

The outcome carries four independent facts: request consumed/result known,
whole memory/restore accepted, first error pending/delivered and cleanup
pending/inflight/uncertain/settled. Preserve existing arbitration and designated
error delivery, including cleanup-before-throw for ordinary callers. Store a
potential moving pending error in reserved typed roots before another collection.
Passing a raw SCMOBJ in unscanned outcome metadata is not accepted.

Deferring postlude retains actual queue/error/resource ownership and an eventual
permitted owner scheduling path. It does not suppress GC notification, user jobs
or foreign release. release_foreign clears shell fields before invocation, so
cleanup result comes from saved invocation identity and known return. Nested drain
is not settled. Unknown callback effect is retained and never replayed.

No new Scheme callbacks/call/cc capture points may appear inside native bulk
physical work. Existing Scheme fill polls retain their control behavior. If a
future effectful checkpoint is admitted, its progress must respect each Scheme
shot, not share one consumed cursor that skips later multi-shot execution.

:PROPERTIES:
:CUSTOM_ID: bulk-interface-coverage
:END:

#+NAME: bulk-interface-coverage-guard
| Guard at source ACK | Actual implementation obligation |
|---------------------+----------------------------------|
| Target content | Complete canonical endpoint/input/error slots and exact committed revision; no FAL-membership substitute |
| Source inclusion | Registered target in a live surviving same-VM RC domain captured by root_round_begin |
| Membership lifetime | Target source/context/operation cannot retire before its roots transfer again or finish; query/native last users remain protected |
| Cut exclusion | Between-round transfer or separately qualified overlapping coverage; retain old admitted source during a preexisting frozen round |
| Old data closure | Every prior source/destination writer/helper known stopped; separate from ACK itself |
| Source removal | Clear/drop original roots only after recorded ACK and old last-user closure; generic terminal activation loop dispatches actual purpose |

After ACK, the real consumer is root_round_begin -> freeze -> publish worker
assignment -> strided claim/scan/finish -> mark_rc over data/root_count -> complete
round/restore. It must cover the target when W<R and after original owner has
actually exited. ACK does not require this future GC to have run already; it
requires continuous protection across every cut that could precede it.

The target query/ACK API must not expose a current C return-stack pointer as a
permanent identity. Native-return and effect-affinity constraints remain separate
from root movement. No qualified surviving target means retained original
custody/refused exit. Final VM teardown cannot detach live Scheme staging into
RC_DETACHED byte storage. Arbitrary unknown owner death remains unqualified.

* RESEARCH Allocation adoption and partial-install windows
:PROPERTIES:
:CUSTOM_ID: bulk-interface-adoption-windows
:END:

The current typed allocator returns a pointer; begin_sfun assigns it to
record->roots only after return. The required common allocation seam captures
ownership into a caller-owned sink as part of preparation, rather than making a
second bulk allocator. Candidate private ABI change: retain the alloc_rc_roots
name and add a held owned_out sink; update its rc.h declaration and current
begin_sfun caller together. Both SFUN and bulk use the same checked initialization
and registration logic. This is a proposed internal change, not current C code.

The sink is storage retained by the actual operation/activation, not a temporary
caller stack address. After native allocation returns an initialized private RC
header, capture it in the owned sink before registration; record private versus
registered state separately. A query observes only published control state while
allocation is active, never an unsynchronized private sink. After completion,
publish the adopted state under the metadata guard/release rule. Failure clears
and frees a known-owned private block or unlinks a known registered one only after
its last use and no-effect cleanup are established.

#+NAME: bulk-interface-allocation-windows
| Window | Required retained facts | Permitted result / recovery |
|--------+-------------------------+-----------------------------|
| Intent exists, native call not started | Original roots, target attempt and owned result storage | Known refusal before call can be REFUSED_NO_EFFECT |
| malloc/native allocator may have succeeded, no pointer captured | Intent says allocation may exist; original roots and attempt remain held | UNKNOWN; no second target, inferred NULL absence or made-up free |
| Owned private pointer captured, initialization not published | Known native ownership and exclusive writer, not yet a scan-visible target | Known-stop private cleanup or finish valid initialization; no input ACK |
| Registration link stores incomplete / mutex outcome unknown | Exact intent/private pointer if known, source/link/lock uncertainty | Retain; existing multi-store RC registration/nonrobust mutex is not crash-safe merely because writer death was observed |
| Registered FAL span, return/adoption unfinished | Actual source membership and allocation lifetime if known; original roots | Adopt/query same target once known; FAL registration is not installed payload |
| Some target slots installed | Valid typed prefix/FAL remainder, canonical source and immutable root_count | IN_PROGRESS; GC may scan only when physical write closure and shape are known |
| Full payload committed, result lost | Exact installed revision and protected target lifetime | Query same intent; repeated request does not refill or reapply bulk effects |
| ACK recorded, response lost | Both possible holders plus exact ACK state and old-user dependencies | Query/idempotent ACK; source clear/free only after its own guards |

Cooperative noncollecting/nonreentrant allocator windows do not promise arbitrary
OS-death recovery. A safe common output sink narrows and identifies ownership
windows; it cannot recover an allocator result that never reached any controlled
record, repair an unknown mutex or stop an already-issued native write. Such
outcomes remain UNKNOWN with explicit custody until real supporting evidence
exists. Shape, byte count, list membership or payload equality is not a substitute
for missing allocation/operation identity.

* RESEARCH ACK-to-next-GC acceptance and complete source change set
:PROPERTIES:
:CUSTOM_ID: bulk-interface-change-set
:END:

The key native acceptance history is: protect original -> prepare target ->
install complete canonical endpoint/input/error roots -> record known coverage
and ACK -> clear/release original under known old-user closure -> let original
owner physically exit -> start a later GC -> freeze active target source -> W<R
worker claims and scans target -> reload current roots -> restore map twice.
No GC must be inserted merely to let ACK complete. GC racing before commit keeps
original protection; a preexisting frozen roster is not rewritten by this path.
Target retirement must resolve or transfer the operation again, not drop its roots.

** Owned allocation is not an accepted root loan

A typed owned-output sink must distinguish a known private allocation, registration
in progress, complete registered ownership and any accepted root loan. It lives
in the existing activation/operation's native metadata and starts before the
fallible call. It is separate from the accepted =record->roots= field until the
required root loan is known accepted and ownership is explicitly adopted.

This distinction is required by real consumers: marker_abort currently returns
and releases roots whenever record->roots is nonzero. begin_sfun's ordinary
failure path releases an unborrowed allocation and clears roots before calling
abort. An early raw owned-output pointer placed in record->roots would let generic
abort return a loan never acquired, or release a node whose registration is still
uncertain. Updating the allocator signature without these consumers is incomplete.
