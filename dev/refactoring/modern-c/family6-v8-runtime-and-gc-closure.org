* Runtime correctness fixes

** Fix 1A-ext: Spinlock-held write-group interrupt deferral (=lib/_kernel.scm=, =lib/_kernel.c=)

Under concurrent heartbeat interrupts in =thread_interrupt2_stress.scm=, a
=(not interrupts-enabled)= critical section holding =CURRENTPROCESSOR='s
spinlock (=primlock_depth > 0=) could hit a write-group shortage while a
heartbeat set =stack_limit = alloc_stack_start=. Because =___FP_AFTER(fp,
stack_limit)= evaluated true, =___group_demand_before= returned 0 and
=handler_stack_limit= fell through into =##interrupt-handler ->
##thread-heartbeat! -> (macro-lock-current-processor!)=, self-deadlocking
on its own spinlock.

=handler_stack_limit= now services stack limits whenever
=pending_demand == 1 || ___ps->group_demand_active || ___ps->primlock_depth > 0=,
re-arms pending interrupts via =___refresh_interrupts_pstate(___ps)=, and
returns via =internal_return= so locked runtime sections never re-enter
Scheme interrupt handlers while holding a processor spinlock.

** Fix 1C: Live GVM register scrub after =___PUSH_REGS= (=lib/_kernel.scm=, =lib/_kernel.c=)

Under SMP stress, =gsc/_t-c-2.scm= (=targ-spill-dirty-unboxed=) can hold an
unboxed 64-bit IEEE-754 =___F64= value in =___R1= (for example,
=0x41dac16f167b4228= from =##absrel-timeout->timeout= in =lib/_thread.c=)
with its GC-map bit cleared in the =___RETI= stack frame. Previously,
=handler_stack_limit= and =handler_heap_limit= pushed =___R1..___R4= onto
the stack via =___PUSH_REGS= and then wrote the live registers into
=m->context->r[]= via =___W_ALL= without clearing them. During census and
mark, =mark_registers(work, m->context)= unconditionally scanned
=m->context->r[]= as Scheme roots, faulting in =mark_array= whenever the
raw double had bit 0 set (=___MEM_ALLOCATED=).

Both =handler_stack_limit= and =handler_heap_limit= now zero
=___R1..___R4 = ___FIX(0L)= immediately after =___PUSH_REGS= and before
=___W_ALL=. The intact unboxed bits remain in the =___RETI= stack frame
(governed by its exact GC map) and are restored verbatim on return by
=___POP_REGS=.

* Compiler 8 GiB envelope and runtime performance repairs

** Thresholded header guards and zero-spill leaf =___group_demand_enter=

- =include/_gambit/object_access.h.in= and
  =include/_gambit/runtime_protocols.h.in=: guard inline observation and
  attempt-0 commit fast paths with =#if !defined(___LBLCOUNT) || (___LBLCOUNT < 6000)=.
  Hot runtime units (=_kernel.c=, =_thread.c=, =_eval.c=, =_repl.c=,
  =_system.c=, =_nonstd.c=, =_module.c=) all have =___LBLCOUNT < 6000= and
  avoid empty out-of-line calls, while giant modules (=_std.c=, =_num.c=,
  =_io.c=, =gsc/_prims.c=, =gsc/_t-univ-2.c=) keep compact 1-block calls so
  full two-pass GCC 16 compilation stays strictly below 8 GiB (measured
  =peakRss = 7.246 GiB=).

  out-of-line per the C contract, while splitting the cold slow path into
  =static __attribute__((noinline, cold)) group_demand_enter_slow= inside
  the projected =entry.inc= slice. On ARM64, =___group_demand_enter=
  compiles to a 29-instruction pure leaf function with zero stack frame and
  zero callee-saved spills, tail-branching to =group_demand_enter_slow= on
  miss (and refreshing =publish_fast_span= when local room admits).
