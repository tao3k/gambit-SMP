Logical VM cells are =(VM identity, VM-root family, slot)= for slots0 through
=VM_SIZE-1=. RC cells belong to separately allocated native headers. Two cells
may point to the same heap object or multi-shot continuation: cell partition
must never become referent deduplication. The copying/frame/control protocols
remain Gambit's own implementation.

The VM task is a coordinator-confined C record, never placed on a shared queue.
Its source allocation and stopped roster are held by the enclosing actual GC,
independently of task-record lifetime. Its scanner never queues addresses into
the task record; descendants belong to the existing heap traversal. After
normal completion the C record may leave scope, while VM storage remains held
through weak/copy/cleanup. It must not be exported as a durable async handle.

Only a fresh unexposed record may be initialized. Production seeds its epoch
from the already published nonzero coordinator RC epoch minus1, and requires
the resulting epoch to match. Init is not an unknown-work reset. Epoch wrap,
stale requests, wrong source/executor and duplicate entry are refused. Source
lifetime must already cover lookup before metadata is read; stale addresses
are not resurrected by epoch checking.

** Exclusion and conditional proof :proof:counterexample:

RC keeps its existing domain mutex. VM control state adds no lock: only the
current coordinator's nonallocating, nonreentrant C invocation can access it.
Real barriers protect the admitted source data plane. This does not establish
writer coverage for arbitrary native code, unknown live threads or future
asynchronous workers. The new API is private; fabricating a fresh record does
not prove a valid GC phase. Publication does not independently detect that
all source writers stopped: this cut establishes the actual caller placement
after the barriers. Calling it earlier violates a private-call precondition;
it is not a promised dynamic rejection or an authorization boundary.

1. Given a live stopped VM view, valid coordinator and current epoch, publication
   installs one typed origin and one lease before any claim can succeed.
2. Shared claim permits only READY -> CLAIMED once. Scan checks the same origin,
   executor, key and lease, and calls the actual VM source scanner.
3. Only normal scanner return sets SCANNED. Shared finish releases once;
   duplicate known completion does not decrement again.
4. Completion leaves source/round lifetime with the enclosing GC; it cannot
   establish global termination, mutator reentry or worker retirement.

Counterexamples retained as obligations: publish before setup quiescence;
reinitialize unknown SCANNING work; hand the C record to another thread;
deduplicate two cells by the same pointed-to continuation; infer whole-round
completion from task DONE. None is admitted by this cut. Worker-death progress
or healthy-VM isolation must not be claimed from a synchronous task adapter.

** Native replay, shrink and actual payload :pbt:evidence:

The existing =tests/root-task.scm= and =test-root-task= target are extended.
There is no second harness, configuration format or Python test. Four-field
Scheme traces name either the existing RC family or the VM family; both use
the same generator, independent observable oracle, fresh-process replay and
deletion shrinker. The VM observation called phase encodes whether the origin
is published; it is not a synthetic certificate that all VM writers stopped. VM opcode4 submits an alien source and must be refused
before dereference; it is not RC retirement. The first integer is warm-GC
count, not a version name.

VM replay children require p1 and replace the actual VM root body's fields
with FAL in one C invocation. No subsequent Scheme allocation/callback/return
is allowed; the child emits its result and exits. This tests actual task and
scanner code with immediate payloads; it does not pretend to model production
reset/recovery. Actual relocation is tested separately: a joined Scheme
producer places a fresh pair/vector in documented unused-field2, ordinary GC
must update its address and preserve content, and dynamic-wind clears only
fixture-owned storage. The raw before-address is comparison data, not a root.

Per family, a labeled stale-finish invocation mutation must be detected and
shrink24 noisy actions to publish/claim/actual-scan/finish, replaying the same
failure while retaining SCANNED/lease1. This is deletion1-minimality for that
failure class, not global minimality or a discovered production defect.
