[[file:models/sysml/root-dispatch.sysml][SysML]] owns this detailed refinement of the roadmap's =root-origin-dispatch=
node. This is the next complete chain: root census -> writer stop/frozen view ->
publication -> task claim -> scan using the source origin -> completion ->
source-borrow release and bounded record reuse. A counter or wrapper around
the old scanner is insufficient. No runtime implementation is added here.

The predecessor separates root storage from the carrier. This successor must
separate root scan identity and permission from the collector's identity. It
does not simultaneously replace worker copy arenas, capacity/restoration,
thread-affine cleanup, VM retirement or the whole CFFI service. Those are
separately gated dependencies, not deficiencies to hide in this REV.

* Frozen source, task identity and memory order :contract:

- The descriptor borrows the real context, RC head and root address view. Root
  writers must be stopped/cooperatively parked before publication; a logical
  phase flag alone proves neither physical stop nor lifetime.
- Publish the fully formed immutable census with release semantics; claimers
  acquire that publication and a generation/lifetime pin. =VM, epoch, kind,
  slot, partition= identify a bounded task. A separately checked epoch followed
  by a state-only CAS permits ABA and is rejected. Reuse requires old readers
  and requests to drain; epoch exhaustion rejects rather than wraps.
- A claim has one winner. =Ready -> Claimed -> Scanning -> Done= represents
  permission and progress, not a new ownership claim over every reachable
  object. Different root tasks may reach the same captured continuation.
  Preserve existing frame/forwarding rules; do not infer unique copying from
  unique root-job claim.
- Finish release-publishes rewritten roots. The observer acquires completion,
  but source borrows/writer reentry still obey the existing whole-round strong,
  weak, queue and cleanup barriers. Root tasks alone cannot seal the round.
- Actual C23 atomics and existing lock/barrier implementations must refine
  these edges. No assumption of universal lock-free multiword atomics is made.

The source-explicit scanner accepts origin and executor separately. Executor
eligibility includes capacity and thread-affinity capabilities. Until the
worker-arena REV qualifies arbitrary assignment, existing affinity/capacity
constraints remain explicit. The code must not advertise unrestricted stealing
or whole-collector =W<R= merely because a dispatcher can accept two counts.

* Failure and unknown-result custody :failure:

| Cut / result | Custodian and permitted action | Forbidden inference |
|--------------+-------------------------------+---------------------|
| Census/metadata reservation fails before publication | Original source roots and lifetime owners remain responsible; reject without partial roster permission | Source-root ACK or GC completion from allocation failure |
| Claim rejected or stale key | Existing owner retains the root; no scan occurs | Reusing an old slot/key or dropping its root |
| Completion ACK lost after Done | Query the same generation/identity and return the recorded completion | Restarting the destructive scanner |
| Worker stopped before scanner entry, with actual exclusion proof | Transfer the unstarted task while preserving the source pin | Treating a status read or join error as a stop proof |
| Scanner may have entered; stop/result unknown | Keep task and source roots pinned; completion/reuse remains blocked for that owning round | Requeueing partially changed stack/frame work or reporting missing roots as done |
| All root tasks done | Continue the existing GC phases and final lifetime drain | Whole-round/VM/global reclaim permission solely from root count |

Unknown join isolation and healthy-VM progress still need the separate VM
membership/retirement contract. This cut must preserve/refuse safely; it cannot
claim that a task descriptor solves arbitrary owner death or native side effects.

* Benefit and additional-cost matrix :benefits:

| Mechanism | Verifiable benefit target | Added cost and falsifier |
|-----------+---------------------------+--------------------------|
| Explicit closed root census | Every admitted context and actual RC head is represented, with no leader-only implicit coverage | O(R+K) metadata/work; a reachable producer outside the census blocks the REV |
| Origin/executor separation | A worker-policy change cannot silently change which stack/register/RC bank is scanned | Task arguments and root-view pins; any indirect helper still deriving source from executor fails refinement |
| Unique generation-checked claim | Duplicate/stale jobs cannot authorize a second root-task scan | Bounded claim/completion synchronization per task; aliasing objects still use existing forwarding rules |
| Lifetime/unknown custody | Lost ACK or unknown stop cannot silently discard a root or recycle its descriptor | Pinned metadata/roots may retain memory and block their round; physical-stop/recovery remains necessary |
| Existing FrameSpec and multi-shot semantics | The same precise frame roots support repeated continuation recovery while later worker policies can vary | No one-shot restriction, extra GC scan elimination or speedup is claimed |

Let R be origin count and K task count including VM/global partitions. Storage
is R*sizeof(RootOrigin)+K*sizeof(RootTask)+bounded borrow/status records, not an
invented byte estimate. Runtime work adds census/claim/completion operations;
it does not remove necessary reachable-object scans. Exact bytes, atomics,
root visits and peak retained memory must be reported from the implemented
source before the next code REV is admitted.
