* Frozen source, task identity and memory order :contract:

- The descriptor borrows the real context, RC head and root address view. Root
  writers must be stopped/cooperatively parked before publication; a logical
  phase flag alone proves neither physical stop nor lifetime.
- Publish the fully formed immutable census with release semantics; claimers
  acquire that publication and a generation/lifetime pin. =VM, epoch, kind,
  slot, partition= identify a bounded task. A separately checked epoch followed
  by a state-only CAS permits ABA and is rejected. Reuse requires old readers
  and requests to drain; epoch exhaustion rejects rather than wraps.
- A claim has one winner. =Ready -> Claimed -> Scanning -> Done= represents
  permission and progress, not a new ownership claim over every reachable
  object. Different root tasks may reach the same captured continuation.
  Preserve existing frame/forwarding rules; do not infer unique copying from
  unique root-job claim.
- Finish release-publishes rewritten roots. The observer acquires completion,
  but source borrows/writer reentry still obey the existing whole-round strong,
  weak, queue and cleanup barriers. Root tasks alone cannot seal the round.
- Actual C23 atomics and existing lock/barrier implementations must refine
  these edges. No assumption of universal lock-free multiword atomics is made.

The source-explicit scanner accepts origin and executor separately. Executor
eligibility includes capacity and thread-affinity capabilities. Until the
worker-arena REV qualifies arbitrary assignment, existing affinity/capacity
constraints remain explicit. The code must not advertise unrestricted stealing
or whole-collector =W<R= merely because a dispatcher can accept two counts.

had not completed =CLOSING -> DISPOSING -> PASSIVE=. The next GC's

unwanted dependency and retain the VM-wide collection blockage.

The replacement assigns managed root retirement to the old roster:

1. Preflight existing root borrows/activation states, unknown-affinity foreign
   release functions and already-queued procedural cleanup. Unsupported
   effects refuse shrink before transfer; raw concurrent unmanaged enqueue
   still lacks admission and remains excluded.
2. Reserve departing slots, transfer the address-stable still lists and both
   accounting components to the survivor while all old members are parked.
3. A shrink-only old-roster collective orders completion of that list transfer.
   Each departing owner then closes its own activations and performs only
   =___cleanup_mem_pstate=; its independently lived RC domain becomes PASSIVE.
4. Before acknowledging the existing membership-publication collective, the
   owner verifies the passive domain has no activation, bound writer or scan.
   Invalid managed-stop premises fail closed; no unsafe continuation resume
   is manufactured for a partially retired activation.
5. Only then publish the smaller roster. Native interrupt/OS cleanup and
   =thread_exit= occur after that acknowledgment. They do not own Scheme
   roots or allocator state and cannot run a managed Scheme entry through
   the PASSIVE domain. Unknown unmanaged effects remain outside admission.
6. A failed/unknown join retains quarantine and VM-reclamation custody. It
   does not expand the GC roster, suppress its PASSIVE root task or wait under
   a GC/control lock. The fixture confirms subsequent GC and root access,
   rejects growth into that slot, disables injection, executes a fresh actual
   =___thread_join=, and only then acknowledges that success and reuses it.

| ClaimTask | One bounded identity (VM, epoch, origin, partition), one claimant; enforce source-specific allocation/affinity eligibility | Generation and claim checked under one synchronization protocol; no separately checked generation followed by state-only CAS |
| ScanTask(worker, origin) | Root address selection comes solely from origin; worker provides qualified allocation/chunk/diagnostic state | Array, active-stack, captured-frame, RC and global indirect helpers all stop selecting source through worker->context/id |

For R admitted context domains, C admitted RC heads and P frozen global ranges,
one explicit task decomposition has K=2R+C+P+2: a bank task and stack task per
context, one task per RC head, P global slices, one VM-body task and one
symbol/keyword-root task. The current private candidate chooses P=R, giving
K=3R+C+2. It is not an installed public ABI. Further coalescing needs a source
coverage proof and actual affinity/capacity rules; retained RC domains are not
silently bounded by live carriers.

A bounded record is pre-reserved before publication; metadata reservation
failure leaves the original source responsible and publishes no permission.
Logical epochs do not wrap. A task slot is not reused while old requests,
readers or unknown execution remain. A source view also needs real backing
capacity: the base MULTIPLE_VMS glos allocation has a fixed 20000-element
allocation and an expansion TODO, while its scanner uses current glo count.
Record actual allocation extent and valid initialized range; do not introduce
another unexplained constant or assume the count is a capacity certificate.

Frozen means the source owner, storage lifetime, initial coordinates and
traversal contract are pinned. It does not freeze root values or make every
descendant frame address immutable: GC must rewrite values and may materialize
stack frames on the heap. The C adapter must follow current forwarding and
FrameSpec coordinates while retaining logical root identity. Context-array/RC
top-level cells need stable backing storage; descendant relocation needs the
separate currentAddressCovered premise. Neither is implied by a saved pointer.

** Counterexamples that block a partial rewrite :counterexample:

- *Leader coverage*: processor1 registers a Scheme payload, but leader-only
  mark_rc leaves its word stale even though the ordinary Scheme root moves.
- *Release race*: caching h->next does not prevent release_rc from freeing h
  before mark_array(&h->data,1). A descriptor pin without a node/chain lifetime
  protocol does not fix this use-after-free window.
- *Late root*: locking only during mark_rc allows set_data_rc to publish an
  unmarked Scheme object after that chain was scanned. Freeze or explicit
  late-work accounting is required for the entire relevant interval.
- *Cleanup cycle*: a proposed blocking RC writer gate remains closed until GC
  completion; GC -> free_unmarked_still_objs -> release_foreign -> TLS/event
  release function -> release_rc waits on that gate. GC cannot release its own
  wait. The source proves these feature-conditional destructor paths; this
  cycle is a counterexample to the proposed gate, not an observed hang in the
  current ungated Darwin runtime. Proven delete-only cleanup may use a distinct
  phase-local permission after scans drain; arbitrary callbacks need effect
  admission/deferred cleanup and cannot merely block the collector.
- *False stop*: shrink frees an RC head before a borrowed task drains; the
  subsequent failed/unknown join does not resurrect that storage.
- *Unknown entered scan*: requeueing a partially executed continuation task can
  replay destructive frame/Tail work. Retain its source and progress instead.

These are responsibilities to replace together, not permission to bolt on
checks and call the runtime modernized. The task protocol cannot establish
unknown native side effects, complete GC termination or whole-VM isolation.
