** Actual cost and source cause

The unchanged default root-task Make recipe costs67.071s: compile10.802s,
original task/continuation histories53.402s, RC writes2.635s, moving bank/globals
0.157s. A temporary native Scheme clock probe retains every history and shrunk

This observation is not a complete original Make pass or an uninstrumented speedup.

Source: =os_io.c:___device_stream_setup_from_process= forks, performs cleanup,
fd relocation/redirection, then calls =___closefrom=. =os_setup.c:___closefrom=
falls back to =sysconf(_SC_OPEN_MAX)= and a close loop. The actual configured
Darwin headers have no closefrom/close_range/F_CLOSEM route; OPEN_MAX1048575.
The source work bound is limit minus retained low descriptors per admitted child.
No syscall trace or blanket claim that every launch took that route is invented.

** Responsibility replacement and semantic boundary

Prepare opaque spawn attributes/actions in the parent before fork; allocation
failure keeps the existing path. Keep the existing forked child and all signal,
affinity, pipe relocation/redirection and errno-pipe preparation. In that child,
check real stdio flags after relocation: closed or CLOEXEC stdio retain the old
path. After the unchanged child chdir/environment handling, for explicit paths, =POSIX_SPAWN_SETEXEC= and
=POSIX_SPAWN_CLOEXEC_DEFAULT= move descriptor closure to the kernel. Three stdio
self-dup actions retain only the intended streams. Successful SETEXEC replaces
the same PID and never returns. The existing parent EOF/error and registration
protocol remains; no child is published twice and no new launcher is introduced.
Failed SETEXEC falls through the original close/exec branch; no second child was
created. Non-explicit PATH lookup, PTY and refused standard streams keep the old branch.
Explicit cwd and environment semantics remain in the existing child; their
resolved values precede SETEXEC. Arbitrary foreign interference is not admitted
by pipe tests.

Primary platform evidence:
- [[https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_exec.c][Apple XNU kern_exec.c]]: SETEXEC and file-action execution, failure handling,
  PSFA_DUP2 and final inheritance marking.
- [[https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_descrip.c][Apple XNU kern_descrip.c]]: fdt_exec closes non-inherited entries in the actual
  descriptor table; file-action policy differs from a user loop up to OPEN_MAX.
- [[https://github.com/apple-oss-distributions/Libc/blob/main/sys/posix_spawn.c][Apple Libc posix_spawnp source]]: distinguish libc PATH/shell policy from the
  deliberately explicit-path posix_spawn operation selected here.
- Local public SDK =spawn.h= / =sys/spawn.h= declare the operation and flags.
  Public source is architectural evidence, not a binary version identity claim.

** Quantitative mechanism and cost boundary

Let L be the configured open-fd upper bound and E the retained errno fd. The
legacy upper-range loop attempts max(0,L-max(E,2)-1) closes, plus the unchanged
low-range exclusions. Kernel default closure uses the actual descriptor-table
extent, not a claim of O(number-of-open-fds) or O(1) total exec. The admitted
branch adds one attribute-object/action-list lifecycle, three self-dup actions,
three child F_GETFD checks and one SETEXEC attempt. Fork count and Scheme heap
limits are unchanged; native allocation/reallocation and kernel copy cost remain.
No positive speedup at every smaller fd limit, RSS or whole-bootstrap causal
attribution is claimed from a single cohort timing.

The current Apple libsyscall [[https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/spawn/posix_spawn.c][posix_spawn wrapper]] assembles a stack descriptor
for already prepared attributes/actions and calls the kernel; its parent-side
init/destroy routines allocate/free storage. Optional internal spawn filtering
is a separate platform capability: public source says its hooks are normally
NULL on customer systems. This source audit does not certify arbitrary injected
hooks, private Apple builds or exact binary/source version identity.

The public Scheme process API forces a bidirectional process device, and default
stdin redirection can replace an otherwise closed parent fd0. Closed/CLOEXEC
controls explicitly disable stdin redirection and use a child-only environment
marker for an early native constructor to emit fd state and PID before Gambit
initialization. They do not infer exec-time fd state from a later Scheme view.
The marker is test-local, not a runtime profile or new launcher. All byte values
are read through the existing API with its supported ISO-8859-1 setting.
