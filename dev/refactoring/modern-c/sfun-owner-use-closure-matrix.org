** Gain

| key | avoided | added | condition |
|---+---+---+---|
| reuse | Existing owner marker is reused across Q calls; no new per-call marker is required | Invocation epochs/completion records and final-use gate | Current code already reuses it: do not count Q-E allocations as a new saving |
| receipt | Queries after commit add zero native reference decrements | Stable receipt lookup, generation and retention work | Physical decrement/commit gap still needs NoAbandon; unknown outcomes retain resources |
| finalizer | One managed owner finalizer can replace three END_SFUN kill/propagate forms | Generated result/converter effect plan and stable abnormal-exit cleanup | Remove unconditional duplicate kill sites after all three forms and abnormal exits qualify |
| control | Preserve old same-owner Scheme continuation delivery to current call | Separate origin identity, current invocation and receipt ownership | Requiring origin epoch to equal active invocation changes supported control behavior |
| token-alternative | A qualified native token ABI may remove E marker vectors and E native releases | R reflective views, S boxes and D newly owned native releases plus token support | Net object constructors E-R-S; native count releases E-D; Q calls may exceed E owners; no time/byte speedup proved |
| root-descriptor | One owner/capture/receipt ledger can replace repeated lifetime reconstruction | Root enumeration, parked-context handoff and code grace | Only if obsolete responsibilities are deleted; existing necessary supports counted once |
| language | C23 can express this protocol and generate the finalizer from Scheme | The same lifetime and source obligations remain for Zig | No Zig-specific net return is established by this study |
| watermark-support | Observation-only stale invocation handling can avoid adding one retained outcome record for every retry | Per-owner current epoch/completed watermark and closure tombstone plus query-record pins | Bounded identity metadata O(E) for E owners, versus O(Q) retained per-call outcomes for Q calls, only if queries need no historical payload; this avoids new support cost and does not retire an existing ledger |

** Memory

| key | publication | observation | obligation |
|---+---+---+---|
| invocation | Publish new current epoch before entering ___call under owner gate | Completion records current epoch after authenticated return | Old-origin Scheme frames select a live owner; old completion receipts do not select a new invocation |
| final-use | Close same-owner future-use admission after result and cleanup completion | Acquire zero active/nested users and exact final epoch, then commit closure | Several C stores are not a hardware transaction; real gate and GC synchronization remain open |
| escape | Preowned stable subtree record keeps roots/code while landing result is unknown | Exact native exit acknowledgement plus child/borrower closure | No stack-local guard on a discarded C frame can be the sole issuer |
| marker-drop | Qualified NoAbandon interval excludes GC/count writers through physical effect and receipt | Release commit before cancelling masks or replying; acquire query does not replay | C23 atomics alone cannot couple plain -- with a separate receipt |
| gc | Existing scanner/registry participation retains mutable slots while in use | Retire logical root only after final captures, guards and GC readers leave | This model uses a root lease bit; moving-slot and image-group refinement to parent remains unproved |
