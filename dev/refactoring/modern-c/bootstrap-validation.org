:PROPERTIES:
:CUSTOM_ID: bootstrap-validation-index-owner

The earlier target could enumerate 1,588 primitive entries after GC while
1,582 same-key lookups missed. Canonical symbol identities did not change.
Explicit Scheme rehash repaired the lookup diagnostic. The source had allowed
the collector's native address-hash algorithm to rebuild a Scheme semantic-hash
index. Reference repair and bucket ownership were conflated.

The candidate uses a persistent owner bit in the existing flags word. The
collector still repairs references. For a Scheme-owned index it clears
KEY_MOVED, preserves any existing NEED_REHASH debt, and does not invoke the
Scheme callback. Native identity indices retain their address-based reindex.

premise that Scheme hash/equality is stable under movement, ordinary GC adds
no Scheme rebuild and no first-reader rebuild race. Arbitrary user mutation,
address-dependent custom hashes, old serialized flags, raw foreign mutation,
and concurrent explicit rebuild are outside that premise.

The actual source closure is:

1. =lib/setup.c:893--954= sets the target count and asks GC for space when free
   sections are fewer than two per additional processor, then calls setup for
   each new processor. It lacks an explicit physical-interval grant consumed
   by those setups.
2. =lib/mem.c:4557--4603= initializes each processor with a fresh stack section
   and a fresh local heap section. A new context has neither as fallback.
3. =lib/mem.c:6303--6310= computes a nominal floor from two times the target
   count and a separate occupied-space estimate.
4. =lib/mem.c:6360--6373= applies that floor only within the max_heap branch.
   Moving one clamp is insufficient: even an unconditional
   =max(2*target, live_estimate)= need not reserve two *additional* sections on
   top of already assigned physical regions.

** Proposed conserved quantity and complete responsibility replacement
#+NAME: startup-physical-floor
#+BEGIN_EXAMPLE
A = closed set of already active contexts
T = requested target; N = max(T - |A|, 0)
S = actual physical regions already assigned after collection/compaction
R = bounded physical resume reserve, disjoint from startup grants
capacity >= S + 2*N + R
initialize one context: assigned += 2; pending -= 1
grant: known successful allocator result, complete root view, no overlap
unknown result: retain custody; do not publish grant or member
#+END_EXAMPLE

This floor is necessary under the current two-region initialization protocol,
not sufficient for a new collector. Actual intervals, allocator overhead,
checked arithmetic, partial failure, root freeze and post-GC reserve must be
refined separately. The model's =10 assigned / 24 capacity / 11 pending=
counterexample is mathematical, not a measured native state.

The next complete cut must jointly replace nominal count authority with:

- a closed current-participant census used for this collection, distinct from
  the requested future execution-context population;
- a physical reservation ledger with disjoint stack, local allocation and
  worker/resume intervals; no double spending of worker tails;
- setup consumption and member/thread publication backed by the same grant;
- partial creation rollback and unknown-result retention, including root and
  native resource custody; success/rollback must not race a new collection;
- completion semantics that distinguish collected successfully, reservation
  fulfilled, all contexts initialized and all threads published.

A larger initial heap, p1-only operation, moving one clamp or copying a repair
patch cannot discharge these obligations. The current runtime is unchanged at
this capacity path. No independent-worker, generational collector or complete
PSTATE retirement is claimed by this bootstrap slice.
