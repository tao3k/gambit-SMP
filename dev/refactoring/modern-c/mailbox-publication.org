* Complete responsibility replacement
** One identity
The target thread's low-level lock protects lookup and publication. Candidate
allocation happens before taking the commit lock. A second lookup chooses one
winner; a losing candidate remains GC-owned. No mailbox mutex is nested under
the thread lock. The public =thread-send= initialization check releases its
thread lock before this protocol. Multiple first publishers must never retain
different queue identities for one target.

** Rooted allocation before queue ownership
=##thread-send= initializes its detached cons before the mailbox mutex wait.
The current frame roots the detached cell, its payload, mailbox and mutex
across heap checks and blocking. The commit links the initialized cons with
no allocation between its two pointer stores. Reachability transfers to the
mailbox graph; there is still one cons per sent message. Generated root maps
must retain and reload the cell after any relocating GC in the wait path.

** Uniform mutation ownership
All SMP head/tail/cursor accesses in send, receive, peek, extract and rewind
use the same mailbox mutex. The old unlocked nonempty path is removed. A
selective cursor is a predecessor node; extract changes its successor and
possibly the FIFO tail under the permit. The non-SMP implementation remains
separate; the generic FIFO allocation macro retains its previous API.

** Safe points and timeout delivery
The link/splice batches contain no allocation or explicit heap check. Existing
mutex helpers can check the heap at entry/unlock; the graph is complete before
unlock is invoked. The first empty observation releases the permit before
converting the timeout, then reacquires and rechecks the queue. The resulting
absolute timeout is reused across wakeups; it is never restarted. Timeout
exceptions arise after the condition-variable wait has released the permit.
Asynchronous Scheme interrupts remain disabled over the commit batch.

** Collector ownership stays independent
=mark_execution_roots= owns frame/root repair through a RootTask. Object
=scan= claims READY -> OWNED -> DONE separately, with the existing forwarding
and Tail contract. Unique scan authority cannot repair a graph whose mutator
lost the published link. The scanner must never acquire the mailbox mutex:
a stopped receiver could own it. Current physical writer stop remains a
precondition; this change does not establish independent collector workers.

* Source refinement and remaining C memory-model obligation
=macro-lock-thread!= uses the existing primitive lock; =macro-mutex-lock!=
and unlock coordinate queue ownership through the thread/mutex low-level
locks. =gambit.h.in= ticket-lock operations use =___FETCH_AND_ADD_WORD= and
=___COMPARE_AND_SWAP_WORD=; the GCC sync backend uses full-barrier builtins.
The portable ticket-lock acquire also polls a volatile =current= word. A strict
portable C acquire/release proof for every supported backend is still OPEN;
Darwin/GCC native success must not silently stand in for that proof.

Modern C should eventually make that low-level synchronization contract
explicit. Adding a second mailbox-specific C atomic implementation here would
leave two conflicting authorities. This candidate reuses the existing scheduler
lock service and records its prerequisite instead.

** Peak memory and work bounds
:PROPERTIES:
:CUSTOM_ID: mailbox-permit-cost-bound
:BOUND_KIND: SOURCE-DERIVED; NOT-A-PERFORMANCE-MEASUREMENT
:END:
A Scheme pair occupies two payload words plus its header. Relative to allocating
only after acquiring the permit, =W= simultaneously blocked senders can retain
up to =3 * sizeof(word) * W= additional detached-node bytes. On this 64-bit
profile that is =24W= bytes, excluding allocator rounding and additional frame
root slots. Payloads were already live sender roots, so they must not be counted
as newly introduced copies. This is a local occupancy bound, not a measured
whole-round GC peak or a promise of lower peak memory.

Completed sends still allocate one node each. A queued message's vector/list
payload is shared, never serialized or copied by the mailbox protocol; any
copying during GC is the collector's existing responsibility. The uniform
permit adds synchronization to successful nonempty receives and selective
cursor operations. The initial empty path pays a release/reacquire to preserve
lazy timeout conversion. Possible additional heap checks and generated frame
slots require inspection of generated C; no throughput or latency percentage
is inferred from these work counts.

** Writer inventory and admission boundary
The first =enable-smp= branch has one thread-mailbox publication site, two
standalone cursor writers (rewind/extract), one unified receive/peek writer,
and send through the nonallocating tail-link helper. Initial object construction
is private. The duplicate later mailbox implementation is the non-SMP branch.
Raw =##unchecked-structure-set!=, arbitrary C/FFI mutation or reflective changes
to private scheduler objects are outside this API ownership proof; they cannot
receive a controlled-writer credential merely because exported operations pass.
GC relocation remains an authorized stopped-world writer with separate scan
ownership. Preserve these distinctions in any future generational write barrier.

** Concrete blocked-frame consumer chain
The generated =##thread-send= constructs the detached cell in =R3=, checks the
heap, spills it to =STK(-4)= before =##mutex-lock-out-of-line!= and reloads =R3=
from that slot at return label3. Its corresponding normal-return descriptor is
=IFD(RETN,5,0,0xf)=. The two link stores are adjacent in generated C. These
checks are bound to the completed bootstrap's =lib/_thread.c= hash, not a copied
illustrative fragment.

The actual slow mutex path calls =macro-thread-save!=. The SMP syntax maps this
to =##thread-save!=; =gsc/_t-c-2.scm= emits =THREAD_SAVE= after its end-of-block
checks. =gambit.h.in:___THREAD_SAVE= forms the break-frame link and stores the
frame in the thread continuation. The queued thread remains reachable through
scheduler/mutex queues; stopped-world continuation/root consumers repair its
frame according to the descriptor. Resume label3 then reloads the repaired
cell. Generated-code inspection alone does not establish this whole delivery:
the blocked-cell native test must actually observe the sender waiting on the
exact mutex, complete GC, release the permit and validate the payload.

The original sender's forced collection at multiples of eight can expose a
queue with only31 left before32 is sent. After GC resumes both processors, the
unlocked receive and send can overlap. This makes the source counterexample
relevant to the old workload; it still does not recover that old execution's
unrecorded schedule or received value.
