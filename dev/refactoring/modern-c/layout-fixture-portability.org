* Independent layout assertion :source:proof:

The fixture still compares Scheme backend coordinates with C's actual layout.
For a declared fixed array =a= and an in-bounds literal index =i=, use:

#+begin_src c :eval never
offsetof(T, a) + i * sizeof(((T *)0)->a[0])
#+end_src

The array member offset includes structure padding; C array elements are
contiguous and =sizeof= uses the actual element type. Its operand is unevaluated.
The expected coordinate remains independently produced by the existing Scheme
backend. It is not recomputed from C's offset. Existing register indices0..4,
saved indices0..2 and type-cache indices0..1 remain unchanged.

The Scheme field metadata now records array member and index separately.
Scalar offsets and optional lowlevel bridge assertions retain their spelling.
There is no new platform conditional or disabled assertion. This does not
redefine offsetof, require C++, or evaluate a null-pointer dereference.

Microsoft's [[https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/offsetof-macro?view=msvc-170][offsetof reference]] describes the simple member form; its
[[https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/c4841?view=msvc-170][compound-designator diagnostic]] advises avoiding compound member designators.
The latter is C++ documentation, not a substitute for this actual C failure
log. [[https://www.open-std.org/jtc1/sc22/wg14/issues/c11c17/issue0496.html][WG14 issue496]] documents the portability ambiguity around extended member
designators. Native MSVC C success must be observed after publication.
