* Handler, retry and effect views are different

The source now exposes four linked hazards, not four independent patch tasks.
=group_demand_after= saves =context.hp/fp= while the internal handler frame is
still present. The later =resume_view= writes those snapshots into resumed
locals. Internal return reverses =RETI_RA=, pops the saved registers and uses
the descriptor's *stored CFS* to remove alignment padding. Never apply a global
12/15-word pointer correction: the direct check-heap path must be classified
by its actual published frame/view and need not have the stack handler's
internal spill frame. Its cursor is 12–15
words above the handler cursor at the current ABI; Lean proves these coordinates
cannot be identical under the supplied frame premises.

The kernel subsequently invokes the existing Scheme interrupt handler. That
code can allocate or change heap sections without changing GC epoch. Replaying
the saved hp can rewind allocation over a still-live published object, or put
hp into a different active section. Context and GC epoch equality alone cannot
prevent this. The current processor slot can also retain a phase-2 parent
request while nested service needs the same slot. These are source-level risks;
no current sealed-GSI trace is claimed to establish which caused TFIB failure.

The preferred contract is:

- Fast admission of a source-qualified no-safepoint group checks the *actual*
  current physical spans and existing execution ownership. It need not create
  persistent service state, allocate a record or issue a VM-global attempt ID.
- A short request publishes a transient service hint before its first write.
  Precise roots remain in the mapped GVM frame. The hint describes need; it is
  not an owned construction result, RC bank or delivered object.
- The C service validates its refill outcome in the decoded prospective retry
  coordinate without assigning that pointer into the resumed registers. Unknown
  or insufficient outcomes retain custody or fail through the existing bounded,
  nonallocating path. Do not redispatch the same empty service indefinitely.
- Settle that pure hint before calling Scheme interrupt/effect code. Clearing it
  does not clear roots or release a section. Owned rest/FFI construction results
  and their install/query/ACK obligations must keep their separate lifecycle.
- Existing internal return restores registers and removes its frame. At the
  actual retry label, reload/recheck current hp/fp, section authority and epoch.
  Never overwrite those locals with a pre-effect snapshot. Any later effects or
  GC require a fresh check, even if the label or GC epoch happens to match.

A captured continuation retains the immutable retry recipe and ordinary precise
roots, not a linear physical grant or a naked service-record pointer. Each
multi-shot resumption reacquires authority for its own execution episode. Unknown
native effects cannot silently join a no-safepoint group: end the group and use
the existing explicit effect/root contract. Do not change interrupt scheduling
policy to hide the pending-slot conflict.
