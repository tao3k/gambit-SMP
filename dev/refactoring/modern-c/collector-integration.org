Private collector records live in the existing VM-owned root-round allocation.

the work record does not carry another general execution context. No second
root namespace or build profile is introduced. Owner memory remains where the
published mutator/FFI code expects it; moving unrelated native lifecycle/layout
prototypes into this result would create an unjustified migration dependency.

The published PSTATE layout still contains dormant historical scan fields.
They are layout storage, not a second active collector or a fallback authority:
all current copy/scan/transport callers use the worker record. This cut retires
the old execution paths and preserves the established low-level offsets; it does

its own consumers and module-rejection evidence. The metadata matrix counts the
new storage in full and subtracts no fictional savings from dormant fields.

** Conditional interval bound

Let H be a half-section, C=H-FUDGE-3, U the sum of small worst-case requests,
m their maximum (one if empty), L the count of requests larger than C, and
B=U+floor(U/CHUNK). Each request must fit H-3. Reserve before flip:

#+BEGIN_EXAMPLE
K = W + 2*L + min(floor(B / (C-m+1)), floor(2*B / C))
R actual stack-restoration sections + K actual copy sections <= current pool
#+END_EXAMPLE

The small no-fit rule charges every retired small section at least C-m+1
words. Threshold links charge actual successful payload words. Each large
request adds at most a transition into an isolated large section and back into
a small section. A final large arena must make that counted transition before
handoff, because it has no execution fudge. =RoundCapacity.lean= owns the
conditional arithmetic; =copy_pool= in existing =round_capacity.qnt= owns
collective observation, sealed-prefix grants and final-tail/refusal histories.
Neither proves the C source premises or hardware memory order by itself.

The adjacent-bin certificate also charges every small no-fit occupancy plus
its incoming request above C. Each successful word participates in at most two
such pairs, so closed-small-sections*C <=2B. Taking the smaller sufficient bound
avoids the old formula's singular pessimism when m approaches C. A near-C native
vector must now copy successfully; rejection there is a retained predecessor
counterexample, not accepted behavior.

This is still sufficient rather than optimal packing: conservative refusal
remains possible near actual pool pressure. Native admission composes the
production fit function (including a one-section-short negative control) with
actual all-R known-refusal/thaw/retry execution using invalid worker admission.
It does not claim a production low-pool exhaustion experiment. The QNT finite
model separately checks whole-pool shortage; C fit/thaw coupling remains an
explicit source-refinement obligation. No native pool, heap or deadline is
changed to manufacture a test refusal or acceptance.

=copy_first= / =copy_past= seal actual physical section identities. Actual refill
uses only that prefix. All R active stack spans and R-W disjoint bottom/fudge
intervals are checked before flip. A root owner remains its original native
owner even when another worker scans its roots. Normal source contenders see
forwarding before obtaining a grant: the old cancellation/refund path is removed.
A changed header under held source authority is an unknown foreign writer and
retains the pending interval; it cannot justify a refund.

** Decision, refusal and unknown custody

The coordinator publishes one decision through the existing all-R barrier;
every participant records observation before flip. Known refusal checks that
no task was claimed, retires READY tasks as REFUSED rather than DONE, releases
the shared globals snapshot, reopens RC and returns the unchanged source epoch.
A new collection receives a fresh task epoch. Construction rollback is allowed
only when that known pre-copy receipt proves source parity/cursors unchanged.

Unknown native allocation/free has =ALLOCATING= and VM-owned queue,
replacement and retired slots. Unknown copy/Tail grants likewise remain in
stable VM records. A later planning/cleanup attempt refuses to reset those debts.
The controlled native test induces an unsettled record; it does not establish
real OS owner-death detection, automatic takeover or healthy-VM isolation. Those
remain separate lifecycle obligations. Partial unknown collection is fail-stop;
only a known entirely unstarted refusal returns to Scheme.

* Mandatory architecture questions :audit:

- Why is this a responsibility replacement? Source identities stay in the frozen
  RootOrigin population; assignment is modulo W, destination ownership lives in
  worker arenas, physical restore/cleanup stays with all R native owners. Old
  implicit context heap refill and post-reserve losing-copy refund are removed.
  A counterexample is an unplanned refill, repeated charge of a source extent,
  duplicated Tail, or task DONE before physical restoration.
- What Gambit advantage is amplified? Precise effective frame roots and explicit
  safepoints supply a closed graph to the planner; lazy captured stack frames
  copy under one frame authority and remain reusable by multi-shot map/wind
  consumers. No one-shot rule or actor-private heap constraint is introduced.
- What is gained, at what cost? W may be1/2/3 for R3 with complete canonical roots;
  source losers acquire no destination interval. Initial grants are R+W rather
  than2R, but K and actual pool are separate. Fixed metadata, bitmap, one extra
  typed traversal, native queue growth and conservative refusals are costs.
  Pause, throughput and RSS net benefit remain unmeasured.
- Does this solve unknown owner retirement? No. An unsettled journal prevents
  source/grant release and is fail-stop. The induced-record child checks that
  boundary; actual owner-death detection, safe takeover and healthy-VM isolation
  belong to the third result and cannot be claimed from this test.
- What remains after this result? Owned lifecycle/startup/affine cleanup, then
  request/waiter/service separation and complete independent SMP populations.
  The13-item catalogue is not a percentage; the4-result architecture and12-family
  native ledgers retain distinct evidence and blocking conditions.
