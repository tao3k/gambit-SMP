| key | ordering | premise | obligationId |
|---+---+---+---|

** Gain

| key | benefit | overhead | positive | refutation |
|---+---+---+---+---|
| immutable-install | static lifetime certificate may erase per-call counter traffic | provider/lifecycle closure and immutable targets still need proof | no live rebind/unload or premature base teardown; stable family for all origins | adding hot replacement or global counters without a use case increases maintenance/work |
| scope-amortization | one lease can cover the whole native prefix dependency bundle | one enrollment and one settlement per scope in replaceable mode, not per EXT read | all nested calls and free/log dependencies use captured bundle | reload mutable GSTATE for each dependency mixes generations |
| allocation-origin | match free to old allocator family after call finishes or replacement | one origin hold per outstanding non-null or unknown allocation | reuse existing stable allocation/cleanup ledger | zero readers does not imply allocator code or family can retire |
| debug-default | no new log-stream lease is needed for default-disabled logging | debug override requires separate ABI and FILE lifecycle qualification | both configured cohorts retain DEBUG_LOG and DEBUG_ALLOC_MEM disabled | conditional logging cost must not be charged to ordinary default allocation |
| unknown | zero blind free/realloc replay after unknown completion | provider/stream/root/intent retention may be unbounded | same-operation backend receipt proves known result | freeApplied ghost or a timeout cannot authorize reclamation |
| c23-baseline | unify checked target/ownership services in modern C | legacy compatibility, native ABI and loader qualification remain | retire managed raw table reads only after caller migration | Zig does not remove allocator family, I/O or C lifetime proofs |
