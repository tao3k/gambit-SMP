* Source responsibility and retirement :c23:smp:gc:
:PROPERTIES:
:CUSTOM_ID: modern-c-write-authority
:AUTHORITY: GambitWriteAuthority; GambitRootTaskCRefinement::writerAuthority
:STATUS: SOURCE-REPLACED; SELECTED-NATIVE-PASS; WHOLE-ADMISSION-OPEN

The C component grants generation-bound write permits. It carries no Scheme
payload, roots or physical-stop receipt. Its single packed word couples actor,
generation, closed admission, live permits and spent permits. Release follows
the producer's real last store or borrow. Close rejects new permits while
preserving existing writers; a closed-and-drained CAS transfers both owner
permits to the next checked generation.

* Configuration and generation have different completion boundaries :build:darwin:
:PROPERTIES:
:AUTHORITY: GambitRootWorkerExit::configureProbes; configureTemplates; buildRelocation
:STATUS: CURRENT-SOURCE-BUILD-AND-REUSE-OBSERVED
:END:

The same Bazel-derived profile, configure and Make remain the only build
path. No flag profile or task executor is added. Standard Autoconf cache files
are task-owned observations keyed by exact input request. Three =AC_CACHE_SAVE=
boundaries retain completed compiler, OS and option observations before later
work can time out. A cache file is not a completed configuration receipt.

The shared owner distinguishes full configure, template emission through the
existing =config.status=, and exact completed reuse. Template-only reuse requires
unchanged configure policy, tools, environment and non-template inputs, plus
intact previously generated outputs. Its proof retains the original configure
receipt and a separately completed template-emission receipt. Unknown emission
cannot replace the prior proof; unexplained same-request output changes refuse.

The object context now records the last successful Make result's native
parameters, archive membership, public/feature header hashes and tool/environment
identity in the existing source-state record. Reconciliation preserves it;
failed configuration/build cannot overwrite it. Merely repeating a relocation
declaration no longer deletes objects. The initial record was adopted only after
the completed runtime and every artifact byte were authenticated; an attempted
child-tool call in the first adoption was rejected by process auditing. A
duplicate build request without its required prior lineage was also refused
before any compilation. Both failures remain recorded.

The native relocation adapter validates all old/new paths and predecessor
hashes before mutation. Only literal native file/object lists and native
dependency rules normalize moved paths. In root Make replay metadata it removes
only the exact task-owned, hash-keyed =--cache-file= argument. All other flags,
Scheme commands, preludes, module edges and unknown effects remain significant.
The generation entry is physically disabled during the native Make phase.

* Hash-tool dependency is caller-owned :toolchain:
:PROPERTIES:
:AUTHORITY: GambitModularSmpValidation::hashToolVariable; hashToolContract
:STATUS: ENVIRONMENT-SELECTED; NO-FIXED-PATH-FALLBACK
:END:

The Scheme runner reads the required =GAMBIT_SMP_SHASUM= environment variable
once before hashing. It requires an existing absolute tool path supporting the
=shasum -a 256 --= interface and records both the path and tool SHA in the
receipt. Missing or invalid input fails explicitly; the runner does not select
a system binary on the caller's behalf.

The existing CI installation step preserves an explicit setting; otherwise it
resolves =shasum= through its tool environment and exports the result through
=GITHUB_ENV=. The existing generator derives the environment variable name
from native SysML and checks that the Scheme consumer reads that name. This is
tool-dependency injection in the existing entrypoint, not a new build profile.
