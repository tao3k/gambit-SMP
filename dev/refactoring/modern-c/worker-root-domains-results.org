The =modern-c= C runtime now admits selected =1 <= W <= R= rounds. This is an
actual dispatcher, restoration, cleanup and phase-completion replacement. The
atomic request defaults to all workers and is a VM-internal ceiling, not another
Bazel/configure profile. Every admitted request is clamped to the frozen root
population; actual W is published only after physical restoration admission.

The [[file:models/sysml/root-worker-exit.sysml][SysML authority]] owns three realizations and the seven worker admission
conditions. [[file:root-worker-exit.org::#root-phase-realization][Generated Org tables]] and [[file:diagrams/root-worker-exit.svg][D2]] are projections. The [[file:models/sysml/root-task-c-refinement.sysml][C refinement contract]]
now has twelve operations. [[file:../../modeling/ascent/root-worker-exit.rules.scm][Actual ASCENT DSL]] qualifies the selected source/native
slice and keeps full unequal-count and whole-runtime retirement queries empty.
QNT and Lean files were not rewritten or duplicated.

Only W slots receive current copy arenas, private queues/frontiers and scan
participation. The VM still has fixed descriptor storage for all possible slots;
an inactive carrier's legacy instrumentation pointer is not collector authority.
Native controls check its reserve pointer is null and its root-domain receipt has
=source_worker=-1=.

** Complete round sequence

1. All R managed carriers stop and publish complete context root views.
2. The coordinator snapshots the atomic worker ceiling and examines actual stack
   restore lengths. Every nonworker needs a bounded empty heap with heap fudge.
3. If that restoration condition fails, this round uses W=R within the same new
   role architecture. All initial grants still fit the old =2R= envelope; no heap
   is added to make a requested W<R pass. Full copy packing remains open.
4. The setup barrier publishes actual W, R restoration grants and W arenas. Only
   these W executors service all R PREPARE/STRONG/WEAK tasks. Their termination
   counter has W participants; every physical barrier still has R carriers.
5. After weak descendants drain, W tails and retired prefixes transfer to W
   distinct recipients. The other R-W contexts accept their own empty span.
6. Every owner copies its active stack and sets the physical =restored= receipt.
   One additional all-R barrier precedes all native cleanup callbacks.
7. W workers finish their reached hash tables; all R native owners independently
   claim and finish their CLEANUP task, including inactive collectors.
8. Cleanup completion, public resize/capacity outcome, GVM pointer/limit
   finalization, root thaw and final acknowledgement gate actual Scheme resume.

A physical stack-copy receipt does not authorize execution. In particular,
=move_continuation= prepares physical stack storage; =prepare_mem_pstate= still
finalizes GVM fp/hp and interrupt limits after cleanup and capacity outcome.
Collecting/reentrant native cleanup is not admitted by this slice.

** Conditional correctness and counterexamples

| Obligation | Source argument | Counterexample prevented / remaining limit |
|------------+-----------------+---------------------------------------------|
| All R roots serviced by W | Every active worker iterates all R tasks; per-epoch claim is exclusive; coordinator requires exact predecessor completion | Merely lowering worker_count while dispatching roots by worker index loses R-W domains |
| Scan termination | All W workers begin active, finish root production before declaring idle, and drain chunk/Tail work before phase advance | Decrementing an R-sized counter from W workers never terminates; counting inactive owner services as scan workers is invalid |
| Unique copy accounting | W worker identities have W distinct recipients; retired prefix credit transfers once; other R-W spans carry zero copy credit | Reusing one tail for multiple contexts double-counts or overlaps copied objects |
| Restore capacity | One shared partition function drives pre-flip admission and actual empty-span bounds; insufficient-fudge cases choose W=R before flip | Accepting a tiny nonworker heap then computing limit-fudge can construct invalid bounds after flip |
| Native affinity | Direct owner-domain service uses actual original PSTATE and pthread; token namespace is disjoint from worker tokens | Scheduling an affine destructor on a different worker changes library semantics |
| Final resume | All R physical stack copies precede cleanup; task completion and final prepare/thaw follow the public result | A physical receipt or worker idle result alone cannot permit Scheme reentry |
| Unknown join | Existing empty unpublished abort isolation excludes held actor from both R and W; healthy registered domains still participate | Unknown published/native writers and arbitrary collector death remain unqualified |

No copy/restore grant or unknown completion is silently duplicated. An unreturned
native cleanup callback retains its claimed task and prevents unsafe resume; this
change does not create an asynchronous release coordinator or make an unknown
shared-heap writer safe.

* Gambit leverage and existing model responsibilities :architecture:

The native case demonstrates that a worker on another physical carrier can
repair roots for a map continuation that resumes repeatedly on its owning
execution context. Captured frames, shared aliases, root masks and dynamic-wind
stay Gambit's semantics. Splitting work authority from context/native ownership
amplifies that portable explicit-stack design; it does not impose isolated
process heaps, message copying or one-shot continuations.

The same design separates three completion facts: W scan executors drained,
R contexts physically restored, and R affine cleanup services completed. An
OS-thread count, one idle counter or one task flag cannot substitute for all three.
Physical carrier migration and cleanup reentry need their own ownership proof.

Existing QNT owns bounded task/producer/termination interleavings. Existing Lean
owns coverage, interval/accounting algebra and refinement premises. SysML assigns
those owners; the current work supplies C/native adapters. No duplicate scheduler
model, repeated theorem claim, or general C memory-model proof is introduced.
