** Actual C chain and source ownership :source:refinement:

| Actual endpoint | Responsibility / condition | Removed behavior |
|-----------------+----------------------------+------------------|

| =___root_task_claim= | Same mutex checks source, epoch, published executor, current PSTATE and READY before CLAIMED | Scan eligibility inferred merely from caller/root head |

The actual GC caller carries =rc_epoch= as an unboxed C integer through the
existing phase calls. RC cell addresses still come from the task's domain;
=___ps= continues to supply the existing copy resources. The source gate spans
list reads and synchronous source-slot rewrites. Released ownerless nodes may
disappear before enrollment, as in the preceding RC contract. No RC source
address is queued as a child scan; copied-heap descendants remain owned by the
existing collector protocol.

A completed RC task is not a completed collection. Its source remains FROZEN
after lease release. Existing barriers and the actual GC epilogue, not a public
Boolean seal or root count, authorize reopen. No generic resume/requeue API is
exposed to native callers. Unknown scan effects keep their lease/state; this
does not implement worker-death progress recovery or healthy-VM isolation.

Source attachment/closed-roster lifetime must protect the pointer before any
task API loads metadata. Epoch checking does not resurrect a stale raw pointer.
One inline record is reused only after the prior task completed and the round
reopened the domain. Counter exhaustion rejects publication before mutation;
recovery from that exhaustion is not a native claim. Current executor admission
remains source-owner/current-PSTATE; this is not W!=R qualification.

** Replay and shrink contract :pbt:counterexample:

The existing Scheme/Make test path builds =root-task.scm= once. Its structured
trace contains an opcode, relative epoch and logical actor; it contains no raw
address or opaque generated bytes. An independent observable oracle recomputes
expected acceptance/state/phase/lease/epoch after every candidate edit.

Each replay starts a fresh executable process and performs real warm GC before
the trace. An unfinished prefix is never reset in-process to run another trial.
The child drives the actual C task functions and byte-only RC scanner, writes
its outcome and terminates without running Scheme allocation under a frozen
source. This deliberate process boundary is not production unknown-task recovery.
Real moving-object scans and normal reopen are tested separately by the existing
RC, map/multi-shot and frame-root consumers.

The negative calibration changes only the invocation adapter: a requested valid
finish is sent with an old epoch. The C implementation must reject it and keep
SCANNED/FROZEN/lease1. The oracle disagreement must survive replay and shrink
to publish -> claim -> actual scan -> finish. The certificate means deletion
1-minimality for that failure class; it is not global minimality. No new runtime
fault flag, configuration layer, Python test or solver is introduced.

The first native run passed24 positive cases/864 actions but correctly exposed
the adapter's process-status decoding error during negative calibration:
Gambit returns the raw wait status18176 for child exit71. That failure remains
retained. The corrected adapter checks the encoded status; it does not turn a
child mismatch into success. Controlled thread schedules remain future work.

The Scheme/GVM semantics, exact tagged roots, copying algorithm, trampoline and
multi-shot continuation representation stay intact. This cut makes the native
root source and scan obligation explicit, so a future executor can be selected
without locating roots through its carrier. It does not replace Gambit's
continuations with one-shot effects or assume Erlang's isolated heaps. Modern
C provides the mechanism directly; Zig cannot remove these ownership duties.
