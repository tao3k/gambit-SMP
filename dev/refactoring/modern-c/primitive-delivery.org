The two-path cut replaces the unchecked safe-mode increment specialization in
=make-ref-set!-cas!-inc!-expander=. A general vector admits arbitrary values;
increment still requires fixnum operands. Existing operand binding evaluates
arguments once. The existing conjunction chain checks vector, mutability and
index before reading the element, then checks delta and element before the
atomic mutation or authoritative Scheme error fallback. The two-argument form
uses its existing default delta. Other specialization paths remain unchanged.

Native observations (local locator: =../../../.cache/research/legacy-evidence/evidence/refactoring/modern-c/vector-increment/tests.json=; unavailable in a clean checkout) retain the real old-compiler counterexample: it compiles
the fixture but its executable fails with the invalid-delta error. The new
compiler builds incrementally in 7.858 seconds. The fixture passes interpreted
and compiled execution, checks rejection without mutation and verifies the old
value returned by default and explicit increments. Both unchanged affected
original GSC files pass. Only one Scheme compilation and two module-link
generation actions appear in the core build; unrelated module generation is
reused in the same SDK and profile.

* Benefit and scope matrix :assurance:

| Mechanism | Benefit | Added work | Boundary |
|-----------+---------+------------+----------|
| Delta validation | Reject invalid third operand before mutation | One fixnum predicate for explicit delta | Safe specialization only |
| Element validation | Reject non-fixnum stored value | One vector read and fixnum predicate after index admission | No typed atomicity against concurrent arbitrary-value replacement |
| Shared generator chain | Preserve one-evaluation binding and error fallback | Existing short-circuit control nodes | No parallel primitive or new namespace |
| Existing incremental Make | Reuse unrelated generated modules and objects | One affected compilation plus two link-generation actions | Not a full new bootstrap or all-original-GSC acceptance |

QNT and Lean have no new duty here: the source contract is validation dominance
and existing operand binding, witnessed by native counterexamples and affected
cases. It adds no concurrent scheduling protocol or new representation law.
The native SysML projection and shared ASCENT policy retain the five submission
gates and reject absent native evidence, stale trees/artifacts/profiles and
model-only admission. Portable generated C, tail calls, multi-shot continuation
and GC root protocols retain their existing contracts. Global GSC/SMP acceptance
and broader atomic element ownership remain separate programme obligations.
