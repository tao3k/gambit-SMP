The existing SysML five-role CSectionRole model owns caller evidence and
qualification duties. Its SDK projection in =tfib-producer-retry.org=
retains source hashes and compares producer and consumer separately with
the historical native role report. Missing consumer ancestry is unknown,
not a match. Historical numeric counts are not a current emission census.

The actual =targ-plan-compilation-unit= selects =configured= if any of the
four C lists is nonempty, before consulting the five-role partition. Its
procedure placements are built only when that configured predicate is
false. Therefore merely producing five role labels does not remove the
whole-unit layout dependency. Keep that fallback until the following
complete qualification exists for the changed module.

* Replace a responsibility, not a compiler option

| Responsibility | Retained authority | Proposed replacement and retirement condition |
|----------------+--------------------+-----------------------------------------------|
| Scheme control and GC maps | Existing GVM points, frames, root maps and continuation semantics | Physical placement consumes these immutable identities; no renumbering or one-shot restriction to simplify C layout. |
| Physical host selection | Existing configured/procedure choice and host graph | Use explicit dependencies of each generated component after the module's five C roles are qualified. An unknown global macro/private-label effect conservatively connects all affected hosts. |
| Resource declarations | Per-host read/write/unboxed resource closure | Each selected host owns all explicit and implicit spills/reloads. The historical seven undeclared-r4 failures and 21 resource definitions are concrete acceptance cases, not permission to reuse the module-wide union. |
| Foreign C placement | Declaration order, CFUN_SELECT and generated entry/return descriptors | Preserve the opaque body, preprocessor effects, conversion/error protocol and root ownership. A compiler-produced wrapper tag does not prove body neutrality. |
| Module setup and objects | Existing module/linker identity and ordered initialization | Preserve setup exactly once and object/code/root lifetime. Zero initializers or objects in the numeric sample proves no global absence. |

Use the already-required compilation-unit plan as the semantic owner.
It must carry component origin, required resources, label/frame consumers,
opaque effects or explicit unknowns, and the chosen physical host. Reuse
existing labels, Scheme names and Make entrypoints. Do not add a parallel
runtime namespace or infer C dependencies from a token whitelist.

* Numeric caller qualification as one complete example

The SysML-linked source cases cover three distinct requirements:

- The raw declaration includes internal =mem.h=. Resolve the real headers,
  macros and target ABI. File-level location alone does not discharge them.
- =##mult-inner-loop= writes existing bignum payloads through C pointers
  and defines a preprocessor macro. Preserve object lifetime, preprocessing
  order and return/error behavior. It is not a pure numerical expression.
- Four IEEE bit-conversion c-lambda sites have simple-looking bodies but
  still use typed argument/result conversion. Qualify conversion allocation,
  root publication and exceptions in the real wrapper and entry stub.

All five roles must be considered together. The native object observation
only qualifies compilation of its retained DEV variant. It does not
qualify every callback, the current compiler graph, or target self-hosting.

* What work can actually disappear

| Mechanism | Work potentially removed | Added work and falsifier |
|-----------+--------------------------+-------------------------|
| Procedure-sized physical C hosts | One optimizer control-flow graph combining unrelated Scheme procedures | More C functions, host dispatch and local declarations. Reject if code-point, tail-call, continuation, root or conversion behavior changes. |
| Per-host resource closure | Inheriting unrelated host resources or missing implicit r4/unboxed uses | Compute exact closure and check every host. Reject missing read/write/declaration membership; compilation alone does not prove correct GC maps. |
| Stable semantic/placement separation | Rebuilding semantic identities merely to change physical layout | Maintain one dependency plan and current source ancestry. Reject if a layout edit changes frame/point/module identity. |
| Keeping one translation unit in this cut | No claimed reduction in complete-TU preprocessing or parsing | Headers/macros and total source still enter GCC. Per-function placement is not translation-unit splitting. |
| Any later TU partition | Potentially independent native compilation and incremental reuse | Separate proposal: C linkage, declarations, private macros, module tables and new include/build dependencies must be qualified. Not assumed here. |

GCC memory is not bounded solely by maximum host size: whole-TU data,
inlining, compiler arenas and retained optimization structures also matter.
The [[https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html][GCC optimization manual]] explicitly describes the memory cost of large
functions. Public [[https://github.com/gcc-mirror/gcc/blob/master/gcc/ggc-page.cc][GGC source]] shows compiler allocation contexts, cached pages
and heuristic collection. These mechanisms support treating host size as
one factor, not as a complete memory bound. This is an architectural
inference, not a source-version match or diagnosis of the installed GCC.
No measured memory reduction is claimed from the source plan. The user-
terminated approximately 20 GB compilation and the historical 24.629-second
DEV numeric object are different observations, not a matched speedup ratio.
Both remain retained with their exact source periods and resource limits.

* Whole-delivery acceptance and falsification

1. Freeze complete current host sources, resolved headers/macros, typed
   argv, cwd and host ABI. Explicitly activate an existing resource guard;
   possessing a guard API does not qualify its actual use.
2. Produce the complete compiler graph through existing Make. Emit the
   selected host plan and resource closure on the existing diagnostic port,
   without inserting C comments that alter =__LINE__=.
3. Compare semantic points, frame/root descriptors, raw C bodies and their
   order independently of the intended host/resource differences. Include
   preprocessor-sensitive opaque code, private labels, conversions, module
   setup and callbacks as falsifiers; do not force an unqualified component
   into procedure mode merely to lower memory use.
4. Compile and link under the unchanged GCC/C23 profile with observed
   resource limits, natural completion and source-stable inputs. Compare
   preparation, preprocessing, native compilation, linking and runtime
   costs separately; a faster host-emission sample does not qualify them all.
5. Regenerate all target C, bootstrap the target and perform same-GSI A,
   then the original 295/300-second p2-to-p1 family. These remain separate
   gates. Do not count an object, role count, macro graph or model PASS as
   current full producer ancestry or SMP progress.

This is source/native compiler refinement. Existing Quint owns request,
retry and exit histories; existing Lean owns frame and interval geometry.
No additional arithmetic or temporal proof copy is required for C-role
classification. Any new runtime temporal effect must first be mapped to
its existing owner before implementation.
