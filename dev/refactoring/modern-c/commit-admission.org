* Current Process and architectural learning

:EVIDENCE_CLASS: candidate-source; scoped-native-controls; conditional-models

The current cut is =source-cut= plus native catalog and role observations. Its
source removes root and collector-work payloads from the carrier and changes
actual consumers. The final source-generated runtime now completes the bounded bootstrap; the
previous independently completed runtime keeps its historical identity. Product
reconciliation is closed for the declared families; semantic/lifecycle admission
remains open. The
whole execution/participation/collector separation is not complete. The process
matrix gives each stage's exit criterion rather than using a percentage.

The concrete lesson is that representation, participation and lifetime are three
different contracts. A carrier can shrink while the VM grows. A worker pointer
can be explicit while its allocation and logging still require the carrier.
Phase assertions can reject bad ordering while not proving barrier publication
or participation progress. This follows from actual =cleanup_pstate=,
=mark_execution_roots= and worker allocation consumers, not language branding.

Immediate advantages are an explicit root origin, separate queue/cursor custody,
one shared GC capacity outcome, and compiler-visible removal of old raw fields.
The new representation is a base for independent scheduling and future nursery
policies; those benefits require subsequent replacements and native evidence.
The earlier role-only cut measured +3080 VM bytes for its recorded 64-slot,
64-bit configuration. That is not a measurement of this complete 144-path
candidate. Root indirection, phase checks and one extra collective
are added; the full current representation/capacity cost still needs a matched
measurement. No scan reduction, pause improvement, speedup or solved 12/12 claim
is supported. See [[file:runtime-role-realization.org][source realization]] and [[file:runtime-role-matrix.org][the benefit/cost matrix]].

** PVM cooperation and semantic authority
[[https://www.iro.umontreal.ca/~feeley/papers/FeeleyMillerLFP90.pdf][Feeley and Miller, A Parallel Virtual Machine for Efficient Scheme Compilation]],
sections 1-2, motivates cooperation between machine-independent optimizations
and target information. Our architectural inference is to complete native
contracts in Scheme and share them among modern C and future consumers. This
role cut exposes consumers but does not complete that generator transformation.
The paper distinguishes continuation labels from Scheme call/cc objects; our
question therefore requires both the physical frame ABI and multi-shot language
semantics. No historical benchmark ratio is transferred to this refactoring.

** Safepoints, foreign participation and bounded progress
[[https://kcsrk.info/papers/retro-parallel_icfp_20.pdf][Retrofitting Parallelism onto OCaml]], section 3.4, cites Feeley's 1993 polling
algorithm and identifies nonallocating loops as a reason for additional safe
points. We learn that root freezing, compiler placement and participation must
compose. The current phase model does not prove that a blocked or spinning
processor ever arrives. The question requires that progress premise to be
exposed rather than inferred from a closed participant array.

** Stack/control cooperation without one-shot substitution
[[https://kcsrk.info/papers/retro-concurrency_pldi_21.pdf][Retrofitting Effect Handlers onto OCaml]], sections 4-5, studies stack/control
and C interaction together, and deliberately uses one-shot continuations.
Gambit's repeated continuation restoration is a stronger requirement for this
design. Learning from that cooperation does not justify consuming a Scheme
continuation on first use. The real map/capture/GC/repeated-resume chain and its
native callback boundaries must pass on the newly generated cohort.

* CHECKED Ownership refinement of the original failures :source:ownership:models:
:PROPERTIES:
:CUSTOM_ID: original-runtime-ownership
:AUTHORITY: GambitModernCCommitAdmission::threadLease and pipeOwnership
:END:

#+begin_abstract
The replacement unit is the owner of a whole critical operation. The thread
helper owns acquisition through decision and release; interrupt dispatch is a
subsequent action. A pipe pair owns its shared FIFOs and predicate mutex from
construction. The pre-existing failure models remain unchanged: DEV records
how these actual owners satisfy their premises, and records what they do not prove.
#+end_abstract

The sole caller of =##thread-lock-remove-btq-toq!= is interrupt propagation.
Its callback must return through the helper, without user dispatch or its own
unlock. Retry paths release before retry. Terminated, running and queued outcomes
all leave the lease through one final release. The Scheme generator retains
root/continuation semantics; this change adds no one-shot continuation restriction.

The actual lock chain is =macro-lock-thread!= -> =macro-lock-btq!= ->
=##primitive-lock!= -> =___PRIMLOCK= -> =___TICKETLOCK_LOCK2=.
The current C consumer takes a relaxed ticket, waits with an acquire load,
and releases with a release fetch-add. The model assumes this synchronization;
it does not prove every target fallback, ticket wrap or scheduler progress.
The unlock moved to the helper, so its release orders the internal decision
before the later interrupt dispatch. No weaker memory order was introduced.

The three private vector/string/u8vector constructors accept an optional existing
mutex. Ordinary ports still create their own guard. The pipe constructor creates
one shared guard before either endpoint becomes reachable. Both directions share
it; readers must atomically register their wait while releasing that guard.
The implementation removes one mutex allocation per pair, but serializes both
directions. It does not establish a throughput improvement or bounded wait latency.

[[file:../../../evidence/research/revision-admission/ownership-model-reuse.json][Existing QNT receipts]] retain their original model hashes and negative controls.
Thread release safety assumes abstract atomic lock operations. The pipe model is
one bounded direction, two messages and one buffer item; it does not cover every
chunk/timeout/GC schedule. C memory-order and source-to-model refinement remain
separate obligations. No QNT or Lean copy is introduced.

** Checked arithmetic as a concrete semantic obligation
The unchanged original =fxmul.scm= requires intermediate overflow to raise during
=(fx* -1 (##least-fixnum) -1)=. Generated C branches on a checked operation's success
predicate. The old constant-negative-one specialization assigned =FIXNEGP= to the
result and returned success unconditionally, allowing a failure value into later
arithmetic. The specialization now delegates both result and success to
=FIXNEGP_NOTFALSEP=. This removes duplicated success ownership; it does not freeze
the old C macro spelling or claim completion of the multicore architecture.
