* OBSERVED Original p11 physical failure
:PROPERTIES:
:CUSTOM_ID: vm-resize-physical-failure
:END:

Direct LLDB process-memory observations use offsets compiled from the exact
configured predecessor header. The executable is unchanged. They show target
11 with one active participant, six physical sections, two assigned and one
stack section. Collection returns with six sections. New contexts 1 and 2
consume the four remaining sections; context 3 enters with six assigned and
fails. The initial root views and list addresses are retained in evidence.
The old max_heap=0 decision does not apply its nominal target floor. This
evidence is causal for the observed exhaustion, not a speed or regression claim.

* OPEN Actual replacement and refusal boundaries
:PROPERTIES:
:CUSTOM_ID: vm-resize-source-protocol
:END:

1. The old closed collective roots the request in the VM ledger. A future
   target is not a current GC participant census.
2. Collection retains actual assigned regions and accounts for each real
   post-GC fudge-restoration endpoint. A policy cap cannot free live intervals.
3. The coordinator reserves every additional physical stack/heap pair before
   initializing any new context, with checked count/budget bounds. Setup binds
   the exact grant and cannot fall back to shared/unavailable regions.
4. Created OS threads park before TLS/Scheme participation. Count publication
   requires all setups and creates; a new-set completion barrier separates
   membership commit from normal synchronization/entry.
5. VM thunk -> context startup root -> rooted marker allocation is explicit.
   Threads reload after the sync loop; entry markers invalidate on retirement.
6. Known create failure aborts parked children. Refund and cleanup require
   successful join of every created child. Unknown calls or failed joins keep
   the fixed ledger, root and physical grant; GC, reuse and cleanup are denied.
7. Shrink rejects domains with RC/native borrows, foreign effects or additional
   retained C markers. Admitted owner exit invalidates its entry marker, joins,
   and transfers still objects to an active collector origin before metadata
   cleanup. Context retirement is not permission to free shared objects.

The POSIX create/join adapters consume their returned error number directly;
pthread errors are not errno observations. Common initialization precedes the
native create call, leaving no fallible common initialization after publication
of a native thread. POSIX cancellation is excluded in the coordinator's resize
scope. A nonlocal escape or owner death without a stop receipt is not silently
converted to a rollback or successful helper takeover.

The current C barrier and raw FFI facilities still need refinement/admission.
Unknown-result retention is a safety boundary, not a liveness guarantee. Raw
borrowers that bypass refcount/effect registration, destructor affinity, nested
continuation escapes and old processor-object identity remain mandatory gaps.
The single rooted startup endpoint does not qualify the legacy SFUN wrapper's
unregistered local argument as a GC root.

* OPEN Benefit and peak frontier
:PROPERTIES:
:CUSTOM_ID: vm-resize-cost-frontier
:END:

| Responsibility | Work/capability gained | Added cost / qualification |
|----------------+------------------------+----------------------------|
| Physical grant | Remove per-context opportunistic startup allocation and fatal fallback | Fixed two pointers/status per slot; reserve only the deficit beyond usable capacity |
| Publication | Remove committed members without a created OS thread | One gate mutex/condition and a completion collective |
| Entry roots | Root and reload across pre-publication GC, sync and marker allocation | Two root cells per context plus one VM root; scan those cells |
| Failure custody | Known failure rolls back; unknown cannot reclaim or reuse | Fixed progress metadata; retained memory and possible blocked progress |
| Retirement | Preserve shared still objects instead of unconditional freeing | Admission/list walks; RC/effectful domains refused until their own contracts close |
| Peak space | Explicit already-assigned + startup pairs + actual resume demand | No peak-RSS or elapsed speedup claimed; necessary capacity is not automatically new architecture overhead |

The old six-section failure needs twenty startup sections for ten new contexts
on top of two already assigned, not a larger arbitrary default heap. At 64-bit
131,072-word sections, this is physical payload accounting, with allocator
metadata and existing capacity considered separately. Allocation failures,
checked arithmetic, copy/restore intervals and returned ownership must be
qualified against actual callers.
