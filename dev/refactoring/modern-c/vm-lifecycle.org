** Three different facts, never one stopped flag

1. ABORT before RUN proves a native actor cannot acquire PSTATE or Scheme roots.
   An unknown create/join retains its descriptor and forbids slot reuse/global
   free; the unpublished initialization grants and roots can be refunded.
2. A previously RUN actor needs owner-side data closure before a smaller member
   set may collect without it. An unknown join keeps native identity in custody.
3. Native join success is the OS resource acknowledgement. Data closure alone
   never permits freeing the VM/control record or replaying an uncertain join.

Known constructor rollback releases only completed setup stages, in reverse
order, before any LIVE publication. An unknown foreign release keeps its
in-flight object, original function/payload and charge, and never replays it.
Live affine foreign resources refuse migration; ordinary still nodes transfer
under the stopped old membership. Arbitrary unregistered aliases, asynchronous
native death, permanently blocking destructors and forced resource reclamation
are not admitted by a timeout or by these receipts.

** Exit capability is narrower than an owner-thread match

Only =run_startup_root= marks its exact activation as the terminal native
stack. Public SFUN/host entries default to a nonterminal record. Retirement
requires either no native activation/borrow or the sole startup marker plus
its =___call= lease; a nested host marker cannot lose its external C return.
The actual lifecycle fixture constructs and kills a host marker and checks
retirement/cleanup refusal before the debt is released. Arbitrary direct
private-C calls into the collective outside the managed entry contract are
not granted safe abandonment.

The handoff result distinguishes READY, GC-retryable foreign garbage and
BUSY owner/request/effect debt. Only the second class permits one complete
GC/owner-drain retry. Unknown effects and live host calls do not become safe
because GC ran or because a wait expired. The original QNT native-pin law
supplies the temporal obligation; this role/lease adapter is a C source and
native-consumer premise, not a repeated Lean state machine.

** Root completion and owner-effect completion are different receipts

The original collector consumer checked all owner release counts immediately
when processor0 returned from GC. That was a dependency on callbacks executing
inside the stopped collective. The replacement deliberately removes it.

The existing =collector-on-owner= pinned task/join path now collects a query-only
receipt on each real owner after that owner resumes. It does not call the drain
function, poll, sleep or extend a deadline. The original all-owner/thread/once
assertion remains after those receipts. The callback also rejects an active
root scan lease or joined GC round. This verifies both that the runtime delivers
the effect and that arbitrary native code runs after root ownership reopens.
A general GC caller does not wait for arbitrary callbacks, so an indefinitely
blocked/unknown native release cannot become a whole-VM GC completion dependency.

** DRAINED is a retryable control state

The topology/control pin =___lifecycle_registry_begin/end= replaces private
list access. It does not authorize PSTATE/root dereferences. A native owner
callback can retain that pin after physical VM data is drained, so the final
registry writer may legitimately refuse. A retry must keep the DRAINED control
record and request only unlink/global permission; it must not resize, recreate
roots or replay any destructor.

The real library-style host fixture now covers both cuts: a pin before close
refuses without draining; a pin acquired by the actual owner callback permits
data drain but refuses global free. Releasing that pin lets the same cleanup
request complete with one callback execution. Existing registry QNT owns this
schedule and its resize-after-drain negative history; no new Lean state machine
is introduced. Native owner/TLS checks still apply to the final permit retry.

** Real consumers and build context

The primitive-override fixture still used separate PSTATE cleanup and the old
private =vm_list_mut=, then called VM cleanup from the parent TLS binding.
It now calls the BOOL whole-VM cleanup API on the actual owner and checks its
receipt before restoring the parent. All three same-address VM reuse/isolation
cycles remain. Production =vm_list_mut= use is retired, rather than aliased.

The nested lifecycle fixtures exposed a separate consumer-context defect:
Make redefines inherited =GAMBITDIR_INCLUDE= and =GAMBITDIR_LIB= as relative
paths. The C builder interprets them from the generated file's directory.
The new target alone exports the same variables as absolute paths. Official
names, workflow, profile and limits stay intact; no alternate executor is added.
The actual Make target now executes both fixtures, including successful global
reclamation after secondary acknowledgement and duplicate/refused teardown.

** Benefit and additional cost

#+NAME: owned-lifetime-benefit-cost
| Dimension | Concrete benefit | Added work / boundary |
|-----------+------------------+-----------------------|
| Unknown startup | Healthy roots can collect while an ABORT-only descriptor is quarantined | Retained native handle/control storage; no forced reclamation |
| Native entry | Marker/root protection precedes allocating constructors; exit invalidates only owned activations |32 bytes per activation record on the measured Darwin profile, allocation and entry/registry CAS |
| VM control | One bounded owner record replaces resize-only lifetime and carrier borrowing |15,560 bytes for MAX_PROCESSORS64 on the measured profile; private pointer storage is unchanged for SMP |
| Effects | No arbitrary foreign callback runs inside a stopped GC collective or registry writer | Deferred still-object charge, owner drain latency and indefinite uncertain payload custody |
| Publication | Readers exclude retirement; late notifications cannot be stranded by opener ordering | Member view admission/pending CAS; callbacks must obey the admitted native contract |
| Control semantics | Shared precise frames and multi-shot continuation retain repeated map restoration | No one-shot restriction or per-actor heap conversion; no assumed throughput gain |
| Build | Same cache, Bazel-derived C23 profile, configure/Make and exact test-only producer reuse | Full production-source changes still require the complete producer; no new executor/profile |

The byte counts are layout/accounting observations, not RSS/peak or statistical
performance measurements. Native payload size under an unknown destructor is
not bounded by the control record. Throughput, latency distributions and whole
VM peak remain unmeasured until matched product workloads exist. Result4 owns
request/service/FIFO and complete product qualification; lifecycle safety does
not qualify its scheduler work or increment the independent SMP12 families.
