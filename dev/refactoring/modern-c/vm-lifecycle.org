The global caller no longer loops over secondary VMs and assumes success. Their
owners explicitly retire them. A remaining node is an outstanding dependency,
even when that VM cannot run. Registry exclusivity closes the race in which a
constructor or reader appears after an unlocked list preflight.

The actual source callers of VM setup/cleanup are the global setup/coordinator
and their C function-table exports. The pthread/client/main examples consume
process-global setup/cleanup. The new C-host fixture follows the existing
=tests/client.c= / test8 library path. Generated Scheme names remain unchanged;
old C declarations/function tables migrate together to BOOL cleanup results.
Old native objects must be rebuilt against the new header.

** Failure and concurrency boundaries

A failed setup result alone does not release host-owned VM storage. Known
pre-context rollback reaches CLOSED; unknown context construction remains
registered and denies global free. A false cleanup result likewise retains
ownership. No retry replays an unresolved foreign release. A killed registry
writer supplies no release receipt: it cannot be stolen or reset merely to make
progress. This protocol does not claim arbitrary native owner-death recovery.

A same-owner SFUN root borrow prevents VM retirement. Closing lifecycle and
owner-cleanup phase reject managed reentry before destructors can allocate new
Scheme state. Returned foreign errors and captured Gambit throws keep the
pending cursor and native payload in the existing cleanup escrow. Other live VMs
may continue; retained storage remains a real memory cost.

Signal dispatch queues bits instead of waiting on a mutator it may have
interrupted. Only complete LIVE nodes are visited. =INTR_USER= still targets
VM0/processor0. Asynchronous qualification currently requires native full-word
atomics; an emulated mutex-based CAS does not inherit that claim.

Setup publication is an invocation-local receipt. Reading SETUP from the shared
registry after returning from an old invocation could observe a newer setup and
close the wrong generation. The local receipt avoids that inference. It does
not grant arbitrary stale raw-pointer use or cross-VM movable-object sharing.
