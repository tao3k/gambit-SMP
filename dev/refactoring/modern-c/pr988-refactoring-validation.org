an SMP architecture certificate. It is closed and unmerged; its current body
retracts the submission. Neither that withdrawal nor its large generated diff
decides whether an individual mechanism is correct. Evaluate each mechanism
against its preconditions, failure exits and actual consumers.

existing counterexamples and native acceptance. It applies no patch and changes

* Why Repair9 needs the architectural route

The retained [[../../../docs/smp-repair9-interrupt-request-lifecycle.md][request lifecycle audit]] distinguishes enqueue, dispatch, action,
result, runnable state and caller consumption. Its final table deliberately
does not select an unobserved native transition as the actual cause. The
[[../../../docs/smp-repair9-reply-replay-current-status.md][reply-replay correction]] also distinguishes its corrected source cut from an
older executable and from the earlier TFIB failure. These histories cannot be
collapsed into one patch-success claim.

The complete replacement must establish all of the following together:

1. One request remains owned across dispatch, action, GC, reply and consumption;
   readiness or a wakeup is not completion. Unknown outcome retains custody and
   cannot authorize replay or resource release.
2. The waiting caller and service activation have separate lifetimes. The
   internal service tail becomes collectible only when registers, resume
   closure, RC roots and user continuations no longer retain it. Preserve
   intentional user capture and repeated continuation restoration.
3. A static retry entry has an exact repaired FrameSpec and root reload path;
   reflection, serialization, unsupported aliases and control escape select
   the general path without repeating the action or losing its result.
4. Root-domain count and collector count are independent; W<R scanning retains
   each source and unfinished worker obligation through failure and exit.
5. Original-load completion, work counts and peak pass under original limits.
   A small overlay demonstrates a mechanism, not the original flood capacity.

PR988's phase barrier can satisfy part of the first collection-order premise.
It does not imply items 1--5. Conversely, the new architecture cannot discard
that ordering premise merely because it replaces the old barrier implementation.
This is the practical value of the patch evidence: retain the invariant and
negative control while replacing the authority that currently enforces it.

* Cost and falsification ledger

Let N=360,000,000 denote original useful requests. Let alpha be the measured
fraction that actually avoids an old capture/closure, not merely uses a new
macro. Let C_old be eliminated work per eligible request, C_new added per-request
admission/frame/root work, F fixed epoch work and C_fallback the extra fallback
work. A necessary CPU-work benefit condition is

#+BEGIN_EXAMPLE
N * alpha * C_old > N * C_new + F + C_fallback
#+END_EXAMPLE

Measure capture, closure, materialized frame, scans, retries and completions
separately. This inequality is not a wall-time speedup prediction; contention,
scheduling and allocation overlap need matched measurements. Peak acceptance
must bound simultaneous source and destination roots, staging, retained frames,
unfinished requests and worker slack. Live reachability and physical capacity
are separate bounds. Falsifiers include alpha=0, unchanged retained frame graph,
more root work than eliminated capture, or a failure path that forces permanent
whole-VM retention. No invented percentages or person-day estimates are used.

Retained [[../../../evidence/research/retained/modern-c/shared-heap-smp-design/pr988-mechanism-validation.json][machine-readable receipt]] and [[../../../evidence/research/retained/modern-c/shared-heap-smp-design/pr988-mechanism-native-replay.log][raw native output]] bind an unchanged archived
DEV executable to this replay. It uses the existing validation role and original
30-second budget, R=3, W=2, census and full GC. No compiler/runtime build or new
workspace was created. All four transfer/restore/serdes/resolver markers passed;
the included map/PBT controls are scoped to this executable and overlay.

The initial comparison reported changes to gsc and libgambit.a; the final
comparison matched all 30 retained input identities. Intermediate producer bytes
were not captured, so this does not establish producer stability throughout the
window. The executable identity matched. Replay is valid for that archived
static executable; it is not a new build receipt, current modern-c qualification
or execution of the historical PR988 head.

load on one qualified cohort. Source, native and cost gaps are explicit rather
than hidden behind a passing model or a complete directory.
