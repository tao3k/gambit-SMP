* RESEARCH Actual readers, writers and aliases
:PROPERTIES:
:SCOPE: source-level named footprint; not whole dynamic escape closure
:END:

** Entry, resource vector and index cell are distinct objects
In [[file:../../../vendor/gambit/gsc/_t-c-1.scm][_t-c-1.scm]], a table entry's value
is =(index-cell . resource-vector)=. =table->list= adds a key pair but does not
deep-copy that value. Both table implementations in
[[file:../../../vendor/gambit/lib/_system.scm][_system.scm]] retain values when
building pairs. =targ-glo-rsrc= and the heap-dump map expose the same resource
vector. =keep= retains selected elements; sorting a spine is not freezing them.
The resolved cell is another shared pair mutated by =set-cdr!= and recursively
read by =targ-code='s =cell= case. =targ-c-id-glo= also retains its name string.
The plan must own name bytes and copy the resolved integer, not retain these
objects under a readonly type label.

** Named writer and consumer closure

| Family | Actual source path | Timing and consequence |
|--------+--------------------+------------------------|
| session lifecycle | heap-begin replaces global table; heap-end clears it | normal sequencing, not demonstrated unwind cleanup |
| use-glo | existing entry writes complete demand/supply list; absent entry inserts | alias-visible normalization, allocation and validation effects |
| GVM global users | six _t-c-2 callers from prior study | demand/supply during conversion; loc-opnd supplies then demands |
| header | start-dump filters resource demand/supply roles | serialized before both binding helper passes |
| layout | supplied partition, DEF_GLO and index backfill | before binding output; supplier/indices still matter |
| binding helper | two loops call one helper | first can change demand; second writes again |
| ordinary module suffix | DEF_MOD_SYM, DEF_MOD_KEY, end-dump | reads names/cells/output state, no named demand-list consumer found |
| linker | reads header, reconstructs records, unions/differences, validates warnings | separate reconstructed object graph, not live compile vectors |
| open observer | global variable access, raw vector access, aliased names, ports/hooks | cannot be excluded by accessor search alone |

The study checks the exact named-identifier footprint against immutable source
snapshots and binds its digest/count/scope into ASCENT. It is not a Scheme parser,
whole-program alias analysis, dynamic reader proof or platform-qualified graph.
The ordinary successful path contains no directly named demander read after the
header cut other than helpers that write it. That narrows the proof obligation;
it does not establish that the first write is unobservable under all callbacks.

=targ-union-rsrc= creates a new overlap record but retains unmatched resource
objects. Difference can return an original list suffix. These aliases belong to
the linker graph. =targ-link-info= reads bytes, and =targ-get-mod= reconstructs
s-d/s-nd/ns records with file provenance. In particular, a supplied-only header
stays supplied-only in that reconstruction even though late emission normalized
the compile resource. Replacing linker input with final mutable metadata would
change warnings and dependency roles.

* RESEARCH Two admissible replacement contracts

** Observation-limited elision
Require complete discovery, fixed roster/indices, owned plan, closed writers and
no capable observer of demand-list contents/identity over the entire interval.
Preserve the original header snapshot and both binding tuples, native store
roles and C-init text ordering. In this domain both metadata writes may be
removed. The equivalence observation must include linker header bytes and
warning inputs, not merely native store tuples. Full error-prefix equivalence
is an additional need. It is not discharged by the normal-output argument.

** Metadata-preserving adapter
If a legitimate observer needs final metadata, retain the first normalization
at its original logical cut, under a separate explicit effect owner. The text
emitter can still be readonly. The second normalization is value-redundant only
when no writer changes the same field before it. This may remove one write per
primitive, not two. A writer between the two passes invalidates that proof.
Physical setter events, quoted-list identity and concurrent observations require
additional exclusion; structural value equality alone is insufficient.

This adapter is not a blanket solution for arbitrary callbacks between output
operations. A callback may observe the first normalized value or change it
before the second use. Retaining those semantics can require both effects, so no
write-elimination benefit may be claimed for that domain.

* RESEARCH Exception order, partial output and plan failure
The legacy call builds a list containing =targ-use-glo=, a tagged C-ID object
and a procedure label before entering =targ-code*=. Evaluating the call's list
operands is not port output order. Current source has =arg-eval-order= and
=free-vars-order= heuristics; this does not establish the exact order of an
already-built compiler binary or another supported Scheme host. Do not invent
one universal left-to-right failure order from source indentation.

An uninterned key raises compiler-error. A missing entry allocates/inserts an
unresolved cell; it is not necessarily the same error as a missing sealed plan.
Changed name encoding, allocation or output can fail at different points.
Precomputing the whole plan can move an error before BEGIN_MOD_PRM or before
earlier bindings. Retain a typed deferred fault and surface it at the matching
logical operation only if original precedence and visible output prefix are
proved. Allocation failure during preflight is a new path unless resource
preconditions establish its impossibility. A private output transaction changes
legacy visible partial-file behavior; that is an explicit contract change, not
an automatic equivalence argument.

=targ-code*= writes a macro then its line; =targ-display= calls display on
=targ-port= and updates source/line state. Failure can leave a prefix and mutated
metadata. =targ-heap-end!= follows normal heap-dump return. In _utils,
=with-exception-handling= installs a captured continuation and restores the old
handler by ordinary control flow; =compiler-abort= invokes that continuation.
These are actual escape paths, not evidence that arbitrary exceptions rollback
the table or close every port. The model retains plan custody after unknown
output and never issues a success receipt for that transaction.

* RESEARCH Continuation and nested compilation
A captured continuation can retain local =objs=, =proc=, =p= and output cursor
while =targ-glo-vars= and =targ-port= are process globals. Nested compilation can
replace globals; normal nested cleanup can clear them before old locals resume.
Thus the same interned symbol is insufficient identity for the old operation.
There is no claimed user-program witness that arbitrary native C-init text
executes during compilation: here it is emitted as text. Callback/reentry
reachability depends on actual port/host capabilities and remains OPEN.

The proposed managed service pins an owned plan by session generation, primitive
ordinal, binding kind and output operation identity. It also retains output
position/source mapping, fault status and root ownership. Resume of the same
unsettled operation continues from its committed cursor; a lost answer does not
authorize writing the macro twice. A genuine repeated execution receives a new
operation and output context. These are different semantics. Arbitrary legacy
multi-shot continuation reexecution cannot silently be treated as an idempotent
retry. Until its operation identity and side effects are established, reject
managed reuse for that capability or retain the legacy owner path.

Closing admission is followed by writer/reader drain and proof that no suspended
or foreign borrower still owns the plan. =const= does not give lifetime safety.
A paused old context must not use a new global table or a closed output port.
Late writers revoke an elision certificate before further publication; unknown
exit preserves custody. Eventual reclamation after that state is a separate
progress/root-retirement proof, not included in this model.

* RESEARCH C23 physical refinement and parallel contexts
The architectural default is one owner for each mutable semantic workspace,
with independent compilation contexts and immutable stage results. Removing
process-global table dependence is the concurrency gain being sought here;
wrapping the same shared table in another globally contended lock would retain
its architectural bottleneck. This component does not prove independence of all
other expander, optimizer or output state.

For a concrete publication protocol, initialization and root registration must
precede publication; a consumer acquires the same generation and an ownership
lease before accessing values. Close excludes new leases and drains accepted
ones before retirement. A check of an epoch followed by a write is not an atomic
handoff: revocation must serialize with operation admission/publication. A
single owner can provide that serialization; a cross-owner design needs a
separately qualified C23 atomic or lock protocol. Lock freedom is not inferred.
Unsigned generation wrap or identifier exhaustion must reject/rekey under an
explicit policy rather than silently permit ABA. Checked capacity/span arithmetic
and target-qualified layout belong to the capability profile.

The current QNT models these transitions atomically. It does not prove the
instruction-level protocol, Scheme/C root handoff, pointer provenance or reclamation.
Those duties stay under NB-platform and NB-source. New contexts must not publish
old mutable cells as immutable pointers; native plan storage can hold owned bytes
and integers while any remaining Scheme handles stay in registered root custody.
The relevant C23 rules require direct refinement; historical C11 proof labels
cannot substitute for that work.

* RESEARCH Formal scope and nontrivial counterexamples
The actual QNT has 22 actions, including elision versus metadata-preserving
first effects, output stages, suspend/resume, foreign reentry, late writer,
escaped observer and unknown exit. Named external admission steps are explicit
assumptions, not automated discovery proofs. The extracted Lean AST validates
actual binding IDs, field kinds, supported expressions and complete step roster.
Lean proves all-step preservation and finite reachability safety. Counterhistories
retain stale generation, double PRM emission, unauthorized elision, missing close
and lost custody. Bounded sampling adds no native correctness claim.

[[file:models/lean/NativeBindingRefinement.lean][Refinement lemmas]] prove equality
of two normal-output projections that deliberately exclude resource aliases;
proving that this projection covers real observations remains OPEN. They also
prove exact canonical-list conditions for the second metadata update, and retain
distinguishing alias, intervening-writer, error-prefix and duplicate-output
examples. These examples are formal distinctions, not observed native failures.
The abstract model normalizes demand as one action; byte-level exception points
inside Scheme allocation and display still need source refinement.

* RESEARCH Retirement conditions and benefit

| Replacement | What can retire | Required evidence | Remaining work |
|-------------+-----------------+-------------------+----------------|
| owned plan | unresolved cell/name/table lookup in text consumers | fixed entry, layout, name identity, roots and immutable bytes | one owned record per primitive |
| both helper uses | late lookups plus both metadata writes | full observer/writer closure and error-prefix equivalence | preserve header and two native binding stores |
| second update only | one redundant normalization per primitive | retained first effect, exact canonical value, no intervening writer | first effect adapter and ownership still needed |
| legacy reentry path | global-backed emission under managed service | real caller operation IDs, resume/fault/output equivalence | currently OPEN; refusal is not unrestricted equivalence |
| old whole path | mutable lookup plus old text emitter | all source, exception, platform and full byte-fidelity needs | no production path retired by this study |

The preceding artifact has P=455 matching primitive tuples and 910 native
binding records. The inspected source helper would perform 2P late uses in a
matching generation. The maximal elision domain can remove those late uses;
metadata-preserving operation can remove at most P normalizations under its
conditions. Lookup, conversion and validation may move into planning: charge
that work to the new design. No direct macOS preprocessing saving follows from
emitting the same C bytes.

Let D be genuinely shared lookup/encoding work and W certified redundant
metadata work removed; let K be planning, S owned storage/root/pin work, V byte
verification and A capability qualification. Positive net benefit requires
=D+W > K+S+V+A= with equivalent admitted semantics. This is an operation/cost
boundary, not a timing estimate or person-day argument. The immutable plan's
larger value is a stable, source/ABI-keyed stage result for independent compiler
sessions and later reuse; incremental validity is not proved just by this seam.
