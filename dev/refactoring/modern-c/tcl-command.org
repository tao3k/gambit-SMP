** Existing official caller and selected responsibility

This is the existing official =examples/tcltk/tcltk.scm= adapter, originally
copyright1997--2025 Marc Feeley. No new example directory or Scheme namespace is
introduced. Its native command operations move into =command.h=; the invocation
and deletion block is byte-identical. The new private =scheme_create_cmd= owns
construction. The existing Scheme =##tcltk-define-procedure= and GUI initialization
names/behavior remain. The example Make description includes the header in its
distribution and compilation dependencies, including out-of-source include lookup.
The actual include option is =-I$(srcdirpfx).=: an empty configured prefix becomes
=-I.=, while an absolute source prefix becomes its source directory plus a dot.
Both actual Make expansions and object compilations using those options are
required. These are argv/context tests, not a claimed second full VPATH build.

Two actual source defects/obligations justify this leaf. The old example calls
=alloc_rc(0)= without the processor argument required by the current SMP ABI;
same-profile compilation of the actual generated C fails with expected2/have1.
The old native result path also loses ownership of initialized RC/still resources
when =Tcl_CreateCommand= returns NULL before accepting ClientData.

The extraction adds another necessary contract: the original generator's
=___arg2= expands through =___ARG2= to the live =___CFUN_ARG(2)= stack cell. It is
not evidence of an old stale scalar parameter. A C helper receives a scalar;
rooting that captured value before allocation is necessary to preserve the
original semantics. This does not justify adding a new global root registry.

The [[https://github.com/tcltk/tcl/blob/core-9-0-3/generic/tclBasic.c][public Tcl source]]

hashes and actual =Tcl_GetVersion= output. Public release-tag source is supporting
API evidence, not a claim of byte-equivalence with the loaded library. Source
behavior for other platforms and GUI/Tk execution is not qualified here.

** Conditional argument

Given valid owner-thread Tcl input and the existing participating owner/OPEN RC
and GC protocol, install the captured procedure before any Scheme allocation.
The collector's existing claimed RC source scan updates that cell. The helper
therefore initializes the still payload from the relocated referent rather than
a C local captured before collection. At native acceptance the existing callback
becomes the owner. At returned rejection no native owner was acquired, so the
constructor releases both resources through the same release implementation.
Allocation failure releases only the existing RC record. These are disjoint
returned outcomes, so there is no double-release in the admitted sequence.

Arbitrary native reentry/nonlocal escape during registration is not a returned
rejection. Do not run rollback merely because a call did not finish. Existing
registered roots/native holds retain actual custody where it still exists;
automatic resolution and whole-provider drain are not established. Unresolved
RC debt may prevent cleanup but is still a root source, not a reason to stop
all VM GC. No callback pin-before-read or cross-library result boundary is claimed.

** Benefit and added-cost matrix :matrix:

| Contract | Established benefit | Added cost / limitation |
|----------+---------------------+-------------------------|
| Captured C value | Existing RC allocation roots it before make_vector; actual GC reload passes | One extra RC store and one post-GC load, using existing mutexes |
| Returned native rejection | No indefinitely retained RC record or positive still hold | Same existing deletion code; still physical reclaim waits for GC |
| Size boundary | Native RC header48 bytes; one-field still vector7 words at8 bytes,56 accounted bytes |104-byte structural floor per leaked pair, excluding allocator/alignment overhead and captured graph; not measured RSS |
| Repeated rejected registrations | n rejected pairs no longer retain n RC roots/still holds indefinitely | Reclaimable captured graph is the unique reachable union excluding other roots, not a sum that double-counts sharing |
| Successful construction | No new object, persistent table, field, lock or allocation site | Two additional existing RC critical sections; no throughput claim |
| Invocation hot path | Native invocation/deletion text preserved byte-for-byte | Active-callback ownership and exception semantics are not fixed by this leaf |
| Maintenance/build | One command ownership module, distribution/dependency closure, shared PBT | Optional external Tcl matrix; default tests remain independent of Tcl |

Before the next GC, rollback immediately frees the RC block while the zero-refcount
still object can remain physically present. After collection, unreferenced still
payloads and otherwise unreachable captured objects can be reclaimed. No complete
round-peak reduction, latency result or human-day estimate is used for admission.
