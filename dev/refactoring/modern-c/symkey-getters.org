** Complete responsibility and learning

Insertion locking does not protect a bucket alias after a getter returns. The
registry owns count/buckets and intrusive NEXT; a Scheme caller with that vector
can retain it through GC, mutate it, or traverse links that a later rehash
rewrites. These are different lifetimes. Adding another check at a reader cannot
transfer that ownership, and holding a registry lock through Scheme control
would span allocation, exceptions and multi-shot continuation restoration.

Both private C-target getter names now return fresh flat Scheme-owned identity
vectors through the admitted capture service. The getters permit allocation and
GC; their old noninterrupting declarations are retired. All four actual in-tree
direct consumer sites migrate in the same source cut. The symbol fold uses the
same getter authority. There is no production raw fallback, duplicate registry
or new root API. The only raw getter is an explicitly named predecessor fixture.

This is a representation and ownership replacement, not a repair-line patch or
a claim that every SMP failure is solved. The C runtime continues to own canonical
PERM publication and atomic capture; Scheme owns traversal and managed lifetime.
Preserving canonical identities and allowing a captured view to survive multiple
resumptions amplifies Gambit's control semantics without imposing OCaml's one-shot
restriction. Existing QNT and Lean do not prove this concrete adapter by naming it.

** Lifetime, failure and conditional proof

#+NAME: getter-transfer-cuts
| Cut | Custodian and invariant | Failure / unknown disposition |
|-----+-------------------------+-------------------------------|
| Query | Existing native gate reads current count N | No new object/resource retained |
| Allocate | Scheme frame owns an initialized vector outside the gate | Allocation may collect/escape without a native debt |
| Matching copy | Existing native gate excludes count/NEXT/rehash writers; exactly N PERM identities | Mismatched count writes nothing; retry has only ordinary GC-owned garbage |
| Deliver | Native retains no destination pointer; getter returns owned vector | No borrowed registry storage crosses return |
| Retain/mutate | Normal Scheme aliases and GC/continuation roots own the vector | Mutation changes that vector, not registry or another getter's vector |
| Callback/resume | Existing fold frame carries one snapshot | Exceptions unwind normally; multiple resumptions share it and preserve dynamic-wind |

The claim requires admitted native interning, a coherent matching-count capture,
complete generated roots and ordinary Scheme mutation discipline. Reflective
stores into arbitrary native/symbol storage are not made safe by this API.
Binding values are still read at their original callback-time points. Finite
completion needs a stable-size interval; continuous native growth can starve the
two-pass retry. Capture delays polling while holding the gate. No bounded latency,
dead-owner recovery or independent collector admission follows from alias safety.

Falsifiers include: two getter results sharing the same mutable vector; mutating
one changing registry or another view; growth changing a retained view; omitted
or duplicated canonical identities; a live consumer still reading count/bucket/NEXT;
GC or a second continuation restoration losing a view root; external raw readers
being declared supported without a migration. These are concrete source/native
obligations, not a second QNT/Lean state machine.
