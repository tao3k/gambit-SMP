The modern C refactoring line targets C23, formally ISO/IEC 9899:2024. C11 is
historical provenance for memory-model mechanisms, not this project's language
or architecture target. Historical receipts and earlier model names remain
unaltered; citing them does not qualify the new baseline. Do not silently carry
old C11 premises into a C23 refinement without checking the relevant rules.

The authority is the standard rows and platform need in
[[file:models/sysml/native-binding-plan-retirement.sysml][SysML]]. Their current
projection appears in [[file:native-binding-plan-retirement-matrix.org][the matrix]].
Official reference observations are retained with the source-bound research
receipt. These observations establish standard/toolchain publication status,
not local compiler acceptance.

* RESEARCH Standards, research capabilities and admission

| Layer | Policy | Evidence and limit |
|-------+--------+--------------------|
| Published C language | C23 baseline | [[https://www.iso.org/standard/82075.html][ISO/IEC 9899:2024]] |
| Next language | Track C2y explicitly | [[https://open-std.org/jtc1/sc22/wg14/www/projects.html][WG14]] lists it as unpublished; not a shared ABI premise |
| Tail calls | Study generalized-call TS for future leverage | WG14 TS work is not a universal compiler guarantee |
| Cleanup | Study the resource-cleanup TS | Lexical cleanup alone does not settle Scheme continuation or asynchronous exits |
| Pointer model | Study published provenance TS 6010 | Separate specification; not automatically part of C23 language mode |
| Compiler | Qualify features individually | [[https://clang.llvm.org/c_status.html][Clang status]] and [[https://gcc.gnu.org/onlinedocs/gcc/Standards.html][GCC modes]] are upstream evidence; Apple Clang/SDK remain separate |

* RESEARCH Required architecture, not a dialect-flag exercise
The mainline must give immutable ModuleSpec/FrameSpec/NativeBindingPlan values
explicit owners, target-qualified layouts, roots across safepoints, and separate
execution-context and collector responsibilities. It must support independent
compilation sessions and dependency-driven reuse. Choosing C23 syntax does not
establish any of those properties.

For NativeBindingPlan, use resolved integers and owned bytes instead of shared
mutable Scheme cells. Retain Scheme semantic discovery and explicit tail-call /
continuation protocols. C portability is a reviewed capability profile rather
than permission to rely on unspecified behavior. A plan that eliminates no old
responsibility and merely adds wrappers has no established modernization gain.

* RESEARCH Capability profile to be bound before native admission

| Field | Required design evidence |
|-------+--------------------------|
| compiler | exact executable identity, version, target triple, explicit C23 dialect, feature diagnostics |
| SDK and library | SDK/libc/header identity and actual availability of selected library facilities |
| layout | size, alignment, endianness, calling convention and generated descriptor schema |
| atomic publication | object types/alignment, acquire/release protocol and required operation widths |
| progress | lock-free claims qualified per type/platform; standard atomics alone do not imply lock freedom |
| lifetime | root ownership, generation pin, close/drain and reclamation; const is not deep freeze |
| checked bounds | checked arithmetic policy for plan sizes, spans and capacity; qualify selected C23 facilities |
| generated diagnostics | static assertions and selected attributes; diagnostic support does not replace ownership proofs |
| research extensions | isolated feature policy for C2y, tail-call and cleanup TS; mandatory fallback has explicit semantics |
| build identity | compiler/SDK/ABI/schema policy participates in artifact reuse and invalidation keys |

No native probes, preprocessing, compiler execution or runtime tests are used
in this study. Availability of a mode flag is insufficient. Current Darwin
GCC build artifacts remain source evidence; they are not automatically qualified
C23 producers. The open platform need covers publication, lifetime, ABI and
feature support, not just memory-order spelling.
