* Research basis and its exact engineering use
:PROPERTIES:
:CUSTOM_ID: research-basis
:END:

The following implications are engineering applications to this source tree.
None of these papers proves the modified SMP implementation or its deadline.

** Feeley: compositional entry and return invariants

[[https://www.cs.tufts.edu/~nr/cs257/archive/marc-feeley/polling.pdf][Marc Feeley, Polling Efficiently on Stock Hardware (1993)]], especially
Section 5, derives polling placement from invariants at entry, call and return
boundaries. Its reasoning distinguishes ordinary calls and tail calls. This
is more useful here than a generic instruction to reduce checks.

Our application: require an explicit transfer rule at generated entry,
service entry and repaired return. A check may be combined or removed only
when the preceding boundary supplies its authority and effect budget. Polling
latency credit and memory-allocation credit remain different quantities;
balanced polling is not a proof of rest allocation safety or 295/300 seconds.

** Feeley: semantic continuation versus frame coordinates

[[https://3e8.org/pub/pdf-t1/feeley.pdf][Marc Feeley, A Better API for First-Class Continuations (2001)]] distinguishes
capture, graft and return and discusses restoring the appropriate dynamic
environment. It explains why invoking processing code under the wrong
continuation can retain frames or reenter an exception context incorrectly.

Our application: describe the continuation in which refusal cleanup, retry
and body delivery execute. The saved handler fp, post-unwind caller fp and
actual first-store fp require separate correspondence. A numerically restored
pointer alone does not establish the correct roots or dynamic environment.
Internal delivery is single-settlement; Scheme multi-shot continuations are
still permitted by the language and must not be globally made single-use.

** Meyer: obligations instead of duplicated defensive checks

[[https://se.inf.ethz.ch/~meyer/publications/computer/contract.pdf][Bertrand Meyer, Applying Design by Contract (1992)]] assigns obligations and
benefits to caller and supplier, and warns that indiscriminate duplicate
checking increases complexity. A contract's preconditions cannot hide further
requirements from a caller that already satisfies the stated obligations.

Our application: each of the existing ownership contracts must name the real
supplier of its premises. If delivery requires a still-live root borrow after
grant, publish that lifetime in the grant/custody contract. Do not discover it
only as a late READY failure or repair it by another unrelated wrapper check.

** Reynolds: small footprints and explicit interference

[[https://www.cs.cmu.edu/~jcr/seplogic.pdf][John C. Reynolds, Separation Logic: A Logic for Shared Mutable Data Structures
(2002)]], its introductory discussion and frame rule, explains separating
conjunction and local reasoning
about the memory a command accesses. The frame rule has side conditions;
unmentioned storage is not automatically protected under arbitrary interference.

Our application: separate construction, old-frame service, root repair and
allocator bookkeeping footprints. A moving GC changes reachable cells and
roots, so those cells cannot be framed as immutable across collection.
For shared section ownership, a sequential footprint proof must be paired
with the actual lock/atomic and lifetime protocol. Integer interval arithmetic
does not establish C pointer provenance, object bounds or absence of UB.

** Necula: validate each actual translation instance

[[https://people.eecs.berkeley.edu/~necula/Papers/tv_pldi00.pdf][George C. Necula, Translation Validation for an Optimizing Compiler (2000)]]
checks correspondence between representations for particular compilation
instances. This avoids treating trust in the whole compiler as the only route
to confidence in an output.

Our application: Make hashes identify the Scheme, generated C, object and
linked image. A separate correspondence must show where the complete demand,
root map and first protected effect landed. Equal hashes establish identity,
not semantic refinement; a line-number association is not that refinement.

The official [[https://gambitscheme.org/research/][Gambit research index]] also identifies Feeley's 2000 portable
continuation implementation, Larose/Feeley's 1998 collector and the 2015 task
migration paper. Full texts at the attempted official endpoints were not
accessible during this review. They remain follow-up sources, not authority
for claims about this branch's section geometry, GC algorithm or memory order.

* One concrete state relation, not one model of all Gambit
:PROPERTIES:
:CUSTOM_ID: state-relation
:END:

Use the existing ownership contract vocabulary with these separate coordinates:

| Coordinate | Actual supplier | Required distinction |
|-
| Execution identity | VM/processor and actual runtime entry | An observer's case label cannot assign the runtime owner. |
| Storage identity | Allocator claim, section, half and generation | Reused addresses do not reuse old ownership. |
| Operation identity | Activation, internal attempt and generated group | Group commit, READY claim and Scheme body entry are different settlements. |
| View identity | Collector/root revision and returned frame descriptor | Root movement can change view without changing the command or region generation. |
| Logical source | Real frame decoder, stop and successor descriptors | Physical half bounds do not define the whole continuation. |
| Authority | Owned intervals and complete selected demand | Cached hp/fp and a future grant do not back earlier spill stores. |

Write demand as a vector =(heap words, stack words, parameter footprint,
old-frame backing)=, not one scalar used for all resources. For the reported
ordinary case, heap reservation is ten and fast consumption is six. An
authorization envelope can be conservative while its debit remains actual.
The geometry and consumption of other spellings require their own lowering.

For a concrete state =c= and abstract state =a=, =R(c,a)= must relate these
coordinates using actual source fields. For each chosen C transition, prove
its preconditions, permitted effects and matching abstract transition(s).
Unmodelled C steps may stutter only while preserving that relation and the
protected footprint. An unbounded stutter loop is not a progress proof.
The relation is a proof obligation here, not an extracted implementation.

For independent resources a specification can use
=Construction * ServiceBacking * SourceCustody * UnrelatedStorage=.
Shared or overlapping root cells need explicit ownership/permission transfer,
not an unjustified separating conjunction. After GC, obtain =R(c',a')= using
reloaded roots and the current return view; do not carry raw pre-GC pointers
across the relation by assumption.

* Four implementation cuts and the missing supplier at each

** Admission and refusal: checklist 6

Real path: generated rest entry -> =___rest_fast_grant_fits= ->
=rest_interval_fits= -> either pair construction or recovery preparation.
Check all three spellings against their actual emitted effects. Before a
protected effect, invalid authority, valid shortage and complete grant have
different consequences, even if the public C ABI still uses a Boolean.

The actual root-window copy, RA stores, argument pop/adjustment, pair stores,
result header and parameter staging need named footprint membership. Preserve
the original oracle's zero-effect window. Legitimate service/root updates are
separately authorized effects, not a reason to hide construction writes.

The current source full-envelope edit addresses the old fast-pair mismatch;
it does not supply terminal one-short refusal. Identify the real no-recovery
condition at the final decision. If none exists in the candidate mechanism,
repair that mechanism while preserving legitimate recovery; do not manufacture
an unconditional exception at initial room=9. An initial local miss followed
by delivery remains recovery, not checklist 6's terminal receipt.

Source verification must establish that all preparatory reads and writes have
their own backing before root-window copying or GC. A diagnostic force-slow
operation cannot silently bypass that requirement. Check this source cut
before trying another heap-pressure program.

** Logical source and custody: checklist 7

Real path: handler's supplied =stack_break= -> =___rest_caller_chain= ->
=read_admitted_stack_frame= -> real break/successor consumer.
First determine what this walker promises: a safe current prefix, or a full
logical chain. A consumer that only needs a prefix must not perform a larger
walk solely to produce pin events.

For the actual required cross-break consumer, relate old source claim, next
descriptor, successor authority and final old metadata use. A pin counter
increment is insufficient without proving that retirement observes it and
that the protected lifetime covers that last use. Follow the actual decoder
and descriptor storage, including fields used after an apparently final data
read. A valid successor witness and an invalid-source rejection are different
controls; invalidity must never become permission to allocate a destination.

** Mapped recovery and delivery: checklist 8

Real path: =___rest_root_window= -> mapped =___garbage_collect= -> return and
=___rest_reload_window= -> fresh grant -> pair construction ->
=___rest_claim_ready= -> =___rest_resume_delivery= -> body.

Obtain a failure table for READY/delivery from real C: record lookup/pin,
root-view openness, domain/borrow/count, phase, epoch and duplicate settlement.
For every failure still possible after the first pair store, either prove
the held grant/custody makes it impossible or move the corresponding fallible
preparation earlier. The definition =finishCanFail = not(granted)= cannot
discharge any row of this table. Do not weaken zero-effect refusal to fit a
post-construction failure.

The three fp observations must be independent: handler-saved fp, post-unwind
current fp and the actual first-store address. Pair them with one root revision
and owner/attempt, not merely one sampled register. Actual moving roots,
reloaded aliases, dynamic environment, READY claim and body entry complete
the semantic evidence. GC return alone supplies none of these by implication.

** Capacity and publication: checklist 9

Real path: legitimate destination shortage -> =___rest_extend_interval= ->
allocator lock -> eligibility and =rest_predicted_soft_room= -> claim ->
interval publication. Remove the semantic reliance on source-walk failure
without prescribing an unrelated allocator replacement.

The prediction proof must connect the candidate, split geometry, published
soft limit and full demand under the actual custody retained after unlock.
If the final return can fail after claim, account for the owner's settlement
without restoring a shared cursor from a stale snapshot. A model that combines
claim and successful publication into one atomic action does not prove this.

The contest is over one section eligible for both actual requests, not simply
one section somewhere in the pool. Two real handlers must reach the boundary
in one VM and resource epoch. Existing abstract winner schedules remain useful
after that entry premise has a legitimate source/native supplier. Do not use
an allocator-only fixture as the complete rest-handler acceptance.

** Item 7: distinguish old reads from successor reads

=___rest_caller_chain= now inspects the break link at the supplied
=stack_past=. A zero link still terminates the current prefix; the current
walker can follow a link to a live parked successor. Trace that real
consumer and compare its source-claim checks with
[[file:../../../vendor/gambit/lib/_mem/continuation-roots.inc][=continuation-roots.inc=]], including
=lock_source_stack_frame= and =source_break_agrees=. Classify terminal, raw
or forwarded links before reading the next frame. Acquire the next
segment's independently validated owner, half, generation and extent
under the existing lock order.

Feeley's [[https://www.schemeworkshop.org/2000/feeley.ps][portable continuation implementation]] motivates separating the
logical continuation from the lifetime of its physical backing. In this
SMP implementation that separation becomes two obligations: validate
the logical link, and prove the concrete source stays readable until
both the last use and the handoff. The paper does not supply either
obligation for the current C code.

Keep the old pin until after both the last actual old-source use and
successor acquisition. A successor read carrying an old pin identity is
not an old-source read. The current
[[file:../../../src/gambit_smp/rest_observation.py][Python projection]] joins the dereferenced source and requires a
matching activation/attempt. Verify that the sealed image supplies those
identities on the actual handoff. Either use can come last; do not add
another old read to satisfy the
trace checker. =RestNativeObservation.pinCoversBothUses= expresses the
conditional lifetime relation; C must supply the actual event order.

If a repair admits pins on an ACTIVE segment concurrently with
=release_stack_section=, verify caller exclusion or serialize the pin-zero
decision with admission. The current release checks =source_pins= before
acquiring the section's copy gate. GenMC can try the gap between that
check and the gate acquisition using the actual synchronization owners.
This is an interference obligation, not an observed race.

** Item 9: split legal entry, claim and publication

Both current handler forms now reject a failed root reload (cut 6) and
short stack slots (cut 7) before calling =___rest_grant_fits=. After a
heap grant miss, =___rest_physical_tail_short= selects extension; the
soft-only case instead calls =___rest_publish_owned_soft_edge=, with
refusal at cut 8. Both successful returns still require another reload
and grant. A valid reloaded view with a short physical heap tail is the
entry to the modeled fresh-section contest.

Let =D>0= be full demand, =F= the guard, =R= the validated physical tail
in words, and =S= the published soft room. If =S<D= but =R>=F+D=, the
current handler publishes only the carrier-local soft edge of its
already-owned section. The implementation in
[[file:../../../vendor/gambit/lib/_mem/heap-sections.inc][=heap-sections.inc=]] leaves the shared pool unchanged. A separating
observation is =S<D= and =F<=R<F+D= after the last GC/reload/refill; for ordinary
=D=10=, try to observe =R=F+9=. This does not establish that a natural
workload reaches the point. Check =___heap_limit= in
[[file:../../../vendor/gambit/lib/_mem/allocation-limits.inc][=allocation-limits.inc=]] for earlier consumption by generic refill or
reusable-section selection. Quint separates soft-only from physical
shortage; Lean checks the arithmetic equivalence. Neither supplies
native reachability.

Focused checks of these model edits: =rest_section_claim= ran nine Quint
tests at seed 6112, including =softOnlyShortageDoesNotRequestSectionTest=;
=RestNativeObservation.lean= checked with Lean 4.35.0. The existing Recipe
inventory includes the new Quint test. These are direct model checks,
not a sealed Recipe result. The old =invalid-source-control= assumed
that the invalid source would enter extension. Its successor projects

collection, reload and grant providers at their call boundaries.

The allocator now refuses candidates with an existing stack or heap

either request under the lock. Use the cursor/count change as the claim
point. Following [[https://www.columbia.edu/~wing/publications/HerlihyWing90.pdf][Herlihy and Wing's linearization distinction]], that
point does not prove the later successful response: verify the same
section and half after the actual context limit stores and guard clamp.
Check that interference cannot change ownership or the destination view
before publication. Retain a GenMC schedule in which the loser acquires
the lock before the winner publishes; the loser must preserve the claim.

The current =REST_UNLOCK= is emitted before the actual unlock and does
not show publication. For ASCENT, join a real post-store publication
and renewed grant to the winning VM, epoch, processor, activation,
attempt, section and half. Reject missing publication, wrong half,

Safety, reachability and refinement are separate questions:

1. Safety: every reached target state satisfies its required invariant.
2. Reachability: a legal input and path actually reach that target boundary.
3. Refinement: the C edge and linked producer implement the model transition.

A never-entered path may satisfy safety vacuously. A model-selected capacity,
actor or GC return is not a concrete witness. Conversely, a bounded verifier
not finding a path is not a whole-language unreachability theorem. Record the
bound, input assumptions and unresolved dependencies instead of adding tests
at the same unreachable boundary.

An ASCENT requirement row describes what to collect; it is not an observation.
An empty =nativeOpen= relation in a byte-only recipe has no native coverage
meaning. A fixed admission Boolean also has no measurement meaning. The
existing native =rest_required/rest_check= scope and transport must supply the
actual cut; do not infer it from model PASS or absence of a failing row.

For each proposed diagnostic, state the competing source-grounded hypotheses
and the event at which their predictions differ. Repeating the same command
