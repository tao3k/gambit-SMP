** Source/model reconciliation

The earlier [[file:native-entry-admission-design.org][entry design]] already proposed a bank and pre-marker root prefix,
but its source descriptions do not all match the published a9b896c4 runtime.
That runtime allocates one RC block per raw Scheme argument, registers marker
ownership separately and emits final argument stores directly on the stack.
The new =_c_intf/sfun-entry.inc= makes the complete proposal concrete without
silently treating the historical document as native evidence.

| Boundary | Replacement | Retirement |
|----------+-------------+------------|
| Admission | Existing lifecycle activation retains actual owner before any collecting operation | No second activation/identity table |
| Root storage | One initialized span; known-PERM zero arguments need no bank | Per-raw-argument allocations and redundant permanent zero roots |
| Raw arguments | Existing generator prefix writes span before marker; byte flags identify raw inputs | Pointer array and stale post-GC raw C-local reads |
| Conversion/call | Converted arguments fill span; one noncollecting copy precedes the existing call frame | Exposing intermediate argument stores across future collection |
| GC capacity/scan | Existing RC census and RootTask scan enumerate identical primary/span cells | Single-data-cell assumption for typed root spans |
| Exit | Existing activation owns marker, borrow and bank until actual last C use | Conflating logical Scheme restoration with physical C quiescence |

The existing startup word becomes a tagged activation kind, without adding a
second state record: legacy/startup, rooted/permanent preparation, active and
revoked. During permanent preparation the marker slot holds an immovable
procedure. Cleanup checks kind before interpreting it as a vector; only exact
STARTUP grants the existing terminal handoff. A compiler error identified the
still-sweep consumer, which is included in the complete cut.

The generator's =root-arguments= prefix and Scheme names remain unchanged;
the current generated C cohort can be recompiled against the new header.
Native modules with the old global-state layout must be rejected/recompiled.
The generated arity and existing call-frame reserve remain an explicit premise;
this unit does not solve arbitrary unbounded native argument injection.

** Memory-order and failure custody

1. All payload cells start as false and =root_count= is immutable before the
   existing RC gate publishes membership. Byte-only RC has count zero.
2. The registered cooperative owner holds the lifecycle entry. Native metadata
   allocation and the prefix neither collect nor invoke Scheme. User allocator
   hooks that abandon/reenter this interval do not satisfy this profile.
3. Raw inputs precede marker allocation. Borrowed C-closure self is read under
   its existing stable-root ownership and copied before the source borrow ends.
4. Census and scan use the same frozen source gate and task lease; GC can move
   span values, while resumed C code consumes canonical span cells.
5. Constructor refusal releases only acquired resources. Unknown native owner
   abandonment retains the activation; timeout/failed join cannot free it.
6. Logical marker kill only revokes the return destination; it retains the
   bank, borrow and entry. Physical marker cleanup, bank borrow return, bank
   reference release and lifecycle leave occur at the last generated C use. Terminal cleanup uses existing proven
   owner authority; no generic asynchronous-stop recovery is invented.

* Conditional benefit and explicit costs :matrix:

Let =n= be total arguments and =r= raw Scheme arguments. The baseline has =r=
root nodes; the candidate has one node with =n= payload cells and the procedure

Memory benefit requires saved repeated headers to exceed span slots, the added
record pointer and the count word on all other live RC blocks. Allocation-count
savings alone do not establish latency or VM peak improvement. Zero/one/many
raw-input populations must remain separate; no invented scalar ROI or human-day
estimate is used.

The first matched cohort found fixed zero-argument +45.7%, one-input +6.75%
and eight-input -48.3% body medians. This identified redundant zero-root
allocation, not a universal benefit. The final implementation reuses Gambit's
existing PERM predicate; seven constructor controls include failure/GC in this
zero-bank preparation. These initial numbers do not transfer to final code.
