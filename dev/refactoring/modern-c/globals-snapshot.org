** Conditional correctness and counterexamples :proof:
Let N be the registry count at the coordinator cut, R the frozen participant
roster, and I(i)=[floor(i*N/R),floor((i+1)*N/R)). All tasks carry the same
snapshot identity and epoch. The existing partition helper covers [0,N)
without overlapping cell coordinates; actual cells are scanned and rewritten.

Independent live samples do not have this property. For R=2, a first shard
using N=5 ends at2; a later shard using N=6 begins at3, leaving cell2 unvisited.
This is an arithmetic/source counterexample, not a claim of an observed
production crash. Actual registration/PBT observations must establish the
immutable-prefix premise separately.

Other-VM append is safe only because indices are permanent and append-only,
the stopped VM's entire fixed backing was initialized, and registration does
not write its value cells. A raw foreign store of a moving pointer into the
stopped VM's new suffix invalidates this argument and is not admitted by this
REV. In single-VM mode the frozen source roster and closed bootstrap exclude
append, preserving the bucket graph. Concurrent symbol interning remains a
different shared structure; pre-created permanent symbols keep the native
control honest about that boundary.

The RC gate serializes current-source registration against freeze/cleanup.
The registry gate serializes append, extent capture, shard lease publication
and completion. The permanent gate serializes the cursor even for allocation
callers outside registration. Order is RC -> registry -> permanent, with no
Scheme allocation, callback, barrier or join under these locks. Existing
collectives publish and drain the borrowed snapshot; no new barrier is needed.

Absent, claimed or unknown shards prevent close. A stopped/unknown worker
does not authorize a second scan or release of the coordinator stack record.
The existing GC invocation retains that responsibility. This is safety, not
recovery/liveness of an arbitrarily stopped collector. Global cleanup still
requires the runtime's outer VM/reader drain; one snapshot count is not that
global permission.

** Architecture questions and falsifiers :questions:
1. Why is this modern SMP work? Root extent, source-write admission and scan
   completion have distinct owners and publication points. A per-scanner
   observation can no longer silently define a different root population.
2. What does it amplify in Gambit? Actual moving root cells remain visible to
   the existing frame/continuation scanner; multi-shot restoration is retained.
   The explicit source contract is a prerequisite for independent workers,
   rather than a one-shot control restriction or a replacement of Scheme.
3. Why not hold one global mutex for the whole GC? Other VMs can safely append
   after the cut under the prefix law. A long lock would add cross-VM pauses;
   this design releases it before physical scanning and reuses collectives.
4. What would falsify correctness? An index rewrite, uninitialized suffix,
   admitted value store into a frozen VM, same-VM unclosed writer, stale source
   lifetime or unreturned scan lease invalidates the corresponding premise.
   The real live-count consumer mutation is detected and shrunk natively.
5. Is this a measured performance win? No. It adds synchronization and metadata.
   Cached compiled GLO access is unchanged; reflective registration/lookup and
   permanent allocation incur new gates. Release benchmarks must decide the
   performance tradeoff separately from this correctness requirement.
6. Does this solve Repair9? No. Request/service activation, runnable/wait
   ownership, repeated continuation materialization and resource retirement
   retain their own stages and acceptance evidence.
