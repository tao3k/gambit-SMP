a GSC special case, a second namespace, an iterator snapshot, or a new runtime
language. [[file:models/sysml/hash-index-ownership.sysml][SysML]] owns the contracts;

* OBSERVED Reconstruction roots before final index policy :roots:construction:
:PROPERTIES:
:CUSTOM_ID: reconstruction-roots
:AUTHORITY: models/sysml/hash-index-ownership.sysml construction
:EVIDENCE: evidence/research/revision-admission/construction-results.json
:END:

The current full compiled inventory exposed a different producer failure:
text-roundtrip under concurrent GC lost keys and reached the strict frozen
fromspace boundary. Both text implode and binary deserialize built tables with
flags zero, installed heap references, and only later enabled the final scan
policy. A separate explicit-GC control observes a stale installed key with
flags zero and an updated key with strong construction coverage. This narrows
the mechanism; it does not prove every historical copy failure had this cause.

Both real decoders now use the same reconstruction begin/commit operations.
The shell initializes unused slots before return; installed keys/values stay
strong across intervening safepoints. Commit is nonallocating, publishes final
weak/index flags and preserves explicit reconstruction debt. Binary alloc!
roots the shell before recursively decoding fields. A thrown construction
retains ordinary Scheme root/unwind obligations; no detached recovery or
foreign-owner-death claim is introduced.

This composition also depends on the existing collector/layout split: GC may
repair references and remove dead weak entries, but it must not permute table
slots. A decoder can resume its private next-slot cursor after GC only under
that contract. Merely enabling strong keys while retaining collector-side
rehash would still invalidate the construction cursor. The SysML construction
edge to reference repair and the existing traversal contract express this
dependency; native between-store checks verify the same relative key/value
slots after relocation. Final index reconstruction stays with the mutator
owner and explicit NEED_REHASH debt.

The existing hash QNT now also checks a representative installed key during
construction:17 tests pass; finite safety covers2160 distinct states with an
empty queue; the flags-zero construction counterexample remains executable.
This is one existing scheduler model, not a second Lean interleaving proof.
The existing Lean reference-transport premise is unchanged; real pointer
coverage and exception/foreign adapters remain C refinement obligations.

Actual source bootstrap, unchanged roundtrip/concurrent-GC fixtures and the
native Scheme between-store/commit regression pass in the linked packet.
The current full original aggregate and the remaining root/exit obligations
still determine commit admission. No table layout lock, heap enlargement or
permission to copy tospace was added.

The private rehasher now has exactly two C call sites, both in the native
mutation API. Its definition remains in =weak-tables.inc=; the GC processing
function no longer calls it. The GVM macros in =gvm_operations.h.in= still call
the same three C functions, including both UNION and FIND. Their public function
table/ABI and the Scheme generator remain unchanged by this cut.

Scheme-owned hashing keeps the earlier SCHEME_INDEX contract: GC does not
substitute the native address algorithm or invoke a user hash callback.
Deserialization NEED_REHASH remains distinct from native KEY_MOVED. The existing
Scheme reconstruction path, not a read-only native scan, owns that debt.

The [[file:../../../vendor/gambit/doc/gambit.txi::@deffn procedure table-for-each][Gambit manual]]
already forbids same-table public query/mutation operations during a
=table-for-each= call. This cut does not silently lift that public restriction.
The fixture's nested lookup uses the private native primitive on an already
rooted GC-table object, avoiding a public table-access prelude.

* Net work and peak-memory matrix :decision:
:PROPERTIES:
:CUSTOM_ID: hash-layout-net-work
:END:

For an interval of unchanged capacity, let m be table key-slot capacity,
k the key-field slots visited by the strong memory-key scanner, G the number of
ordinary GC episodes, Q the reads performed with address debt, and U the
mutations which settle it. Let b be reconstruction cost per slot, l linear
comparison cost per slot, h the displaced hash-lookup cost, and c the added
before/after key-slot comparison cost. The scan includes empty/deleted slots;
k is not merely the number of live keys. If capacity varies, use the sum of
each episode's actual capacity and scanned slots. These are cost parameters, not assumed
benchmark numbers.

#+NAME: hash-layout-net-benefit-matrix
| Workload / responsibility | Removed work or hazard | Added work / peak | Positive condition or refutation |
|---------------------------+------------------------+-------------------+----------------------------------|
| Permanent-symbol native table | GC-induced reordering and speculative whole-table reconstruction | G*k extra identity comparisons; no new address debt for unchanged keys | Saves reconstruction traffic if G*m*b exceeds G*k*c; the regression demonstrates correctness, not a measured speedup |
| Moving-key table | GC no longer invalidates a suspended cursor | Q linear reads up to m slots, plus U writer rebuilds | Relative index work improves only when G*m*b > G*k*c + U*m*b + Q*(m*l-h) |
| Read-heavy moving-key table | Pure reads no longer acquire hidden write authority | Debt can persist indefinitely with no writer; repeated O(m) reads | Large Q can make this slower; no universal net-performance claim |
| Collector critical path | Native slot permutation leaves the stopped-world repair phase | Actual key-movement comparison remains | Less GC layout work does not by itself prove a shorter end-to-end pause |
| Safepoint latency | No extra collector callback or Scheme hash invocation | A large noncollecting linear C query can delay that context's next safepoint | No constant-time latency promise independent of m; a future interruptible query needs real frame/root/reload state, not an unrooted GC poll in this loop |
| Incremental table metadata | No new owner registry, reader count, version field or traversal snapshot | Reuse KEY_MOVED and existing flags; one temporary key value in scan and a loop index | Delta in heap/table fields is zero for this cut, not for the entire cumulative modern-c refactoring |
| Weak semantics | No snapshot that accidentally keeps dead weak keys alive | Existing weak-phase deletion and root retention rules | Dead weak bindings may disappear; fixture roots all 97 weak keys/values intentionally |

An iterator snapshot would add O(m) storage/root lifetime and could change weak
liveness. A reader registry needs lifetime rules for continuation escape and
unknown owners. Stable object identity may restore O(1) native lookup but has
object-layout and transport costs. None is introduced without its own evidence.

physical-layout authority to GC, and a read no longer silently becomes a
reconstruction writer. This preserves Gambit's existing higher-order/control
path while exposing the real performance and recovery costs.
