** Concrete failure and responsibility replacement

The92d native interner correctly serializes each individual lookup/rehash.
The Scheme fold still carries a bucket-vector alias between user callbacks.
Rehash rewrites permanent symbols' intrusive NEXT links. A callback that interns
enough names can therefore change the remaining traversal even on one processor.
A mutex around each native insertion cannot make that Scheme control lifetime
own a stable topology; a mutex held over callbacks would deadlock reentrant
interning and span arbitrary GC, exceptions and continuation escape.

The new boundary copies canonical identities into one Scheme-managed vector
before the first callback. The native service owns capture; ordinary Scheme
frames own traversal and GC/continuation lifetime. No bucket or NEXT is read
after entering user code. This replaces one complete higher-order fold
responsibility, not every raw private-table reader.

** Capture, publication and failure contract

#+NAME: view-capture-cuts
| Cut | Owner and invariant | Failure / unknown disposition |
|-----+---------------------+-------------------------------|
| Query | Existing registry gate reads valid permanent table/count N | Error uses existing heap-error protocol; no destination/native resource |
| Allocate | Scheme constructs vector[N] outside gate and roots it through generated frames | Allocation may GC or escape; no native lock/buffer/root registration to clean up |
| Copy preflight | Under gate compare current count with vector length | Mismatch returns new count, writes zero cells; Scheme retries with a new private vector |
| Copy | Gate excludes native NEXT/count/rehash writers; copy exactly N identities in existing descending-bucket order | Bound/type/count inconsistency returns error; partially filled vector remains unpublished ordinary Scheme state |
| Deliver view | Scheme returns vector only on successful matching count | Native retains no view pointer, permit or record after return |
| Callback / resume | Managed frame and captured continuation retain view; no registry lock held | Exceptions/nonlocal escape use existing Scheme unwind/GC; multi-shot resumption shares that same view |

The copy service does not secretly collect. Holding its gate delays competing
native writers and GC polling for O(bucket count+N) work. Under infinitely
growing registration, query/allocate/copy may retry indefinitely; finite completion
requires a stable-size interval. No timeout/heap increase or liveness theorem
is inferred. Arbitrary death inside the existing registry critical section is
still outside the native service admission.

The view is isolated from registry writes, not universally immutable. Intentional
mutation through a caller-owned vector alias changes that private Scheme object
and cannot rewrite the registry. The higher-order entry does not expose its local
vector to its callback. Reflective frame mutation/arbitrary concurrent alias
writers remain explicit ROOT-WRITERS premises rather than being silently forbidden
by changing Gambit's shared-object semantics.

** Conditional refinement and falsifiers

1. With92d canonical native publication and exclusive gate ownership, the table
   has N permanent entries. Matching-capacity copy either visits exactly N valid
   subtype identities and succeeds, or refuses publication. It preserves the
   old traversal's order at capture, before callbacks run.
2. A changed count is checked before the first store. Thus abandoned destination
   storage is still initialized Scheme memory; no retry duplicates a registry
   insertion or acquires an extra native owner.
3. After capture, native rehash cannot access the managed vector. The fold's
   next identity is read from that vector rather than an intrusive global NEXT.
   A callback-triggered grow may change the registry but not the entry set of
   the suspended fold.
4. Existing compiler/frame/GC rules root the ordinary vector. Capturing inside
   a callback retains its frame once; multiple resumes reuse the heap view.
   Existing dynamic-wind transitions remain intact. The claim assumes sound
   ordinary Scheme frame/root consumers and does not prove the whole collector.
5. A normal callback exception, nested fold or nonlocal escape has no native
   capture resource to drain. This is a consequence of ending native ownership
   before arbitrary Scheme control, not a new FFI cleanup guard.

Falsifiers: destination changes on size refusal; duplicate/missing/noncanonical
identity; later rehash changes a retained view; a resumed fold sees new membership;
incorrect dynamic-wind counts; callback escape prevents the next registry call.
The PBT suite must exercise these through actual Scheme/C, not a second simulator.

** Mandatory architectural answers and next cut

This is fundamental for the selected fold because ownership follows the
*semantic execution lifetime*: registry capture ends before callbacks, while
Scheme-managed state covers suspended and multiply resumed control. Per-store
patches, extra heap and longer waiting cannot give a live intrusive chain that
property. The old loop must disappear from production, not remain as a fallback.

Gambit's shared canonical identities and multi-shot continuation are amplified:
an extensible native registry can coexist with a retained higher-order computation
without imposing one-shot effects or isolated actor heaps. It remains a bounded
foundation, not proof of independent W/R workers or repaired SMP stress capacity.
