The candidate does not narrow an out-of-range unsigned value by a signed cast.
It reconstructs the managed word representation through memcpy into a local
signed word, then performs the volatile store while the existing source mutex
is held. The target premise is equal-width C23 two's-complement word types;
actual qualification covers64-bit GCC/Darwin. No new word field, allocation,
mutex table, namespace or concurrent-owner identity is introduced.

[[https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf][C draft N3220]]6.3.1.3 retains implementation-defined out-of-range signed
conversion; two's complement does not justify pretending that cast is a fully
portable conversion rule. Unsigned arithmetic and representation are separate
steps here. Its7.17.4 specifies fence ordering. A fence is not thread stop or
a cure for ordinary data races. [[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fatomic-Builtins.html][GCC atomic documentation]] likewise requires
race-free protocols and explains that fences work with appropriate accesses.
Current ticket publication still uses actual acquire/RMW/mutex handoff.

The parent strict diagnostic fails on signed max+1 in the actual emulated C
function. Candidate runs the same queued native test under UBSan with no such
failure. This diagnostic deliberately disables -fwrapv; the existing production
profile keeps it, so its old behavior is not labeled a production UB failure.
C23 atomic support is a requirement for the revised fallback fence; no claim
is made for compilers without that support or an actual CAS-less machine.
