* RESEARCH Decision
:PROPERTIES:
:CUSTOM_ID: decision
:AUTHORITY: GambitRestoreEntryIssuers
:BASELINE: C23
:STATUS: bootstrap-and-admission-model; real-issuers-open
:END:

A complete restore contract classifies semantic intent at the caller, not from the shared primitive spelling. The source-root owner must establish custody before an allocating guard registration, not merely before ___call. These are mandatory modern-C runtime boundaries. No Zig-specific capability is needed to state or prove them.

The current source contains partial ingredients, but this study identifies no complete native issuer of the proposed exact TicketId guard. Candidate insertion points are not existing signers. The stable reservation issuer must own the VM/native entry domain and a source-generation lease; the completion issuer must own the actual outer catcher and parent binding after return/unwind. They can share storage, but their evidence and authority differ.

[[file:models/sysml/restore-entry-issuers.sysml][SysML]] owns source anchors, caller-role rules, issuer responsibilities, component/action/proof routes, scoped needs and benefit rows. Native queries generate [[file:restore-entry-issuers-matrix.org][Org]] and [[file:diagrams/restore-entry-issuers.d2][D2]]. The [[file:../../modeling/ascent/restore-entry-issuers.rules.scm][actual ASCENT DSL]] requires source hashes, owners, action names and proof identities, not merely associated filenames. This extends [[file:restore-entry-guard-design.org][the preceding restore/guard study]] without altering its historical evidence.

* RESEARCH Source census and intent taxonomy
:PROPERTIES:
:CUSTOM_ID: census
:SCOPE: vendor/gambit lib,gsc,tests,examples,include; scm,h,c,inc
:LIMIT: literal enumeration; not expanded or indirect call closure
:END:

The driver records the complete searched file roster and hashes, every matching line and a bounded lexical owner classification. It retains comments, generated metadata and inactive branches explicitly; their presence does not establish a runtime caller. Imported external modules, first-class aliases, macro-generated names, dynamically evaluated code and effective configuration expansion are not covered by literal enumeration. Unknown provenance must deny the optimized receipt rather than being silently classified as navigation.

|---+---+---+---|

| Direct graft in active contcapgraft examples | Fresh graft invocation | New external AttemptId | GVM caller provenance and incoming values required |

| continuation-graft-aux / return-aux | Values/argument packing, same-denv fast path or winding for an invocation | Preserve invocation identity | Root maps must cover allocations before final low-level jump |
| continuation-unwind-wind internal graft | Restore transaction navigation | Same ticket | User before/after may escape or invoke a new continuation; the callback body is not globally restricted to navigation |
| Local queue / steal / alternate scheduler | Existing suspended execution | Same ticket; carrier handoff | Qualified context identity, scan ownership and C affinity |

[[file:../../../vendor/gambit/gsc/tests/15-cont/ctak.scm][ctak]] directly calls the no-winding primitive with extended bindings. [[file:../../../vendor/gambit/gsc/tests/15-cont/contcapgraft.scm][contcapgraft]] contains active zero-to-three argument cases and additional block-comment cases. These are inspected source examples, not executed tests. The primitive registry and [[file:../../../vendor/gambit/gsc/_t-c-2.scm][jump inliner]] confirm direct recognition/emission. A wrapper-only entry hook therefore cannot provide complete admission.

[[file:../../../vendor/gambit/lib/_thread.scm][The runtime wrappers and scheduler]] reuse the same primitive through arity packing, winding and scheduling. An intent capability must identify source PointId, invocation/operation identity and parent restore transaction. Internal privilege is validated against generated caller role or an admitted runtime capability; arbitrary Scheme code must not forge a navigation tag to evade a fresh invocation boundary. The exact producer/validator representation remains a design obligation.

* RESEARCH Where the FFI bootstrap really begins
:PROPERTIES:
:CUSTOM_ID: foreign-prologue
:END:

[[file:../../../vendor/gambit/gsc/_ptree2.scm][c-make-function]] emits BEGIN_SFUN before convert-param-list. It prioritizes Scheme-object conversion within that later list, but does not move conversion before the BEGIN macro. [[file:../../../vendor/gambit/include/gambit.h][BEGIN_SFUN]] allocates the marker; BEGIN_SFUN_ARG_SCMOBJ is empty; SFUN_ARG stores an argument on the Scheme stack later. Consequently, a generic root registration inserted only at ___call or within the later argument body is too late for this allocation window.

This is a limitation of the proposed blanket admission proof, not proof that every current callback loses an object. A static MLBL destination, a still vector with retained ownership, a registered RC slot and a raw movable object each require different evidence. Static code identity does not prove that all Scheme-valued C arguments are rooted. The bootstrap model covers entries carrying live Scheme payloads. A static-label entry with only native values may use an empty payload contract after module/code lifetime is qualified; this is not a reason to allocate a synthetic Scheme root for every call. A nonmoving object address does not prove its native owner cannot release it.

[[file:../../../vendor/gambit/examples/tcltk/tcltk.scm][Tcl]] installs a still vector into cd via set_data_rc and later reads data_rc at scheme_call_cmd. [[file:../../../vendor/gambit/lib/memory/rc-allocation.inc][RC allocation]] separates list registration from payload assignment and exposes ordinary data reads/writes. [[file:../../../vendor/gambit/lib/memory/rc-roots.inc][mark_rc]] updates the actual data slot. A raw copy returned to a native local is not automatically updated by that scan, and registration alone does not prove deletion/cleanup exclusion or arbitrary-thread admission. Bootstrap requires a live source owner lease, scannable slot and nonallocating handoff before callback prologue allocation.

[[file:../../../vendor/gambit/lib/setup.c][Managed ___run startup]] passes context->startup_thunk to the rooted helper. [[file:../../../vendor/gambit/lib/memory/root-origins.inc][mark_execution_roots]] scans that slot and entry_marker. These consumers can be reused after their origin membership and scan epoch are qualified. The generic legacy helper explicitly says that passing a local address does not register roots. This existing managed special case is not a universal FFI guard.

** Conditional dynamic C closure path

[[file:../../../vendor/gambit/lib/c_intf.c][SCMOBJ_to_FUNCTION]] distinguishes static c-define code from dynamically allocated C closure. [[file:../../../vendor/gambit/lib/os_dyn.c][os_dyn.c]] stores the closure procedure in RC data, describes a trampoline writing c_closure_self, and has an explicit TODO that this global needs to be thread-local. The marker helper reads data_rc(c_closure_self()) after allocation.

A conditional counterexample is therefore: ambient self=A; marker allocation or another admitted transition permits callback B to change ambient self; resumed A reads B. Thread-local storage would exclude some cross-thread interference but cannot by itself prove same-thread nested restoration. A bound payload and lifetime lease before allocation avoids dependence on a later ambient lookup. The current source does not prove that marker allocation actually performs such a nested callback, so that concrete nested history remains unresolved.

The dynamic closure generator is architecture-gated; the inspected conditions cover historical x86-32/PPC/SPARC cases and return null when no code size is defined. This is not evidence that the path is enabled on Darwin arm64. Static c-define callbacks remain a distinct source family. Platform selection and executable correspondence must be qualified before promoting any conditional counterexample to a current-platform defect.

* RESEARCH Nonallocating bootstrap and stable issuers
:PROPERTIES:
:CUSTOM_ID: protocol
:END:

#+NAME: ingress-bootstrap
#+BEGIN_EXAMPLE
classify caller intent and source kind
 -> validate SourceRootId / generation / owner
 -> nonallocating source pin
 -> initialize a pre-reserved registered carrier slot
 -> publish/acknowledge scan-visible target custody
 -> allocate stable guard while carrier is live; reload after GC
 -> publish immutable GuardId and parent binding
 -> release source only after target root acknowledgement
 -> marker allocation / argument conversion / destructive restore
 -> outer completion owner restores binding/catcher and closes marker
 -> exact-key terminal publication before reply
#+END_EXAMPLE

A source pin cannot be implemented by waiting for GC while holding a lock needed by the collector or callback completion. The owner supplies a reserved slot or rejects optimized admission before allocation. If pin/slot registration itself may allocate, it needs an earlier independently protected source; circularly claiming that the future guard protects its own inputs is invalid. No reserved-slot allocator is implemented or proved here.

The stable guard issuer needs VM/native-domain storage independent of captured frames and stack-local completion variables. Its reservation includes immutable TicketId, GuardSerial, owner generation, parent binding, source lineage and custody state. A source owner may attest a slot, but cannot independently attest that the foreign outer stack has exited. A ledger may retain a terminal outcome, but cannot manufacture that exit proof.

The outer guard wraps the actual host-entry operation, including conversion, not just its final ___call. ___call may propagate an unmatched unwind; ___run's TRY and marker handling supply partial integration points. A generic SFUN prologue still lacks an identified full exact-key reservation/completion issuer. No source anchor is labeled as already implementing the proposed guard.

* RESEARCH Failure ownership and C23 ordering
:PROPERTIES:
:CUSTOM_ID: failure
:BASELINE: C23
:END:

| Failure/cut | Custody | Release condition |
|---+---+---|
| Source origin or generation unqualified | Original source/caller | No optimized receipt; preserve baseline semantics |
| Reserved carrier unavailable | Source owner | Fail admission before allocating or switching; no invented accepted ticket |
| Guard allocation fails before acceptance | Source plus carrier escrow | Reconcile exact reservation; restore source or acknowledge transfer before dropping carrier |
| Guard commit outcome unknown | Stable reservation owner | Query exact reservation; never allocate an unrelated replacement as retry |
| Marker or argument conversion fails | Stable host guard | Complete failed entry only after actual outer cleanup evidence |
| Unmatched unwind / callback escape | Outer completion owner or retained recovery owner | Rooted guard survives; UNKNOWN is not absence |
| Source deletion or processor exit races handoff | Source owner until acknowledged target custody | Source pin, origin generation and scanner lease must be closed coherently |
| Old receipt during new invocation | Old exact ledger record | Cached old outcome or defined rejection; no ambient retarget |

C23 publication must make initialized carrier/guard state visible before consumers act on it. Source and target root-domain epochs must agree on the handoff cut; ordinary atomic pointer publication does not establish GC scan membership. Use a qualified short owner critical section or specified atomic protocol, with no lock spanning Scheme, allocation, collector waits or native callbacks. Complete outcome and custody publication precede acknowledgement. Finite generations, ABA prevention and stable owner retirement remain platform/refinement obligations.

The model's moving-GC version is a logical slot revision, not a numeric address ABI or a promise to pin movable objects. It assumes valid source classification and collector updates to admitted slots. Retained UNKNOWN records may consume unbounded memory without a reconciliation policy; liveness and bounded retention are not proved.

[[file:models/quint/restore_entry_issuers.qnt][QNT]] models source classification, pin, carrier publication, moving-GC updates, allocating reservation, source release, marker allocation, execution, exceptional escrow and outer completion. Navigation, scheduling and conversion operations reuse an admitted existing execution rather than allocating a new ticket. Raw local sources cannot enter the allocating reservation path. Ten history checks inspect these cuts without running Scheme/native programs.

The restricted typed-IR projection generates [[file:models/lean/RestoreIssuerAst.lean][Lean AST]]. [[file:models/lean/RestoreIssuer.lean][Lean]] proves initial safety and each of the 25 modeled actions, reachable safety, carrier revision consistency, raw-source exclusion, source-release ordering and reuse without fresh issuance. Four corrupted-IR controls check the extractor's restricted binding contract. Negative proof controls remove the carrier prerequisite or stop GC updating the carrier revision; preservation must fail. Initial proof-tactic failures are retained separately from semantic counterexamples.

[[file:models/lean/RestoreIngressBridge.lean][The explicit Admission relation]] connects the published bootstrap to the earlier two-ticket entry: intent, roots, reserved guard, parent/current binding and marker condition must agree. entryAgreement derives the earlier enter guard; admittedSuccessorSafe then invokes its established step proof. ReuseAdmission separately requires a real live/parked prior guard: reuseAgreement derives bootstrap reuse eligibility, while schedulerBindingAgreement and navigationBindingAgreement derive the corresponding earlier-model guards. A source root alone cannot attest that prior execution. Conversion operation identity remains an external host-entry premise. This is a concrete conditional composition, not an assertion that the entire native runtime simulates both models. The imported arbitrary-key algebra proves that changing ambient execution cannot retarget an old witness; the actual native witness producer remains open.

ASCENT joins twelve component/action/source/proof routes. Only scoped formal and bridge receipts are supplied as current proof evidence. Missing action, lemma, entry route, issuer, source hash, owner or scope must block qualification. Synthetic all-premises success is not native evidence. [[file:../../../evidence/research/restore-entry-issuers/checks.json][Receipts]] distinguish these results from the five remaining source/platform/equivalence gates.

* RESEARCH Migration, benefit and retirement matrix
:PROPERTIES:
:CUSTOM_ID: benefit
:END:

The migration replaces responsibilities, rather than layering another generic wrapper: first add generated caller-role/root declarations; then move allocating FFI entry under a common pre-marker carrier contract; finally replace frame-local or ambient-dependent completion inference with exact-key owner records. Keep C marker liveness/affinity checks and baseline unrestricted continuation behavior until an equivalent replacement is proved. No native path retires in this study.

| Architectural change | Work potentially eliminated | Added work | Positive-net-benefit condition | Current evidence |
|---+---+---+---+---|
| Caller-qualified reuse | H+S+O fresh ticket allocations under a rejected per-hop design | Intent validation and carrier transfer | All reuse roles qualified; untrusted tags cannot suppress real invocation | Conditional model; complete semantic census open |
| Shared pre-marker carrier | Per-wrapper root and failure bookkeeping that can actually be replaced | Source pin, reserved capacity, scan acknowledgement | Migrated callers retire old duplicate support; bootstrap is genuinely nonallocating | Actual consumers located; issuer unimplemented |
| Bound foreign payload | Ambient identity re-read across relevant allocation/reentry | Payload lease and explicit binding | Dynamic path active and native lifetime/scan handoff qualified | Conditional historical path; Darwin activation unresolved |
| Stable outer guard | Duplicate cleanup and premature root release | One record per semantic/foreign entry, outer cleanup, retained outcome | Every exceptional exit has an owner; no callback/collector lock cycle | Bootstrap and entry composition proved under premises |
| Second normalization retirement | At most one redundant resource traversal D | Marginal ingress, root, query and unknown-retention costs | D exceeds all added costs and all writer/issuer/emission gates close | Zero claimed native retirement or speedup |

For E new semantic invocations and F foreign entries, intended fresh-ticket work is proportional to E+F, not E+F+H+S+O, where H is internal graft navigation, S scheduler resumes and O internal conversion operations. This is a comparison between design policies, not measured savings relative to today's Gambit, which has no such ticket system. Shared support is charged once; root scanning, pins, unresolved custody memory and ABI invalidation remain real costs.

** Explicit accounting boundary
:PROPERTIES:
:CUSTOM_ID: accounting
:END:

The model's allocations counter records its successful guard/marker operations. It does not price failed allocation attempts, allocator instructions, collector work, resident bytes or elapsed time. Let A_fail be failed/reconciled reservation attempts, Q keyed queries, U unresolved guards and R_extra additional scanned slots. A necessary work condition is:

#+BEGIN_EXAMPLE
DeltaW = removedTraversalWork + actuallyRetiredOldSupportWork
         - [E*c_sem + F*c_ffi + (H+S+O)*c_validate
            + A_fail*c_attempt + Q*c_query
            + extraGcWork(R_extra) + reclamationWork]
DeltaW > 0
RetainedMemory includes U * (guardRecord + retainedRootClosure),
with no established bound on U or closure size in this study.
#+END_EXAMPLE

These are symbolic cost obligations, not invented numerical speedups. If source pinning serializes producers, UNKNOWN retention grows without bound, or migrated callers keep both old and new bookkeeping, positive net benefit is not established even when the safety models pass.
