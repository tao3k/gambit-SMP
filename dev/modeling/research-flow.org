* DESIGN Fresh execution and source publication
:PROPERTIES:
:CUSTOM_ID: research-execution-lifecycle
:IMPLEMENTATION: ../../src/gambit_smp/research_flow.py
:END:

Each executable study receives a fresh =.cache/tasks/TASK/runs/RUN/= identity.
Execution-time workspace reads now use the existing owner context: CACHE maps
to work, while OUT/EVIDENCE map to results. Module-level old paths are immutable
task-selection hints, not active output destinations. The shared lifecycle never
mutates caller globals or inspects/rebinds helper module dictionaries. Nested
studies still require independent processes. Owner retirement revokes workspace
access before resetting the ContextVar, including a copied callback context.

The execution record begins at =running= and ends at =completed=, =unavailable=
or =failed=. It always keeps =evidenceAccepted=false= and =runtimeAdmitted=false=.
Old success files are not copied into the fresh workspace. Proof acceptance
still belongs to the relevant semantic verifier and source-bound publication.

Study text/byte writes to maintained source produce a cache preview and compare
against the existing bytes. Equal views require no source write. A difference
raises =SourceViewDrift=; the source remains unchanged. Native output arguments
must target the current run. Unknown native executables are rejected. Full
subprocess effect confinement remains unresolved: recognized tool names and
declared output checks are necessary conditions, not an OS sandbox or proof of
all indirect native writes.

The legacy cache archive is read-only to framework Python. New replaceable
projections, including =formal-bindings.json=, are outputs of the selected task;
they are not prerequisites that a clean checkout must somehow already contain.

* ARCHITECTURE Converge on the existing framework
:PROPERTIES:
:CUSTOM_ID: framework-convergence
:AUTHORITY: models/sysml/research-storage.sysml::GambitResearchStorage::frameworkBoundary
:STATUS: designed-not-migrated
:END:

The storage audit count is coverage, not a desirable program architecture.
The 362 Python files include framework modules, projectors and helpers; they
are not 362 independently necessary research programs. The tool directory has
80 files defining =sha=, 77 defining =save=, 49 defining =run=, 123 directly
constructing an ASCENT Engine and 53 directly calling subprocess APIs. These
are source-census observations, not estimates of semantic equivalence or speed.

The prior mass entry rewrite contains unsafe output but leaves overlapping
lifecycles. =research_flow.study_execution= allocates its own UUID and completion
record and rebinds module globals, while the established framework already has
task/output allocation, =ExecutionContext= and durable execution records. This
transitional layer must not become a second permanent research framework.

| Responsibility | Existing owner to reuse | Standalone code to retire |
|----------------+-------------------------+---------------------------|
| Task/run identity and storage | workspace, task_entry, cli | Per-study CACHE/OUT globals and UUID lifecycle |
| Processes, deadlines, outputs and completion | recipes.ExecutionContext; research_kernel | Repeated run(), subprocess logging and independent receipts |
| Source identity and missing evidence | source_identity; evidence_views | Ad hoc hash checks and local-cache prerequisites |
| Checked ASCENT sessions | ascent_program | Unowned per-study Engine setup and teardown |
| Architectural meaning and proof obligations | Owned SysML model; existing typed Recipe projection | Per-study orchestration encoding the same plan in Python |
| Domain translation and decoding | Explicit tested projectors/adapters | Only duplicated support; retain necessary domain semantics |

The existing execution registry currently covers Quint model operations and
evidence evaluation. Its pure-model admission recognizes Quint specifically.
SysML projection, Lean checks and design-view publication need explicit typed
capability review; they cannot be integrated merely by pointing a Recipe at an
arbitrary Python script. Complete those capabilities in the existing registry
and reuse its execution protocol rather than add another runner, manifest or
general-purpose mega-script.

The old-header and Makefile investigations are the concrete migration chains.
Source references should bind immutable source identity plus an unambiguous
symbol/field or target contract. Coordinates are derived observations. A
modular-header layout change should update one owned source adapter or model,
not require editing every study's file I/O and lifecycle. Ambiguous resolution
stays unresolved; Makefile drift cannot be repaired by silently resigning a hash.

Retirement requires the same failure and unavailable outcomes, unchanged
resource limits, retained negative controls and a cache-free source checkout.
After those hold through the existing managed entry, delete the old launchers,
global-rebinding bridge and redundant receipt writers. New studies normally
add or change models, data and fixtures. New compiler/runtime semantics can
still require a domain adapter change; no claim of configuration-only evolution
or completed framework convergence is made.

=gambit_smp= module must originate there. Unavailable views must produce
incomplete evidence coverage with =runtimeAdmitted=false= and
=executionAuthorized=false=. Neither the original editable installation's
project code nor its local evidence cache is a fallback.
