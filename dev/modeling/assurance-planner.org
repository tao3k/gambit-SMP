ModelNeed has a component owner, local obligation ID, kind, premise, exact
subject path and exact subject scope. The key is the pair (component, obligation),
not a global filename or language. For another independent subject, declare
another need and its typed prerequisites. Multiple method/check demands on one
kind are conjunctive: one matching result cannot discharge the others.

Unknown kinds, missing endpoints and unbound producer components remain explicit
diagnostics. Typed native dependencies name both endpoint owners. Their closure
is a proof dependency relation, not an operational wait graph.

* Evidence readiness and transitive reasoning
#+NAME: assurance-dsl-relations
| Relation | Meaning |
|---+---|
| componentFact / boundComponent | Component tied to exact native output, whole source bundle and DSL digest through the task hypothesis |
| needFact / methodFact | Native-owned subject/scope and required modeling/checking method |
| dependencyFact / dependsOn | Cross-component direct edges and positive transitive closure |
| artifactFact / receiptFact | Scenario/component/obligation/method/path/digest/check/scope/status evidence inputs |
| qualifiedSlice | One exact presented artifact/check/scope receipt matches |
| locallyChecked | All method/check demands for this particular need match |
| assuranceReady | This local need and all transitive premises match, with no reachable cycle, dangling need or unbound producer |
| componentFrontier / componentReady | Missing declared evidence frontier, or its absence for a component with actual needs |
| missingModel / pendingCheck | Absent subject or missing/mismatched required result |
| unmetDependency / dependencyCycle | Missing transitive premise or cyclic proof demand |
| danglingDependency / unboundDependency | Missing need declaration or unmatched producer identity |
| nextAction / openPremise | Construct/check/resolve/policy/repair work and remaining argument |
| sharedContract | Typed producer/consumer scope, guarantee, rely and failure custody; association is not satisfaction |

Let D+(n) be the transitive prerequisite set. The intended evidence predicates are:

\[
L_s(n) = \bigwedge_{r\in Required(n)} Match_s(r),\qquad
R_s(n) = L_s(n) \land \bigwedge_{p\in D^+(n)} L_s(p)
         \land ValidReachableGraph_s(n).
\]

ValidReachableGraph excludes cycles, dangling needs and unbound producer
identities. This distinction prevents a supplied local source-proof receipt
from hiding its missing grandparent premise. componentReady means only
completeness of the *declared evidence classes under the presented snapshot*.
It is not semantic truth of input facts, whole-system proof or runtime acceptance.

Receipt matching includes component, obligation, method, declared subject path,
current digest, check class, exact symbol/history scope and pass status. Matching
bytes do not independently authenticate the producer; actual retained command
receipts, traces and namespace probes must justify genuine input facts. Synthetic
all-pass or altered receipts are labeled planner-control-only.
