* Quantification without invented performance numbers :cost:span:memory:
:PROPERTIES:
:CUSTOM_ID: useful-parallelism-budget
:EVIDENCE_CLASS: accounting-model; not-native-measurement
:END:

For a chosen post-rendezvous GC interval, let A(W) be total normalized worker CPU
work, S(W) its dependency span, M(W) actual memory traffic and beta a justified
upper bound on available bandwidth. A useful lower-bound model is
=T_gc >= T_enter + max(A(W)/W, S(W), M(W)/beta)=. Keep units consistent; actual
elapsed time also pays scheduling, phase boundaries and resource effects. This
is our accounting requirement, not a paper benchmark or a proved C cost bound.

The entry term depends on the last required participant; adding workers cannot
remove it. Report work export delay, serial root prefix, queue/CAS traffic,
destination revisits, private/Tail debt and phase waits separately. Copied bytes
alone miss revisits and pointer-only scanning. Preserve pairwise same-work
baseline/candidate identities and the existing heap/watchdog limits.

#+NAME: smp-benefit-admission
| Claim | Required numerical observation | Refutation boundary |
|-------+--------------------------------+---------------------|
| Less repeated work | Same-work capture/materialization, root visits, lookup and reservation counts; normalize units before combining costs | Removed operations may be outweighed by gates, metadata and synchronization |
| Useful parallel collection | Per-worker CPU/scan/copy work, W, export/start delays, critical phase times and total wall time | Balanced counts with serialized execution, scarce work or bandwidth saturation |
| Better minor collection | Complete allocation interval and major cycle: mature work avoided versus barriers, dirty scanning, promotion and extra majors | Mature scan reduction without accounting for changed frequency/major work |
| Safe bounded capacity | Simultaneously live physical copy/restore/retained intervals, actual backing and peak | A later refund or virtual reservation is not an earlier physical peak reduction |
| Robust lifecycle | Fault/unknown paths with exact retained roots/resources and healthy independent-VM progress | Successful local cleanup, process-wide fatal exit or dropping an unknown debt does not prove isolation |

All current values for these prospective claims remain UNMEASURED in this study.
Historical regressions in [[file:../../refactoring/modern-c/post-delivery.org][the source-bound cost ledger]] remain counterevidence.
There is no unconditional speedup or constant-space claim for arbitrary shared
graphs, retained continuations, external arrivals or native blocking.

** RESEARCH Concrete work publication and termination chain :source:ownership:
:PROPERTIES:
:CUSTOM_ID: concrete-work-chain

The [[https://simonmar.github.io/bib/papers/parallel-gc.pdf][ISMM2008 discussion, sections3.5-3.6]], relates active-producer accounting,
pending blocks and scarce-work export. Gambit's actual mechanisms below must be
qualified under their own C/VM contracts; the paper's counter protocol or tuning
threshold is not transplanted. These are one composed chain, not separate REVs.

#+NAME: concrete-work-ownership
| Boundary / actual source | Established source mechanism | Remaining complete-owner requirement |
|--------------------------+------------------------------+--------------------------------------|
| Root union -> collector: root-tasks.inc | Root tasks retain source kind/context/epoch while executor assignment can use W workers for R domains | All sources publish complete views; W<R must not confuse source observation with scanner authority |
| Initialization -> object scan: copy-reservations.inc / object-scanning.inc | Forwarding/canonical repair may precede payload copying. publish_object_scan sets UNPUBLISHED->READY; scan takes READY->OWNED and completes OWNED->DONE for movable objects | READY requires initialized body; copying owner retains first-field Tail. Duplicate OWNED/DONE returns skip field mutation but retain the first owner's debt |
| Private chunk -> FIFO: heap-sections.inc end_heap_chunk | Writes end marker, transitions chunk0->1, publishes link/tail with ordering barriers under chunk_gate, then signals | All payload/link/boundary state visible before an acquired reader can traverse; publisher remains counted through final publication and private use |
| FIFO -> private scanner: take_heap_chunk | Successful gate acquisition changes1->2 and advances head before returning; failure to acquire returns0 | Return0 can mean contention, not emptiness. | Local frontier / Tail: scan_movable_objs_to_scan, finish_tail | Scans completed chunks then its incomplete local region; cursor tracks progress. Chunk DONE does not settle every object or region lifetime |
| Phase termination: collection-round.inc mark_reachable_from_marked | Scans still/local work, steals, decrements phase count under termination mutex; zero broadcasts, nonzero waits and reactivates | Every potential publisher is counted until its last use. No late uncounted helper/native producer, hidden claim or phase-crossing publication; wake predicates and C ordering need refinement |
| Phase/restore -> lifecycle: heap-sections.inc and collection-round.inc | Strong/weak counts start at W; R participants join phase barriers and restore spans before root union retirement | Worker terminal state is not source/context/OS-thread death. Reserve and last-user debt remain separate from queue completion |

The state distinctions are essential: a complete queue element, a unique object
scan owner, an outstanding first-field Tail and the source/root lifetime are
different things. A duplicate visit can be semantically harmless while still
costing a queue traversal, state probe or cache miss. A busy queue gate cannot
supply an absence proof. The selected atomic/backend barriers remain part of
the C refinement; source comments alone do not discharge it.

There is also a granularity question beyond worker count. =mark_rc= visits one
slot and calls =mark_array= before advancing the RC chain; =mark_array= can follow
a first-field Tail before returning. Partitioning root domains therefore does
not prove that all independent root work becomes available promptly. A graph's
true dependency chain is unavoidable, while delayed export of independent work
is a different, potentially removable serialization. This distinction requires
matched source/workload observations rather than inference from W alone.

The architectural option is bounded root-range and initialized-prefix work
export under the same source lease. A published prefix must have a valid closed
layout and a unique claimant; the publisher retains its unexported cursor,
reserved interval and Tail. Source completion waits for every child range.
This is not permission to expose a half-initialized object or merely signal the
condition variable earlier. More frequent publication pays extra markers,
locking, metadata, cache traffic and possibly unusable tail slack. Choose no
unmeasured constant threshold or extra configuration knob. This remains a
source-refinement and cost candidate in the whole collector delivery, not an
implemented early-export feature or a new progress item.

#+NAME: collector-memory-order-refinement
| Source backend | Concrete synchronization candidate | Remaining qualification |
|----------------+------------------------------------+-------------------------|
| sync builtins | CAS acquires chunk gate; fetch-and-and clear releases it; explicit synchronize calls remain inside publication | GCC documents these operations as full barriers. Check exact compiler implementation/target, word alignment, atomic-only access to gate and every payload/link read under the gate or independent ownership. Do not infer Clang/Darwin qualification from GCC documentation alone |
| POSIX emulated | CAS and clear each lock the same address-selected hash mutex; checkout now has a C23 seq_cst fence, while the captured historical cache barrier is empty | Same gate address implies the same hash mutex. Its unlock/lock chain may publish preceding payload writes; establish mutex lifetime and every access route. | Win32 | Existing Interlocked gate operations and MemoryBarrier | Preserve selected widths, alignment and condition-variable contract; no Win32 native evidence issued here |

The official [[https://gcc.gnu.org/onlinedocs/gcc/_005f_005fsync-Builtins.html][GCC sync builtins reference]] supports the GCC ordering premise,
not a whole C23 happens-before proof. A future explicit acquire/release C23
adapter must replace the existing atomic abstraction consistently. Mixing atomic
and plain concurrent accesses, or merely removing the two barriers, is not
authorized by this design. No runtime change is made here.

Apple's archived [[https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/pthread_cond_wait.3.html][pthread_cond_wait]] describes atomic mutex release plus wait;
[[https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/pthread_cond_signal.3.html][pthread_cond_signal]] wakes a waiter. These sources do not make a notification
sent before the wait into a stored task. Current end_heap_chunk signals outside
scan_termination_mutex. That observation alone is *not* a demonstrated lost-work
bug: an active publisher can still drain its own FIFO/frontier before decrement.
The adapter must show both that route's completeness and whether useful steal
opportunities can be missed. Safety and prompt parallel progress are separate.

A source-level adversarial schedule is: thief misses a busy gate; publisher
unlocks and signals; thief later decrements and waits. To claim actual lost work,
one must additionally defeat the publisher's own-drain obligation or introduce
an uncounted producer. That last premise has not been demonstrated in current C.
The previous QNT idle guard forbade *any* queued item. That mismatch is now
removed in the existing model: =localDrained= excludes only work for which the
idling worker holds custody, including published items. =producerCoverage=
requires every outstanding private, queued or claimed item to have a counted
owner. Other workers' queued items may remain when this worker idles. The
changed count is a real =idle= step, not hidden as a stutter. A nonterminal wake
may re-count a worker even with no visible queue item, matching the C spurious
wake route. The conditional mapping below closes this abstract guard mismatch;
it does not establish all of its C layout and producer premises automatically.

*** Conditional C-to-QNT counted-work refinement
:PROPERTIES:
:CUSTOM_ID: local-idle-count-refinement
:STATUS: GUARD-MISMATCH-CORRECTED; TOTAL-C-SIMULATION-OPEN
:END:

Let =U(w)= be work currently held by worker w: initialization/copy remainder,
first-field Tail, unscanned local range, its published-but-unclaimed ranges,
still-list remainder, and removed-but-not-finished chunks. Queue location alone
does not determine the owner: successful dequeue transfers custody to the
active claimant even before =active_scan_chunk_= records it. Let =A(w)= mean
counted active in this phase, and =C=sum A(w)=. The composed invariant is:

#+BEGIN_EXAMPLE
every outstanding item has exactly its current custodian
item in U(w) => A(w)
C = sum of counted active workers
idle(w) requires U(w) empty, a fresh own-queue empty observation,
and no unsettled take; it does not require all other U(v) empty
#+END_EXAMPLE

This is a finite-model abstraction of item custody; a real range can stand for
many items. The publication transaction before FIFO linkage is private debt,
not an unowned queued node. The logical phase witness is VM/round/phase, not an
invented extra C API or field. C must establish that witness through control
location, fixed membership and phase barriers.

#+NAME: local-scan-count-step-correspondence
| C interval / linearization | Existing QNT correspondence | Required source premise and retained debt |
|----------------------------+-----------------------------+------------------------------------------|
| scan_still_objs_to_scan removes head, then calls scan | Work stays scanning/private until scan returns; removal is not finish | configuration.inc maps still_objs_to_scan to this work record; mark_array successful still-mark CAS pushes onto the discovering worker's list, not an idle victim's list |
| scan_movable_objs_to_scan follows completed links, claims own FIFO, then incomplete prefix until ptr equals arena.cursor | Complete owned ranges before localDrained becomes true | Prove linked-layout partition and own-FIFO exhaustion at the return edge; a lexical cursor equality alone is insufficient. Only this active worker extends its arena; Tail returns synchronously before idle |
| Another worker succeeds at take_heap_chunk | acquire changes current custodian to active thief | Queue gate serializes head/claim; the transient returned pointer remains a private claim before active_scan_chunk is set |
| take_heap_chunk fails gate CAS | busyTake stutters with no queue observation | It cannot clear queued debt or justify any empty-queue observation, including the owner's local FIFO |
| end_heap_chunk publishes body/link/tail | publish preserves counted publisher until claim or local drain | All writes and intermediate transaction debt belong to an active initializer; READY alone does not discharge Tail |
| Under scan_termination_mutex, decrement count | idle removes exactly one active owner whose U is empty | No external/native/helper producer can assign new work to that inactive owner; queued work elsewhere still has an active custodian |
| condvar return with count nonzero, followed by increment | wake re-counts before subsequent stealing, including a spurious wake | Successful mutex reacquisition; neither queue visibility nor an owned task is required to re-count |
| Last decrement observes zero under mutex | done follows from no counted owner and coverage, not queue sampling | Under complete private/published coverage, zero excludes unfinished work. New admitted publishers must not appear after this cut |
| All-R strong barrier, then process_wills and second drain | arrive/nextPhase introduce the next admitted producer cohort | The model resets its small graph as abstract weak work; actual weak work can overlap already marked identities. No old-phase operation or last user may cross the barrier |

Preservation is local: publication leaves its producer counted; acquire moves
custody to another counted worker; discovery assigns new work to its active
scanner; finish removes debt; idle removes an owner only when its U is empty;
wake adds a counted owner. Therefore all other unfinished items retain counted
owners after idle. At zero there are none. This argument uses no global FIFO
empty snapshot and no persistent-notification assumption. It is a conditional
source argument backed by bounded transition checks, not a proved arbitrary-C
forward simulation or liveness theorem.

The existing Lean =PublishedLifetimeSafe= predicate supplies the data bridge:
queued work, just like private work, implies a counted custodian.
=zeroCountAndProducerCoverageExcludeHiddenWork= derives queue emptiness and
reuses the earlier zero-count theorem; =missingPublishedLifetimeCounterexample=
shows why private-only coverage is insufficient. Lean does not re-prove the QNT
transition invariant, wake behavior or phase changes.

The existing =gc_work_closure= histories include local idle while
foreign queued work remains, a failed steal with no observation, spurious wake,
the queued-owner early-idle counterexample and stale-phase rejection/control.
The earlier histories are retained. Positive source claims still require the
real linked-layout, Tail, all-producer and memory-order premises in the table.

**** Actual source obstruction: own FIFO busy is treated as drained

=scan_movable_objs_to_scan= uses =while ((ptr=take_heap_chunk(work,work)) != 0)=
before switching to the incomplete allocation chunk. =take_heap_chunk= returns
zero both on failed gate CAS and on an acquired empty FIFO. Therefore an owner
that loses this CAS can leave that loop without an authoritative empty result.
The later cursor-equals-arena return and =mark_reachable_from_marked= count
decrement do not independently recheck its FIFO under the gate. This blocks the
localDrained premise, even after the former global-empty guard mismatch is fixed.

A conditional schedule has an active thief holding the owner's gate while
claiming one chunk, with another chunk still queued. The owner's own-FIFO call
can fail and its local drain loop ends. This establishes an ambiguous control
edge, not a demonstrated global premature-termination bug: to establish that
bug one must also show the remaining active workers can all stop without taking
the queued work. That complete layout/gate/progress schedule is not proved by
the current two-item QNT or a lexical source trace.

=busyOwnQueueCannotCertifyIdleControlTest= preserves this missing-premise
counterexample in the existing model: a no-observation result plus omitted
localDrained allows a queued custodian to become inactive and violates
producerCoverage. The deliberate fault is not a native C reachability claim.

The complete runtime responsibility replacement must distinguish three results
at the existing queue boundary: acquired chunk, acquired-empty observation, and
no observation/busy. An opportunistic thief may return on busy; an owner's drain
cannot certify emptiness from it. Existing lock_chunk_fifo provides a candidate
authoritative gate acquisition, but adopting it requires lock order, last-user,
unknown holder and progress qualification. No runtime change is made here.
The owner must retain custody across the last local frontier, initialization,
Tail and published FIFO until that authoritative cut; phase closure consumes
that cut and closed publisher admission. An unknown outcome retains the claim,
queue/arena and gate, rather than retrying or decrementing responsibility.

**** DECIDED Typed three-outcome contract and the complete admission chain
:PROPERTIES:
:CUSTOM_ID: queue-three-outcome-contract
:AUTHORITY: GambitSharedHeapSmp::queueObservationToIdle
:STATUS: MODELLED; C-ADAPTER-OPEN
:END:

The existing QNT now uses the sum type =QueueObservation= with =Acquired(item)=,
=ConfirmedEmpty= and =Unobserved=. A returned outcome is interpreted only for a
settled operation. This is the semantic contract for the existing queue
boundary, not a new runtime namespace, runner or unbounded receipt registry.

#+NAME: queue-observation-custody
| Settled outcome | Observation and linearization | Work and resource custodian | Permission withheld |
|-----------------+-------------------------------+-----------------------------+---------------------|
| Acquired(item) | Under target gate, claim and queue removal select exactly this initialized item | Active claimant owns the removed chunk/private scan; publisher keeps every other unpublished or queued range. VM retains queue/control storage | Receipt is not scan completion, Tail completion, idle permission, restore or physical reclaim |
| ConfirmedEmpty | Successful gate acquisition observes empty head/tail for the identified queue, VM/round/phase and logical revision | Existing private/frontier/still/initialization/Tail holders keep their debts; queue/control lifetime remains with its lifecycle owner | Empty own queue alone does not prove local drain; empty foreign queue cannot certify own idle; the observation is not a permanent no-publisher seal |
| Unobserved | Known unsuccessful gate acquisition; no queue observation was obtained | This operation transfers no node. Every pre-existing publisher/claimant keeps its responsibility; gate holder owns exclusion only, not all queued work | No inference of empty, no decrement, no phase arrival, no replay or reclaim authority |

The identity includes target queue separately from caller. The QNT empty
witness is tied to the caller's own queue before idle; acquisitions can claim
another queue's item. Busy against that foreign queue does not qualify the
caller's queue. The model keeps one current observation slot per worker;
replacing it with Unobserved removes its empty-witness authority. This bounded
model bookkeeping is not an instruction to store matching fields in runtime C.

The full protocol is:

1. Keep the active owner's root/work/arena/control lifetime before attempting
   the gate. Gate acquisition failure does not leave that lifetime.
2. Interpret only a settled result. Acquired installs private custody before
   queue reachability disappears; ConfirmedEmpty records a scoped observation;
   Unobserved leaves all work custody with the prior holders.
3. To become idle, conjoin a fresh own-queue empty observation with complete
   private/frontier/still/initialization/Tail drain and no unresolved claim.
   Publication increments the logical queue revision and invalidates an older
   empty observation. The model's revisions are proof witnesses, not another
   proposed runtime counter.
4. Under the termination protocol, decrement exactly once. Other queues may
   remain nonempty only while their work retains a counted owner. Nonterminal
   wake re-counts before new work and requires a new observation before idle.
5. Only whole phase closure and admitted arrivals permit nextPhase. Earlier
   empty witnesses are invalid in the next phase; strong closure still does
   not finish weak, restore, cleanup or native/control resource users.
6. If a claim committed but result delivery was lost, do not manufacture any of
   the three outcomes. The operation is unsettled. QNT retains the exact item,
   claimant and count; finishScan, new queue result and idle are blocked until
   identity settlement delivers the already acquired item without a second
   scan claim. Physical owner death remains an existing last-user obligation,
   not a new implicit settlement or a timeout-based release.

The unsettled example models the committed-claim/lost-delivery branch, not
every crash point. Unknown-before-commit, interrupted linkage and real native
stop still need source adapters. A source with no settlement path must retain
the affected resources; this is safe blocking, not a liveness result. An
independent healthy VM is admitted only by the separate non-sharing/last-user
proof, not by a queue outcome.

Lean =QueuePost= specifies the data relation at one operation's linearization:
Acquired moves one exact head item to private custody; ConfirmedEmpty requires
an empty source queue and performs no transfer; Unobserved performs no transfer.
Its four laws establish no-observation custody preservation, the empty premise,
acquired work-count conservation, and a busy/nonempty counterexample. A no-effect
law does not assert two arbitrary concurrent queue snapshots are equal; other
operations have their own linearization. QNT alone owns freshness and ordering.

The retained deterministic histories include busy with queued work, empty while
private debt remains, empty invalidated by publication, acquired-but-unfinished
work, unsettled claim and exact settlement, busy replacing an empty witness,
foreign empty rejected for own idle, and old-phase rejection. Existing bounded
exploration is retained. Neither the
sum type nor these checks proves the actual C's current zero return implements
three distinct outcomes; that source obstruction remains explicitly OPEN.

The count/wait path also ignores platform operation return values at these
callsites. Successful mutex/wait behavior is therefore a source-admission
premise; erroneous/unknown waits cannot be treated as normal reacquisition or
proof that a worker stopped. This remains OPEN, without raising timeouts.

**** Normal call and local fixed-point algorithm

The output location must be live caller storage and must not alias a queue,
worker-control or payload field. Clear it before attempting the gate. On busy,
return Unobserved without reading queue links or altering work custody. Under
successful exclusion, empty head/tail returns ConfirmedEmpty. For an acquired
node, validate chunk transition1->2, install the existing private claim fields,
update head and output, then release the gate before returning. The exact
multi-store order and interruption boundaries remain a C refinement duty.

No caller scans, copies, allocates, executes a callback or reenters Scheme while
holding this queue gate. Such work can recursively publish chunks. In particular,
moving =scan_complete_heap_chunk= inside the critical section would introduce a
self-publication deadlock rather than establish the contract.

The owner retries a known Unobserved result while retaining its cursor, roots,
arena and counted authority. Use the existing CAS/CPU_RELAX synchronization
mechanism; introduce no new spin threshold, yield, timeout or enlarged watchdog.
A normal thief may move to the next victim on either non-acquired status. The
two caller policies differ in authority, not in return-value decoding.

The owner loop must not immediately return on the incomplete-prefix
cursor-equals-arena edge. It needs an authoritative own-FIFO observation at the
movable fixed point; if Acquired, scan the claim outside the gate and revisit
the frontier, since scanning can create more chunks. =mark_reachable_from_marked=
then repeats its existing still/movable loop if moving work discovered still
work. Only the combined local fixed point supplies =localDrainReady=.
Successful stealing also restarts that local path. Nonterminal wake refreshes it
before another idle decrement. The intended loop uses existing control labels;
this changes collector admission, not Scheme scheduling policy.

The own-empty observation can remain valid across the final steal attempts only
under the admitted single-publisher rule for this worker queue: no external
helper may append to it while the owner is idle. A successful own publication,
new private claim, reentry or phase change invalidates the relevant local proof.
The model's revision stamps express this premise; they do not mandate matching
runtime counters. An implementation may establish it by control-flow confinement
and synchronization if that covers every producer.

**** Unknown fragments, lifecycle and retirement

Installing =active_scan_chunk_= earlier closes the normal return gap using an
existing field. It does not make claim transition, head update and output write
one hardware transaction. An unknown stop inside the fragment retains the gate,
node, queue/arena and enclosing round; it grants neither a fresh claim nor a
forced gate unlock. Before the private record is complete, the critical fragment
itself retains responsibility. After commit with lost delivery, exact settlement
must recover the same claim without incrementing claim/execution counts again.
No generic crash-repair implementation is supplied by this design.

Every normal gate holder/waiter/publisher remains inside an admitted counted
worker's phase lifetime. If that coverage is complete, no independent per-queue
publication counter is needed. This avoids proposing two extra atomic counter
updates per operation; it does not claim to remove such updates from current C,
which has no such counter here. External/native observers, asynchronous helpers
and returning postludes must instead be covered by their existing lifecycle
authority; they cannot be silently included in W.

Strong zero is followed by the admitted all-R cut, weak production/drain, then
the weak barrier and restoration. Raw post-weak head/tail comparisons are valid
only after these users are quiescent. =setup_stack_heap_vmstate= must not erase
old pointers during an unknown claim; =cleanup_rc= must not free the root round
while a holder/waiter or postlude can still touch an embedded gate. RC root
closure, data_closed and native join remain different facts. Known join does not
close helpers automatically; unknown join retains native/control storage.

An unknown same-heap writer can block that collection. An independent healthy
VM may progress only if the retained gates, storage and registry permissions
really do not obstruct it. Never hold a global registry permission while waiting
for an uncertain per-VM queue user. No latency guarantee follows from retrying
the existing gate; progress requires admitted platform operation and scheduling
premises.

The selected representation is one bounded take slot attached to each existing
VM-owned worker, not a new identity table. Its logical key contains VM incarnation,
collection epoch, phase, worker slot and operation generation. The caller must
know the expected key before the fallible call. A key must not be invented by
reading a potentially reused pointer after the return was lost.

The slot needs immutable queue/item/expected-head information and an atomically
published decision/progress view. Initialize immutable fields before release
publication; queries acquire that publication and pin the live slot before
reading. The existing active pointer/origin can serve normal execution, but do
not contain all these identity, commit, delivery and query-grace facts. This
extends the earlier normal-return design rather than claiming those fields
already provide recovery. Actual field types, alignment and backing are source
refinement duties; no runtime record is implemented here.

The QNT now retains separate effects for claim versus its progress store, head
removal versus its progress store, and gate clear versus closure publication.
A logical item in state3 is claimed-but-linked: physical reachability does not
create a second owner. Pending slot/gate/work stay counted through these cuts.
Completed atomic acquire remains the existing abstract fast path; the microsteps
expose interrupted prefixes, not a second queue algorithm. Atomic record
publication and each source-effect step are abstractions, not machine-store or
weak-memory proofs.

**** Query, ACK and reuse protocol

1. Enter the existing VM/control lifetime before deriving any worker pointer.
   Pin the exact slot generation; merely matching a numeric key does not make
   freed storage readable.
2. Read a coherent acquired decision plus immutable identity/data. Classify
   partial, committed/release-unconfirmed, committed/return-pending, delivered,
   known-unclaimed-abort or not-current observation. These are operation query
   states, not extra normal queue-result variants.
3. Query is read-only with respect to queue head, chunk state, claim counters
   and execution authority. Repeat it without issuing another take. A partial
   result retains custody; a stale/vacant result does not prove non-admission.
4. Settle only the exact committed claim after actual gate-use closure. Return
   its recorded item; ACK delivery once without incrementing claim counts.
   Duplicate query may observe delivered, but must not grant a second executor.
5. Reuse the fixed slot only after prior claim/operation completion and query
   grace. The finite model represents one reader and blocks reuse while pinned;
   arbitrary readers and native counter exhaustion are not thereby proved.
   Native generations must not wrap into a live key: reject admission before
   exhaustion or prove a complete incarnation/grace reset, without erasing debt.

Lean =ClaimKey/ClaimReceipt= and the two lookup laws supply only the immutable
data interpretation: a mismatching key supplies no item; a successful lookup
supplies exactly the recorded item. QNT owns pin/reuse and once-only settlement.
Constructing a valid receipt from current C still requires coherent publication,
correct committed classification and live storage; lookup is not a memory-safety
or physical-stop certificate.

**** Owner loss and helpers

An unknown owner remains a possible writer. It may not be replaced concurrently,
even by a helper intending the same idempotent store: concurrent unsynchronized
C writes are not justified by equal values. VM custody retains the slot, queue,
node, arena, roots and synchronization backing. It may read coherent published
state, but may neither force a gate open nor infer stop from timeout or gate zero.

A helper may finish an existing fragment only after original *and previous
helper* write permissions are closed, last users drained and a unique replacement
generation admitted. Under that exclusion, reconcile actual chunk/head state
against immutable intent, advance the same record, and never invoke ordinary
take as a recovery probe. If readback is ambiguous, retain; if claim has not
occurred, known abort preserves publisher custody; after claim, finish/transfer
the existing responsibility rather than restoring it to an unclaimed queue.
The helper's own interruption repeats the same retained obligation. No generic
helper recovery or stopped-thread oracle is implemented by this study.

The finite model's unknown-owner observation changes no authority. Cooperative
cancellation and completion steps are legal original-owner actions, or require
separately established source-closed helper premises. Existing retirement models
retain ownership of those stop/last-user premises; model actions do not certify
actual owner death. An uncertain same-heap writer can block its collection;
healthy-VM progress still requires independent retained resources.

There is a real exceptional edge beyond imagined asynchronous death:
=require_chunk_transition= calls =___fatal_error= before the queue gate is
cleared. =os_base.c= calls =setup_params.fatal_error= before =___exit_process=.
The default path exits the process; a configured callback can attempt reentry
or escape. It is not a normal resumable busy/empty outcome. The adapter must
keep diagnostic/user effects outside an authorized normal claim span, or retain
and close the affected VM on exceptional escape. No callback return/escape can
stand in for rollback, gate-use closure or native last-user drain. Preserving
the hook's effect boundary is part of this adapter, not permission to redesign
unrelated CFFI or Scheme exception semantics here.

**** Header and intent publication

The immutable header is prepared under exclusive construction while both
admissions are closed and no old borrower exists. Release-opening query admission
publishes that header. The caller can then observe Reserved without reading
uninitialized node fields. Under the one admitted writer, fill intent before
release-publishing IntentReady. A query acquires one decision snapshot and reads
only the prefix certified by that snapshot. Reserved does not authorize an
intent read; a later acquired readiness can authorize it once.

Once a prefix is published, keep its plain fields immutable until full
retirement. Progress/decision changes use atomic words. Do not use an optimistic
seqlock retry to justify concurrent plain reads and writes: retry does not remove
the C23 data race. The QNT prepare step abstracts complete publication, so torn
fields and the actual release/acquire edges remain source/native obligations.

The source has a related, distinct pattern: =lifecycle.h= uses closed bit/+2
borrows in VM entries; =vm-registry.inc= performs CAS admission/release. That is
engineering evidence for reuse of the mechanism, not proof that VM entry pins
already protect a take slot. The existing ordered-word service has native and
legacy branches; each selected branch still needs actual compiler qualification.

**** Pin before identity, then seal and drain

1. Acquire existing VM/control lifetime before the first raw slot address use.
2. Load query_gate atomically. If closed, return unavailable/retained without
   reading key or payload. If open and adding2 is representable, CAS the same
   word to add a reader pin with acquire semantics; retry only the CAS race.
3. Now check the immutable operation key. On mismatch, drop this pin and report
   a not-current observation, not a proof of no prior admission. On match,
   acquire the decision and copy only its certified immutable prefix.
4. Release the pin with a release RMW. This is the query's last slot access;
   later native postlude remains covered by its enclosing VM/control lifetime.
5. Reuse closes the same gate by CAS setting its low bit while preserving the
   count. A prior pin wins and is included, or close wins and admission fails.
   Mutate no plain payload until acquired closed-and-zero is established.

A delayed caller may pin a newer generation after the gate word returns to its
open encoding. Post-pin identity validation makes that safe: it protects the
new storage while rejecting the old semantic key. It does not borrow an old
generation's counter. Pin-before-key is essential; check-key-then-pin is unsafe.
Queries never wait for commit or GC completion while holding a pin. An unknown
query release cannot be guessed or forcibly subtracted.

Use full ordered RMWs for seal/admission/retirement where the current service
does not provide the required weaker operation. Do not silently assign release
ordering to an acquire-only CAS. Reject admission before reader-count overflow;
the current source's checked word range can be reused after exact arithmetic
qualification. Lean's Nat encoding law supplies no finite-word overflow proof.

**** Owner/helper write permission and generation

The exclusive writer gate follows the same close-without-erasing-borrow rule.
Entry pins the gate, then acquires and validates the operation key and writer
generation *before any data write*. Checking generation before pin allows an
old owner to enter after close/drain/reopen and is rejected by this design.

Seal excludes new writers but lets the current owner/helper finish and release.
Closed plus zero establishes enrolled write-access closure only when all writers
use the protocol and no slot store occurs after release. It does not prove
physical native thread death or release enclosing VM/TLS/code resources.
Never clear an unknown borrow on timeout, fatal-hook escape or failed join.

To transfer to a helper: seal, establish original and earlier helper closure,
then advance writer_generation while still closed and empty, and reopen for the
new permitted writer. The operation key and immutable intent do not change.
An old permit may transiently pin the reopened gate, but post-pin generation
validation must reject it without a payload write. The helper's interruption
retains its own borrow and blocks another rotation until equally valid closure.
Known cooperative last release and an unknown stop are different evidence.

**** Retirement is a conjunction

Retirement first closes new operation admission and writer/query admissions,
preserving old borrowers. It requires a terminal delivered-and-scanned claim or
a known unclaimed abort; no unsettled take; actual gate-use closure; zero writer
and query borrowers; and closed helper/original data access. Zero readers alone
does not finish work. An old progress word alone does not close a writer.

Under that exclusive cut, advance the nonwrapping operation generation and
initialize the next header/intent before reopening their respective publication
prefixes. Exhaustion refuses new admission rather than wrapping into a live
identity. The finite QNT resets phase only after query/writer closure; real
collection/incarnation rollover requires the same source lifetime proof.

Native postludes may survive slot-write closure but may not access reused slot
data. Their VM/control lease must still prevent enclosing round free. Slot
retirement cannot free a WorkerArena or VM that owns other work. A writer or pin
whose release is unknown retains backing and may block this VM's reuse; another
VM's progress remains conditional on genuinely independent resources and no
global-lock wait cycle.

not a Clang, Darwin, Win32 or C23 whole-program qualification. A future uniform
acq_rel implementation belongs in the existing service, rather than a parallel
take-specific service; weaker fast paths require a separate justified change.

the earlier empty implementation, excluded by its selected sync backend. Establish matching

historical empty function as a global fence or the new fence as a stop certificate. The sequential branch admits only its

Counts encode quantity, not borrower identities. Query cleanup needs a scoped,
once-only pin token and its enclosing lifetime; it cannot subtract a pin merely
because a key is stale or native join succeeded. This layout alone does not
recover a dead reader whose release ownership is unknown. A further registered
borrower proof, or continued retention, is required; no automatic counter repair
is claimed.

The QNT now has a small ceiling3 for generation exhaustion and one-reader
admission histories. These are finite qualification horizons, not production
constants or newly configurable limits. Lean proves that a checked gate increment
fits its mathematical bound and a strict generation successor is distinct and
within bound. Mapping these premises to actual C types, signed arithmetic and
finite widths is still a source/native obligation. Arbitrary repeated helper
failure cannot yield a bounded recovery guarantee with finite fresh identities.

**** Reject late owner/helper access after pin

The QNT separates writer storage pin from validation. An unvalidated pin blocks
drain but has no payload authority. Validate operation key and writer generation
under that pin; if either mismatches, release without a data write. The model
retains the completed atomic-entry abstraction while exposing this intermediate
state for delayed old owners/helpers. A generation check performed before pin
does not cover close/reopen races and is not the selected C mapping.

The coordinator changes writer generation only after closing new entries and
observing zero existing writer borrows. Thus it cannot rotate under a delayed
pin. The original owner and an interrupted helper retain identical obligations:
no timeout-based borrow deletion, no metadata write after release, and no raw
slot dereference without existing VM/control admission. Native postludes keep
their outer lifetime even after slot-write permission ends.

An old permit can pin the newer storage if admission has reopened, but validation
must reject its old full key or helper generation before touching payload. The
scoped pin protects the current storage during rejection. Source must prove all
writers follow that path; neither a numeric generation nor a zero counter
protects an unmediated stale pointer. Coherent query identity remains read-only;
exact settlement grants no second claim execution.

** Scheduler, exit and worker roles in the same round

The Scheme scheduler owns runnable/waiting requests and their roots. The GC work
scheduler owns private/queued/claimed scanning; these are not the same FIFO or
completion event. Parked requests and callback arguments remain root sources.
GC completion cannot deliver a request result or infer a native callback ended.

Membership remains fixed for the admitted collection. Removing a participant
or changing a work owner requires the corresponding root/work handoff, not just
decrementing processor_count or the active scan count. Current C still uses
=work->carrier= for some services; separating the worker record does not prove
that every service or exit route is carrier-independent.

If a worker is known stopped, a successor needs its exact private cursor,
dequeued chunk, object/initialization/Tail debt and arena lifetime before taking
authority. If stop or handoff result is unknown, retain those obligations and
exclude repeated execution. Timeout alone cannot authorize concurrent recovery.
An unrelated healthy VM may progress only if the retained region/control and
synchronization resources really have separate lifetime; this is an acceptance
obligation, not an inference from a per-VM field name.

The movable object-state encoding in =change_object_scan_state= uses two bits
per addressed destination word for four states. This is a structural accounting
fact, not total runtime overhead or peak RSS: chunk metadata, alignment, atomic
contention, roots and retained regions must also be counted. Current code has
one active-scan count per strong/weak phase, each initialized to W. Neither fact
justifies a throughput or pause percentage.
