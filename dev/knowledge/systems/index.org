** Capability sources
- [[file:build-modernization.org][Chez/OCaml/Dune build modernization mechanisms]] and their Gerbil-specific refactoring obligations.
- [[https://ziglang.org/learn/overview/][Zig overview]]: C import, compilation and ABI interoperability are distinct facilities. They do not supply Gambit GC or continuation correctness.
- [[https://mlir.llvm.org/docs/CAPI/][MLIR C API]] provides a language-neutral integration boundary, with API limitations and stability costs. It can serve modern C as well as a Zig candidate.

** Reflection for Gambit
Gambit owns semantic completion. Native implementations consume explicit frame, root, effect, module and product contracts. LLVM/MLIR can be a decoupled optimization service; importing C headers is not a high-level Scheme semantic export.
