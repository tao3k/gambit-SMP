# Source-Bound GC Design Transfer

This ordinary declarative Evidence DSL produces research obligations for a
specific Gambit candidate. Python only supplies JSON rows, actual file digests
and C ABI lifecycle. Downstream has no Scheme import or compile workflow.

`source` declares path/SHA; the trusted host supplies `verified_source` only
after checking those bytes. The DSL does not authenticate a host assertion.
`design` states a reviewed implementation contract; `applicability` distinguishes
portable protocol properties from implementation-specific mechanisms.
`candidate` binds the exact source lock, not a qualified runtime or binary.
`observation` binds historical receipts and exact JSON pointers. Their finite
counterexamples inform investigation; they do not establish a native defect.

The current facts bind the 23-file fdset-owned-rollback source lock. Rules derive
three portable obligations: publication readiness, work conservation and strong
field coverage. Chez generation/card retention remains collector-specific and
does not become a missing Gambit feature. See
`docs/gc-design-transfer-boundary.md` for source and motivation distinctions.

`required_test` identifies a real Scheme workload for aliases, cyclic pairs,
vectors, bignums, closures, records and saved frames through two collections.
Its execution is pending. It does not measure physical bitmap spans, multi-VM
isolation or C-side still-object ownership. No test declaration closes a gate.

Every portable obligation remains `unproven` for native correctness and source
refinement. `performance_required` remains independent. There is deliberately
no runtime-admission rule, authorization rule or model-PASS-to-native-PASS edge.
Agentic AI may choose investigations from these relations; no fixed action
sequence is prescribed.
