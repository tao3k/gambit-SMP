# Optional tool reasoning

This catalog is open-world, non-exhaustive and unordered. Its ten currently
matching tool profiles are examples derived for one archived GCC code-generation
investigation, not ten permitted tools, ten required tools or the research
universe. The declared target format is Mach-O; the retained artifact itself is
assembly text. No binary, debug-info, tool installation or permission premise is
therefore invented from that target declaration.

`choice_scope` makes these semantics machine-readable. `exploration_window`
survives an empty tool catalog, an unclassified compiler and novel caller-owned
questions. No missing known option forbids another authorized investigation;
the caller need not register an idea before considering it. New `tool`,
`offers`, `support` and `requirement` facts extend known applicability without
Python branches or changing the inference rules. Model reasoning is not
restricted to these relation labels. External execution still requires its
independent capability, permission and evidence checks.

`options` gives known applicability and limits; `why` gives source-bound
investigation rationale; `missing` reports declared prerequisites; `ready`
means only no declared prerequisite is missing. It is not execution permission,
installation, completeness, source correctness, native repair or a ranking.
`reuse` retains the exact existing observation rather than silently rerunning
tools. Conflict and provenance queries retain uncertainty without fallback.

Use Python/C ABI through the existing consumer:

```sh
gambit-smp actions discover --request evidence/scenarios/tool-reasoning/action-context.json
```

The Working action-context and view registry include this same view. Tool
execution is not added. The actual Library, Action and complete-graph outcomes
must be reported separately; local component success does not close the full
current graph or the Gambit repair.
