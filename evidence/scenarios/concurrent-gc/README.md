# Concurrent Relocation Research

This is a caller-owned declarative Evidence DSL scenario. Python/C ABI loads
`design.ss` through the existing Library API. The downstream source contains
no Scheme import/module/export or compile workflow. Action discovery consumes
`action-context.json`; its read-only actions use the existing discover/select/
observe kernel, revision checks and independent host authorization.

The view binds the current 23-file fdset-abort-owned-rollback overlay, its
source lock, exact bootstrap identity, and three flag values at exact pointers
in the successful configure observation. Every overlay file is separately
hashed. The bootstrap identity's reported 956-source inventory is recorded;
this view does not requalify that entire runtime tree or custody chain.

Eight open obligations cover epochs/ABA, publication visibility, continuation
roots, Still edges, foreign leases, VM retirement, producer custody and matched
performance. Model observations never discharge these source/native duties.
Withdrawal of a flag or model source changes the answers; restoring the same
bytes restores the answers in the same Library session. Recorded model PASS
does not create an executable native retry or authorize acceptance.

`RelocationEpochRoots` permits two moves and wrapping colors. Its checked path
uses a logical generation stamp as a ghost requirement: an implementation
must provide an equivalent handshake/epoch scheme, not assume unlimited color
bits. Continuation and Still roots each contain one modeled reference. The
foreign lease abstracts joint source-reclamation/metadata retirement; raw C
payload coherence, pin acquisition races and arbitrary FFI stores are absent.
No actual physical page layout or concurrent Gambit protocol is claimed.

`ForwardingVisibility` is a release/acquire message-publication litmus with
explicit delayed visibility. It is not the complete C/ARM memory model, a
compiler check or a proof that any current Gambit access is synchronized.

Performance remains unmeasured: the experimental collector is not implemented
in Gambit. Do not substitute checker durations or Library query latency for GC
performance. A real comparison must freeze baseline/candidate source, GNU GCC,
all three flags, generated binaries, fixture bytes, heap/live-set, CPU/jobs and
execution budgets, then retain all failures while measuring pause p99/max,
throughput, barrier CPU, peak RSS and FFI latency. No synthetic metric closes
the six `missing_metric` rows.
