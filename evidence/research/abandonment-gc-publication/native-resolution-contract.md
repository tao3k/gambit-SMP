# Ticket wait evidence obligations

These are caller-configured evidence dependencies, not an execution plan,
exclusive hypothesis set or permission policy. They are interpreted by the
existing ASCENT checkpoint fragment and exposed through the existing Clue
exchange. Presentation completion does not discharge any of them.

| Requirement | Evidence scope |
| --- | --- |
| `owner-barrier-record-models` | Reviewed finite model results, bound to model, contract and manifest bytes |
| `ownership-source-coverage` | Actual acquisition paths for the sampled processor lock, including Scheme and other C paths; executing caller identity must not be confused with remote target `___ps` |
| `barrier-wait-correspondence` | Current wait phase and accountable proposal/election identity; a past completed record is not current participation, and a winner may not exist yet |
| `lock-collective-progress` | Source-corresponding wait/holder protocol, rooting, membership and publication conditions; an always-enabled abstract unlock is insufficient |
| `source-repair` | Reviewed source difference corresponding to the qualified protocol and actual build inputs |
| `compiled-original-stress` | Current candidate's original four compiled stress files, with actual exits, source/artifact bindings and quiescent teardown |
| `interpreted-original-stress` | Current candidate's original four interpreted stress files, with actual exits, source/artifact bindings and quiescent teardown |
| `native-lock-wait-resolution` | Source-bound acceptance of both native stress scopes; not all twelve SMP milestones |

The record-model result supports only its first requirement. No receipt for
the other requirements is asserted here. Unknown or missing evidence remains
visible rather than being inferred from the absence of failures. A legitimate
empty review command inventory does not substitute for native commands.

The original sources are `tfib_stress.scm`, `thread_interrupt_stress.scm`,
`thread_interrupt2_stress.scm` and `thread_terminate_stress.scm`. Their workload
and watchdog semantics remain unchanged: real completed-file inactivity,
not total wall time or diagnostic output. Parallel capacity is host-selected.

Diagnostic attribution and protocol repair are distinct claims. The record
models and a witness to the original sample's current barrier are not universal
prerequisites for a conditional, source-corresponding wait-progress repair.
That repair requires actual acquisition-path/caller coverage and its own
qualified progress protocol, not a diagnostic record model in its place.
An unknown original holder or barrier remains an open diagnostic obligation;
a successful repair or stress run does not retroactively identify it. No
statement attributing the retained timeout to GC follows from this dependency
configuration.

Existing execution checkpoints, source/producer identities and bootstrap
receipts remain the execution framework's inputs. This declaration neither
requests another bootstrap nor grants reuse of a mismatched binary. Changes
invalidate only the applicable evidence dependencies; cleaned material is
different from lost historical evidence. Historical progress remains 6/12.
