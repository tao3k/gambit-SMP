[[file:models/sysml/modular-smp-validation.sysml][Native SysML]] owns the case namespaces, shared contracts and coverage.
[[file:../../../vendor/gambit/.github/workflows/smp.yml][The workflow belongs to Gambit]], on its =modern-c= branch, and operates on a
standalone Gambit checkout. It does not install the SMP Python framework, ASCENT
SDK or Gerbil SDK. The earlier parent-repository workflow was withdrawn; the
existing SMP shared action was restored. Historical attempts remain evidence.

The native entry is [[file:../../../vendor/gambit/tests/smp/suite.scm][the Scheme suite]], with explicit
=gambit#tests#smp#= bindings, =execute-case= and a generated
[[file:../../../vendor/gambit/tests/smp/catalog.scm][case catalog]]. Fully qualified case names are the CI, receipt and model keys.
GC, control, scheduler, runtime and memory-module scenarios have separate names
and responsibilities. New Gambit tests contain no Python or Shell framework.

Before an interpreter exists, GitHub invokes the existing configure/Make seed
targets. The resulting Gambit interpreter owns two-pass bootstrap validation
and subsequent case execution. =open-process=, =process-pid=, byte-port reads,
=process-status= and Scheme threads own waiting and result delivery. GNU
=timeout= supplies the external OS process-group deadline; =/bin/kill= checks
and terminates that group. This is an explicit platform boundary, not a claim
that Gambit's current public process API already provides group cancellation.
No pseudo-terminal is introduced to obtain a session. Child stdout and stderr
are captured as one byte stream and are labelled =output=, never as two
independently observed streams. Scheme semantic cases require the exact stream.

Models, ASCENT, Org, D2 and retained receipts stay in SMP/dev or SMP/evidence.
Existing QNT schedule/permit histories and Lean issued-view algebra retain
exclusive ownership. No new theorem or duplicated model is introduced for CI.

* Actual source and complete bootstrap
:PROPERTIES:
:CUSTOM_ID: modular-smp-source-bootstrap
:END:
The source lock contains 45 explicit paths, including 25 new memory fragments,
the Make inventory and the real root-task C test. A null base hash means absent
in the pinned Git archive; it does not mean an empty file. New-file admission
checks paths, parents, regular files, hashes and strict patch applicability.
The overlay serializes the current candidate; it does not transplant the
historical SMP repair patch series.

The existing Darwin/GCC Bazel profile expands to the same eleven Gambit flags
in the independent workflow: SMP, multiple VMs, multiple threaded VMs,
single-host=0, module=-O1, runtime optimized, and the existing jump/dynamic-clib/
C-tail-call options. The profile reference hash is
=3aa072e9ced23ba963d623476f9e2380172d71b7c747188386dcd07c252d695b=.
The observed GCC executable was GNU GCC 16.2.0; a GitHub definition is not
evidence that the hosted package or cold seed has qualified this configuration.

The retained =modular-smp-current= campaign passed under the original 600-second
budget. Each of phase1 through phase4 occurred twice; the complete bootstrap
command took 223.907 seconds. The resumed campaign took 256.463 seconds and
reused its exact candidate, configure and hosted seed stages. Those three
historical command streams remain =executionLaunched=false= with authenticated
origins. This is not a cold-build timing or speedup claim.

The same campaign passed real =map= capture and repeated full-continuation
restoration, eighty live frame roots, eleven completed forced GCs, and the
host-managed case with eleven processors on a twelve-CPU host. These bounded
observations do not promote the global =nativeGcPassed= or =runtimeAdmitted=
flags, and do not solve all original 0–12 acceptance families.

Even synthetic success for every module and every gate must not create
=msCommitReady= without the canonical architecture relation. A C kernel result
cannot supply a real Scheme observation; an unknown result conflicts with pass;
one bootstrap pass cannot supply two. The [[file:../../modeling/ascent/modular-smp-validation.rules.scm][actual ASCENT policy]] checks these
distinctions, including source/profile/case-contract identity.

* Failure evidence and architectural implications
- Strict patch admission rejected 24 preserved blank-at-EOF fragment payloads.
  A generated end marker now follows each exact original payload. Reconstruction
  strips the =#line= prefix and marker, retaining the original 240456 bytes.
  Whitespace admission was not weakened; eight preprocessor pairs, the release
  object and 26 Make dependency cases were rechecked.
- A causal review referred to a stale model digest. The current model matched
  an independently retained source archive; rebinding records that identity
  without upgrading its still-open obligations.
- An authenticated reused configure stage exposed a missing origin-command
  consumer. The corrected consumer verifies journal-step and child-receipt
  ancestry; it never invents a second configure launch.
- Early standalone compile attempts inherited Nix linker search paths. The
  independent entry chooses GNU GCC and Darwin system tools and removes caller
  SDK/header/library overrides. Those link failures remain separate from
  runtime failures.
- The new mailbox case observed an actual value/order mismatch at message 32
  in an earlier invocation. It remains a failure witness, regardless of a later
  result. No heap increase, shortened workload or waiting extension is allowed
  to remove it from the acceptance record.

The root-task C kernel establishes local publish/claim and private grant
operations under external physical-stop and grace assumptions. Real GC/control
cases exercise consumers beyond that kernel. They do not yet retire collective
physical writer stop, =W=R=, carrier-backed refill, weak/cleanup phases or unknown
native writer custody. These boundaries are precisely why a green bootstrap
cannot stand in for modern multi-core architectural closure.
