## Final function-level contract: run lifetime, legal resize and every cleanup use

This is the authoritative integration order for the entire proposed delivery repair. It supersedes ambiguous “run counts must be zero before resize” or “a pass pin protects the caller after return” readings in earlier versions. It is one implementation/acceptance unit for Grok, not a collection of independently closed milestones. All current-code coordinates remain those of the frozen353 snapshots; the live temporary checkout is not used as an equality oracle.

### The two decisive corrections

**Ordinary native runs protect destruction, not resize.** A long-running worker's `___run` must remain counted while it can touch generated Scheme frames, but that count must not prevent an already-admitted collective from retiring the worker. SFUN counts still protect actual foreign frames. Delivery counts still protect unfinished R/S/pass duties. The new ordinary-run lifetime is checked only for resource destruction and native-owner departure. No counter is reset because processor_count changed.

**A successful OS join is a persistent fact.** Frozen `setup.c:2277–2345 recover_retired_processors` currently calls `___thread_join` whenever `join_pending` is set. If join returns0 but borrower/transfer checks then fail, the flag remains set and a later call can join again. Persist OS_JOINED before any subsequent check. A retained post-join transfer retries transfer/reclamation only. It must never recreate a join error to satisfy qualification.

### One ownership record, at the actual native boundary

Use the run-entry context already specified in `run-ack-source-protocol.md`, with full VM incarnation/native-owner/activation identity. Keep mutable state in stable native-owned storage reached through an immutable pre-setjmp handle. A record holds predecessor, marker ownership, owned saved-root tokens, phase and the exact admission units it owns. Its marker's real still-object reference is a traced root; a raw journal pointer is not a new GC root domain.

Use one VM packed **destruction admission** word (`run_cleanup_gate`, closed bit plus count), following existing CAS admission conventions. It accounts for ordinary run records **and their admitted outer native owners/tails**. A checked child run is nested under an existing native owner; do not release the parent's unit when the child returns. The per-native-P view identifies P0/worker ownership and validates the journal; it is not inferred from the currently migrated Scheme thread. Overflow or incarnation exhaustion refuses new admission. Records and VM addresses are not recycled while a record/tail/ticket survives.

Three states must have different consumers:

| Record state | Who may finish it | Last legal accesses and release |
|---|---|---|
| RUNNING → RETURNING | The same native `___run` boundary, after END_TRY | Restore catcher, finalize only the crossed inner context, invalidate its installed marker once, restore current traced saved roots, copy status, then release its child count. Its parent native owner remains admitted. |
| RETIRED_TAIL / native sync tail | The original worker until real OS exit; after real join0, the recorded P0 cleanup owner | Direct OS exit must leave its outstanding records/tail counted. P0 may finalize abandoned records only after join0 and the required root/memory ownership handoff under GC exclusion. No remote Scheme unwind or restoration of a dead C catcher. Release those units before donor memory destruction, after their actual final accesses. |
| HOST_OWNER → DESTROY_OWNED | The unique checked cleanup caller under existing host/registry serialization | Transfer the caller's own final unit into its destruction ticket without an unowned gap. Other users must be gone. The ticket may perform the last VM accesses and free resources; its final epilogue then accesses host-owned ticket/status storage only. |

The caller holding a valid VM pointer must have an admitted native owner context. Bootstrap `___setup`, worker creation/entry, and checked external VM entry must establish it; the public `___run` wrapper requires that context before dereferencing a VM. A copied raw pointer or TLS pstate alone does not establish ownership. The known callers at `setup.c:2051 ___run_and_throw_error_on_processor_0` and `8990 ___setup`, plus the exported GSTATE run entry, must all be migrated. Do not leave an unchecked compatibility route. External host calls outside this owner contract are refused, not made safe by reading an atomic from potentially freed memory.

The initial VM identity is passed explicitly during setup; do not derive it from a not-yet-initialized ps->vmstate. Private setup is not public OPEN admission. Failed setup owns only its constructed prefix and cannot issue a published-VM destruction ticket.

### Checked owner C ABI v1: fixed implementation contract

The following is the selected ABI, not a set of interchangeable options. These declarations belong to the final-B header/implementation migration; they are **documentation only here**. All current raw exported setup/run/cleanup callers and GSTATE dispatch slots must migrate to the checked surface or wrappers that require an already-issued handle. No wrapper may infer a valid owner merely from TLS/ps or silently retain an undisclosed handle.

#### Public value types and result rules

```c
#define ___NATIVE_OWNER_ABI_VERSION 1
typedef struct {
  ___U64 instance_epoch;
  ___U64 vm_epoch;
  ___U64 record_slot;
  ___U64 record_epoch;
} ___native_handle;

/* Same key representation; private record kind/phase enforces each role. */
typedef ___native_handle ___native_owner;
typedef ___native_handle ___native_vm_ref;
typedef ___native_handle ___native_run;
typedef ___native_handle ___vm_destroy_ticket;

typedef struct {
  ___U32 abi_version;
  ___U32 struct_bytes;
  ___U32 disposition;      /* NONE, LIVE_OWNER, LIVE_RUN, LIVE_TICKET,
                            LIVE_WORKER, DONE */
  ___U32 reason;           /* OK, BUSY, CLOSED, STALE, WRONG_OWNER,
                            BAD_PHASE, LIMIT, OS_ERROR, INTEGRITY,
                            PREFIX_RETAINED, RUN_ERROR */
  ___U32 phase;            /* copied observation, never caller authority */
  ___U32 reserved;         /* zero in v1 */
  ___native_handle live;   /* actual surviving capability, or all-zero */
  ___U64 progress;         /* record progress serial, saturating/refuse wrap */
  ___SCMOBJ original_status; /* immediate run/OS status, never Scheme payload */
  ___SCMOBJ cleanup_status;  /* immediate cleanup status; keep both errors */
} ___native_op_result;
```

Require 32-byte handle with four 64-bit scalar components; assert layout/alignment for the selected compiler/target. An all-zero key is invalid. No returned key contains a VM, record or stack address. All codes returned by the functions below are immediate Gambit fixnum error codes; Scheme payload/result values stay in their existing traced locations. `___NO_ERR` means that named operation succeeded, not that the whole VM is destroyed. Refusal uses `___INVALID_OP_ERR`; identity/phase reason distinguishes it. Counter/key exhaustion uses `___IMPL_LIMIT_ERR`; allocation failure uses the existing appropriate allocation error; OS failure preserves its real encoded code. Integrity/destructor uncertainty returns an error with a surviving owned capability, never a manufactured success.

For the selected 64-bit ABI, require result size80/alignment8 and SCMOBJ size8, with compile-time assertions in final B. Caller initializes abi_version=1, struct_bytes=80 and reserved=0 before every call. Callee validates this prefix **before mutating admission or writing result fields**; incompatible ABI returns INVALID_OP_ERR with the result untouched. On a valid prefix every result field is initialized on every path. Other word-width profiles need their own admitted ABI binding; do not silently assume this result layout.

Fixed v1 scalar assignments: disposition NONE=0, LIVE_OWNER=1, LIVE_RUN=2, LIVE_TICKET=3, LIVE_WORKER=4, DONE=5; reason OK=0, BUSY=1, CLOSED=2, STALE=3, WRONG_OWNER=4, BAD_PHASE=5, LIMIT=6, OS_ERROR=7, INTEGRITY=8, PREFIX_RETAINED=9, RUN_ERROR=10. Record phases PRIVATE_BOOTSTRAP=1, RESERVED_WORKER=2, HOST_OWNER=3, RUNNING=4, RETURNING=5, NATIVE_TAIL=6, RETIRED_TAIL=7, JOINED=8, DESTROY_OWNED=9, DONE=10. Scope VM=1, INSTANCE=2. Internal VM_ANCHOR publication state is a separately tagged enum, not interchangeable with owner phases.

Every valid-ABI call initializes the result, including failures. `LIVE_OWNER` on refused close means **no ticket transfer**. `LIVE_TICKET` on a failed destruction step means the same record remains DESTROY_OWNED with its prefix intact; it cannot be used as an ordinary owner. `DONE` means this exact capability is consumed and cannot be left again. An unbound/stale key returns NONE without dereferencing a VM. Original run status is copied before record departure; cleanup refusal must not overwrite it with NO_ERR. The two status fields preserve both outcomes: run_owned returns original_status when its cleanup completed, otherwise cleanup_status with the surviving disposition. A nonzero original run status and RUN_ERROR can therefore accompany an intact LIVE_OWNER. Helpers unrelated to run/OS status initialize original_status to NO_ERR.

Each host-owned `prefix_items[i]` is keyed by VM/slot incarnation and resource kind, with stage NOT_STARTED/IN_PROGRESS/DONE/UNKNOWN and actual error. Each `close_items[i]` records the particular VM/generation, gates owned by this attempt and prior state. Use an array for the complete VM/slot set, not one truncated64-bit mask that omits processors or child VMs. An interrupted IN_PROGRESS destructor with unproven side effects becomes UNKNOWN, not a retry of the same free.

Use process-native allocation independent of Scheme GC/GSTATE allocator callbacks for the journal and immutable handles. Recycle a slot only after its owners/children/API readers have completed; increment its epoch before reuse. Refuse epoch/serial/count overflow. Validate all four key components and allowed kind/phase/native actor **under journal admission before obtaining a VM pointer**. Reading from a freed caller-supplied record is not validation. A hostile C pointer or invalid result buffer is outside the supported C contract; ordinary stale/cross-owner value keys are explicitly rejected.

`native_instance_begin` is a trusted installed-runtime bootstrap operation: match the instance against the runtime's process-stable instance registration, without dereferencing arbitrary caller memory. It claims first/repeated setup before GSTATE mutation and returns PRIVATE_BOOTSTRAP parent. `setup_owned` binds explicit VM0/P0 exactly once, creates the VM_ANCHOR and publishes vm_out only after the selected setup/READY requirements succeed. On failed private setup it returns the surviving PRIVATE prefix owner; on failure after public VM binding it returns the live owner/ticket dictated by the actual cleanup stage. It cannot silently consume the handle and still return LIVE_OWNER. Main and embedders handle these dispositions identically.

`owner_attach` resolves an OPEN VM_ANCHOR under journal admission, admits a counted HOST_OWNER, and binds the current registered native actor. It does **not** grant simultaneous execution of the same P0: checked ps/execution authority must also admit that actor before run/callback entry. Where the existing supported embedding cannot supply that authority, return WRONG_OWNER/BUSY rather than inventing a pstate or weakening the gate. `owner_leave` requires no live children, loans, pending native tail or resource-prefix obligation; it consumes only its own unit and returns a host-only DONE result. A caller that intends cleanup uses destroy_begin instead of leave.

`run_owned` is the public/internal checked replacement for raw run invocation. It performs begin→marker prepare→TRY/body→END_TRY→finalize→leave, preserves the parent, and returns the original immediate status plus actual surviving disposition. Its thunk is protected before any Scheme allocation using the existing traced saved-root/marker mechanism. No Scheme value is rooted merely by putting it in a native record. Supported recursive callback children use their own keys; they may not finish the parent's record. Trampoline retry does not call begin/finalize again. Native fatal/cancellation/arbitrary host longjmp that skips the checked boundary remains terminal/unadmitted, never successful cleanup.

Before returning past a native run frame, finalize must invalidate that frame's marker so a captured continuation cannot reenter a dead C activation. Marker invalidation and release of its still reference are separately journaled exact-once stages; if other cleanup is retained, the disabled marker's owned reference may remain rooted. A LIVE_RUN retained record after native return is not permission to restore its old catcher/stack. If marker invalidation itself cannot be established, do not return a recoverable child handle past that native frame: take the declared terminal containment path. Unit counts alone cannot make a logically live marker safe after its C activation disappeared.

Worker helpers are internal checked operations. `reserve` requires live creator/resize authority, a matching prepared RUN with an actual traced startup-root slot, and an exact initialized worker slot incarnation. It allocates/publishes the worker parent and charges its unit **before** OS create. `preparation/startup_root_slot` names the selected resize preparation's existing traced carrier; validate its epoch, owner and root type. Native journal storage or `t->data_scmobj` alone does not establish GC coverage. Child startup reloads the current value from that authoritative carrier and installs its own Scheme/marker root before releasing the preparation borrow. The final B must bind this preparation at the Scheme/resize landing; if no such root cell is implemented, reserve refuses instead of accepting a boolean preparation assertion. This reuses the selected preparation/root mechanism, not a second root domain.

`create` owns the actual ___thread_create result and OS-created outcome; callers cannot supply a guessed errno/no-consumer flag. Child `claim` acquire-observes the reservation, establishes the actual native actor, and CASes RESERVED_WORKER→HOST_OWNER without charging again. It is allowed to claim that already-reserved lifetime even if an attempted close is pending; it does not create a new admission. A legal growth's existing resize admission prevents whole-VM teardown from invalidating required startup SYNC. No new unreserved run is admitted after a successful destruction close.

Actual POSIX baseline sets thread_id only after pthread_create returns; claim cannot wait on or assume that field. A definite failed create with no claimed/started OS consumer cancels the reservation once. Started or unknown outcome retains LIVE_WORKER and requires actual join/terminal disposition; it is never PRIVATE_PREFIX. The baseline thread_init_common always succeeds, so the real fault control is native create failure, not an invented later return error. Partial creation must preserve every already-started worker record.

`retire` release-publishes RETIRED_TAIL and leaves native units/marker ownership intact before direct thread_exit. `join_once` records the real OS return and durable OS_JOINED before any grace/transfer check. A subsequent call on OS_JOINED does not call OS join again. `finish_joined` is the sole post-join path shared by direct shrink/recovery: validate GC/scan exclusion and root handoff, transfer memory/ownership, finalize only safe abandoned records (no remote Scheme/catcher restoration), then consume their units. Failure returns LIVE_WORKER with OS_JOINED and actual prefix unchanged. Record real native actor/generation authority for the reaper; a random P0 id is not a capability.

#### Atomic transactions, refusal and ticket ownership

All registration changes use short journal admission with no Scheme allocation, GC, callback or blocking while T/M/P/VM locks are held. Reserve/allocate native records before mutation; under admission validate the parent, gate and target, charge the exact unit, link the child, publish ACTIVE, then return its key. A close cannot observe the middle as unowned because it uses the same journal admission. Before publication a failed admission rolls back only its own provisional unit. When a collective cannot acquire this admission without blocking, return BUSY/retained with existing ownership, never wait while other members need it.

`destroy_begin(scope)` accepts only explicit VM or instance scopes (VM=1, INSTANCE=2), under the canonical preflight in this document. It stages reversible close-mask ownership; it refuses an active caller-child, real foreign frame, live delivery/pass or unprepared root. Worker parents and already-admitted native SYNC service are not required to vanish before their shutdown is issued. Do not add normal run counts to sfun_frame_count or delivery_admission.

When only the caller's exact transferable owner remains, initialize all ticket-prefix/output storage, then CAS its own phase HOST_OWNER→DESTROY_OWNED. **No counter decrement and no new record** occur at this linearization point. Return the same key as LIVE_TICKET. Every ordinary owner operation now rejects that key's phase; only ticket operations accept it. Closed gates/owner-state checks prevent duplicate or recursive close from taking over. The scalar key's copied aliases do not grant multiple units.

Before-CAS BUSY/error returns LIVE_OWNER and reopens only this attempt's reversible closes. After-CAS error returns LIVE_TICKET, keeps admission closed and records the completed prefix/original error. `destroy_step` starts at the first uncompleted safe resource step; it does not rerun completed destructors or turn an unknown free/unlock into success. If an operation's side effect is unknown and cannot be safely reconciled, retain/terminate; do not offer automatic resume of that step. Caller result.phase/progress cannot advance the private ledger.

`destroy_finish` requires a fully accounted prefix and no child/foreign/delivery/registry/native tail except the ticket's remaining authority. Perform final VM/global reads and registry replay while their instance parent/ticket is still live; copy all status/free arguments. Consume the one charged unit while VM metadata is still valid (closed3→closed1 for one unit); the same DESTROY_OWNED record retains exclusive physical teardown. No other actor is admitted by closed1. Physical free/invalidating association is followed only by host-owned record/status accesses; generic owner/run leave must reject this ticket and never touch a freed VM. If interrupted between the debit and its host-only acknowledgment, the same exclusive ticket may reconcile the still-live expected closed word; if container liveness is unknown, it cannot read that word or retry free. No successful recovery is inferred from an ambiguous final boundary.

For INSTANCE scope enumerate all VM/generation units and the caller's exact owned transfer set; do not subtract a guessed constant “one caller” from a global count. Early multi-VM refusal rolls back this attempt's closes; any irreversible prefix makes the retained instance ticket the single owner of subsequent work. VM0's static address does not permit using destroyed VM resources. External stale vm_ref/owner/run/ticket values fail journal lookup before ps/VM access, including after re-setup at the same address.

### Parent owner establishment, generated returns and the exact final handoff

This section fixes the actual parent boundaries; a phrase such as “the caller still owns it” is no longer an implementation premise. All helper names ending in owner/entry/ticket below are proposed changes, not existing runtime symbols. Reuse the selected native owner record and destruction admission, with no alternate scheduler or message channel.

**Establish the parent outside the child, with an explicit handle.** The parent is allocated in process/host-owned native storage whose allocator/free lifetime does not depend on Gambit VM memory, RC lists or GSTATE callbacks. The immutable handle is established before any setjmp. Full instance/VM incarnation, native owner, parent identity and owned unit are carried in that record. A TLS association may locate the handle but is not evidence that a raw ps/VM pointer is still valid. Never store this native-owner association in a migratable Scheme continuation.

### Why all-blocked no longer depends on a notification callback

There are three exhaustive delivery cases within the supported scope. If GC is pending, return all ordinary claims/locks and serve SYNC at the existing outer safe point before retry. Do not enter GC inside a T/P/VM lock or retain old W/N/Q/D pointers through it. A generic procedure hint alone is not permission to execute arbitrary Scheme in a fabricated denv; this scoped idle helper does not claim to close every external callback contract. ### The selected redesign: execution ends before notification/reclamation ends

The target's interrupt list represents **Queued/Active execution**, not a journal of all delivered requests. The existing VM Retained list represents outstanding delivery/notification/reclamation responsibility. These are distinct memberships, with distinct links and locks. Root ownership is not execution eligibility.

1. Before admission, the existing request/R is rooted in the existing Retained list. Queued and Active stay on the target list so termination and nested delivery can find them. No early Active dequeue is introduced.
2. In the actual result/abandon transaction, while holding the exact target T plus the already required mutex/waiter/P locks, prepare result/runnable state and pending-D, detach this node from the target execution list, and release-publish terminal3/4 last. These stores are one no-GC/no-escape commit; all validation is before the first mutation.
3. **Do not wait for pending-D=false or R.armed0 to remove execution membership.** Retained membership/roots, exact finish ownership and R pin survive independently. Sender can still wait, notification can still retry, and native idle services the existing rooted debt. No false success/reply is produced by unlinking.
4. Only the existing shared retained-unlink/pass/owner closure removes GC roots and final pins after all obligations actually settle. A thread-queue detach is never a delivery debit or permission to recycle the mutex/R/VM.

The hot-path data structure no longer contains completed history. This prevents the identified cost mechanism, while retaining the same accepted requests and failure evidence.
