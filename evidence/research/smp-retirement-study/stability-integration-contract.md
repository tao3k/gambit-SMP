## Decision: integrate an existing coherent delivery design, not another wake-only edit

The current lock has a two-field request `[next,result-mutex]`. `##thread-intr!`1439 and `##thread-intr-propagate!`1463 selects P or T ownership based on running state; its running branch1507..1521 splices the request directly into the P queue. T resume and P dispatch independently execute/unlock it. The current candidate has none of `##thread-intr-notify!`, `##thread-intr-wake!`, `##thread-intr-execute!`, `##thread-intr-drain!`, and no `device_select_with_cap` backend. Presence/absence and all26 lock hashes were checked, rather than inferred from patch titles.

A prior applied implementation already combines these mechanisms. `owned-request-fault-coordinator-native.patch` SHA256 `78c2900a783cf9c6948eeed8245f2ac1815bbe2d3b93051e773d67dbfc4ea435` reconstructs all seven source files exactly from retained before snapshots. Its GSI was `1a32b364a5b421ea674db68b67e8219570cebfe2d2398a120fec2096a29aa184`. Its three underlying native receipts were rehashed in this audit, not rerun:20 checks (including expected failure/refusal cases), of which eight are p11 flood runs of100000 with exact result markers, each inside12 seconds. Retained flood logs and fixture SHA `d940a05a0880e06e7ff3364b52103eb5fb274834f9dc6543fdc781baf4f11f17` were rechecked. This is positive native evidence for an implementation, not proof that the user's historical flood is the same fixture or that the current lock passed it.

**Do not apply that old patch wholesale.** Six of its source files are bound by the current lock and all six differ. The seventh, `lib/c_intf.h`, is not listed in this lock; its current identity must be bound explicitly before integration. Preserve current migration-target consumption, live-member checks, sync-participation retry, bootstrap/registry/FFI/lifecycle work and diagnostic changes. A file-level rollback could lose newer repairs. The tested reference is a function/edge source for a new integrated producer, not a completed-producer authorization for changed bytes.

## The implementation contract

|---|---|---|---|

P receives a separately allocated two-field procedure hint with its own next. Never pass the result node to the P C enqueue or manually splice it there. | T queue owns accepted request until a T-locked pop. Failure/rejection/loss of a hint does not transfer or discard request ownership. | Held-boundary running→park and migration tests: request reachable in exactly one T queue or execution frame; zero result nodes in P queues; exact once execution/reply. |
| An old hint can remove a thread from BTQ/TOQ after its request already finished (`##thread-lock-remove-btq-toq!769`) | Add the tested optional pure `should-remove?` check **under T lock before either BTQ or TOQ removal**. On each trylock retry recheck it. Hint predicate is live target AND nonempty interrupt queue. Preserve current lock-free retry's SYNC participation. Existing three-argument callers keep their behavior. | A stale hint releases T and ends without changing scheduling membership. | Complete request, leave old hint pending, then deliver hint: no BTQ/TOQ change, no new runnable copy or duplicate reply. |
| Hint delivered on old P after migration | `##thread-intr-wake!` rereads current route under T and current P protection. Validate current live member before use; no cached pstate across SYNC/GC. Release P before T. P dispatch executes procedure hints, not result-mutex nodes. | Active Scheme frame roots node/mutex/outcome; handler owns the request until result publication or explicit abandonment. | Nested interruption, GC between result store and unlock, migration/yield in thunk, ordinary exception, continuation escape/reentry, target termination. | Handler throws/escapes before result mutex release | Reuse the tested dynamic-wind ownership check and actual mutex-abandon path. Normal result is stored before real unlock; ordinary exception releases ownership then follows declared exception semantics. A continuation returning to an already-completed request must be rejected before invoking the thunk again. | Current owner/abandonment protocol, or VM terminal fault, accounts for the blocked sender. A phase flag or caught diagnostic exception alone is insufficient. |

Native slice expiry returns to the scheduler; service occurs after P unlock. Recompute against the original absolute device deadline. An internal slice must not report user/device readiness. Native device cleanup keeps uncapped semantics. | Stable T queue survives notification failures; P hint survives masked flag until actual service. Hard write errors enter the existing reference fault-coordinator mechanism; if compatible current lifetime/context support is absent, retain/fail explicitly, not silent successful delivery. | Mask OTHER, drain pipe, then wait again: the scheduler must return and service pending work. Inject EINTR once, persistent EINTR, EBADF, and held write; preserve real deadline, no close while writer active, no successful fake reply. |

The reference backend uses50ms internal slices (up to20 native returns/second/indefinitely waiting P). This is an explicit stability/idle-cost tradeoff, not an increase in an acceptance watchdog or device timeout. Extra request fields and fresh forwarding hints add allocation; exceptional-path outcome vectors/dynamic-wind and fault-coordinator state add work. There is no matched application CPU/latency claim yet. If those costs are unacceptable, optimize only after the integrated producer passes; do not revert to wake-only semantics.

Current ticket acquisition already has an acquire-read repair in the Darwin GCC branch. Preserve it and verify the active target/compiler branch; blindly adding the old barrier patch is not a new causal fix. Valid VM/pstate lifetime and incarnation checks must precede native hint dereference. Neither the old patch's integer P id nor a new request phase is a stale-pointer safety mechanism.

## Why this is a causal change, and what it does not prove

The structural change removes the transition in which the result node's sole intrusive next is rewritten by another queue domain. It also gives a detached request an explicit active owner and a real exit path. The independent wait return prevents correctness from depending on one masked pulse arriving at exactly the right time. Those are distinct obligations: thread-only enqueue without durable notification/recheck already failed; polling alone cannot recover a lost request; a catch alone cannot repair queue ownership.

The shared link in the current design is not by itself proof of simultaneous ownership: correct locked detach/transfer could make such a representation safe. This audit has no request-R trace proving the exact lost edge in the historical hang. The recommended redesign eliminates that failure class by construction and has finite native support; it is not a claim that this audit identified the unique corrupting interleaving.

Existing `owned_request_fault_coordinator.qnt`, its13-control receipt and the request lifecycle models supply conditional negatives for shared-link ownership, stale hints, execution/reply and root coverage. This audit did not add fairness assumptions or rerun those models. They do not establish current C refinement, compiler memory ordering or infinite-migration progress. The native eight-round result is supportive and finite. Completion assumes scheduled owners get CPU, finitely many adversarial route changes, successful allocation or a real terminal outcome, and user thunks that return/raise/escape through the supported boundary. A new producer must supply C/generated-code evidence rather than inheriting the old model label.

## TFIB remains a separate repair decision

The historical failure is bound in `tfib-crash-binding.json` to GSI `5620dd70a28f46765551c07742bfc4b5877096008900f9addd486d90de1bf5ad`, UUID `c823a9d8-418b-35f6-88bf-1330cef04de5`. Its recorded fault is mark_array+104, `ldr x25,[x0]`, x0/FAR `0x3f947ae147ae1478`. The floating-point mask coincidence with0.02 does not establish an F64 origin. This audit rehashed the published binding; its old run-local audit receipt is no longer present at the named cache path. That retention gap is explicitly recorded, not silently called fresh raw-PC verification.

A matching new crash record determines the next code change:

| First accepted scan context | Required repair location | Evidence needed before choosing it |
|---|---|---|
| A scalar field was genuinely included in a pointer scan range | The exact `scan` subtype/field-range producer that called mark_array | Valid containing object/header/layout plus actual cursor proves the range includes the scalar; mask resemblance alone fails. |
| Frame slot was selected by an invalid/stale frame map | `mark_frame`/captured continuation plus the **actual emitted return-label/map** or save/restore writer | Return label, map bits, saved frame identity/epoch and current slot distinguish stale map from legal tagged data. Fix map/publication/root materialization; never hide the slot. |
| A legitimate pointer field was overwritten earlier | The actual writer/bounds or relocation publication that changed that field | A before/after write tied to same object generation and covering address. Last scan payload alone cannot identify the writer. |
| Record unavailable, partial, wrong owner/epoch, or only injected null PC | No runtime repair selected from that run | Correct observation coverage and rerun only the authorized targeted control; never skip suspicious words in GC or substitute a fabricated record. |

The eight delivery passes do not close TFIB, and a diagnostic carrier does not repair GC. This specification therefore supplies an evidence-backed interrupt integration solution and a finite TFIB decision procedure, not an unsupported claim that all four gates are closed. Lifecycle contract review and the remaining Gerbil/release gates remain separate.
