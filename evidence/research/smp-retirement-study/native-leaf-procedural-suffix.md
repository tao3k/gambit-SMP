## 2. Procedural callback error: exact lock and suffix ownership

Current `lib/setup.c`:

-348 locks `procedural_interrupts_mut`;350..357 detach only the current head, advancing shared head and changing tail only if next is NULL.
-361 unlocks before `probe->execute_fn(probe, ___TRU)`363.
-365 `break` bypasses367 relock and reaches370 unlock: **source-confirmed unlock-while-unlocked path**.
- `___service_interrupts_pstate393..408` clears `intr_flag[OTHER]` only when service returns NO_ERR. On ordinary callback error it retains the flag and trips the stack again. The present caller tests the error and does not forward it as a Scheme result. Preserve this behavior unless a separately reviewed API change is intended.

Required implementation order:

1. Before detach, carry queue responsibility into a stable native activation record with valid VM/slot/incarnation borrow. Do not place the only completion/pin context in `probe`: the callback may free itself. Snapshot the callable and any independently valid release context while its header is live. Install required Scheme roots before a callback that can GC.
2. Detach current head under the mutex; retain the untouched suffix in the shared queue. Release the mutex and check the actual unlock result before invoking the callback. Existing POSIX macros10990/10991 reduce status to booleans and current callers ignore it; do not infer a known lock state after failure. A checked platform-specific helper must preserve/handle the real result. Unknown unlock state cannot be retried, treated as ordinary callback error, or returned into collective progress; use the existing reviewed terminal disposition outside the uncertain lock path.
3. Invoke current callback once outside the mutex. On ordinary non-NO_ERR, **return while already unlocked** after settling the stable activation's last use. Do not relock solely to use the old loop epilogue, do not retry the detached callback, do not clear head/tail, and do not restore cached `next`/tail after unlocking. Concurrent append or nested service may have changed the queue. The untouched suffix remains owned by the queue, with OTHER service debt preserved by393..408.
4. On NO_ERR, release the current activation after its last valid context use, then reacquire the mutex and reload shared head. No read of `probe` (including its function, next or accounting fields) is allowed after a self-freeing callback. Do not cache the old suffix pointer as the next iteration's authority.
5. Distinguish nonlocal escape from a callback error return. A stable activation ledger must either be discharged by a verified `___run`/native catcher cleanup path, or remain retained with its roots and VM borrow. Do not return a fake NO_ERR or re-enqueue an item of unknown callback progress. Arbitrary host longjmp outside a registered catcher is unsupported: reject before acceptance or use terminal retention/termination. This source currently has no per-item escape ledger; a `return err` alone fixes lock balance but does not close escape lifetime.

For A→B plus concurrent C: after detaching A, B→C belongs to the live queue. An error return must leave that queue intact. With legitimate nested service, B/C may already be consumed; acceptance must check per-node ownership/completion history, not insist that a stale B pointer is still head. Ordinary error may not erase them. Exact FIFO and arbitrary callback behavior are not proved by the small set-based model below.

### Cleanup is another consumer, not a special exemption

`cleanup_interrupts_pstate591..605` currently invokes release callbacks while holding the mutex, ignores their returned status and later clears both head/tail. Grok must change this together with service: close admission; establish exclusive cleanup/dispatch ownership and drain or retain active invocations; detach one item under lock; invoke its false-op release outside lock; re-read the queue only after reacquisition. Preserve current-item uncertainty and suffix ownership on error/escape. Do not repeatedly release a partially destroyed item. If the public cleanup API cannot return failure, route an internal checked status to callers615/1472/5766/5804 so they retain resources or enter a declared terminal path; never let a void return authorize mutex/VM destruction. Closing publishers alone does not prove active callbacks have left.

## 3. Generated C root and last-use certificate

The procedural header at header11678..11682 contains only native next and execute_fn; neither a native pin nor that header is a Scheme GC root. A callback payload containing SCMOBJ must have a separately registered, actually scanned carrier or mapped callback frame. Do not add raw SCM fields to a native activation and count them as covered.

For the Scheme result-mutex leaf, the certificate must identify mapped live slots/registers for request node, result mutex, payload, waiter, owner threads and WakePending carrier at every legal GC point. Evaluate/preallocate the carrier before participating preparation; after **every** SYNC/GC/retry reload relocated SCM values, then derive body pointers only after the final validation with GC excluded. A native local `___SCMOBJ` or `W_ALL` token does not by itself extend a frame map. Raw interior/body addresses cannot be carried through finish GC; rederive from its live carrier.

For procedural callbacks, bind C-to-Scheme entry and return/throw maps on the actual generated code. Keep carrier/activation ownership while native code is not on a Scheme frame. For ordinary error, a Scheme-valued error must stay rooted through any participating cleanup before it is consumed; if current compare-and-return has no safepoint, prove that region rather than inserting a logging/allocation helper. Copy native release context before callback, release its VM borrow only after last access, and perform no trailing header/context access after the final release. Nested callbacks need distinct activations; clearing the outer pin on nested completion is invalid.

The previously hashed `_thread.c` and `_kernel.c` are source-package references, not an SMP regeneration certificate for the new leaf. Their actual `MW_ALL` definitions are captured as reference evidence only. `targ-use-all-res` at `_t-c-2.scm4208` selects compiler resources, not root lifetime. No leaf/object/root certificate is admitted this round.

Reject trailing second unlock or repeated A. |

## Judgment

The local error fix is concrete: replace the erroneous unlocked `break` path by an already-unlocked ordinary error return while preserving queue/retrip semantics. A stable activation and checked cleanup/escape contract are still necessary around it. The leaf needs an actual implementation and selected macro/object audit; current source only proves reusable store chains and identifies helpers that cannot be carried inside. Those are implementable acceptance conditions, not evidence that TFIB or interrupt hangs are already repaired. No further broad protocol is proposed here.
