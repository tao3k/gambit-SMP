## 1. Route recheck: remove the unsafe capability, not merely add an id test

The current Scheme running branch checks member identity, but releases P/T and then performs a C nudge using a saved integer. The reference notify does the same class of unchecked lookup through `_kernel.scm:1560`. A bounds test by itself is not incarnation protection. Current source has a VM-list reader gate, not a general checked P request-acquire interface; no such interface is assumed to exist.

For this integration, use the following default implementation, keeping native nudge an optimization:

1. Allocate a **fresh hint** in mapped Scheme state before acquiring T/P. Initial allocation precedes request acceptance. A forwarding activation keeps its popped hint/target rooted until a replacement is committed or real failure ownership is recorded.
2. Acquire T using the predicate-aware helper. Under T validate the request is still needed. Read last-P as a Scheme object; acquire P with the current SYNC-participating helper. After any participation, reload target/last-P/membership and restart route selection if it changed. Do not use a pre-GC raw address.
3. With a validated live P locked, append only the new hint using the current running-branch queue splice, substituting the hint for the result node. The critical segment from final membership observation through splice consists of immediate stores: no allocation, Scheme callback or further SYNC. Release P then T. If target is not running, make it runnable under valid destination-P protection instead; preserve pin/migration destination semantics.
4. **Do not call the unchecked id-based native publisher/abort after unlock for correctness.** The scheduler slice return and heartbeat service described below are mandatory. A native nudge may be added only with actual same-VM/slot lifetime admission spanning that use. This avoids inventing a lease in a document or holding T/P across an error callback.
5. At an unlocked service point, a consumed hint reruns this route check. If target is current locally, pop its T requests; if it is elsewhere, commit a new hint on the new valid route. An expired hint predicate returns without BTQ/TOQ mutation.

This is a **new integration choice**, not one already measured by the old8/8. It trades promptness/idle work for removal of a delayed-id dependency. Existing run-queue helpers include hidden `##wait-abort!` calls after P unlock; a request-specific insert-without-unsafe-nudge variant is required if the new path otherwise reaches them. Do not silently discard pinning to simplify the variant.

Resize is a separate route boundary that cannot be ignored: a hint committed on P before a subsequent collective must not vanish with that P. Before shrinking/removing that P, its pending hints must be drained in legal Scheme context or transferred with their roots to a surviving service owner. Existing `handler_quiet`, `post_join_borrowers_clear` and `post_join_donor_empty` do **not** check or hand off the Scheme high-level hint queue. If such handoff is not implemented, shrink must reject/defer **before count/domain change** while these obligations remain; neither clearing the queue nor retaining unserviced bytes establishes delivery. A callback-triggered resize may not wait for itself to complete. Growth/reuse must not reinitialize an occupied queue. Fixed-cohort p11 controls are useful but cannot certify concurrent resize. This is an explicit implementation dependency, not a claim that lifecycle is repaired.

## 2. Release: actual mutex ownership decides whether cleanup may abandon

The reference sets `completed?` after the thunk/catcher and ends its dynamic-wind **before** writing result/phase and calling mutex-unlock. The current unlock macro calls `##check-heap-limit`; its slow helpers drop/reacquire locks and participate in SYNC. Thus the reference's exception fixture does not establish coverage of all result-store→unlock transitions. This is a source-correspondence/coverage gap; no new native failure is claimed.

Implement one protected request activation encompassing thunk, caught outcome, result store, phase preparation and actual unlock. Do not mark release complete merely when the thunk returns. Retain the reference semantics: ordinary thrown error is re-raised on target after disposition; sender gets the existing abandoned-mutex action, not a successful exception object. Normal result and failure phase must be visible before actual unlock permits the sender to consume them.

Add request-specific `##thread-intr-abandon-owned!`:

- Root request/mutex/immutable target. Acquire target T, then mutex using the current try/SYNC discipline. Inspect **actual** mutex owner under its mutex lock.
- If still owned by target, set failed disposition, release mutex lock and invoke existing `##btq-abandon!` while retaining target T. The private result mutex has no independent user releaser; target T excludes concurrent termination. The helper reacquires mutex itself: do not call it holding the mutex lock. Recheck after any lock-dropping participation before relying on an old owner observation.
- If ownership was already transferred/unlinked, do not abandon, unlink, overwrite successful phase/result, or decrement anything again. This covers escape after the physical transfer but before the unlock helper's ordinary return.
- Release T on every supported return. Cleanup itself may participate in GC; request/mutex/target and pending error must remain mapped roots. Cleanup failure/nonreturn is retained/terminal, not successful release. If source inspection of the adapted helpers cannot exclude another releaser in this interval, merge a checked-owner variant into the helper rather than use the unlock/relock sequence.

A debug `phase`/`released?` flag can reject duplicate kernel dispatch, but it cannot replace the actual owner test. Protect both no-waiter and waiter-transfer paths. A continuation entering after terminal disposition must be refused before dispatch; arbitrary C longjmp bypassing Scheme dynamic-wind remains outside this Scheme guarantee and must follow the native marker/fault boundary.

## 3. Wait return: specify both lock states and service the queue even if OTHER was masked

Bare scheduler idle path: P is unlocked → `##wait! #f #t` adds/removes VM-deq entry with V lock → native slice returns → all T/P/V primitive locks are absent → pending hint service/fault observation → schedule again.

Device path: P initially held → `##thread-check-devices!` → wait/native adapter enumerates device pointers/condvars → C drops P → native wait → C reacquires P → device flags/timeouts processed → Scheme caller unlocks P → pending hint service/fault observation → schedule again. A C RECHECK reason is not permission to invoke Scheme before this last unlock. Preserve the current kernel RA/register wrapper.

Add a common **unlocked** delivery-service edge used after both returns and after heartbeat's P unlock. It explicitly checks/drains committed P procedure hints (and current T requests when current-thread exists), rather than assuming `##service-interrupts!` will necessarily observe masked OTHER. Keep ordinary interrupt servicing too; permit nested service on distinct requests. Same-request phase/ownership prevents redispatch; do not hold a processor-global service-busy flag through a thunk, because a nested synchronous interruption may need that service to finish. Hint service may yield/GC: subsequent code must use current mapped P/T bindings. SYNC participation under locks does not call this helper.

Port reference `native_cap=0.050` only to scheduler waits; slice expiry produces internal RECHECK, maps to retry/EINTR at the scheduler adapter, and bypasses false device-timeout callbacks. Public `___device_select` and native cleanup preserve existing uncapped deadline contract. Repeated abort/EINTR cannot rebase an absolute user deadline to now+duration. Up to20 returns/second/idle P plus heartbeat queue checks is an explicit cost. There is no hard50ms completion promise under OS preemption, a blocked collector, or arbitrary user callbacks.

Permanent write failure must still latch a real fault and enter a rooted, valid Scheme coordinator outside locks. This fallback is separate from ignoring an optional nudge. A sticky fault without an eventual legal observer is not completion. Existing fault-coordinator reference code is reusable only after current marker/VM carrier/lifetime declarations and generated code are reconciled. No `_Exit`/callback under P lock is introduced as a queue repair.
