## Receipt fields: existing versus diagnostic observations

Keep existing raw execution fields unchanged. Direct execute/owned-request style has `name, exit, timedOut, seconds, process`; `process` includes `pid, startedAt, endedAt, parentReaped, processGroupQuiescent, processGroupProbes`. It returns a combined stdout/stderr log: save raw log path/hash; do not invent separate stderr hashes. Recipe ExecutionContext.run instead uses `timeout` and explicit `argv,cwd,effectiveBudgetSeconds,log,logSha256`, plus stdout/stderr paths/hashes only when engine capture actually supplies them. Do not silently translate away the raw fields or replace an old receipt.

Add a separate case-observation sidecar in the existing audit outputs; these are **proposed Evidence fields**, not new framework-recognized recipe keys:

* `caseId, scheduleId, scope` (actual-helper race / actual-GC integration / actual-load fault), fixture/controller hashes and producer identity receipt/hash, gsi/gsc/library/mem.o and actual crashing executable UUID/hash.
* `injection`: compile/config binding, selected function/point, target owner/slot/incarnation, expected cut, actual reached hit count, native ordering trace/raw return values and source delta. A copied algorithm or an unhit selector is rejected.
* `expectedTermination` declared before spawn, `observedExit` as raw signed code, fault report path/hash with PC/signal/actor/address if there was a fault; ordinary partial _Exit must be distinguished from a real original-load fault. No fabricated PC when unavailable.
* `carrier`: backing device/inode or equivalent object identity, size, layout/schema hash, run nonce, supervisor/child mapping roles, declared writer set and actual quiescence observations, immutable raw snapshot path/hash and last-reader-before-release observation.
* `decodedObservation`: both banks' raw commit/footer, slot/native state, active/coverage, exact sequence/context/identity, initialized-field presence and reader verdict plus reason. Store raw bytes first; no trusted interpretation of partial identity or pointer dereference.
* `comparison`: before/after raw snapshots for no-write/no-reset cases, valid original collector/setup outcomes, actual GC/worker hit evidence, and explicit invariants evaluated. Missing native fact remains UNKNOWN/NOT_RUN, never a guessed boolean success.
* `runtimeAdmitted=false, nativeGcPassed=false`, qualification unchanged. A case can satisfy its controlled-failure expectation while raw exit remains nonzero; that observation is not a formal campaign PASS.

Existing process reaping metadata proves only the observed group; known additional registered writers need their own completed observations. A raw artifact can be safely retained even when interpretation is UNKNOWN. Its final consumer is the harness after all writers and all readers finish; only after snapshot/hash may that owner unmap/close/unlink. No runtime destructor, active reset, catch or DMB supplies this storage ownership.
