## 1. Durable ownership precedes any OS notification

There are two obligations, with different last consumers:

| Stage | Canonical object and owner | What may release |
|---|---|---|
| Accepted, not executed | Request is rooted in target's thread interrupt queue; target/hint routing owns execution responsibility | A notification attempt releases nothing. Transfer only under the target lock to an admitted, rooted receiver; termination must use the existing exactly-once abandonment path. |
| Target result-release commit | The actual waiter W is in admitted D's runnable tree, with outcome/owner/resume-thunk committed under M/T/W/N/Q/D; R-unit roots pending-D | D scheduler owns *service* before producer attempts abort. W and its continuation retain sender request/S; verify that actual map chain. |
| Producer finish | R protects native destination/descriptor use, pending-D roots its Scheme object | After checked best-effort notification returns and no future D/fd access remains, clear pending-D and settle R only if durable receiver ownership is established. |
| Receiver service | D reacquires its queue lock, re-reads canonical runnable/hint queues, schedules W or routes target request | Empty OS pipe or successful write is not completion. Request terminal/exact unit consumption remains separate. |

**Refinement of the previous “retain pin on notification uncertainty”:** retain R if queue/domain ownership or native access is uncertain. A *known* failed wake write does not force the already transferred producer R to remain forever: D owns the committed work, provided D has an independent bounded service return and removal/cleanup cannot discard that work. If either premise is missing, this optimization is inadmissible and the pin stays retained. Do not release R on a bare status integer or on an empty hint queue.

Do not encode service responsibility solely in a new flag. Its evidence is the actual rooted queue membership and admitted processor incarnation. Existing planned request pin/admission must prevent destination removal across commit. Under the existing common resize boundary, refuse/defer removal while queued interrupt, runnable work, activation, pending-D or native descriptor borrowers remain, unless an atomic rooted handoff is implemented. The current lock does not yet prove that common removal rule; concurrent shrink remains BLOCKED until Grok binds it. No delayed bare processor id may select a new incarnation.

## 2. Function-level integration order

1. **Native commit and Scheme finish:** implement `___thread_intr_try_release(ps,request,mode,unit,normal_action,abandoned_action)` and the Normal/Abandon/SenderFinal paths from the preceding document. Install rooted pending-D before releasing locks. Retry changes no queue/unit and returns with no primitive locks. Never call wait-abort under M/T/P.
2. **Checked abort:** factor a checked internal variant of `___device_select_abort` (`os_io.c1538..1564`), used by `##wait-abort-no-remove!2802..2806` / delivery finish. Borrow the admitted destination descriptor/instance through the existing planned checked entry, not id-only lookup. Snapshot errno immediately. A one-byte write is only notification. EINTR retries must be bounded by the already chosen finish bound; on exhaustion retain a diagnostic wake-failed result and let independent service proceed. EAGAIN/EWOULDBLOCK is coalesced only after proving the actual descriptor is nonblocking and still belongs to this instance; never infer completed request execution. EBADF/EPIPE/other errors retain fault evidence. Prevent SIGPIPE termination with the runtime's actual safe pipe mechanism, or classify that backend unsupported before accepting delivery. Unknown writer lifetime is retained, not retried against reused fd. Unlock/close unknown states still use the existing terminal/retention policy; this proposal does not repair corrupted descriptors.
3. **Bound only scheduler select:** preserve original absolute D_user; for a scheduler wait compute one effective deadline `D_eff=min(D_user,now+0.05)` (infinity handled explicitly, immediate poll stays immediate). Apply to both `devices=#f` and device-set paths of `___os_condvar_select11703..11794`, without changing general port read/write blocking calls at1657/1671. Reuse `___device_select_add_timeout844` / existing relative-time helpers only after verifying their clock domain. Repeated EINTR/internal retries must reuse D_eff, not refresh now+0.05. A stream of EINTR cannot extend the quantum forever. Match existing scheduler clock semantics; no new user-visible timeout or altered TOQ deadline. If backend cannot honor the bound, fail this control; do not widen the outer budget.
4. **Return and service:** for bare idle, retain `_thread.scm3236..3238`. For device wait, finish device-ready publication under reacquired P, release P at3262, then run existing `##thread-intr-service-unlocked!3264` and `##service-interrupts!3265`, then re-read queues through `##thread-schedule!`. A quantum expiry is internal RECHECK (existing non-error return may represent it here); it must not mark a condvar ready or invoke `##thread-timeout-action!` before the original absolute timeout. `##thread-check-timeouts!3259` uses real time/original TOQ. Hard select error must preserve roots/work while the existing scheduler-error path runs; it does not mean request completion.
5. **All entry contexts:** `##thread-heartbeat!2917..2919` already unlocks P then services; `##thread-resume-execution!2975..2988` consumes migration before draining target queue. Reuse these. Internal retry/sync loops must leave primitive locks before legal collective/GC participation and must not discard delivery responsibility. A permanently running foreign call without a supported safepoint/bounded park return is outside the progress guarantee; refuse such delivery before acceptance or retain it explicitly. Never promise bounded completion for arbitrary non-returning user thunk/native code.

The cap yields at most about20 idle returns/s/processor; this is a wake/rescan bound conditional on OS scheduling and finite backend calls, **not** an end-to-end50ms result bound. Active computation pays native tree/trylock work and existing service checks, not a mandatory50ms sleep. Two failed notifications must not double-execute a request; service always consults canonical queues.

## 3. Generated C: where no GC is enforceable, and where roots are required

A `not interrupts-enabled` declaration is not a no-GC certificate. The selected header `___CHECK_STACK8582..8586` still transfers to stack-limit code; `___CHECK_HEAP8594..8607` and `___POLL8571..8575` are additional exits. `_t-c-2.scm4201..4245` emits c-code operands as aliases and uses all resources; it does not automatically make C locals into moving-GC roots.

Choose a *single synchronous ordinary C call* for try-commit. It starts with no primitive locks and no allocation; managed active owner participation prevents a moving collection until this processor reaches a real safepoint. Native kernels have fixed locals, iterative tree repair, direct accessors, trylocks and release; no Scheme call, conversion, allocation, blocking operation, callback, logger, recursion, setjmp/longjmp or GC/stack/poll hook. Any ordinary refusal is pre-mutation and releases every acquired lock. After first mutation, only deterministic completion/unlock or the declared non-returning internal-corruption disposition is allowed. This excludes arbitrary hardware corruption recovery.

| Boundary in the regenerated wrapper | Required live roots / rule | Concrete rejection |
|---|---|---|
| Before native call | Actual generated locations for request, explicit R/S unit, outcome and action procedures; request reaches M/T/id, target R carrier | Missing liveness/map entry, wrong slot/shape, stale pointer from prior retry |
| Native holds lock set | No safepoint and active owner remains in GC cohort. W/N/Q/D locals valid only within this interval | Any transitive allocator/poll/callback/blocking lock; parked/unmanaged owner; early collective participation |
| Retry → unlocked SYNC/GC → next call | Request/unit/outcome/actions mapped; discard W/N/Q/D and all interior addresses. Recompute fields after reload | Map updated but C cached pointer reused; map absent so moving GC cannot rewrite the value |
| Commit → finish/notification | pending-D in scanned R carrier; reachable request/outcome/S until their last consumer. Native descriptor lease is a different unit | Native pin treated as GC root; R dropped before last D/fd access; callback escape bypasses cleanup |
| SenderFinal → last S release | Final unlock completed/confirmed, no future request/M/unit access | Unconditional dynamic-wind decrement on an uncertain or incomplete release |

The existing blocking bridge `_kernel.scm4558..4593` does FRAME_STORE_RA/W_ALL before select and R_ALL/RA restore afterwards; preserve that convention for the changed wait path. It is **not** proof that our unimplemented release wrapper has maps, and copying W_ALL inside a held-lock body is not a substitute. `mem.c7786..7799` scans actual processor SCM fields and8134 enters that scan; request/pending-D must be reachable through real scanned Scheme fields/frames. Native count or a raw pointer in an unregistered C struct does not provide this path.

## 4. Reflection: mechanism, dependency, falsification

| Change | Actual failure edge it removes | Dependencies / how to falsify it |
|---|---|---|
| Independent scheduler return | Lost wake write → infinite device wait → no queue service | Backend must honor absolute finite bound including EINTR. Force permanent wake failure with nonready device; no unlocked queue inspection refutes it. Bare-idle control alone is inadequate. |
| Transfer to durable D before notification | Producer drops responsibility because write returned or failed, while no receiver owns work | Rooted queue plus admitted domain and common shrink rejection. Force cleanup/resize just after commit; lost/misrouted work or freed D refutes it. |
| Native complete release | GC/escape between owner detach, TOQ removal and runnable publication | Port/lock-set correctness, active-owner premise and pure call graph. Hidden stack/heap/callback edge refutes the no-GC claim. |
| Mapped retry/finish | GC updates object while C continues from old W/N/Q/D or unrooted destination | Real generated maps and reloads. Move live request/outcome/D during retry/finish; stale address or wrong result refutes it. |
| Original deadline preserved | Scheduler slice converted into spurious device/thread timeout | Check no readiness/timeout action before original deadline; repeated RECHECK/EINTR must not extend or rebase it. |

No finite model proves arbitrary fair scheduling, C11 memory ordering, true backend deadlines, actual frame maps or absence of memory corruption. We can close the **design obligation** without claiming the missing implementation certificate. TFIB and the formal lifecycle gate remain independent. Count remains8/12.

### Lock-reacquire and model granularity limits

A finite OS wait does not bound the following P-ticket reacquire at `os_io.c11782`. The ordinary-return contract still requires P reacquired before publishing device readiness, then explicitly unlocked before Scheme service. Do not add GC or callback dispatch inside the current C condvar-array loop: its raw SCM locals are not a new moving-GC map. Grok must test contended reacquire and pending SYNC on the same B and establish finite no-GC lock ownership/absence of a P-held collective wait for this path. Otherwise the wait-backend control may pass while the *service* control remains BLOCKED. Supporting indefinitely blocked lock owners requires a separately materialized rooted device-wait activation; that is not implemented or proved by this focused change.

The QNT `pin` field abstracts aggregate live delivery/domain protection through receiver service; it is not a proof of each concrete R/S/H decrement or of the optimization releasing producer R immediately after checked notification. The latter additionally requires the native queue/root/descriptor-handoff certificate listed above. Likewise the model abstracts tree mutations and actual priority scheduling; existing native differential tree controls remain mandatory. These distinctions prevent a passing Boolean from replacing the missing C evidence.
