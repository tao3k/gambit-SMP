## Journal layout and ownership sequence

Proposed internal units: a stable native-owner anchor, an invocation frame with `(VM K, owner incarnation, invocation nonce, parent, kind CFUN/SFUN/run, marker association, phase, completed/error disposition)`, and entries with `(descriptor control reference, resource-loan nonce, typed GC carrier slot, consumed/handoff state)`. A native-stack watermark is a journal frame identity, not a movable Scheme fp or a raw stack address reused across epochs. The current producer does not contain these proposed units.

A descriptor control reference and a pointer resource loan are different counters. A resource's last loan may end and permit its release callback while the journal is still executing native cleanup. Its control reference must keep descriptor/key/outcome metadata alive until all those reads/writes finish. VM/run authority additionally keeps ps, catcher, marker roots and return tail alive. Conflating any two permits a use after free despite correct callback arbitration.

1. Acquire checked enclosing VM/native-owner authority and publish a rooted journal frame before converting pointer arguments. Allocate fixed prefix-entry capacity and mapped carrier first. If this fails, refuse without returning a raw pointer. A C automatic pointer used after longjmp is valid only if initialized before setjmp and not modified; mutable progress belongs to stable registered storage. C++ RAII alone is not portable to the setjmp configuration.
2. For each conversion, reserve a slot and descriptor control reference, then acquire resource loan under the shared phase/count protocol, then write the actual pointer output. There must be no fallible allocation between loan acquisition and recording ownership. A half-acquired entry is either rolled back by a known inverse before exposure or retained as debt; it cannot vanish on conversion error.
3. Keep the argument-prefix journal through native body, nested SFUNs, C result conversion and alias/out-param decisions. A conversion error after arg1, body exception, result-allocation failure and conversion-error-handler callback are separate exit edges. Protect error/status/root fields before invoking the existing handler or propagating.
4. On a matching SFUN/___call return, drain that SFUN's temporary entries and crossed descendants only. An enclosing CFUN which resumes C after the callback still owns its argument loans. On an actual outward unwind, settle frames inner-to-outer until the surviving marker/run boundary. Do not settle the survivor or a previously popped frame. An internal trampoline retry preserves the entire surrounding ownership chain.
5. `SFUN_SCMOBJ_TO_POINTER` result conversion is an additional escape boundary: C will use the returned pointer *after END_SFUN kills the marker*. If an admitted enclosing CFUN is the consumer, transfer the exact loan/control reference/root carrier to that parent journal **before** retiring the SFUN. Do not decrement then reacquire. If there is no checked parent, require an explicit exported capability or documented independent native ownership; a naked C pointer result cannot convey an invisible release token by itself. This needs ABI/caller migration, not a cleanup-only macro tweak.
6. Finalization copies the next entry, full key, status and completion destination while its control reference is held. Mark the entry consumed and update persistent owner/root bookkeeping. End the pointer resource loan; this may publish ready debt but cannot run arbitrary callbacks from the unwinding helper. Finish descriptor-dependent bookkeeping, unlink the entry/control root and make its **last control-reference decrement the final descriptor access**. Logging/wake hints after that point must use copied scalar identity or another independently retained object, not dereference a freed descriptor. Queue ownership for ready debt must be established before any last release, so a failed hint does not lose it.
7. After all pointer/metadata cleanup, finish R_ALL, temp/error writes, marker/catcher restoration and ps-dependent native tail under a separate live VM authority. Detach this journal frame using its saved parent/owner anchor before dropping the frame pin. Neither the helper nor generated epilogue may read the frame after its last reference. The enclosing run anchor survives that pop; dropping the last run/VM authority is separately ordered after every remaining native access. A last decrement followed by `ps->...` is not repaired by SC.

Unknown cleanup or synchronization state is not rolled back by restoring saved counts/head/fp. Transfer the stable journal/root suffix to a retained owner (or use declared terminal policy if no safe owner exists); do not acknowledge unwind/reclaim/reopen a new incarnation. The model represents a retained frozen suffix, not an executable implementation of returning through C with that suffix on a vanished native stack. A helper that simply returns an error after uncertain resource decrement has no exact-once proof.

## Real nesting in the new combined model

`recursive_ffi_loan_composition.qnt` composes shared resource claim, VM close, root-carrier versions, separate descriptor control references/native tails and explicit native stack:

`run anchor -> CF1 -> SF2 -> CF3 -> SF4 -> CF5`.

Each CF has a successful pointer prefix, body/result stage, loan drain, native tail and final pop. Each SF owns a marker and is distinct from its enclosing C borrower. The stack is a real ordered prefix, not two independent client IDs. An unwind to SF2 cleans CF5/SF4/CF3, leaving CF1's loan and SF2's marker; an unwind to run cleans the whole suffix. A trampoline retry leaves all three pointer loans live. Two abstract relocations require every live frame's registered carrier to remain covered. A separate returned-pointer mode transfers loan6 from SF4 to CF3 without a loan gap and releases it with the parent's last C use. Descriptor metadata remains pinned through journal tails even after resource release.

Candidate paths cover normal depth-five return, arg-prefix failure, intermediate/outer marker unwind, internal trampoline retry, retained cleanup failure, result failure and returned-pointer ownership transfer. Negative mutations cover wrong outer drain, prefix/result bypass, lost crossed frame, early descriptor free, post-final-reference access, whole marker-list retirement, stale-root restore, wrong-owner cleanup, duplicate unwind, early frame-pin drop, retry after uncertain cleanup, missing callback parent, premature run-anchor release and result-loan death at SFUN marker retirement. Direct bad-event mutations for wrong-owner/post-final-reference actions express a prohibition; they do not identify an existing C line that executed it.

This is bounded same-native-owner nesting (five frames), with fixed identities and abstract atomic transitions. It does not prove arbitrary recursion depth, C stack unwinder semantics, cross-OS-owner migration/lineage, moving-GC frame maps, C11 code generation or longjmp-local validity. It also does not replace the previous two-client/exported-token model: asynchronous exporters and concurrent callers remain separate prior controls, not silently included in this stack bound. Safety needs exact marker/owner routing and published roots. Completion additionally needs callbacks/borrowers to return, valid executor service and a known cleanup outcome; retention is safe failure, not completion.

These are review dependencies, not instructions to patch historical cache paths. Resolve ABI and root-carrier layout with that implementation. Only then is there an executable work item; this report does not authorize edits to that owner's thread or qualification.

1. Implement stable journal/control-reference primitives and no-fail/no-callback drain under the existing checked VM owner gate. Bind frame/marker/parent/nonce and declare allocation, migration and unsupported native unwind behavior. Include clean refusal before pointer output on journal/root-capacity failure.
2. Change generator cleanup classification and `c-make-function` entry/exit structure together. Put scope setup before conversions and common finalization before inline jump, OOL return and propagate_error; keep mode-specific W_ALL/R_ALL/frame maps correct. Audit `___CFUN_OOL` and `___END_CFUN_DEF` temp1 tails. Do not append a cleanup macro after an early-return macro.
3. Wire `c-function`/BEGIN_SFUN/END_SFUN, ___call marker match/rethrow, trampoline retry and ___run boundary finalizer. Distinguish matching return, continuing internal retry and actually abandoned frame; do not indiscriminately clean at every TRY catcher. Bind terminal worker marker retirement to retained journal ownership separately.
4. Implement SFUN pointer/struct/union/type results into a surviving parent or explicit exported loan. Result conversion failure, conversion-error handler reentry and multiple return must preserve exact owner and refuse stale/nonreturnable journals. Do not promise arbitrary foreign-address integer retention or unregistered host longjmp recovery.
5. Regenerate C/header from that producer and review concrete prefix-failure, result-failure, nested callback, matched marker, mismatched marker, internal retry and final native-tail expansions. Validate actual stack/frame root maps and supported setjmp/C++ configurations before treating source agreement as a native result.
6. Focused same-producer tests: depth-one/two/three C↔Scheme recursion; later arg failure at each depth; result allocation and forced GC while parents hold payloads; inner handled error and outward unwind; conversion-handler recursive FFI; internal trampoline retry retaining outer loans; SFUN returned alias used after marker death; duplicate/stale return refusal; explicit/will/VM-close races at drain and tail pauses; descriptor freeing immediately after final control decrement; owner mismatch/refusal; uncertain cleanup retention. Check destructor count, loan/control/frame/VM counters, relocated live roots and zero reads after final decrement with native instrumentation/sanitizers where supported. No marker banner alone is evidence.
7. Compare affected front-eight contracts on the accepted producer, then address lifecycle/GC-FFI/Gerbil/performance gates independently. The present evidence/model run neither starts native tests nor changes the unreachable historical lifecycle-error predicate. The needed contract review is explicit, not replaced by a fabricated errno.

The new sufficient conditions are narrower and testable: per-native-frame journal ancestry; exact supported unwind boundary; durable prefix record; uninterrupted result ownership handoff; distinct descriptor-control and VM-tail references; correct typed GC root registration; synchronized close/claim and no post-final-decrement access. They are not yet established in the landed claim patch or a native producer. Until implementation, generated C and focused native evidence meet them, fundamental stability and 9/12 remain unproved.
