## 1. First-session eligibility and one-use owner claims

Keep the bounded first-version scope: one recording session per process, one selected VM, no reused processor slot. Published mapping stays until process exit. Repeated *ordinary* setup may work under its existing host-serialization contract, but its diagnostic recording must be unavailable. Reusing an address or VM-local processor ID must never grant the old recording capability.

Proposed process-native fields in mem.c: `setup_seen` (sticky consumed bit), `session_open` (atomic admission flag), `session_serial` (constant1 for this first-version session), and fixed native `owner[MAX_PROCESSORS]` entries with atomic claim state EMPTY/CLAIMED/READY, immutable session/id and bound pstate identity. Per-pstate header fields: diagnostic session/id capability and eligible flag, initialized to zero before any processor-memory allocation. A pointer is only a consistency check, not the identity. With one-use claims and no reopening, (session1, slot id) identifies exactly one admitted pstate initialization; no wrapping counter is needed. No shared-carrier ABI extension is required if the harness sidecar binds this session and source identity.

Function-level order:

1. Add proposed `___gc_diag_begin_setup()` to global ___setup after existing cleanup admission and parameter validation, **before** reset of setup_state/VM observations. First call atomically consumes setup_seen; later calls close diagnostic admission and return unavailable. Never reset this bit in ___cleanup_mem, ___setup_mem, ___setup_pstate or a failed initialization. Invalid setup parameters rejected before this hook need not consume it. A failed first admitted setup does consume it. This helper does not turn concurrent/recursive global setup into supported runtime behavior; host serialization is still required.
2. Keep ___gc_diag_prepare_process at setup_os_and_mem5705. It may prepare only the first eligible session. Publish mapping/header state2 after complete validation, then release-open the session. Refusal is terminal for recording. A repeated prepare must not reopen a closed session just because mapping state2 persists. For early setup failure and accepted cleanup, close session_open; no wait/unmap/reset. A refused cleanup leaves a live session alone. A setup failing before setup_state1 needs explicit diagnostic close, since ordinary cleanup can no-op there.
3. Add proposed `___gc_diag_claim_pstate(ps,vms)` in ___setup_pstate immediately after vmstate assignment and local diagnostic zeroing, **before** setup_os_and_mem_pstate. Use the explicit vms argument. Require eligible first setup, selected VM identity and terminal prepared/open session. A child VM never inherits permission from VM-local id0. CAS native owner[id] EMPTY->CLAIMED once. Require a fresh parent slot (owner -1 and declared initial sequence/record state); do not overwrite stale bytes to make it fresh. Write immutable owner payload and shared owner initialization, then release-publish native READY. Finally store the pstate's session/id capability and eligible flag. Claim failure or partial claim disables only diagnostics, never waits, steals, resets or returns from GC. A pstate whose later setup fails leaves that claim consumed.
4. Change gc_diag_bind_owner3994 to acquire-open/READY and compare the pstate capability, selected VM and immutable owner descriptor. It only adopts pointers after these checks. Remove the current acceptance of arbitrary `owner_id == id` as sufficient authority. New local initialization clears eligible/session before any new claim; even the same pstate address therefore cannot inherit the previous capability. Attached may cache a validated immutable association, but must not bypass session-close checks in arm/publish.
5. Session close is a release/acq_rel revocation. A writer that already acquired permission may finish using the retained mapping; this is not unmap permission. Later arm/publish declines. Owner entries are never cleared. All payload readers in the parent wait for every writer/descendant to quiesce, snapshot/hash, and only then release their mapping and unlink the parent-owned object.

Native READY is distinct from mapping state2. A crash between CLAIMED and READY leaves a retained unusable claim, not a slot other workers can recover. This avoids spinning or cross-owner repair. If a later version needs reusable slots or multiple sessions, it needs a separately reviewed generation/drain protocol; do not quietly implement it in these two fixes.

## 2. Publication receipt and one-shot cut consumption

Existing mem.c gc_diag_publish is void; it returns early on coverage/sequence refusal. mark_array nevertheless tests its cached cut and performs the null dereference. ___gc_diag_arm4124 checks only ps and cut range. Closing admission and checking arm are necessary but insufficient: coverage or exhaustion can change before publication.

Proposed internal signature: gc_diag_publish returns a nonzero `___U64` committed sequence and fills a stack-local `committed_cut` integer; zero means no attributable publication. No Scheme allocation/root carrier is introduced. Initialize both results to zero on entry. The local receipt contains immediate scalars only and may not outlive the current call. It is not a pointer loan or evidence for a different record.

___gc_diag_arm(ps,cut) keeps its existing external signature. cut0 cancels. For1..6 require eligible owner, open session, coverage and sufficient remaining sequence; reject without arming on failure. Store a one-shot pending cut bound to that local session/owner. cut1 selects the next admitted CELL stage, cut2 the next admitted HEADER stage;3..6 select the next admitted publication as today. Do not promise a prior complete record for3..6 unless the fixture deliberately established one. Re-arm behavior must be explicit (reject a second nonzero arm until consumed/cancelled); no silent nested overwrite.

Publication order inside gc_diag_publish:

1. Recheck session/owner/coverage and sequence capacity. On refusal return0, leave the carrier untouched and invalidate/cancel this owner's pending test cut with a refusal reason. Do not leave it armed for an unrelated future scan. A nonmatching stage preserves the pending selection.
2. Validate current record before copying into previous. Copy a known complete current into prev; never promote an invalid/partial current as the last complete record. Reserve a new nonzero sequence without wrap. Only then select/consume the matching pending cut into a local cut variable.
3. **Invalidate cur.footer to0 and enforce invalidation-before-payload ordering before overwriting any payload.** Sequence0 is reserved invalid. Use the existing atomic conventions plus a full compiler/CPU fence at this cut until the actual target object establishes a weaker sufficient ordering. This is missing in the lock. cut4 exits84 at its declared pre-payload point, now with current invalid. Previous complete record, if any, remains available.
4. Write stage/site/raw_present/cell; cut5 exits85. Finish payload and write commit_seq; cut3 exits86. Both must leave footer invalid. An equal old footer/old commit must not survive partial payload mutation.
5. Release-store footer=seq; full ordering before the original scanned load. cut6 exits87 here: it is a complete-record control. For cuts1/2 return this seq and the consumed cut only **after** this commit/order point. No injected null read occurs inside the refused path.
6. In mark_array, replace `if (diag_cut == 1/2)` with a check of this exact returned seq and returned committed_cut at the matching stage. Do not use the cached entry cut as authorization. The existing original `obj=*cell` / `head=body[-1]` still executes when diagnostics decline. The test null fault, when armed and committed, remains explicitly labeled a later null-probe fault rather than the original GC load.

Cuts3/4/5 intentionally terminate before a complete commit. They cannot truthfully require “successful complete submission.” Their obligation is an eligible **specific in-progress transaction**, declared cut position, and rejection of that partial record; cut6 and cuts1/2 require a complete commit. Never rename partial controls as completed submissions. No signal-catching workaround is required.

Source-derived negative witness (not an executed native result): begin with cur commit=footer=7 and payload A. Copy it to prev; current code then writes new stage/site/cell B and cut5 exits before commit_seq changes. cur still has7==7 but hybrid payload B/A. A footer-equality-only reader accepts it. After proposed invalidation, the same cut has footer0/commit7 and must be rejected. Even postmortem quiescence does not fix the old acceptance error: it merely makes the hybrid bytes stable.

## 4. Implementation and review order

First header/native fields and begin-setup/close hooks; then setup-time one-use claims; then scanner acquire-only attachment; then arm semantics and publication receipts; then invalidate-before-overwrite and stage-specific cut consumption; finally regenerate/build the same target producer and inspect actual optimized invalidation/commit/load ordering. No Scheme generator change follows merely from an internal scalar publication receipt, but changed header layout requires all affected objects rebuilt consistently. Do not hand-edit generated Scheme C.

Correctness requires all of these together. A guard in ___gc_diag_arm alone cannot prevent a later failed publication. A retained mapping alone cannot prevent slot reincarnation. A returned sequence alone cannot reject cut5 hybrid bytes without invalidation. Cost is a bounded setup-time CAS per owner plus hot-path native eligibility checks and an invalidation fence per recorded publication; measure on one bound producer before making performance claims. No per-cell refcount, new coordinator, collector catch or lifecycle expansion is proposed. This closes diagnostic ownership/attribution conditions only; TFIB causality, interrupt progress and formal lifecycle receipts remain independent.
