# Carrier initialization, cleanup and repeated setup: implementation handoff

2026-10-24. Evidence only. This document gives Grok proposed runtime edits; it does not authorize or implement them in this research turn. Main baseline7c490c3, carrier patch bec577ea and lock `current-lock-scan-carrier.lock.json` are authoritative. Source hashes and the credential index are in the companion receipt. No native execution, runtime/qualifier/history edits, peer operation, commit or push. Recorded8/12 is unchanged.

The static pointer, binding state and fault mode currently survive cleanup/setup; no reset/unmap for them exists in the locked mem.c. Local pstate fields do reset. That combination is unsafe for interpreting reused processor IDs as the same writer. This is separate from the unlocated20-second timeout.

## Closed first implementation scope

Use **one diagnostic session per process**, for the first supported serialized global setup and one VM/pstate incarnation set. The mapping is bounded by sizeof(shared), held until process exit after publication, even on setup or cleanup failure. Later global setup, new VM, and processor-slot reincarnation get diagnostics unavailable; ordinary runtime semantics remain unchanged. Do not claim repeated-session or multi-VM recording support. This deliberately trades a bounded retained mapping and lost diagnostic coverage on unsupported reuse for no scanner wait, no shared-slot ABA and no premature unmap. Tests of repeated setup must show correct runtime behavior plus explicit diagnostic refusal, not fabricated fresh coverage.

This scope needs a setup eligibility decision and first-incarnation owner checks. A second global setup must revoke diagnostic eligibility before any local fields are reinitialized; acquiring an old READY state alone must not admit it. A reused VM-local processor ID is not an ownership token. Claim each supported slot once with a native owner/incarnation identity prepared outside scanning; subsequent owners decline diagnostics. Do not use a potentially invalidated pstate address alone as the identity. If implementation omits these checks, restrict acceptance to fresh-process, no-resize, single-VM controls and mark repeated setup/reuse controls uncovered.

Concurrent or recursively re-entered host setup remains outside the existing serialized API contract. Do not bolt a diagnostic mutex onto the scanner and call the runtime API concurrency-safe. If a hook invokes a second setup during preparation, the diagnostic helper must return unavailable immediately without touching the initializer's resources; this does not authorize recursively entering the remainder of ___setup.

## Proposed functions and exact edit sequence

Names below are proposed, not existing symbols.

1. mem.c / internal mem.h: replace lazy `gc_diag_bind_shared` and `gc_diag_note_fault` responsibilities with `___gc_diag_prepare_once()`. State remains process-native: UNSEEN, PREPARING, READY, DISABLED/CLOSED, plus mapping pointer/length, immutable parsed mode and session eligibility. One CAS claims UNSEEN->PREPARING. A loser returns unavailable immediately; no spin. Parse config into local variables, validate the complete header, and only then assign shared pointer/mode and release-publish READY. A reader's acquire READY is the only permission to read either payload. Remove the earlier independent fault_ready claim-before-payload race.
2. Call prepare from setup_os_and_mem after successful ___setup_os and before ___setup_mem. Diagnostic refusal does not replace the runtime's err, skip memory initialization, or change its cleanup branch. Prepare invokes no Scheme/host callback, GC or barrier. Missing config is terminal unavailable for this process, not a later scan-time retry. The parent header is immutable after READY; child never creates/truncates/unlinks the object.
3. Track acquired fd and mapping in **local preparation ownership** until publication. Split fstat failure from short-size reporting: current combined branch may read uninitialized st_size when fstat failed. MAP_FAILED is never dereferenced/unmapped. On prepublication failure, close owned fd and unmap only a successful local mapping. If resource release has an unknown result, retain a diagnostic failure record and do not retry an uncertain/reused fd number. Do not create a READY session from partially cleaned state. Published mappings are never rolled back/unmapped by the setup error path.
4. Add proposed `___gc_diag_close_session()` at accepted cleanup after the existing admission checks (after close_cleanup_sfun_vms succeeds, around6285), and on failed setup after preparation. Close only revokes future diagnostic admission via atomic release/RMW; it does not wait or unmap. Existing writers that acquired permission may finish into retained storage. It must not return early from GC or change the runtime failure code. Paths that fail before setup_state1 require an explicit close call, because ___cleanup_checked may no-op there. Repeated close is idempotent. A later setup must not reopen/reset the consumed session, even if cleanup_phase is reset to0.
5. Refactor `gc_diag_bind_owner:4007` into bounded acquisition/owner validation only. No note_fault, getenv, shm_open, fstat, mmap, fprintf or state1 loop. Initialize private storage as today; acquire-load state once. PREPARING/disabled/closed/reused owner means skip **diagnostics only**. Never set attached1 before a valid terminal decision, and never treat private fallback as shared-control coverage. Set shared pointers only after matching the eligible session and native owner. Do not reset a shared seq or claim an old slot because owner_id equals VM-local id.
6. `gc_diag_publish:4046` should return a native publication-success token/boolean, without allocating. Gate cell/header/split injections on actual eligible committed publication (split deliberately stops at its declared incomplete cut). Current unconditional null probe can fire even when publish returned early; that is an unattributable failure. Mark_array must always continue the original scanning/barrier flow when diagnostics are unavailable. Local depth/coverage and shared evidence must distinguish refusal from a complete record. No general collector or lifecycle protocol change is needed for this diagnostic correction.

Closing admission does not invalidate a pointer already acquired. Storage retention makes that safe without adding per-cell reference counts. It does not make current prev/cur overwrites safe for a live reader; the parent must read after **all writers** quiesce. Parent owns object unlink and final reader release, after raw snapshot/hash. Child owns only its mapping/fd, never object deletion. A child crash leaving a live descendant is not quiescence.

## Failure cleanup controls to retain

No configuration; malformed nonce; shm_open failure; fstat failure versus short object; MAP_FAILED; header mismatch; success followed by global memory failure; module/VM failure after setup_state1; cleanup refusal; accepted cleanup with retained failure; normal cleanup then another serialized setup. Each records acquisition cut, terminal state, fd/mapping disposition, ordinary runtime return and whether any shared writer was admitted. No config or bad nonce must not start scan-time retries or fire configured faults through private fallback. A second setup cannot reset old footer/seq/owner fields. Unknown release results retain resources rather than claiming cleanup completed. These are acceptance requirements, not executed tests.

## Credential lookup and the20-second control

The follow-up indexes retained spawn request.json files, including native gsi argv and associated state-record references when present. Exact marker search excludes Grok prompts and model names; prior broad carrier matches included those and were not native evidence. The index does not prove environment, image digest, budget or last progress: request.json stores argv, while task state stores argvSha256/cwd/event and process evidence. A generic Python harness can carry environment/config outside argv. Inspect its retained script and output receipt before concluding no such run exists. Nothing here reconciles or modifies another role's state.

For each candidate, join request token -> birth/exec-intent -> .state/task-processes/task/run/token -> owning task/work-process run output -> retained stdout/stderr, fixture and raw carrier. An executable path reused across generations is not the d03 image identity. Require SHA d03d6e26 and UUID E2BB92CC for B, or clearly label a different image. Preserve missing/quiescence-unknown outcomes rather than obtaining a substitute by rerun.

Grok execution order, after legitimate exclusive custody and the actual source delta:

1. Bind the original B fixture bytes, argv, environment, cwd, exact actor topology and20-second receipt. If not recovered, comparison to that original lane is BLOCKED; a new fixture may be labeled a separate control only. Do not invent original argv or infer two processors from “two workers”.
2. Build C once and freeze its lock, generated header, mem.o/archive/gsi hashes and image UUID. Record B->C source delta. No relink between control rows. Existing framework.execute receives the recovered literal argv/cwd/env, `seconds=20`, managed process metadata and owned output; do not change Recipe/qualification semantics or turn signal controls into ordinary success.
3. Parent prepares the same-layout carrier/nonce before spawn. Native sidecar records PREPARE_ENTER/terminal and each actual actor's owner binding, GC entry/return and fixture return. Collecting progress must not depend on a Scheme thread that needs the paused cohort. No per-cell logging, extra waiting mutex or new coordinator. Native20-second cap includes the same command interval as B; no preparatory delay outside it that hides previously charged work.
4. Two-worker pass requires both intended independent owner slots, completed GC and worker joins, raw exit0, timeout=false, reaped parent and group quiescence, valid snapshot identity/coverage. Two occupied slots alone fail this standard. Completed binding with missing GC return rejects a binding-only explanation. Completed workers with a stuck harness locates a different failure boundary.
5. On the same C, run scoped no-config/bad-nonce/partial-init/cleanup/repeated-setup controls and normal/null/split survival controls with their real exit/signal interpretation. Repeated setup after a clean first session must decline old recording and preserve old bytes. Fault-mode refusal must not cause an unrelated null fault. Null probes remain carrier-survival controls; original cell/header fault attribution additionally needs actual original-load operand/PC evidence.

Passing this closes a diagnostic initialization/control gap only. TFIB corruption and request-delivery hang remain separate until their unchanged real failure reproductions provide causal evidence. No9/12 claim follows from this handoff.
