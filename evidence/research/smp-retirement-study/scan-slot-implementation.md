## Bounded choice: no in-run slot recycling

Use one fixed-size shared artifact owned by the existing harness. Slots are never reassigned within that artifact's run, even after processor/VM cleanup. Repeated setup/incarnation needs a fresh slot. Capacity/identity/sequence failure disables diagnostic attribution and leaves original GC execution and error semantics unchanged. It must not wait, grow, raise a Scheme error or silently fall back to global/private records.

This explicitly answers cleanup/reuse: cleanup detaches a local non-owning view, **not** the historical slot's ownership. Physical storage may be reused only after the old artifact's writers and readers are finished and a new artifact/run identity is established. A new incarnation is not permission to overwrite unread old bytes. This intentionally trades bounded capacity for a much smaller ABA argument; dynamic reuse or live snapshot readers are outside this cut.

## Exact claim, collector admission and cleanup order

1. **Harness artifact:** create/sizes/map before exec; retain reader mapping. Child opens/maps that same object before diagnostics attach. No inherited virtual address through exec. Missing/mismatched artifact disables coverage; do not alter VM startup success merely to enforce diagnostics.
2. **VM5126/5261 attachment:** setupVM5261 only attaches a non-owning validated artifact descriptor. setupP5126 starts with a null local handle before early returns. Allocate a unique diagnostic pstate-instance token outside scanning; use a nonwrapping allocator and verify explicit VM identity. Bounded scan of FREE slots outside collector hot path: CAS FREE->CLAIMING, acq_rel success/relaxed failure, no spin on occupied entries. Initialize IDs/zero bank footers/next_seq only inside this new slot; release store READY; publish the local handle after initialization. Partial attach/setup failure retains the consumed slot instead of returning it to FREE. Existing initialization unwinds are unchanged. Slot capacity affects diagnostics only.
3. **Native binding:** real worker/P0 entry claims an unbound registration once, writes native owner identity, release-publishes native_bound. A competing bind is not permitted to rewrite an already published identity. Reentry while binding is incomplete is unavailable, not a wait. Claiming and native binding use only target-proven lock-free aligned atomics; unsupported targets disable diagnostic mode rather than calling a lock helper while collector locks are held.
4. **GC7776 entry:** acquire-check READY, immutable identity, native_bound and current registered native owner. Copy the slot view to the local GC activation; CAS active0->1 with acquire semantics, no retry loop. The owner then alone uses next_seq/context/banks. A failed active CAS sets sticky REENTERED/OWNER_CONFLICT coverage using an atomic operation and leaves original GC execution alone; it writes no record payload and never releases another invocation's guard. A plain depth counter shared between competing writers is not a replacement. An inherited local admission flag must explicitly propagate to scanner calls: rejected nested GC must not reuse the outer activation's diagnostic authorization.
5. **Normal collector return:** after the last scanner/record use and on every actually reached return path, owner release-stores active0. A longjmp/fatal fault may bypass this. Do not add a catch/finally to make the guard look clear. After process-group quiescence, active1 is compatible with an interrupted valid last record; active is not a substitute for a live-process test. Sticky conflict/coverage flags remain and may prevent attribution. An unavailable attempt is not repaired by clearing flags at next GC entry.
6. **cleanupP5673 / cleanupVM5691:** use existing caller quiescence/admission preconditions, not a new wait. When writer completion is established, transition that slot to RETAINED and detach its local view. Never clear banks, reset sequence or make it FREE. If active1/writer completion is uncertain, preserve the slot/backing and report incomplete diagnostic closure; do not spin, add a cohort wait or claim runtime lifetime is repaired. Child mapping is not detached while any local writer may still use its copied view. Existing cleanup may still have independent bugs; this diagnostic rule does not certify it. cleanupVM's existing P0-only cleanup call5717 is not proof every worker has detached.
7. **Last release:** after registered group is quiescent and no outside mapped writer exists, harness reader copies the raw artifact, validates status/records, writes immutable snapshot+identity+hash, and finishes all readers. Only that owner may then unmap/close/unlink the backing artifact. A crash does not execute runtime detach, so no detach ACK is required to read a faulted process's bytes once quiescence is established. Reusing the physical bytes starts a new object/run nonce after this final release, never by resetting an old slot in place during execution.

READY and active are separate: READY publishes a fully initialized slot; active authorizes one collector activation's writes. They are diagnostic admission, not new VM execution/GC participant states. No scanner lock or callback is added. A pstate memory address or processor index alone is not an incarnation identity.

## Local context and the two-bank commit

Remove all globals3883..3885 and global records3899; change publish3901 to consume an explicit admitted view and context/attempt, never process globals. Preserve the existing PSP/PSD calling convention in both debug3951 and normal4170 wrappers; pass __LINE__ as data instead of storing it globally. Keep the same original scan operations, tag rules and write barriers.

Direct callers keep their role/site as invocation-local values: continuation/frames4174/4337/4418, actual RC `&h->data`4489ff, scan/pair4718 and registers/saved/global/will paths enumerated in the companion29-call table. Frame origin comes from the frame caller; a raw return-address guess is insufficient. `parent` resets at3995 for each outer cell. Before words is consumed by copy4104..4107, retain the already-read containing header and its original extent; tail4123 updates local current parent/span/index without overwriting the original entry origin. Pair fast scan bypasses generic scan and needs its own local role. Never reread a suspect header just for the context. Context bits are observations, not extra roots.

Pass the nullable admitted activation through the actual helper chain, rather than adding a pstate-global pointer to a C stack local: GC7776 -> strong7647 / weak7710 -> root markers7304/7319/7334/7349/7366/7384/7457, mark_reachable_from_marked7473 and process_wills5787 -> scan_still_objs_to_scan4757 / scan4521 / pair macro4718 -> mark_array body/debug and frame/continuation/RC helpers4174/4337/4418/4489 -> publish3901. A rejected nested invocation passes null on its own chain; it does not inherit the outer admission from ps/TLS. This requires diagnostic argument plumbing through these existing C helpers, with null outside the authorized collector path. Keep mark_array wrapper argument evaluation and PSP expansion correct in both configurations. The companion table lists all29 direct call sites; no caller may fall back to the removed globals. This is explicit C instrumentation plumbing, not a new activation journal or Scheme GC root.

Keep the current unsigned sequence type only with an explicit checked limit and actual ABI width. Reserve **two** consecutive commit values before beginning an attempt, since a pointer cell may need CELL_PENDING and HEADER_PENDING. If `next_seq > UINT_MAX-2`, latch EXHAUSTED and record nothing further; do not wrap, reset at new GC, widen to bignum or borrow a previous incarnation's sequence. Reserve even if the cell proves immediate and uses only one publication; gaps are legal. The same attempt token connects its two stages; commit values differ. All other sequence/context counters also need checked exhaustion or must derive from this bounded attempt token. This is not the64-bit standalone control's ABI; test the actual emitted footer width/alignment.

Use two banks instead of `gc_diag_prev = gc_diag_cur`3929. While overwriting the nonlatest bank, the other complete bank stays untouched. First invalidate the selected bank's atomic footer and **prove invalidation visible before any payload overwrite** with compiler/target ordering; source order or release invalidation alone is not sufficient for following stores. Then write complete local payload and commit_seq, release-publish its footer, enforce the actual full barrier before the original load, and advance owner-local bank selection. HEADER_PENDING uses the cell word already read at4003, then original head at4021. There is no normal 'finish this bank' epilogue required after the faulting read.

The inactive-bank invalidation is part of the existing bounded record's completeness, not a live-reader protocol. Without that ordering, a fault during overwrite can leave an old nonzero footer over new partial payload. A previous valid record does not by itself identify a later incomplete fault attempt. The reader chooses the latest validated complete version only as an observation and requires exact fault PC/stage/attempt/context to attribute it. If newest overwrite or coverage is uncertain, return UNKNOWN rather than backdating the fault to the previous bank. Do not add a live seqlock reader over plain payload or count invalid records as complete.

## Grok implementation order and minimum native checklist

Implement in this order on one registered producer: (A) nullable native views + isolated slot claim/registration, (B) explicit local scanner context and checked two-value reservations, (C) two-bank completeness and shared reader-owned backing, (D) compile/preprocess/disassemble exact object and link B, (E) following bounded controls before original TFIB. No catch, heap-floor increase, per-cell mutex or full inventory is needed. Request-ID/SMP generation remains a separate lane and must not be smuggled into this patch.

| Native control, all on same B and original bounded runner | Required observation | Reject / preserve |
| --- | --- | --- |
| Two actual native workers concurrently scan distinguishable test roots | Distinct slots/native tokens, correct per-attempt cell/raw/header/context, no cross-owner sequence or payload | Any mixed record/duplicate owner is diagnostic failure, not a valid TFIB witness |
| Same-owner attempted nested collector/recorder authorization | Exactly one admitted activation; nested attempt latches coverage and cannot write payload or clear guard; original control result unchanged | No wait/recursive lock, no successful attribution across known coverage loss |
| Seed next_seq near actual maximum before launch | Last complete pair possible; next reservation refuses before any wrap; previous bank retained | No sequence0 reuse or reset on later GC/setup; no changed GC outcome |
| Controlled partial write after bank invalidation, during payload and before footer | Overwritten bank invalid, other bank intact; reader does not invent a fault from the older attempt | Check actual emitted invalidation-before-payload ordering; no assumptions from the old20 controls |
| Clean up pstate, initialize another at same address/index | Old slot/records unchanged and retained; new instance gets fresh slot/token; exhausted capacity disables attribution | No in-run reassignment, zeroing or alias by pstate address; no original startup refusal for diagnostic exhaustion |
| Normal child exit; then deliberate actual cell and header faults | Reader mapping survives each child, original fault PC/owner matches B, HEADER has actual first word; CELL has no raw | No atexit/catch/stdio flush dependency, no reused old mark_array+104, no private static fallback |
| Child faults with active1; another declared child/descendant still writes | Reader waits for actual all-writer quiescence; after quiescence interrupted guard itself does not force a false 'still live' claim | Reaping only direct child is insufficient; unknown outside writer means no read/release |
| Partial setup/native-bind failure and wrong object/nonce/size | No uninitialized handle use; consumed slot retained/coverage unavailable; existing cleanup behavior and error unchanged | No slot reclamation/free transition, repeated initialization clearing old evidence or anonymous pointer-through-exec |

Record binary SHA/UUID, exact generated/preprocessed C and object hash, all compiler flags, atomic width/alignment/lock-free evidence, shared backing identity/size/nonce, native actor mapping, per-control real status, quiescence and raw snapshot hash. This document does not invent currently absent diagnostic CLI switches. Grok should place these cases in the existing registered native lane and retain its original caps/receipts; native cases above have **not** run here. Passing QNT or independent assembly is not an alternative receipt.

Then run original TFIB15/5000 with the same B and accept only the first valid cell/header context for choosing the root/map/bounds/write repair. This closes the finite diagnostic implementation boundary. It does not itself solve TFIB or9/12, and does not justify another protocol expansion.
