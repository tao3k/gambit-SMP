## Decision and immediate priority

The drain-before-GO contract is **not presently a demonstrated causal fix for either TFIB SIGSEGV or the retained result-mutex hang**. Its guarantees concern a collective/member/channel lifetime cut. The failing header load and pending Scheme request are different concrete transitions. A common GC/ownership cause is possible but not established by the retained data.

Freeze protocol scope. The next implementation effort should obtain the first invalid scan context and one blocked sender's request lineage on one bound diagnostic producer. Use those witnesses to choose the relevant existing repair surface. Do not make completion of a broad retirement/reaper rewrite a prerequisite for investigating these two failures. Do not repeat a full inventory or add another generic barrier/heap floor/select tweak to obtain a nicer pass ratio.

## Discriminating QNT, not a larger handoff protocol

`models/gambit/repair9_causal_projection.qnt` assumes drainComplete=true in **every** state. It deliberately asks whether the original failure classes can still occur under that strong assumption. The GC projection models root relocation and post-GC reload, intact scalar skip, frame-selected scalar, polluted heap field, mistyped scalar container, escaped extent and missing provenance. The payloads/writes are conditional hypotheses, not generated C executions. The classifier uses actual modeled cursor/layout/extent/metadata, not the scenario label; a scalar-like word alone cannot prove F64 origin or a first writer.

The request projection has concrete two-node next/head/tail append/pop mutations, detached dispatcher ownership, masked park and terminal reply. It compares tail guard/wake-only/thread-only against unique-link plus native return. Every counterexample still has drainComplete=true. No new runtime mechanism is prescribed by those scenario initializers. `nativeReturn` models an eventual independent native return, not a timer/selector implementation or its real deadline. Normal and dispatcher positives assume finite callback and fair service; CallbackNoReply explicitly violates that termination assumption while preserving ownership.

Controls are independently decoded against each invariant. The strongest useful conclusions are **non-implications**: drain safety does not imply GC cell validity or request delivery; a root fix does not repair a bad map/earlier write; a wake does not repair a lost node; empty queues do not imply lost or completed request. RootFixed demonstrates value for its actual stale-root premise; UniqueAndReturn demonstrates conditional delivery for the small queue/park projection. They do not identify the original first writer, prove corrected-source duplicate reachability, certify all callers/11 workers or prove the C memory model.

## Independent conclusion

There is no justified single-cause attribution yet. The latest drain refactor has specific preventive value, but the missing TFIB origin and missing request R are what block a causal repair claim. The next work is targeted diagnosis and an evidence-selected source cut, not a wider protocol. Maintain the original DENY and8/12 while those witnesses are absent. This report narrows the handoff implementation's claimed benefit; it does not enlarge it.
