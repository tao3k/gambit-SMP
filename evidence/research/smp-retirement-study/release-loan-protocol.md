## Independent conclusion

One atomic exchange of the release function is insufficient. It can prevent duplicate callbacks while still freeing a pointer inside another processor's C call. A pointer loan without invocation-scoped unwind cleanup is also insufficient: a later argument conversion, nested Scheme callback or supported nonlocal return can abandon the loan. Finally, a C call can return an alias or save a pointer; ending the input loan at C return does not establish that the native resource has no remaining consumers.

The required unit is a shared, per-wrapper resource descriptor plus checked invocation scopes and explicit exported loans. Keep the resource owner until both the release action and every admitted pointer consumer have resolved. The descriptor must integrate with the existing VM admission/cleanup ledger. Do not identify resources by raw address: the documented at-most-once rule is per foreign wrapper, and two wrappers can intentionally represent independently reference-counted ownership of the same native pointer.

## Descriptor and lock/memory-order contract for implementation

Proposed fields (names are recommendations, not claims they exist): full VM K and resource generation; native `ptr` and `release_fn`; callback class and module ownership; one aligned atomic `phase_and_loans`; typed rooted owner/journal handle; accepted release intent and outcome; exported-token generation; retained/unknown-side-effect disposition. Stable descriptor lookup must itself hold the existing VM registry/admission reference before dereferencing the descriptor. A stale wrapper/token must not dereference freed native storage to test its generation.

Use the initially conservative sequentially consistent operation on the combined phase/count word. `LIVE(n) -> LIVE(n+1)` is the linearization point of borrow; the returned pointer is loaded only after that succeeds. Never implement check-LIVE then separately increment. Close is `LIVE(n) -> DRAINING(n)`; claim is exclusively `LIVE(0)` or `DRAINING(0) -> CLAIMED(0)`. Publication initializes payload/key/roots/module before opening the descriptor. SC does not repair unsynchronized public-field readers: migrate or give those reads a separately defined synchronized status representation. Do not blindly make existing foreign Scheme fields C atomic without checking layout, GC and ABI.

A loan ends after its last actual native access and ownership transfer, with an RMW on the same word. Claim therefore observes all prior borrower completions. Payload disarming/public released status must be published consistently with claim and observed by all readers; callback invocation follows a winning claim, after releasing descriptor locks. Audit weak-memory implementation/architecture builds before reducing ordering to release/acquire. The QNT checks transition atomicity, not C11 compilation or hardware ordering.

Suggested helper responsibilities:

1. `foreign_scope_enter(K, invocation_id)` acquires a checked existing VM/run authority and creates a nested loan-journal boundary. No T/P/descriptor lock may span a Scheme callback.
2. `foreign_loan_acquire(scope, wrapper, expected_generation, out_ptr)` validates live descriptor, atomically increments before pointer exposure and records a unique loan nonce. Prefix recording must not fail after acquisition without compensating release. Registration storage/root capacity is reserved first.
3. `foreign_release_request(desc, origin)` shares the claim for explicit release, deferred will and VM preparation. Claim is per wrapper, independent of consuming a will action. A failed claimant never invokes the callback.
4. `foreign_scope_unwind_to(boundary)` ends only the loans belonging to crossed invocation frames, exactly once. The current frame's wrapper/tag/carrier roots remain valid through decrement/status writes. Nested callback return must not consume outer C loans.
5. `foreign_loan_export(scope, loan, out_token)` creates a child descriptor loan and persistent VM/module ownership before the source loan ends. Its key/nonce release is exact-once. A result alias requires this or a proven independent native reference; pointer equality does not prove either.
6. `foreign_loan_end(token)` records completion without running arbitrary release code. If DRAINING reaches zero, preserve ready debt and notify the existing safe executor. A missed hint cannot discard accepted ownership.
7. `foreign_scope_leave` happens after R_ALL, conversion/error propagation and the last `ps`/marker/native-return consumer, under an enclosing authority that remains valid through the helper's own final access. No read of descriptor or VM after its last reference decrement. Cleanup waits for resource pin, scopes, exported loans, callbacks and native return tails using the same admission ledger.

These are multiple inseparable implementation surfaces; an atomic-release-only patch is not the proposed repair.

## Release origins, failure and roots

| Interleaving / outcome | Required behavior | Last owner |
|---|---|---|
| Explicit release with outstanding loans | Return a documented BUSY/refusal without disarming or silently scheduling release; never wait for the current invocation's own loan. A native call may reenter Scheme and request release of its argument. | Existing wrapper resource pin and borrowers. This is an explicit compatibility addition, not a fake NO_ERR. |
| Will or VM-preparation accepts release with outstanding loans | Persist a rooted release intent, close new loans, drain existing ones; only the valid executor claims/invokes when zero. | Descriptor resource pin + preparation job until completion/retained outcome. Will eligibility keeps existing weak-selection semantics. |
| Explicit release races selected will | Both route through same claim. Public repeat release remains a no-op after consumption; it does not clear an internal error/debt. | Winner callback/job; loser preserves independent strong roots and consumes only its own action. |
| Callback returns non-NO_ERR or escapes after possible destruction | Public payload cannot be restored/rearmed; keep outcome/descriptor/VM debt. Do not retry an unknown callback, assume resource still exists, or release the VM merely because address==0. | Retained fault/preparation owner; declared terminal policy for unsupported native unwind. |
| VM close races an already admitted FFI scope | Close VM admission, then per-resource draining; scope acquires and pins resource before close or refuses with prefix cleanup. No release/reacquire gap between parent and child units. | Existing run scope, resource/job pin, exported loans. |
| Borrower does not return / exported token never released | Retain/quarantine resource and VM generation. Deadline expiry reports unresolved ownership, never revokes a live C pointer. | Borrower/export owner; no unconditional completion proof is possible. |

Generated Scheme roots and native loans solve different problems. The wrapper/tags/current continuation and typed journal carrier need mapped roots or existing still/RC paths through GC; the native payload/module need counted lifetime. An integer address is neither root nor loan. The new mapped driver must show executed W_ALL/R_ALL, frame descriptors and nonlocal-return coverage, not merely PW_ALL declarations. Existing immutable `_thread.c` READY evidence is not evidence for a new foreign scope frame. GC must update actual rooted Scheme fields; never cache movable SCMOBJ in an unregistered native journal. Invocation IDs/generation/nonces are native identity, not pointers into fromspace. The model assumes these root invariants; it does not validate frame maps.

## Escaped address support boundary

`foreign-address` continues to mean a numeric address snapshot. A Scheme reference can prevent GC selection of that wrapper but cannot prevent a concurrent explicit release. No runtime can discover arbitrary copies of an integer, native global, pointer arithmetic or a host longjmp that bypasses its ABI. Thus transparent safe revocation of every historical `foreign-address` user is not a sufficient or achievable promise.

Supported asynchronous retention requires an explicit exported loan/native reference protocol and explicit final release. A host-managed independently refcounted pointer can use that native contract if ownership is documented and the callback/module lives long enough. Uncooperative raw pointer retention remains outside the checked API's safety guarantee; quarantine/retention is the safe response to a known unresolved loan. Do not silently infer an exported loan on every numeric address read (unbounded invisible lifetime), or silently keep every foreign object forever. Wrappers sharing an address require explicit shared control ownership or independent native retain/release; address deduplication changes valid programs.

## Model, negatives and proof boundary

`models/gambit/release_loan_composition.qnt` composes two independently admitted C calls, one shared resource claim, explicit BUSY, deferred close, VM admission closure, result conversion, scoped error/unwind cleanup, an exported alias, retained callback error and VM return tails. Six candidate initializers run the same nondeterministic transition relation. Export can occur before or after VM closure while an admitted loan still exists. Four existential target observers establish representative export/BUSY completion, prefix failure cleanup, supported unwind cleanup and retained-error states; these are not fairness or termination proofs.

Twelve mutants distinguish claim-with-loan, early loan-end while C still uses pointer, dropping VM scope before tail, abandoned argument prefix, alias without child loan, duplicate release, retrying consumed unknown callback, unsupported raw use after release, check-then-borrow, nested unwind consuming another frame, stale duplicate token and last-loan release running a callback without a valid executor. Several mutations record a bad event directly where concrete fields do not represent context/ABI; these check the stated protocol prohibition, not discover a C defect. Raw-use negative is deliberately a client-contract counterexample, not a promised runtime interception. The stale-token negative exercises duplicate final decrement in a bounded generation; full old-VM ABA remains the separate full-K model's obligation, not a new proof here.

No new root scanner, actual C atomics, arbitrary nested FFI stack, alias inference or fairness is proved by this finite model. Internal close may safely retain forever; completion requires borrowers to return, exported owners to release, executor service fairness and callback termination. More elaborate forced GC does not remove those preconditions.

Update `type-needs-cleanup?`, `c-make-function`, `build-c-lambda`, conversion/body/error/TRY/SFUN boundaries together; regenerate exact C. Show the prefix failure and nested callback paths, code/module lifetime and all return tails. Preserve legacy no-op `release_pointer`; require migration/refusal at unscoped old C entry points.
4. Add explicit exported-loan token/alias transfer. Audit `##foreign-address` users and `##init-mod` bypass separately. Decide host compatibility before claiming transparent correctness.
5. On that same final producer run deterministic targeted controls: two processors hold pointer use while explicit release reports BUSY; nested C->Scheme self-release refuses without deadlock; explicit/will/VM-close claimant races invoke once; second-argument conversion failure; result-conversion allocation with forced GC; struct/union/type copy; nested callback and supported throw drain only crossed scopes; exported alias survives parent return/VM-close until release; stale/duplicate/full-K token refusal; error after native destruction is retained/no retry; module unload refusal while callback/native call remains. Validate actual root relocation and last-tail access, not banners alone.
6. Reconcile per-resource/per-VM counts and allocation/destructor events at each pause; cleanup must refuse while any known consumer remains, and proceed only after exact final consumer release. Include bad-context refusal before payload access, known BUSY retention under inherited deadline, and declared unsupported raw pointer misuse as negative controls. Do not enlarge timeouts or replace real failure with a model boolean.
7. Revalidate affected front-eight bootstrap/GSI/GSC/PR/stress/registry contracts on the accepted producer before full native claims. Focused loan tests do not close lifecycle 9/12, complete GC/FFI, Gerbil TYPEID or performance. This turn runs no native tests and changes none of their predicates/receipts.

The remaining closure requirements are concrete: descriptor/root/ABI design approval; complete caller migration including direct raw dereferences; generated C supported-unwind implementation; actual stable-descriptor C11 ordering and old-token rejection; same-producer fault/root/native evidence. Until these exist, this is an implementable research contract with conditional model controls, not a claim of a fundamental runtime fix already delivered.

## Cost and evidential limits

A straightforward implementation adds descriptor lifetime RMWs at acquire/end per converted foreign pointer, plus invocation/VM entry and exit bookkeeping when no enclosing checked scope can be reused. Several arguments referencing the same wrapper may initially take separate loans; coalescing requires a journal proof and is not needed for correctness. A hot wrapper's combined word can contend across processors. Callback execution is off the locks, no borrower spins waiting for its own callback, and persistent export costs apply only to opted-in retention. These are structural costs, not measured performance results; generation checks, GC roots and module pinning cannot be removed to meet a throughput target. Any reused outer VM scope must keep continuous ownership through all nested invocation tails.

The observed unsynchronized fields, no-op release_pointer, absent pointer cleanup selection and raw-field bypass are source facts. Whether a particular legacy concurrent release program is supported is a compatibility/specification question. They do not establish the cause of the historical TFIB SIGSEGV or thread-interrupt hang, nor prove that those failures disappear with this protocol. This work identifies necessary conditions for concurrent foreign lifetime safety; it does not justify calling one new atomic field a sufficient 9/12 repair.

The descriptor's initial native ownership pin must not create a hidden strong Scheme reference to the will testator before weak selection. A live pointer invocation legitimately roots its wrapper through the mapped journal; after weak selection or accepted VM preparation, the job owns the required typed carrier. A native descriptor with only key/weak identity is not itself a GC root. The implementation must distinguish these lifetimes rather than solving native retention by permanently rooting every foreign wrapper.

The combined graph has two independently owned scopes, not an implementation of the recursive C/Scheme stack. Its wrong-frame negative checks the prohibition on consuming a different scope's loan; actual nested-frame ordering and marker-unwind coverage remain required generated-C/native evidence.
