# Lock-main run finalization, sender ACK disposal and generated roots

This is a source-bound research and implementation handoff, not an applied runtime patch. This audit changes evidence and Quint only. Its restrictions do not prohibit Grok from implementing the explicitly listed dependencies in its own authorized production custody. Native admission remains false; the previously recorded count is 8/12. No qualifier, Recipe, historical receipt, runtime or other-thread state was changed.

Three conclusions follow independently of a model PASS:

1. `___run` has a supported outward-error path that bypasses its marker kill. Its allocation and body are inside TRY, and kill is inside the same TRY. `___call` rethrows errors and unmatched unwind destinations. This is a concrete cleanup gap in this source slice, not a demonstrated cause of TFIB or interrupt hangs.
2. ACK alone is insufficient permission to unlink a B-owned RC cell. `mark_rc` saves `next` before scanning `h->data`; `___release_rc` changes adjacent links and frees `h`. Receiver-root publication, native-owner authority, scanner exclusion and final reader grace are different facts.
3. The archived `_kernel.c` is not evidence of regeneration from the patched Scheme. Its wrong-processor branch passes one argument, while the patched Scheme preserves the result in R2 and passes two. A real build may regenerate; this mismatch does not establish that any particular gsi used stale C.

Suggested helpers are new implementation names, not existing symbols: `___run_entry_begin`, `___run_marker_prepare`, `___run_entry_finalize`, and `___run_entry_leave`. Finalize is idempotent per full VM/owner/activation key; it performs no Scheme allocation, arbitrary callback, wait or remote longjmp. If a loan release needs Scheme work or unknown host effects, enqueue retained debt instead of executing it in this epilogue. A `volatile marker` only fixes the setjmp local-value rule; it does not provide admission, recursive saved-root ownership, GC scanning or the native tail.

Order: capture error after END_TRY restores the outer catcher; finish crossed-frame journal work with the context still pinned; invalidate the marker and decrement its still reference exactly once; restore owned root/binding tokens; complete the final ps/status accesses; drop the native entry token last and immediately return. Copy any status needed after the last decrement before that decrement. The decrement helper itself must finish its own descriptor accesses before publishing that the last consumer is gone. Retained completion roots have an independent domain token, so leaving the native run cannot free them.

The two observed callers need different tails. `setup.c:7488 ___setup` calls `___cleanup` on error after `___run` returns; cleanup must reject outstanding domain/loan consumers rather than free them. `setup.c:1006 ___run_and_throw_error_on_processor_0` reads scheduler status, publishes the error collectively, then loops forever at `1034 service_sync_op`. Its outer processor/native lifetime must survive those later ps accesses; a run-entry token is not permission to destroy the processor on return from `___run`.

## B-owned ACK disposal: exact service boundaries

Proposed completion record fields: full VM incarnation, native owner incarnation, activation/request sequence, carrier owner, `PUBLISHED / RECEIVER_ROOTED / ACKED / DETACHED`, sender-domain token, scanner-reader generation, and one-shot detach claim. These belong to stable metadata, not to a returned B stack. The rooted value is stored in B's actual `___rc_header.data` until B unlinks it. Native control atomics are not a substitute for scanning this cell.

1. B registers its carrier on B's RC domain before release-publishing the message. A acquire-loads and validates the full key, then copies the current relocated value into A's registered root storage under the appropriate GC exclusion. Only after that publication does A release-publish ACK. A must not cache raw `h->data` across GC and subsequently register the stale scalar.
2. B acquire-observes ACK, validates the key and wins its detach claim. Claiming cleanup is not yet detaching. A duplicate/late ACK has no new effect and cannot release a reused entry. The parent may already have returned; the completion-domain pin remains.
3. Execute `___ffi_owner_drain_ack` (new helper) on the registered B native owner, with no T/P locks, no GC in progress against that RC domain, and no scanner/native reader retaining the cell. Failed admission or busy reader means retained debt, not a wait and not a fabricated ACK completion. Do not substitute TLS/processor id for the owner key.
4. Detach once, call owner-local `___release_rc`, then discard the carrier pointer permanently. Retire the completion entry only after no queue or reader can still reference it; drop the domain/VM token last. Copy status and next-work identity before the potentially final release. Never read the freed carrier to obtain its next item, owner or generation.

The existing `mark_rc` in `mem.c:4405` caches `next` and scans the actual `h->data`; strong-root processing at `7601..7620` scans RC, globals, continuation, registers and saved slots before a barrier. This makes a post-ACK free during that traversal unsafe. The barrier shown is not by itself a public unlink lease. The simplest reviewable first implementation is a collectively selected, bounded owner-service window using the existing collective exclusion, rather than introducing a new lock into every RC link and GC traversal. It has a service-round cost; it must preserve pending requests and allow GC to proceed between bounded batches. A per-domain reader protocol may optimize it later only with a complete reclamation proof.

Use a persistent debt generation and an acknowledged service generation, not a coalescing interrupt bit. After a completed GC, if debt remains, the next common election must reserve a bounded service batch before another resize/GC can indefinitely overtake it; a GC needed to make current roots safe may run first. No member independently enters the window. A batch budget is a work bound, not a widened test timeout. Analytically the cost is one shared election/barrier round plus O(number of ACKs serviced), with constant native bookkeeping per entry; no measured latency or throughput claim is made. A permanently blocked cohort member still prevents this collective from progressing. That case needs the previously proposed pending scan-domain ownership transfer/fault policy and cannot be solved by priority alone.

## Grok implementation order and remaining sufficiency

1. Freeze one lock-derived production identity and the generation chain. Add stable checked run contexts, owner/domain tokens and temporary-root ownership; keep ordinary runs distinct from SFUN counts.
2. Move `___run` cleanup to a common supported-exit epilogue and instrument one-shot marker invalidation, catcher restoration and last-token access. Audit both callers' outer tails. Convert/refuse unsupported host escapes explicitly.
3. Implement receiver-root-before-ACK and owner-local detach claims with full incarnation/activation keys. Keep carriers in an admitted scanning domain beyond native frame exit. Admission close rejects new work while existing ACK obligations remain serviceable.
4. Add bounded Scheme and native collective service paths, including GC-loser debt retention and starvation prevention. Prove T/P-lock freedom and scanner exclusion before calling the existing non-atomic RC unlink. Never wait for a remote ACK from inside a collective.
5. Regenerate with the exact compiler/configuration, decode the actual root maps, and run the targeted native controls on that same producer before any larger acceptance campaign.

The new Quint slice checks run exit/marker/tail, delayed ACK ownership and repeated relocation together. It refines the previous model's atomic `ownerAckFinal`; it is not an executable refinement proof of either C or the complete previous state space. Positive witnesses are reachability, not unconditional liveness. Still missing for closure: actual generated-C maps; the implemented reader/grace and collective service/aging protocol; checked token allocation/wrap/ABA and queue reclamation; allocation-unwind saved-root restoration; supported host-boundary tests; and same-producer native evidence. These are concrete implementation/proof obligations. A model PASS alone cannot close 9/12 or solve the separate TFIB, request-delivery, Gerbil and release gates.
