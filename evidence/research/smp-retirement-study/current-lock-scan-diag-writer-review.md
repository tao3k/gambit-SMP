## New blocking defect: the proposed recorder is multiwriter global state

Patch lines3009ff add process-global `gc_diag_entry_line`, `gc_diag_parent`, unsigned `gc_diag_seq`, and `gc_diag_prev/cur`. `gc_diag_publish` copies cur to prev, increments a plain counter, then writes plain payload fields plus one atomic footer. The original per-pstate strong phase at mem.c7563ff/7768 invokes continuation/register scanning using its own ps; the added recorder receives no ps/owner argument and has no exclusion. There is no established single-writer constraint. SMP workers can therefore concurrently mutate the same record/context/counter. This is a source-level data-race defect in the diagnostic design, not evidence it caused the historical TFIB crash.

An example allowed by the missing exclusion: A begins CELL_PENDING; B replaces global parent/site and begins HEADER_PENDING; A writes footer. The resulting payload/footer can mix distinct cells/actors. The non-atomic whole-struct prev copy can also race the atomic footer and payload writers; it is not a stable previous record. A barrier does not provide ownership or mutual exclusion. GCC's [atomic builtins documentation](https://gcc.gnu.org/onlinedocs/gcc/_005f_005fatomic-Builtins.html) assumes data-race-free surrounding code; atomic footer does not extend atomicity to other fields.

The added unsigned counter has no explicit wrap refusal. It differs from the earlier64-bit control. Entry site and parent are global mutable context rather than values owned by one attempt; moving only cur/prev to MAP_SHARED or making only seq atomic does not repair them. Reentry on one worker still needs explicit coverage refusal or a proven local context discipline; TLS alone would not make nested same-owner overwrites safe. Do not add a GC hot-path mutex to serialize the probe.

## STR is not itself a verdict

Reported ordinary STR footer plus a later DMB before the original LDR proves neither a release-publication failure nor a correct shared-publication implementation in isolation. The producer's complete instruction envelope, exact footer address/width/alignment, earlier stores/barriers, preprocessed macros and actual observer must be examined. A trailing full fence covers the subsequent-read ordering obligation; it is not automatically the independently required payload-before-publication proof for a live observer. Equally, do not label compiler lowering invalid solely because the mnemonic is not STLR/STLUR.

The present carrier is private, lacks a legitimate cross-process observer and already has unprotected concurrent writers. It is not a sound experiment for choosing a shared publication primitive. Do not guess optimizer cause, patch in handwritten assembly or relax the old checker to accept every STR. First implement the already specified single-writer/shared-carrier boundary, then inspect **that** actual object's exact publication sequence. If no actual mem.o artifact is retained, record codegen as reported/unverified rather than reusing independent-C evidence.

## Direct next implementation order for Grok

1. Replace the diagnostic globals with bounded exclusively owned worker/native-owner slots. Pass the actual GC ps/owner and attempt-local site/parent to publish; do not infer them from a process-global most-recent call. Bind VM/slot incarnation and native actor before scanning. Previous/current records and their context versions belong to the same writer. Unsupported reentry, unavailable owner or exhausted/nonwrapping sequence disables attribution explicitly; original collector behavior continues. No new collector lock, callback, allocation or syscall per cell.
2. Put those raw slots in the existing proposed fixed-size task-owned MAP_SHARED artifact. Supervisor creates/maps and retains it; child maps the same object after exec before first write. Pin backing identity/size/schema/nonce, not a pathname or FD number alone. VM cleanup may detach its view after writer completion but cannot clear/truncate the reader's object. The final consumer is the supervisor after actual writer-group quiescence and immutable snapshot/hash. A private static or a child-only malloc can never meet this ownership condition, regardless of DMB/DSB.
3. Recompile through the same registered producer path. Bind candidate bytes, config/preprocessed C, compiler command, mem.o hash, final gsi SHA/UUID and actual disassembly. Verify each payload/commit/footer/fence/original cell or header read and operand. Footer primitive must be proven for its actual width, alignment and reader model; do not prescribe a mnemonic instead of semantics. Capture no new target-header read for logging.
4. Run only owned minimal controls on that B: (a) normal write then process exit without flush/VM cleanup dependence, (b) actual cell-load fault, (c) actual header-load fault after successful cell read, (d) two concurrent workers writing distinct identifiable slots, (e) interruption during next record publication preserving prior complete record or explicit UNKNOWN, and (f) wrong object/nonce, attempted slot reuse/reentry or sequence exhaustion rejected as coverage. Parent reads after every writer is quiescent, not merely after the direct child exits. Never truncate a live mapped file as a test. Existing watchdog limits remain; no new signal handler or catch.
5. Accept faults only with one B identity, correct fault PC/address/native actor, committed matching attempt/context and surviving raw artifact; no mixed-actor record, old+104 assumption or timeout-as-fault. Then run original TFIB15/5000 and stop at the first accepted cursor to choose the root/map/copy/bounds correction. Request-ID work need not block this independent TFIB measurement. Full inventory is premature.

For request delivery, the prior coherent one-thread-inbox plus reliable park/service handoff remains the recommended structural repair, not another catch. Its implementation still needs the immediate nonwrapping ID, actual SMP generation, and node/mutex/result root audit on that producer. The current lock's Scheme unchanged hash0332cfab and old package C do not supply those proofs. A generic exception catcher cannot reconstruct an absent ID; unsupported escape stays UNKNOWN. Do not serialize the diagnostic recorder with the result mutex or keep dead request nodes rooted for logs.

Acceptance order is now finite: isolate writers -> attach surviving carrier -> bind actual object publication -> pass the six bounded carrier controls -> reproduce/classify original TFIB.
