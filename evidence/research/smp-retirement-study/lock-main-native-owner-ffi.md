## Root maps and registered root carriers

Root path in this candidate is explicit: `gsc/_t-c-3.scm:471 targ-build-gc-map` computes bits from liveness; `_t-c-2.scm:299..306` attaches return label kind/fs/link/map; `_t-c-1.scm:1854 targ-dump-prc` emits IFD/OFD descriptors and GC-map chunks; header `9334..9388 RETI/RETN_GET_*` decodes them; `mem.c:4253 mark_frame` scans only mapped cells with mark_array. `FRAME_RA_DESCR` checks return-address tagging when that build option is selected; it does not prove map completeness. `_kernel.c`'s MW/PW_ALL definitions and header `6833..6834` show executed register save/restore macros; a declaration alone is not root publication.

Native C automatic variables do not enter Scheme frame maps just because a journal pointer exists. Use typed registered carriers or generate a real Scheme-visible carrier whose liveness is emitted by this compiler. `mem.c:7220 mark_registers`, `7235 mark_saved`, and `4404 mark_rc` update actual traced storage. GC_SAVE1 uses a bounded ps saved slot; it is not a recursion stack of root sets. Do not keep an entire recursive journal in one saved slot which an inner call overwrites, or restore old scalar SCMOBJ after GC.

Existing RC is owner-local: `mem.c:752 ___register_rc` splices the current processor's linked list without an ownership lock; `789 ___release_rc` does a plain decrement and unlinks through next/prev; `mark_rc` writes back `h->data`, and GC invokes it per processor at7601. These are not cross-native-owner atomics. Native descriptor/control reference atomics do not make the RC header/list thread safe.

For cross-owner result handoff, keep separate sender and receiver registered carriers. Sender publishes an immutable envelope and retains its carrier/domain. Receiver, at its own valid safe context, acquires the envelope, validates full keys and copies the **current GC-updated** value into its own registered cell before ACK. Sender removes its carrier only at the sender's safe point after that ACK. Never transfer one intrusive RC header between two lists or let receiver call release_rc on sender's cell. A pending sender-domain pin remains even after its SFUN/C frame count reaches0; root/domain removal and GC snapshots require the same reviewed exclusion/lease protocol. If sender cannot serve ACK cleanup, retain its domain/debt. This is a new required protocol, not something present in the locked patch.

## Native owner, parent lineage and last consumers

Choose **fixed native stacks with explicit semantic lineage**. A Scheme callback may migrate from owner A to worker B. A's C journal, saved binding, catcher and native frame remain A-owned and paused. A child C call on B uses B's independent local journal; its parent-lineage reference is a stable native descriptor/key, never a pointer to a remote C automatic frame. A VM token includes its incarnation; a native-owner token includes an independently registered OS-owner generation; each activation/marker has a nonce. `pthread_t`, TLS ps, processor number or marker address alone is insufficient because identities can be rebound/reused. This source stores only processor id in the marker.

A native owner registry/control block must outlive lookups and be pinned before ps access. Rooted lineage/envelope pinning must precede release of the parent or sender frame. Existing `thread_init_from_self` in os_thread.c:466..478 records pthread_self, but does not implement this generation-checked registry or authorize arbitrary native entry. A foreign OS thread with no checked VM owner/context should submit a checked request to an already admitted Scheme owner or receive a no-mutation refusal; it must not bind to another processor and invoke ___call/___THROW on that processor's catcher. Cross-VM SCMOBJ transfer is unsupported without separate clone/serialization/native ownership semantics.

| Unit | Acquisition / handoff | Last legitimate release |
|---|---|---|
| A's argument loan + descriptor control ref | Before exposing pointer; remains through nested callbacks. B never becomes its owner. | A finishes native use/result conversion, ends resource loan, completes descriptor bookkeeping, then drops control ref as final descriptor access. |
| B's child loan/frame/control ref | After checked B context/journal/root registration; refusal cannot publish pointer. | B's local conversion/body/error exit drains loan, finishes ps/status tail and detaches its local frame. It cannot drop A's reference. |
| Parent-lineage bridge | Created under A's live authority before child admission. | After child completion envelope consumed/ACKed and sender cleanup responsibility resolved. Parent stack may already have returned; stable descriptor only remains. |
| Sender RC carrier/domain + message pin | Before release-publishing completion; payload is still traced after B frame return. | Sender's own safe point after receiver's rooted ACK. Receiver cannot directly decrement sender RC refcount. Domain/owner retirement refuses until cleared or transferred under a proved GC handoff. |
| Receiver result carrier | Before ACK, using current traced cell, with acquire/release publication. | Receiver's own native last use/parent result/export policy. No scalar pointer snapshot substitutes for root ownership. |
| SFUN frame lease → native tail | Tail authority exists before frame_count decrement. | After propagate_error, catcher/binding restoration and last ps/marker access at the local surviving boundary. No decrement-then-reborrow window. |
| Ordinary run marker/entry | Checked run entry before marker creation; common all-exit marker tracking. | Common finalizer outside TRY after every supported error/return; entry/tail pin ends after last ps access. Teardown requests inside run must defer physical destruction until native return. |

A need not wait for B's RC destructor before resuming its own native C after receiver-root publication. B's independent message/domain pin preserves cleanup debt asynchronously. VM physical destruction waits for the ledger, not for a guessed timeout. A blocked/uncooperative B can retain resources indefinitely; no model turns that into unconditional completion. Closed admission refuses new work, while previously accepted bridge cleanup still needs its registered safe executor. The existing collective's ability to service GC while a native borrower is blocked remains a separate native progress requirement.

## QNT evidence and limits

The new cross-owner model composes independent A/B native lifetimes, A's paused parent loan, B's child prefix/body error, run-error finalizer, counted lineage/message/domain pins, two abstract relocating GCs, full-key destination checks, receiver-root publication, owner-local ACK cleanup, duplicate/stale rejection, close and final reclamation. It explicitly permits A's native return before sender ACK cleanup; remaining debt blocks destruction. It does not transfer C frames/catchers between owners.

The predecessor model treated the completion root as an owner-agnostic abstract bridge. Its passing controls remain archived but do not prove safety of applying owner-local RC APIs remotely. The final model adds sender-domain/owner-liveness and ACK-owner obligations derived from the actual locked mem.c. Negative traces cover remote longjmp, processor-only routing, child clearing parent's state, publication without root, premature bridge/frame/domain removal, stale owner acceptance, duplicate decrement, pre-GC restore, post-final-reference access, run marker skipped on throw, freeing a blocked borrower, wrong ACK owner and ACK before receiver root. Direct bad-event flags express protocol exclusions, not reproduced native crashes.

Atomic publication, root scanner correctness, registered safe execution, bounded same-VM identities and exact owner checking are model assumptions requiring C implementation. The fixed destination values are a bounded stale-generation control, not a proof of an unbounded token allocator. Body-error and prefix-error scenario goals are distinguished at their actual B-stage/loan state, then separate continuations start from the exact decoded reachable error states and reach final cleanup. Earlier generic failed-status goals also admitted refusal before B entry and are not counted as those recovery paths; their receipts are retained. These coupled witnesses prove existence of paths, not fairness or native recovery. Completion witnesses are existential; fairness, arbitrary nested depth, cross-VM sharing, permanent callback termination and native GC participation are not proved. The prior depth-five local-stack and exported-pointer controls remain separate evidence, not a silently unified unlimited model.
