# Checked park entry, materialized roots and cohort commit

This is an evidence-only implementation handoff for Grok. It applies no runtime, qualifier or historical-receipt changes. Names explicitly called new below are proposed implementation symbols. All source coordinates refer to the reproduced lock-main candidate at revision `7c490c3ab5b5a4238b26f4a59d8cd9fd4b085882` plus the cumulative foreign-release-claim patch, using [the bound source receipt](run-ack-source-protocol.json). Vendor HEAD is not the source authority. Recorded qualification remains 8/12; native admission is false.

## Independent design decision

Checked park cannot be implemented as “save the thread, decrement processor_count, run the old c-lambda.” `THREAD_SAVE` may leave a stack address; the existing barrier and GC use logical processor_count as their worker set; raw C locals and pointers may not survive moving GC; and returning through ___run would invalidate the return marker of the captured continuation.

Use a split blocking-call contract: **prepare while active → Scheme landing and completed old-cohort materialization → common freeze/membership commit → an internal ___call native dispatch → checked rejoin → Scheme result conversion and one-shot restore**. Keep the native ___call/___run activation and marker alive across the parked interval. The first production contract should refuse parking logical P0 and any unclassified/raw-movable-address ABI before accepting the job. Supporting P0 later requires a separate migration of VM leadership and shutdown authority. This is a bounded support decision, not evidence that arbitrary legacy C calls can be isolated.

Preparation must register the root carrier before clearing the scheduler's current-thread root, preserving continuous coverage. Perform one completed old-cohort materialization pass, including nested GC if needed, and follow with a common certificate round. A later preparation GC updates the same carrier; its success does not justify using an earlier scalar copy. No user callback, Scheme allocation or continuation switch is allowed between the accepted freeze certificate and common membership commit.

The job preflight classifies converted values and native aliases. Admit copied native buffers, true native handles, or specifically pinned/registered representations with a proved lifetime. A raw movable SCMOBJ held in C, a pointer into Scheme stack/heap, untracked recursive callback, outstanding private mutation, or unclassified release callback prevents parking. A native journal pointer is not a Scheme root. Merely increasing a reference count on unrelated metadata does not stabilize a movable payload.

A bare external C thread without a live admitted Scheme/native-call context cannot manufacture this landing by setting TLS or rebinding PSTATE. Refuse before ps access, or dispatch an explicitly rooted request to an admitted owner under the separately proved request-delivery contract.

## Internal native dispatch without destroying the caller

New helpers: `___park_prepare_job`, `___park_commit`, `___park_dispatch_native`, `___park_request_rejoin`, `___park_attach`, and `___park_abort`. Add a distinct tagged internal dispatch result/escape to `setup.c:3951 ___call`, before its generic error/unmatched-marker rethrow at4058. Do not reuse an untagged error as a park signal.

After the old cohort commits, the controlled landing helper transfers its journal suffix to the persistent job, then escapes to this local ___call handler. This is an internal suspension of the same native owner, not an outward error to ___run. Keep the marker and native context/tail pin; do not let the common ___run finalizer run at this point. The dispatcher executes only the prepared native body; it must not use B's ps allocation, old fp, GVM registers or caller conversion locals while detached. The outer catcher remains on the same live OS stack. No remote OS thread may longjmp to it.

On native return, record native result/status into the stable job and request rejoin without touching Scheme heap. A checked callback entry does the same request before entering Scheme; it does not call the ordinary ___call on the parked ps. Put the parked-job check ahead of the generated `BEGIN_SFUN*` marker/conversion path and `___sfun_frame_enter`: those existing operations already access pstate and cannot serve as a pre-entry guard. The active coordinator services the request and wakes B through the admitted backend. While waiting, B is outside the cohort and retains its domain/native/job tokens.

After common rejoin commit, B initializes a fresh current stack/heap landing and installs current relocated roots. For final host completion it enters new `##checked-park-resume!`, performs result conversion and consumes the saved parent continuation once. `THREAD_RESTORE` then uses the current stack break, not the saved raw fp.

For a nested callback, admit a separate SFUN activation and journal instead; do not consume the parent's saved continuation. After the callback's result conversion and local cleanup, the host body may block again. Before returning the callback result into that body, B must repeat the checked materialization/freeze/park commit (or prove the remaining native segment bounded/nonblocking). Only the eventual host-body return requests the final rejoin and parent restore. The model distinguishes callback completion, repark and final host completion across four abstract membership epochs. This corrects an earlier model abstraction that equated callback rejoin with parent completion. An arbitrary C longjmp/cancellation that bypasses this checked dispatcher is outside the recovery contract.

## Freeze and active membership transaction

Keep logical processor slots, native owners and active GC ranks separate. New fields should include: VM/cohort generation; active member rank mappings and leader; job/owner/activation ticket; SAVED/MATERIALIZED/FROZEN/PARKED/REJOIN_REQUESTED/ATTACHED/RESTORED phase; frozen-domain descriptor and scan owner; private-work and native alias certificates; per-domain scan/native-reader leases; native tail and root-carrier pins; one-shot restore/cleanup claims.

Suggested native interfaces are `___park_prepare_job(ps, abi, rooted_args, &ticket)` while active, `___park_commit(ps, old_cohort, freeze_certificate, ticket)` inside the agreed collective, `___park_dispatch_native(ticket)` without a ps/heap capability, and `___park_request_rejoin(ticket, native_result)` before any Scheme conversion. A ticket references stable native storage containing VM generation, native owner generation, activation nonce, callback depth/parent ticket, rooted carrier, native argument/result storage, return marker, old/new cohort epoch, loan journal and restore claim. Allocate/reserve these before the commit boundary. B release-publishes the completed freeze record; the collective acquire-validates it, then release-publishes the committed cohort/scan descriptor. B acquire-observes rejoin completion before touching the newly attached ps. Do not publish success through a plain boolean independently of descriptor initialization.

Before commit, B remains in the old cohort and is its own root scanner. At a tagged common boundary with GC readers out, verify materialization, native-loan freeze, no private GC work and a complete root-domain inventory. Publish **active membership, GC worker count/ranks and scan-domain assignment in the same epoch transaction**. After commit B is no longer a scanner, but its domain remains registered under exactly one active scan owner. Never publish membership first and fix roots later, or scan B both actively and as frozen storage. Reuse the READERS_EXITED / OWNER_SERVICE_DONE protocol from [ACK service](ack-collective-service.md); all affected members must follow the same phase schedule.

`barrier_sync_op` (`setup.c:751`) currently builds a tree from logical id/processor_count. It needs the immutable active-rank descriptor for that epoch; do not decrement logical processor_count to make B disappear. B is still an existing logical slot and native borrower. Resize and cleanup must refuse reuse/destruction while its frozen domain or native activation remains live. This also avoids accidentally admitting a new incarnation into an old return marker or job ticket.

Extend `sfun_vm_try_close` and the checked cleanup/destroy admission paths with the native run/job/domain consumers; an ordinary ___run marker is explicitly not an SFUN lease in this candidate. A zero SFUN count cannot authorize freeing a parked run. Closing external admission must preserve an internal drain/rejoin lane for an already accepted ticket; otherwise shutdown can strand its own accepted job. Park neither joins the OS thread nor publishes a new slot incarnation, and its pending state is not an OS join errno.

## P0, rollback and rejoin boundaries

The initial implementation should reject P0 park before conversion/job acceptance. P0 presently owns barrier root broadcast, VM root/symbol scanning (`7595`), stack/heap assignment (`7545`), heap resize (`7789`), GC statistics/notification (`7710/7808`), and error/startup/cleanup paths in setup.c. A dense active rank zero is not automatically permission to replace all those logical-P0 duties. Supporting a parked P0 needs a single committed leader plus explicit VM shutdown/main-host authority and result routing; it is not included in this model's positive contract.

| Failure point | Required disposition |
| --- | --- |
| Invalid ABI, owner, ticket or P0 | Refuse before executing the body or publishing membership. Existing active root coverage remains. |
| Preparation/materialization failure | Old cohort and scan ownership stay intact. Return through one ABORT landing using the current GC-updated continuation. Clear only this job's native prefix loans; do not restore old msections/fp or outer journals. |
| Commit preflight failure before publication | Abort the prepared transaction collectively; retain old membership, roots and worker counts. No partial decrement or scan-domain publication. |
| Rollback/restore failure or unknown publication outcome | Retain carrier, root domain, journal, full ticket and native lifetime. Do not fabricate RESTORED ACK or release/reuse the slot. Unknown cohort publication requires fault containment/common reconciliation; this model does not prove distributed commit recovery. |
| Failure after a known park commit | Remain outside the active cohort with its frozen domain scanned and native pins retained. Active C/GC may progress. Retry only a known side-effect-free stage or enter the reviewed fault policy; do not rerun an uncertain host effect. |
| Rejoin preflight/reservation failure | Stay PARKED; failed private reservation cannot change shared worker count/heap cursor. Keep the original job and generation. No Scheme entry before successful commit. |
| Rejoin success | At a GC-excluding common boundary attach valid current stack/heap/limits and atomically move membership+scan authority to B in a new epoch. Validate same native owner and full job ticket. Then restore once and acknowledge the new root owner; carrier removal waits for reader grace. |
| Repeated callback/late ticket | Match depth and activation; reject duplicates/stale tickets without changing the current incarnation. Epoch wrap/ABA requires a separately proved allocator/nonreuse policy. |

An ABORT failure while B is still an active member requires B to remain in a controlled native sync/fault-service loop. The model's active retained state assumes that serviceability. If the failed unwind has destroyed that ability, retaining its roots is necessary but cannot preserve cohort progress; use common VM fault containment rather than claim that a missing active member is harmless. In contrast, a rejoin reservation failure occurs while B is already parked, so C can keep scanning its frozen domain without waiting for B.

## Grok implementation and targeted native checks

1. Add the explicit blocking adapter and immutable job descriptor, separating prepare/native-body/complete in `_ptree2.scm`. Reject raw movable aliases and P0 first; retain the ordinary bounded FFI contract separately. Make every admitted pointer loan and Scheme value visible in a typed job journal/root cell.
2. Add `##checked-park-landing!` / `##checked-park-resume!`, using the real thread-save/restore emitter and generated maps. Request materialization through the existing old-cohort GC path, then verify the complete carrier/frame/private-work certificate with no T/P lock held.
3. Implement epoch-tagged active rank/scan-domain commit in `execute_sync_op_loop` and `barrier_sync_op`. Migrate worker counters, global partitions, heap accounting and frozen typed scans as one source change; keep logical slot/native ownership and P0 duties fixed. Refuse commit unless every dependency is initialized.
4. Add the internal tagged park branch to ___call, preserving its marker/catcher/native context through the dispatcher. Add checked rejoin request/admission and fresh Scheme resume. Do not pass through ___run's outward cleanup for this internal pause.
5. Inject failures before materialization, before commit, after known commit, during private rejoin reservation, and during ABORT restore. Assert old-state preservation before commit and rooted retained state after commit; assert one restore/one cleanup and no access after the final lifetime decrement.
6. On the same producer, force GC before/after save, materialization, park and callback rejoin; hold B in a controlled native wait while C runs repeated real GC and drains ACKs. Check frame/RC/still relocation writeback, exact scanner count, complete global partitions, P0 refusal, duplicate tickets and native-only sync service. Retain the real generated header/C/object/link identities and raw negative traces. No full-suite run or acceptance change is part of this audit.

Independent conclusion: this is a coherent implementation contract for **classified non-P0 blocking jobs**. It does not safely park arbitrary existing raw c-lambda frames or an already-blocked owner. The remaining work is executable: the split generator/landing, complete frozen-domain collector, active-rank accounting, internal ___call dispatcher and checked rejoin must be implemented and verified together. Generated frame maps, nested callback journals, weak/finalizer policy and unknown commit recovery cannot be inferred from a conditional QNT PASS.

## Recorded validation and limits

Final `models/gambit/checked_park.qnt` and verifier receipts contain 33 expected controls: 9 safety plus weak-fairness conditional-progress scenarios, 17 decoded safety counterexamples, 5 distinct reachability witnesses and 2 exact-state continuations proving another GC transition after retained rollback/rejoin failure. Maximum observed case 14.728s, unchanged 30s per-case cap. Receipt: `.cache/tasks/repair-9-12/processes/audit/runs/6cc4e9ceebce43d989cdc2a8eea46438/outputs/checked-park-retained-gc/receipt.json`; its source verification receipt identifies the 31 base controls. All projections and both continuation initial states were reconstructed independently.

Positive cases cover success, prepare/commit failure, known postcommit retention, unsafe ABI/P0 refusal, callback→rejoin→callback return→rematerialization/repark→host return→final rejoin, rollback retention and failed rejoin retention. Negatives cover save-without-materialization, split membership, wrong worker count, lost frozen roots/run marker, raw-fp rollback, P0 park, direct parked callback, stale ticket/remote owner, double restore, premature rollback release, omitted still or RC scanning across actual model GC, private work left behind, duplicate scan ownership, and treating callback completion as parent completion.

Two earlier conditional slices (24 controls at audit a4b8b048c3584ea3bec6f74920581346 and 28 typed controls at75e942bf7fa24589bca3bbf6e0b6a74d) are retained as predecessors. They did not separately model callback return, repark and final host completion; final conclusions use the strengthened model, not those simplified callback traces. No earlier runtime test was repeated.

The model has recurrent GC without a finite collection counter, a single nested callback, and four abstract membership commits. It abstracts completed GC materialization, typed-root scans, atomic cohort commit, fresh allocation reservation and native context/loan admission. It does not prove generated C frame maps, arbitrary recursion, P0 delegation, unknown commit recovery, unclassified callbacks, native reader grace implementation or epoch wrap/ABA. The retained active failure assumes B remains a functioning sync-service participant; the parked failure does not require B to participate. These are precise proof preconditions, not native acceptance.

## Subsequent native-stack correction

[Staged FFI generator and callback repark](staged-ffi-generator-protocol.md) distinguishes initial dispatcher transfer from callback-return repark. The latter must synchronously preserve the live host C activation; an outward longjmp would destroy it. The atomic callback transition in checked_park.qnt did not establish this distinction. The newer 32-control slice records this gap and error/cleanup ownership negatives; prior immutable receipts remain unchanged.
