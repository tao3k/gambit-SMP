# Release leaf, registered delivery entrances and common refusal return

2026-10-24. Current baseline remains `scan-session-cut.lock.json` / main7c490c3 / cumulative patch0949fbbf. This is a source-bound implementation and acceptance specification for Grok. No runtime implementation or native campaign is performed by this audit. It refines, rather than replaces, the preceding shrink/owner protocol.

## 1. Concrete no-GC/no-escape boundary

The current `_thread#.scm:1785` unlock macro performs a heap check before acquiring the mutex. `_thread.scm:1000` and4020 may drop locks, participate in SYNC and re-read queues. `_thread#.scm:1431` timeout removal acquires another P/TOQ lock. These operations belong to **preparation**, not a no-failure commit. `(not interrupts-enabled)` does not prove no GC, no stack check or no native throw.

Use three request-specific functions, preserving generic unlock callers:

- `##thread-intr-release-prepare!`: mapped request/outcome/waiter roots; heap/stack reserve; try/release/retry for required T/mutex/TOQ/destination-P state; current owner/head/link/route validation after each SYNC or lock drop. Compute all arguments and conversions here. Native pointer validity, bounds, expected request layout, and slot/VM lifetime must be established before the leaf.
- Private `___thread_intr_release_commit`: a bounded C leaf called from a generated `##c-code` bridge, after preparation. It performs only the already-prepared ownership/link/resume-disposition stores and commits a rooted WakePending responsibility. No allocation/free, Scheme/c-lambda callback, polling, blocking lock acquisition, GC, error construction, `___THROW`, longjmp, C++ throw, logger, or function-pointer dispatch. Use no mutex helper that can drop/reacquire a lock. It may return a pre-mutation refusal; after its first destructive store there is no recoverable error return. Invalid-address/hardware failure is a retained terminal fault, not a rollback path.
- `##thread-intr-release-finish!`: after leaf ownership commit and physical lock release, finish runnable insertion/wake under current scheduler locks, preserving mapped waiter and exactly-once membership. Recheck if another wake already scheduled it. Keep target cleanup and sender-result consumption responsibility until each last access. Cleanup checks actual owner **and** release/link stage; it cannot repeat old-owner removal from a partially committed state.

The raw C leaf does not implement Scheme tree/priority/timeout algorithms by calling back into Scheme. Move their fallible participating acquisitions to preparation; any remaining runnable algorithm is finish work with an explicit rooted WakePending journal. If its body cannot be kept within the specified bounded store set, do not label it the no-GC leaf.

Compiler source correspondence is exact: `gsc/_t-c-2.scm:4201..4245` emits a literal `##c-code` block and marks resource use with `targ-use-all-res`. That bookkeeping is **not** an executed spill or a purity theorem. Its check generator398..437 emits CHECK/POLL/return-label machinery elsewhere. Current header macros6833/6834 expand real `___R_ALL`/`___W_ALL`; the native throw macros10054..10085 use setjmp/longjmp or C++ throw. The new bridge must explicitly preserve the required frame/register state and arguments, without argument boxing/conversion inside the held-lock region.

### Required generated-C/object certificate

Bind the real SMP compiler/header/config/flags and label the following region in the *newly generated* bridge:

`PREPARE_DONE → root/register stores and fixed native call → leaf first destructive store → owner/phase/root journal stores → LEAF_COMMIT_DONE → lock release → FINISH`.

Preprocess and audit the actual leaf's full transitive call/macro expansion and its object code. A text blacklist or `leaf` attribute alone is insufficient. No hidden libatomic/allocator/throw/stack-overflow helper may appear in its normal path. Lock-free atomic size/alignment and all referenced addresses must match the target. Compiler stack-protector failure/hardware memory corruption is not a recoverable normal branch. The caller's next heap/stack/interrupt check must occur only after a consistent committed or unchanged state, with the WakePending roots still present.

Retained source-package `_thread.c` and `_kernel.c` are hashed separately as **unadmitted generated references**. `_thread.c` has none of the requested named SMP request/no-waiter/slow-unlock entry labels; `_kernel.c` contains the raw resize C wrapper and a wait RA/register wrapper, but lacks current source's extra RA checks. There is no source/config/producer receipt binding those files to the proposed implementation. Absence of a name alone does not rule out inlining, but these files cannot certify the new release map or commit. Do not hand-edit them or reuse their hashes as proof of a newly compiled producer.

### Additional current C error branch that must be fixed

`service_procedural_interrupts_pstate340..371` unlocks the native mutex before `execute_fn`. On non-NO_ERR it `break`s past the relock and reaches the trailing unlock. This is an established source lock-state defect in the current candidate, not a newly observed crash. The older native-tested reference had a repair; preserve current source around it and port that edge deliberately: return the callback error while already unlocked, retain the untouched queued suffix and OTHER service debt, and discharge the activation only after its last valid use.

`cleanup_interrupts_pstate587..607` invokes release callbacks while holding the mutex, then clears the queue. Convert to an admitted detach-one/execute-outside-lock protocol with explicit ownership of current item and untouched suffix; an error/nonlocal escape cannot authorize clearing/freeing the rest. No callback retry after unknown partial release, no mutex destroy with outstanding callbacks. These paths invalidate a purported complete entrance ledger if left unaudited. Native lock balance itself remains a targeted C control, not a property inferred from the abstract QNT.

## 3. Common refusal: exact return/throw sequence

1. `_kernel.scm:2394` raw c-lambda calls `___current_vm_resize`; SMP wrapper2406 migrates an ordinary Scheme caller to P0 first. A raw native worker caller has no such migration: validate a returnable owner before admission and refuse unsupported retirement of its own native activation. Do not invent an in-C Scheme migration.
2. `___current_vm_resize2004..2040` validates target, then `sfun_vm_try_close1972`. A failure here is **before** `on_all_processors`; it can return locally. This sfun gate is neither delivery count nor zero-debt proof.
3. `current_vm_resize_admitted1992` builds OP_VM_RESIZE; `on_all_processors1933` enters the elected operation. The new delivery guard goes in `execute_sync_op`1644 **before** calling `___vm_resize_pstate`. Once peers joined, a root-only early return is invalid.
4. All old members receive the same tagged guard result in scratch transport, preserving the original outer winner id, thunk root and target arguments. Do not overwrite the outer winner with P0's guard winner or borrow the outer thunk slot as a status before its lifetime is settled. On busy: skip1364 for **every** member; old target/pending/count/queues remain unchanged.
5. Feed the common status into the existing OP_VM_RESIZE result return, preserving required loop/NOOP/flag-reset phases. `execute_sync_op_loop1883..1887` copies the result only to the original winner/requester (or combining operation), then marks it executed. Native service peers return to their sync loop; this is not a second Scheme error callback on every processor. Keep startup/growth result choreography separate from a rejected shrink.
6. `current_vm_resize_admitted` returns the SOP status. Outer `___current_vm_resize` reopens sfun on its **ordinary** return. If a genuine native throw is propagated, its `___ON_THROW` handler must reopen sfun and rethrow the same error. Normal busy status is not an invented OS errno or necessarily a Scheme exception: the c-lambda returns a Scheme object according to the existing interface.
7. `execute_sync_op_loop1908..1912` has a distinct `___err` route for elected processor errors. Preserve genuine higher-priority errors and actual setup_state-dependent throw behavior; do not replace a common guard refusal with stale NO_ERR/thunk, or raise while another old member remains inside a barrier.
8. A mismatched collective epoch/phase is **not** ordinary busy/throw cleanup. Keep the affected generation/admission state retained until a common safe abort or terminal disposition exists. Current unconditional outer sfun reopen is not proof of that retained-fault path; add an explicit retained-protocol-fault classification before reuse. Never fake ACK or reopen merely because P0 returned from one local round.

Existing generated reference `_kernel.c:6259..6280` shows `___return` assigns a local CFUN result and jumps to conversion/return epilogue. The actual new generated raw/SMP wrapper must prove conversion roots/error path, native catcher and returnability on the final producer. That reference is not a current-wrapper certificate.

## QNT obligations and implementation limit

`delivery_commit_entry_return.qnt` adds distinct prepared/unlink/owner-commit/unlock/wake events; GC/escape/retry inside the critical region; admission-before-pointer-use for9 entrance groups; closed/invalid-host refusal with caller ownership; pop-to-frame roots and activation lifetime; common two-member result/epoch; normal return/native throw sfun cleanup; and old-slot reset with debt. Positive native fault retains the partial commit and pin; it does not recover it. Critical-region GC is disabled by the **modeled leaf contract**, not by verified machine code.

Mutants include missing initial/internal-async registration, raw invalid host access, legacy silent drop, early dequeue unpin, missing returned-node root, GC/escape/retry-unlink in commit, local-only return, wrong returned error, missing outer reopen, stale ACK and reset with old debt. Reachability controls require accepted completion for each of9 modeled entrance kinds, not just refusal. This is an executable specification for source/codegen review; it cannot discover unknown C callers or prove an arbitrary generated helper pure.
