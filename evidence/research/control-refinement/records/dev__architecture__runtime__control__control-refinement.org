* Decision and evidence boundary
:PROPERTIES:
:CUSTOM_ID: control-refinement
:AUTHORITY: GambitControlRefinement
:STATUS: SOURCE-MAPPED; REFINEMENT-OPEN; NATIVE-OPEN; COMMIT-BLOCKED
:END:

Modern C is the implementation line. The complete cut is a shared generated
frame/root/control ABI, Scheme-owned winding, context-owned roots, independently
authorized collector work and explicitly admitted native activations. Replacing
those responsibilities together is the refactoring; adding checks around the
same implicit owners is insufficient.

[[file:models/sysml/control-refinement.sysml][SysML]] refines the six existing open obligations in
[[file:continuation-segments.org][the captured-segment design]]. It creates no duplicate QNT or Lean obligation.
Its 36 source witnesses locate concrete operations; five obligations require
source refinement and one owns native acceptance. Seven native case families
qualify the full-control target. An eighth is specific to a later, separately
admitted prompt extension. These are case families, not eight executed tests.

[[file:../../../modeling/ascent/control-refinement.rules.scm][ASCENT]] distinguishes mapped source, checked source refinement, matching native
case evidence and the five submission gates. Reading a function, matching a
token, passing a model, or running a historical binary cannot substitute for
the source relation of an unimplemented adapter. The LLM remains the default
working environment, with no extra service or approval tier.

** CS-BRIDGE: specify the real abstraction, not another endpoint model

The actual source demonstrates three different changes that cannot be collapsed
into one integer revision:

1. A supported frame-slot or continuation-field update changes logical image
   content. Revocation belongs to the shared physical frame/alias domain, not
   merely to one continuation wrapper. =##continuation-copy= copies the wrapper
   while sharing frame and denv; a write through its sibling must invalidate
   any affected prepared view.
2. GC relocation changes physical addresses while preserving Scheme object
   identity. The abstraction into Lean slot values must use logical identity;
   authoritative roots and cache reload use a distinct relocation epoch.
   Do not claim a logical payload mutation every time GC repairs an address.
3. Mutation of an object referenced by a slot preserves that object's identity
   and ordinary shared-heap effects. Restoration does not roll back that heap.
   The current Lean =denv= identity does not prove deep immutability of the denv
   vector or its parameter tree.

The source simulation must map a granted QNT ticket to an actually rooted,
authentically prepared view satisfying the existing Lean premise, then relate
every writer/revocation and GC/reload transition. Matching revisions are only
useful after this issuance/history relation exists. Finite C counters require
no-wrap/reissue rules and identity non-reuse while observers remain; the Lean
=Nat= result does not supply those rules.

Use read/write exclusion for real C payload accesses; acquire/release ordering
publishes initialized descriptors and completed root views. Do not use a
seqlock-style retry to excuse concurrent plain-C data races. No physical grant
or exclusion lock survives a call to a user winding hook. After that hook,
reacquire current authorization and reload authoritative roots before commit.
The existing collector-only =frame_gate= is not evidence that raw mutator
setters obey this protocol.

** CS-WRITERS: an admitted closure, with explicit unbounded escape hatches

The real inventory has separate writer classes: public/internal reflection;
=continuation-next!= traversal; deserialization shells; I/O explode/implode;
thread-save/restore; mutable denv/environment/winder vectors; collector forwarding
and root repair; RC registration/data updates; generated FFI arguments/results;
and arbitrary native stores. They need different permissions, not one blanket
barrier around Scheme assignment.

Deserialization already calls =alloc!= before recursively decoding child values.
The replacement must retain that cycle/root custody. A registered, scan-safe
shell and initialized-field state are required across a collecting recursive
decode; an unknown or failed construction remains rooted until its unique
initializer settles. It cannot become a replayable complete frame early.

=THREAD_RESTORE= clears a scheduler-owned continuation slot. This is not a
license to consume an ordinary full multi-shot continuation. Likewise,
=continuation-next!= can rewrite a traversal wrapper and stack RA without
meaning an application has consumed the saved continuation.

The optimized writer closure is a managed admission boundary. Known generated
stores get explicit FrameStore/RootRegistry adapters. Ordinary vector aliases
must either be routed through a complete managed store or keep the affected
image conservatively scanned and non-shareable under concurrent mutation.
An unknown raw native writer cannot be qualified merely by scanning more often:
it also needs an access/exclusion contract; otherwise reject that optimized
entry. This is an unresolved compatibility decision, not a claim that existing
FFI or reflection can silently disappear.

** CS-HOOKS: preserve Scheme continuations, replace physical authorization

Both scheduler branches contain =##continuation-unwind-wind= and its grafted
Scheme suffixes. The proposed common Scheme semantic body should be factored
only with equivalence of the branch-specific bindings/accessors established.
It is an intended retirement of duplicated policy, not an achieved removal.

The two core source intervals =4916-4991= and =8426-8501= are literally identical:
76 lines each, SHA256 =7cd523c939af6e66420ce4068ea20f12e6eaa1a16dab3af3e1be3a612aa9cf24=.
The retained receipt recomputes this equality from the pinned source. This is
concrete duplicate policy that can be retired after binding equivalence, not a
runtime speedup or proof of equivalence for the surrounding schedulers.

The source relation compares dynamic extent identity, denv and observable hook
effects at every user-procedure boundary. Same extent skips hooks, so no hook
can serve as a universal resource reacquisition guard. If a hook captures its
own continuation, its saved suffix may legally run many times; it gets a fresh
physical execution grant each time. Refuse a late native helper's obsolete
completion, while preserving that Scheme suffix. Globally deduplicating hook
effects by transfer ID would change legal semantics.

Before/after may collect, raise, abandon the transfer or initiate another one.
The rooted pending transfer owns values and the selected destination while
Scheme owns successor control. The returning path refreshes the image/root
view and revalidates NativeOrigin. No collector or native gate may wait for a
hook while holding the root/frame exclusion it needs to run.

** CS-PROMPTS: full-control first, an explicit extension later

The selected =full-control= target introduces no hidden delimiter into existing
=call/cc=. Its source obligation is preservation of full extent and explicit
exclusion of unimplemented partial operators. =prompt-extension= additionally
requires a real tag/cut/handler/composition/reinstatement definition, mapped to
the same frame/root ABI. Closing a baseline-boundary claim must never be
reported as closing that extension's semantics.

Guile's saved-register check shows why moving a partial Scheme segment does not
imply resurrecting intervening C frames. Its Scheme =shift= wrapper reinstalls
=reset= explicitly. Those are source-grounded questions for Gambit, not an
operator implementation to copy blindly. Full multi-shot availability and
delimited extent are independent design choices.

** CS-FRAMES: coordinates, ordinary roots and structural custody

For an admitted one-based slot i, the current raw code uses heap =fs-i+1=,
stack =FRAME_SPACE(fs)-i= and root bit =i-1=. Structural link =link+1= has its
own traversal contract and is excluded from ordinary root runs. Internal frames
expand stored size through =RETI_CFS_TO_FS=; IFD/OFD decoding and map chunks must
agree at every target word boundary. Module metadata remains live while any
captured frame, root cursor or native restore consumer can reference it.

The source cut must include =gsc/_ptree2.scm=, which emits SFUN/CFUN conversion
and argument macros. Restricting the change list to =_t-c-*.scm= misses a real
frame constructor. =___call= constructs the two-slot C-return frame, and the
kernel return handler and catcher consume it. Their offsets migrate with the
generator and collector, not after the old macros have already retired.

In current captured-frame copying, reservation precedes payload copying, link
repair, publication and grant commit. A unique slot writer/root custodian is
required; multiple roots may legitimately name the same object. Deduplicating
object copying is not permission to omit relocation of another authoritative
root slot. Per-copy reserve does not prove enough contiguous capacity for the
whole collection. The pre-flip planner and restore headroom remain dependencies
of the complete cut.

The source chain for =map= is concrete: =proc (car lst)= returns a value that
remains live while the recursive map tail runs, and consing occurs afterwards.
The checked fixture captures inside that call, resumes with 20 and 200, checks
the shared effect trace, retains 80 roots and forces eleven collections. It
contains a synchronous =c-lambda= leaf, not a C-to-Scheme callback. Merely running
it in a VM with eleven processors does not prove two simultaneous restorations,
collector migration or native callback correctness.

The two =___run= origins are processor startup and initial module setup. Generated
SFUNs instead call =___call= through emitted macros, adding a separate entry
family. All three are required. Native marker allocation must protect the proc
before allocation; a local pointer wrapper does not register that root. Return
checks must cover still-live origin, processor/context binding and marker
invalidation on ordinary and nonlocal exit. =___propagate_error= throws through
the current catcher; cleanup code placed only after a call is insufficient.

Tcl is a concrete external caller: =scheme_call_cmd= reads ClientData payload
and =scheme_delete_cmd= releases both Scheme and RC ownership. Its managed bridge
must pin before payload read and settle deletion/exception cleanup before reuse.
Until that adapter and its tests exist, keep it explicitly unqualified; absence
of Tcl in a particular profile is not evidence that the bridge is safe.

Each native case receipt must bind the complete producer-recorded source and
generated dependency closure, exact Bazel profile, target,
case recipe, termination/outcome and unchanged limits. Failure or unknown
outcome retains the specific roots/resources. Baseline receipts or model logs
do not become results for the new replacement. No native tests run in this
research update.

The current audit digest covers the selected witness files and the existing
18-file candidate lock. It identifies this source investigation; it is not a
complete build-input manifest. Hypothetical routing controls use it solely as
an equality discriminator. A future native evidence importer must bind the
actual bootstrap/generated/object/link closure before issuing execution
acceptance; this script never imports an actual new native receipt.

The control inputs select one authoritative final outcome per case and one
target-scoped evidence set. They do not implement arbitration among conflicting
native attempts. A production importer must retain failure/unknown histories,
reject contradictory selected outcomes and bind the selected evidence-set
identity; it cannot union an old pass with a new failure into acceptance.
Prompt-extension admission additionally depends on the full-control baseline;
the current checker deliberately admits only the full-control target.

* Complete modern-C migration and retirement
:PROPERTIES:
:CUSTOM_ID: control-refinement-cut
:END:

1. Complete Scheme-owned FrameSpec/PointId/ControlSpec after liveness and expose
   one descriptor ABI, including FFI frame construction and module retention.
2. Introduce context-owned registered capture roots and stable shared alias
   domains. Materialize only through those roots. Retire raw physical layout
   owners only after reflector, serializer and I/O consumers migrate.
3. Use per-invocation RestoreView and one shared Scheme winding definition;
   unify native checkpoint/reload/commit accessors. Preserve multiple values,
   proper tail space and arbitrary multi-shot hook restoration.
4. Publish complete context root views to GC participants. Workers own copying,
   queue/Tail obligations and capacity grants, not mutator roots. Worker carrier
   identity cannot choose the source RC list or authorize execution. Retire
   implicit processor-as-context/participant/worker equivalence after all paths
   migrate and unknown-worker outcomes retain bounded selected custody.
5. Migrate both =___run= origins, generated SFUN/CFUN and admitted external
   callbacks to explicit activation/root/borrow/exit protocols. A Scheme restore
   never revalidates a dead C activation. Physical stopping, join and GC epoch
   receipts remain distinct from logical activation closure.
6. Close whole-round physical capacity and unique scan ownership, then requalify
   the entire generated/native closure. No global gate across hooks, heap
   increase, longer wait or copied SMP patch substitutes for this replacement.
7. Admit prompt extension and generational scan skipping as explicit later
   capabilities of the same ABI, after their own complete writers, capacity and
   semantic conditions hold. They are not silently counted as baseline gains.

This is one integration cut with dependency-ordered edits, not seven independently
submittable correctness claims. The existing dirty =modern-c= candidate is
preserved. This update changes research models, DSL and views only.

The current source still selects root participant and completion phase using
the worker carrier's processor ID (=mem.c:7462-7475=), and its GC entry requires
=work->context == ps->context= and =work->carrier == ps= (=7570-7598=).
Those are concrete old responsibilities to retire. An independent worker must
claim an explicit participant/root task; the frozen root origin survives carrier
changes. Completion belongs to the claimed task/phase, not to the carrier index.
Termination must account for queued, in-flight, private frontier/Tail and
publication debts before declaring the round complete.

For shared captured frames, structural forwarding/link mutation has one task
owner per admitted frame/chain domain; other root slots still require their own
relocation updates. Independent domains should proceed in parallel. The current
VM-wide frame gate is a baseline correctness mechanism, not proof of scalable
independent workers. Replacing it requires the task/alias ownership and capacity
protocol together; deleting it alone is not the refactor. Unknown join isolation
may retain physical sections and origins; it cannot invent a frozen root view
for an owner that might still write.

* Amplification, work and peak-memory matrix

The [[file:continuation-segments.org::continuation-benefit-matrix][SysML-owned benefit matrix]] remains authoritative. The following quantities
make its opportunities falsifiable, rather than asserting an unmeasured speedup:

| Capability | Work that can disappear | Work that remains / is added | Positive-benefit condition |
|---+---+---+---|
| Multi-shot capture and replay | Rebuilding equivalent semantic descriptors; unnecessary materialization of untouched capture | Each reached frame restore, hooks, view/root/grant work; shared heap effects | Saved work exceeds view/root/alias overhead for the measured invocation history; current Gambit already copies reached frames rather than always the full image |
| One Scheme winding policy | Two independently maintained scheduler-branch bodies become one common semantic definition | Scheduler-specific accessors, fresh physical grants after hooks | Both branch binding/behavior relations and native traces pass; no duplicated C winding engine |
| Backend-independent roots | Independent offset/liveness interpretations across scanner, restorer, reflector and FFI | One descriptor generation/validation and metadata retention | Count migrated consumers and physically removed authoritative interpretations; wrapper count is not a saving |
| Multi-core execution/collection | False dependence of root origin on worker carrier; unnecessary GC participation of admitted parked native calls | Freeze/publication, task accounting, exclusion, reentry and failure retention | Healthy contexts/VMs progress with selective unknown debt retained; simultaneous replay still requires alias/writer admission |
| Generational continuation reuse | For m minor rounds and eligible mature payload M, up to m*M ordinary payload visits | Barrier/log/remembered scans, promotion and still all mandatory root-domain work | Complete writers, overflow path, live-code and promotion reserve; benefit zero until implemented and qualified |
| Bounded restore | Copy only reached words across invocations, with permitted chunk bound B | Splits/dispatch, continuous headroom and per-shot effects | Do not compare B against an imaginary whole-chain-copy Gambit baseline |
| Peak memory | Shared capture storage counted once; safe reuse of physically available pre-flip intervals | Live captured images + sum of active view/transfer storage + code metadata + GC/promotion/resume reserves + pending native debt | Reuse lowers actual overlapping physical intervals before peak; post-GC refunds alone do not lower the round maximum |

For concurrent replay, one logical capture may serve separate execution contexts
only when each has independent mutable execution storage and all shared aliases
have defined access semantics. The default must not serialize all hooks behind
one VM-wide lock, but simply removing a lock does not establish multi-core safety.
The source =map= order and effects stay sequential; parallel tasks are an admitted
scheduler operation, not an automatic rewrite of arbitrary higher-order code.

Chez's single-owner stack segment in its GC generator is a useful ownership
lesson. Gambit should extend its own lazy capture, descriptor knowledge and
proper-tail mechanics into the joint contract, retaining general multi-shot
control. Guile's prompt composition supplies operator/foreign-boundary lessons.
Neither implies replacing Gambit's collector or inheriting one-shot limits.
