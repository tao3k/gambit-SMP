** Papers, selected lessons and limits

[[https://www.cs.tufts.edu/comp/150VM/modules/archive/kent-dybvig/one-shot-continuations.pdf][Bruggeman, Waddell and Dybvig, PLDI 1996]], sections 3.1--3.2, present a segmented
stack supporting both multiplicities. Capturing a multi-shot continuation seals
occupied storage; bounded copying and splitting control restoration work. A
one-shot path may avoid copies, with segment allocation/cache tradeoffs. The
lesson is representation-sensitive reuse with explicit multiplicity, not that
Gambit should discard multi-shot semantics or adopt the same segment sizes.

[[https://www.ccs.neu.edu/scheme/pubs/pldi93-sitaram.pdf][Sitaram, Handling Control, PLDI 1993]] supplies the prompt/handler lineage
referenced by Guile's implementer. [[https://www-old.cs.utah.edu/plt/publications/icfp07-fyff.pdf][Flatt, Yu, Findler and Felleisen, ICFP 2007]]
show why delimited/composable control must be designed jointly with dynamic
binding, exceptions and dynamic-wind; frame identity matters. We use these as
semantic obligations, not a claim that a call/cc library simulation preserves
all interactions. Guile's =module/ice-9/control.scm:69-78= builds shift/reset
using prompt/abort with explicit delimiter reinstatement.

All three original PDFs are hash-pinned in the source lock. Detailed source
correspondence is established only for the selected code above. OCaml remains
a selective reference for safe points and native participation; it does not
define this control contract.

** CapturedControl and FrameStore

=CapturedControl= names the logical frame chain, continuation denv, wind extent
identity, PointId, supported multiplicity and a root custodian. Its frame field
may initially refer to live stack storage. Before materialization can collect,
the source slot must already be visible to the collector. A materialized image
does not authorize withdrawing its previous roots until registration and scan
synchronization are complete.

=FrameStore= owns supported frame/denv mutations and structural link repair.
It distinguishes ordinary payload slots, control links, code labels and raw
words through FrameSpec. Every admitted semantic mutation changes the image
revision and revokes dependent issued views. A generational path records
old-to-young writes before publishing the edge, without hidden GC in the store
barrier. Overflow needs an admitted slow/fallback route. Raw setters cannot
remain an untracked parallel authority.

This does not license changing observable reflection aliases. A copy-on-write
or immutable sharing class is eligible only after alias observations, serializer
reconstruction, debugger/frame mutation and concurrent users are accounted for.
Opaque writers retain a sound explicit path; rejecting an optimization is not
permission to reject existing Scheme semantics.

** RestoreView and source revision

Each invocation obtains a writable execution view, rooted result/argument slots
and a transfer continuation. It shares Scheme heap objects by identity; it does
not roll back heap mutation when control is restored. A view can be prepared
early, but before/after hooks may mutate the target image, allocate or collect.
The commit therefore requires a current, authentically issued view; refresh
after winding may be necessary without repeating already performed hooks.

The algebraic condition is stronger than comparing two integers. View issuance
must observe one consistent image, every later writer must be represented, and
no revision wrap can alias an old reader. Lean proves coherence under those
premises. C must establish publication, writer exclusion/history and exhaustion
handling. A manufactured same-version view can still contain incorrect slots.

Version matching is not a license for a C data race. Issuance needs a real read
permission/frozen image while copying non-atomic fields; writers must exclude
those readers or use an independently valid atomic representation. A seqlock
retry around racing plain C loads is insufficient. Publish a fully initialized
view/root record with release ordering and acquire that publication before use.
Validation and restoration commit must have a writer-exclusion/ownership cut,
not a version read followed by an unprotected copy. No such image/root lock may
be held while Scheme wind hooks run. Hooks execute with rooted custody, then
the adapter reacquires permission and refreshes if needed. Unknown partial
publication retains its custodian; it cannot issue a coherent-view receipt.

** WindTransfer stays in Scheme

Gambit's existing Scheme winding algorithm remains the semantic owner. Exit
hooks run from inner to outer; entry hooks run from outer to inner; jumping
within the identical extent runs neither. Required hook effects are not work
to optimize away. Hooks can capture, throw, collect and initiate another
transfer. Their successor closures/control frames must remain rooted.

Modern C supplies generated root/checkpoint/reentry adapters, not another wind
state machine. A stale native helper cannot mutate a newer activation. Restoring
a captured Scheme hook is nevertheless legal when current Scheme semantics
permit it: it needs a fresh physical execution grant, not reuse of an expired
native permit. The finite model covers hook takeover and stale helper exclusion;
arbitrary captured-hook reinstatement remains a separate source-semantic
obligation.

** RootCut, GC and native origins

The root view includes active and captured frames, denv/winders, prompt tags,
transfer/view/result slots and code metadata owners. Moving scans update
authoritative slots; native cached pointers are surrendered before the cut and
reloaded before reentry. Captured-frame ordinary slots and structural links
retain the existing distinct write authorities. A mature captured graph can
skip a minor full scan only with complete remembered-root/writer coverage.

A =NativeOrigin= is a live C activation, not a saved Scheme frame. The target
must classify ordinary managed entry, blocking park, nested callback and return
crossing separately. Guile's register-context test is an instructive concrete
boundary, not Gambit's replacement API. Unknown native writers require retained
custody or refusal of the proposed handoff; they are not declared stopped by a
logical continuation restore.

* Delimited continuation admission
#+NAME: continuation-delimited-boundary
| Dimension | Required specification | What does not establish it |
|---+---+---|
| Extent | Prompt/tag identity and exact frame cut, including denv/wind slice | A full call/cc captured inside an escape wrapper |
| Application | Abortive or composable; caller suffix, values and exception destination | Calling every delimited operator shift/reset |
| Handler | Whether prompt is removed, and where/when it is reinstated | A physical saved stack offset alone |
| Multiplicity | Multi-shot is independent of the cut; escape-only exposes no resumable image | Reusing an escape-only path as a multi-shot optimization |
| Wind/binding | Common extent identities and effects under composition/reentry | Equality of hook closures or normal-return tests alone |
| Foreign | Actual native-origin/borrow admissibility for the selected segment | Restoring Scheme storage resurrects C state |

Introduce these operations through the same generated control/root ABI after
full multi-shot baseline coverage. Existing call/cc retains its documented
extent. Delimited control is an extension with its own semantic acceptance,
not a replacement justified by smaller copied segments.

The proposed default is explicit: installing a new prompt does not silently
shorten existing Gambit full call/cc. A dedicated capture-to-prompt operation
selects the tag and application policy. Full capture that includes prompts must
retain their logical metadata, while each reinstatement revalidates physical
execution and native authority. A prompt tag is a Scheme identity protected
across GC, not a raw address used after movement. Delimiter reinstatement for
shift/reset belongs in the selected operator specification, as Guile's wrappers
illustrate; it is not inferred from having a saved frame slice.

* Exclusive verification responsibilities
:PROPERTIES:
:CUSTOM_ID: continuation-verification-ownership
:END:

An obligation has one semantic key and one verification owner. A component may
depend on several different obligations, but no obligation is submitted to both
Quint and Lean. Shared interface data does not create shared proof ownership.
The LLM is the current working environment: source correspondence, scope review
and semantic-key normalization are part of this research, not a new LLM service
or validation layer.

Quint has no captured payload values or slot-map coherence assertion. It checks
which operation may proceed, which ticket is current, which root is retained
and which helper can return. Lean contains no scheduler or winding model. Its
single principal obligation is issued-view coherence for arbitrary slot maps
and finite histories; auxiliary lemmas support that result and a forged-view
counterexample.

=CS-BRIDGE= is intentionally separate and open: Quint abstracts payload as an
opaque ticket, while Lean assumes authentic issuance and a versioned writer
history. The source adapter must establish that a granted ticket satisfies
those premises. Two passing tools do not establish this correspondence.

[[file:../../../modeling/ascent/obligation-ownership.rules.scm][ASCENT ownership rules]] reject dual owners, renamed obligations retaining a
duplicate semantic key, wrong responsibility domains and evidence from another
owner/artifact/scope. They cannot discover arbitrary semantic paraphrases with
dishonest keys; reviewing those keys against source and claims remains ordinary
work in the current LLM environment.
