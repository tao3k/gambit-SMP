## Concrete small-refactor boundary

### R1 — make existing retirement ownership explicit

Keep the scheduler, shared heap, collector algorithm, generated frame ABI and external FFI API. At the current lifecycle/resize/recovery call sites, represent at least ExitedUnjoined, JoinedAwaitingTransfer, Transferred and TerminalRetained. Store the OS outcome with the exact VM/slot/incarnation and the existing exclusive retirement owner; a successful join is never attempted again. A generation is changed only at actual safe reuse, not as a workaround to qualify stale evidence. Preserve native error codes and partial cleanup outcomes. Runtime state and evidence observations must agree; adding a success boolean to the journal alone does not repair the runtime.

Before adding each field, audit whether the actual selected source already represents the distinction. If quiet=false after successful join is proved impossible under its legal entry premises, retain that exclusion rather than add unused machinery. Fixed arrays/pstate ownership can remain initially; there is no proposed new generic lifecycle framework.

Failure policy is resource-specific: a legal retryable error can resolve only the same live incarnation under its legal owner; terminal failure retains resources and reports failure. Root sticky failure remains terminal. Safe refusal is containment, not successful completion of an API that promises recovery. Capacity/backpressure must bound retained failures: do not allow a failing VM to consume unlimited slots, and do not free them on deadline. The capacity and native API response are design obligations not checked by the new model.

### R2 — add closure checks at actual ownership boundaries

Before clearing/reusing the current container, identify for each field: creator, root/owner, producer of future work, last scanner/borrower, transfer operation and invalidation event. Start with still/RC chains, published/private heap chunks, frame/RA interpretation state, saved/GVM/cache roots, device aliases and supported foreign-return state. A field absent on a particular legal path is discharged by an exclusion proof, not by rooting arbitrary bytes.

Use existing normal collective completion where its cohort/phase premises hold. Any finish/orphan/transfer operation that creates work must be followed by the corresponding work closure before withdrawing the producer. Root transfer must remain continuously covered through destination registration/observation. Do not call `end_heap_chunk` from arbitrary cleanup just because it closes allocation in another GC phase.

Initially retain the existing correctly rooted owner container until its exact consumers finish. Extract a smaller independent carrier only for an identified consumer that legally outlives that container; require no live backreference into reclaimed context and preserve GC interpretation. A carrier is optional, not the default rewrite. Do not copy OCaml's generational collector or Chez's entire allocation design into Gambit. Nonlocal return requires an actual live C activation; preserving heap storage cannot resurrect one. Never add a blocking mutex to an asynchronous signal handler.

### R3 — keep independent compiler and integration repairs causal

Retain the proven CLI option-order repair and numeric semantic grouping. Neither explains every runtime fault. For Gerbil, discriminate the exact failing producer and first invalid writer/root/descriptor/return transition before choosing R1/R2 or a compiler fix. Current cumulative-budget evidence does not supply a justified new optimization. No reset, unrelated reseal, alternate directory or recreated producer is a repair. The previous cost audit already excludes checkpoint overhead as the dominant component in that run; repeating it does not close an unknown compiler phase cost.

### R4 — enforce production cost and regression admission

Retirement bookkeeping belongs on create/shrink/recovery/cleanup paths unless source inspection demonstrates a hot-path requirement. Measure any new atomic/root/lock on the normal allocation/GC path explicitly. Measure churn, retained resource high-water marks, successful recovery and terminal refusal separately. Retain original limits and matched configurations. A mathematically safe retention policy that misses deadlines or grows memory without bound fails production admission. Performance is a separate acceptance step; it cannot be derived from model-state counts.

The trade-off is **bounded change to existing ownership boundaries versus the proof/compatibility risk of replacing the runtime architecture**. Delayed release and slot reuse are the selected safety cost. Extra independent carriers are an optional later space optimization with a larger backreference/root proof burden. Normal SMP execution is preserved. Finite safe retention does not establish arbitrary fault recovery or unlimited admission.

## How the first eight are protected

Protection has three independent layers; none is a shorthand for all eight being automatically preserved.

1. **Change exclusion:** no scheduler algorithm, collector algorithm, representation tags, generated frame layout, multi-shot continuation semantics, foreign API, fixture/expectation, processor population or timeout changes are part of R1/R2. If implementation requires any of these, stop and revise this bounded proposal before treating it as a small repair. C struct/header field changes still require regenerated code even with unchanged semantic frame ABI.
2. **Composed mechanism checks:** validate admitted-reader closure, future producer work, uninterrupted roots, terminal retention and independent-VM progress together. Negative controls must break a named premise and produce a decoded counterexample. This tests a local regression mechanism, not whole-language semantic equivalence.
3. **Same-source production qualification:** bootstrap -> complete GSI/GSC/PR/stress/registry campaigns, then complete remaining fault/GC/FFI/Gerbil/release campaigns on the same causal candidate. Unchanged canonical completed producers may be reused only under the existing verified binding rules. A changed candidate must not inherit gate status from obsolete binaries. Retain all historical denials and budgets.

## New QNT experiment and precise value

`twelve_gate_retirement_composition.qnt` composes one retiring cohort A and a separate VM B. It starts after A's OS exit, and checks retirement admission, existing admitted reader return, future producer work, source/destination root coverage, successful join/transfer/release, and terminal retained join failure. Normal B work can finish while A is retained. It does not represent the twelve acceptance results as booleans.

Positive initializers: `initNormal` (complete successful retirement) and `initTerminal` (terminal retained failure, explicitly not successful recovery). Both check safety plus per-action weak-fair conditional completion. Per-action fairness is needed because unrelated B work must not mask enabled retirement progress. Environment premises remain: seal eventually executes; admitted users return; producers can finish; published work drains; destination registration is supported. Arbitrarily stuck foreign callbacks, undelivered OS signals, moving GC, C atomics, FFI activation lifetime, repeated generations, capacity/backpressure and measured performance are outside this new finite model. Prior two-generation/carrier models cover separate local mechanisms, not those native premises.

Four mutations share the same transition body and invariant: allow transfer before the resource cut, drop the source root before destination registration, permit transfer on an empty snapshot while a producer survives, or call terminal error successful recovery. The runner requires the corresponding violating state in the decoded trace, not merely a nonzero checker exit. Two explicit trajectories show terminal retention while B completes, and an initially empty queue followed by newly published work before legal release.

Results are appended from actual retained checker receipts below. No model result proves all 12 native gates or establishes the cause of an observed SIGSEGV. Previous first-model terminal/retry 30-second timeouts remain unresolved; this smaller composition's results cannot relabel them.

## Decision and remaining uncertainty

Proceed conceptually with R1/R2 as the smallest credible protocol repair, subject to the selected source's actual field/consumer census. They address concrete classes of lifecycle/root/producer hazards without replacing Gambit's architecture. The independently proven CLI/numeric repairs remain separate. No evidence currently establishes that this bounded set alone cures the unbound Gerbil/native failures or meets the release cost gates. Therefore **a guaranteed 12/12 solution is not yet demonstrated**; the matrix identifies precisely what must be proved or measured before that claim is allowed. If the actual failing trace requires a collector/frame/FFI semantic redesign outside R1/R2, this proposal must be revised rather than presented as a production fix.
