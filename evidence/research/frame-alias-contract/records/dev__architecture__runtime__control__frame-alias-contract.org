* Decision and scope

Modern C realizes one Scheme-generated frame/root ABI. This study refines
=CS-BRIDGE= and =CS-WRITERS=, not another Quint scheduler or Lean image proof.
[[file:models/sysml/frame-alias-contract.sysml][SysML]] owns ten adapter premise clauses, seventeen source witnesses, six
necessary SMP criteria and the benefit matrix. These clauses are subordinate
questions of the two existing source obligations, not ten new formal duties.

[[file:../../../modeling/ascent/frame-alias-contract.rules.scm][ASCENT]] keeps located source, supplied refinement premises, native SMP evidence
and submission admission distinct. The current source has neither the complete
adapter nor qualifying native results for it. The existing QNT/Lean artifacts
and their checked logs are reused unchanged. The LLM is the working environment.

The key correction to the earlier [[file:continuation-segments.org][RestoreView design]] is its consumption scope:
coherence is required for the fragment actually restored now. An invocation-wide
frozen copy of the whole continuation is not a justified replacement for the
current lazy break-handler behavior. The full continuation remains multi-shot;
each invocation has private active frames and a rooted, not pre-snapshotted,
unconsumed tail.

The chain is concrete: capture can retain stack-backed frames; continuation-copy
allocates a shallow wrapper with the same frame and denv; reflection writes
through either wrapper; graft installs the selected frame chain and denv; the
break handler copies a reached caller frame into the execution stack. GC can
materialize the captured stack chain and later repair its roots, ordinary slots,
structural links and code references. These operations do not all mean the same
kind of mutation.

* Four identities and three distinct changes

The proposed records below are design shapes, not an implemented C header:

#+NAME: frame-alias-records
#+begin_example
WrapperSelection = { rootedHead, rootedDenv, selectionRevision, incarnation }
FrameDomain      = { logicalIdentity, rootedPayload, contentRevision,
                     topologyRevision, accessState, incarnation }
FragmentPermit   = { issuer, contextGrant, selectedWrapper,
                     orderedDependencies, metadataRoots, sourceRoots,
                     relocationEpoch, reservedDestination, completionState }
ExecutionView    = { privateActiveFrames, rootedUnconsumedTail, pendingValues }
#+end_example

Wrapper identity selects a head and denv; shared FrameDomain identity follows
actual aliased payload or a conservatively grouped segment. Execution context
identity names authoritative root slots and private active storage. Collector
worker identity names a task executor. None is a raw moving address or a synonym
for processor ID.

| Change | Logical content | Physical coordinates | Required action |
|---+---+---+---|
| Copy a wrapper | New selection record; existing frame/denv identity shared | New wrapper allocation may collect | Root original before allocation; register copied selection before exposing it |
| Reflective frame-slot write | Changes the shared domain's logical slot map | Target address may be unchanged | Synchronize store and publish domain revision; all dependent permits become stale |
| Wrapper head/denv write or next! | Changes that wrapper's selection; traversal may also repair stack RA | May change which domains are reachable | Update selection/topology under the correct permission; rediscover dependency scope |
| GC relocation or stack heapification | Preserve abstract Scheme values and control meaning | Addresses, tags, forwarding and layouts change | Update all authoritative roots, advance physical epoch and reload caches |
| Mutation of a referenced Scheme object | Preserve slot's referent identity; shared heap effect remains | Referent may separately move | Obey shared-heap memory/barrier rules; do not roll back it during continuation replay |
| Restore a reached fragment | Establish private active execution slots from the current admitted source | Copy into reserved execution storage | Retain shared source and remaining tail; no consumption of full multi-shot capability |

Two captures can overlap only in their tails. Canonicalization therefore cannot
key solely on the first frame or wrapper. Rooted live domain/segment records
must represent shared tails before cross-context access is granted. A capture
that stays local can remain lazy and stack-backed. Export to another context
requires owner freeze or completed managed materialization, with destination
root registration before source acknowledgement. The current implementation
does not yet supply this complete transition.

Domain incarnation cannot be reused while a reader, native borrower, rooted
certificate or unknown completion can still name it. Metadata is bounded by
live wrappers/domains/certificates, rather than an ever-growing alias history.
Its exact native layout, canonicalization allocation path and safe reclamation
remain source/native obligations. A design name is not an allocation solution.

** Abstract logical image, physical address map and ghost history

For one prepared fragment, the source abstraction maps FrameSpec slot roles and
rooted logical object identities into the existing Lean =Image.slots= and =denv=.
It does not map raw heap/stack addresses into immutable values. Denv identity is
not a theorem about all nested denv/winder contents. If a derived field is cached,
the adapter must explicitly cover its actual writers and reread policy.

The logical value encoding must preserve admitted equality, distinct referents,
aliasing and immediate values; collapsing distinct objects to one abstract
number would make the existing theorem irrelevant to Scheme observations.
These may be ghost identities in the source argument, not an unbounded runtime
object-ID table. FrameSpec/code-lifetime refinement remains a separate dependency.

The dependency certificate records exact wrapper selection, ordered domain
identities/incarnations, content/topology revisions and metadata lifetime. It
includes every source component actually read to decide this fragment and its
next selection. Comparing an unchecked hash, sum of revisions, head pointer or
wrapper counter is insufficient. Membership changes can make a scalar sum
repeat even with strictly increasing counters.

A coherent selection is one state between admitted updates. Separate public
head/denv setters remain separate operations; the adapter must not invent a
transaction across user calls. Operations that already perform a grouped
publication, such as an initialized shell or traversal update, need the matching
group boundary and cannot expose a half-committed record.

For a fixed certificate scope, a ghost serial order of relevant, synchronized
logical writes supplies the mathematical =ImageHistory=. It is a proof device,
not a requirement for a single global VM increment counter. Disjoint writes
may commute; the actual source relation must justify a consistent observation
cut. Revision-vector equality is useful only after authentic issuance, complete
writer coverage, membership stability and no wrap/ABA are established. Scope
change expires the old certificate and starts a newly issued scope; it is not
silently treated as the same history.

The existing Lean result can then justify a still-current issued fragment's
coherence. It does not prove that this vector/ghost-history refinement exists.
The QNT permit remains an opaque current/stale authorization abstraction within
its finite experiment. Its one aggregate capture and bounded ticket values do
not establish multiple mutators, arbitrary execution length or parallel worker
composition. No duplicate model is added to conceal those boundaries.

** C access and publication protocol

Before a shared payload read, acquire the required domain read permissions and
the current execution/GC epoch grant. Acquire/release publication must cover
initialized descriptor fields, wrapper selection and registered root slots.
When several domain permissions are required, use a canonical identity order
or restart without holding a partial set; recursive helper and callback paths
must not violate that order. No allocation, user hook, unknown native call or
collecting wait occurs while holding those short physical permissions.

A writer reserves noncollecting remembered-log capacity, obtains the proper
exclusive permission, validates FrameSpec slot role, stores the rooted value,
updates its logical revision/topology and publishes before releasing access.
An overflow retry releases permissions before reaching a complete rooted safe
point. Reacquire and reload after any GC. Initialization and collector repair
use explicit privileged paths; neither is a blanket permission for arbitrary
raw writes to live shared frames.

Revision comparison cannot legalize a payload read that already raced a plain
C write. This follows the data-race boundary in [[https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf][WG14 N1570, 5.1.2.4 paragraph 25]].
Local Scheme interrupt suppression is not interprocessor synchronization. An
atomic revision with unsynchronized ordinary payload reads is therefore not
the proposed modern-C protocol. Conservative GC scanning does not solve that
access problem either.

Complete owner-exclusive execution may use private fast paths, provided alias
publication atomically withdraws those privileges before sharing. That is a
source refinement requirement for generated ordinary stores and stack capture,
not an assumption that all existing writes are already managed. Raw C/FFI or
unclassified reflective writers keep affected optimized operations unqualified.
Any retained legacy path is explicit migration debt and contributes no claimed
retirement saving; the goal remains replacement of actual responsibilities.

** Per-fragment prepare and consume, not a frozen whole invocation

At a complete caller checkpoint, keep source selection, arguments/results and
pending transfer rooted. Preallocate permit metadata and reserve the continuous
destination span before the noncollecting copy. Prepare one fragment under a
consistent access cut, then copy it while the read permissions remain valid.
Publish only a complete private execution frame, release physical permissions
and continue Scheme execution. The tail stays a logical rooted source. When
the break handler reaches its next frame, obtain a fresh permit from the then
current source and reload all moved references.

This preserves the existing lazy observation boundary: a legal write to a not
yet restored frame can be observed when that frame is actually consumed. The
new adapter may not hide that write by eagerly cloning the whole chain at the
first continuation invocation. Conversely, modifying a saved source frame does
not retroactively rewrite a private active copy already restored. The admitted
concurrent access contract must define overlapping writes at a synchronized
copy boundary; source behavior for racy legacy native accesses is not promoted
to a portable modern-C guarantee.

A destination span that cannot fit the admitted fragment returns to the rooted
preflight point before any partial frame becomes executable. Per-copy reserve
is not a whole-round capacity proof. Unknown initialization or publication owns
the roots, span and domain debt until settlement; a timeout is not rollback.
The existing GC planner and restore-headroom dependencies remain open.

** Winding and destination mutations

Scheme computes winding destinations and runs arbitrary hooks. The final graft
macro subsequently reads the continuation's actual frame/denv fields. Thus a
physical revalidation failure must not automatically restart Scheme winding or
replay hook effects. Preserve the actual Scheme suffix and reread/reissue only
the physical fragment/root permission at its next consumer boundary. Capturing
and repeatedly restoring a hook suffix remains legal; an old C helper's stale
completion is a different identity.

All physical domain permissions are released before a hook. Rooted logical
transfer custody remains. Same-extent return can skip hooks, so every actual
physical consume needs its own permission, even when no hook ran. NativeOrigin
is validated separately; rebuilding Scheme frames cannot revive an expired
foreign C activation.

model-checked traces or native demonstrations. Existing QNT/Lean evidence keeps
its original scope.

Modern SMP means useful, correct simultaneous execution of multiple mutators in
one shared VM, with a defined shared-heap/control protocol and collection that
can progress under stated participation and failure assumptions. Gambit already
has SMP mechanisms; this study does not redefine its history as single-threaded.
The question is how to make those mechanisms compositional and dependable.

The proposed leverage is one capture representation and one Scheme control
semantics serving independent execution contexts and GC workers. Immutable
observations can be shared under read permissions, private active frames belong
to each invocation, and overlapping mutations have explicit local ownership.
Root origin survives worker migration. The carrier processor no longer chooses
which context's roots or completion phase a task belongs to.

This two-obligation adapter is necessary, not sufficient. The current source
still selects participants/completion by carrier ID, requires synchronous
worker/context binding and serializes frame work through a VM-wide gate. Full
SMP qualification also requires shared-heap stores, safe-point/membership
closure, publication/Tail accounting, weak/foreign cleanup, native participation,
capacity and scheduling progress. Those are existing module obligations; they
are not silently proved again here or by the single aggregate control QNT.

Short root-freeze/collection coordination can coexist with genuine parallel
execution; the target is not an unsupported promise of pause-free GC. Unknown
join/owner writes require real access bounds and exclusion/stop evidence. An
unknown writer into the current shared moving arena can still block that VM's
movement. Healthy-other-VM GC is useful isolation evidence, but does not prove
independent progress within the affected VM. Do not claim that a handle table
or revision counter removes this architectural dependency.

The decisive native experiment is same-VM simultaneous active contexts with
correct shared capture/heap observations, independent claimed GC tasks and
measured contention/throughput/physical peak under unchanged limits. An eleven-
processor population and a sequential map pass do not supply that evidence.
This study executes no such native experiment and claims no SMP speedup.

For fixed useful work, write the target time as serial work plus parallel work
divided by worker count, plus domain/root/GC/scheduler/failure-retention overhead.
The ideal serial-fraction bound is only a ceiling under that fixed-work model.
Net gain requires the complete new total to beat the source-bound baseline;
no serial fraction, throughput improvement or byte saving is invented here.

Domain state and live dependency metadata add storage; source payload sharing
counts once. Physical peak additionally includes active restore copies, rooted
transfers, GC/promotion/resume reserve and unresolved native debt. A refund
after the peak is not peak reduction. New canonicalization and remembered-set
paths must be included in ordinary allocation/store costs, not only in rare
capture benchmarks.

* Complete responsibility replacement and closure

The dependency-ordered integration cut is: Scheme FrameSpec/slot roles and
semantic liveness; registered wrapper/domain publication; all kernel reflection,
traversal, serializer/I/O and admitted native writers; per-fragment rooted
prepare/copy; unchanged Scheme winding with fresh physical permissions; GC
root repair and explicit task/participant mapping; generated FFI and code
metadata lifetime; then complete bootstrap and native acceptance.

Retire raw authoritative frame interpretations, per-wrapper-only invalidation,
unregistered source/address caches, global frame-copy serialization and carrier-
indexed root/completion selection only after their actual producers, consumers,
failure paths and unsupported clients are accounted for. Migrating names or
leaving both owners authoritative does not achieve the replacement.
