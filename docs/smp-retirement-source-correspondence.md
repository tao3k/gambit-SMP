Proposed helper boundaries, in existing `lib/setup.c` rather than a new framework:

- `retire_join_once(owner, ps, record)` is shared by the shrink loop in `___vm_resize_pstate` and `recover_retired_processors`. It invokes `___thread_join` only in JoinPending; on success it first records JoinedAwaitingTransfer. It returns without retrying if transfer prerequisites are not established. Legal retryable failure stays JoinPending with exact identity; unsupported/terminal failure stays retained and reported. Do not infer that every non-EINVAL error is retryable.
- `retire_try_transfer(owner, ps, record)` accepts only JoinedAwaitingTransfer of this owner/incarnation, checks/discharges the resource rows below, calls existing `___transfer_mem_pstate`, and then `___cleanup_mem_pstate` only for the resources its contract actually owns. It records Transferred once. Clearing the slot/decrementing `pending_join_count` happens once after successful discharge; any partial failure retains the record and ownership.
- These helper names designate a design. Their guards must be backed by source exclusions or actual synchronization; adding `can_transfer=true` without implementing that closure is not a fix.

### What can already be derived for the normal shrink path

In P's normal departing-processor branch, the store of handler_quiet=1 dominates ___thread_exit. P0 sets zero before publishing the shrink, and permitted slot initialization/reuse cannot run between that exit and its successful join under the exclusive-owner/no-reuse premise. Therefore a successful join of this normal departure followed by acquire-load has quiet=1. This path does not demonstrate the suspected quiet=false/rejoin bug. The unresolved part is whether every legally supported departure/error/cancellation route has that dominance and identity. Audit those routes before adding recovery states just for a supposedly reachable zero. If zero denotes an unsupported abnormal exit, consume the successful join once and retain/report terminal failure; never try the consumed join again. The enum is a clear representation proposal; a smaller consumed-join flag plus an exact per-incarnation record is sufficient if it enforces the same transitions. External signal/TTY/foreign-tail quiet still does not follow from this local proof.

### Concrete call order and lock constraints

**Resize/shrink path:** `___current_vm_resize` -> `sfun_vm_try_close(vm,target)` -> `current_vm_resize_admitted` -> `on_all_processors` -> `execute_sync_op_loop`/`___vm_resize_pstate`. Keep the existing old-cohort collective transitions. P0 reserves retiring records before OP_SET_PROCESSOR_COUNT; each departing processor removes its Scheme deque membership, releases its local interrupt/OS state, publishes local `handler_quiet`, then exits. P0 uses retire_join_once, then retire_try_transfer. All normal/throw paths reopen SFUN admission exactly once through the existing wrapper. Do not close the process registry and wait in `pthread_join`: a departing worker can still need interrupt delivery. Do not add a VM-wide stop-the-world lock around the whole OS join.

**Later pending recovery:** `___vm_resize_pstate`'s existing pending branch (P:4714–4725) lets P0 service pending records and every participant return before entering a new resize barrier. Keep this shape; do not make only P0 enter a new collective while peers have returned. JoinedAwaitingTransfer skips the OS call. A remaining pending summary returns an error; safe retention is not resize success.

**Owned child VM destruction:** `___cleanup_owned_vmstate` -> recover pending before registry closure -> require one processor and no unresolved retirement -> `sfun_vm_try_close(vm,0)` -> lock `vm_list_mut` -> registry close/drain -> `cleanup_pstate_locked(P0)` -> `cleanup_vmstate_locked` -> registry reopen -> unlock -> replay. This ordering already exists in P:5441–5480. Keep error-path reopen/lock release. Root VM is explicitly excluded; public void cleanup retains its separate terminal policy. Origin/direct users must already be joined (**X**). Counts zero do not establish that precondition by themselves.

**Startup rollback:** `___setup_pstate` constructs interrupts, OS/memory and sync resources in stages; `cleanup_failed_pstate` uses `os_mem_ready` and root-P0 exceptions. Preserve these stage distinctions. A setup failure before a thread was created is not a join-pending retirement. A create-success/startup-failure has a real thread and requires its own join record. Cleanup must release only successful constructions and only after the applicable users finish; do not overload a single phase with partial OS/device release success.

## Gate 10: source-specific transfer boundary

### Pre-exit and failed-join premise that the earlier model did not prove

The earlier retirement composition starts after OS exit. A failed pthread_join does not establish that exit occurred, that the target is still joinable, or that it stopped producing roots/work. Consequently it cannot be used to qualify a pending worker as post-exit merely because memory is retained. P's pending resize branch returns before starting a further resize, which is useful, but that is not by itself an exclusion of ordinary allocation-triggered GC.

Before mapping a failed join into the model, prove the exact OP_SET_PROCESSOR_COUNT/cohort handoff: no retiring member executes new Scheme work or GC-relevant release callback after being removed from the participant/root population; all its live roots/private work are either already transferred or still visible to a supported scanner. P calls cleanup_interrupts_pstate on the retiring side, whose request release invokes execute_fn(..., false); the API must either prove these legal release callbacks cannot create such work there, or move their GC-relevant work into the existing collective before withdrawal. We have not established that exclusion. This is a source-correspondence obligation, not an observed native corruption trace.

The concrete lifecycle design therefore also distinguishes ExitRequested/exit-not-yet-established from JoinedAwaitingTransfer. The existing local handler_quiet can be one exit-side witness, but its post-cleanup store does not substitute for the cohort/root handoff. Do not solve the gap by prohibiting all GC while waiting: the pending worker or release callback may need GC to finish, producing a deadlock. Preferred bounded repair is to complete legal root/work publication under the existing old-cohort protocol before withdrawal, preserve its source-visible ownership on failure, then use the join/transfer phase ordering above. If that cannot be shown for a legal callback path without changing its API semantics, this path needs an explicit API/ownership design decision. A new checked boolean alone cannot supply it.

Current `___transfer_mem_pstate` is accurately described as a still-list/word-counter/RC-list transfer. It does not move r/saved/cache, continuation frames, private copying frontiers, wills, queue borrowers, C activations or global handler code. This scope is directly proven by its body; whether each omitted resource is live at this legal boundary is not proven by omission.

The bounded design is therefore a per-row discharge at retire_try_transfer, not wholesale memory copying:

1. Prove donor OS thread exited/joined, supported raw producers and origin invocations completed, existing registry/SFUN intervals closed as applicable. These are distinct resources and not a single `handler_quiet` predicate.
2. Establish completed relevant old-cohort collective/GC phases, including dequeued scan return and no remaining producer capable of adding work. For ordinary resize the existing return/aggregation bridge is evidence to reuse; for exceptional/nonlocal paths supply a separate source exclusion or owner retention.
3. Classify L10–L15 values as dead/excluded, already traced elsewhere, or actually transferred. For transferred strong roots, install them into an existing scanner-visible receiver root location while the source is still covered; preserve registration through a collector observation contract. A root field in an unscanned retired slot is insufficient. No need to invent a new root ABI if existing registered RC/other root storage suffices; confirm its scan phase and ownership before choosing it.
4. Splice still/RC lists once using existing MISC_MEM_LOCK with no collector observer concurrently traversing inconsistent links; release lock; clean the now-empty donor resources; keep sync objects needed by slot reuse; publish released record/count last. Avoid waiting for borrowers while holding the lock they need to finish. Error retains the container and its roots/ownership record, not just bytes.
5. At final VM cleanup, destroy persistent sync/interrupt resources only after their rows discharge, then free VM memory/sections. Existing `cleanup_vmstate_locked` iteration is a construction-resource inventory, not proof that every row is quiet.

## Must change, already present, and unresolved decisions

**Must change in this retained representation:** exact per-incarnation recovery/result attribution; separate OS-joined from transfer completion or prove the retained post-join quiet branch impossible and simplify accordingly; a single shared one-time retirement helper contract across the shrink and recovery paths; source-backed discharge or explicit refusal for every applicable consumer before free/reuse. The latter may be a proof of an existing boundary, not added counters.

**Already present, preserve:** pthread return-code repair; staged construction flags; slot-persistent sync resources; registry close/readmission/flush; SFUN enter-close handshake; active root scanners; publication barriers and same-phase GC termination; normal collective result/return protocol; marker-allocation root protection. None should be reimplemented based on an abstract model that forgot it.

**Decisions/proofs still needed:** actual legal error retry classes; whether successful join can observe quiet=false; complete current-producer field liveness at resize; old cohort exclusion on abnormal/nonlocal paths; root visibility while retaining an unscanned slot; origin-owned outer invocation guarantee; process-global signal/device/code lifetime. These cannot be fixed by labeling terminal retention success or adding a generation to already dangling pointers.

The new QNT experiment is a local source-order discriminator: an empty FIFO can coexist with a live scanner, and a zero SFUN frame count can coexist with a pstate-using error tail. Correct resource-owner cuts exclude early frees. It does not claim those overlaps occur in a supported native teardown; actual cohort/joined-origin exclusions may already prevent them. Those exclusions, when proven, remove the need for new counters and keep this a small refactor. All runtime implementation and native acceptance remain deferred.
