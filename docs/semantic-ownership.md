# Semantic Ownership

The research consumer executes one exact source-bound Library entry: DSL source
definitions, an Evidence constructor, a compiled module or a declared component
composition. Decoded relation/rule dictionaries are inspection/proof transport,
not an alternative research execution language. `ascent_program.evaluate` rejects
that fallback. Queries, replacement, withdrawal and reuse belong to the retained
Scheme session; Python transports facts and renders the returned answers.

## Action Catalog

`evidence/dsl/actions.ss` generates study actions and their prerequisites from
study, hypothesis, capability and exact source-binding observations. It derives
support, missing premises and explanation gaps. Python validates path/SHA/pointer
identity and duplicate study IDs before transporting observations, then projects
the native answer. It separately enforces host permission, state revision,
request reservation and the sealed execution contract.

This does not authorize experimental execution. A proposed action and declared
support do not establish causal review, retry eligibility or source refinement.

## Remaining Migration

These paths are still open and must not be disguised as transport:

- Library `EvidenceChain` now transports the Scheme `evidence-dag` plan. SCCs,
  canonical rule identities, dependency fingerprints, rule lowering and retained
  path selection are implemented in `program/evidence-dag.ss`. Python still owns
  completed-session handle transport and clears its retained records on source
  replacement. This migration requires the matching new compiled Library.
- The finite proof bridge `assemble` now sends the complete catalog, facts and
  requested relations to the Scheme `slice` action. Its lossless-projection
  requirement remains a proof boundary, not a result boundary. Missing Library
  capability fails explicitly; the Python dependency traversal is removed.
- Graph-validation and Recipe eligibility observations need an explicit audit of
  which facts are measured versus which policy decisions remain in the adapter.
- Qualification must use a durable generic inventory/receipt contract, not a
  new Python research producer or temporary driver for each mechanism.

The first two are implemented but not yet fully qualified through the new ABI,
sealed review and complete current graph. The two offline structure tests have
been moved to actual Library integration controls, not omitted. Eight source
GxTest contracts passed in 2.779/15 seconds with unchanged bound inputs; earlier
JSON-contract and hash-table-identity harness errors remain archived. This is
not whole-consumer acceptance. Keep all negative controls and provenance checks
during direct migration.
