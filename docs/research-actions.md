# Agentic AI Research Actions

The first consumer is Agentic AI. There is no TUI, numbered menu or second
execution framework. `gambit-smp actions` transports structured requests through
`discover`, `select` and `observe`; execution uses the existing sealed kernel.

## Evidence And Explanation Contract

Each action now includes a structured `explanation`: transitive required and
missing premises, supported premises, reused exact path/SHA/pointer references,
same-input failures, and satisfied premises whose provenance is unbound. ASCENT
derives `Need`, `Missing`, `Supported`, `ReusedEvidence`, `ExistingFailure` and
`ExplanationGap`; Python only resolves already-bound reference identifiers.
References to Scheme/C source bytes use the empty pointer for the entire file.
JSON references retain their exact RFC6901 pointers. These are declared supports,
not per-row causal proofs, research-value rankings or host authorization.

`Observation` alone no longer closes an open prediction: it requires an
`ObservationEvidence` reference in the current explicit evidence inventory.
Withdrawal of that reference reopens the prediction. Even a bound observation
does not establish a hypothesis, coverage or refutation. Those conclusions need
separate typed semantics; a missing observation is not a falsifier.

`ActionEvidence.qnt` adds bounded reference withdrawal and non-refutation checks
to the existing request protocol model. Checked and mutation wrappers explore
missing references and false refutation; the existing unauthorized, stale,
duplicate and false-cause controls remain separate. Finite simulation does not
prove unbounded scheduler fairness, source refinement or experimental efficacy.
Actual source/receipt correspondence and retained-owner withdrawal/restoration
are additionally exercised through the real SIGBUS consumer and Library ABI.

The CLI-Agent versus ASCENT-Action-Agent study remains unperformed. It must bind
the same incident, source/evidence inventory, model version, host authorization,
tool capabilities and original time/token budgets before paired trials. Retain
all failed/censored trials and raw provider usage. Count effective experiments,
unchanged retries, tokens, evidence-backed attribution milestones and actual
repair success separately. Source anchors, proposals and model PASS are not
experiments or successful repairs. No efficiency or success-rate improvement is
claimed from component tests or from the protocol model.

## Contract

`discover` accepts an explicit inventory of repository-relative v2 Recipes and
an optional sealed engine path. It returns their actual scope, capabilities,
unchanged original budgets, input schema, prerequisite gaps and a state revision.
The import-free `evidence/dsl/actions.ss` derives prerequisite closure and rejects
recorded failed actions with unchanged source identities. Python transports facts;
it does not implement a second inference engine.

Study actions are now generated by the same declarative program, not an adapter
branch per action. `StudyDeclaration` and `StudyHypothesis` produce
`StudyActionSpec` and `StudyExpected`; the adapter reads their IDs, operation,
subject, risk, admission boundary and expected evidence. `StudySourceBinding`
only supports a premise when its study matches and its exact reference is in
`EvidenceReference`. Source withdrawal retracts support; withdrawing the study
retracts its generated actions. `Capability` observations are separate from host
authorization. In particular, generating a dynamic-origin action does not add a
kernel capability or authorize running it.

Recipe observations and graph-validation observations still have their existing
typed transport contracts. This migration is not a claim that every adapter
policy or every Library compatibility path has been migrated.

`PREFLIGHT_READY` means that the declared recipe passed schema checks and a seal
was checked with its capability inventory. It is NOT retry eligibility, native admission, authorization or a
claim that every execution-time gate will succeed. Missing inputs fail discovery
closed; unsupported diagnostic capabilities are not invented as executable actions.
The recipe scope is preserved, including mock/component-only boundaries.

`select` accepts the discovery snapshot, action ID, exact input object (currently
empty: execution parameters remain in the reviewed Recipe), and a canonical UUID
request ID. Host authorization is a separate API argument, not a JSON field an
Agentic AI can use to grant itself permission. The CLI authorization option is
for a trusted host adapter; this interface is not a security sandbox.

The adapter rediscoveries and compares the revision before execution, then reserves
the request in a short SQLite transaction. A duplicate UUID with different content
is rejected. A matching duplicate observes the original request, never relaunches
it. Requests are committed before side effects; exceptions retain a failed result.
No database transaction spans inference or execution. The local request ledger is
not Evidence admission, a published history analysis or a budget authority.

`observe` returns the retained request and its result, rehashing and inspecting
terminal kernel receipts. An unfinished request is `PENDING_OR_INTERRUPTED`, not
an assertion that a process is still running. A completed execution can still
have a DENY outcome. Observation neither retries nor publishes acceptance.

## Python And CLI

The Python API is `gambit_smp.research_actions.discover/select/observe`. A discovery
request has this shape:

```json
{"recipes": ["evidence/research/source-schedule-revalidation/control.recipe.json"]}
```

Without an engine, the returned action is blocked by `sealed-engine`.
Run `gambit-smp actions discover --request context.json` to emit the snapshot.
Selection has `snapshot`, `action`, `inputs` and `requestId` fields. Observation
has a single `handle` field. No downstream Scheme import or compilation is added.

## Qualification And Open Work

The protocol model `models/library/ResearchActions.qnt` covers finite revision
drift, explicit authorization, request reservation, at-most-once launch, failure
and non-executing observation. It does not prove native admission or fairness.
Tests pair real ASCENT prerequisite withdrawal/restoration and failure inference
with transport fault controls. Mocked executor tests do not qualify real execution.

This first action contract exposes declared Recipes, not a complete scientific
diagnosis system. Hypothesis proposal assets, competing predictions, evidence-value
explanations, crash-origin capabilities, multi-step intent revalidation, cancellation,
portable request archives and a full current-graph regression remain separate work.
No local result from this interface closes the overall ASCENT/Gambit acceptance gates.

## Scientific investigations

The structured interface, not a TUI, is the Agentic AI entrypoint. ASCENT
derives candidates, transitive missing premises and discriminating observations;
the Agentic AI chooses their research value. Only the existing sealed kernel
can admit experiment execution. Neither discovery nor a prepared proposal is
causal evidence, retry approval, permission or candidate acceptance.

`context.studies` names explicit `research-study.v2` data assets. Each source
reference binds an original document SHA and RFC6901 pointer. Correspondence
equalities check selected PID/binary identities; missing exact source bytes
block source inspection rather than substituting a nearby candidate. Hypotheses
declare predictions, falsifiers, coverage requirements and limitations. An open
prediction means no observation is bound in this declared inventory, not that
the observation is absent from the world or the hypothesis is false.

`failureReferences` declares which exact referenced integer fields are process
exits. ASCENT derives nonzero `FailedEvidence`; transport does not classify every
integer (for example a PID) as a failure. These existing failures inform the
explanation, while unchanged action-route blocking and the kernel's typed native
retry review remain distinct checks. Historical v1 receipts are not upgraded.

Optional `context.observations` is an explicit path/SHA/pointer inventory into
`research-observation.v1` records with `study`, `observation`, `sourceSha256`,
`receipt` (path/SHA/pointer) and `value`. The value must equal the original receipt
field and the source must match the selected study. Observation keys are scoped
by study to prevent cross-investigation leakage. This establishes recorded byte
correspondence only, not measurement validity or sufficient coverage. References
withdrawn from the current inventory reopen predictions. None of these records
authorize execution or establish scientific refutation.

`evidence/scenarios/sigbus-origin/study.json` binds Diagnostic 010's actual
compiler SIGBUS and incident. Inspect and design actions are recorded-only.
Allocation extent, payload layout and lifetime/ownership remain competing
proposals. Exact mem.c bytes were recovered from the local candidate011 input
cache and independently matched to the Diagnostic010 source SHA, then frozen in
`patches/snapshots/010-child-bound-mem.c`. Static tracing exposes eight exact
reference/extent/copy/forwarding/scan anchors, not a complete runtime provenance
chain or a claim that both entire candidates match. No first-producing-operation instrumentation capability is implemented
by this adapter, so its proposals cannot launch a debugger or retry a compiler.

`context.graph = {"model": "gc_recursive_queue_wait"}` exposes full current
graph validation. It requires a real engine seal and calls the existing
agent-context path with an outer **whole 300-second** watchdog covering all
validation and graph generation, not a fresh budget for each phase. Its receipt
includes actual exit, timeout, process teardown and raw log SHA. Observe checks
the complete graph again; source/backend drift is STALE. A framework PASS never
establishes runtime acceptance. Failed or interrupted requests remain retained;
an unchanged failed action is blocked and a duplicate UUID never launches twice.

### Audit boundaries

The legacy snapshot `CausalEvidence` rule currently joins Cause to any Reusable
claim without a specific failure/claim contract. The current projection emits
no Cause facts; the action interface does not consume this rule as permission.
Strengthening that relation requires a typed correspondence contract and
independent controls, not filling it with a text hypothesis. Native retry policy
remains independent. Multiple campaign disposition rows are not an exclusive
state machine: all explicit action prerequisites must hold, and any bound
blocker dominates execution, without blocking authorized read-only inquiry.

No token savings, optimal experiment ordering or SIGBUS root-cause discovery is
claimed. A future matched Agentic AI evaluation must retain failed/censored
trajectories, measure effective experiments and invalid retries at equal budgets,
and separate architecture benefits from actual repair outcomes.
