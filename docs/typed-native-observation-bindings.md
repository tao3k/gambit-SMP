# Typed Native Observation Bindings

`evidence/native-observation-bindings.json` is a separate transport inventory,
not a rewrite of historical receipts. Schema `gambit-native-observation-bindings.v1`
binds the entire canonical failure inventory SHA, each original receipt SHA,
one record and process event, and exact RFC 6901 field pointers. Unknown identities,
changed bytes, mixed events, wrong types, fixture substitution and duration-as-budget
are rejected. Python transports schema/hash/pointer values; `evidence/catalog.ss`
uses the upstream native Scheme/ASCENT evaluator to derive observed failure
categories, mismatches, missing fields and unregistered model references.

These facts are recorded observations, not normalized suite DENY receipts,
causal reviews, retry eligibility, complete native admission or authorization.
A positive exit under an assertion-labelled inventory row records a failed process;
it does not independently prove the assertion's cause. A negative signal exit is
matched against the original declared signal. A timeout remains recorded even
when its original cap is missing; the budget gap remains visible.

The nine retained observations bind embedded stdout/stderr where present.
The original core process log is independently bound by its actual receipt
pointer and file SHA; changed log bytes fail closed. Normalized suite DENY
receipts cannot select this observation-only transport to bypass strict controls.
The build timeout has an actual `seed-core` stage, argv, `budgetSeconds:180`
and `wholeBudgetSeconds:180`. The inventory's `Makefile:core` label is not
substituted for that stage. Other snapshots lack explicit original budgets;
their elapsed seconds and descriptive inventory status are not budgets. The
ninth observation has a real parent `processBudgetSeconds:30` field; this
process-scoped cap is transported, not inferred from its 30.004-second duration.
Parent `accepted:false` is allowed for a nested process when the original record
does not repeat it. Exit/timeout still come from that exact nested event.
Reported identity digests are not reconstructed complete runtime-tree identities.
Producer, environment, topology and complete runtime identity gaps remain open.
An observed teardown value is not a independently verified process-group receipt.

Three changed-candidate or different-fixture positive references stay in
`observed_control_reference`; none enter `local_control_pass`. Existing strict
same-source/runtime upstream-suite control checks are unchanged. Standalone QNT
links bind current source bytes but do not establish a check or source refinement;
unregistered links remain explicit native query results.

The new queries keep results, provenance bindings and gaps separate. No rule
derives runtime admission, source refinement, release or retry permission.
No provider rebuild, seal mutation or dedicated Python experiment producer is
needed: the already-qualified native API loads this research Scheme Fragment.
Fragment remains a composition unit, not the exclusive Evidence language.

Full graph export also depends on valid protocol-bundle schemas. Working audited
and corrected three missing `composes` declarations as actual standalone QNT
models, without converting checker dependencies to composition proofs. This is
an independent data correction. A successful export still does not establish
fresh full graph validation; that requires its own matched complete receipt.
