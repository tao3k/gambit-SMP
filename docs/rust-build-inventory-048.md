# Rust Transport and Build Inventory 048

## Implemented Boundaries

The local `gerbil-scheme-python` bridge owns `OwnedValue`, exact Python integer
transport, boolean separation, bytes/nested data, structural decoding bounds and
positive host-sized optional ceiling validation. ASCENT uses this transport
instead of another Python conversion implementation. Owned trees do not encode
cyclic/shared object identity; provider handles retain owner/generation checks.

`ResourceTree::file` and `stage_source_inventory` own generic complete per-path
source publication. ASCENT's Cargo build script declares source inputs and calls
that API. Installed `ascent.build.runtime_identity` verifies packaged sources,
not an SDK, compiler, checkout or original build-machine resource path. This is
a local authorized bridge path dependency, not a published Git revision claim.

Rust DSL work includes computed heads, scoped pure functions, numeric columns,
string/symbol conversions and strict string comparison. `eq?` currently accepts
interned symbols and immediate booleans; heap/numeric identity is explicitly
unsupported. Explanation templates needing an unsupported result-object binding
report a gap without blocking relational execution. No Scheme fallback is used.
