# RFD Benefit Matrix: C-G, C-ZT and Zig

Reviewed: 2026-10-20. Reporting matrix for the real
[return-frame planner component](return-frame-planner-case.md), grounded in its
[evidence ledger](return-frame-planner-evidence.md). No implementation, native
test, timing or engineering-hour observation. This is not a weighted scorecard.

## 1. How to Read the Report

**B0** is the inspected Scheme/C descriptor path. **C-G**, **C-ZT** and **Zig**
implement the same proposed RFD contract/algorithm. C-ZT keeps the C core and
uses the same selected downstream Zig driver; that driver is outside RFD.
Only actual common work cancels. Different downstream LLVM versions are not
an admitted controlled performance comparison merely because they accept IR.

Statuses below concern attribution/evidence, not pass/fail native admission:

- **S — shared mechanism:** available to all three through the reconstruction.
- **L — local mechanism:** bounded language/library expression advantage;
  selected economic value remains conditional.
- **Z — no credit:** the claimed Zig-specific mechanism is absent in this scope,
  or the purported support is unnecessary. This is not a measured zero seconds.
- **U — unresolved:** an empirical magnitude or required design/capability is
  not established. No favorable direction is silently assigned.
- **A — added/substituted work:** name and account for the incremental owner;
  no hour value is invented.

## 4. Decision Matrix and Reversal Conditions

| Decision | Sufficient condition | Current evidence | Reversal / stopping rule |
| --- | --- | --- | --- |
| Continue RFD contract reconstruction | Required runtime descriptors are preserved and shared decisions remove selected emitter coupling | Necessary source chain is identified; extraction/decoder admission remains open | Reject design if it loses mandatory roots, kind-specific coordinates or real consumers |
| Select Zig for RFD alone | Recurring private-work saving lower bound exceeds marginal migration/core support upper bounds versus the small checked C control | No such bound; no required visitor/growth/bignum family exists in chosen topology | Do not adopt on this slice alone if remaining saving is zero or insufficient |
| Select common Zig downstream tool | Required driver/distribution capability has an admitted net benefit independent of planner language | CLI source recognizes IR/bitcode; target/version/end-to-end value not qualified | Retain language-independent choice; do not use tool selection to force core rewrite |
| Select a larger Zig subsystem | Independently necessary neighboring component supplies additional disjoint support savings, with shared costs charged once | Separate open research, not an RFD result | Do not extend this matrix into a whole-compiler or GC/VM claim |

**Present report:** RFD is a justified reconstruction target with shared
mechanisms. It does not provide a demonstrated positive Zig-language ROI.
The small C core is now a concrete counterdesign, rather than a hypothetical
assertion that C can somehow do everything. A positive claim must identify
remaining private work it beats, using FM01-FM06 and the full marginal costs.

No percentages, hours, runtime ratios, weighted score or adoption approval is
issued. Native and performance evidence remain separate later phases.
