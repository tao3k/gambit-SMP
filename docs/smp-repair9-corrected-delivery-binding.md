## What the new C guard proves and cannot prove

The guarded append still has the following literal assignment consequence. Starting from `head=A, A.next=B, B.next=null, tail=B`, re-enqueueing **A** passes `tail!=A`, sets `A.next=null`, sets tail=A and sets `B.next=A`. Traversal from head now visits only A; B is orphaned although its link points back to A. The new guard correctly rejects re-enqueueing **B**, the already-tail node. Processor locking serializes these assignments; it does not prevent a semantic alias supplied by a caller.

Thus a production fix must establish *why each node is detached before enqueue*, or detect and reject an invalid ownership transition without pretending a reply occurred. Dropping a self-loop or retrying a still-owned node does not supply that proof. An unconditional redelivery after a scan count, dual queue links and a CAS around the thunk do not preserve all queue/root/reply invariants; the retained failed experiments must not be promoted to a working design.

## Minimal request-specific evidence, still not activated

Keep the existing six-surface observation design and private Scheme descriptor; do not add a native strong-root registry or raw-pointer identity. Request identity remains `(session, VM incarnation, nonwrapping serial)`, causally nested parent and activation IDs, with moving object references reloaded through the rooted mutex. A per-hop transfer intent and destination acknowledgement distinguish publication from its last consumer.

1. **Sender:** construct/first-owner complete, second-lock attempt, actual sender BTQ insertion, reacquire or supported error, final consume. Start at the blocked sender's BTQ container; confirm it is R rather than a join/other mutex. Log current result-mutex state under its lock; specific is no longer necessarily a target after reply.
2. **Route/migration:** R/request token, old/current processor, migration-target, pinned target, BTQ container, routing snapshot/recheck and chosen destination. Preserve the original target identity before specific becomes a result. Record failed/retried lock attempts separately from ownership publication.
3. **Transport:** under existing queue lock retain enqueue before/after head/tail/next identities, ownership transition, pop's captured next and local activation acknowledgement. Cover both C processor pop and Scheme thread pop. No queue scan or rescue loop in the proposed hot path.
4. **Dispatch/nesting:** actual current-thread versus original target, reroute before action or action entry, suspension/migration, parent/child synchronous wait relation, action return/error. Unfinished local dispatcher frames remain consumers even with empty queues.
5. **Wake/reply:** distinguish raise intent, flag/pipe effect, handler dequeue, result store, unlock commit, sender BTQ removal, resume action and runnable-queue publication. One wake is not one reply; zero wake is valid for early reply. A void-resumed mutex waiter must retry, not report completion.
6. **Terminal/final consumers:** target abandonment, original sender error/value consumption, dispatcher return, restored activation and nested child closure. Close only when all relevant consumers release; the root-bearing Scheme objects are reclaimed by normal GC. Writer/reader drain and overflow/torn-event status remain part of the evidence carrier's own release boundary.

Classify R by its last *acknowledged* transition: no queue commit → sender/route; queue commit without pop → destination/wake; pop without action/reroute → detached dispatcher; action entry without completion → callback/nested wait; stored result without unlock → reply lock; unlock without runnable publication → mutex wake path; runnable without reacquire → scheduling/restore; reacquire without consume → caller/error. Missing coverage yields UNKNOWN at that boundary. Aggregate counts cannot reconstruct these tokens retroactively, and this audit does not activate instrumentation.

## Unified QNT value and limits

The maintained `interrupt_request_lifecycle.qnt` now includes bounded delivery state in the same state record. A two-node intrusive processor queue, detached consumer, thread reroute, target move/recheck and separate notification feed into the existing action/result/reply/root/nested lifecycle. The unrelated second queued request must stay reachable. The receiver that accepts token 1 hands it to the existing lifecycle and completes one action, one reply and one caller consumption in named trajectories.

New negative initializers distinguish six different failures: sleep after consuming a wake while queue debt remains; re-enqueue a non-tail owned node; publish one node to both queues using the same link; accept a stale/unrechecked destination; claim no outstanding request despite a detached local; discard that local before delivery. These are decoded violating states, not boolean “model passes”. Positive trajectories cover mismatch reroute, migration then recheck, wake without reply, detached ownership and a harmless already-tail retry. Existing once/reply/GC/nesting/opaque-exit controls remain regression obligations on the changed model bytes.

This model deliberately requires a single transport owner and a safe sleep predicate. Those are exactly the native obligations still needing source refinement and R-bound evidence; they are not granted by model validation. It proves neither scheduler fairness, arbitrary C memory safety, all GC maps, full source-to-binary correspondence nor native 12/12. It helps reject incomplete repairs: fixing replay leaves at-least-once delivery open; a wake does not repair a lost link; a tail guard does not establish unique ownership; empty queues do not exclude detached consumers.
