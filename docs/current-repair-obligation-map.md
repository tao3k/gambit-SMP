## One Library, Distinct Obligation Bundles

Each actual gate needs a dedicated **declaration bundle**, not its own ASCENT
engine, Python workflow, numbered state machine or proof framework. One bundle
may contain several independent clauses, and a clause can support several gates.
An unknown gate-to-clause association must remain unknown, not a guessed cause.

Reuse the existing interfaces:

| Concern | Existing owner | Required declaration or observation |
| --- | --- | --- |
| Gate and clause identity | Scheme `requirement`, `dependency`, `contract` | Stable semantic IDs; complete acceptance clauses and their scope |
| Model applicability | `make-modeling-guidance`: `assessment`, `model_assumption`, `proposal_change`, `scope_review` | Exact model revision, covered premise, changed premise and unproved correspondence |
| Source combination | `make-parallel-gc-review`: `composition_edge`, `model_interface`, `interface_check`, `composition_binding` | Actual source-to-source handoff, checked property and independently supported correspondence |
| Completion and reuse | Library checkpoint fragment via `make-checkpoint-state` or `make-modeling-guidance` | Receipt, bindings, support declaration and completeness witness; material/custody remain separate |
| Progressive discovery | Registered view, existing Scheme association and Clue exchange | Gate/clause/candidate factors, source references, counterevidence and expandable model links |
| Host observations | Existing Python transport and execution adapter | File/tool identities, process results, real progress and quiescence; no semantic gate inference |

These are available vocabulary owners, not a claim that the missing connections
are implemented. In particular, `related` exposes a reference; `dependency`
states a required support premise. Do not use one in place of the other.

## Gate Dossier Checklist

Every remaining gate must expose the following through the same registered DSL:

- Its semantic identity, definition source and independently witnessed acceptance
  inventory. The inventory may legitimately be empty for a particular supported
  branch, but absence of a declaration is not an empty-inventory witness.
- Candidate source/patch/configuration, toolchain and executable identities.
  Historical completion, current applicability and reusable material are separate.
- Clauses with source anchors, assumptions, counterevidence and unknowns. A
  source hazard without an observed failure remains a conditional hazard.
- QNT transitions/invariants/progress assumptions and Lean lemmas relevant to
  each clause, including what they do not prove. No mandatory fresh model per
  gate: a performance measurement is not replaced by a theorem.
- The actual failing run and its producer, original fixture/inventory, observer
  effects, completion/timeout semantics and last verified execution frontier.
- A repair hypothesis with discriminating observations, source scope and explicit
  falsifiers. Changed premises can justify revisiting a failed path; a historical
  failure is information, not a permanent prohibition.
- Source repair and acceptance evidence bound to the same relevant inputs.
  Model checks, diagnostic success and native acceptance never substitute for
  one another. Dependencies reused from a checkpoint need applicable support;
  a query checkpoint never grants execution or native credit.

An inspection should return the selected clause, its present support/counters,
missing premises and expandable references. It must not return a deterministic
`next` operation or constrain the Agent's hypothesis space.

## Composition And Research Milestones

The whole path needs shared interfaces, not a Cartesian product of every model.
Trace only actual shared contracts: caller/VM/processor incarnation, root and
private-work ownership, publication visibility, admission/withdrawal, exceptional
exit, last access and reclamation. A relation must identify the relevant source
profile and property, not just connect two documents with a hyperlink.

Separate four forms of connection:

- **Runtime dependency:** a consumer genuinely requires a producer's ownership,
  roots or visibility guarantee. Compose the relevant existing QNT transitions
  and check the transferred assumptions, including abnormal paths.
- **Acceptance dependency:** release admission needs current correctness; each
  gate needs its complete declared inventory. This need not serialize profiling
  or independent investigations.
- **Hypothesis reference:** a root-retirement hazard may help explain a Gerbil
  failure, but remains a reference until source/trajectory evidence connects it.
- **Execution reuse:** a prior stage can be reused only under its actual support
  contract. An unrelated model update does not by itself invalidate a binary;
  changed relevant source does not inherit old native acceptance automatically.

Research milestones are deliverables, not a mandatory Agent execution order:

1. **Identify:** the four semantic contracts, actual candidate and required
   inventories are queryable; unresolved ordinal mapping is explicit. Correct
   the ninth-item status without overwriting historical evidence.
2. **Connect:** each open clause reaches existing QNT/Lean coverage, source
   premises, counterevidence and the specific observation still missing. An
   anchored query and checkpoint continuation must exercise the registered path.
3. **Discriminate:** a proposed small repair has mechanism-level counterexamples,
   source correspondence and falsifiers. Extend only the missing mechanism in
   existing models. Lean proves stated conservation/order/composition lemmas,
   not the authenticity of an unobserved native event.
4. **Handoff:** provide the implementation session with the bounded source
   Recipe and original acceptance obligations. Only its real source-bound
   qualification closes a native gate; this research does not repeat its runs.

Mechanism redesign that adds a general root carrier, host admission capability
or different collector protocol remains in Experimental. A current defect that
can be closed within existing semantics belongs in these current-repair bundles.

## Acceptance Of The Connection

This refinement is complete only when the following are actually demonstrated:

- The exact gate inventory distinguishes eight completed contracts from items
  9 through 12 under repair, without modifying old results or losing partial
  successes. Canonical IDs, not table order, determine a gate's identity.
- A relevant anchored query reaches the registered obligation and applicable
  sources; direct constructor tests alone are insufficient. Unregistered or
  unsupported clauses remain visible as gaps rather than disappearing.
- Withdrawing a source, completeness witness or model-scope binding exposes the
  corresponding gap and never awards native completion. Restoring it restores
  support; unrelated updates do not erase independently applicable history.
- A fresh process reuses the query checkpoint, exposes changed counterevidence,
  and preserves applicable execution receipts after disposable material cleanup.
  Missing build products do not erase historical achievement or invent runnable
  artifacts. No unchanged stage is rerun merely to reconstruct a progress count.
- One real repair can be followed from failure through model/source reasoning,
  patch and original native acceptance. Until that occurs, the connection is
  research/framework work, not closure of item 9 or any later native gate.

No runtime change or new formal campaign is justified solely by the absence of
a connection. First make the already available evidence usable and identify the
actual unsupported premise; extend an existing model only if that premise is
outside its current abstraction.
