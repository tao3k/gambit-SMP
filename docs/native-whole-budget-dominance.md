# Whole Deadline Dominance

## Problem And Evidence Boundary

The complete Grid must not omit the four historical PR regression fixtures.
Earlier atomic campaigns selected 379 files and applied a 300-second cap to
each batch; the newer whole campaign selected 375 files. Neither multiplying
the old batch cap nor relabeling a partial suite as complete is valid.

A complete containing suite can impose a strictly stronger deadline: every
original file must occur in the current selection, every current file must
complete in the same mode, and its preparation/compilation/execution interval
must fit inside a whole cap no larger than the original atomic cap. Therefore
every constituent interval is also below that cap. Original nested file/group
caps remain separately required. This is conditional retry correspondence, not
an old whole-mode timing claim or SMP/runtime admission.

## Model And Framework

`native_whole_budget_dominance.qnt` keeps a finite original/current/completed
inventory, mode binding, preparation interval, nested caps, clock expenditure
and acceptance state. The positive verifier exhausts 1,540 distinct / 5,225
generated states with an empty queue. The bypass policy has an actual
counterexample; four trajectories retain scope omission, detached preparation
and overrun controls. Both verifier checks remain below their 15-second caps.
The previous exact-regime model and its counterexamples remain unchanged.

Python transports original/current file members and the actual whole suite
deadline. Scheme DSL determines nonempty coverage, missing members, compatible
regimes and numeric dominance. It rejects larger caps, missing files, unbound
preparation and absent causal review. This extends the existing framework and
restricted Scheme policy; there is no new runner or MCP-specific logic.
