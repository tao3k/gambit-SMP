Continuation escape, dynamic-wind failure, startup before helper registration, abrupt-exit semantics and unregistered native callers still need explicit contracts. Unsupported raw faults retain state/fail closed; they are not normal recovery paths.

## Concrete ordering and root coverage

1. Late helper registration after Scheme threading readiness publishes a traced per-VM record (proposed unused VM slot 2), not an unscanned C payload. Acquire a unique P0 execution claim without holding native/VM locks across user callbacks. A worker request must not use the existing immediate-P0-throw operation.
2. P0 records primary exit intent before jobs/wills. Persist the detached queue cursor and current callback/error ownership. Run callbacks with the full old cohort available for nested GC; no irreversible count reduction or root removal yet. Current action/testator/error/suffix roots must be updated by every GC.
3. On ordinary callback failure stop further callbacks under the chosen policy, preserve untouched suffix, and enter the same landing. A recursive nonreturning exit must transfer control to the coordinator boundary; a normal return into the interrupted callback is not an implementation.
4. Invoke the already-studied safe-point/collective protocol. Preparation failure uses old membership for GC and common abort, restoring original owners/root coverage. Success publishes one survivor owner only after collective/work/last-consumer closure. Shutdown disposition of saved runnable work is an additional requirement; ordinary resize activation is not automatically valid shutdown cancellation.
5. Permit final raw P0 host return/exit only after retirement and all required last consumers complete. At each actual `___run` boundary finalize its initialized marker exactly once; never invalidate an invocation that may still return to Scheme. Raw native fault before landing remains retained unsupported context, rather than being marked complete.

Source guarantees that can be reused: matched return-to-C restores its specific frame/R0; P roots marker procedure across GC; VM structure fields are scanned; queue callbacks have explicit detach/pop semantics; P fixes known sync-aware locking and explicit migration ownership. None proves the proposed worker escape boundary, status policy or all-path native unwind safety. These gaps prevent a sufficiency claim and a 9/12 upgrade.

## Unified QNT: executable trajectories, exhaustive proof blocked

The experimental [single model](../models/gambit/retirement_exit_landing.qnt) extends the shutdown state machine with P0/worker exit intent, two callback GC opportunities before retirement, failed job/will disposition, repeated exit, landing permission and per-host-marker states. The existing two-donor, repeated-GC/two-epoch handoff remains in that state machine. Packed exit digits are an IR-size experiment, **not a native representation**; [field metadata](../models/gambit/retirement_exit_landing_fields.json) decodes both packed and renamed fields. The [trajectory module](../models/gambit/retirement_exit_landing_tests.qnt) imports that exact model.

Typechecking passed for the final model hash. TLC was **not reached**: Quint-to-Apalache RPC decoding rejected an IR string longer than the existing 20,000,000-character limit. The attempted nested record, flattened fields, unused-initializer projection and packed-exit record did not remove that blocker. The historical reserved-identifier type error and repeated earlier-source attempt are retained. No RPC/capture/timeout limit was raised and no framework was changed. The previous 83-check shutdown result belongs to its own model hash and is not reissued for this model.

Nineteen selected mutation initializers include old root/context controls plus early worker throw, lost detached suffix/error root, replayed failed job/consumed will, recursive cleanup, early host exit, missing/double/uninitialized/returnable marker finalization, worker exit before finalization, cleanup failure bypassing landing and replacement of primary status. They are **written but not decoded/validated as counterexamples** because the first positive compilation failed. Ten planned positives and nineteen negatives therefore remain unproved.

Named TypeScript trajectories are recorded separately. An initial unfiltered test invocation selected no named runs; it is rejected as evidence. Follow-up explicitly selected each named run and required `1 passing` for each. These demonstrate concrete modeled paths only; they are not exhaustive safety/liveness or native refinement proofs. See [validation summary](../evidence/research/smp-retirement-study/exit-landing-validation.json) for actual accepted counts, exact hashes and preserved failure runs.

The next formal step requires a justified smaller abstraction/compositional correspondence that fits existing limits, not repeated compilation of unchanged oversized IR. Before runtime implementation, the controlled worker return, callback escape compatibility, typed suffix disposition and C finalizer error matrix must also be refined. There is no claim of a complete landing-pad solution or a cure for the new TFIB SIGSEGV.
