## Decision and trade-off

Prefer an explicitly rooted **parked owner through commit**, followed by one survivor Scheme activation. Do not insert an allocating Scheme queue operation into the closed C commit interval. Before commit the saved donor thread is reachable but absent from every runnable queue. After common success the survivor owns this parked descriptor, and a Scheme completion helper activates it exactly once. After common abort the original processor restores it exactly once. No callback side effect is rolled back or replayed.

The price is a small but real control-flow refactor across setup.c and the Scheme interrupt/resize wrappers, plus a persistent typed descriptor and a completion obligation. Existing thread-save/restore, frame scanners, RC/still splicing and scheduler queue primitives remain. This is smaller than replacing the collector or frame ABI, but **not** a C-only cleanup patch. A postcommit activation failure cannot be converted into precommit abort: retain a rooted committed-pending record and retry/dispose by explicit policy; never resurrect departed processors. The positive model assumes this helper terminates successfully. It does not prove that native allocation/lock/wake failures are recoverable.

**Offer priority is a required detail, not solved by adding one flag.** Existing lower encoded sync operation wins; RESIZE=2 precedes GC=3. A suspended parent resize frame is not itself an active offer, but repeatedly advertising an outer RESIZE while helper GC needs service would starve it. A proposed preparation-wait offer must yield to GC, retain the transaction obligation without consuming it as terminal NOOP, and stop only at the authenticated common decision. Never return an internal token by abusing an SCMOBJ error code. The finite model schedules GC explicitly; it does not verify the C opcode arbitration implementation, memory ordering or barrier generations.

## Scheme/C crossings and admission boundary

A valid crossing is `C service -> completed-round internal request -> Scheme helper -> same-epoch C service`. This is not normal user/API return. Store phase, current helper claim, typed descriptor and error in persistent rooted state; do not retain `sop_ptr` pointing into a C frame that has returned. Restore the generated register context before Scheme execution, and spill it again before reentry. Freeze ordinary donor scheduling, not synchronization service. Release queue/processor locks before any path that can collect, call external code or wait for another cohort member.

P0 initiation is a separate case: its current path is inside `___current_vm_resize` called by c-lambda, not necessarily inside the interrupt wrapper. Implementing only a donor interrupt hook leaves P0 activation unreachable. A bounded begin/poll/finish Scheme wrapper, or a correctly generated C-to-Scheme completion bridge, must be selected and proved. Existing SFUN macros (header:10043–10056) allocate a stack marker and call `___call`; they are not an allocation-free magic return into Scheme. Their foreign origin, root, error and admission semantics require audit before reuse. In B c_intf.c:6511–6547, marker creation calls `___make_vector` and explicitly notes the unresolved protection of `proc_or_false` across that allocation; this source TODO is a reason to audit rooting, not a new observed native failure.

Direct C/shutdown callers have no automatic Scheme wrapper. Either prove a supported completion bridge for them, or reject an active-donor shrink **before C2** under an explicitly narrowed API contract. The latter is safe refusal, not sufficient coverage of an inventory requiring that success path. This study does not silently assume every caller reaches a Scheme helper. The registered-C positive below exercises error-result rooting on an abort, not direct-C successful migration.

## Persistent ownership / last-consumer ledger

| Resource | Owner before C3 | Success last consumer / release | Abort last consumer / release |
| --- | --- | --- | --- |
| Epoch/request and helper claim | Resize descriptor; exact epoch + donor/processor incarnation | Unique activation acknowledgement and external result consumer; retain across join error | Every old member's common abort, original-thread restore and caller result |
| Saved Scheme thread/continuation | Actual scanned thread/continuation root; private nonrunnable reservation | Survivor parked root -> destination queue/current-thread root; release extra anchor only after successful publication | Original processor current-thread/active frame root after THREAD_RESTORE; release anchor afterwards |
| Stack-backed frame storage | Donor stack plus typed saved-continuation edge | Full current GC copy/private work/tails before withdrawal, independent of later OS join | Remains valid; full restore makes original execution active again |
| Arbitrary native C activation | Original OS thread; excluded/held by actual admission contract | Must already be discharged; never migrated as bytes | Same OS thread until supported unwind/return completes |
| Callback X and untouched Y | X popped/in-flight until actual return; Y queue-owned | Each required false callback once; never reread freed X | Never replay X; resume untouched Y only under independent liveness contract; opaque invalid suffix stays retained |
| Strong still/RC and weak/will lists | Old participant list owners through full GC closure | Typed splice/exclusion + per-slot transfer state before count change; do not transfer twice after join | Keep original ownership; do not attempt to undo arbitrary callback effects |
| FIFO/private copying/scanning work | Original cohort scanners and msections | Full old-cohort return before C3; new helper GC starts fresh using reduced population | Old cohort remains available through helper GC and original restore |
| Movable result/error | Traced descriptor until final read | After activation, reload -> no-GC PSR1 bridge or explicit registered C root | After restore, same final-read rule; catcher/local C variable alone is insufficient |

The descriptor root handoff and scheduler execution-owner handoff are different operations. In the model a captured representative thread stays `runOwner=parked` across count reduction. Success publishes once only after common commit; abort restores once only after common abort. Another root may coexist for reachability; another runnable/active owner may not. There is no rollback from successful activation to old-cohort membership.

## Unified QNT correspondence and limits

`retirement_safe_point.qnt` extends the previous unified relation: two donors, two epochs, two full preparation GC rounds, callbacks/suffix/error roots, captured/private work, plus a full **third** helper GC in each epoch. Abort helper GC uses P0+A+B; successful activation helper GC uses only P0. All arrivals and full epilogue acknowledgements use current `(epoch,round)` equality. This is one state machine; the importing test module only supplies named trajectories.

`h` is the explicit Scheme/C control location: 0 C before capture, 1 Scheme capture, 2 C preparation, 3 survivor Scheme activation, 4 activation complete, 5 origin Scheme rollback, 6 rollback complete. `he` authenticates helper epoch; `pc` counts successful publication; `rr` records original restore; `blocked` is a negative-control loss of synchronization service. These are model fields, not proposed native field spellings. The emitted field-name map preserves semantic names while shortening long identifiers under the existing compiler output bound.

| Model action / invariant | Concrete obligation |
| --- | --- |
| yieldCapture / reenterPreparation | Completed-round internal yield; valid generated context; persistent request/root; same-epoch reentry. Does not assert current void service function already supplies this. |
| saveDonorThread / publishThreadAnchor | Existing save and typed root semantics under exclusive scheduling admission. |
| commonCompletion | C3 publishes membership and outcome, but does not publish runnable execution or authorize final API return. |
| yieldCompletion / requestHelperGC | Exact-epoch completion helper; preserved parked root; GC service on the outcome's actual cohort. |
| publishRunnableOnReceiver / pc<=1 | Success after C3, original owner never restored, one queue activation, no second invocation on retry. Actual queue update/lock/wake is abstract and must be refined. |
| restoreThreadOnAbort / rr | Abort after C3, old cohort retained, one original restore, no destination publication. Actual nonlocal Scheme jump must replace C fallthrough. |
| helperDone guard on leave/result | OS join/result error cannot bypass the pending execution-owner completion. This is a proposed ordering, not an observed guarantee. |

Seven additional decoded controls reject publication before common commit, restore before common abort, unrooted parked completion, stale helper epoch, helper loss of GC service, repeated activation and API exit before helper completion. Prior negative controls remain. `initHelperStopsGC` violates an explicit service-capability invariant; it is **not** an executed OS deadlock witness.

The detailed frame/activation token is one representative donor. Multi-donor callback/ack interaction is explicit; arbitrary simultaneous saved threads and survivor topologies are not enumerated. The helper's internal claim/queue update is atomic in this model: partial link updates, claim races, lock ordering, interrupts and wake failures require C/Scheme refinement and native controls. Full helper GC is deliberately scheduled before final activation/restore; possible collections inside a partially updated BTQ are not admitted by assumption. Proving the native critical section cannot collect, or refining the model to its actual intermediate states, is mandatory.

## What still prevents an executable sufficiency claim

1. **Control transfer construction:** generated safe-point/helper entry for donors **and P0**, exact internal-vs-external return, persistent request storage, one-time parent offer consumption, GC-prioritized wait arbitration. Current source has no complete path.
2. **Helper critical-section refinement:** prove existing BTQ operations' generated code and locking do not poll/allocate/throw while links/claims are inconsistent; prove wake/claim retry and all postcommit errors preserve the rooted pending descriptor. Atomic model publication is a contract, not this proof.
3. **Abort continuation refinement:** original-thread restore must jump once to the correct saved Scheme continuation with correct interrupt/lock state; preserve error/catcher ownership and untouched suffix. Callback side effects are not reversible. Unsupported corrupted suffix/native origins require explicit containment.
4. **Complete donor/caller census:** idle/foreign/Scheme/SFUN/initiator/direct-C/shutdown cases, actual thread/deque/will roots and all private borrowers; independent VM and the first eight gates must stay valid. Rejecting an unsupported caller is not proving the required successful path.
5. **Native synchronization and capacity:** real epoch/incarnation reset/wraparound, visibility and races, original-budget cost of extra GC/helper service, causal native fault/GC/FFI/join tests and complete 12-gate acceptance. No budgets were enlarged and no native timing improvement is claimed.

The finite model's value is specific: it discriminates a rooted parked execution owner from a runnable owner, forbids early API completion, and makes old/new GC membership at the Scheme/C crossing observable. It removes the previous model's precommit runnable-publication shortcut. It cannot manufacture a missing P0/direct-C control path or turn a finite conditional-completion pass into production sufficiency.

A descriptor allocation before thread-save must keep the still-active generated context rooted and able to service GC. The model starts capture from an available helper context and adds explicit GC after capture and in completion; it does **not** separately execute allocation failure/GC before the first typed-anchor publication. That entry interval, thread/processor lock order, and atomic root-anchor replacement still require generated-code or finer-model evidence. Similarly, `h` represents one detailed donor/survivor completion token, not a complete simultaneous per-member helper implementation.
