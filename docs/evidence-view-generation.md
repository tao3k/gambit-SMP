# Source-bound Evidence view generation

`research.view.source.json` is the authored Zig research declaration. The generated
view and its binding receipt are produced through `tool view-materialize`; a hash
edit in the generated JSON cannot substitute for generation. Full graph collection
checks the authored declaration, generated bytes, producer source and receipt.

Local source locators pin reviewed bytes. A changed source requires an explicit
`ascent.source-binding-review.v2` record: immutable `before` and `after` identities,
a scoped review reason, retained claim scope, and every affected citation ID.
`--review-source` checks both identities and the actual current source before
changing the authored pin. A Git identity includes repository, full commit,
path, blob and SHA-256. Uncommitted bytes belong in the existing task execution
checkpoint, authenticated through its complete prefix and payload digest.
Legacy v1 baseline/patch reviews are rejected by the normal review entry.

An independent semantic author can publish a non-admitting declaration update.
`--adopt-reviewed-view` checks the exact review/input identity, old fact retention,
explicit reviewed value changes and new claim/reference inventories before
importing it. A concurrently changed output causes publication to fail its
compare-and-swap check. Regeneration must never erase a concurrent owner's facts.

External Git sources retain their exact declared revision and dirty-source
checks, but no source, baseline or patch is copied into Evidence. Committed bytes
use Git identities; dirty bytes use the existing task checkpoint journal. The
view carries an explicit immutable identity alongside its source label, so the
reader does not mistake historical bytes for the current working file. No
external checkout is modified. A local checkpoint alone is not portable Git
publication evidence: a fresh consumer needs the authentic journal, or an
explicit rebind of the exact bytes to a committed Git identity. Missing custody
fails rather than starting an empty history or accepting current file bytes.

The same entry's `--migrate-source-storage --out .cache/source-migration`
maintenance action migrates every legacy review and generated source-copy
reference. It retains original records and the migration plan through the
existing checkpoint, regenerates maintained views with the real producer, then
removes redundant copies. Interrupted migration resumes the same plan and
rejects concurrent edits. The migration manifest keeps an identity resolver for
every removed artifact; historical success fields do not become current passes.

The producer loads the candidate through the real Evidence loader and evaluates
its queries with the actual ASCENT engine. It publishes only after rechecking all
inputs and the expected old output hash. Binding/query validity leaves missing
requirements and blocked model/runtime obligations open. It is never native
recovery or build/test admission.

Use the existing work item and its reusable Evidence process:

```sh
gambit-smp --task repair-9-12 --process evidence tool view-materialize \
  --source evidence/scenarios/zig-native/research.view.source.json \
  --expected-view-sha <observed-old-view-sha> --out .cache/view-generation
```

The expected output hash is a concurrency precondition, not a source review. Add
`--review-source <record>` or `--adopt-reviewed-view <record>` only for an actual
reviewed delta. Historical failure receipts and original model-author acceptance
fields remain unchanged.
