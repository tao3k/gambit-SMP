# Rust Graph And Evidence Entry Migration

The new public relation-composition object is `Graph`, with
`Engine.source_graph`, `project`, `union`, `join`, and `open_session`.
It describes an immutable relational operation graph, not a research action
plan. There is no `Plan` alias, `source_plan`, or Scheme module-name dispatcher.
Composition and admission run in the Rust Library. Python transports values
and owns leases; independently opened sessions survive graph-handle closure.

The execution Evidence entry now binds `evidence/dsl/execution.ss` through
`evidence/research/execution/entry.json`. Active recipes declare both files.
Old receipts and historical entry files retain their original identities.
The `module` capability, compiled Scheme source registry, and `open_module`
consumer route have been removed, not adapted into compatibility layers.
`build_sources` validates all actual build inputs without inventing module names.

Explicit `object-graph` DSL data retains cycles, shared references, tables,
uninterned symbols, and opaque observations. Opaque observations do not grant
access to external resources. Program observation carries owner namespaces;
reusable Catalog projection still rejects unsupported identity-bearing values.
Result execution and explanation metadata are separate contracts.
