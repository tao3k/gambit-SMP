# Recipe Continuation Contract

Continuation is not a completed producer and does not erase a failed run.
The shared execution framework owns the eventual capability integration;
Evidence/Scheme DSL retains causal review and acceptance decisions.

## Implemented Boundary

`recipe_continuation.remaining_budget` observes byte-bound, terminal,
quiescent sealed receipts and counts outer execution, including teardown.
Duplicate identities, changed bytes, non-finite/invalid expenditure,
non-quiescent observations and expanded caps are rejected. Exhaustion cannot
be turned into a fresh budget. Its result explicitly does not admit a
producer or qualify prefix reuse. The focused tests cover these boundaries.

## Required Before Prefix Execution

1. Bind the immutable original request, seal, full step inventory, all failed
   observations and cumulative expenditure. Do not omit an intermediate run.
2. Bind each reusable step's complete declared and observed input closure,
   configuration, generator dependency closure and tool identities. A new
   engine does not automatically authorize an old generator's output.
3. Validate typed output descriptors and complete inventories, including
   modes, links, extra files and source ancestry. A PASS label alone is not
   reusable evidence. Reject legacy records lacking the closure contract.
4. Invalidate at the earliest changed or failed step and its consumers. A
   changed review intent may not invalidate unrelated source work only when
   the framework proves those separate dependency closures.
5. Transfer through the existing checked storage interface, never hardlink
   mutable outputs. Recheck original and transferred bytes before and after
   use; record reuse without changing the old receipt or artifact type.
6. Carry the remaining cumulative deadline into review, bootstrap, output
   checks and teardown. Mandatory negative controls cover source/config/tool
   drift, output tampering, missing/added files, path escape, failed or
   non-quiescent prefixes, missing expenditure, budget exhaustion, missing
   generator dependencies and review/budget bypass.

None of these obligations may be replaced by manually copying a seed into a
completed-runtime record. The accounting helper alone does not close them.
