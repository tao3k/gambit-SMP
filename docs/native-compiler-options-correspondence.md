# Historical Compiler Command Correspondence

## Purpose And Boundary

The numeric compiler probe timed out in C-to-dynamic-module compilation after
successful Scheme-to-C generation. Its original raw log records GNU GCC O1;
the current resize-grace producer's configured dynamic driver uses O0. The old
receipt does not bind a driver digest or raw-log digest. This interface does not
invent either binding, infer parent success, or attribute the failure to GC.

This is a distinct command-evidence transport, not a build-driver change with a
fabricated historical driver identity. Lower optimization can reduce compiler
work but is not evidence of runtime performance or SMP correctness. Release and
Gerbil performance qualification remain separate mandatory gates.

## Checked Chain

The semantic `numeric-compiler-phase-history` archive preserves the exact old
receipt and identity. It validates the historical generated C digest before
archival and records that the C artifact was checked, not copied. Portable logs
retain the explicit command projection without personal paths. An additional
command-association review is mandatory because the original receipt did not
bind that raw log.

`compiler_options_change` validates the archive, exact failed receipt, unchanged
Scheme fixture, current admitted GNU compiler and actual configured driver
bytes. It requires one literal dynamic optimization assignment and a dynamic
command using that binding. The returned observation is data, not acceptance.

Scheme DSL only recognizes this change for an original C-module budget failure,
a reduced optimization level, complete causal and command-association reviews,
matching campaign and unchanged scope/deadlines. It cannot waive Scheme-phase
failures, assertions, signals or expanded budgets.
