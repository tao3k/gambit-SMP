# Stable interrupt delivery and an independent wait-return contract

2026-10-23. Research only, native **8/12**. The design criterion is now structural stability and explicit failure disposition, not minimum diff. Runtime edits remain unauthorized. This extends [accepted hard-failure consumers](smp-repair9-accepted-hard-failure.md) and preserves the existing failed profiles, source hashes and native qualification.

## Architectural decision

Use one delivery protocol across request publication, scheduling, park, wake outcome and retirement. A thread request lives only in its authoritative mailbox or a mapped active invocation; a processor event carries a hint/sequence, never that request's intrusive next link. A wake byte/event is not evidence of request completion. The waiting processor must recheck durable work/control/fault state before committing park and after every return. Its owner cannot destroy the wait instance until writers, selector, fault observer and accepted-request/terminal obligations have their explicit outcomes.

This changes scheduler and OS boundaries together if necessary. Keeping the existing broken split merely because it produces a smaller patch is no longer the objective. It still does not justify a whole collector rewrite or unsupported external-C lifetime promises. Existing host joined-owner contract A is reusable; optional concurrent-owner contract B remains a separate API undertaking.

An independent bounded wait-return is the most directly source-mappable baseline to study. It can be combined with a dedicated kernel event backend later for idle efficiency. **The bound must be armed before every potentially indefinite wait.** Enabling a short timeout only after a remote writer discovers failure cannot alter a syscall already asleep. This is a fault-observation guarantee under OS return/scheduling assumptions, not a fix for a previously orphaned request and not an unconditional shutdown theorem.

## Candidate mechanisms and costs

| Mechanism | Failure independence / necessary ordering | Performance and compatibility cost | Decision |
|---|---|---|---|
| Retry same pipe, stack trip, P0 error collective or primordial scheduler-error interruption | Still relies on failed channel/interrupt delivery; no independent return from already blocked OS wait | Small diff but no new progress guarantee | Reject as hard-failure closure |
| Dedicated rescue pipe/event | Different object can carry persistent wake; register it before wait and keep it alive through final consumer | Extra descriptors/handles per scope, setup rollback and close/grace; failures can share the same cause; needs a defined second-channel-failure policy | Useful backend option, not unconditional proof |
| Per-thread signal plus atomic signal-mask/wait protocol | Must cover check-to-sleep race and signal arriving before syscall; no Scheme/GC in handler; target thread identity must remain live | Signal ownership/coexistence with embedders, platform mask/handler management, syscall/backend changes, delivery error handling; POSIX-only and requires current Darwin evidence | Alternative requiring deeper platform qualification; plain pthread_kill + select is insufficient |
| Internal finite native wait quantum q, armed before park | Return no longer depends on successful pipe write; after q recheck durable state at correct lock boundary | Every fully idle processor wakes roughly1/q times per second; more syscall/setup/device scan work; no extra request allocation. Need timer/error classification and platform implementation | Preferred reference contract for independent observation; q is an unchosen latency/idle-cost parameter, not an increased test budget |
| Unified native wait backend plus finite fallback | Durable event/sequence avoids healthy-path periodic rescans where a proved backend permits it; prearmed finite fallback still bounds observation of an event-trigger failure | Larger coherent OS/scheduler refactor and generated ABI/object invalidation; platform-specific tests, fallback idle cost remains unless a stronger backend guarantee replaces it | Stability-oriented target, with semantics established before backend tuning |
| Host supervisor retains or terminates failed VM/process | Does not require fabricating a target reply, but owner must really receive fault through an independent path | Changes embedding failure contract; process termination is not graceful Scheme completion | Explicit terminal policy option, not native9/12 success |

The cost estimate is symbolic: for N continuously idle processors, q seconds per internal wake yields approximately N/q extra returns per second in the no-event case, plus clock/timeout/set preparation and scheduler checks. Work arriving earlier usually ends that wait early. This is not a measured throughput, latency bound or acceptable q selection. Stable performance needs matched idle-energy, wake-latency, CPU-bound and I/O-deadline measurements from one producer. No timings or benchmark results were generated here.

Apple's archived [select manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/select.2.html) documents finite timeout versus indefinite wait and EINTR. The archived [pselect manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/pselect.3.html) describes temporary signal-mask replacement and an old libc-wrapper implementation. These are interface/design references, not evidence that the current machine's implementation has a qualified atomic signal-to-wait handoff. Current target qualification is still required. No kernel failure or unbounded scheduling delay is converted into a wall-clock theorem.

## Proposed protocol and exact ownership

1. Under target T, publish request once to the thread mailbox. Under destination P, publish runnable work and increment its durable `wake_seq`. Migration transfers runnable ownership under the existing lock-order contract and rechecks destination; the request node never enters a processor hint queue. Correct normal ticket-grant acquire separately.
2. Before OS park, under the P publication protocol sample `park_seq`, validate no runnable/control/mailbox debt and establish one wait-instance selector claim. Release P and use the prearmed native return facility. A publication after the validation cut must be covered by transport success or independent return; it cannot depend on a second queue owner.
3. `___device_select` retains the **real** absolute deadline and device-relative poll requirements. Compute a separate internal wait interval. Internal expiration is a recheck reason, not device timeout, negative user error or synthetic interrupt completion. Preserve ready bits for genuine events. A private reason enum may replace overloaded error codes; otherwise a proof must cover all code-ignoring callers and EINTR handling. Do not mutate public API timeout/budget/fixtures.
4. On return, finish native drain/outcome/instance copy; `___os_condvar_select` completes its condvar lock protocol; `##wait!` finishes idle-list work. Devices path additionally finishes its P-held checks and unlocks. Only then claim the matching sticky fault/control record. A record copied under a live scope is scalar; any Scheme target/error/suffix remains in traced ownership.
5. A hard transport fault moves its delivery domain Healthy -> Faulted -> Quarantining. New external entry uses its existing owner contract; do not reinterpret accepted work as rejected. Stop new park on the invalid transport, preserve runnable/mailbox/active roots, and elect one fault coordinator with an atomic claim. The coordinator does not synchronously send itself or primordial another result-mutex request to obtain authority.
6. At mapped resume checkpoints, obligations safe to execute may finish normally. Target cancellation requires the real authorized ordinary-thread termination path. Primordial/VM disposition instead enters a refined exit landing while the old cohort and saved roots can still service GC; captured jobs/wills errors and remaining suffix need explicit policy. If that boundary is unavailable or raw C unwind is opaque, retain the domain and report noncompletion to its actual owner. Do not make retention look like reply, abandonment or recovery.
7. Close routing/admission and wait all **actual** consumers, per resource: old wait FDs require original/nested wake writers through outcome publication, selector through drain/native return/condvar restoration, no old-instance re-park and matching observer acknowledgment. Closing those FDs does not free accepted requests or VM storage. Queue mutex/pstate/VM destruction additionally waits active callback through its post-call loop work, pending release batch through final callback, mapped request execution/real abandonment, old cohort/private GC work and nonreturnable host markers. If fault quarantine closes only the broken pipe while keeping the domain alive, split that operation from broad `___cleanup_os_pstate`; do not run whole pstate cleanup on a still-owned domain. A stale epoch report cannot acknowledge a new instance; sequence wrap needs refusal/quiescence rather than ABA reuse.

Suggested private state is a wait-instance identity, durable wake/park sequence under its publication lock, sticky immediate fault code, fault-domain phase/coordinator claim, and any lifetime counts not already established by joined-owner/cohort/registry guarantees. Add a native internal-return reason to the per-call select state if needed. A new Scheme helper gets compiler-generated maps; no raw native field can hold an unscanned SCMOBJ. These are proposed representations, not installed fields. Direct API/ABI migration must occur in one producer, with every real caller and initializer covered.

## QNT value and remaining sufficient conditions

New `independent_wake_return.qnt` specifies independent observation, not installed OS behavior. Four candidate positive profiles cover prearmed slice, atomic signal, healthy spare channel and separately authorized disposition. Ten negatives distinguish fault-only slice, signal-before-plain-select loss, early device timeout, reporting while P held, stale acknowledgment, close before writer return, erased fault, unrooted observer, fake completion and both channels broken. Five named trajectories keep return/observation separate from completion. Model `close` closes only the old FDs after its writer/selector/observer episode, not the retained domain/queue/VM storage. The projection has no new old-instance park after closure; a real implementation must establish that quarantine cut. Internal return, fault observation and terminal completion are separate state fields; legal terminal authority is an explicit unimplemented premise.

This does not replace the authoritative-mailbox QNT, the accepted-terminal projection or callback/FD models, and their separate passes do not constitute a composition theorem. New checks are deferred until production custody naturally releases. Typechecking, TLC positives/decoded negatives and any selected trajectories must bind exact bytes and unchanged caps before a result is admitted. No new model PASS is claimed here.

A sufficient production claim still requires: (a) source refinement of unique ownership, acquire and every block/park/migration cut; (b) a real independent-return backend covering every blocking caller and its same-instance lifetime, with no early deadlines; (c) mapped fault dispatch with legal owner/coordinator, not arbitrary-thread throw; (d) ordinary/primordial/raw-unwind terminal policy and all-path root/marker/last-consumer closure; (e) explicit supported OS/foreign-callback failure envelope; (f) integrated model checks and native failure-injection/normal controls, followed by unchanged first-eight and complete same-producer qualification. The goal is structural repair of the delivery protocol; no amount of broader code motion alone proves those obligations.
