# Preparation protocol: dispatcher, abort and root-owner refinement

2026-10-22. Follow-up to commit `2211f9d400b65ecfeeb4b154004b8b43da0a36b1`. Research only; native acceptance remains 8/12. B and P retain the pinned identities defined in [the preparation design](smp-retirement-prepare-phase.md). No runtime implementation or other worker is changed.

## Correction: election priority is conditional evidence

B setup.c:1067 copies the current invocation's `*sop_ptr` into a local offer. B:1099–1108 consumes that invocation's request only after `execute_sync_op` returns. However, a nested `on_all_processors` supplies its **own** `sop_ptr` (B:1131–1149). There is no source evidence here of an automatic enumeration of suspended C frames as pending election offers. Consequently the earlier parent-replay mutation proves the consequence **if** a member reoffers the parent resize; it does not establish that the current callback path necessarily reoffers it. The priority comparison (B:584–590, 618–624) alone cannot prove that reachability.

The implementation obligation is precise: each old member must enter preparation service with the parent request consumed/suspended once, and must never resume an outer loop that offers RESIZE while peers still prepare. Saving the parent result and its owner remains necessary. Whether this requires a new operation or a carefully delimited existing resize subloop depends on a concrete dispatcher implementation and refinement trace. The model's `parentEligible=false` is a proposed guard, not an already proven runtime fact or an observed runtime defect.

## Abort boundary with another donor still running

The one-donor model's callback==Failed does not imply all callbacks in a real VM have returned. For a multi-donor implementation, P0 records the first error but continues collective service until **every** old member has either completed its active callback or entered a supported caught-failure path. A ready/failed donor remains available for another donor's nested GC. Failed is not Exited, and an abort acknowledgement must not mean permission to leave early.

Use an old-cohort decision round to establish the closed frontier: producer admission closed under its actual supported contract; all active callbacks returned/caught; all member progress and current roots published; no member can subsequently request preparation GC. An earlier local `gc==0` observation is insufficient. A pending GC wins over decision; a callback that can still allocate prevents this frontier. Only after every member reaches the frontier may a common abort completion authorize return and SFUN admission reopening. No claim of termination is possible for a stuck callback under unchanged budgets.

Abort preserves cohort membership and scanner registration, not a byte-for-byte pre-call world. Uncalled detached requests require an explicit policy: reattach only a known-live never-invoked suffix under its queue mutex and supported ownership contract, or retain it under a scanner-visible phase owner for defined later disposition. Do not blindly requeue the invoked request. If a legal callback can invalidate another suffix node or close a resource required by continued old-worker service, retaining the cohort alone is insufficient; that callback contract must be restricted or the failure must be classified as terminal retained. This semantic decision is still open, not covered by the existing successful abort check.

## Root coverage through success and abort

1. Before any allocating callback, establish a scanned owner for the suspended thunk and each potentially movable saved error. Native RC allocation is a candidate with a narrower non-Scheme allocation path, not proof of arbitrary callback rooting. Initialize/publish it before entry to service.
2. Through preparation and abort, retain each donor's original **registered locations**. Another donor's GC must update them. Registered receiver locations may coexist; consumers reload current values rather than restoring old addresses.
3. Defer destructive donor root withdrawal until a global **success** decision. A donor's local Ready is insufficient: a later failure on another donor must not require reconstructing the dropped source. Ownership transfers that remain monotonic on abort are an alternative, but need a different explicit proof.
4. On abort, discard temporary receiver roots only after old-source coverage remains current, all callbacks have returned and both publication/consumer sides complete the common abort cut. Preserve any error/result root until the outer caller has consumed it. Clearing all phase roots when the first error arrives is unsafe.
5. Strong roots, weak/will lists, private GC work and active C continuations retain separate discharge obligations. Registering a strong RC root for everything would change collection semantics. No whole-state copying is justified.

## What the existing QNT proves and what it does not

The committed `retirement_prepare_phase.qnt` remains unchanged with its original receipts. Its three positives and seven mutations demonstrate single-donor/single-GC obligations. In particular, `dropDonorRoot` is allowed after local successful callback completion, and `beginAbort` only follows that same donor's failure. There is no second donor that could fail after the first drops a root. This is why those checks do **not** establish the multi-donor rollback cut above. Likewise `observed` is adequate only under that model's one-GC/version guards; repeated GC needs repeated current-version checks, epoch-bound arrivals and freshly reset acknowledgements.

No new model execution or native test is claimed by this source audit. Next formal extension must include two donors, a failure after another donor is Ready, a second GC while failure is pending, shared abort completion, and receiver teardown/result-root lifetime. Required negative controls are early failed-member return, early successful-donor root drop, stale GC/epoch acknowledgement, and error-root release before the caller consumes it. Until that extension and a concrete C refinement exist, this remains a small-refactor specification with explicit missing premises, not proof that all twelve production gates are solved.


## Executed finite extension

The [two-donor/repeated-GC successor](smp-retirement-multi-donor.md) now checks the targeted missing scenario, with successful and abort paths plus seven decoded negative controls. It does not discharge uncalled queue-suffix semantics, complete weak/root classification, arbitrary callbacks, C memory ordering or repeated transaction reuse.
